## 核心贡献

> 把「CT 体渲染」直接烘焙成标准 3DGS 模型，**不做任何迭代优化**——用三个关键机制（不透明度解析映射、光照烘焙进颜色、淡 splat 随机保留）跨越体渲染与 splat 表示之间的鸿沟。

1. **免训练烘焙**：不做迭代优化、不需渲染训练视图、不需专用 GPU 训练。转换耗时约「每趟 ≤1 分钟」（普通笔记本 / 4GB 显存台式机），输出标准 `.ply` / `.spz`，任意通用 3DGS 查看器甚至 HMD 均可实时显示。
2. **三步关键机制**：
   - **(a) 不透明度解析映射**（重叠高斯的光学深度守恒）：cell 光学深度 τ 按 `h²/(2πs²)` 缩放到单个 splat。去掉该步 PSNR 掉 **4.5–5.9 dB**——是**最大**单项误差源。
   - **(b) 光照烘焙进 splat 颜色**：3DGS splat 是视角无关单色，故先用体渲染器自身的「光照体」预计算 24 方向天空可见度 + 主光透过率（软阴影），再把着色后的颜色烤进 splat。
   - **(c) 淡 splat 随机保留**（1/255 不透明度地板技巧）：解决薄半透明层整体消失问题（皮肤+骨 wide view PSNR 29.8 → 23.8 dB 的差异来源）。
3. **自适应八叉树 + 毫米级 cell，使 splat 数量可控**：从 4 体素宽 cell 出发，仅在不透明度剧烈变化处细分（可到亚体素），使每个体数据输出**指定数量**的 splat（如统一 200 万），而不被体素总数绑定（本文数据中体素网格 splat 数在 0.14–2.86 M 间浮动）。

## 技术方案

### 核心思想

体渲染（DVR）的输入即 3DGS 需要的全部信息：CT 数据给出「材质在哪」（HU → 传输函数给出颜色与消光），传输函数给出颜色/不透明度，虚拟光照给出最终观感。而 splat 与 voxel 的三点本质差异是：splat 位置/尺寸可自由指定；splat 存储的是**外观**而非测量量；splat 直接按深度序混合投影（GPU 极快），无需 ray casting。

因此：**把体数据切成小 cell → 每个 cell 变成一个 splat → splat 继承该 cell 在体渲染中的颜色与不透明度**。

### 关键技术

| 步骤 | 内容 | 关键参数/判据 |
|------|------|------|
| **Step 0 前置** | 预计算光照体，把 GI 近似烘焙成每采样点的着色 | 沿最长轴约 **112 个 cell**；24 方向天空穹可见度 + 至主光的透过率（软阴影）；颜色 = 可见度加权天光 + 透过率加权主光，再 tone-map。渲染器两种视图：**real-time**（每帧一趟，供转换取色）与 **progressive**（抖动帧平均，供参考图） |
| **Step 1 光照** | 决定 splat 颜色的光照模型 | 视角无关颜色 → 必须烘焙；渲染器自身的光照近似全局光照 |
| **Step 2 Cell / 自适应八叉树** | 决定 splat 的位置与尺寸 | 起始 4 体素宽；**分裂判据**：cell 内 HU 区间的最大传输函数不透明度 `α_max` 超过该区间两端不透明度中较小者 `α_max/2` 以上，且 `α_max > 0.01`；分裂测试范围外扩 **1.5 个 cell 宽**（防止大 splat 穿出邻近表面）；cell 为**毫米立方体**（单位=最细体素间距）；最细 cell 尺寸按幂律调节以命中目标 splat 数，**重复转换直到数量落在目标 ±8% 内**（通常 2–3 趟） |
| **Step 3 Cell → 颜色/不透明度** | GPU 上每 cell **27 个分层采样点**（3×3×3） | 传输函数给消光；颜色用 real-time 视图的光照与光照体着色；点颜色按**消光权重 + 至最开阔轴向透过率权重**平均（避免 cell 内部深处的点把 cell 拉暗）；由平均消光 `σ̄` 和 cell 尺寸 `h` 得 `α_cell = 1 − exp(−σ̄ h)` |
| **Step 4 不透明度映射** | cell 光学深度 → 单个高斯 splat 的光学深度 | 高斯需**伸出 cell 边界**以免缝隙/波纹 → 相邻 splat 重叠、光线穿过多个 → 必须缩放；取 `s = 0.55h`（使间距 h 的高斯点阵沿各轴光学深度恒定误差 <1% 的最窄宽度）；`τ_splat = τ_cell·h²/(2πs²)` → **`α_splat = 1 − exp(−0.526 τ_cell)`** |
| **Step 5 淡 splat 保留** | 处理 8-bit 不透明度地板（1/255） | 阈值 `α₀ = 0.01`（≈2.5/255，为抗锯齿补偿后仍能高于地板的最小值）；保留概率 `p = τ_splat/τ₀`，赋予不透明度 `α₀`；用 **cell 索引的哈希**决定 → 转换保持确定性；期望光学深度不变且 splat 数更少 |
| **AA 补偿** | 抑制 aliasing（类似 Mip-Splatting） | 绘制时乘 `w = sqrt(det Σ / det(Σ + 0.3 I))`，Σ 为投影协方差（屏幕空间滤波器方差 0.3 px²） |
| **输出** | 标准 3DGS 文件 | `.ply`（68 bytes/splat，2M 模型 128–146 MB）或 `.spz`（不透明度 8-bit） |

### ⭐ 关键的 1/255 不透明度地板随机保留技巧

**问题机理（两层）**
1. **标准 3DGS rasteriser 的量化地板**：其 alpha 混合/写缓冲为 8-bit，`α < 1/255 ≈ 0.0039` 的 splat 直接被跳过（discard）。同时 `.spz` 等紧凑格式以 8-bit 存储不透明度，低于 1/255 的值在**存储阶段**也会被截断为零。
2. **薄层「整体可见、个体不可见」现象**：皮肤 + 骨传输函数的最外层软组织极薄，单个 cell 的 `α_splat` 全部低于地板，但沿斜射线**许多个这样的 cell 累加起来形成一层可见的「纱 veil」**。若直接丢弃，这整层就没了——表现为外层软组织缺失、**肋骨透过皮肤层显示**（Fig. 3），case 2 的 skin-and-bone wide PSNR 从 29.8 dB 崩到 23.8 dB。

**做法（随机化不透明度量化 / 概率化提升）**
- 判据：`α_splat < α₀`（`α₀ = 0.01`）。
- 以概率 `p = τ_splat / τ₀`（`τ₀ = −ln(1−α₀)`）**保留该 splat**，并把它的不透明度**抬高到 `α₀`**。
- 期望光学深度不变（`p·α₀ = 1−exp(−τ_splat)`），但 splat 总数更少、且每个 splat 都能通过 8-bit 地板。
- 用 cell 索引的哈希决定保留与否 → **转换保持确定性**（可复现）。

## 公式

```math
% cell 不透明度（由平均消光与 cell 尺寸）
\alpha_{\text{cell}} = 1 - \exp(-\bar{\sigma}\, h)
```

```math
% 不透明度解析映射：cell 光学深度 -> 单个 splat 光学深度
\tau_{\text{splat}} = \tau_{\text{cell}}\cdot\frac{h^2}{2\pi s^2},
\qquad s = 0.55\,h
\quad\Rightarrow\quad
\alpha_{\text{splat}} = 1 - \exp(-0.526\,\tau_{\text{cell}})
```

```math
% 淡 splat 的随机保留（保持期望光学深度不变）
p = \frac{\tau_{\text{splat}}}{\tau_0},
\qquad
\tau_0 = -\ln(1-\alpha_0),
\qquad
\alpha_0 = 0.01
\quad\Rightarrow\quad
p\cdot\alpha_0 = 1-\exp(-\tau_{\text{splat}})
```

```math
% 抗锯齿权重（类 Mip-Splatting）
w = \sqrt{\frac{\det\Sigma}{\det(\Sigma + 0.3\,I)}}
```

## 代码片段

> 论文实现为**单文件 WebGL 2 应用**（JavaScript + WebGL 2，浏览器本地运行），**未给出 CUDA kernel 列表**。以下为依论文描述重构的着色器级伪代码。

```glsl
// --- 淡 splat 的随机保留（确定性：哈希 cell 索引）---
// 目标：让低于 1/255 地板的 splat 以概率 p 保留并赋予 alpha0
float stochastic_opacity_keep(float tau_splat, float alpha0, uint cell_hash)
{
    float tau0 = -log(1.0 - alpha0);
    float p    = clamp(tau_splat / tau0, 0.0, 1.0);
    // 由 cell 索引哈希生成确定性随机数
    float r = hash_to_float(cell_hash);
    if (r < p) return alpha0;      // 保留：抬高到 alpha0
    return 0.0;                    // 丢弃
}

// --- 抗锯齿权重 ---
float aa_weight(mat2 sigma_proj)
{
    return sqrt(det(sigma_proj) / det(sigma_proj + mat2(0.3)));
}

// --- cell 颜色/不透明度采样：3x3x3 分层采样点 ---
// 颜色按「消光权重 + 至最开阔轴向透过率权重」平均，避免 cell 深处把 cell 拉暗
void sample_cell(vec3 cell_center, float cell_size,
                 out vec3 color, out float alpha_cell)
{
    float sigma_bar = 0.0;
    vec3  wsum = vec3(0.0), csum = vec3(0.0);
    float w_total = 0.0;
    for (int k = 0; k < 27; ++k) {          // 3x3x3
        vec3 offset = cell_size * (vec3(k%3, (k/3)%3, k/9) - 1.0) / 3.0;
        vec3  p = cell_center + offset;
        float sigma = transfer_function_extinction(p);   // HU -> 消光
        float t_open = transmittance_to_most_open_axis(p); // 至最开阔轴向透过率
        float w = exp(-sigma) * t_open;                  // 消光权重 * 开阔向权重
        sigma_bar += sigma;
        csum += light_volume_shade(p) * w;
        wsum += w;
        w_total += w;
    }
    color = csum / max(w_total, 1e-8);
    alpha_cell = 1.0 - exp(-sigma_bar / 27.0 * cell_size);
}
```

## 实验结论

- **数据集**：TotalSegmentator dataset v2 的 6 例公开 CT 扫描（1.5 mm 体素），3 种传输函数（bone / contrast-enhanced vessels / skin-and-bone）。
- **基线**：**收敛后的参考渲染**（用体渲染器充分抖动累积的 ground truth），指标为 PSNR / SSIM / 学习感知度量。
- **结果**：
  - 200 万 splat 模型：**bone PSNR 32.6 ± 0.9 dB**；**contrast-enhanced vessels 30.1 ± 1.0 dB**；**skin-and-bone 32.3 ± 1.5 dB**。
  - 转换耗时：笔记本 **4–30 s**，带 4GB 显存的台式机 **9–60 s**；每个模型通常需 **2–3 趟**。
  - 渲染：笔记本上 **800×800 下 68 FPS**。
  - 消融（最大误差源排序）：不透明度解析映射缺失 → **PSNR −4.5~−5.9 dB**；淡 splat 直接丢弃 → skin+骨 wide view **29.8 → 23.8 dB**。

## 局限性

- **完全依赖 CT 数据**：体渲染的输入是 CT，方法本身不适用于 RGB 输入的场景。
- 依赖已有的 CT 体渲染器提供光照体与 transfer function，本文实现为 WebGL 2 单文件应用，**未提供 CUDA 内核**，性能天花板受限。
- 质量上「认为足以交互浏览」而非与真实体渲染等价——PSNR 30~33 dB 仍有可见差异。
- 仅验证 6 例扫描、1.5 mm 体素，未覆盖更厚体层或更低分辨率数据。
- 光照为体渲染器自身的近似（24 方向天空可见度 + 单主光），非完整 GI。

## 实现建议

- **实现难度**：**中**。核心是三个数值技巧（不透明度解析映射、随机保留、AA 权重），工程量不大，但需要能同时跑体渲染器与 3DGS 栅格化器。
- **预期性能**：转换 ≤1 分钟/趟，普通笔记本 68 FPS @ 800×800 实时显示；PSNR 30–33 dB 相对收敛参考。
- **适用场景**：
  1. **医学影像可视化**：CT 体渲染结果在无 GPU / 弱设备上的实时交互浏览；
  2. **「烘焙即得资产」范式**：任何「已有渲染器 → 3DGS」的转换任务都可复用其三件套。
- **行动建议**：**推荐移植其通用技巧，而非整套流程**：
  - **1/255 地板的随机保留**是一个**可直接复用到任何 3DGS 变体的通用技巧**（本文、Hexels、任何做「薄层/半透明结构」的 3DGS 工作都会遇到），**优先级：高**；
  - **光学深度守恒的不透明度解析映射**（`h²/(2πs²)`）对任何「体数据/体素 → splat」转换都有参考价值，**优先级：中**；
  - 完整的 CT 流程属于医学垂类，与通用渲染管线相关性较低，**优先级：低**。
