## 核心贡献

> **纯视频世界模型的死穴：用「生成的帧」作为唯一的循环状态 → 同一个视角相关的信号要同时承担「保几何、跟实体、预测交互、合成外观」四重任务 → 视野外的信息只能靠视觉记忆重建，且生成历史的误差会自回归传播。** PlayGen2 的做法是**把「3D 世界状态的演化」和「神经渲染」彻底解耦**：世界状态显式建模（体素占用栅格 + 身份索引实体表），渲染器只负责把状态投影成深度/语义图再合成 RGB，**生成的帧永不回流到状态预测**。

1. **显式 3D 世界状态 + 持久世界记忆（persistent world memory）**：
   - 静态几何 = **体素占用栅格** + 可用性掩码 $\mathbf{K}_t$（区分「空」与「未知」）
   - 动态实体 = **身份索引的 3D 状态表**（语义类 / 位置 / 尺寸 / 速度），包含玩家、怪物、投射物、道具
   - 世界记忆**保留局部处理区之外的几何与实体记录** → 回头探索时几何仍在，视野外实体仍在演化
2. **世界状态模型：几何补全 + 实体发现 + 动作条件状态转移三合一**
   - **Shared Context Transformer**：融合几何 token + 玩家/实体历史 + 动作 → 共享上下文 $\mathcal{C}_t$
   - **Discovery Transformer**：处理 Geometry Queries（补全未知几何）与 Spatial Entity Queries（发现新实体）
   - **Transition Transformer**：预测 $t\to t+1$ 的玩家/实体状态，**含当前实体 token**（新接受的实体无需重算共享上下文即可参与状态预测）
   - **位置用残差形式预测**，**无运行时碰撞修正**（模型学出几何感知运动）
3. **神经渲染器与状态解耦**：把占用栅格 + 实体几何投影成**深度图 + 语义图** → 作为扩散渲染器的显式空间条件 + RGB 历史 → 合成第一视角观测。**生成的帧只更新 RGB 历史，绝不回流到状态预测**
4. **消费级硬件实时**：MacBook Pro (M4 Pro) 上完整仿真+渲染管线 **≈160–200 ms 后端延迟 / 4.98 FPS 串行**，**世界更新与渲染重叠后 7.16 FPS（+44%）**
5. **可组合、可编程**：**零样本**部署到未见地图、**单人模型组合出多人**、**基于规则的状态干预实现可编程玩法**——全部无需重训

## 技术方案

### 核心思想

**三代范式的对比**：

| 代际 | 代表 | 状态表示 | 问题 |
|------|------|---------|------|
| 视频驱动 | GameNGen、PlayGen、Matrix-Game | **像素历史** | 视野外信息靠记忆重建；生成误差自回归传播；无法暴露实体状态供编辑/组合/规则干预 |
| 代码驱动 | Code World Model、CoDeR、Programmable World Model | **可执行程序** | 状态可编辑，但「世界如何演化」由代码给定，**不学习** |
| **显式状态 + 学习转移（本文）** | **PlayGen2** | **显式 3D 状态** | **状态可编辑 + 演化是学出来的** |

> **本文的定位很清楚**：不是「让视频生成器更好」，而是「让状态成为一等公民，渲染只是状态的投影」。这与传统游戏引擎的组织方式同构（显式状态 + 状态转移 + 独立渲染管线）。

### 关键技术

| 技术 | 说明 |
|------|------|
| **世界状态 $\mathcal{S}_t$** | $\mathcal{S}_t=(M_t, K_t, e_t, \mathcal{O}_t)$。$M_t$ = 体素占用图；$K_t$ = **可用性掩码**（区分「已知为空」与「未知」——**未知体素不被当作空空间**）；$e_t$ = 玩家状态；$\mathcal{O}_t$ = 身份索引对象表 |
| **对象表记录** | $o_t^i=(c_t^i, \mathbf{p}_t^i, h_t^i, r_t^i, \mathbf{v}_t^i)$：语义类 / 基位置 / 高度 / 水平半径 / 速度。**状态可在不移动时变化**（如道具被拾取） |
| **持久世界记忆** | 网络只处理**玩家中心的固定尺寸 3D 裁剪体**（local region），但已提交的几何与实体记录**持久保存**在记忆里。回头访问时几何仍在；局部体外的实体「被存储但不持续仿真」 |
| **历史对齐技巧** | 编码前，**所有历史位置都表达为相对于同一个当前裁剪原点** → 保证滑动窗口下的时序一致性 |
| **3D 卷积编码器** | 处理局部占用图、可用性掩码、**相对玩家的逐体素垂直坐标** |
| **Shared Context Transformer** | 融合几何 token + 玩家/物体历史 + 动作信息 → 共享上下文 $\mathcal{C}_t$，同时支撑「增量世界生成」与「状态转移」两个分支 |
| **Discovery Transformer（几何查询）** | Geometry Queries 关联到粗特征体中的空间位置 → **Geometry Decoder** 用 3D 上采样 + 编码器 skip connection 重建体素占用 |
| **Discovery Transformer（实体查询）** | Spatial Entity Queries 围绕候选 3D 参考位置（anchor）提出新实体。查询 = 学习到的 embedding + anchor 位置编码 + proposal 元数据。**New-entity Decoder** 预测 objectness / 语义类 / 相对 anchor 位置 / 尺寸 / 速度 |
| **Transition Transformer** | Entity Queries 预测玩家与活跃对象的下一状态。非玩家对象的查询条件 = 当前状态 + 相邻可用历史帧的位置差 + 从编码器采样的局部几何。**对采样几何特征做注意力** → 对象专属空间上下文。自注意力 + 对 $\mathcal{C}_t$（拼接 Current Entity Tokens）的交叉注意力 |
| **残差位置预测** | $\hat{\mathbf{p}}_{t+1}^i=\mathbf{p}_t^i+f_{\mathrm{xyz}}(\mathbf{h}_{t,\mathrm{trans}}^i)$。**玩家用同样的残差形式**。**无运行时碰撞修正** |
| **更新顺序** | **先**在当前已提交的玩家位姿上补全局部几何，**再**预测下一状态 → 新生成的几何为状态转移提供上下文，而玩家移动又决定下一块需要生成的区域 |
| **神经渲染器** | 占用栅格 + 实体几何 → 从玩家相机视角投影成**深度图 + 语义图** → 与 RGB 历史、动作一起送入独立训练的扩散渲染器 |
| **不变量：帧不回流** | **生成的图像永不进入世界状态预测环**，只更新 RGB 历史 → 切断误差自回归传播路径 |
| **几何感知运动** | 玩家运动通过共享上下文访问几何、动作与历史 → 模型**自己学出碰撞感知导航**，不需要脚本化的碰撞修正 |

## 公式

**世界状态定义**：

```math
\mathcal{S}_t=(M_t,K_t,e_t,\mathcal{O}_t),\qquad o_t^i=(c_t^i,\mathbf{p}_t^i,h_t^i,r_t^i,\mathbf{v}_t^i)
```

> $M_t$：体素占用图；$K_t$：可用性掩码（**未知 ≠ 空**）；$e_t$：玩家状态；$\mathcal{O}_t$：身份索引对象表

**位置残差预测**：

```math
\hat{\mathbf{p}}_{t+1}^{i}=\mathbf{p}_t^i+f_{\mathrm{xyz}}(\mathbf{h}_{t,\mathrm{trans}}^{i})
```

**核心架构分工（论文 Fig. 2 的结构化描述）**：

```
                    ┌─────────────────────────────┐
  局部占用图 M_t ──┤                             │
  可用性掩码 K_t ──┤  3D 卷积编码器               │
  垂直坐标 ────────┤      ↓ 几何特征 F_t           │
                    │  Shared Context Transformer  │
  玩家/实体历史 ────┤  （+ 动作 a_t）               │
                    │      ↓ 共享上下文 C_t         │
                    └──────────┬──────────────────┘
                               │
              ┌────────────────┴────────────────┐
              ↓                                 ↓
   ┌──────────────────────┐        ┌────────────────────────┐
   │ Discovery Transformer │        │  Transition Transformer│
   │  ├ Geometry Queries  │        │  ├ Entity Queries      │
   │  │   ↓ Geometry      │        │  │   (自注意力 +        │
   │  │   Decoder         │        │  │    交叉注意力到 C_t  │
   │  │   ↓ 体素占用       │        │  │    ⊕ Current Entity   │
   │  │                    │        │  │      Tokens)          │
   │  └ Spatial Entity    │        │  └ 预测头:               │
   │    Queries            │        │     位置残差/类别/尺寸/ │
   │    ↓ New-entity       │        │     速度/朝向          │
   │      Decoder          │        └────────────────────────┘
   │    ↓ 新实体           │
   └──────────┬───────────┘
              ↓ 写回世界记忆（持久化几何 + 实体记录）
              ↓
   投影：占用栅格 + 实体几何 → 深度图 + 语义图
              ↓
   扩散渲染器（+ RGB 历史 + 动作）→ RGB 帧
              ↓
   只更新 RGB 历史，❌ 不回流到状态预测
```

**不变量（本文的架构基石）**：

```math
\underbrace{I_t^{\text{RGB}} \;\not\to\; \mathcal{S}_{t+1}}_{\text{生成帧永不回流到状态预测}}
```

## 实验结论

**训练配置**：
- 数据：ViZDoom 中用规则控制器在 **Freedoom2 MAP01** 上自动采集约 **500 小时**游戏数据（约 500 GB）
- 模型规模：世界状态模型 **41.2M** 参数，渲染模型 **29.1M**（不含固定的 **55.3M** VAE）
- RGB 分辨率 **160×120**；**全部从零训练**
- 算力：4× A100 约 **3 天（288 GPU-hours）**

**评测设置**：未见地图用 Scythe（Doom II 社区地图包）**7 个关卡**；global / local 两种世界记忆初始化；每种组合 **64 条探索轨迹**（每条 10 模拟分钟），共 **256 条轨迹**。每个模拟步 = 3 个引擎 tic @ 35 Hz → 每模拟分钟 700 步。

### 4.1 学到的游戏动力学

| 指标 | 结果 |
|------|------|
| **ActAcc**（动作识别准确率，从生成 RGB 反推指令动作） | **82.1 – 85.6 %** |
| **CER**（接触错误率 = 严重穿透的碰撞/落地占比，累积） | **5.2 – 6.8 %** |
| **怪物追击成功率**（200 步内水平面距 <30 world units） | **55 %** |

- **已见地图与未见地图性能相当** → 模型学到的是**可迁移的玩家动力学**，不是记住训练地图的交互
- CER 与 ActAcc 在 **5 分钟到 10 分钟之间保持稳定** → 长时程可控性与物理交互可持续
- **关键能力**：怪物在**玩家视野外**仍然追击（模型在整个 3D 仿真体内更新 NPC 状态，与是否可见无关）→ **「转身只改变看到什么，不改变世界是否继续演化」**

### 4.2 长时程渲染与世界生成

**与 PlayGen 对比（Freedoom2 MAP01，双方共享的训练地图，Tab. 2）**：

- **1 分钟**：两者视觉质量相当
- **5 分钟**：PlayGen 质量**显著劣化**；PlayGen2 在**全部 5 项指标上更优**
- **1/5/10 分钟三阶段**：PlayGen2 的 **LPIPS 始终保持在 0.41–0.44**（稳定）

**未见地图（零样本 Scythe）**：
- **PSNR 16.1–16.6 dB**，**LPIPS 0.63–0.66**，10 模拟分钟内变化有限 → 支持对训练中不存在的布局的迁移
- 论文诚实地指出：深度/语义条件**不指定 Scythe 原生纹理** → 参考指标同时反映结构差异与外观差异，需结合定性结果解读

**局部初始化（增量生成世界）**：
- FID / FVD 在各时间跨度**保持大体稳定** → 随世界扩张视觉质量不退化
- 从单一局部邻域出发，增量生成几何 + 引入实体；**已见/未见地图初始化都能生成合理的空间布局** → 学到了可迁移的空间先验

### 4.4 交互效率（MacBook Pro, M4 Pro）

| 配置 | 吞吐量 | 延迟 |
|------|-------|------|
| 串行（8 步去噪） | **4.98 FPS** | **200.6 ms** 后端延迟均值 |
| **世界更新与渲染重叠**（同设备） | **7.16 FPS（+44 %）** | 275.7 ms |

**分项 profiling**：世界状态更新 ≈ **75 ms** / 潜在渲染 ≈ **90 ms** / VAE 解码 ≈ **30 ms**

> 摘要中给出的 "≈160 ms backend latency" 是另一配置下的测量。

### 4.3 可扩展玩法（无需重训）

- **多人组合**：仅用单人训练的模型，组合出多人交互
- **可编程玩法**：基于**规则的状态干预**叠加在学习到的动力学之上
- **零样本未见地图**：直接部署

## 局限性

- **只在 Doom 上验证**：单一游戏引擎、单一地图（Freedoom2 MAP01）训练、160×120 分辨率 → 迁移到开放世界 / 照片级场景完全未验证
- **低分辨率**：160×120 的输出远达不到产品级视觉质量；论文定位是「证明可行性」而非「可用」
- **训练成本不低**：500 小时数据采集 + 288 A100 GPU-hours，**全部从零训练**（没有复用预训练权重）
- **未见地图的外观生成受限**：因为渲染器只见过训练地图的纹理 → PSNR 仅 16.1–16.6 dB。这是「显式状态 + 学到的外观」的固有折衷：**结构能泛化，纹理不能**
- **世界状态是体素占用栅格**：没有精细几何（无网格、无材质、无高保真表面）→ 无法直接做光线追踪级渲染或物理精确交互
- **无运行时碰撞修正**：碰撞完全靠模型学习 → 仍有 5.2–6.8% 的接触错误率
- **光照只有环境光**：没有可编程的光源；实时光照与阴影能力弱
- **NPC 行为有限**：怪物只会追击，不会复杂战术；论文只评估了「追击成功」这一个行为
- **延迟仍偏高**：4.98 FPS 串行 / 7.16 FPS 重叠，对真正的动作游戏（60 FPS）差一个数量级
- 未提供正式会议发表信息（arXiv 预印本）

## 实现建议

- **实现难度**: **高**。需要：3D 卷积编码器 + 双 Transformer 分支（Discovery / Transition）、体素占用栅格 + 身份索引实体表的持久化状态管理、占用+实体几何到深度/语义图的投影管线、独立训练的扩散渲染器（29.1M + 55.3M VAE）、以及 ViZDoom 级别的数据采集基础设施。**数据采集（500 小时/500GB）本身就是一个独立的工程量**
- **预期性能**:
  - 交互延迟 **200 ms（串行）/ 275 ms（重叠）**，4.98–7.16 FPS @ 160×120，M4 Pro
  - ActAcc **82–86%**，CER **5.2–6.8%**
  - 训练 **288 A100-hours**
- **适用场景**:
  - **可交互程序化内容生成**（游戏原型、关卡草稿、交互式演示）
  - **需要「结构持久」而非「画面持久」的应用**（XR 空间叙事、教育仿真、训练模拟）
  - **需要状态可编程的世界模型**（规则干预、多人组合、agent 训练环境）
  - **Agent 训练环境的候选**：显式状态 + 规则可注入，比纯视频世界模型更适合做 RL 环境
- **可借鉴的通用技巧**（本文最值得迁移的部分）:
  1. **「状态」与「外观」彻底解耦** — 任何自回归生成系统都该问：**哪些信息应该是显式状态，哪些应该是渲染产物？** 本文把「必须持久且可查询」的东西（几何、实体、位置）放到状态，把「只是观测」的东西（RGB）留在渲染侧。**这个切分方式可迁移到任何带空间一致性的生成任务**
  2. **「可用性掩码」区分「空」与「未知」** — 增量生成场景中，**把未探索区域当作已知空闲**是常见的隐性错误。本文用 $K_t$ 显式区分 → **任何做增量/分块生成的系统都应引入这个概念**
  3. **「未知的东西不应被回流污染」** — 生成结果**不回流**到状态预测，切断误差自回归传播。**这个隔离原则可以直接套用到任何生成管线**
  4. **「先补全，再转移」的更新顺序** — 在当前位姿补全几何，然后才预测下一状态 → 新几何为转移提供上下文，转移又决定下一块要补哪里。**这是一个可复用的增量世界建模调度模式**
  5. **状态接口 = 可组合性的来源** — 有了显式状态接口，零样本泛化 / 多人组合 / 规则干预**都变成免费的副产品**。这提示我们：**如果一个系统的扩展性差，往往是因为状态接口没有显式化**
  6. **world-state update 与 render 重叠** — 简单的流水线并行带来 +44% 吞吐。工程上极容易实现
- **优先级建议**: 🟡 **P1 — 概念借鉴价值 >> 直接实现价值**。不建议直接复现（Doom 专用、160×120、成本高）。但**「显式 3D 状态 + 独立渲染器」的架构模式非常值得借鉴**，特别是对任何需要「空间一致性 + 可交互 + 状态可查询」的自研系统。建议：
  - **优先迁移第 1、2、3 条技巧**到我们自己的空间生成/仿真管线（成本低、收益明确）
