## 核心贡献

> **把「TSDF 融合 → Marching Cubes → 噪声移除 → 纹理映射 → 修补 → 辐射度接缝校正」全部常驻 GPU**，中间网格/图像不回传主机；用**定长数组网格拓扑**实现常数时间邻居访问，配合**每相机 24×16 低频增益场**消除曝光接缝。**0.02 m 体素下 13.1 ms/帧（实时），比 nvblox 快 15.9×、比 Open3D(CPU) 快 103.8×。**

1. **GPU 原生全管线**：输入上传后，网格级运算与纹理处理全部在 GPU 上，**阶段之间无中间数据回传主机**（含 CPU→GPU 2.0 ms 与 GPU→CPU 2.9 ms 的传输计入总时长）。
2. **定长数组网格拓扑表示**：使 GPU 上的邻居访问为**常数时间**，并把下游网格级运算（噪声移除、纹理映射、修补）变成**数据并行**。
3. **辐射度接缝校正（radiometric seam correction）**：把相邻面的相机 ID 差异当作**稀疏的亮度失配测量**，在每相机的 24×16 对数增益场上扩散其证据，**烘焙进纹理图集**。
4. **实时在线纹理**：避免 MRF 式全局视图标签优化（每帧面图都在变，全局求解难以界定延迟），改为**逐面独立决策 + GPU 并行**。
5. **感知-失真权衡的诚实呈现**：离线基线 PSNR **最低**但 LPIPS 第二好；本文 LPIPS 第二好而 PSNR 被顶点色变体超过——论文明确解释这是**感知-失真权衡**。

## 技术方案

### 核心思想

**目标场景**：室内体素视频（volumetric video），多 RGB-D 传感器、高密度高帧率捕获，要求每帧产出**图形兼容的纹理三角网格**（几何与外观预算可独立调节：网格简化调几何、图集分辨率与纹理压缩调外观）。

**为什么不用点云/NeRF/3DGS**：点云数据量大、实时传输困难；NeRF/3DGS 的逐帧重建成本与存储占用阻碍实时使用。

**核心矛盾**：现有 TSDF 系统（nvblox、Open3D）加速了融合与网格提取，但**扩展到逐帧纹理网格化会引入 CPU 网格处理、CPU 侧纹理工作或额外的 CPU-GPU 传输**。

### 关键技术

| 技术 | 说明 |
|------|------|
| **单核 TSDF 融合** | 稠密（uniform dense）体素网格而非哈希/树稀疏结构；整个融合步骤是**单个 CUDA kernel，每线程拥有一个体素**，逐视图投影、算有符号距离、积分 TSDF → **无需原子操作**，并行效率高 |
| **定长数组拓扑** | 网格拓扑用定长数组表示 → GPU 上**常数时间邻居访问**；下游网格级运算完全数据并行 |
| **噪声移除** | 连通分量标记式去噪（GPU 上做，3.2 ms） |
| **视图选择纹理映射** | 固定图集布局（垂直堆叠各相机 RGB 图，每个相机一个已知条带）。对每个三角面用其三个顶点测试候选相机：**顶点观测深度无效、或相机空间深度与投影处深度差 > 10 cm** 则拒绝该相机（容差固定，与体素尺寸无关）。在有效相机中选**面法线与视线夹角最小**者，**排除 > 80°**（避免透视畸变） |
| **避免 MRF 优化** | 面图每帧都变，数据依赖的全局求解难以界定延迟 → 改为逐面独立分配；**辐射度不连续由接缝校正阶段处理** |
| **接缝失配测量** | 沿每条共享边的 **8 个对应位置**，向各自投影面内做小 inset 后采样两张源图；用 **1/8 分辨率线性 RGB 代理**抑制纹理细节与错位敏感；排除尖锐折痕与退化投影面、拒绝过暗/无效样本；每条接缝汇总为 $d_s=\operatorname{median}_i(\log Y_b^i-\log Y_a^i)$，权重 $w_s$ = 有效样本比例 |
| **粗增益场平滑** | 每相机 **24×16 对数增益网格** $g_k$；接缝关联到两相机各自最近单元格 $p_a^s,p_b^s$；**平滑项**把接缝证据传播到未观测单元格；**锚定项**（$\lambda_a$）偏好单位增益（$g=0$）；整体偏好渐变的辐射度变化而非逐面独立偏移 |
| **求解与烘焙** | **12 次无矩阵加权 Jacobi 迭代**（$\omega=0.7$）；每次更新组合邻居值与接缝约束，把对数增益**裁剪到 ±0.15**，并**去掉跨相机的全局均值**以控制整体曝光漂移；烘焙时改用**双线性插值**求解场、裁剪 ±0.15；烘焙 = 一次乘法（每像素乘 $\exp(\hat g_k)$）后转回 sRGB。垂直堆叠的相机图给出「图集像素 → 相机网格」的直接映射，无需改网格 UV |
| **时序平滑** | 相机曝光帧间变化小，对增益网格用**指数滑动平均**（$\alpha=0.15$，所有实验一致）→ 帧间网格变化减小 8×，抑制闪烁 |
| **仅亮度 vs 全 RGB** | 三通道校正对留出指标影响可忽略（曝光主导相机间差异）→ 保留**仅亮度场**（保留色度、参数少 1/3）。在独立白平衡的自采数据上 RGB 版持平 |

## 公式

**接缝失配（中值稳健汇总）**：

```math
d_{s}=\operatorname{median}_{i}\bigl(\log Y_{b}^{i}-\log Y_{a}^{i}\bigr)
```

**增益场能量（联合求解所有相机）**：

```math
E(\mathbf{g})=\sum_{s\in\mathcal{S}}w_{s}\bigl(g_{a(s)}[p_{a}^{s}]-g_{b(s)}[p_{b}^{s}]-d_{s}\bigr)^{2}
+\lambda_{\mathrm{sm}}\sum_{k}\sum_{(p,q)\in\mathcal{E}}\bigl(g_{k}[p]-g_{k}[q]\bigr)^{2}
+\lambda_{\mathrm{a}}\sum_{k}\|g_{k}\|^{2}
```

其中 $a(s),b(s)$ 是接缝 $s$ 的两个源相机，$g_k[p]$ 是相机 $k$ 在单元格 $p$ 的值，$\mathcal{S}$ 是接缝集合，$\mathcal{E}$ 含每条无向四邻网格边一次。

**对数域匹配条件**：

```math
g_{a(s)}[p_{a}^{s}]-g_{b(s)}[p_{b}^{s}]\approx d_{s}
```

**烘焙**：

```math
\text{atlas}_{\text{out}}=\text{atlas}_{\text{in}}\cdot\exp(\hat{g}_{k})
```

**增益裁剪范围**：

```math
\hat{g}\in[-0.15,\,0.15]\;\Longrightarrow\;\exp(\hat{g})\in[0.86,\,1.16]
```

```text
// 接缝校正求解器伪代码
for iter in 0..11:                       # 12 次加权 Jacobi，无矩阵
    for each cell p in each camera k:
        # 平滑项：四邻域平均
        smooth = mean(g_k[q] for q in nbrs(p))
        # 数据项：接缝约束（最近单元格关联）
        data   = sum over seams s at p of w_s * (g_a[p] - g_b[p] - d_s) / deg(p)
        g_new  = (1-λ_sm-λ_a) * g_k[p] + λ_sm * smooth + λ_a * 0 + data
    g_k[p] = clamp(g_new, -0.15, 0.15)
# 去掉跨相机全局均值（控制整体曝光漂移）
g_k -= mean_over_all_cameras(g_k)
# 时序 EMA
g_k = 0.15 * g_solved + 0.85 * g_prev
# 烘焙（双线性插值 + 裁剪）
gain(pixel) = exp(clamp(bilinear(g_k, uv_pixel), -0.15, 0.15))
```

## 实验结论

- **数据集**:
  - **CMU Panoptic Studio**：10 台 Kinect v2 半球布置，观察约 6m×6m×2m 体积；用 **office2**（单人交互多个物体）与 **band2**（三人演奏乐器）两个序列
  - 运行时测于 office2，帧 400–2399；留出重渲染与接缝指标用 100 帧
  - 辅助测试：自采数据，5 台 Orbbec Femto Bolt
- **基线**:
  - **nvblox**（CUDA，GPU 路径）
  - **Open3D (CPU)**：Scalable 与 Uniform 变体，含/不含连通分量去噪
  - **Open3D (CUDA)**：仅融合 + MC
  - **Offline**：SPSR + mvs-texturing
- **关键结果**:
  - **运行时**：voxel 0.02 m 时全量 **13.1 ms/帧**（不含输入上传与预处理为 10.9 ms），在 30 fps 的 **33 ms 预算内** → 实时；纯几何版 7.7 ms
  - **voxel 0.005 m**：比 nvblox 快 **29.4×**，比 Open3D(CPU) 快 **89.7×**（比其 Uniform 变体快 179.9×），比 Open3D(CUDA) 快 **1.6×**；此时峰值显存约 **24.1 GB**，其中 16.6 GB 是静态网格与网格缓冲
  - **离线条目**比本文慢约 **993×**（约 13 s/帧：SPSR 3 s + mvs-texturing 10 s）
  - **质量（留出五相机重渲染，voxel 0.02 m）**：本文 LPIPS **第二好**（仅次于 Offline）；PSNR 排序不同——**Offline 最低、Open3D 最高**，论文解释为**感知-失真权衡**
  - **顶点色消融**：同几何下把图集换成逐顶点颜色后 **PSNR/SSIM 上升但 LPIPS 变差**，隔离出图集对感知相似度的贡献
  - **接缝校正效果**：留出指标上 **Ours** 在 PSNR/SSIM/LPIPS 三项均优于 **Ours w/o sc**；**单相机单增益只能达到 30–72% 的收益**（说明空间变化增益场是必要的）
  - **接缝处对数亮度失配**：求解器内部残差降低 **31.8–36.5%**，写入图集后降低 **27.3–33.3%**
  - **帧时代价**：开启接缝校正后 10.8 ms → 13.1 ms（端到端 +2.3 ms，其中接缝校正 1.9 ms）
- **消融**:
  - 去掉噪声移除与修补 → 深度噪声大的动态场景出现伪影，**尤其时序闪烁**
  - 仅亮度场 vs 全 RGB 场 → 留出指标差异可忽略 → 保留仅亮度

## 局限性

- **受限观察体积**：系统面向**有界观察体积**的室内体素视频，需预先设定体素网格范围
- **稠密体素网格的显存**：voxel 0.005 m 时峰值约 24.1 GB（其中 16.6 GB 是静态网格与网格缓冲）→ 极高分辨率下显存成为瓶颈
- **不使用哈希/稀疏体素**：为追求并行效率用了稠密布局，在大场景中代价高
- **接缝只约束相机间差异**：seam 只提供相机间的相对失配约束，**所有相机共有的着色不可观测**
- **不建模完全镜面/视角相关表面**：视场选择依赖「面法线 vs 视线角」假设
- **接缝校正只能修正亮度**：曝光主导差异时够用，但独立白平衡场景下 RGB 版更稳（论文承认）
- **纹理覆盖缺口未评估**：报告的指标在共同覆盖像素上计算，**不衡量表面覆盖缺失**
- **单作者单系统**：未与在线纹理融合类方法直接对比（论文说明这些方法假设持久单传感器扫描，与逐帧多视图协议不同）
- **图集采用相机垂直堆叠**：每个相机占用固定条带，纹理空间利用率非最优

## 实现建议

- **实现难度**: **中高**（CUDA kernel 优化 + 定长数组拓扑 + GPU 图集烘焙，工程量大但不涉及算法创新）
- **预期性能**: 0.02 m 体素 13.1 ms/帧（30 fps 实时）；0.005 m 体素显存 24.1 GB
- **适用场景**:
  - ✅ **体素视频 / 远程临场感（telepresence）/ AR 化身生成**：需要图形兼容的纹理网格以便后续用标准光栅化引擎渲染
  - ✅ 需要**独立调节几何与外观预算**的场景（网格简化 / 图集压缩）
  - ✅ 多 RGB-D 传感器 + 高帧率室内场景
  - ❌ 大尺度室外场景（稠密体素显存不可行）
  - ❌ 高动态范围/强镜面材质场景
- **落地建议**:
  1. **GPU 原生化是主要收益来源**：论文 Table 1 显示 nvblox 的时间大头是 **CPU→GPU 传输（86.3 ms）与 GPU 侧容器开销（54.2 ms）**，而本文的对应项仅 2.9 ms 与 0.2 ms → **「中间不回传主机」这一条设计原则比单个 kernel 优化更重要**
  2. **定长数组拓扑**是把网格级运算数据并行化的前提，值得单独抽出为可复用组件
  3. **接缝校正的思路可迁移**：任何「逐面/逐块选源视图」的在线纹理系统都可套用「把视图 ID 差异当稀疏失配 → 扩散到低频增益场 → 烘焙」的流程
  4. **低频增益场 vs 每相机单增益**的对比（30–72%）说明**空间变化的辐射度校正确有额外价值**，尤其是有镜头暗角或局部 ISP 的相机
  5. 若显存吃紧，可优先降体素分辨率（0.02 m 已满足实时）或引入哈希体素——但会损失 GPU 原生带来的并行优势
