## 核心贡献

> 开源 GPU 原生 PDE 求解框架 **FLUCS**：以 **"solver"（数值机器：空间表示 + 边界条件类）** 与 **"system"（方程特定的项、强迫、诊断）** 的分离为核心架构；当前发布提供单 NVIDIA GPU 上的 **1D/2D/3D 周期域 Fourier 伪谱求解器**（积分因子时间推进 + 多种时间积分器 + 多种去混叠方法），并验证收敛性、量化计算成本、演示三个**聚变与天体等离子体湍流**降阶模型。

1. **Solver / System 双层架构**：不追求"一个通用求解器吃所有方程"，而是让每个 solver 针对**定义明确的问题类**做极致优化，同时让 system 通过规定接口提供方程特定的项。这在"易加新模型"与"计算性能"之间取中间路线。
2. **System 作为可独立分发的插件**：通过 Python **package entry points** 发现已安装的 system，system 可以脱离主包单独开发、发布、安装。
3. **Python / CUDA C++ 分工**：Python 负责接口、I/O、内存管理（CuPy）与 kernel 启动协调；计算密集部分写成 **CUDA C++ kernel**，**运行时编译**，从而规避 Python 循环开销。
4. **积分因子（integrating factor）时间推进**：把线性算子 $L$ 的耗散解析处理，时间步长不再受粘性/扩散约束，**只需满足对流稳定性**（对高 Re 谱方法极为关键）。
5. **两类去混叠方法**：标准 2/3 padding（Orszag 1971）与 **phase-shift dealiasing**（后者支持两种截断方式）。
6. **定长数组设计**：Fourier 空间与实空间的数组尺寸在整个运行期间保持固定（即使某些模式被掩码排除也不重新分配）——实测**略快**且实现更简洁。
7. **性能剖析**：用 NVIDIA Nsight Systems 统计 kernel 时间分布，发现**绝大部分时间花在右端显式项求值（尤其是其中的 FFT）**；单精度比双精度**快近两倍**（A100-SXM4-40GB）。
8. **三个示例 system**：等温 KREHM（零维模型）、冷离子 ITG（离子温度梯度）、碰撞 ETG（电子温度梯度）。

## 技术方案

### 核心思想

**问题**：每一个新的流体/等离子体方程模型都要重新实现时间推进、空间离散、去混叠、数据管理——大量重复劳动。但若采用 Dedalus 式的"符号输入方程"通用框架，solver 就无法针对具体问题类优化，性能被通用性拖累。

**FLUCS 的折中**：

```
FLUCS
├── solver   —— 数值机器（空间表示 + 边界条件类）
│              FourierSolver：1D/2D/3D 均匀周期域，单 GPU
│              （未来：其他空间表示 / 边界条件）
└── system   —— 方程特定的项（插件，可独立分发）
               KREHM / ITG / ETG / 用户自定义
```

- **solver** 不知道被解的是什么方程，只知道"如何在一类空间表示 + 边界条件下推进一阶时间导数的 PDE"。
- **system** 通过**规定接口**告诉 solver：线性项 $L$、非线性项 $N$、强迫 $F$、运行时诊断。

**这种设计的关键后果**：solver 可以高度特化（数据布局、kernel、内存）而不牺牲物理模型的灵活性；system 可以自由选择非线性项的计算方式，只要遵守接口。

### 关键技术

| 技术 | 说明 |
|------|------|
| **Fourier 伪谱离散** | 每个周期方向 $n_a$ 个均匀配点，$L_a$ 长度；DFT 频率 $q_a$ 取主值区间；物理波数 $k_a = 2\pi n_a q_a / L_a$ |
| **积分因子时间推进** | 线性算子 $L[\bm{X}_\bm{k}]$ 解析指数化并从时间推进中剥离；非线性项 $N$ 由用户实现 |
| **linearity-local 假设** | $L$ 可以依赖 $\bm{k}$ 与时间，但**不耦合不同 Fourier 模式**（齐次系统通常满足） |
| **标准 2/3 padding** | Orszag (1971)；只推进 $2/3$ 模式，在更大的变换网格上计算非线性乘积 |
| **Phase-shift dealiasing** | 两种截断方式；与 padding 的实现互不干扰 |
| **Gaussian 消混叠（3/2 rule）** | 论文中作为标准 padding 的替代路径讨论 |
| **AB3 / SSPRK3 / RK4** | 三种时间积分器；AB3 单次 RHS 求值，SSPRK3 与 RK4 需 3 / 4 次 |
| **CUDA C++ runtime JIT** | kernel 在运行时编译（NVCC），避免预编译二进制的 ABI 问题 |
| **CuPy 设备端内存管理** | 演化变量与临时工作数组**常驻 device**，避免 host-device 往返 |
| **Nsight Systems 剖析** | 统计 kernel 时间分布，定位瓶颈（右端项求值 / FFT 占主导） |
| **mass-weighted velocity** | 部分系统使用 $\bm{w} = \sqrt{\rho}\,\bm{u}$ 使谱动能密度 $\frac{1}{2}w^2$ 正定 |
| **KREHM** | 零维（0D）回旋流体模型，用于最低成本基准 |
| **ITG (cold-ion)** | 离子温度梯度不稳定性，降阶 gyrokinetic 模型 |
| **ETG (collisional)** | 电子温度梯度不稳定性，含碰撞的降阶模型 |

## 公式

```math
\text{演化的 Fourier 方程}:\quad
\frac{d\bm{X}_{\bm{k}}}{dt} + L[\bm{X}_{\bm{k}}] + N[\bm{X}_{\bm{k}}] = F[\bm{X}_{\bm{k}}]
```

```math
\text{Fourier 展开与离散化}:\quad
\bm{X}(\bm{r},t) = \sum_{\bm{k}} e^{i\bm{k}\cdot\bm{r}}\bm{X}_{\bm{k}}(t),
\qquad
r_a = \frac{p_a L_a}{n_a},\quad p_a = 0,\dots,n_a-1
```

```math
\text{DFT 频率与物理波数}:\quad
q_a = -\frac{\lfloor n_a/2\rfloor}{n_a},\dots,\frac{\lceil n_a/2\rceil-1}{n_a},
\qquad
k_a = \frac{2\pi n_a}{L_a}q_a
```

```math
\text{积分因子变换（分离线性耗散）}:\quad
\bm{X}_{\bm{k}}(t) = e^{-Lt}\,\bm{Y}(t)
\quad\Longrightarrow\quad
\frac{d\bm{Y}}{dt} = e^{Lt}\bigl(F[\bm{X}_{\bm{k}}] - N[\bm{X}_{\bm{k}}]\bigr)
```

```math
\text{混叠的严格表述}:\quad
(uv)_{\bm{q}} = \sum_{\bm{s}}\sum_{\bm{q}'} u_{\bm{q}'}\,v_{\bm{q}-\bm{q}'+\bm{s}},
\qquad
s_a = q_a' + q_a'' - q_a
\quad\text{（整数混叠向量，各分量 } s_a \in \{-1,0,1\}\text{）}
```

```math
\text{混叠不可区分性}:\quad
e^{2\pi i p_a s_a} = 1
\quad\text{（整数平移不改变 DFT 相位）}
\quad\Longrightarrow\quad \text{必须移除 } \bm{s}\neq 0 \text{ 的贡献}
```

```math
\text{2/3 padding 的无混叠条件}:\quad
2q_a^{\max} < 1 - q_a^{\max}
\quad\Longleftrightarrow\quad
q_a^{\max} < \frac{1}{3}
\quad\text{（即保留 2/3 的模式，在 } 3n_a/2 \text{ 或 } 2n_a \text{ 网格上求乘积）}
```

```math
\text{速度尺度估计（性能分析用）}:\quad
\text{每步耗时} \propto
\begin{cases}
1 \times (\text{RHS 求值} + \text{FFT}) & \text{AB3}\\
3 \times (\text{RHS 求值} + \text{FFT}) & \text{SSPRK3}\\
4 \times (\text{RHS 求值} + \text{FFT}) & \text{RK4}
\end{cases}
```

## 代码片段

```python
# FLUCS 系统（system）接口的最小骨架 —— 概念性伪代码
# 实际 API 见论文 / 代码仓库；此处展示 solver-system 契约

from dataclasses import dataclass
import cupy as cp
import numpy as np

@dataclass
class SystemSpec:
    """方程特定的描述：system 需要告诉 solver 的全部信息"""
    n_fields: int                 # 变量个数 X_1..X_n
    linear_op: callable            # L[X_k] -> array (nk, n_fields)，可依赖 k 与 t
    nonlinear_op: callable         # N[X_k] -> array (nk, n_fields)
    forcing: callable              # F[X_k] -> array (nk, n_fields)
    diagnostics: callable          # 运行时诊断（能量、衰减率等）

class FourierSolver:
    """
    周期域 Fourier 伪谱求解器（概念性）
    - 积分因子时间推进
    - 多种时间积分器（AB3 / SSPRK3 / RK4）
    - 多种去混叠（2/3 padding / phase-shift）
    """

    def __init__(self, nx, ny=1, nz=1, Lx=1.0, Ly=1.0, Lz=1.0,
                 dt=1e-3, integrator="RK4", dealias="padding",
                 precision="float64", device_id=0):
        self.n = (nx, ny, nz)
        self.L = (Lx, Ly, Lz)
        self.dt = dt
        self.integrator = integrator
        self.dealias = dealias
        self.dtype = cp.float64 if precision == "float64" else cp.float32
        self.device = cp.cuda.Device(device_id)

        # 波数网格（主值区间）
        self.k = self._build_wavenumbers()
        # 演化变量：常驻 device
        self.Xk = cp.zeros(self._shape(), dtype=cp.complex128)

    def _shape(self):
        nx, ny, nz = self.n
        return (nx, ny, nz, self.n_fields) if self.n_fields > 1 else (nx, ny, nz)

    def _build_wavenumbers(self):
        """k_a = 2π n_a q_a / L_a,  q_a 主值区间"""
        ks = []
        for n_a, L_a in zip(self.n, self.L):
            q = cp.fft.fftfreq(n_a)                  # 主值区间
            ks.append(2.0 * np.pi * n_a * q / L_a)
        return ks

    # ---------- 积分因子：线性项解析处理 ----------
    def integrating_factor(self, L_op, dt):
        """E = exp(-L dt)，逐点（k 相关）"""
        return cp.exp(-L_op * dt)

    # ---------- 非线性项求值（含去混叠）----------
    def compute_nonlinear(self, Xk, sys: SystemSpec):
        """
        流程：
          1. inverse FFT -> 实空间
          2. 计算非线性项（实空间）
          3. forward FFT -> Fourier 空间
          4. 去混叠（padding 或 phase-shift）
        """
        Xr = cp.fft.ifftn(Xk, axes=(0, 1, 2))
        N = sys.nonlinear_op(Xr)                    # 用户实现
        Nk = cp.fft.fftn(N, axes=(0, 1, 2))
        Nk = self.apply_dealias(Nk)
        return Nk

    def apply_dealias(self, Nk):
        """
        标准 2/3 padding：在更大的网格上求乘积，再截断
        （phase-shift 变体：施加相位因子后截断）
        """
        if self.dealias == "padding":
            # 掩掉 |q| > 1/3 的模式（等价于 2/3 规则）
            mask = self._two_thirds_mask()
            return Nk * mask
        elif self.dealias == "phase-shift":
            return self._phase_shift_dealias(Nk)
        else:
            return Nk

    # ---------- 时间推进 ----------
    def step(self, sys: SystemSpec):
        """一个时间步；具体格式取决于 integrator"""
        if self.integrator == "AB3":
            return self._step_ab3(sys)
        elif self.integrator == "SSPRK3":
            return self._step_ssprk3(sys)
        elif self.integrator == "RK4":
            return self._step_rk4(sys)

    def _step_rk4(self, sys: SystemSpec):
        """RK4 + 积分因子"""
        E = self.integrating_factor(sys.linear_op(self.Xk, self.t), self.dt)
        k1 = sys.nonlinear_op + sys.forcing      # 已在 Fourier 空间
        # 经典 RK4，显式部分 N+F
        def rhs(X):
            N = self.compute_nonlinear(X, sys)
            F = sys.forcing(X)
            return N + F
        y1 = rhs(self.Xk)
        y2 = rhs(self.Xk + 0.5 * self.dt * y1)
        y3 = rhs(self.Xk + 0.5 * self.dt * y2)
        y4 = rhs(self.Xk + self.dt * y3)
        self.Xk = self.Xk + (self.dt / 6.0) * (y1 + 2*y2 + 2*y3 + y4)
        self.Xk = E * self.Xk                  # 积分因子：线性耗散
        self.t += self.dt
        return self.Xk
```

## 实验结论

- **收敛性验证**：对 1D/2D/3D 周期域 Fourier 伪谱求解器系统验证收敛性（含去混叠后的谱精度）。
- **计算成本量化**：给出 timing 与 memory 基准。
- **时间积分器比较**：每步 wall time 相对双精度 AB3 为基准——SSPRK3 ≈ 3×，RK4 ≈ 4×，与各格式的 RHS 求值次数一致（**AB3 单次，SSPRK3 三次，RK4 四次**）。
- **kernel 时间分布**（Nsight Systems）：**大部分时间花在右端显式项求值，其中主要是 Fourier 变换**——这是谱方法的主要瓶颈。
- **精度与性能权衡**：**单精度比双精度快近两倍**（NVIDIA A100-SXM4-40GB）。
- **应用演示**：三个降阶等离子体湍流模型——**等温 KREHM、冷离子 ITG、碰撞 ETG**。
- **架构可扩展性**：设计明确支持新增 solver（其他空间表示/边界条件）与新增 system（任意方程集）。

---

## 局限性

- **仅单 GPU**：当前版本只支持**单块 NVIDIA GPU**，多 GPU / 集群分布式不在本次发布范围。
- **仅周期域**：仅 FourierSolver 一个 solver，面向均匀周期域；**非周期几何、复杂边界、固体边界均不支持**。
- **仅一阶时间导数**：框架定位是"systems of first-order-in-time PDEs"，二阶时间导数需自行离散处理。
- **需要 GPU**：所有 kernel 均为 CUDA C++，无 CPU 回退路径。
- **方程需显式适配**：不像 Dedalus 那样可符号输入方程，实现新 system "more involved"（论文自述）。
- **未覆盖**：壁面函数、破碎源项、多相流、AMR、OpenMP/MPI 并行。
- **示例系统均为等离子体/零维降阶模型**，**没有传统的 Navier-Stokes 湍流或 DNS 示例**——对纯流体社区的迁移成本未量化。

## 实现建议

- **实现难度**：🟡 中（若已有 GPU 环境）。架构清晰，但 CUDA C++ kernel + runtime JIT + CuPy 设备端内存管理需要一定经验。
- **预期性能**：A100 上单精度可达双精度的约 2× 速度；瓶颈在 FFT 而非 kernel 逻辑——**若能融合非线性项求值与变换（"spectral deferred transform" 思路）可进一步提速**。
- **适用场景**：
  - **周期性、齐次、无边界**的湍流/波湍流问题（管道流、衰减湍流、Kelvin-Helmholtz、色散关系）；
  - **降阶流体模型**（0D KREHM 类、reduced MHD 类）的长时间积分与参数扫描；
  - 需要在 GPU 上做**大规模参数扫描**（论文明确提到参数扫描是主要计算需求）。
- **落地建议**：
  1. **先评估周期域是否够用**——本框架目前**无法处理壁面**，若问题是管道/边界层则不适用；
  2. **实现自定义 system 时，先做 AB3 + 2/3 padding**（最简、最快），确认正确后再升级；
  3. **务必用 Nsight Systems 剖析自己的 system**——论文表明瓶颈几乎总在 FFT，可据此判断是否值得投入 kernel 优化；
  4. **单精度先跑通再做双精度对照**（时间步长限制需重新评估）；
  5. **关注后续版本**——作者明确规划了更多 solver 与 system 的加入。
