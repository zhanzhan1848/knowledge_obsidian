## 核心贡献

> 呼吁机器学习社区：把 (3+1) 维湍流当作**四维现象**来处理——空间与时间分辨率的评估结论会相互矛盾

1. 使用单次运行**超过 28 TB** 的巨型时间分辨 DNS 数据
2. 系统分析**数值选择**（网格、时间步、求解器等）如何决定所解析出的 (3+1) 维湍流物理
3. 研究**神经网络**如何表示这些记录的湍流运动
4. 核心发现：**空间评估与时间评估可能给出相互矛盾的结论**——对数值记录和"学习到的表示"皆然
5. 明确诉求：ML 社区应把 (3+1) 维湍流视为四维现象

## 技术方案

### 核心思想

3D 湍流的能量级联需要同时解析精细空间结构**和**流场的连续时间演化。但常规评估指标（如瞬时场误差、单点统计）只看空间维度，会漏掉时间演化的缺陷。本文用超大规模数据 + 神经网络双重探针，检验空间/时间评估的一致性。

### 关键技术

| 技术 | 说明 |
|------|------|
| 超大规模时间分辨 DNS | 单次运行 > 28 TB，覆盖空间+时间四维 |
| 数值选择敏感性分析 | 系统改变网格/时间步等，考察所解析物理的偏移 |
| 神经网络表示探针 | 用 NN 学习/表示湍流运动，检验其时空保真度 |
| 空间-时间一致性检验 | 对比空间指标与时间指标是否给出相同判定 |

## 公式

```math
三维 N-S 的时间演化:
  ∂u/∂t + (u·∇)u = -∇p + ν∇²u + f

时空四维视角:
  数据表示为 D(x, t) ∈ R^{N_x × N_t × 3}
  空间评估:  E_s = ||u_num(x,t) - u_ref(x,t)||  在固定 t 切片上
  时间评估:  E_t = ||u_num(x,t) - u_ref(x,t)||  在固定 x 序列上
  关键结论: E_s 小 ⇏ E_t 小（可能相互矛盾）

能量级联的时间约束:
  时间分辨率需满足 Δt ≲ Δx/|u|   （Courant），否则级联被截断
```

## 代码片段

```python
# 空间/时间一致性检验骨架
def consistency_check(u_num, u_ref, dx, dt):
    """
    u_num, u_ref: (Nt, Nx, Ny, Nz, 3)
    返回空间指标与时间指标，判断是否相互矛盾
    """
    # 空间指标：逐时刻切片误差
    e_space = np.linalg.norm(u_num - u_ref, axis=(1, 2, 3)) / np.sqrt(u_ref[0].size)

    # 时间指标：逐空间点的时间序列误差
    e_time = np.linalg.norm(u_num - u_ref, axis=0).mean() / np.sqrt(u_num.size)

    # Courant 数（时间分辨率是否足够）
    courant = dt * np.abs(u_ref).max() / dx

    contradictory = (e_space < tol) and (e_time > tol)
    return dict(e_space=e_space, e_time=e_time, courant=courant,
                contradictory=contradictory)
```

## 实验结论

- **数据集**: 超大规模时间分辨 DNS（单次运行 > 28 TB）
- **基线**: 常规的空间维评估方式
- **结果**:
  - 数值选择（网格/时间步等）显著影响所解析出的湍流物理
  - 神经网络的"学习到的湍流表示"同样呈现空间/时间评估不一致
  - 空间指标表现良好并不保证时间演化正确 —— 这是 ML 湍流建模的隐蔽陷阱

---

## 局限性

- 结论基于特定 DNS 配置与特定的 NN 表示方式，普适性待更多数据规模验证
- 摘要未给出具体的评估指标定义与量化对比
- 28 TB 级数据的存储与 I/O 成本极高，复现门槛很高
- 属观点/方法论论文，未提出具体的改进算法
