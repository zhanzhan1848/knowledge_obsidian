## 核心贡献

> 离散伴随方法对 GPU CFD 求导首次以"源码转源码"路径实现，性能/精度同时优于编译器方案 Clad。

1. 给出 **流求解器 CUDA kernel 的源到源自动微分**：CUDA → 反向模式 → 普通 CUDA 源码，无运行时 tape、无 GPU 框架依赖
2. **流求解器 kernel 结构感知**：纯累加免 tape；中间变量重算而非存储；多线程只写同位置时 atomic add
3. 与编译器方案 Clad 在 stencil kernel 上结果与代价一致，但在 **Biot–Savart 点涡求和**类 kernel 上 **`16–470×` 加速**（无 tape 存储）
4. 单精度稳态 Burgers 反设计演示：当条件数增至 $2.5\times10^5$，**有限差分 Jacobian 误差 45–75 %**，而 **CuAD Jacobian 误差 < $5\times10^{-5}$**

## 技术方案

### 核心思想

把"反向模式 AD"重写成"在编译期一次性分析流求解器 kernel 的读写/累加结构"，对每个 thread 输出原生 CUDA 反向核，**避免 tape** 与 **最小化全局存储**。

### 关键技术

| 技术 | 说明 |
|------|------|
| 源码转源码 AD（parser + AST 重写） | 读 CUDA C，输出 tangent / adjoint CUDA C |
| Per-thread reverse mode | 每个 GPU thread 独立反向，warp 内 reduction 用 shared memory |
| 流求解器 kernel 结构分析 | 分类 `pure accumulation` / `recomputable intermediates` / `cross-thread writes` 三类 |
| Atomic-free parallel adjoint | 仅在多线程命中同地址时降级为 atomic add |

## 公式

### 离散伴随框架（教科书）

$$
\frac{\partial J}{\partial \phi} = \left(\frac{\partial R}{\partial \phi}\right)^{\!\top}\!\lambda,\quad
\text{with }\left(\frac{\partial R}{\partial U}\right)^{\!\top}\!\lambda = -\left(\frac{\partial J}{\partial U}\right)^{\!\top}
$$

- $J$：目标函数（升力、阻力、传感器读数等）
- $R(U;\phi)=0$：离散残差
- $\phi$：设计参数；$\lambda$：伴随变量（adjoint）
- 单精度下 $R$ 条件数 $2.5\times10^5$ 时，FD Jacobian 失效，CuAD Jacobian 仍保持机器精度

### 四个验证 kernel

| Kernel | 类型 | 关键观察 |
|--------|------|----------|
| Viscous Burgers 残差 | Stencil, 标量 | stencil 类：与 Clad 同结果、同代价 |
| 2D Advection-Diffusion | Stencil, 系统 | 同上 |
| 准一维 Euler 残差 | Stencil, 守恒律 | 同上 |
| Biot–Savart 点涡求和 | Reduction, 离散和 | **CuAD 16–470× 快于 Clad** |

## 实验结论

- **数据集 / 验证算例**：
  1. Burgers shock adjoint 场
  2. cellular vortex 内标量传感器 sensitivity
  3. **transonic nozzle 反设计**：面积恢复至 $2\times10^{-8}$
  4. **vortex sheet 卷起 unsteady adjoint**（400 时间步）
- **基线**：Clad（编译器方案）、有限差分 Jacobian
- **结果**：
  - **精度**：单精度条件数 $2.5\times10^5$ 下 FD 45–75% 误差，CuAD < $5\times10^{-5}$；与解析匹配至舍入误差
  - **速度**：adjoint kernel 是 primal 的 $2$–$6\times$；reduction kernel 较 Clad 加速 **16–470×**

---

## 局限性

- 仅验证四个 kernel；**未在完整 NS/Euler 工业求解器上端到端跑通**（如 SU2/PyFR/OpenFOAM GPU kernels）
- 暂未涉及多 GPU / MPI 分解后的 adjoint；MPI 边界交换的 reverse mode 需要手工辅助
- 仅支持 CUDA；HIP/ROCm、SYCL、Triton 等异构后端待扩展

## 实现建议

- **实现难度**：**高**（需要 CUDA C 前端 + AST 遍历 + 类型推断 + 反向代码生成）
- **预期性能**：reduction kernel 较 Clad 16–470×；stencil kernel 与 Clad 持平；adjoint = $2$–$6\times$ primal
- **适用场景**：
  - GPU 形状 / 拓扑优化（C++ 原生 CFD，避开 JAX/酶）
  - 反设计（transonic nozzle / airfoil）
  - 高精度梯度需求（数据同化 / 4D-Var）
- **集成路径**：
  1. 把当前 PyFR / SU2 CUDA kernel 子集导出为文本
  2. 用 CuAD 生成 adjoint cubin
  3. 在 OpenMDAO/PyOptSparse 容器内串联
- **风险**：依赖 CUDA 编译器对生成代码的反复编译；建议接入[NVRTC](https://docs.nvidia.com/cuda/nvrtc/) 进行运行时缓存
