# Patch-Based Generalized Neural Texture Upscaling

> 用一个**通用 MLP** 在**纹理采样时**按需上采样局部贴片，**不需要修改任何现有纹理资产**。小到足以直接跑在 **GPU 着色器**里。

## 核心贡献

> 传统纹理上采样要么在 GPU 显存里存全分辨率纹理，要么离线预处理。两者都不可用于「运行时按需、随机访问」的场景。本文让 MLP **直接替代解析纹理采样器**。

1. **局部性（locality）设计** —— 不整体上采样纹理，而是在**纹理采样时**上采样一小块贴片 → 消除全分辨率副本的显存开销
2. **贴片上下文边距（margin）** —— 输入贴片四周扩展 $m$ 个 texel 作为上下文，输出丢弃该边距，解决**贴片边界块状伪影**
3. **极小配置** —— $n=1$, $m=1$, $c=3$：输入 3×3、输出 2×2，使参数量与算力低到能**作为 GPU 着色器执行**
4. **通用模型（generalized）而非过拟合（overfitted）** —— 单一模型在多样贴片集合上训练一次，**无需每资产优化**，部署时**直接替换采样步骤**
5. **统一模型** —— 可用 diffuse+normal+ARM 三类统一训练一个模型（折中但更易部署）

## 技术方案

### 核心思想

给定 $n\times n$ 的低分辨率输入贴片，模型输出 $2n\times 2n$ 的双倍分辨率贴片。但单独上采样贴片会在边界产生**块状伪影**，因为模型看不到贴片边缘之外的纹理模式。

**解法**：输入贴片四周扩展 $m$ 个 texel。网络接收 $(n+2m)\times(n+2m)\times c$ 张量，输出 $2n\times 2n\times c$；$m$ 边距作为上下文被**消费并丢弃**。

实验配置：$n=1$, $m=1$, $c=3$（RGB），即 **3×3 输入 → 2×2 输出**。选 $n=1$ 是为了最小化每次采样取回的 texel 数。

**纹理边界处理**：靠近纹理边界处 padding texel 不存在 → **镜像（mirror）边界值**，假设纹理连续。

### 关键技术

| 技术 | 说明 |
|------|------|
| **模型配置** | 隐藏维度 $d=256$，$L=4$ 个残差块，开启残差连接 |
| **纹理类别** | diffuse / normal / ARM，用**相同架构**；可训三类统一模型，也可分类训练 |
| **边界镜像填充** | 假设纹理连续，反射边界值 |
| **训练数据** | Poly Haven 网站 + 渲染场景纹理（Hangar / Victorian / Museum）；下采样至 ≤2048×2048；Poly Haven 做完整划分，**训练数据不接触测试数据** |
| **指标选择** | **PSNR/SSIM 不适合** —— 因为上采样纹理**不保证逐像素准确**。作者发现**很多模糊纹理 PSNR 更高但视觉质量更差**（PSNR 只看逐像素误差，不看感知正确性）。**因此主指标用 LPIPS** |

### 关键公式

**贴片上下文扩展**

$$
\text{input}: (n+2m)\times(n+2m)\times c \;\longrightarrow\; \text{output}: 2n\times 2n\times c
$$

### 通用 vs 过拟合

过拟合模型（类似 NTC）除少数情况（如 Museum normal）外一致更好，但**给内容创作管线增加开销**。是否过拟合**取决于开发场景**，可按需选择。

### 统一模型

在 Hangar / Museum 上用 Poly Haven 不同组合训练对比（LPIPS）：
- Hangar 的 diffuse 与 normal 在**同类训练集**下最佳
- Museum 的 diffuse 同样规律，但 **normal 只用 normal 纹理训练表现不佳**
- 总体上 **diffuse + normal + ARM 三类联合训练**在两个场景都表现均衡（虽非最佳，但部署最简）

## 复杂度分析

- **每次纹理采样**：一次 $3\times3\times3$ 输入 → $2\times2\times3$ 输出的 MLP 前向。参数约 $O(d^2 \cdot L)$（$d=256$, $L=4$）→ **~1M 量级参数**，算力 $O(d^2 \cdot L)$ per texel
- **显存**：**无需全分辨率纹理副本** —— 这是相对传统方法的核心节省
- **部署**：可作为 **GPU 着色器**执行（作者强调参数量与算力足够小）
- **无随机访问问题**：按需生成，可支持任意 mip 层/任意缩放比

---

## 数值稳定性

- **贴片边界伪影**：用 $m$ 边距上下文缓解；$m$ 太小会残留块状伪影
- **纹理边界镜像填充**：假设纹理连续 —— 对大面积平铺纹理成立，但对**不连续/图案化纹理**可能在边界引入瑕疵
- **PSNR 的误导性**：作者明确论证 PSNR 不适用于上采样评价（模糊纹理 PSNR 反而更高）—— **这是方法论上值得注意的一点**

---

## 局限性

1. **未做系统的运行时性能评估** —— 作者自陈的明确局限。虽然设计目标是实时，但缺少实际帧时间测量
2. **仍是 2× 放大** —— 未扩展到更高倍比
3. **边界镜像假设** —— 纹理边缘不连续时不成立
4. **统一模型是折中** —— 分类模型在多数场景更优
5. **过拟合路线仍需预处理** —— 与「零改动部署」的目标冲突
6. **PFT 在部分纹理上仍明显更好**（如 Weapon_D：0.0304 vs 0.0974）—— 差距存在

## 实现建议

- **实现难度**: **低-中**（模型很小；难在着色器集成与边界处理）
- **预期性能**: $d=256$, $L=4$；部署进纹理采样步骤即可
- **适用场景**:
  - **引擎内/运行时纹理增强**（不改动任何现有资产）
  - 需要**随机访问**的上采样（离线超分器无法胜任）
  - 纹理内存受限的平台（移动/VR）
- **最值得复用的技术点**:
  1. **「MLP 直接作为纹理采样器」** —— 把神经网络塞进采样点而非烘焙进资产，是**零管线改动**的部署范式
  2. **上下文边距（margin）机制** —— 任何局部 patch 推理都会遇到边界伪影，$m$ 边距是一个通用且极省的解法
  3. **「PSNR 不适合上采样」的方法论提醒** —— 评估任何生成/上采样任务时都应优先用感知指标
  4. **$d=256$ 甜点** —— 可直接作为起始配置
- **依赖项**: PyTorch 训练 → 导出为着色器（GLSL/HLSL/SPIR-V）；无现成库可直接用
