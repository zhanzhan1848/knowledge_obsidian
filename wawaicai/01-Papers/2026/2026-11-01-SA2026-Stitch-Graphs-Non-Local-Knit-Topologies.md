# Stitch Graphs for Interactive Modeling of Non-Local Knit Topologies

> 📌 **SA2026（papers_1930）**。方向偏服装/制造，但**内核是一个拓扑表示问题**：现有 stitch mesh 把针织当成「多边形曲面」，而真实针织（缆线、堆叠、堆垛）**本质上是图**。本文提出用**图**承载编织操作 ⟹ 拓扑表示范式的一次替换。

## 技术概述

### 问题：stitch mesh 的「曲面偏见」

**Stitch mesh** 已经让针织可以交互式建模——把针织表示为**多边形曲面**，一个针圈（loop）对应一个面片。

但这个表示有一个**根本性假设**：

> **针织是「面状的」（surface-like）**。

现实中的复杂针织结构**违反了**这个假设：

| 复杂针织结构 | 为什么曲面表示失效 |
|---|---|
| **Volumetric cables**（立体缆线） | 纱线路径**跨越**多个面片区域，不在单个面片上 |
| **Stacked tucks**（堆叠 tuck） | 纱线在**同一区域**反复穿行，需要**多层**重叠 |
| **Dimensional ribbing**（立体罗纹） | 局部纱线做**高度方向**堆叠 |
| **Crossings / long-range connections** | **非局部**（non-local）连接：a 针与 b 针相连，但二者在网格上相距很远 |

核心矛盾：
- 曲面表示是**局部邻接**的（一个面连接相邻面）
- 而某些编织操作（transfer、cable cross、tuck）是**非局部**的
- ⟹ **被迫用「重叠面片 / 极窄通道」等 hack** 来编码非局部关系

### 核心思想：把「编织操作」提升为**图节点**

> **stitch graph**：把 knitting operation 表示为图中的节点，利用**非局部连通性**自然地建模 crossing 与 long-range connection。

这是**表示层**的替换：

| | Stitch Mesh | **Stitch Graph** |
|---|---|---|
| 原语 | 面片 / 针圈 | **编织操作节点** |
| 连通性 | 局部邻接 | **非局部（可跨任意距离）** |
| Crossing | 需 hack | **图边原生支持** |
| 拓扑 | 强制流形（2-manifold） | **可带环、带分支** |
| 3D 形状 | 由面片位置隐式决定 | 由**模拟/优化**显式求解 |

**为什么必须是图**：因为编织工艺本身就是**图论对象**——一个针筒（needle bed）的状态本质上是一个**转移函数**，而 cable、tuck、transfer 都是在改写这个转移关系。用曲面去模拟图论，必然失真。

#### ① 完整框架：建模 → 模拟 → 纱线可视化

本文不只是一个表示，而是**一整套管线**：
- **建模（modeling）**：从 stitch graph 生成针圈序列
- **模拟（simulation）**：在图上做纱线路径/形状求解，产出**三维形状**
- **纱线可视化（yarn visualization）**：把抽象的图操作还原成**真实的纱线走向**

⟹ 这是本文敢说「real-time, interactive」的前提：图表示让**编辑**变得轻量，而**模拟/渲染**是下游消费者。

#### ② 统一编辑工具 ⭐

> 「一个**统一的交互模型**同时处理 transfers、cables、tucks。」

这是本文工程上最有价值的部分。三种编织操作本质不同（transfer 是重连、cable 是交叉、tuck 是堆叠），但在**图操作**层面它们都是**节点/边的局部改写** ⟹ 一次交互模型即可覆盖。

- 传统做法：三个工具、三个心智模型
- 本文：**一个交互模型** ⟹ 学习成本低，组合操作（先 cable 后 tuck）自然

#### ③ 验证方式

- 与**代表性图样（patterns）**对比
- 与**物理样片（physical samples）**对比
- 覆盖：**volumetric cables、stacked tucks、dimensional ribbing**

## 复杂度与性能

- **实时交互**：图结构本身是**稀疏的**（节点 = 针圈/操作，边 = 纱线连接）⟹ 编辑操作的复杂度是 **O(受影响局部)**，与整体规模几乎无关 ⟹ 这正是「非局部连接」能被实时编辑的前提
- **模拟**：摘要提到实现「实时」框架，但**未给出模拟的具体复杂度与耗时数据**
- **未公开的数据**：摘要未给出针圈规模上限、帧率、图规模与内存占用 ⟹ 复现时需自行定标

## 数值稳定性

### ✅ 优势
- ✅ **图表示消除了「重叠/自交」的表示性压力**：非局部连接在 mesh 表示中必须靠几何 hack 制造重叠（这正是很多针法实现里「面片重叠导致 z-fighting / 深度排序错误」的根源）⟹ 图表示把这类问题从**几何层**移到了**语义层**
- ✅ **编辑操作的局部性** ⟹ 用户一次操作只改写少数节点/边 ⟹ 数值误差不会全局累积
- ✅ **与物理样片对比** ⟹ 说明图表示能正确反映**纱线的力学后果**（不止是拓扑）
- ✅ **统一交互模型** ⟹ 减少了「不同工具不同数值约定」导致的不一致

### ⚠️ 风险点
- ⚠️ **图 → 三维形状的映射不唯一**：图给出拓扑，但**具体形状**取决于模拟（纱线张力、针筒位置、拉伸率）⟹ 形状是**多解的**，需要额外约束；摘要未说明解的唯一性/稳定性如何保证
- ⚠️ **stacked tucks 的层叠深度**：多层纱线堆叠时，层间**接触与挤压**是典型的接触病态问题（法向不确定、接触集合跳变）⟹ 极易出现抖动或穿透
- ⚠️ **cable crossing 的拓扑翻转**：交叉操作在图上是「换边」⟹ 存在**符号歧义**（左压右 vs 右压左）⟹ 解算时可能在两者之间跳变
- ⚠️ **大针筒的图规模**：真实 garment 的针圈数是 10⁴–10⁵ 量级 ⟹ 图很稀疏但**度分布集中**（针圈连接多），邻域更新与碰撞查询可能不再是 O(局部) 的常数开销
- ⚠️ **摘要未给出数值稳定性分析**：稳定性完全依赖下游模拟器（摘要未披露用的是何种布料/纱线求解器）⟹ 这是复现的主要黑盒

## 推荐结论

✅ **推荐（强烈推荐，⭐⭐⭐）**

### 理由
1. **这是纯正的拓扑表示创新**：不是「把已有表示做得更准」，而是**换掉原语**（面 → 图）⟹ 属于我们关注的「几何表示」核心命题
2. **非局部性是几何处理中的长期痛点**：缝合、缆线交叉、束带、多体连接都受困于此 ⟹ 图表示是一个可推广的通用解法思路
3. **「统一交互模型」把三种工艺操作统一** ⟹ 工程上非常实用
4. **与物理样片对比** ⟹ 说明它真的做对了纱线力学，不是纯拓扑玩具

### 与相关工作的定位

| 方向 | 代表 | 与本文关系 |
|---|---|---|
| Stitch mesh 表示 | 既有 stitch-based 建模 | **被本文替代**的表示层 |
| 服装/编织 CAD | 商业 knit CAD | 面向工业；本文偏**交互式建模** |
| 图结构几何 | 曲线网络、拓扑优化（见本库 FlowLoops / S4R） | **同源思想**：用图承载结构 |
| 缝合/线缆 | 3D 打印路径规划 | 同属「非局部连接」问题 |
| 布料/纱线模拟 | PBD/XPBD 布料、线缆模型 | **下游消费者**：本文提供表示，模拟提供形状 |
| 可展开曲面 / 服装打版 | 本库 `Efficient and Robust Seamless Parametrization` | **互补**：那是参数化，本文是结构表示 |

### 落地建议
- 若我们做**服装/软体制造工具** ⟹ stitch graph 是「立体针织」从「不可做」到「可做」的关键表示
- 若做**通用几何** ⟹ 「用图承载非局部连接」的思路可直接迁移到**缝合线布局、束带/绳缆拓扑、3D 打印支撑结构**
- 实现上建议：**图操作层（图编辑）+ 形状层（模拟/优化）严格分离** ⟹ 这是本文框架最值得抄的结构
