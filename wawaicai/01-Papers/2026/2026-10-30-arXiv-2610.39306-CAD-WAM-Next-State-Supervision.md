# CAD-WAM: Anticipating Geometry for Text-to-CAD Generation

> 📌 **arXiv 24 小时窗口内的 CAD 生成论文**。核心方法论值得记：**用「几何的下一状态」作为辅助监督信号，约束 LLM 生成的操作序列** —— 这是把几何正确性注入语言模型的通用范式。

## 技术概述

### 问题：操作选错会「污染后续步骤」

从文本生成**可编辑**的 CAD 模型，需要**选择能产生预期几何变化的操作**。

> **一个错误的操作会损害后续步骤**，使可靠的多步生成变得困难。

既有 LLM 方法的根本缺陷：

> 它们主要**学习预测命令**，而**没有对「这些命令应该产生什么几何状态」的显式监督**。

于是 LLM 在语法上正确（命令合法）却在几何上错误（结果不是想要的形状），且**错误会级联**。

### 核心思想：World Action Model 式的「动作 + 下一状态」双预测

> 受 **world action model** 启发，我们引入 CAD-WAM，**将几何条件的动作生成与下一状态预测耦合**。

具体设计：

| 组件 | 说明 |
|------|------|
| **动作空间** | 完整的建模操作，定义在 **CAD 领域特定语言（DSL）** 中 |
| **状态编码** | 把中间实体的**表面点云**编码为**紧凑的潜在状态**，用**预训练变分自编码器（VAE）** |
| **主干** | LLM 主干：根据「目标描述 + 当前几何状态」生成下一个动作 |
| **辅助头** | **同一主干**上的辅助头：**预测下一状态**，为训练提供**几何监督** |

**为什么「下一状态」预测能起作用**：

辅助头强迫 LLM 主干**内部表示**包含「当前几何长什么样、以及下一个动作后会长什么样」的信息。仅靠动作监督时，主干只需学会「文本 → 命令」的映射，可以完全绕开几何；而下一状态监督**强迫**主干建立几何状态表征。

### 训练与推理

- **训练**：从 DeepCAD 的参数化 CAD 模型构建**逐步训练轨迹**，每条轨迹配一段**专家级文本描述**
- **推理**：每个生成的动作由 **CAD kernel 执行**，结果实体被**重新编码**以 informing 下一次决策

### 关键技术

| 技术 | 说明 |
|------|------|
| **预训练 VAE 状态编码器** | 表面点云 → 紧凑潜在状态 |
| **共享主干的辅助头** | 下一状态预测头与动作头**共享**主干（不是独立网络）—— 这样几何监督能传导到动作生成 |
| **在线重编码** | 推理时执行每个动作后重新编码几何，形成闭环 |
| **专家级文本配对** | 训练轨迹与专家描述配对，而非粗糙标注 |

## 复杂度分析

- **训练**：LLM 主干 + VAE（预训练）+ 辅助头。VAE 只需训练一次（可复用）。
- **推理**：**串行**（每步必须执行 CAD kernel 再重新编码）⇒ 延迟与步数线性相关。这是 LLM-CAD 范式的固有串行性。
- **消融结论**：仅用动作监督的同构模型，Chamfer 距离比有下一状态监督的高 **13.2%** ⇒ **辅助头带来了实质增益**

## 实现难度与数值稳定性

- **算法复杂度**：**中**。VAE + LLM + 辅助头都是标准组件；难点在**轨迹构造**（从 DeepCAD 提取逐步轨迹并配对专家描述）与**状态/动作的时序对齐**。
- **数值稳定性**：**中**。CAD kernel 是确定性的，无数值发散风险；VAE 潜空间有重构误差（表面点云的 VAE 编码是有损的）。
- **依赖项**：CAD kernel（OpenCascade / build123d / PythonOCC）、预训练 VAE。

## 实验结论

- **数据集**：DeepCAD 测试集
- **基线**：任务专用基线；以及用**相同 DSL 提示的通用 LLM**
- **结果**：
  - 在**几何精度**与**输出有效性**上**超过任务专用基线**
  - **在需要更多操作的模型上增益更大** ⇒ 印证了「错误会级联」的诊断
  - 几何精度**优于通用 LLM**（同 DSL 提示）
  - 消融：下一状态监督使平均 Chamfer 距离**降低 13.2%**

## 局限性

- **推理串行**：每步要跑 CAD kernel + 重新编码 ⇒ 无法批量并行
- **状态编码有损**：VAE 编码表面点云是压缩的，细微几何差异可能被抹平
- **依赖 DeepCAD 的轨迹构造**：方法的有效性部分依赖于**专家级文本描述**的质量 —— 这些是自动配对还是人工标注，摘要未明说
- **只能建模「已存在于轨迹中」的操作** —— 泛化到新操作组合的能力受限
- 摘要未给出具体数值（只有消融的 13.2%）

## 实现建议

- **实现难度**：**中**
- **预期性能**：串行推理（步数 × kernel 耗时）
- **适用场景**：**文本 → 参数化 CAD 模型的程序化生成**（设计草图自动化、方案探索）
- **对团队的直接价值**：**高**。「**下一状态监督**」是一个**可迁移的范式**：

> 💡 只要我们的生成系统是「离散操作序列 + 连续几何结果」的结构，就可以加一个「下一状态」辅助头。而且关键细节是：**辅助头与动作头共享主干**（不是独立网络），这样几何监督才能传导。

这个模式适用于：CAD 脚本生成、网格编辑操作序列生成、分层建模命令生成。

## 可直接抄的工程结论

1. **「操作级」监督不够，要加「状态级」监督**。仅监督输出（动作）允许模型完全绕过状态表征；监督「状态如何变化」强迫模型建立几何内部表示。
2. **辅助头必须共享主干**，否则几何监督学不到动作上。
3. **诊断「错误会级联」的论文，其增益应当在「操作数更多」的样本上验证** —— 这是本文实验设计中最值得学的一点。
4. **在线重编码形成闭环** —— 执行后立刻把结果反馈回模型，比一次性生成全部命令更可靠。
