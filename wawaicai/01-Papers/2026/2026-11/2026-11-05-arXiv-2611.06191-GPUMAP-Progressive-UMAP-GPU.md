## 核心贡献

> 把 UMAP 拆解为**三个原子操作**，重组为**渐进式（progressive）流水线**，并用 GPU 加速：使**百万级数据集**的降维可**交互式**完成。

1. **原子操作分解**：识别 UMAP 内部的**三个原子操作**，重构为渐进流水线
2. **UMAP 的实质性改造**：
   - **操作队列（operation queues）**
   - **实例级局部连接（instance-wise local join）**
   - **调度策略（scheduling strategies）**
3. **GPU 并行加速**：在**普通消费级 GPU** 上实现百万级数据的交互式分析
4. **渐进式行为研究**：系统研究渐进降维的行为 —— 投影如何随时间演化、相对真值投影的偏差，以及**有偏数据流**如何影响投影质量与稳定性

## 技术方案

### 核心思想

```
UMAP（原始）：
   高维最近邻搜索 → 模糊隶属度 → 谱布局优化（全局）
        ↓ 成本高，交互式不可行
GPUMAP：
   拆为三个原子操作 → 渐进式流水线（每步只做局部工作）
        ↓
   操作队列 + 实例级局部 join + 调度策略（GPU 友好）
        ↓
   百万级交互式
```

### 关键技术

| 技术 | 说明 |
|------|------|
| **渐进式降维** | 分步推进，中间结果即为"当前最佳投影" ⟹ 可随时中断/交互 |
| **三个原子操作分解** | 论文的核心分析贡献 |
| **操作队列** | GPU 上的任务调度抽象 |
| **实例级局部连接** | 把"邻接关系计算"改为逐实例独立 ⟹ 天然并行 |
| **调度策略** | GPU 资源利用优化 |
| **有偏数据流分析** | 渐进式下数据分布偏斜对结果的影响（论文的实证部分） |

## 算法复杂度

- **时间复杂度**：渐进式 ⟹ 单步成本低；总成本仍与 UMAP 同阶但可分摊到交互帧
- **空间复杂度**：$O(n)$（GPU 显存）
- **目标**：百万级数据集，普通消费级 GPU，交互式

---

## 实现难度

- **算法复杂度**：**中** — UMAP 已有成熟实现（`umap-learn`），改造点明确
- **数值稳定性**：**中** — 降维本身是启发式算法，质量依赖超参（论文正好研究了这一点）
- **依赖项**：CUDA；可基于 `umap-learn` / `cuML`（RAPIDS 已提供 GPU UMAP）
- **⚠️ 定位提醒**：**这篇本质上是机器学习 / 数据可视化论文，不是几何处理论文**。收录理由：① 主分类含 cs.GR；② **"渐进式"的降维思想与几何处理中的渐进式网格简化（progressive simplification）高度同构**，思路可迁移

---

## 实验结论

- 消费级 GPU 上百万级数据集**交互式**降维
- 系统研究渐进式降维行为：投影演化 vs 真值投影；有偏流对质量与稳定性的影响

---

## 局限性

- 降维结果质量仍依赖 UMAP 超参（n_neighbors, min_dist）
- GPU 显存限制
- 渐进式早期阶段的投影质量低于最终结果
