# Same Pixels, Different Documents: Measuring Part-Level Editability in Image Vectorization

## 核心贡献

> 矢量化评估长期只看渲染保真度，但**渲染相同的文档可能支持完全不同的编辑**。本文提出 **Pass@k** 指标来量化「零件级可编辑性」，并配套八项文档诊断。

1. **Pass@k 指标**：检验一个指定编辑能否在**指定交互模型**下、于 **k 次点击**内可选中的对象上成功完成。
2. **八项文档诊断**：刻画编辑相关的属性（超出任务本身）。
3. **三类评估轴**：
   - **结构敏感性** — 通过受控扰动
   - **实际相关性** — 通过设计师真实操作
   - **参考依赖性** — 通过不同替代绘制
4. **大规模实证**：12 个开源与商用方法，211 个参考图，93 个上执行 **635 个编辑任务**
5. **关键发现**：在四组参考集（含两组设计师手绘）上，**64–88% 的 oracle-passed 任务**在零件由多个碎片组成时失败——即"oracle 通过"掩盖了选择成本。

---

## 技术方案

### 核心思想

传统矢量化评估的三个盲区：

| 盲区 | 问题 |
|------|------|
| 渲染保真度 | 无法区分"渲染一致但编辑能力不同"的文档 |
| Oracle 式编辑评估 | oracle 收集零件碎片会**掩盖选择成本** |
| 单一参考图 | 不测参考依赖性 |

Pass@k 把评估从「编辑是否成功」改为「**编辑能否在 k 次点击内完成**」，从而把**零件选择成本**纳入指标。

### 关键技术

| 技术 | 说明 |
|------|------|
| **Pass@k** | 在指定交互模型下，k 次点击内可选中的对象能否支持指定编辑 |
| **八项文档诊断** | 刻画编辑相关属性（结构组织、零件粒度、图层语义等） |
| **结构敏感性评估** | 受控扰动（controlled perturbations）—— 系统性改变文档结构看指标退化 |
| **实际相关性评估** | 设计师实际操作（designer operations） |
| **参考依赖性评估** | 替代绘制（alternative drawings） |
| **规模** | 12 方法 / 211 参考 / 635 任务 / 93 参考含任务 |

---

## 实验结论

- **数据规模**：211 个参考图，其中 93 个承载编辑任务，共 635 个编辑任务
- **参考集**：四组参考集，**其中两组由设计师手绘**
- **核心数字**：**64–88% 的 oracle-passed 任务**在零件由多个碎片（multiple fragments）组成时失败

---

## 局限性

- 交互模型是假设的，不同编辑器的交互范式差异可能影响结论
- 635 个任务仍属中等规模
- 依赖设计师操作的部分存在主观性

## 实现建议

- **实现难度**：**中**（作为评估框架）/ **低**（作为消费方）。需要：矢量格式解析（SVG path）、零件分组、模拟 k 次点击的选择模型、编辑算子定义。
- **数值稳定性**：编辑成功判定是**离散**的，需要明确定义容差（几何容差 / 语义容差）；Pass@k 是阶跃函数，样本量小时方差大
- **依赖项**：SVG 解析（svgpathtools / lxml）、几何距离（CGAL / shapely）
- **适用场景**：
  - 评估矢量化工具（Inkscape 自带、Adobe Illustrator、autotracer、vtracer 等）
  - 为 3D 编辑器/几何工具设计「零件级可编辑性」的类比指标 —— **对几何处理社区有间接价值**：这本质是「拓扑/语义分组质量」的评价问题，与网格分割、UV 岛划分、材质槽划分的评估诉求高度同构
- **对几何处理的价值**：**Pass@k 的思想可直接迁移**。例如评估网格分割算法时，可以问「要选中一个语义零件，用户需要点多少次？」—— 这比 IoU 更贴近实际编辑体验。
