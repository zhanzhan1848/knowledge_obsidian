## 核心贡献

> v3 引入**100 任务**基准（30 text-to-CAD 创建 + 30 text-to-CAD 创建并编辑 + 40 工程图重建机械零件），agent 在**固定版本的 FreeCAD 环境**中工作，提交**原生 CAD 产物**给独立的程序化验证器。主指标是**连续任务奖励**（几何相似度 + 规格一致性），而非二值成功率。

1. **原生 CAD 产物 + 独立验证器**架构 —— agent 提交 FreeCAD 原生文档，验证器独立程序化评估。
2. **主指标改为连续奖励** —— 合并几何相似度与规格一致性，而非二值任务成功。
3. **覆盖三种任务形态** —— 文本创建、文本创建+编辑、工程图逆向重建。
4. **版本化任务、评估配置与可检视结果产物** —— 完全可复现。

## 技术方案

### 核心思想

**评估理念的三层递进**（v2 → v3 的关键变化）：

| 层次 | 内容 | v3 的处理 |
|------|------|----------|
| 1. **能否构建** | 生成了可执行的 CAD 脚本 | 不再是充分条件 |
| 2. **几何是否正确** | 结果几何与目标形状相似 | 纳入连续奖励 |
| 3. **规格是否满足** | 指定尺寸（工程图标注）一致 | 纳入连续奖励 |
| 4. **建模历史是否合理** | 原生 CAD 建模历史 | 新增评估维度 |

> **关键论点**：「Producing an executable CAD script is not sufficient to establish that an agent has satisfied an engineering design request.」

### 关键技术

| 技术 | 说明 |
|------|------|
| **固定版本 FreeCAD 环境** | 环境 pinned → 消除 FreeCAD 版本差异导致的不可比性 |
| **原生 CAD 产物提交** | agent 提交 FreeCAD 原生文档（而非渲染图/网格）→ 验证器可检查完整建模历史 |

## 复杂度分析

- **评估侧**：每个任务需在 FreeCAD 中加载 agent 产物、重建几何、计算几何相似度、抽取尺寸与规格比对 → 单任务数十秒级（FreeCAD 脚本执行 + 几何计算）
- **任务集规模**：100 任务 × 13 系统 = 1300 次评估运行 → 全量评测需数小时
- **产物存储**：原生 CAD 文档 + 渲染结果 + 验证报告

## 数值稳定性

- **规格一致性容差**：工程图尺寸是离散标注，浮点几何必然有偏差 → 验证器需容差策略（论文细节在验证器代码中）
- **几何相似度度量**：连续奖励避免了二值阈值带来的信息丢失，但也更敏感于度量选择
- **环境 pinned**：FreeCAD 版本固定消除了 kernel/几何引擎差异引入的不确定性 —— 这是评估可复现性的基础
- **原生产物验证**优于网格/截图验证：能捕获「几何对了但建模历史非法」的情况

---

## 局限性

- **任务规模仍小**（100 任务），统计功效有限
- **FreeCAD 专用**：评估管线绑定特定 CAD 内核，迁移到其他 CAD 需重写验证器
- **结果依赖智能体框架**：分数反映系统而非模型，跨论文比较需谨慎
- **工程图任务仅 40 个**：逆向重建这一最难的形态覆盖不足
- **只报告点估计**：论文提到「highest overall point estimate」，未详述置信区间处理
