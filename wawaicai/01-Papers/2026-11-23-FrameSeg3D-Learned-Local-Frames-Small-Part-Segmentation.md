## 核心贡献

> **核心诊断：小部件分割的精度瓶颈不在「有多少点落在部件上」，而在「部件被看到的方式」（从哪个方向、以什么尺度）。** FrameSeg3D 因此预测每个部件的**局部坐标系**，把分割变成一个规范化的、可跨部件类型共享的问题。

1. **问题诊断的重新表述**：指出两类现有方法都失败的原因——
   - *整体处理类*：点/网格网络必须缩小扫描以适应显存，**小部件只保留少数几个点**；多视图方法渲染整个物体，**每个部件只占几个像素**，且倾斜部件只能从侧面看到
   - *先定位再近距分割类*：定位用的是**某一种部件的知识**（如牙弓形状找牙齿），**无法迁移到其他部件**
2. **学到的局部坐标系（learned local frames）**：从低分辨率的整体视图预测每个部件的**中心 + 朝向方向**，再**绕法线方向取多视图**、在**扫描仪原生分辨率**下分割该部件。
3. **分辨率成本解耦**：因为每个视图只覆盖一个部件，**覆盖整个扫描不再消耗分辨率**
4. **单一网络跨部件类型**：每个部件到达分割网络时都是**居中、正对相机、固定尺度**的，因此**一个分割网络可服务不同类型的部件**，且能从**少量标注掩码**学习
5. **验证**：在**指甲**（手部扫描）和**牙齿**（口内扫描）两类部件上测试，超越对比方法

## 技术方案

### 核心思想

**关键洞察（论文原话大意）**：

> 精度受限于**部件如何被看到**（从哪个方向、以什么尺度），而不是**有多少点落在它上面**。

这与传统直觉相反——通常认为「部件太小 → 点不够 → 要更高分辨率 / 更多点」。论文指出真正的解法是**改变观测坐标系**。

于是：
1. **阶段一（低分辨率）**：从整体扫描的低分辨率视图，预测每个部件的**局部坐标系**（中心 + 朝向）
2. **阶段二（原生分辨率）**：把相机摆到该部件法线周围的一圈，在**扫描仪原生分辨率**下渲染该部件，做分割

因为每个部件都被**归一化**（居中 + 正对 + 固定尺度），一个分割网络即可通用。

### 关键技术

| 技术 | 说明 |
|------|------|
| **局部坐标系预测** | 从低分辨率整体视图预测每个部件的**中心** $c$ 与**朝向** $n$（一个局部正交基） |
| **法线环绕多视图** | 相机在部件法线周围的一圈采样角度，绕开「倾斜部件只能从侧面看」的问题 |
| **原生分辨率渲染** | 每个视图按扫描仪原生分辨率渲染**部件局部区域**，而非缩放后的整体 |
| **视角归一化（canonicalization）** | 部件被平移到中心、旋转到正对相机、缩放到固定尺度 → 跨部件类型共享网络 |
| **单一分割网络跨类型** | 指甲 / 牙齿 / 其他部件共用一个网络，因为输入已被规范化为同一分布 |
| **少标注学习** | 规范化后，部件类型差异被消除，**少量标注掩码即可训练** |
| **自适应采样（隐含）** | 部件检测在低分辨率做（便宜），分割在高分辨率做（贵但只针对单部件） |

### 公式

**局部坐标系定义**

```math
\mathcal{F}_i = \big(c_i \in \mathbb{R}^3,\; n_i \in \mathbb{S}^2,\; t_i \in \mathbb{R}^3\big), \qquad t_i \perp n_i
```

$$\mathcal{F}_i = \big\{ c_i,\; n_i,\; t_i \big\}$$

> $c_i$ 部件中心，$n_i$ 朝向（法线），$t_i$ 切向。构成局部正交基。

**相机位姿（法线环绕采样）**

```math
\mathbf{cam}(\theta, \phi) = c_i + R_{\mathcal{F}_i}\,\begin{pmatrix} \sin\phi\cos\theta \\ \sin\phi\sin\theta \\ \cos\phi \end{pmatrix} d
```

$$\text{视角集合}:\; \theta_k = 2\pi k/K,\qquad \phi \in \{0, \pm\phi_0\}$$

> $K$ 个方位角 × 若干仰角。俯仰角 $\phi_0$ 的选择很关键——需要能覆盖部件的实际朝向范围。

**视图规范化（canonicalization）**

```math
\tilde{p} = S \cdot \left[ R_{\mathcal{F}_i}^\top (p - c_i) \right], \qquad S = \text{diag}(s,s,1)
```

$$\text{渲染分辨率}:\; \frac{W_{\text{scan}}}{W_{\text{render}}} = \text{原生分辨率比例}$$

> 部件在渲染图像中占据固定比例 → 尺度一致。

**视角一致性聚合**

```math
\mathcal{L} = \sum_{v \in \mathcal{V}} w_v \cdot \mathcal{L}_{\text{seg}}(m_v, \hat{m}_v)
```

$$w_v = \text{visibility}(v)\quad\text{或由光流/一致性加权}$$

> 多视图分割结果需融合（投票 / 平均 / 图优化）。

### 复杂度

- **阶段一（部件检测 + 局部系预测）**：在低分辨率图上跑网络 → $O(W_{\text{low}}^2)$ per 部件候选，远便宜
- **阶段二（多视图渲染 + 分割）**：$K$ 视图 × 每视图原生分辨率像素 → $O(K \cdot W_{\text{scan}}^2)$，**主要成本**
  - 实践中每视图只渲染部件的 **bounding box 区域**，不是整个扫描 → 成本远低于 $K \cdot W_{\text{scan}}^2$
- **总**：$O(W_{\text{low}}^2 + K \cdot W_{\text{bbox}}^2)$
- **对比基线**：整体点/网格网络需下采样到显存可容纳 → 部件只保留少数点；多视图整体渲染 → 部件只占几个像素

## 实验结论

- **数据集 / 任务**：两类部件
  - **指甲** — 手部扫描
  - **牙齿** — 口内扫描
- **对比方法**：整体处理的点/网格网络路线、整体多视图渲染路线、「先定位再近距分割」路线（用部件专用知识）
- **结果**：FrameSeg3D 在两类部件上**均超越对比方法**
- **消融**：验证了局部坐标系预测、法线环绕采样、原生分辨率渲染、规范化共享网络各组件的贡献
- **规模**：31 页 16 表 → 消融充分

## 局限性

1. **依赖「有局部坐标系真值」或强监督来学**——局部坐标系预测器的训练数据获取方式（人工标注？伪标签？）论文需明确
2. **要求部件是「有朝向的」**——如指甲、牙齿这类有明确朝向的部件最合适；对**各向同性**部件（如球状凸起、斑点）局部坐标系无意义，方法退化
3. **多视图渲染成本**——$K$ 视图 × 原生分辨率的渲染开销大；纯 GPU 光栅化实现需要工程优化
4. **视图融合未充分论证**——多视图分割结果如何一致融合（尤其部件遮挡时）是难点
5. **未覆盖「部件数量先验未知」的场景**——需要先检测出部件
6. **31 页 + 16 表但只有两类部件**——泛化性到更多类型待验证

## 实现建议

- **实现难度**：**中高**。需要：
  - 3D 扫描数据加载与多视图渲染（nvdiffrast / PyTorch3D / OpenGL）
  - 部件检测 + 局部坐标系回归网络
  - 规范化的分割网络
  - 多视图融合
  - **难点**：① 部件检测器（这是前置依赖）；② 局部坐标系的**回归质量**（中心预测容易、朝向预测难）；③ 跨视图融合的一致性
- **数值稳定性**：**好**。几何部分只是中心 + 方向的回归，无迭代求解；主风险在**朝向预测的模糊性**（对称形状下朝向有歧义，需靠损失项或数据结构打破对称）
- **适用场景**：
  - ✅ **高分辨率 3D 扫描的小部件分割**（牙科、手部建模）——这是精准定位的场景
  - ✅ 标注掩码稀缺但部件类型多样（规范化让少量标注可跨类型泛化）
  - ✅ 有明确朝向的细长/扁平部件
  - ⚠️ 部件数量未知或无朝向的斑点状结构
  - ❌ 大规模场景级点云（低分辨率定位的思路不适用）
- **落地建议**：
  1. **「规范化消除类型差异」是本文最可迁移的通用思想**——任何「小目标分割」任务都可套用：预测局部系 → 规范化 → 统一分割器
  2. 局部坐标系可用**PCA + 主轴消歧**作为弱监督初始化，再训网络细化——避开朝向监督的获取难题
  3. 渲染用 **nvdiffrast** 增量实现（只渲 bbox 区域），比全扫描渲染省几个数量级
  4. 多视图融合可先用**概率平均 + 可见性掩码**做基线，再考虑图优化
