# MEvince: Knowledge-Constrained LLM Reasoning for Technique Identification from Malware Reports

### 核心贡献
1. 提出 MEvince：一个知识约束的 LLM 推理框架，用于从恶意软件分析报告中做 report-level 的 ATT&CK technique 识别；其核心是一个连接「报告观测」与「技术定义」的**共享行为表示**（shared behavioral representation）。
2. 该共享表示通过 agentic mining of technique documentation 构建，并支撑两个在线阶段：primitive-guided extraction（用行为原语结构化 LLM 抽取的观测、链接源段落、聚拢分散证据）与 evidence-aligned retrieval（通过同一套概念把证据匹配到技术画像，同时保留可能候选与易混淆的替代项供 LLM 做区分性行为比较）。
3. 在两个阶段都设置了 controls 以校验证据引用并检查技术特定要求；同时支持无需更新参数的适配——离线 agentic audits 诊断概念弱点并据此精炼抽取或检索策略。

### 技术方案
**核心思想**: 用一套跨「报告文本」与「ATT&CK 技术定义」共用的行为原语/概念作为中间层桥梁，把「证据检索」与「证据抽取」两件事都锚定在同一语义空间，从而迫使 LLM 基于充分证据而非似然关联来判定技术。

| 技术 | 说明 |
|------|------|
| Shared behavioral representation | 连接 report observations 与 technique definitions 的共享表示，作为抽取与检索共同的概念坐标系 |
| Agentic mining | 通过 agentic 方式挖掘 technique documentation，自动构建上述共享行为表示（离线） |
| Stage 1: primitive-guided extraction | 以行为原语（behavioral primitives）结构化 LLM 抽取出的观测，回链到源文本段落（link to source passages），并把分散证据分组（group dispersed evidence） |
| Stage 2: evidence-aligned retrieval | 用同一批概念把证据匹配到技术画像（technique profiles），保留 top 候选 **以及易混淆的替代技术**，供 LLM 比较区分性行为 |
| Dual-stage controls | 两个阶段各设控制机制：验证证据引用有效性（validate evidence references）+ 检查技术特定要求（technique-specific requirements） |
| Parameter-free adaptation | 离线 agentic audits 诊断概念层面的弱点，再据此调整抽取或检索策略，无需更新模型参数 |

### 实验结果
- **数据集**: 自建数据集，包含 **610** 份引用 MITRE ATT&CK 的公开恶意软件分析报告
- **基线**: **11 个**基线，横跨 **4 个方法族**（摘要未列出具体基线名称）
- **结果**: MEvince 在 exact-ID F1 上比最强基线提升 **17.4%**；其 concept-guided retrieval 将 gold-label 候选覆盖率从 **31.6% 提升到 47.9%**；使用一个小型 adaptation set 做离线精炼后可获得进一步增益，并**超过了会更新模型参数的基线方法**

### 局限性
- 摘要未列出 11 个基线的具体名称与所属方法族，也未给出 F1 的绝对数值（仅给出相对提升 17.4%）。
- 数据集为 610 份公开报告，规模有限且集中在 public malware reports；对闭源/内部报告的泛化性未验证。
- 候选覆盖率虽从 31.6% 提升至 47.9%，但仍不足一半，说明检索阶段仍有大量 gold label 被挡在候选集之外——这是错误传播的根源。
- 摘要未说明所用 LLM 底座模型、行为原语体系的构建成本，以及「小型 adaptation set」的具体规模与 agentic audit 的执行开销。

### 关键洞见
> 这篇论文最巧妙的结构是**故意让检索阶段「召回得更多但不判决」**：保留易混淆的替代技术（confusable alternatives）一起交给 LLM 去比较区分性行为，把「判定权」交还 LLM，把「召回调优」交给概念空间。结果证明这是必要的——若检索只给 top-1，LLM 只能靠似然关联硬猜；而召回覆盖率从 31.6% 提到 47.9% 之后，LLM 才有足够的「干扰项」去真正辨别 sibling technique 的细微差异。此外，离线 agentic audit 能在**不动参数**的前提下超过会微调参数的基线，说明瓶颈在知识组织而非模型容量。
