## 核心贡献

> 提出 **reasoning-guided translation framework**，把英文 safety / reasoning benchmark 高保真扩展到 11 种语言。

1. **任务敏感的 translation pipeline**：分离 translation strategy selection 与大规模生成 → 易于控制 + 易扩展。
2. **多组件协同**：reasoning-guided configuration selection + task-aware validation + targeted repair + independent quality screening。
3. **源对齐 collection**：7 个 safety / conversational / math reasoning benchmark × 11 语言，**99.94%** item-language coverage。

---

## 技术方案

### 核心思想

LLM 多语言评测的关键难点：直接翻译会破坏 task-specific meaning（harmful request / math / conversational nuance）。现有方法通常一刀切，难以兼顾 quality 与 scale。

新框架显式拆解：
- **策略选择**：reasoning 引导 → 按任务类型选最佳 translation strategy；
- **批量生成**：大规模 LLM 翻译；
- **质量门**：task-aware validation（数学结果一致？safety refusal 保持？）；
- **定向修复**：针对性改坏样本；
- **独立筛查**：第三方 / 单独 model 做最后过滤。

### 关键技术

| 技术 | 说明 |
|------|------|
| Reasoning-guided config selection | 任务驱动策略 |
| Task-aware validation | 按任务特性验证 |
| Targeted repair | 失败样本定向修正 |
| Independent screening | 第三方质量门 |
| Source-aligned collection | source-target 对齐 |

## 实验结论

- **任务**: safety, conversational, mathematical reasoning（7 个 benchmark）
- **语言**: 11 种
- **覆盖**: 99.94% item-language coverage（需修复子集）
- **关键发现**:
  - 拒绝行为跨语言不一致（safety）；
  - 低资源语言 reasoning 能力大幅退化；
  - 表明多语言评估必须 task-aware，不能靠简单 MT。

---

## 局限性

- 翻译质量仍受制于 backbone LM；
- 11 语言未覆盖 long-tail 语言（如非洲、东南亚少数语种）；
- targeted repair 的 repair budget / saturation 阈值未充分讨论。
