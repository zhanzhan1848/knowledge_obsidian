## 核心贡献

> 提出 **AfterDeleteBench** —— 一个**行为层面**的审计基准，用来检验"删除一条原始记忆后信息是否真的消失"；结论是：**删除原始记录并不足以删除信息**，因为 agent 的外部记忆会衍生出**后代记录（descendants）**（如摘要），信息依然存活其中。

1. **问题重构**：许多 LLM agent 维护**外部持久记忆**并从中**衍生出额外状态**（典型例子：**摘要 summaries**）。因此**删掉原始记忆记录**并不必然删掉其后代携带的信息
2. **受控行为审计方法（fixed-weight agents）**：对每个**合成 secret**，构造两个 agent：
   - **exposed-then-deleted** agent（先接触 secret，再删除）
   - **matched never-exposed control**（其它一切相同，但**从未接触过** secret）
   - 二者之差即可**把删除后恢复归因于原始接触**
3. **主设定结果**：**单次查询**即可从 **Qwen2.5-7B-Instruct** 恢复被删 secret，比例约为**三分之二（roughly two thirds）**；而 matched never-exposed 控制的恢复率为**零**
4. **关键发现 —— 恢复不需要逐字副本**：当**完整 secret 字符串已不存在**、只有**分别存储的组件**残留在一条**公开的组合规则（public composition rule）**之下时，**精确重建在 62–99% 的情况下成功**（跨 **Qwen、Mistral、Phi-3**）
5. **方法论警告 —— 响应接口是测量系统的一部分**：带目标信息的回复**若与请求格式/解析器不对齐，会被计为失败** —— 即评测口径本身可以伪造"已删除"结论
6. **区分三件事**：**重建（reconstruction）** vs **写回（write-back）** vs **新 session 回忆（fresh-session recall）**
7. **缓解对比**：
   - **Provenance-aware closure（溯源感知闭合）**：在测试的正基线设定下**消除了观察到的恢复**
   - **Exact-literal write filter（精确字面写过滤器）**：能**阻止再次写入**，但**无法抹除已经存在的信息**

## 技术方案

### 核心思想

```
删除了原始记录 ≠ 信息被删除

原始 secret
   ├─ 原始记忆记录        ← 被删除
   ├─ 摘要 / 衍生状态     ← 仍携带信息
   └─ 分量 + 公开组合规则  ← 信息以"可组合"形式残留

⇒ agent 仍可重建完整 secret
```

### 关键技术

| 技术 | 说明 |
|------|------|
| **Matched never-exposed control** | 关键对照设计：其它配置一致但**从未接触** secret，用于把恢复归因到原始接触 |
| **Synthetic secrets** | 每个 secret 为合成构造，便于精确测量恢复率 |
| **Fixed-weight agents** | 固定权重的 agent（不训练），把行为差异归因到**记忆系统设计**而非模型能力 |
| **Public composition rule** | 分量分别存储 + 一条公开可查的组合规则 → 测试"信息组合"式恢复 |
| **Three-way decomposition** | 分离**重建 / 写回 / 新 session 回忆**，避免混为一谈 |
| **Provenance-aware closure** | 按**来源（provenance）**追踪并闭合残留记录链 |
| **Exact-literal write filter** | 只拦"逐字写入"，不处理已在库中的信息 |
| **Interface/parser alignment check** | 显式检查"请求格式 ↔ 解析器"是否对齐，防止假阴性 |

## 关键实验结果

### 主设定

| 条件 | 结果 |
|------|------|
| Qwen2.5-7B-Instruct，exposed-then-deleted，**单次查询** | 约 **2/3（roughly two thirds）** 的情况恢复被删 secret |
| matched never-exposed control | **0 恢复（zero recovery）** |
| 恢复是否需要逐字副本 | **不需要** |
| 完整 secret 字符串缺失、仅存分量 + 公开组合规则 | **精确重建成功率 62–99%** |
| 覆盖模型 | **Qwen、Mistral、Phi-3** |

### 缓解手段对比

| 手段 | 效果 |
|------|------|
| **Provenance-aware closure** | **消除**观察到的恢复（在测试的正基线设定下） |
| **Exact-literal write filter** | 阻止**再次写入**，但**不能抹除**已存在的信息 |

### 评测口径的发现

- **响应接口是测量系统的一部分**：若回复格式与解析器不匹配，**带目标信息的回复会被判为失败** → 不做接口对齐检查的删除审计**可能给出虚假的安全结论**

## 关键结论 / 局限性

### 关键结论

1. **"删除"必须在 agent 行为层面审计，不能只在存储层面审计** —— 这是本文的核心论断："source deletion should be evaluated behaviorally at the level of the agent and its memory system, not only as a storage operation"
2. **写入过滤 ≠ 删除**：exact-literal write filter 只能防**未来**写入，对**存量**信息无效 —— 安全承诺会因此高估
3. **溯源是最强的缓解**：provenance-aware closure 是唯一在测试中**消除恢复**的方案
4. **评测本身要防"假阴性"**：删除审计必须先验证解析链路，否则"没检测到恢复"可能只是格式不匹配

### 局限性

- **仅 fixed-weight agent**：不涉及训练或微调引入的记忆（如 fine-tune 泄漏），也未涉及 RL/工具链引入的泄漏
- **合成 secret**：合成 secret 的可组合性（"分量 + 公开规则"）是**被构造出来的**场景 —— 真实数据中"可组合"到何种程度未验证
- **模型规模小**：主结果基于 **Qwen2.5-7B-Instruct**；更大模型是否更易重建（参数记忆更强）未测
- **"在测试的正基线设定下"**：provenance-aware closure 的有效性表述**带有范围限定**，摘要未说明该范围
- **未涉及多轮 / 工具放大攻击**：一次查询即可恢复是主设定，实际攻击者通常可多轮试探 —— 论文未系统评估
- 摘要未给出精确恢复率（只给 "roughly two thirds"）与 62–99% 的逐模型分解
