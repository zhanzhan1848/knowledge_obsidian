# What Carries Forward? Pretraining Disclosure Across Language Model Releases

## 元信息

| 字段 | 内容 |

## 核心贡献

> **「新版本通常比旧版本披露更多」这个假设不成立** —— 对 17 个模型家族的连续版本做审计后发现：**后续发布并不一致地保留早期的预训练披露信息**，而且**总分持平或上升会掩盖指标的丢失**。

1. **研究问题**：理解语言模型如何预训练，需要关于**数据、处理流程、计算资源**的信息。**后续发布是否保留或扩展了早期的披露，此事不明**。
2. **方法**：基于文档的审计（document-based audit）
   - **41 个模型条目**，来自 **17 个家族**
   - **24 项预训练相关指标**，取自 **2025 Foundation Model Transparency Index (FMTI)**
   - 跟踪整体分数与**指标画像（indicator profiles）**，追踪**增益（gains）、损失（losses）、保留的披露（retained disclosures）**
   - **10 个家族**的 **24 组相邻比较**
3. **核心发现**：
   - 分数**下降 11 次**，**上升 6 次**，**持平 7 次**
   - 共 **38 项指标损失**、**28 项增益**
   - **「稳定或上升的分数会掩盖损失」**：
     - **OLMo-2 与 OLMo-3 总分完全相同**，但内部是**3 项增益 + 3 项损失**
     - **Llama-3.1 相对 Llama-2 有所改进**，却在**两项与数据相关的标准上失分**
   - **语料构成与训练算力上的差距持续存在**
4. **结论**：后续发布**不一致地**保留早期预训练披露；呼吁采用**明确标注变化、并说明继承信息适用性**的文档规范。

## 技术方案

### 核心思想

这是一个**文档审计**（document audit）而非技术工作。方法学上的关键洞察是：**总分是粗糙的聚合，会掩盖组成它的指标的进出**。

```text
❌ 只看总分:
   OLMo-2:  72  ──▶  OLMo-3:  72   「持平」
   但内部: 3 项增益(+), 3 项损失(-)

✅ 看指标画像:
   增益: {算力披露, 数据处理, ...}
   损失: {语料构成, 训练算力细节, ...}
   → 净效果相同，但信息处境完全不同
```

### 关键技术

| 技术 | 说明 |
|------|------|
| **FMTI 2025 指标集** | 24 项预训练相关披露指标 |
| **指标画像分析** | 不只看总分，逐指标追踪 |
| **相邻版本比较** | 10 个家族的 24 组相邻比较 |
| **增益/损失/保留三分** | 每个指标在版本间的状态迁移 |
| **「总分掩盖」诊断** | 识别持平/上升但含损失的案例 |
| **文档化规范建议** | 要求明确标注变化与继承信息的适用性 |

## 公式

```math
\text{模型 } m \text{ 的披露分数}:\quad
S(m) \;=\; \frac{1}{24} \sum_{j=1}^{24} \mathbb{1}\big[\text{指标 } j \text{ 已披露}\big]
```

```math
\text{相邻版本差异}:\quad
\Delta_{j}^{(t)} \;=\; \mathbb{1}\big[j \in \mathcal{I}(m_{t+1})\big] - \mathbb{1}\big[j \in \mathcal{I}(m_t)\big]
\in \{-1, 0, +1\}
```

```math
\text{总分变化 vs 指标画像}:\quad
S(m_{t+1}) - S(m_t) \;=\; \frac{1}{24}\sum_{j=1}^{24} \Delta_{j}^{(t)}
\qquad
\text{（求和可抵消，但画像不可）}
```

```math
\text{「掩盖」判据}:\quad
\Big[ S(m_{t+1}) = S(m_t) \;\vee\; S(m_{t+1}) > S(m_t) \Big]
\;\land\;
\Big[ \exists\, j : \Delta_j^{(t)} = -1 \Big]
\;\Longrightarrow\; \text{隐藏损失}
```

## 代码片段

```python
# 概念性伪代码：FMTI 指标画像审计
from dataclasses import dataclass

@dataclass
class IndicatorAudit:
    model_id: str
    family: str
    release: str
    indicators: dict          # {indicator_name: disclosed: bool}
    notes: dict = None        # 证据定位（文档章节/链接）

FMTI_2025_INDICATORS = [
    "corpus_composition", "data_processing_pipeline", "training_compute",
    "deduplication", "data_filtering", "contamination_controls",
    # ... 共 24 项
]

def audit_score(a: IndicatorAudit):
    hit = [k for k in FMTI_2025_INDICATORS if a.indicators.get(k)]
    return len(hit) / len(FMTI_2025_INDICATORS), hit

def compare_releases(prev: IndicatorAudit, cur: IndicatorAudit):
    # 相邻版本比较：分数 + 指标画像（关键）
    s_prev, i_prev = audit_score(prev)
    s_cur,  i_cur  = audit_score(cur)

    gains    = [k for k in i_cur if k not in i_prev]
    losses   = [k for k in i_prev if k not in i_cur]
    retained = [k for k in i_cur if k in i_prev]

    # 「掩盖」检测：分数持平或上升，但存在指标损失
    masked = (s_cur >= s_prev) and len(losses) > 0
    return {
        "score_delta": s_cur - s_prev,
        "gains": gains, "losses": losses, "retained": retained,
        "masked_disclosure_loss": masked,   # ← 本文的真正发现
    }

def family_report(audits_by_family):
    # 跨 10 个家族、24 组相邻比较做汇总。
    stats = {"decrease": 0, "increase": 0, "unchanged": 0,
             "total_gains": 0, "total_losses": 0, "masked_cases": []}
    for family, (prev, cur) in audits_by_family.items():
        r = compare_releases(prev, cur)
        if r["score_delta"] < 0:  stats["decrease"] += 1
        elif r["score_delta"] > 0: stats["increase"] += 1
        else:                      stats["unchanged"] += 1
        stats["total_gains"]  += len(r["gains"])
        stats["total_losses"] += len(r["losses"])
        if r["masked_disclosure_loss"]:
            stats["masked_cases"].append((family, r["losses"]))
    return stats
```

## 实验结论

- **样本**: **41 个模型条目**，**17 个家族**
- **指标**: **24 项**（2025 FMTI）
- **比较**: **10 个家族**的 **24 组相邻比较**

| 统计项 | 数值 |
|--------|------|
| **分数下降** | **11** |
| **分数上升** | **6** |
| **分数持平** | **7** |
| **指标损失总数** | **38** |
| **指标增益总数** | **28** |

- **「掩盖」案例**:
  - **OLMo-2 / OLMo-3**：总分完全相同，内部 **3 增益 + 3 损失**
  - **Llama-3.1 vs Llama-2**：整体改进，但**两项数据相关标准失分**
- **持续差距**: **语料构成**与**训练算力**两项

## 局限性

1. **纯文档审计 —— 测的是「文档写了什么」，不是「实际做了什么」** —— 一份写得很详尽但不准确的报告，在本文口径下是「满分」。这是**根本性局限**
2. **「已披露」的判定标准未说明** —— 24 项指标各按什么粒度算「披露」？部分披露算不算？标准不同会显著改变结论
3. **样本不平衡** —— 只有 10 个家族贡献了 24 组比较，家族内部权重（Llama 和某个小众家族各算一组）没有加权
4. **2025 FMTI 指标本身可能过时** —— 模型已到 2026 年，24 项指标是否仍覆盖当前最重要信息（如 agentic 能力数据、合成数据比例、长上下文合成数据）
5. **不涉及技术侧验证** —— 无法交叉验证文档披露与实际训练配置
6. **无时间趋势分析** —— 只比较相邻版本，未看整体多年趋势
7. **「差距持续存在」的判定标准**未明
8. **结论的规范性建议**（明确标注变化与继承信息适用性）没有落地机制 —— 模型卡模板可以改，但没人强制

## 实现建议

- **实现难度**: 低（读文档、打分、聚合），但**人工标注成本高**
- **预期性能**: 不产生模型性能收益；产出**选型与合规判断**
- **适用场景**: **企业采购模型 / 合规审查 / 自研模型对外披露** —— 「这个模型比上一版披露得更好吗」是个真实的尽调问题
- **落地注意**:
  1. **这是选型工具** —— 如果你在候选模型之间纠结，披露质量本身就是可用的比较维度
  2. **注意它只测「披露」不测「真实」** —— 披露好不等于模型好，也不等于模型诚实
  3. **自研模型可直接借鉴它的画像方法** —— 你的模型卡应该**逐项标注相对上一版的变化**，而不是只给总分
  4. **「继承信息适用性」标注是好实践** —— 新版本沿用旧版数据时，明确说明「哪些部分沿用、哪些变了」

## 我的评注

> 这篇表面上是政策研究，实际给出了一条**具体、可操作的文档方法论**，我觉得这个价值被低估了。
>
> 核心洞察是 **「总分掩盖」**。这在所有聚合评分体系里都是经典陷阱 —— 均分没涨，但有的指标涨了、有的跌了，总体持平意味着**你已经永久失去了其中一部分信息**。论文举的 OLMo-2/OLMo-3 例子很说明问题：同样 72 分，一个是「信息更全」，一个是「信息换了一批」。对依赖这些披露做决策的人来说，这两者的差别巨大。
>
> 而论文更进一步，把它形式化成了一条可检测的判据：
> $$[S_{t+1} \ge S_t] \wedge [\exists j: \Delta_j = -1] \Rightarrow \text{隐藏损失}$$
> 这条判据可以直接用在任何有版本演进的文档体系上，不限于模型卡。
>
> 我认同作者的规范性建议 —— **「明确标注变化并说明继承信息适用性」**。这其实是对模型卡社区一个长期痛点的正确诊断：现在主流模型卡的写法是「这次发布了什么」，而不是「相对上一版，什么变了、什么没变、什么沿用了」。后者才是真正有信息量的披露。
>
> 保留意见：**测的是「文档写了什么」，不是「实际做了什么」** —— 这个局限很大。一份写得漂亮但不准确的报告在这个口径下是满分。所以它的用途应该是**相对比较与尽调线索**，不是**信任度认证**。
>
> 另外样本确实薄：41 个条目、17 个家族，但只有 10 个家族有相邻版本对，24 组比较。而且 **2025 FMTI 的 24 项指标在 2026 年是否还覆盖了最关键的信息**（合成数据比例、agentic 数据、长上下文合成数据），我持怀疑。
>
> 落地判断：**方法论可直接复用，结论当参考**。如果你的团队在写模型卡或在做模型选型，这篇的「画像而非总分」框架值得抄。
