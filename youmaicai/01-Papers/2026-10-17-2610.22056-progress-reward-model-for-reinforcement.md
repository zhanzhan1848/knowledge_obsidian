## 核心贡献

> 传统 RL 难处理**稀疏奖励长程任务**。LLM 增强 RL 现有两类方法各有缺陷：
> - **planning-based**：依赖预定义 skill libraries，**不能优化 low-level control**
> - **reward-based**：需要大量 human feedback 或穷举搜索

1. 提出 **PRM4RL (Progress Reward Model for RL)**：
   - **task planning + dense reward** 整合
   - **高层规划**：把复杂任务分解为简单 subtasks，**每个 subtask 设计 subtask-oriented progress reward**
   - **低层 RL**：用 dense progress reward 学习 control policy
2. 利用 LLM 世界知识生成 progress reward。
3. 弥补 planning-based 与 reward-based 方法的 gap。

---

## 技术方案

### 框架
```
High-level (LLM):  T → {s_1, s_2, ..., s_n}  (subtask decomposition)
Low-level (RL):    optimize policy π(a|s, s_i) with reward r_progress(s, s_i)
```

### Progress Reward
- 不是 terminal reward，而是**到达当前 subtask 的"进度"信号**。
- 用 LLM 评估状态 s 对 subtask s_i 的完成度（dense, 0~1）。
- 比 sparse terminal reward **信号密度高 N 倍**（N = num subtasks）。

### 优势
- **无需预定义 skill libraries** → LLM 生成 subtasks
- **无需穷举 human feedback** → LLM 生成 progress reward
- **可优化 low-level control** → dense reward 提供有效梯度

---

## 实验结论

- 在 long-horizon sparse-reward tasks 上显著超：
  - 纯 LLM planning
  - 纯 LLM reward shaping (terminal)
  - 传统 sparse-reward RL baselines
- PRM4RL 在 sample efficiency + final performance 都更好。

---

## 关键洞察

- **Progress reward 是 sparse-reward RL 的甜点**：比 outcome reward 密度高，比 hand-crafted dense reward 便宜。
- **LLM 的两个角色**：task planner + reward designer — 协同 > 单独。
- 与 hierarchical RL 思想契合。

## 实现建议

- **实现难度**：中（需要 LLM planner 接口 + reward 设计 + RL loop）

- **适用场景**：机器人、游戏、agentic workflow 的 RL 微调

---

## 局限性

- LLM progress reward 学得质量参差 → 需要 prompt engineering。
- 计算成本高（每步都要 LLM inference 或 fine-tuned judge）。
