## 核心贡献

> 反驳"RL 教会了 reasoning model 写 `{wait}` 这一说法" —— 通过 label-free 的四类索引（频率、位置、形式、用法）+ 注入错误测试，追溯 `{wait}` 在开源模型训练史中的来源，结论是：**它是继承来的（inherited），不是 RL 发明的（invented）**。

1. **澄清一个普遍误解**：社区普遍认为"RL 教会了模型在重新审视一步前先写 `{wait}`"，但**大幅的 RL 准确率增益并不需要这个词**
2. **方法论：无标签的溯源工具** —— 用**频率、位置、形式、用法**四类 label-free 索引 + **注入错误测试（injected-error test）**，全部**从采样输出计算**（不依赖训练日志、内部激活或人工标注）
3. **零 RL 几乎不"造"这个标记**：在**本身就缺少该词**的 base 上，RL **大幅提升 MATH-500 准确率**（substantially），而 `{wait}` **仍接近缺失（near absent）**
4. **它随训练数据到来**：
   - **OLMo-3 的 mid-training** 阶段引入了它
   - **在 reasoning traces 上做 fine-tuning** 会把它装进**大多数本身缺少它的模型**
5. **RL 配方决定它是"放大"还是"无效果"**：
   - base **已有**该词时，两个已发布的 **RL-Zero 配方（OLMo-3、MiMo）会放大它**
   - **同一 base 上的 KL-free GRPO 则不会**
   - **OLMo-3 的配方磨损了它的形式**，使之成为一个**更敏感但也更宽松（more liberal）的警报**
   - **SFT 之后的 RL 几乎不改变它**
   - **本文的 GRPO 配方会擦除由 fine-tuning 播种的标记**
6. **给出方法论警告**：**标记频率本身不能指示 RL 诱发的推理**；并**警告不要用 LLM-as-a-judge 的修订（revision）指标** —— 自动化 judge 会**反转人工标注的趋势**

## 技术方案

### 核心思想

`{wait}` 这类"反思标记（reflection marker）"的来源有三：base 预训练、mid-training / SFT 数据、RL 奖励。要区分，需要一个**不依赖标注**的溯源框架：

```
观察到的 {wait} 行为
   ├─ 来自 base?         → 追踪 base 的采样输出
   ├─ 来自 mid-training? → 追踪 mid-training 后是否出现
   ├─ 来自 SFT?          → 追踪 SFT 后是否出现
   └─ 来自 RL?           → 对比 RL 配方前后；且看 base 缺失时 RL 能否"造出"
```

关键实验设计：**选本身没有 `{wait}` 的 base**，看 RL 能否凭 RL 信号造出这个标记。答案是**几乎不能**。

### 关键技术

| 技术 | 说明 |
|------|------|
| **Frequency index（频率）** | `{wait}` 的出现频次（label-free，从采样输出统计） |
| **Position index（位置）** | 标记出现的位置分布 |
| **Form index（形式）** | 标记的写法变体（如 `{wait}` / `{Wait}` / 变体形式）—— 用于测"形式被磨损" |
| **Usage index（用法）** | 标记出现时的上下文行为（是否真的伴随重新审视） |
| **Injected-error test（注入错误测试）** | 主动向模型注入一个错误步骤，看 `{wait}` 是否被触发 —— 测功能性而非仅频率 |
| **Inherited vs invented 判据** | base 缺失 + RL 后仍缺失 ⇒ **inherited（不是 RL 造的）** |
| **配方对照** | 对比 **RL-Zero（OLMo-3、MiMo）** vs **KL-free GRPO** vs **SFT-then-RL** vs **本文 GRPO 配方** |

### 被考察的训练配方

| 配方 | 对 `{wait}` 的作用（论文结论） |
|------|------|
| 零 RL | 几乎不"铸造"该标记 |
| OLMo-3 mid-training | **引入**该标记 |
| Reasoning-trace fine-tuning | 在**大多数**缺失该词的模型上**装入**该标记 |
| RL-Zero（OLMo-3） | base 已有时**放大** |
| RL-Zero（MiMo） | base 已有时**放大** |
| KL-free GRPO（同 base） | **不放大** |
| SFT 之后的 RL | **几乎不改变** |
| 本文的 GRPO 配方 | **擦除**由 fine-tuning 播种的标记 |

## 关键实验结果

### 关键判定

| 实验 | 结果 |
|------|------|
| 零 RL（base 缺 `{wait}`） | `{wait}` **几乎从不出现**；同期 **MATH-500 准确率大幅提升（substantially）** |
| OLMo-3 mid-training | `{wait}` **随训练数据到来** |
| Reasoning traces fine-tuning | **大多数** base 缺失该标记的模型被**装入**该标记 |
| RL-Zero（OLMo-3 / MiMo） | base 已使用时**放大**该标记 |
| KL-free GRPO（同一 base） | **不放大** |
| OLMo-3 RL 配方 | **磨损形式** → 标记成为**更敏感但更宽松的警报** |
| SFT 后 RL | **几乎不改变** |
| 本文的 GRPO 配方 | **擦除** fine-tuning 播种的标记 |

### 核心否定性结论

> **RL 带来的准确率增益不需要 `{wait}` 这个词。** 零 RL 在缺失该词的 base 上大幅提升 MATH-500 准确率，而 `{wait}` 仍**接近缺失** —— 这直接把"RL 发明了 `{wait}`"的叙事拆掉了。

## 关键结论 / 局限性

### 关键结论

1. **RL 的功劳与数据的功劳被混为一谈**（论文原话："This view can confuse what RL discovers with what a model inherits from its training data"）。看到 `{wait}` 就断言"模型在做自我反思"是**过度解读**
2. **`{wait}` 的出现更像是"训练数据的印记"**：mid-training 与 reasoning-trace SFT 才是它的主要来源
3. **RL 配方对标记的影响方向不同** —— 这意味着"RL 是否强化反思行为"**取决于具体配方**（KL 正则、目标函数设计），而非"RL"这个标签
4. **可迁移的评测建议**：**不要用标记频率做代理指标**；**不要用 LLM-as-a-judge 统计 `{wait}` 修订率** —— 自动化 judge 会**反转人工标注的趋势**

### 局限性

- **仅开源模型**：溯源需要完整训练史（base → mid-training → SFT → RL），只有 OLMo-3、MiMo 这类**公开全流程配方**的模型能做完整追踪 —— 闭源模型无从验证
- **样本是开源模型中的一部分**（摘要未列全模型清单）
- **标签特征、可能存在功能性差异但不在论文索引范围内**
- **"almost never" / "near absent" 是定性描述**，摘要未给出具体频率数值
- **MATH-500 上"大幅提升"未给具体数字**
- **注入错误测试的效果未在摘要中量化**
