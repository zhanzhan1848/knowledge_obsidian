## 核心贡献
1. **大规模普查（291 个开源仓库、280 个不同 embedding 表）**：**untied gated/hybrid checkpoint 中 52.6%（20/38）含有范数低于 $10^{-6}$ 的"可达"输入 embedding**，而 untied Transformer 为 30.9%（47/152，在 $t>0$ 或有 BOS 时安全），**weight-tied 模型为 0%（0/101）**。受影响的 token 是普通字符串：Nemotron 的泰卢固语/巴斯克语 subword、Falcon-H1 的西里尔蒙古语词、Mamba-Codestral 的 CRLF 代码片段（`});\r`）、Kimi-Linear-48B-Base 的 chat tag（`<|im_user|>`）、Nemotron-H-4B-Base 的 `<s>`。
2. **给出了成因的闭式解释**：token 从未在预训练文本中出现 → $E_{in}$ 的该行每步拿到**精确零梯度**，而 $E_{out}$ 的该行每步拿到非零 softmax 梯度。tied 权重靠输出梯度维持范数，untied 权重则被 AdamW 的 weight decay 按乘积收缩：

$$\|e_v^{(T)}\|_2 = \|e_v^{(0)}\|_2 \prod_{t=1}^{T}(1-\eta_t \lambda)$$

在 $\eta_{\max}=4\times10^{-4}$（$\lambda=0.1$）下百万步把未见 token 压到 $10^{-12}$，在 $\eta_{\max}=1.2\times10^{-3}$ 下压到 $10^{-35}$。在 OLMoE-1B-7B 的 364M token 语料样本上，251 个 near-zero 行的出现次数全为 **0/251**，而所有出现过的 token 范数都在 $[0.11, 0.60]$。
3. **给出了 gated 结构的梯度放大定理（Proposition 1，两区制 scaling law）**：对于首个 $K$ 个块是 gated、随后第 $K$ 层是 Softmax Attention 的 Pre-RMSNorm 网络，

$$\|\nabla_{e_t} \mathcal{L}\|_2 = \Theta\Big(\min\big(\tfrac{\sqrt{\epsilon d}}{r},\, G_{\min(K,L)}\big)\Big)$$

其中 $r=\|e_t\|_2$，$G_k$ 是前 $k$ 个块的小信号增益上界。存在**inverse-norm 区**（$\propto 1/r$）与**深度饱和区**（上限 $\Theta(G_K)$）两个机制。
4. **定位了"静默丢更新"的数值机制**：PyTorch / HuggingFace Trainer / FSDP2 的全局范数裁剪在 FP32 中累加平方梯度（FLT_MAX $\approx 3.40\times10^{38}$），任何超过 $1.84\times10^{19}$ 的梯度项平方后溢出为 $+\infty$，$c/\infty = 0.0$ **把整批梯度清零且不产生 NaN**。在 Nemotron-3-Nano-4B 的泰卢固语持续预训练中，这导致 **19.8% 的 step 完全丢弃当前 batch 更新**，而 backbone 仍因 stale momentum 与 weight decay 而移动。
5. **提出两个补救方案，均无 step 时间与峰值内存开销**：
   - **GroupClip**（针对已发布 checkpoint）：把 $E_{in}$ 的裁剪与 backbone 解耦，用 64-bit 或 rescaled 范数。**3 行代码**，消除更新丢失并让被触发的行**一步自愈**。
   - **GateFloor**（针对从零预训练）：$g_\delta(z) = \mathrm{SiLU}(z) + \delta$，$\delta \in [0.01, 0.1]$，让 gate 在零输入时保持正值，把近零梯度削减 **28 个数量级**（在 370M 参数规模上），困惑度与基线相当。
6. **因果干预实验（gate patching）**排除了"仅仅切断反向导数"的替代解释：只断开 Layer 0 gate 的反向仍留下 $1.7\times10^{31}$ 梯度；只把 Layer 0 gate 的**前向**以 straight-through 打开（保持全部反向导数）则把梯度从 $2.1\times10^{35}$ 降到 **6.71**。
7. **给出了架构分类表（Table 1）**，说明为何 Kimi-Linear 在 $t>0$ 安全（88）而 xLSTM 爆炸（$1.0\times10^{32}$）——Kimi-Linear 对 $t-3..t$ 做因果卷积使 $q_t$ 在 $t>0$ 非零，xLSTM 只从 token $t$ 投影 $q_t$。
8. **量化了"异常漏斗"**：在 Nemotron-3-Nano-4B 的 1,000 step 泰卢固语 CPT 中，词表的 **0.047%（62 行）** 占 token 的 32.3 ppm，却触发 **22.5% 的 batch**，并在 88.1% 的命中 batch 上造成 FP32 溢出（=全部 step 的 19.8% fresh-batch 更新为零）。

## 问题背景
为了降低长上下文解码成本，越来越多开源模型用 gated recurrence（Mamba、Gated DeltaNet、xLSTM）替换或交错 Softmax Attention——Jamba、Nemotron-H、Falcon-H1、Kimi Linear 都是如此。实践者习惯用 AdamW 把这些 checkpoint 适配到新语言或新 chat 模板上。

问题在于：输入 embedding 矩阵里普通 token 的范数接近 1，但许多 checkpoint 含范数低于 $10^{-6}$（低至 $10^{-36}$）的罕见 script 字符或 chat tag——论文称之为 near-zero token。全参训练时遇到一个这样的 token **既不抛异常也不产生 NaN loss**，但输入 embedding 梯度会增长 30 个（最高 35 个）数量级，在 gated 模型中把整个 batch 的更新静默清零。

已有工作只观察到症状：Land & Bartolo (2024) 记录了欠训练的罕见 token；Takase et al. (2025) 与 OLMo 2 团队记录了 embedding weight decay 导致早期 LayerNorm 梯度轻微上升（因此 OLMo 2 把 embedding 排除在 weight decay 外）。但**没有工作解释为什么这个现象在 gated 模型中致命、在 Transformer 中无害**，也没有工作测量它对后训练的实际影响频率。

标准推理评测几乎不会暴露这个问题（评测 prompt 很少含低资源 subword 或未使用的 chat tag，且完好的输出行在解码时产生正常的 next-token 概率），因此必须直接审计 embedding 矩阵。

## 方法
### 1. 可达性判定
因为原始词表包含未使用的 alignment padding（如 50,257→50,304）与不可达的 byte 条目，论文对每个 $\|e_v\|_2 < 10^{-6}$ 的行应用 Land & Bartolo 的 round-trip 测试：解码 ID $v$ 并单独、及在八个短语模板中重新 tokenize，只有 tokenization 能复现 ID $v$ 才计为**可达**。291 个仓库中 92 个含原始近零行，**67 个（23.0%）含可达的 near-zero token**。

### 2. 传播机制：Transformer vs Gated
Pre-RMSNorm 归一化（$\varepsilon$ 为 floor，通常 $10^{-6}$ 或 $10^{-5}$）：

$$\tilde{h} = \mathrm{RMSNorm}(h) = \frac{h}{\sqrt{\frac{1}{d}\|h\|_2^2 + \varepsilon}} \odot w$$

当 $\|h\|_2 \ll \sqrt{\varepsilon d}$ 时分母近似 $\sqrt{\varepsilon}$，**每层把反向梯度放大 1000×（$\varepsilon=10^{-6}$）或 316×（$10^{-5}$）**。

**Transformer（$t>0$）**：Layer 0 的 Softmax Attention 即使 query 近零也给先前 token 非零权重，把正常尺度的 value 加到 $h_t^{(0)}$ 上，一层内恢复尺度。

**Gated recurrence**：状态 readout 乘上一个在零输入处消失的 current-token 因子：

$$h_t^{(\ell+1)} = h_t^{(\ell)} + W_{o,\ell}\Big(N_\ell\, y_t^{(\ell)} \odot \phi_\ell\big(\tilde{h}_t^{(\ell)}\big)\Big)$$

其中 Mamba / Mamba-2 / Gated DeltaNet 用 $\phi_\ell = \mathrm{SiLU}(W_{z,\ell}\tilde h_t^{(\ell)})$（$\mathrm{SiLU}(0)=0$）；mLSTM（xLSTM）用 $\sigma(0)=0.5$ 的 Sigmoid gate，但矩阵 readout $C_{t-1}^{(\ell)} q_t^{(\ell)}$ 中的 current-token 线性 query $q_t^{(\ell)} = W_{q,\ell}\tilde h_t^{(\ell)}$ 在 0 处消失。微小的 $\tilde h_t^{(0)}$ 于是让 readout 按 $O(r)$ 收缩，并持续复合增益 $\gamma_\ell < \sqrt{\varepsilon d}$。

### 3. FP32 裁剪的数值溢出
设 $G_{emb}=\|\nabla_{E_{in}}\mathcal{L}\|_2$，$G_{other}$ 为 backbone 梯度范数（典型 1–10）。裁剪规则：

$$G = \sqrt{G^2_{other} + G^2_{emb}}, \qquad \alpha_{eff} = \min\left(1, \frac{c}{G + 10^{-6}}\right), \quad c = 1.0$$

两种失效模式：
- **step-size suppression**（$c \ll G_{emb} \le \sqrt{\mathrm{FLT\_MAX}} = 1.84\times10^{19}$，如 Falcon-H1）：$G \approx G_{emb}$ 有限，backbone 梯度被 $\alpha_{eff} \approx c/G_{emb} \ll 1$ 压制。Falcon-H1-1.5B 的早期 step 上，新 batch 的 backbone 位移 $\|\delta\theta^{batch}_{other}\|_2$ 下降 **335×**（从总位移的 36.6% 降到 0.55%）。
- **FP32 overflow 与梯度清零**（任一项 $>1.84\times10^{19}$，如 Nemotron-3-Nano 与 xLSTM）：平方溢出，$G=\infty$，$c/\infty = 0.0$，**所有梯度归零且无 NaN**。Nemotron-3-Nano-4B 的溢出 step 上 backbone 仍在动（$\|\Delta\theta_{other}\|_2\approx0.25$，来自 stale momentum 与 weight decay），但新 batch 位移**恒等于零**（0% 权重不同于 $g_t=0$，而干净 step 上是 42.6%）。新命中的 near-zero 行（$m_0=v_0=0$）拿不到梯度更新，只被 weight decay 微缩，并在每次后续遇到时再次溢出。

### 4. GroupClip
```python
clip_grad_norm_(backbone_params, max_norm=1.0)
gn = embed_tokens.weight.grad.double().norm().item()
embed_tokens.weight.grad.mul_(min(1.0, 1.0 / (gn + 1e-12)))
```
干净 batch 上，当 $G_{emb} \ll G_{other}$ 时 backbone 裁剪与标准全局裁剪一致，而 $E_{in}$ 只差一个常数缩放——该缩放被 AdamW 的二阶矩吸收。触发 batch 上 backbone 更新不受影响（$\alpha_{eff,other}=\min(1,1/G_{other})$）。FP32 解耦可止损并治愈 $G_{emb}\le 1.84\times10^{19}$ 的次溢出尖峰；FP64 版进一步避免 $>1.84\times10^{19}$ 溢出，使**一次单位范数的 AdamW step 就把触发行抬出溢出区**。作者同时指出一个 copy-free rescaled 变体可消除 FP64 的 3.1 GB 瞬时内存开销（附录 D）。

### 5. GateFloor
$$g_\delta(z) = \mathrm{SiLU}(z) + \delta, \qquad \delta \in [0.01, 0.1]$$

在 $z=0$ 处 $g_\delta(0)=\delta>0$，让 $\delta y_t^{(\ell)}$ 通过 gated RMSNorm（因为 $\mathrm{SiLU}(z)\ge-0.278$ 在 $z<0$ 时可能为负，停止放大只需在 $z=0$ 不动点处为正）。$t>0$ 时来自 $s_{t-1}^{(\ell)}\neq0$；$t=0$ 时来自 Mamba-2 默认的 conv1d bias $b_{conv}\neq0$。这让 Layer 0 在 $t>0$ 与 $t=0$ 两种情形下都脱离 sub-$\varepsilon$ 区（等价于 Eq. 4 中的 $K=0$），**零新增参数**，且对 $z\gg0$ 只有线性增长。

## 关键洞察
1. **"数值溢出 + 静默清零"是比 NaN 更危险的失效模式。** IEEE-754 下有限梯度除以 $+\infty$ 得到精确的 0.0，**没有 NaN、没有异常、没有 loss 异常**——损失曲线看起来正常，但 19.8% 的 step 学到了东西吗？零。任何涉及 FP32 平方范数的裁剪/归一化代码都应把这条当作安全审计项。
2. **架构差异的本质是"是否有 multiplicative bottleneck"**：Transformer 用 attention 汇聚先前 token 的正常尺度 value（一层恢复）；gated recurrence 的历史 readout 乘上一个在零输入处消失的 current-token 因子（乘性收缩）。这个区分比"gated vs Transformer"更精确——Kimi-Linear 因为有因果卷积而安全，xLSTM 因为纯线性 query 而爆炸，两者都用 Sigmoid gate。
3. **权值绑定不只是省内存，它还是一个隐式的梯度源。** $E_{out}$ 每步都给所有行非零 softmax 梯度，这正是 tied 模型 0% 患病率的原因。任何"untie 嵌入表"的改动（为了效率或参数独立）都会引入这个隐患。
4. **罕见 token 的失败被 batch 规模放大。** 0.047% 的词表行 → 32.3 ppm 的 token → 22.5% 的 batch 触发。词表级稀有度在 token 级与 batch 级是三个数量级的放大关系，因此"稀有 token 有问题"在统计上不能靠抽样排除。
5. **多语言/模板化工作负载是触发重灾区**：英文 web/SFT/code/math 的 batch 命中率 0.0%，而泰语/蒙古语/泰卢固语 CPT 达 70–100%，Kimi-Linear 的 chat SFT 达 100%（因为 `<|im_user|>` 在 $t=0$）。这为"哪些场景需要担心"提供了清晰的判据。
6. **前向打开 gate 与切断反向是两种完全不同的干预**。朴素地"detach gate 反向"只是掩盖症状（梯度仍 $1.7\times10^{31}$）；真正的修复是让前向 readout 在零输入处非零（$g_\delta(0)=\delta>0$），把 $K=0$ 复位。这两个干预在 Figure 4b 里被干净地区分开，是论文最漂亮的因果实验。
7. **"自愈"是比"止损"更强的目标**：GroupClip 让被触发的行在第一次接触时就离开溢出区（$3.5\times10^{-4}$ step），从而不再重复触发；相比之下 step-skipping / Freeze $E_{in}$ / GradientStabilizer 都会把行永久冻结。
8. **三条可复用的工程准则**：(a) 对 $E_{in}$ 与 backbone 分组裁剪；(b) 预训练时对 $E_{in}$ 关 weight decay；(c) gated recurrence 的输出 gate 加正偏置。

## 局限性
- **审计范围**：291 个 HuggingFace 仓库中只覆盖 open-weight 模型，未覆盖闭源前沿模型与私有 checkpoint；镜像副本只有 11 个且全为 Transformer，抽样可能有偏。
- **普查是静态的**：论文只统计了已发布 checkpoint 的既有近零行，没有追溯或预测"哪些训练配方会产生多少近零行"——只是验证了 Eq. (1) 的收缩律与 OLMoE 的实证吻合，未在受控预训练中直接复现"从正常到近零"的完整轨迹。
- **GradNorm 定理依赖假设**：Proposition 1 假设 $\partial\phi_\ell/\partial\tilde h|_0 \neq 0$、非退化（Assumption B.1）、增益非递减；实际模型中 $\gamma_\ell\in[10^{0.3},10^{3.3}]$ 的巨大跨度使两区制的边界难以精确定位。
- **实验规模偏小**：持续预训练只有 1,000 step、16,384 token/step、3 seeds（泰卢固语与蒙古语各一）；从零预训练最大 370M 参数、1.57B token，**远小于现代预训练规模**，$\varepsilon$、层数、gain 结构在大规模下可能改变结论。
- **GateFloor 只在 Mamba-2 与 3:1 hybrid 上验证**，纯 Sigmoid gate 与 xLSTM 风格的线性 query 变体未测；$\delta$ 的最优值随模型规模可能变化（表中 Mamba-2 165M 上 $\delta=0.1$ 的 PPL 30.78 已略差于基线 30.63）。
- **对已发布 checkpoint 的修复只处理"训练"侧**，不改变推理行为（论文承认推理不受影响）；因此已经发布的模型仍带着这些行。
- **GroupClip 的 FP64 版有 3.1 GB 瞬时内存与 21.2 ms vs 18.8 ms 的 clip 调用开销**（论文提出 copy-free rescaled 变体消除，但正文未给完整数据）；在更小的卡上未验证。
- **batch 触发率是估算值**（$1-(1-p)^{128}$ 基于每文档率），不是直接实测的 batch 级命中率；虽然 1,000-step CPT 的漏斗统计是实测的。
- **未讨论"近零 token 应该被修复"与"近零 token 本来就该被 mask"之间的语义区分**——GroupClip 把行拉回正常范数，可能使某些本应稀疏的 token 变得过于自信；论文只验证 PPL，没有做行为/安全评测。

## 适用场景
- **适合**：任何用 AdamW 全参微调开源 gated/hybrid 模型（Mamba-2、Nemotron-H、Falcon-H1、Kimi Linear、Jamba 系）的工程实践，尤其是多语言持续预训练、领域继续训练、以及使用非英语 chat template 的场景；也适用于从零预训练 gated 模型的团队（GateFloor + 对 $E_{in}$ 关闭 weight decay）。GroupClip 的三行代码可直接落地到任何 PyTorch/HF Trainer 训练脚本。
- **不适合**：LoRA / QLoRA 等冻结嵌入表的微调（该失效模式不触发）；只做推理或只做 LoRA 的部署；标准 Transformer 微调（untied Transformer 在 $t>0$ 或有 BOS 时安全，但仍值得加 GroupClip 兜底）；从零预训练标准 Transformer（GateFloor 无对应物）；已经在 $t=0$ 位置使用近零 chat tag 的模型（该场景下即使 tied 也会触发，需要额外处理）。
