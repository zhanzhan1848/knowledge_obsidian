## 核心贡献

> 对 25 个预训练数据配方 × 3 个预训练 seed × 2 个后训练 seed 共 **150 个模型** 的逐 prompt 非拒答率相关性分析表明：**同一预训练 run 的两份拷贝相关 0.984，换一个预训练 seed 就掉到 0.811，换一个数据配方只再掉到 0.779**——即「哪些 jailbreak 能打破一个 checkpoint」主要是**该次预训练 run 的指纹**，而非数据配方的属性；这一"ancestry gap"在 25 个配方中全部成立，在 150M / 300M / 1B 三个规模上同样成立（ancestry gap 分别为 0.204 / 0.211 / 0.171），且 ancestry gap 是 same-recipe 与 cross-recipe 差值的 **5.4 倍**。

1. **150 个模型的大规模受控网格** — 基于 **DataDecide** 发布的 1B base 模型：**25 个数据配方 × 3 个预训练 seed = 75 个 base 模型**，每个 base 模型做 **2 个 post-training seed** 的安全后训练（主配方 DCLM-Baseline 额外做 4 个 seed，即 12 个模型），共 **150 个模型**；每个 base 模型训练 **100B tokens**。预训练 seed 同时决定**模型初始化**与**数据顺序**（dropout 关闭，seed 是唯一受控随机源）。
2. **核心相关性排序（1B，全部 25 个配方平均）** — **MZ twins**（同一预训练 run、不同 post-training seed）**0.984 [0.982, 0.985]**；**same-recipe pairs**（同配方不同预训练 seed）**0.811 [0.804, 0.817]**；**cross-recipe pairs**（不同配方不同 run）**0.779 [0.766, 0.788]**。ancestry gap `r_MZ − r_S` = **0.173 [0.167, 0.179]**，而 same-recipe 减 cross-recipe 仅 **0.032 [0.024, 0.043]** → ancestry gap 是后者的 **5.4× [4.0, 7.2]**。每个配方内部 ancestry gap 落在 **0.145–0.209**，且 prompt-bootstrap 区间在 **全部 25 个配方**中都高于 0，三类 pair 的排序也**在每个配方中都成立**。
3. **数据配方影响「被打破的频率」，预训练 run 影响「被哪些 prompt 打破」** — 方差分解：**data recipe 49% [12%, 70%]**、**recipe 内的 base model 32% [16%, 59%]**、**post-training seed 19% [11%, 37%]**。即：数据配方对「平均脆弱性」影响很大，对「哪些 prompt 有效」影响很小。
4. **单模型不足以比较数据配方** — 三个 base model 各配 1 个 post-training seed 可把「单模型与其配方均值」的偏离从 **3.44 点降到 1.99 点**；若两个配方各只用 1 个模型比较，**23.4%** 的比较中按平均脆弱性的排序会被反转（对比各配方 6 个模型合并给出的排序）。
5. **攻击模板排名几乎不跨预训练 run 迁移** — **91 个** attack template 中最好的那个，在**换了 post-training seed** 后仍最好的比例为 **67% [55%, 79%]**，而在**换了预训练 seed** 后只有 **27% [19%, 35%]**。更强的证据：单模型上领先 10–20 分的 template 差距，被 MZ twin 逆转的概率只有 **2.2% [1.9%, 6%]**（原文为 [1.9%, 2.6%]），same-recipe partner 逆转 **25.3% [24.5%, 26.2%]**，cross-recipe partner **26.6%**；领先超过 20 分时，same-recipe partner 仍逆转 **8.9%**，而 MZ twin 只逆转 **0.05%**。
6. **预训练 run 留下可识别指纹** — 用逐 prompt 非拒答率做匹配，跨全部 **75 个 run** 中**每次都（75/75 次）**能正确识别自己的预训练 run（随机猜测为 1/75）；**随机抽 50 个 prompt 仍有 98%** 的正确率（200 次随机子集平均）。同一匹配若改为识别数据配方，只对 **24/50（48%）** 正确（随机为 1/25）——即配方信号在全部 3,211 个 prompt 下也只能达到约二分之一。
7. **单条 prompt 也携带 run 信息** — 一个「在 10 次里至少破 9 次」的 prompt，在其 MZ twin 上复现率 **75.0%**，在同一配方的另一个 run 上只有 **60.9%**。
8. **消除 template / request 效应后 ancestry gap 反而扩大** — HarmBench 的 **1,212** 条 human-jailbreak prompt 由 **300** 个 harmful request × **91** 个 template 组合而成；对每个模型做一次最小二乘拟合估计「模板强度」与「请求难度」并从脆弱性中扣除后，ancestry gap 从 **0.210 升到 0.525**。
9. **换安全数据集不改变结论** — 把 Tülu 3 的 SFT 安全数据替换为另一套公开安全数据（DPO 不变），ancestry gap 为 **+0.178**，同批 base model 与 seed 上 Tülu 3 的 ancestry gap 为 **0.175**。
10. **人工标注审计支持结论** — 4 个模型（2 个 MZ pair + 4 个 same-recipe pair）、2 名作者、100 条 adversarial-harmful prompt、每模型每 prompt 3 个样本共 **1,200** 条响应；作者标签的 ancestry gap 为 **0.156 [0.036, 0.294]**（judge 在同样响应上为 0.203）；作者在 refusal 上的 Cohen's κ = **0.65**，WildGuard 标注者的 Fleiss κ = **0.72**。

## 技术方案

### 核心思想

标准 jailbreak benchmark 的隐含假设是：**「哪些 jailbreak 能打破这个 checkpoint」是它预训练数据与安全训练的属性**。本文提出一个尖锐的反驳：这个集合（论文称之为 **vulnerability profile**）更像是**某一次具体预训练 run 的指纹**。

要检验这一点，需要构造「除一个变量外完全相同」的模型对。作者用 DataDecide 提供的 **25 个数据配方 × 3 个预训练 seed = 75 个 base 模型**，再对每个 base 模型做**相同的**安全后训练流程但用不同 post-training seed，得到 150 个模型。关键设计是：

- **post-training seed 只控制训练样本顺序**，其余（数据、算法、超参）完全一致 → 得到 **MZ twins**（同卵双胞胎：共享同一预训练 run）；
- **pre-training seed 同时控制初始化与数据顺序** → 得到 **same-recipe pairs**；
- 跨配方 → **cross-recipe pairs**。

于是三个相关系数构成一条因果链：

```
r_MZ (0.984)  >  r_same-recipe (0.811)  >  r_cross-recipe (0.779)
```

关键在于 **0.984 → 0.811 的落差远大于 0.811 → 0.779**：换一次预训练 run 损失的相关性，远大于换一份数据损失的相关性。**数据配方的属性不足以决定哪些 jailbreak 有效。**

### 「ancestry gap」作为核心量

作者定义 **ancestry gap = r_MZ − r_same-recipe**，即「共享同一次预训练 run」额外买到的相关性。它在 25 个配方中全部为正、区间全部不含 0，在 150M/300M/1B 三个规模上分别达 **0.204 / 0.211 / 0.171**。

### 排除竞争解释

作者做了三组关键的排除性实验：

1. **去掉 template 与 request 效应** — HarmBench 的 1,212 条 prompt 结构规整（300 请求 × 91 模板），因此可以对每个模型用一次最小二乘拟合估计每个模板的强度与每个请求的难度，再从逐 prompt 脆弱性中扣除。ancestry gap 从 **0.210 升到 0.525**——说明 MZ twins 共享的不只是「哪些模板/请求有效」。
2. **部分重跑（partial reruns）** — 预训练 seed 同时绑定初始化与数据顺序，作者用 **16 个模型**（base model 1、2 与两次部分重跑，各 4 个 post-training seed）拆分这两个因子：共享都不共享的 pair 相关 **0.823**，只共享初始化 **0.822**，只共享数据顺序 **0.822**；相对「都不共享」，初始化带来的变化 **−0.001 [−0.008, 0.007]**、数据顺序 **−0.001 [−0.008, 0.006]**，三者互相之差 **+0.000 [−0.008, 0.009]**——**三个区间都覆盖 0**，即单独共享任一因子不带来可检测的相关性。
3. **同 seed 完整重跑** — 3 次来自同一预训练 seed 的运行（原 base model + 2 次同 seed 重跑），共 **48 个 model pair**，同 seed 重跑的平均修正相关 **0.844 [0.835, 0.853]**，比 same-recipe pairs 高 **0.030 [0.021, 0.040]**，但远低于 MZ twins 的 0.985。两版重跑之间互相的相关比「重跑 vs 原 base model」高 **0.011 [−0.001, 0.023]**（区间跨 0）——**换硬件与软件栈没有可检测的代价**。结论：新 seed 改变的是「这一次具体的 run」。

### 方法学细节

- **Prompt 集**：来自 7 个公开来源（HarmBench 的 standard / contextual / human-jailbreak 子集、SORRY-Bench、StrongREJECT、XSTest、OR-Bench-Hard-1K、WildJailbreak eval 集）。用 Tülu 3 的 **8-gram test** 移除与后训练数据重叠的 prompt（因 Tülu 3 安全数据含真实世界收集的 jailbreak），并移除超上下文窗口者。过滤后共 **6,226** 条：**1,240** plain-harmful、**1,774** benign、**3,212** adversarial-harmful（后者为主要分析子集）。
- **响应生成**：每个 model–prompt 对采样 **20** 次，vLLM，temperature 1.0，top-p 1，max new tokens 512。
- **Coherence filter**：用规则式过滤移除含重复或 prompt echo 的样本；模型在某 prompt 上若无任何 coherent sample，则该模型在该 prompt 上脆弱性未定义（只有 **1** 条 adversarial-harmful prompt 在某个模型上出现此情况），故需完整 profile 的分析使用其余 **3,211** 条。
- **判定器**：主判定器 **WildGuard refusal label**，辅判定器 **Qwen3Guard-Gen-8B**（主结论在后者下同样成立）。
- **修正相关（corrected correlation）**：对每个模型做一次最小二乘拟合，把「模板强度」与「请求难度」作为协变量扣除后再算相关。
- **人类审计**：2 名作者独立标注 4 个模型的 1,200 条响应，并计算作者间 Cohen's κ 与 WildGuard 标注者间 Fleiss κ。

### 关键技术

| 技术/方法 | 说明 |
|------|------|
| **MZ twins（单卵双胞胎）** | 共享同一预训练 run（含其 seed），仅 post-training seed 不同 |
| **Same-recipe pairs** | 共享数据配方，使用不同的已发布预训练 seed |
| **Same-seed reruns** | 重复同一已发布 run 的初始化与数据顺序，因硬件/软件变更与 GPU 非确定性而不同 |
| **Partial reruns** | 分别只共享 base model 1 的初始化，或只共享其数据顺序 |
| **Cross-recipe pairs** | 既不共享配方也不共享预训练 run |
| **Vulnerability profile** | 每模型在每个 prompt 上的非拒答率向量（模型–prompt 对 × 20 次采样） |
| **Ancestry gap** | `r_MZ − r_same-recipe`，衡量「共享同一次预训练 run」额外买到的相关性 |
| **Corrected correlation** | 扣除最小二乘估计的模板强度与请求难度后的相关 |
| **Coherence filter** | 规则式去除重复与 prompt echo 样本；无 coherent 样本则脆弱性未定义 |
| **WildGuard refusal label** | 主判定器；辅以 Qwen3Guard-Gen-8B 复现主要结论 |
| **Prompt bootstrap** | 对 prompt 做 bootstrap 给出区间（ancestry gap 的配方内区间在 25 个配方中均 > 0） |
| **8-gram overlap test** | 移除与后训练数据重叠的 prompt（Tülu 3 提供） |
| **Attack template lead reversal** | 单模型上 template 领先幅度是否在配对模型中被逆转的分箱分析 |
| **Run fingerprinting via profile matching** | 用逐 prompt 非拒答率把查询模型匹配到 75 个参考 run 中的一个 |
| **Contrastive SFT + DPO** | 安全后训练：SFT 用 Tülu 3 的 WildGuardMix / WildJailbreak / CoCoNot；DPO 用 OLMo 2 1B preference mixture；跳过 OLMo 2 的两个 RL 阶段（不引入安全数据） |
| **OLMo 2 / Tülu 3 后训练配方** | 所有 base 模型使用同一流程，仅训练样本顺序（post-training seed）不同 |
| **Variance decomposition** | 把平均脆弱性的方差拆到 data recipe / base model / post-training seed 三层 |

### 实验设置

| 维度 | 规模 |
|------|------|
| **数据配方** | 25 个（DCLM-Baseline、Dolma1.6/1.7 系列、C4、Falcon+CC 系列、FineWeb-Pro/Edu 等） |
| **预训练 seed** | 每配方 3 个 → **75 个 base 模型** |
| **Post-training seed** | 每 base 模型通常 2 个；主配方 DCLM-Baseline 4 个 → 主网格共 **150 个模型** |
| **模型规模** | 1B（主网格）；150M 与 300M（主配方的规模消融） |
| **训练量** | 每个已发布 1B base 模型训练 **100B tokens** |
| **架构** | DataDecide 的 Llama block，转为 Transformers `LlamaForCausalLM`（重命名 + 必要时切分张量），logits 与 OLMo 参考实现逐尺寸核对 |
| **Prompt 集** | 6,226 条（1,240 plain-harmful / 1,774 benign / 3,212 adversarial-harmful） |
| **每 prompt 采样** | 20 次（vLLM，temperature 1.0，top-p 1，max 512 tokens） |
| **HarmBench 结构** | 1,212 human-jailbreak prompt = 300 harmful request × 91 attack template |
| **主判定器** | WildGuard refusal label；复核用 Qwen3Guard-Gen-8B |
| **bootstrap** | 10,000 次 prompt-level 重采样 |
| **人工审计** | 4 模型 × 100 prompt × 3 样本 = 1,200 条响应，2 名作者 |
| **公开资产** | 代码 + 150M/300M/1B 模型权重 + 逐 prompt judge 标签（不含生成响应；judge 标签以 prompt ID 与来源标识，不含 prompt 原文） |

## 实验结果

### 核心：三类模型对的逐 prompt 非拒答率相关（1B，25 个配方平均）

| Pair 类型 | 修正相关 r | 95% 区间 |
|---|---:|---|
| **MZ twins**（同预训练 run，异 post-training seed） | **0.984** | [0.982, 0.985] |
| **Same-recipe pairs**（同配方，异预训练 seed） | **0.811** | [0.804, 0.817] |
| **Cross-recipe pairs**（异配方，异 run） | **0.779** | [0.766, 0.788] |
| **Ancestry gap** (r_MZ − r_S) | **0.173** | [0.167, 0.179] |
| Same-recipe − Cross-recipe | 0.032 | [0.024, 0.043] |
| **Ancestry gap / (S − cross)** | **5.4×** | [4.0, 7.2] |

配方内部 ancestry gap 范围 **0.145–0.209**，25/25 个配方的 prompt-bootstrap 区间均 > 0。

### 模型规模消融（主配方 DCLM-Baseline）

| 规模 | MZ twins | Same-recipe pairs | Ancestry gap |
|---|---:|---:|---:|
| **150M** | 0.988 [0.983, 0.993] | 0.784 [0.769, 0.799] | 0.204 [0.189, 0.218] |
| **300M** | 0.981 [0.978, 0.985] | 0.770 [0.756, 0.784] | 0.211 [0.198, 0.224] |
| **1B** | 0.985 [0.983, 0.987] | 0.814 [0.801, 0.825] | 0.171 [0.160, 0.183] |

各规模 MZ twin 相关均落在 **0.981–0.988**；换 Qwen3Guard 作判定器结论不变。

### 方差分解（平均脆弱性）

| 层级 | 方差占比 |
|---|---:|
| Data recipe | **49% [12%, 70%]** |
| Base model（recipe 内） | **32% [16%, 59%]** |
| Post-training seed | **19% [11%, 37%]** |

### 攻击模板排名迁移

| 场景 | 最佳模板保持为最佳的 pair 比例 |
|---|---:|
| 换 post-training seed | **67% [55%, 79%]** |
| 换预训练 seed（同配方） | **27% [19%, 35%]** |

**领先幅度被逆转的概率（Figure 4a）**

| 单模型上的领先幅度 | MZ twin 逆转 | Same-recipe partner 逆转 | Cross-recipe partner 逆转 |
|---|---:|---:|---:|
| 10–20 分 | **2.2% [1.9%, 2.6%]** | **25.3% [24.5%, 26.2%]** | 26.6% |
| >20 分 | **0.05%** | **8.9%** | — |

### 指纹识别（3,211 条 adversarial-harmful prompt）

| 任务 | 候选数 | 正确率 |
|---|---:|---:|
| 识别**预训练 run**（全量 prompt） | 75 | **75/75 = 100%**（随机 1/75） |
| 识别预训练 run（随机 50 条 prompt） | 75 | **98%**（200 次随机子集平均） |
| 识别**数据配方**（全量 prompt） | 25 | **24/50 = 48%**（随机 1/25） |

### 排除性实验

| 实验 | 结果 |
|---|---|
| 扣除 template 强度与 request 难度 | ancestry gap 从 **0.210 升到 0.525**（HarmBench 1,212 条 human-jailbreak prompt） |
| Partial rerun（16 模型） | 都不共享 0.823 / 只共享初始化 0.822 / 只共享数据顺序 0.822；相对差异 **−0.001 [−0.008, 0.007]** 与 **−0.001 [−0.008, 0.006]**，互相之差 **+0.000 [−0.008, 0.009]**——全部区间跨 0 |

| 替换安全 SFT 数据集 | ancestry gap **+0.178** vs Tülu 3 的 **0.175** |

一个「10 次中至少破 9 次」的 prompt，在 MZ twin 上复现率 **75.0%**，在同一配方的另一 run 上只有 **60.9%**。

## 局限性

- **受限于 DataDecide 家族** — 所有模型都来自 DataDecide 的预训练 run 与 Tülu 3 的 SFT+DPO 阶段。虽然配方在来源、过滤、去重上变化很大（25 个配方），且 ancestry gap 的 prompt 区间在每个配方都排除 0，但**家族之外是否成立未验证**。
- **主判定器有系统性偏差** — WildGuard 的 refusal label 会漏判 jailbreak prompt 上的拒答：它给出的平均脆弱性为 **0.528**，人工审计其标签后校正到 **0.278 [0.230, 0.324]**；作者自己的四模型人工标签给出的**未校正** ancestry gap 为 **0.156 [0.036, 0.294]**——区间虽在 0 之上，但幅度显著小于 judge 的 0.203。
- **最大模型仅 1B** — 这是比较需求决定的：需要一个配方的多个完整预训练 run × 相同后训练，而 DataDecide 在 1B 只发布 3 个 run。作者引用 Madaan et al. (2025) 指出仅 10 个 7B seed 变体就需约 **15,000 A100 小时**；因此 ancestry gap 只能在 150M / 300M / 1B 上验证。
- **指纹识别仅跨 post-training seed、单一 post-training 配方** — 作者明确写道「We show this only across a new post-training seed under one post-training recipe, not across a different fine-tune」。
- **单 prompt 层面样本有限** — 3,212 条 adversarial-harmful 中只有 1 条在某个模型上无 coherent sample，但「10 次破 9 次」的 prompt 群本身是极小子集，其 75.0% / 60.9% 的对比未给区间。
- **攻击模板分析被 HarmBench 结构限制** — template 强度与 request 难度的最小二乘估计依赖于「每条 prompt = 1 请求 × 1 模板」这一规整结构，且每个模板只覆盖 5–24 条 prompt，强度估计噪声不小。
- **人类审计规模小** — 仅 4 个模型、1 个数据配方、100 条 prompt、2 名作者；κ 值（0.65 / 0.72）本身属于中等一致水平。
- **生成响应未随权重发布** — 公开资产包含模型权重与逐 prompt judge 标签（以 ID 与来源标识，不含 prompt 原文），但**不含生成的响应**，复现逐条分析需自行重跑。

## 与知识库既有工作的关系

- 与 [[2026-10-25-2610.31407-cross-script-entity-matching-failures]] 同属「基准结果依赖未记录的隐含变量」这条主线，但本文给出了一个更锋利的版本：**失败集合本身是单次训练 run 的指纹**，而不仅是「某些语对/脚本更难」。
- 与 [[2026-10-25-2610.31366-afterdeletebench-post-deletion-persistence]] 呼应「删除/干预后的持久性」议题的后端版本：本文证明即使**后训练完全一致**，仅预训练 run 不同就足以让安全画像大幅分叉。
- 与 [[2026-10-27-2610.34491-economics-of-reasoning-effort-in-llm-agents]] 共享同一条方法论：**单次运行 / 单个 checkpoint 无法代表分布**——那篇说单次运行无法代表一个 effort 档位的成功率，这篇说单 checkpoint 无法代表一个预训练 run 的安全画像。
- 与 [[2026-10-27-2610.34836-collective-emergent-alignment-reasoning]] 形成方法论呼应：两者都用「匹配对照」剥离混杂因素——REMAP 剥离的是「self-refinement vs MAS」，本文剥离的是「同 run vs 异 run vs 异配方」。

## 建议

- **是否推荐使用**: 是
- **适用场景**: 任何以 jailbreak benchmark 为证据的安全结论——尤其是「我们的模型比模型 X 更安全」这类跨模型比较；以及需要为安全评测选择模型 checkpoint 的团队（本文直接说明单 checkpoint 结论不可迁移）。
- **可借鉴要点**:
  1. **不要用单 checkpoint 报告 jailbreak 结论**——最强 template 在换预训练 seed 后只有 **27%** 的 pair 仍保持最优（换后训练 seed 是 67%）；跨 checkpoint 迁移攻击（transfer attack）必须承认这个 27% 的天花板，并报告配对模型的 ancestry 而不是单模型分数。
  2. **安全画像可反用于溯源**：一个模型的逐 prompt 非拒答率在 **75 个 run 中每次都**能定位其预训练 run，随机 50 条 prompt 就够（98%）——这既是「评测污染/泄漏检测」的可操作工具，也提醒我们：**模型的行为指纹是稳定且可识别的资产**。
  3. **做数据配方对比至少用 3 个 base model**：单模型与其配方均值的偏离典型为 **3.44 点**，3 个 base model 可降到 **1.99 点**；只用 1 个模型比较配方时 **23.4%** 的排序会被反转。
