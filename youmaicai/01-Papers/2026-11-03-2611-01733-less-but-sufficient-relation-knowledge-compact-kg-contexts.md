## 核心贡献
1. **关系知识驱动的紧凑上下文选择**：用关系路径知识（手写或从带关系路径标注的训练问题中学习）从知识图谱中选出**能推导出答案的紧凑事实集**，而非按相关性排序堆积事实
2. **三重外部校验框架**：可推导性检查（答案是否可从事实推出）、一致性检查（事实之间是否冲突）、验证集选择的路由门（决定何时用派生答案替换 LLM 答案）
3. **系统性指出外部校验的能力边界**：哪些冲突查得出、哪些查不出，并给出"紧凑上下文 + 精确率门"的部署范式

## 问题背景
LLM 读取知识图谱事实时，通常按相关性排序取 Top-k。这种做法有两个未解问题：
- 排在前面的事实**是否足以（sufficient）**推出答案？
- 排在前面的事实之间**是否冲突（conflict）**？

前者决定了上下文冗余度（token 成本），后者决定了答案可靠性。已有工作如 SubgraphRAG 做了子图检索，但并未回答"更少的事实是否就够"以及"外部校验究竟能查到什么程度"。

## 方法

### 关系知识的两种来源
| 来源 | 说明 |
|------|------|
| **手写（written by hand）** | 人工指定的实体间关系模式 |
| **学习（learned）** | 从训练问题中学习，其标注包含关系路径 |

### 流水线
```text
1. 关系知识 → 选出能推导出答案的紧凑事实上下文
2. 派生（derive）→ 从该上下文推导出答案
3. 可推导性检查：派生答案是否真的follows
4. 一致性检查：紧凑上下文内的事实是否相互冲突
5. 路由门（由验证集选择）：决定何时用派生答案替换 LLM 答案
6. 精确率门（precision gate）：仅当检查通过且恰好派生出一个实体时返回派生答案
```

### 一致性检查的作用域限定
一致性检查**仅在"另一条路径连接了它们的实体"**处才以路径证据判定事实 —— 这是一个关键的设计克制，避免在无路径连接时做无根据的冲突判定。

### 精确率门
- 触发条件：检查通过 **且** 恰好派生出一个实体
- 输出：返回派生答案（否则回退到 LLM 答案）

## 实验结果

### 紧凑上下文 vs 相关性排序事实（精确匹配）
| 设置 | 观察 |
|------|------|
| 7 个开放 LLM 读取紧凑上下文 | 精确匹配**优于**读取相关性排序事实 |
| ComplexWebQuestions (CWQ) | 以 **1/4 的 prompt token** 达到与 SubgraphRAG 事实相当的效果 |
| 更强的 LLM | 读取 SubgraphRAG 的事实效果更好（**能力与上下文质量的交互**） |

### 路由门通过的设置
在**全部 53 个** LLM × benchmark × prompt 组合设置中，本方法的精确匹配**领先** SubgraphRAG。

### 精确率门效果（预设测试集）
| 数据集 | 回答覆盖率 | 正确率 |
|------|------|------|
| WebQSP | 18% | **90%** |
| CWQ | 5% | **96%** |

### 一致性检查的作用域
紧凑的 WebQSP / CWQ 上下文中，**具名实体事实里仅 2.5%** 存在"另一条路径连接其实体"的情况 —— 即一致性检查实际生效的范围很小。

## 关键洞察
1. **"更少即够"是可工程化的**：用关系知识做选择可以在 1/4 token 成本下达到子图检索的效果，这直接挑战了"上下文越多越好"的默认假设。
2. **能力与上下文质量存在交互**：更弱的 LLM 从紧凑上下文获益更多，更强的 LLM 能更好地利用 SubgraphRAG 的冗余上下文 —— 意味着不存在普适的"最佳上下文格式"，只有与模型能力匹配的上下文格式。
3. **外部校验的覆盖率必须被诚实标注**：一致性检查只覆盖 2.5% 的具名实体事实，而精确率门只回答 5%–18% 的问题。**任何声称"检查过了所以可靠"的表述，都必须先给出检查的实际覆盖率。**
4. **"路由门在 53/53 设置中领先"是强证据**：这说明校验-路由机制本身是稳健的，而非对特定模型的过拟合。

## 局限性
- 一致性检查的作用域极小（2.5% 具名实体事实），**大部分潜在冲突检测不到**
- 精确率门覆盖率低（5%–18%），对多数问题不提供兜底
- 关系知识本身的质量是上限依赖 —— 手写规则的覆盖度有限，学习版本依赖路径标注质量
- 摘要未给出关系知识的规模与学习方式细节

## 适用场景
- 知识图谱问答系统，需要**在有限 token 预算下保证答案可推导**
- 构建"LLM 答案 + 外部校验 + 安全回退"的分层架构
- 需要量化"外部校验实际覆盖率"的严谨评测场景
