## 核心贡献

> 将推测解码（DSpark/DFlash2）与分层稀疏 KV 缓存（HiSparse）结合，并按负载自适应调整 residency。

1. **统一架构**: 支持 DSpark/DFlash2 推测解码 over hierarchical sparse KV
2. **Load-adaptive residency**: GPU 内存富余时保留更多 history；压力下回退精确 fused retrieval
3. **吞吐**: GLM-5.3 + DFlash2 @ 100K context / concurrency 128 → **793 output tokens/s/GPU**

---

## 技术方案

### 核心思想

长上下文 serving 受限于 KV 内存（先于硬件吞吐耗尽）。HiSparse 把 history 放 host memory、按需取；本文扩展支持 draft-model 推测解码（DSpark/DFlash2），并按负载动态调整 residency。

### 关键技术

| 技术 | 说明 |
|------|------|
| HiSparse baseline | Host-memory 存储 + selective fetch |
| DSpark/DFlash2 integration | 推测解码保持原 proposal/acceptance 规则 |
| Window-bounded ring for draft KV | Draft KV 用 bounded window |
| Load-adaptive residency | 负载高时减少 residency、负载低时增加 |
| Fused retrieval | 压力下精确取回 |
| Layer-group sharing | Verification staging 跨 layer group 复用 |

### 性能数据

| 配置 | 吞吐 | 备注 |
|------|------|------|
| GLM-5.3 + DFlash2 @ 100K ctx, conc 128 | 793 tok/s/GPU | 1.45× HiSparse, 1.27× non-spec adaptive |
| 同 latency bound 下 | up to 4× conc, 2.3-3.7× output | vs HiSparse |
| DeepSeek-V4.1-Flash @ 500K ctx, conc 512 | 1.85× output | vs resident serving + DSpark |
| Load step 中 | host fetches 14.2% → 1.4% | low-load 优化 |

---

## 实验结论

- **模型**: GLM-5.3 (DFlash2), DeepSeek-V4.1-Flash (DSpark)
- **上下文**: 100K-500K
- **并发**: 128-512
- **关键收益**: 推测解码 + 自适应 residency = 显著 throughput 提升 + 长上下文可服务性

---

## 局限性

- 仍依赖 draft-model（DSpark/DFlash2）的额外计算
- Load-adaptive residency 阈值需要在线调参
- 跨模型/跨部署栈的迁移性未深入评估

---

## 实现建议

- **实现难度**: 高（需要重写 KV cache 管理 + 推测解码集成）
- **预期性能**: 长上下文 serving 1.5-4× throughput
- **适用场景**: LLM serving、长上下文 RAG、agent 多轮应用
