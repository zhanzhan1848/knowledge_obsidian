# AuthGateBench: Benchmarking LLMs as Authorization Gate

> **arXiv**: [2610.16426](https://arxiv.org/abs/2610.16426)
> **发表日期**: 2026-10-12
> **分类**: cs.AI
> **会议/期刊**: arXiv preprint（数据：https://github.com/Digital-Trust-Lab/AuthGateBench）

## 📋 摘要

自动化审批系统让 coding agent 在极少人工监督下执行高风险动作，方式是把这一个授权决策委托给一个分类器——通常是一个大语言模型（LLM）。这类系统（Claude Code、Codex 等工具中已有采用）仍存在 **scope escalation**（越权）等失效模式：agent 执行了超出用户授权范围的动作。既有基准主要聚焦恶意请求，在隐式策略下评估"是否拒绝"。本文提出 **AuthGateBench**，首个在**良性请求**下评估授权门控（authorization gating）的**策略引导型**基准。作者实现了一条新流程：由 LLM 生成**对比对（contrast pairs）**——动作与轨迹完全相同、仅请求不同，从而在"拦截"与"放行"之间翻转标签。这使得评估能够检验模型是否**基于上下文而非仅凭动作本身**进行推理。作者进一步考察辅助的**环境信号（environment signals）**能否帮助模型做出更好的决策。最终基准包含 **1400 个实例**，覆盖从真实世界 Claude Code 事故中提炼的 **5 种失效模式**。评测显示：随着模型过度依赖其内部安全对齐，各失效模式上的准确率**下降不均**；而且即便在明确授权的情况下模型仍会拦截大多数动作，表现出**不稳定而非确定性**的决策；不过，**回溯检索到的环境信号能显著提升授权准确率**。

## 🎯 核心贡献

1. **提出 AuthGateBench**：首个面向良性请求、策略引导的授权门控基准，填补"既有基准只测恶意请求+隐式策略"的空白。
2. **提出对比对生成流程**：由 LLM 构造"动作与轨迹完全相同、仅请求不同"的样本对，并在拦截/放行之间翻转标签，**在行为层面隔离出上下文推理能力**。
3. **构建 1400 个实例、5 种失效模式**，全部取材于真实世界的 Claude Code 事故。
4. **揭示决策不稳定**：即使请求明确授权，模型仍会拦截大多数动作——决策是**不稳定**的而非确定性的。
5. **发现环境信号的价值**：回溯检索到的环境信号能**显著提升**授权准确率。

## 🔧 方法/架构

- **评测对象定位**：把 LLM 当作**授权门（authorization gate）**——在 agent 执行高风险动作前作 block/allow 二分类决策。
- **对比对数据流水线**：由 LLM 生成成对样本，控制变量为
  - 动作（action）相同；
  - 轨迹（trajectory）相同；
  - **仅请求（request）不同**；
  - 标签在 block 与 allow 之间翻转。
  这样"只看动作"的 shortcut 无法区分两个样本，必须真正读上下文。
- **失效模式分类**：5 种模式，取自真实 Claude Code 事故（论文以 failure modes 命名，未在摘要中逐一列出；其中 scope escalation 为典型代表）。
- **环境信号增强**：引入**回溯检索（retrospectively retrieved）**的环境信号（如历史授权、相关上下文）作为辅助输入。
- **评估指标**：授权准确率，并按失效模式分组报告。

$$
\text{Score} = \mathrm{acc}\big(\text{label}(x_{\text{action}}, x_{\text{traj}}, x_{\text{request}}) = y\big)
$$

（以上为本笔记对该门控评测的形式化表述，摘要中未给出具体公式。）

## 📊 实验结果

- **基准规模**：**1400 个实例**，**5 种失效模式**，来源为真实世界 Claude Code 事故。
- **失效模式间不均衡**：模型在各失效模式上的准确率**下降不均**，原因是模型**过度依赖内部安全对齐**。
- **不稳定决策**：即使请求**明确授权**，模型仍拦截大多数动作——决策表现出不稳定（stochastic/hesitant）而非确定性。
- **环境信号收益**：回溯检索的环境信号**显著提升**授权准确率。

## ⚠️ 局限性

- **自动生成的对比对可能存在分布偏移**：LLM 生成的"仅请求不同"样本在措辞与真实用户表达之间可能有差距，进而影响结论的现实性。
- **真实授权策略本身难以形式化**：把"策略引导"操作化为请求文本差异，隐含假设授权可以从请求中读出，而现实中往往需要查询权限系统或历史决策。
- **"拦截大多数明确授权的动作"这一现象的解读有歧义**：可能是安全对齐过强，也可能是标注/标签构造噪声，摘要未做区分。
- **五类失效模式的覆盖不完整**：真实事故的长尾（如时序依赖、跨会话授权）可能未被覆盖。
- **评测的门控模型与决策风格耦合**：不同厂商模型的"保守程度"差异会显著影响分数，跨模型比较需谨慎。

## 💡 建议

- 是否推荐使用：**是**（对做 agent 审批层的企业与工具团队价值很高）
- 适用场景：为 coding agent / RPA agent 设计**授权门控模型**并做选型评估；上线前的越权（scope escalation）风险回归测试；研究"如何在不误伤合法操作的前提下拦住越权"；构建带检索的审批决策系统。
- 落地建议：评估审批模型时**必须同时测良性授权场景**，不能只测恶意拒绝；把环境信号检索纳入审批 prompt；在生产中记录审批决策并做稳定性监控（关注同请求决策抖动）。
