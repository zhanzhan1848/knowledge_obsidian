## 核心贡献

> 提出 **ColaBench** —— 一个把"记忆召回"与"知识应用"**联合评测**的合成基准，要求 agent 先用个人历史条件判断"当前请求需要哪些外部知识"，再把这些知识**落到用户的具体处境**上作答；同时给出 **MemKB** 这一基于 state summary 与 memory-document link 的记忆知识库方案作为参考实现。

1. **联合评测两个耦合挑战**：论文明确指出这是现有基准的空白 —— 现有工作分别推进了 **memory recall**、**personalized retrieval**、**memory-guided action**，但**两者的联合评测仍未被充分探索**
2. **"有据可依"≠"适用"**：核心洞察是 —— 即使答案基于相关文档（grounded），如果忽略了用户处境（circumstances），答案依然**不适用**。这与 [[2026-10-24-2610.30485-mempabench-personal-agent-memory]] 的结论互补
3. **Evidence Graph 结构化可追溯**：把个人条件、其在公开交互 session 中的**披露（disclosure）**、历史文档接触记录、以及答案所需证据（个人证据 + 新获取文档证据）全部连成图
4. **MemKB 参考实现**：用 **state summaries** 指导查询与规则应用，用 **memory-document links** 检索与用户历史相关的知识
5. **任务级与错误级分析**：报告在"跨多个历史 Fact 整合信息"的任务上增益更大，并识别出两类障碍 —— **无依据的个人假设（unsupported personal assumptions）**与**规则误用（rule misapplication）**

## 技术方案

### 核心思想

ColaBench 把"用记忆指导知识获取"拆成一个两段式的**条件化检索问题**：

```
用户当前请求
   │
   ├─(1) 从历史交互中读出个人条件（Facts / Conditions）
   │        ↓
   ├─(2) 判定"要回答这个请求，需要哪一条外部知识/规则"
   │        ↓
   └─(3) 把该知识应用到用户处境上 → 生成最终答案
```

关键在于 (2) 与 (3) 不是独立能力 —— 检索到的文档必须被**条件化过滤与解释**（"这条规则在什么条件下适用"），这正是大多数 RAG pipeline 缺失的一环。

### 关键技术

| 技术 | 说明 |
|------|------|
| **Evidence Graph** | 连接个人条件与其在公开交互 session 中的**披露**；记录**先前的文档接触（prior document exposure）**；把答案要求（answer requirements）链接到**个人证据**与**新获取的文档证据** |
| **State summary** | MemKB 用状态摘要来**指导查询构造与规则应用**，而不是把历史原样塞进 context |
| **Memory-document links** | MemKB 维护记忆条目与文档之间的链接，据此检索**与用户历史相关**的知识，而非仅做语义相似检索 |
| **Answer requirements** | 每个任务显式声明"要回答它需要哪些证据"，使评测可归因到证据链而非最终字符串匹配 |
| **Matched task design** | 任务在多个 Profile 上共享结构，便于对比"记忆充分/不充分"的差异 |

### 数据规模

| 项 | 数量 |
|------|------|
| 任务数 | **349 tasks** |
| 用户档案 | **10 Profiles** |
| 知识库 | **13,033 documents** |
| 领域 | health + daily living（健康与日常生活） |

## 关键实验结果

### MemKB 主结果

| 指标 | 结果 |
|------|------|
| Accuracy | **86.25%** |
| 平均交互轮数 | **4.07 interaction rounds / task** |

### 任务级分析

- **跨多个历史 Fact 整合信息的任务上，增益更大**（tasks integrating information across multiple historical Facts 收益最高）—— 提示记忆的价值主要体现在**需要多条件汇聚**的场景，而非单条件查表

### 错误分析（论文明确点出的两类障碍）

| 障碍 | 说明 |
|------|------|
| **Unsupported personal assumptions** | agent 自行假设了用户条件（无证据支撑），把不成立的个人事实带入推理 |
| **Rule misapplication** | 找对了知识，但把它**用错在用户处境上** —— 规则适用条件未被满足时仍强行套用 |

这两类错误恰好对应 ColaBench 设计时强调的"grounded but unsuitable"问题：**检索不是唯一的失败模式，应用同样是**。

## 关键结论 / 局限性

### 关键结论

1. **记忆必须"指导"检索而非"伴随"检索**：state summary 作为查询构造与规则应用的**中介**，是 MemKB 有效的原因
2. **知识获取的质量与适用性是两个独立维度**：面向下游 pipeline 落地时，必须同时评估"检索对不对"和"用得对不对"

### 局限性（依据摘要措辞与基准性质）

- **合成基准**：全部为 synthetic，任务与文档均由生成构造 —— 与真实个人 agent 的分布差异未在摘要中量化
- **领域窄**：仅 health 与 daily living 两个领域，**跨领域泛化未验证**
- **规模小**：**349 任务 / 10 Profiles / 13,033 文档**，相比 LongMemEval 等基准并不算大
- **单一参考实现**：MemKB 的 **86.25%** 是一个方案的结果，摘要未给出与其它记忆系统（Mem0 / MemOS / 文件式记忆等）的**直接对照表**，也未说明**基线（No Memory / vanilla RAG）**的分数 —— 因此"MemKB 好"与"记忆比没记忆好"两个命题**在摘要层面无法区分**
- 摘要未报告具体模型 backbone 与推理成本
