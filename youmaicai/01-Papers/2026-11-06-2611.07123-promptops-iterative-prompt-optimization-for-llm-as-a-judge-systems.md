# PromptOps: Iterative Prompt Optimization for LLM-as-a-Judge Systems

## 摘要
LLM 被越来越多地用作评估 chatbot 与其他 AI 系统行为的**自动评审**，但部署中随着用户交互与分数分布变化，其与**预期人类评估政策**的一致性可能退化。既有自动 prompt 优化方法主要作为**静态开发集上的一次性过程**研究，因此对**长期维持 LLM 评审**提供的指导有限。本文把这一问题形式化为 **judge drift（评审漂移）**，并引入 **PromptOps** —— 一个用于**监控并迭代重校准** LLM-as-a-Judge (LLMaaJ) 系统的**闭环框架**。PromptOps **分离四个运营决策**：**何时优化**、**用哪种优化过程**、**用哪些反馈记录**、**如何更新评审 prompt**。框架实例化五种 prompt 优化方法：**GEPA、SIMBA、Rubric Synthesis**，以及用**模拟退火**或**树结构 Parzen 估计器（Tree-structured Parzen Estimator, TPE）**做样例选择。实验表明：**迭代式 prompt 优化能重校准 LLM 评审** 并在受控分布漂移后**恢复性能**。发表于 **CONVERSATIONS 2026**（国际聊天机器人与人本 AI 研讨会）。

## 核心贡献
1. 形式化 **judge drift** —— 评审与人类评估政策的一致性随交互与分数分布漂移而退化
2. 提出 **PromptOps** 闭环框架，把 LLM 评审维护拆成**四个可分离的运营决策**：何时优化 / 用哪种过程 / 用哪些反馈 / 如何更新 prompt
3. 实例化 **5 种 prompt 优化方法**：GEPA、SIMBA、Rubric Synthesis、模拟退火样例选择、TPE 样例选择
4. 实证：**迭代式优化能重校准评审，并在受控漂移后恢复性能**
5. 发表于 **CONVERSATIONS 2026**

## 方法与架构
**四个分离的决策点**：
```
① WHEN   → 何时触发优化（漂移检测）
② HOW    → 用哪种优化过程（GEPA / SIMBA / Rubric Synthesis / 退火 / TPE）
③ WHICH  → 用哪些反馈记录（样本选择）
④ UPDATE → 如何更新评审 prompt（改写策略）
```

**五种优化方法**：GEPA、SIMBA、Rubric Synthesis、exemplar selection via **模拟退火**、exemplar selection via **TPE**。

**评测**：在受控分布漂移（controlled shifts）前后测量评审一致性。

## 实验结果
- **迭代式 prompt 优化能重校准 LLM 评审**，并在受控漂移后**恢复性能**
- 五种优化方法实例化并比较
- 框架的价值在于**把四个决策分离** —— 可分别替换与调参
- **CONVERSATIONS 2026** 论文

## 局限性
- 「受控漂移」是人工注入的，与真实用户交互漂移的分布差异未讨论；
- 评审一致性相对**人类评估政策**的度量方式未在摘要说明；
- 闭环本身需持续 LLM 调用，运维成本未量化。

## 值得注意的点
「**把运营决策分离**」是这篇相对普通 prompt 优化论文的方法论贡献 —— 不是「哪个优化器更强」，而是「什么时候该优化、用哪种、拿哪些数据、怎么改」这四件事应该**独立演进**。这与本批次 2611.06839 的「算了不用」形成呼应：LLM 系统的维护也需要**显式的触发机制**，否则能力会在漂移中静默退化。
