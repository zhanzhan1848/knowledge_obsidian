## 核心贡献
1. **发现并量化"视觉 token 角色演化"现象**：在 LVLM 的视觉编码器中，token 随编码推进**从"局部细节载体"逐步转变为"全局被引用的代表"**。早期层（如 Layer 9）注意力矩阵呈**局部对角结构**（token 只与邻近/视觉相关区域交互）；深层（如 Layer 17）注意力**跨 query 共享并集中**到一小批被反复引用的位置。[CLS] 累积注意力曲线从均匀变为集中。
2. 提出 **BtsPruner**：一个 **training-free、role-aware** 的视觉 token 剪枝框架，在固定预算下**同时保留互补的两种角色**（global representative + local detail），而不是用单一重要性排序。
3. 提出 **TRIM（Token Role transition Identification Module）**：基于 [CLS] 注意力**集中度（concentration）的层间变化**自动定位角色转变点，从而把编码器分为"深层→全局代表发现"与"浅层→局部细节回溯"两个区段。
4. 提出**递归式局部细节回溯**：以深层选出的全局代表 token 为 parent，从其注意力分布中取 top-k 候选，再经**共享的多样性选择模块**过滤；被选中的局部细节 token **成为下一轮的 parent**，递归下去直到达到预算或到达最早层。
5. 在 **5 个 LVLM 架构**（LLaVA-1.5、LLaVA-NeXT、Qwen-VL、InternVL、CogVLM）× **10 个多模态基准**上全面超过 6 个 training-free 基线（FastV、SparseVLM、DivPrune、PruMerge+、VisionZip、VisPruner）。
6. 极限压缩下的优势显著：在 **LLaVA-1.5-7B 只保留 32/576 个视觉 token（5.6%）** 时保留稠密模型 **91.6%** 的性能（最强基线 VisPruner 89.1%，**+2.5 pp**）；64 token 时 96.4%（+1.1 pp）；128 token 时 98.7%（+0.9 pp）。
7. 实际加速：高分辨率 **LLaVA-NeXT-7B**（2880 视觉 token）上保留 160 token 时，CUDA 延迟从 **821 ms 降到 138 ms（5.95× 加速）**，FLOPs 从 40.8T 降到 4.8T，KV cache 从 1471MB 降到 111MB。

## 问题背景
LVLM 把图像编码为视觉 token，投影进语言模型嵌入空间后与文本 token 拼接处理。在高分辨率场景下，视觉 token 数量常常**主导输入序列**，直接推高计算量、KV cache 占用与推理延迟。

**Training-free 视觉 token 剪枝**是不改参数即可落地的方案，但现有方法存在一个共同的隐含假设：**所有视觉 token 可以用同一个重要性标准排序**。作者指出这一假设忽略了 token 在编码过程中会**分化出不同功能角色**——有的承载细粒度局部证据，有的成为被多个 query 共享引用的全局代表。在激进的预算下，用单一标准选 token 会**系统性丢失其中一类信息**。

具体而言：
- **FastV** 及后续方法（Xing et al.、Ye et al.、Zhang et al.）用**语言模型侧的文本→视觉注意力**估计重要性，但语言模型侧注意力会随层**漂移或弥散**（Xu et al. 2025），因此可靠性存疑。
- 近期方法因此**转向视觉编码器附近**剪枝，使用视觉注意力、特征相似度或两者组合：DivPrune 基于特征相似度选多样化 token；PruMerge、VisionZip、VisPruner 结合注意力重要性估计与相似度冗余削减。
- 但这些方法仍统一使用单一准则。

作者也谨慎地指出：注意力权重**不提供完整的因果解释**——token 表示还受 value 投影、残差连接、FFN 影响；不过自注意力确实反映了 Transformer block 内的 token 交互。

## 方法

### 1. 预备：视觉 token 自注意力
视觉编码器（如 CLIP）为 Transformer 架构。输入序列 $X = [x_{cls}, x_1, \dots, x_N]$，其中 $x_{cls}$ 为 [CLS] token，$x_i$ 为第 $i$ 个视觉 token，$N$ 为视觉 token 数，$d$ 为隐藏维度。$q_i = x_i W_Q$、$k_i = x_i W_K$、$v_i = x_i W_V$（$W_Q, W_K, W_V$ 为可学习投影矩阵），缩放点积注意力：

$$
\mathrm{Attn}(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right) V
$$

记 $A \in \mathbb{R}^{(N+1)\times(N+1)}$ 为注意力矩阵，**第一行 $A_{cls,:}$ 即 [CLS] attention**。去掉 [CLS] 的行列得到视觉 token 注意力矩阵 $A_v \in \mathbb{R}^{N\times N}$，其第 $i$ 行 $A_{v,i,:}$ 是第 $i$ 个视觉 token 对其他视觉 token 的注意力分布。

定义 **token $i$ 的平均入向注意力（mean incoming attention）**：

$$
\mathrm{MIA}_i = \frac{1}{N}\sum_{j=1}^{N} A_{v,j,i}
$$

$\mathrm{MIA}_i$ 衡量 token $i$ 被多少其他视觉 token 引用；越高越可能充当共享表示。多头自注意力下先对各头矩阵求平均再分析。

### 2. 角色演化分析
在 LLaVA-1.5-7B 的视觉编码器上，用 VQAv2 的一个代表样本提取注意力分数，观察到：
- **Layer 9**（早期）：注意力矩阵呈**局部对角结构** → token 主要与邻近或视觉相关区域交互 → **local detail tokens**（保留空间特定的视觉模式）；
- **Layer 17**（深层）：注意力跨 query 共享并集中于一小批位置 → **global representative tokens**（提供更广的上下文表示）；
- [CLS] 累积注意力曲线从均匀变为集中，且 [CLS] attention 与平均入向视觉 token 注意力呈现**相似的峰**；
- 可视化实例：token **284** 成为 global representative，token **175 与 109** 保留局部细节。

### 3. TRIM：角色转变点识别
在第 $l$ 层，[CLS] attention 记为 $a_l$（分布向量），其**极差（range）**为

$$
\mathrm{range}(l) = \max_j a_l[j] - \min_j a_l[j]
$$

相邻层的**变化量**定义为

$$
\Delta(l) = \mathrm{range}(l) - \mathrm{range}(l-1)
$$

转变点由下式确定：

$$
l^{*} = \min\Big\{ l \ :\ \Delta(l) > \alpha \cdot \big(\max_{l'} \mathrm{range}(l') - \min_{l'} \mathrm{range}(l')\big) \Big\}
$$

其中 $\alpha$ 控制阈值，**默认设为 2**。$l^{*}$ 之前的层用于**局部细节回溯**，之后的层用于**全局代表发现**。对于**没有 [CLS] token** 的视觉编码器，改用视觉 token 的平均入向注意力替代。

### 4. 全局代表发现
给定剪枝率，先按**倒数第二编码层**的注意力选候选 token。设 $F \in \mathbb{R}^{N \times d}$ 为视觉编码器输出的 token 特征，$c$ 为倒数第二层的 [CLS] attention，$N_c$ 为候选 token 数：

$$
S_{cand} = \mathrm{TopN}\big(F,\ c,\ N_c\big)
$$

选倒数第二层是沿用前人研究（Yang et al. 2024; Zhang et al. 2025）的默认做法。候选再经**多样性选择模块**过滤：

$$
S_{global} = \mathrm{Diverse}(S_{cand},\ M),\qquad M = \rho \cdot N_{retain}
$$

$M$ 是分配给全局代表的 token 数，$\rho$ 决定全局代表所占比例（**默认 $\rho = 0.5$**），同时也是多样性选择模块的目标规模。

### 5. 共享的多样性选择模块
给定候选特征，先初始化已选集 $\mathcal{S}$ 与剩余集 $\mathcal{R}$；计算已选特征与剩余特征的**余弦相似度**，把与 $\mathcal{S}$ 的**最大相似度最低**的候选**迭代式转入** $\mathcal{S}$，直到达到目标规模 $M$。这是一个贪心的"最不冗余优先"策略——它同时实现了去冗余与覆盖度最大化。

### 6. 递归局部细节回溯
全局代表提供广域上下文，但可能遗漏细粒度视觉证据。自第 $l^{*}$ 层起，已选中的全局代表被当作 **parent token**。对每个 parent $p$，按其注意力分布取 top-k 候选：

$$
C_p = \mathrm{TopK}\big(A_{v,p,:},\ k\big)
$$

候选再经**同一个**多样性选择模块过滤：

$$
L_p = \mathrm{Diverse}(C_p,\ M_{local})
$$

其中 $M_{local}$ 是分配给每个 parent 的局部细节 token 数，$L_p$ 是从当前 parent 的候选中选出的局部细节 token。**被选中的局部细节 token 加入 $\mathcal{S}$ 并成为下一轮回溯的 parent**——递归持续，直到达到目标 token 预算或到达最早层。

这个递归设计的直觉：深层 token 引用了它"看"的浅层 token，因此从深层代表反查浅层，可以系统地找回与之互补的局部证据。

### 7. 推理时的 token 组合
最终索引由全局与局部两个集合合并：

$$
S = \mathrm{RemoveDup}(S_{global} \cup S_{local})
$$

并按视觉 token 序列的**原始顺序**重排（保持空间/时序连贯性）。选中的视觉 token 先经多模态投影器 $P$ 映射进语言模型嵌入空间，再与文本 prompt 拼接送入语言模型：

$$
[\,P(v_{s_1}), \dots, P(v_{s_N})\,;\, \text{text}\,\big] \xrightarrow{\text{LM}_\theta} y
$$

### 8. 架构适配
- **Qwen-VL**（query-based projector）：剪枝后额外**按 query token 对保留视觉 token 的注意力响应**再选 query token；
- **InternVL / CogVLM**（MLP-based projector）：BtsPruner **直接应用于视觉编码器之后**。

- **Dataset/Task**: 10 个多模态基准——VQAv2、GQA、VizWiz、ScienceQA-IMG、TextVQA、POPE、MME、MMBench、MMBench-CN、MMVet，均用官方设置与指标。模型：LLaVA-1.5-7B（576 视觉 token）、LLaVA-NeXT-7B（2880 视觉 token）、Qwen-VL-7B、InternVL-13B、CogVLM-7B。全部在 NVIDIA RTX 3090 上。基线：FastV (ECCV24)、SparseVLM (ICML25)、DivPrune (CVPR25)、PruMerge+ (2024.05)、VisionZip (CVPR25)、VisPruner (ICCV25)。

  - **全局/局部比例 $\rho$（TextVQA）**：32 token 时 $\rho$=0.25/0.50/0.75 → BtsPruner 53.5/54.5/54.0，VisPruner 53.2/53.5/53.3；64 token 时 56.3/56.3/56.2 vs 55.7/55.8/56.0；128 token 时 57.7/57.7/57.3 vs 56.7/57.2/56.8。**结果对 $\rho$ 稳定**，说明增益来自"两种角色都保留"而非某个幸运比例。

## 关键洞察
1. **"统一重要性排序"是一个未经检验的假设，且在极端预算下会系统性失效。** 论文的核心论证是结构性的：既然 token 分化出两种互补角色，用单一准则排序就必然偏向一侧。消融数据支持这一点——单靠全局代表从 48.5 → 54.7 已拿到大部分增益，再补局部细节到 55.3，二者确实互补。
2. **增益随预算收紧而放大。** 128 token 时 +0.9 pp，64 token 时 +1.1 pp，32 token 时 +2.5 pp。这符合"角色分化在压缩到极限时才开始真正决定成败"的直觉——预算宽裕时随便选都能保住大部分信息。
3. **视觉编码器内部本身就存在"全局抽象 → 局部细节"的层级分工**，而语言模型侧的剪枝（FastV 系）看不到这一点。语言模型侧注意力会跨层漂移/弥散，因此早期方法搬到编码器侧；本文进一步指出编码器侧也需要**角色感知**而非仅"编码器侧"。
4. **递归回溯利用了编码器的层级结构。** 深层 token 引用了浅层 token 的证据，因此从深层代表反查浅层候选是一个有依据的检索方向，而不是启发式拼接。
5. **共享多样性模块是性价比很高的设计**：一个模块同时服务两个角色（全局发现的去冗余、局部回溯的去冗余），避免了两套独立的多样性逻辑。
6. **对 $\rho$ 不敏感说明方法稳健**：0.25/0.5/0.75 三档都稳定超过 VisPruner，意味着这个方法不依赖精细调参——这对需要跨模型、跨分辨率迁移的工程方法很重要。
7. **角色视角可迁移。** "不同 token 在不同深度承担不同功能角色，应当分别保留"这个思路，超出视觉剪枝，对 KV cache 压缩、上下文压缩、agent 记忆裁剪同样适用。

## 局限性
- **角色划分本身依赖启发式**：TRIM 用 [CLS] 注意力极差的层间变化来定位转变点，阈值 $\alpha=2$ 是固定值；对没有 [CLS] 的编码器要退回到平均入向注意力，检测可靠性下降。
- **注意力不是因果解释**：作者自己指出，token 表示还受 value 投影、残差、FFN 影响；角色演化只是**相关性观察**，没有做因果干预验证。
- **递归回溯有隐性成本**：需要访问多个编码层的注意力矩阵，在 vision encoder 前向中做注意力提取本身有开销（尤其高分辨率下注意力矩阵很大）；论文的效率表只报 FLOPs/cache/latency，**未单独核算剪枝阶段的额外时间**。
- **CogVLM 上的相对优势虽大但绝对分仍低于稠密**（93.1%），说明该框架在非 LLaVA 系架构上仍有可观的精度损失。
- **对 query-based projector（Qwen-VL）需要额外适配**（按 query 注意力再选 query token），不是即插即用。
- 单次运行、无置信区间；多个 benchmark 上的差异虽一致但未做显著性检验。
- 极端压缩下（32/2880 token = 1.1%）未测试，31.6% 的 Rel. 上限之外的行为未知。
- 未评测生成式任务（仅 VQA/描述/MME 类判别与短生成任务），对需要长视觉推理链的场景（ChartQA、几何、多图推理）未验证。
- 复现代码已开源（github.com/Halenbest/BtsPruner），但论文未报告训练/实现细节的完整超参表。

## 适用场景
- **适用**：高分辨率 LVLM 的推理成本优化（文档/图表/OCR 密集的输入）；需要在**不训练、不改权重**的前提下压缩视觉 token 的部署（边缘设备、批量服务）；多图/长视频帧场景下的上下文预算控制；对精度退化敏感的 benchmark（VQAv2、GQA、MMVet）同时要求延迟收益。
- **不适用**：极低预算下的高精度任务（32 token 仍有 8.4% 性能损失）；需要完整空间分辨率的密集计数/像素级任务；生成式视觉推理（长链条、需要保留全部细节证据的任务）；微调型 token 压缩器（如 TokenPacker 类方法）已足够且更简单的场景；非 CLIP 类视觉编码器且无 [CLS] 的模型（角色检测退化）。
- **不适用**：端到端延迟受视觉编码器前向主导、而非 LLM 前置段主导的部署（此时剪枝的边际收益被编码器开销稀释）。
