## 核心贡献

> 提出 **Route-and-Generate (Rouge)** 层级训练框架，让 LLM **自适应决定每个输入需要多少推理**，解耦**推理努力分配**与**答案生成**。

1. **问题**：LLM 常常**不加区分地应用复杂推理** → 简单题上 **overthinking**（过度思考），难题上 **underthinking**（思考不足）。两者都直接浪费 token 与延迟。
2. **方案**：
   - **路由策略（router）**：在多个**推理格式**之间**分配固定的采样预算**；
   - **基础模型**：用 **GRPO** 以 **per-sample rewards** 优化；
   - **效率奖励**：采用 **rank-based reward**，偏好**更短的正确解**；
   - **路由策略更新**：通过 **KL 正则化的策略改进步骤** **蒸馏进一个神经网络 router**。
3. **结果**：在多个推理基准上取得**更好的 accuracy–efficiency trade-off**；鼓励简单问题给简洁答案、困难问题保留更长推理。

## 技术方案

| 组件 | 说明 |
|------|------|
| Routing policy | 在多个推理格式间分配固定采样预算 |
| Base model 优化 | GRPO + per-sample reward |
| Rank-based reward | 偏好更短的正确解（效率导向） |
| KL-regularized policy improvement | 把路由策略蒸馏进神经 router |
| Output | 自适应推理深度 |

### 关键洞见

- "**把推理预算当成可分配资源**"是一个干净的框架重构：不是"要不要 CoT"，而是"给这个特定输入多少 CoT"。
- **rank-based reward**（而非绝对长度惩罚）避免了长度与质量的纠缠 —— 相对排序更稳定。
- 关键工程点：路由策略最终被**蒸馏进一个神经网络 router** → 部署时只需一次轻量前向，无额外 LLM 调用开销。

## 实验结论

- **基准**：多个 reasoning benchmark
- **结果**：**accuracy–efficiency trade-off 改善**；简单问题倾向简洁答案，困难问题保留长推理。

---

## 局限性

- "多个推理格式"的定义与选择影响结果；
- 路由错误成本不对称（underthinking 比 overthinking 危险），rank-based reward 未体现；
- 需 GRPO 训练，成本较高；
- router 的**跨任务泛化**未验证。

## 实现建议

- **实现难度**：中高（GRPO + 路由蒸馏）
- **预期价值**：高 — 推理成本优化是当前最直接的生产收益点
- **适用场景**：大规模推理服务、成本敏感 API、需要 P95 延迟保证的 agent
- **建议部署**：先做**离线分析**（看现有 CoT 输出长度与正确率的相关性），确认 overthinking/underthinking 的规模，再决定是否投入训练
