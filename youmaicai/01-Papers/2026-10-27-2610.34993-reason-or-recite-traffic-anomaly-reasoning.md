## 核心贡献

> **在单参考 BERTScore 评测下，「推理质量」与「复现标注风格」是两个互相拉扯的目标**：RoR 用 9B reasoning specialist（LoRA on 结构化 trace）+ 27B answer specialist（QLoRA 只学答案）+ 冻结的 27B judge 逐题仲裁，夺得 2026 AI City Challenge Track 3 榜首，**mean score 0.6788**，BCQ 取得 **100%**。

1. **先审计官方标注，再决定怎么训练** — TAR 训练集 44,040 条标注来自 VLM 自动标注流水线（Gemini 3.1 Pro 出 caption/事件描述，Gemma-4 转成多任务 Q&A + CoT），审计发现四类缺陷：推理引用模型看不见的来源（scene description 的 **10.1%**、整体约 **1%**）、时间戳格式混乱（**66.1%** 标注含至少一个时间戳，911 个用冒号当小数点，113 个 gold answer 在一个 JSON 里混两种约定）、标注与视频矛盾、推理不看时间轴就断言（**33.1%** 的 trace 不锚定任何时刻；46.1% 的「No」类 trace 无时间戳）
2. **TAR-RE 结构化推理增强** — 用 Qwen 3.5 9B thinking mode 把每条 trace 重写为五段 schema `<scene>/<query>/<evidence>/<reason>/<conclusion>`，时间戳统一为 `<X.Y seconds>`；词数下限 220（closed-form）/320（descriptive）；改写后 **99%+** 只用统一时间戳格式，每条 trace 的时间锚定观察中位数从 **2 升到 16–30**，无任何时间锚定的 trace 从 **33.1% 降到 0.2%**，与 gold answer 的 ROUGE-L 重叠在各开放式任务上**大致减半**
3. **两个专才（specialists）** — reasoning specialist：Qwen 3.5 **9B** + LoRA（rank-64，α=128），在 TAR-RE trace 上训练，trace 与 answer 都在 `<think>` block 后给出；answer specialist：Qwen 3.6 **27B** **4-bit NF4 量化** + QLoRA，**只用答案训练**（剥离全部推理），直接吸收自动标注风格
4. **免训练的逐题 LLM judge** — 冻结的 Qwen 3.6 27B 逐题仲裁：预筛处理无争议项，**把验证集上更优的候选放在最后**（winner-last），只有被视频证据明确反驳时才推翻；这是应对实测位置偏置与同族自偏的设计
5. **冠军成绩** — Track 3 in-domain (TAR) 榜首，**mean 0.6788**；九个计分任务类型中**四项第一**（BCQ 100%、event verification with explanation、causal linkage、temporal event description），其余每项与列最优差距 **≤0.025**
6. **量化 judge 偏差** — 中性 rubric 下 judge 偏好最后呈现的候选 **65–79%**，且只有 **51.6%** 的裁决在交换顺序后存活（≈随机）；同族自偏好：对同族 27B 候选的选择率 **42.8%** vs oracle 的 **37.8%**；9B 同胞 judge **每一题都返回最后那个候选**，因此 27B 是该家族中最小仍有内容敏感性的成员
7. **仲裁收益 vs. 路由上限** — 内部测试集上：静态路由上限 **0.4958**（等于 27B-only），judge 引导选择 **0.5043**，中性「挑更好的」rubric 只有 **0.4887**（低于 27B 单独），oracle **0.5347** —— judge 回收了约**五分之一**的 oracle gap，0.0156 的差值就是「约束 judge」本身的价值
8. **可迁移的负结果** — 所有事后改写答案的操作全部回退：LLM 重写 −0.071、cleanup −0.012、四候选融合 −0.016、截断句子 −0.028/−0.074；容量杠杆全部打平或回退：vision-tower LoRA +0.002/+0.003、rsLoRA rank 128 −0.012、32→64 帧 ~0；只有「注入可验证内容」有效：转写画面里的位置叠加文字 **+0.004 LB**、把开放式答案锚定到事件窗口 **+0.008 LB**

## 技术方案

### 核心思想

TAR（Traffic Anomaly Reasoning）基准有十种异质任务：closed-form（二元事件验证、多选 QA）按 exact accuracy 计分；七个开放式任务用 **BERTScore F1** 对**单一参考文本**计分。作者的关键观察是：**这两种能力在 VLM 上朝相反方向拉扯**。

closed-form 问题奖励精确、证据接地的推理；而开放式任务按与参考文本的相似度打分，**「匹配标注风格」和「推理正确」同等重要**。更进一步，TAR 的训练标注是 VLM 自动标注流水线产出的（风格指纹来自 teacher 模型），而测试参考是**人工核验**的。于是出现一个悖论：**一个推理得比它的监督更好的模型，可能分数更低**。

RoR 的对策是**解耦**：

- 想要**证据接地推理** → 修好监督本身（TAR-RE），用小一点的 9B 模型在结构化 trace 上 LoRA
- 想要**匹配标注风格** → 这本质是**分布匹配**而非推理，用更大的 27B 模型只学答案，把风格烤进权重（27B 在这种"容量问题"上优于 9B）
- 想**同时拿到两者** → 逐题仲裁而非按任务路由

第三个决定是**不做静态路由**。作者明确指出，已有的 AI City 方案（Kyem et al. 的按任务类型路由、Kachhadiya et al. 的按验证集准确率分派）都依赖预计算路由表。但数据显示 oracle 的收益**集中在 flips**：即那些「更好的答案恰好来自该任务上平均更差的专才」的题 —— 41% 的 BCQ-OE、49% 的 causal linkage、37% 的 temporal description、24% 的 open QA、13% 的 scene description；只有 video summarization（0%）能被路由表完全服务。**因此必须逐题仲裁**。

而逐题仲裁的成败取决于 judge 的偏差控制。中性 rubric 下 judge 有强位置偏好（最后呈现者 65–79%）且只有 51.6% 的裁决在换序后存活 —— 这样的 judge 不能被授予自由选择权。RoR 的设计是：**预筛处理无争议项、胜者放最后、只在被视频证据明确反驳时才推翻、每任务给一句「什么区分对错」的说明**。

### 关键技术

| 技术/方法 | 说明 |
|------|------|
| TAR-RE | LLM 驱动的重标注，把官方 CoT 改写成 `<scene>/<query>/<evidence>/<reason>/<conclusion>` 五段 schema |
| Unified timestamps | 所有字段的时间戳统一为 `<X.Y seconds>`，与 Qwen3-VL 的文本时间戳原生表示一致 |
| Gold-outcome freezing | 重写时冻结 gold 极性/选项字母/时间戳数值，防止静默改标（含故意的错误标注） |
| Gold-wording forbidden | validator 拒绝缺结构标签、缺深度下限或含 gold answer 原文的 trace，采样温度非零，被拒则重新生成 |
| Reasoning specialist | Qwen 3.5 9B + LoRA（rank-64），think-then-answer，答案抽取只需按 `</think>` 切分 |
| Answer specialist | Qwen 3.6 27B 4-bit NF4 + QLoRA，非 thinking 模式、think block mask、只监督答案 |
| 分块交叉熵 | 不materialize完整 logits 张量，切片计算 CE（Qwen 3.5/3.6 目前无主流微调框架支持视频输入，自建管线） |
| Gated DeltaNet 混合骨干 | 线性注意力与全 softmax 注意力按固定 3:1 交织，LoRA 挂在 12 类线性投影上，视觉塔与 token embedding 冻结 |
| 免训练 judge | 冻结 out-of-the-box Qwen 3.6 27B，视频帧 + 问题 + 两个候选 → 选一个；无微调、无路由表 |
| 确定性预筛 | 无争议项直接定，只在候选真正分歧时交给 judge |
| Winner-last 顺序 | 把验证集上更优的候选放最后，对齐位置偏置先验，使覆盖必须靠视觉证据而非槽位赢得 |
| MCQ-OE 构造性作答 | 把 MCQ 预测的选项文本匹配到 MCQ-OE 孪生题的对应选项并逐字提交（benchmark-specific shortcut，与方法正交） |
| 按视频切分的 80/10/10 | 同一视频的所有标注共享 split，按源数据集分层（seed 4242），避免视频泄漏 |

### 实验设置

| 维度 | 规模 |
|------|------|
| 基准 | TAR（2026 AI City Challenge Track 3）：训练 44,040 标注 / 3,670 视频（965 异常 + 2,705 正常，~26.1 小时，8 个公开数据集） |
| 测试集 | 960 条人工核验标注 / 17 个 YouTube 视频的 80 个片段 |
| 任务类型 | 10 种（Basic 5 + Scene 2 + Temporal 3），9 种计分（temporal localization 被组织方排除） |
| 内部测试集 | 70 视频 / 490 题 / 6 个自由文本任务类型 |
| 模型 | Qwen 3.5 9B（reasoning）、Qwen 3.6 27B 4-bit（answer）、Qwen 3.6 27B（judge） |
| 硬件 | 9B 跑 1×RTX 5090 32GB；27B 跑 1×RTX PRO 6000 Blackwell 96GB |
| 训练超参 | max len 512、32 帧/视频、每帧预算 131,072 px、AdamW peak lr 2e-4 cosine + 3% warmup、per-device bs 1 × grad accum 16、bf16 + gradient checkpointing + FlashAttention-2；9B 训 4 epoch、27B 训 2 epoch |
| 推理 | 全部 greedy decoding |

## 实验结果

### 主结果：Track 3 in-domain (TAR) 排行榜

| 指标 | RoR |
|------|------|
| **Mean（9 个计分任务类型无权平均）** | **0.6788（第 1 名）** |
| BCQ（二元事件验证） | **100%** |
| Event verification with explanation | **第一** |
| Causal linkage | **第一** |
| Temporal event description | **第一** |
| 其余任务 | 与列最优差距 **≤0.025** |

> 优势来自**广度**而非单项：九个任务类型中四项第一，其余全部紧贴最优。

### 消融 1：推理监督的价值（9B backbone，内部测试集）

| 训练目标 | 结论 |
|------|------|
| TAR-RE 完整 think-then-answer trace | **MCQ 达 100%**，BCQ 也提升 —— 精确计分的任务由 trace 监督决定 |
| 仅 gold answer（answer-only） | **BCQ-OE 反超 5.1 BERTScore 点**（0.57 → 0.61 的 verdict 差异在 BERTScore 上几乎不可分，但 exact-match 任务会直接惩罚） |
| Open QA / scene description | 两者相差在 2 点以内 |

### 消融 2：选择策略（内部测试集，70 视频 / 490 题）

| 策略 | Mean |
|------|------|
| 静态路由上限（= 27B-only） | 0.4958 |
| **Judge-guided 选择（约束式 rubric）** | **0.5043** |
| 中性「pick the better answer」rubric | 0.4887（**低于 27B 单独**） |
| Oracle | 0.5347 |

> judge 回收了 oracle gap 的约 **1/5**；约束 rubric 相对中性 rubric 的 **+0.0156** 纯粹来自「约束 judge」。中性 rubric 会因位置与冗长偏好推翻好的默认值，多于内容能挣得正确覆盖。

### 消融 3：Oracle flips 的分布（逐题仲裁的价值来源）

| 任务类型 | flips 占该任务比例 | 每 flip 的 oracle 收益 |
|------|------|------|
| BCQ-OE | 41% | +0.060 |
| Causal linkage | 49% | +0.035 |
| Temporal description | 37% | +0.027 |
| Open-ended QA | 24% | +0.024 |
| Scene description | 13% | +0.008 |
| Video summarization | 0% | — （完全可被路由表服务） |

### 消融 4：TAR-RE 重写前后的标注统计

| 指标 | 官方标注 | TAR-RE 重写后 |
|------|------|------|
| 含至少一个时间戳的标注比例 | 66.1% | 99%+ **只用**统一格式 |
| 每条 trace 的时间锚定观察中位数 | 2 | **16–30** |
| 无任何时间锚定的 trace 比例（除 scene description） | 33.1% | **0.2%** |
| trace 与 gold answer 的 ROUGE-L 重叠 | 0.33 | 各开放式任务上**大致减半** |
| 官方 trace 平均长度 | 109–244 词 | 满足 220/320 词深度下限 |

### 负结果（对照基线的配对 bootstrap 噪声底约 0.012–0.016）

| 杠杆 | Δ | 失败模式 |
|------|------|------|
| LLM 重写答案（OQA） | −0.071 | 把匹配 gold 的细节「打磨」掉了 |
| LLM cleanup 草稿（BCQ-OE） | −0.012 | 删掉了与 gold 匹配的词 |
| LLM 融合四候选（BCQ-OE） | −0.016 | 凭空造出草稿一致认为不存在的内容 |
| 删最后一句 / 只留前三句（Scene） | −0.028 / −0.074 | 指标是 recall 驱动的 |
| 车辆枚举 prompt（Scene） | −0.014 | recall +0.04 但 precision −0.07 |
| 追加 gold open-QA 内容（Scene） | −0.083 | 事件叙述不是场景清单 |
| 同胞描述 hint 注入 prompt（OQA） | −0.016 | 把 hint 的错误也传播了 |
| vision-tower LoRA（后 4/8 块）（Scene） | +0.002 / +0.003 | 只是旋转幻觉，不减少幻觉 |
| rsLoRA rank 128（Scene） | −0.012 | 更短输出丢掉边缘属性 |
| 32→64 帧 / 更大像素预算（Scene） | ~0 | 输入杠杆已饱和 |
| 少帧 + 极高分辨率（Scene） | **−0.077（LB）** | 转写远处无关的招牌 |
| 转写画面位置叠加文字（Scene） | **+0.004（LB）** | 唯一有效的内容注入之一 |
| 锚定到 Gemini 定位的事件窗口（OQA） | **+0.008（LB）** | 另一个有效的内容注入 |

## 局限性

- **监督本身有噪声且作者刻意不重标** —— 有整族问题建立在「从未发生的碰撞」这一幻觉前提上，一个上游幻觉会传播到该视频的所有任务类型；作者保留错误 gold 是为了让重生成过程有锚点，代价是这限制了任何方法能从该训练分布榨出的上限
- **TAR-RE 的结构统计只衡量结构，不保证事实接地** —— 缺陷 (a)(b)(d) 靠构造消除，但没有任何机制证明每条被引用的观察都正确；实际准确率影响只在下游间接测量
- **judge 的天花板明显** —— 只回收了 oracle gap 的约 1/5；位置偏好（65–79%）与同族自偏好（42.8%）是先验而非噪声，中性 rubric 下甚至低于单模型
- **本地验证集不是排行榜的代理** —— scene description 上验证集最佳配置在排行榜上**低 0.077**，因为组织方测试集以短、碰撞密集片段为主（中位长度 ~10s），本地 split 跟随发布分布分布；在分布反转后作者只能「在评测服务器上验证配置」
- **每题推理成本高** —— 三个 27B 级模型（answer specialist + reasoning specialist + judge）都要跑，且 27B 需 4-bit 量化才能单卡容纳
- **MCQ-OE 用构造性捷径（逐字复用 MCQ 选项）** —— 虽然合法但属于 benchmark-specific exploit，其贡献被作者单列且声明与主方法正交
- **只有单一作者、单次竞赛提交**，无跨数据集或跨组织复现；也**未提供代码链接**

## 建议

- **是否推荐使用**: **有条件** —— 方法论与负结果清单极有借鉴价值，但直接复现成本高（需自建 Qwen3.5/3.6 视频训练栈）、且强依赖竞赛评测设置的特殊性
- **适用场景**:
  - 任何**多任务混合评测**（一部分 exact match、一部分生成式相似度）上的 VLM 后训练
  - 需要做**逐题路由 / 仲裁**而非静态路由的系统 —— 本文给出了「oracle gap 集中在 flips」的可复用判据
  - 手上**只有自动标注监督**的团队 —— 「把风格匹配当作分布匹配来做」的思路可直接迁移
  - 参赛类任务（AI City / MMBench / 各类 challenge）：本文的「本地验证集可能不是排行榜代理」是极重要的实战警告
- **可借鉴要点**:
  1. **先审计监督标注，再决定训练目标**；审计的四个维度（引用不可见来源 / 格式混乱 / 与输入矛盾 / 不看输入就断言）可作为通用 checklist 直接套到任何自动标注数据上
  2. **judge 必须做偏差控制才能用**：预筛 + winner-last + 「只在被证据明确反驳时推翻」—— 中性 rubric 的 judge 竟然**低于**单模型（0.4887 vs 0.4958），这是做 LLM-as-judge 时最值得记住的反直觉数字
  3. **事后改写答案一律无效**（−0.012 到 −0.074）：单参考相似度指标下，改写等于远离参考；要接近参考必须**把风格训进权重**（答案专才），而不是在推理后修正
