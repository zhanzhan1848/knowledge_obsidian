# SkillMem: Compact External Skill Memory for Latent Multi-Agent Reasoning

## 摘要
Latent multi-agent system 把中间推理与 agent 间通信保持在连续表示中以降低推理成本，但可复用 "skill" 通常以文本形式提供（每次使用都要重新 prefill skill token）或以 layer-wise KV cache / skill-specific LoRA 存储（带来大量 per-skill 存储）。作者提出 **SkillMem**：把每个可复用 skill 编译成一个小型的**外部 latent memory** $Z_s\in\mathbb{R}^{M\times d_{mem}}$，在 latent multi-agent 推理过程中直接可用。核心机制是 **role-conditioned cross-attention reader**：同一份 memory 可按不同 agent 的角色与当前 hidden state 引导不同 agent。训练采用 **behavioral distillation**——匹配"注入文本 skill 引起的 token 预测变化"，backbone 全程冻结。实验在 6 个基准与 Qwen3 4B–14B 上进行：统一使用 **8 × 256** 内存配置，每个 skill 仅需 **9.6 KB**（含检索 embedding）；100 个 skill 的库总存储比 KV Skill 小 **38.3×**、比 LoRA Skill 小 **86.6×**，端到端推理最高 **4.23×** 加速（相对 TextMAS），相对 LatentMAS+文本 skill 为 **1.63×**。

## 核心贡献
1. **SkillMem 框架**：把文本 skill 编译为紧凑的、可独立检索的外部 latent memory，与"如何选 skill"解耦。
2. **Role-conditioned memory reader**：一份共享 memory 通过角色条件化的 cross-attention + sigmoid 门控影响各 agent 的 hidden state，无需 per-role 副本。
3. **Behavioral skill distillation**：三项损失（token 似然、shift 匹配、base 行为保持）以 token 级权重 $w_t$ 软切换，训练 memory 与共享 reader 而不动 backbone。
4. **效率量化**：per-skill 存储 9.6 KB、100-skill 库比 KV 小 38.3×、比 LoRA 小 86.6×；推理 4.23× 加速；训练 reader 只需 11.7 分钟（LoRA 需 110 分钟）。
5. **理论解释（Proposition 1）**：给出 text-to-latent 行为迁移的误差界，把迁移误差分解为蒸馏误差 $\delta$ 与 latent 表示间隙 $(L_F+L_G)L_\Phi\epsilon_{align}$。

## 方法与架构
**预备知识（latent reasoning / LatentMAS）**：decoder-only Transformer $f_\theta$ 有 $L$ 层；latent reasoning 用连续向量替代中间自然语言 token：$z_{t+1}=\phi(h^{(L)}_t)$，作为位置 $t+1$ 的输入 embedding。LatentMAS 中 agent 序列 $A=\{A_1,\dots,A_R\}$，角色 $\rho_r$（planner / critic / refiner / judger）；第 $r$ 个 agent 完成后留下 layer-wise KV cache $C_r=\{K_r^{(\ell)},V_r^{(\ell)}\}_{\ell=1}^{L}$，传给下一个 agent，**只有最后一个 agent 生成自然语言答案**。

**Skill 表示与检索**：skill 库 $S=\{s_1,\dots,s_N\}$，$s_i=(n_i,d_i,p_i)$（名称、何时有用、程序指令）。用冻结 backbone 的文本编码器 $E(\cdot)$ 索引：$e_i=E([n_i;d_i;p_i])$；给定 query $q$，$e_q=E(q)$，$s_q=\arg\max_{s_i}\mathrm{sim}(e_q,e_i)$，sim 为余弦相似度。检索到的 skill 被本次运行中的**所有 agent** 使用。

**存储复杂度对比**：文本 skill 需每次处理 $T_s$ 个 token；KV skill 存储为 $O(LT_sd_{kv})$；LoRA 每 skill 一套参数；SkillMem 的 $Z_s$ 存储为 $O(Md_{mem})$，**与 $T_s$ 无关**。

**Role-conditioned reader**（插入在选定层 $\ell$）：角色向量 $e_\rho$ 由该角色 system instruction $\pi_\rho$ 经冻结 backbone 中间层 token 表示经 attention pooling 得到，训练时固定。$U_\rho^\ell=[\mathrm{LN}_\ell(H^\ell);e_\rho]$：

```math
Q_\rho^\ell = U_\rho^\ell W_q^{(\ell)},\quad
K_{s,\ell} = Z_s W_k^{(\ell)},\quad
V_{s,\ell} = Z_s W_v^{(\ell)},\quad
A_\rho^\ell = \mathrm{softmax}\!\left(\frac{Q_\rho^\ell K_{s,\ell}^\top}{\sqrt{d_r}}\right)
```
```math
R_\rho^\ell = A_\rho^\ell V_{s,\ell} W_o^{(\ell)},\quad
g_\rho^\ell = \sigma(U_\rho^\ell W_g^{(\ell)}),\quad
\Delta H_\rho^\ell = g_\rho^\ell \odot R_\rho^\ell,\quad
H^\ell \leftarrow H^\ell + \Delta H_\rho^\ell
```

$g_\rho^\ell\in(0,1)$ 逐元素控制 memory readout 对 hidden state 的贡献强度。每个插入层的 reader 参数在**所有 skill 与所有角色间共享**，因此每个 skill 只存一份 $Z_s$。

**Behavioral skill distillation**：对每个 (skill, role, calibration task) 三元组，用冻结 backbone 生成 teacher response $y_{s,\rho,x}=(y_1,\dots,y_T)$；然后在三种条件下对**同一响应**做 teacher forcing 打分：text（prompt 含文本 skill）、base（不含 skill）、memory（去掉 skill 文本、改由 reader 提供 $Z_s$）。定义

```math
\Delta^{\text{text},\rho}_t = \ell^{\text{text},\rho}_t - \ell^{\text{base},\rho}_t,\qquad
\Delta^{\text{mem},\rho}_t = \ell^{\text{mem},\rho}_t - \ell^{\text{base},\rho}_t
```

token 级 skill 支持权重（stop-gradient）：

```math
w^\rho_t = \sigma\!\left(\beta\,\mathrm{sg}(\Delta^{\text{text},\rho}_t)\right),\qquad \beta = 5.0
```

三项损失：

```math
\mathcal{L}_{\text{token}} = \mathbb{E}\left[w^\rho_t\left(-\ell^{\text{mem},\rho}_t\right)\right]
```
```math
\mathcal{L}_{\text{shift}} = \mathbb{E}\left[w^\rho_t\,\mathrm{SmoothL1}\left(\Delta^{\text{mem},\rho}_t,\ \Delta^{\text{text},\rho}_t\right)\right]
```
```math
\mathcal{L}_{\text{safe}} = \mathbb{E}\left[(1-w^\rho_t)\,\mathrm{SmoothL1}\left(\ell^{\text{mem},\rho}_t,\ \ell^{\text{base},\rho}_t\right)\right]
```
总目标 $\mathcal{L}=\lambda_{\text{token}}\mathcal{L}_{\text{token}}+\lambda_{\text{shift}}\mathcal{L}_{\text{shift}}+\lambda_{\text{safe}}\mathcal{L}_{\text{safe}}$，权重 $(1.0, 0.5, 0.1)$。

**Skill discovery**：每个基准保留 **20 个 calibration 样本** $D_{cal}$，运行 base 多智能体 pipeline 多次，为每个任务保留匹配对 $P_i=(\tau_i^+,\tau_i^-)$（最终答案分别正确/错误）。用同一 backbone 对比成对轨迹抽取可复用程序；角色特异的输出指示该模式属于 planning / critique / refinement / final verification 中的哪一环；移除含实例特定实体、值、解题细节的候选，并按名称去重。calibration 轨迹与评测样本不相交。

**理论（Proposition 1）**：设文本 skill 与 SkillMem 诱导的行为效应分别为 $F_s^\rho$、$G_s^\rho$（局部 Lipschitz，常数 $L_F,L_G$），behavioral distillation 满足 $|G_s^\rho(u^{\text{text}})-F_s^\rho(u^{\text{text}})|\le\delta$，则

```math
|G_s^\rho(u^{\text{lat}}) - F_s^\rho(u^{\text{lat}})| \le \delta + (L_F + L_G)L_\Phi\epsilon_{align}
```

其中 LatentMAS 的输入输出对齐 $\tilde e_{t+1}=h_t^{(L)}W_a$（$W_a\approx W_{out}^\dagger W_{in}$）配合 $\Phi_\ell$ 的局部 Lipschitz 性 $L_\Phi$，把表示间隙控制在 hidden state 接口处。

## 实验设置
- **Backbone**：Qwen3-4B、Qwen3-8B、Qwen3-14B（全部冻结）。
- **基准（6 个）**：GSM8K、ARC-Easy、ARC-Challenge、MBPP+、MedQA、GPQA-Diamond。calibration 样本与评测样本不相交；结果默认 3 个 seed 平均。
- **SkillMem 配置**：$M=8$，$d_{mem}=256$（即 **8 × 256**）；reader 插入层 $\{L/4, L/2, 3L/4, L-1\}$；每个 agent 执行 **8 个 latent reasoning step**；训练 **200 steps**，AdamW，$\beta=5.0$，$(\lambda_{\text{token}},\lambda_{\text{shift}},\lambda_{\text{safe}})=(1.0,0.5,0.1)$。
- **基线**：TextMAS（文本多智能体）、LatentMAS（latent 基线）、KV Skill（layer-wise KV cache）、Soft Prompt (SP)（同样的蒸馏目标但无 reader，skill-specific 连续 prompt 向量插在输入层）、S2L（Skill-to-LoRA，每 skill 一个 adapter）。所有 skill 方法使用同一 skill 库与同一检索结果。

## 实验结果
**准确率（Table 1，选摘，%）**：

| 任务 | 指标 | 4B: Text / Latent / SkillMem | 8B: Text / Latent / SkillMem | 14B: Text / Latent / SkillMem |
|---|---|---|---|---|
| GSM8K | Acc | 89.40 / 72.40 / **89.90** | 90.80 / 92.33 / **93.07** | 94.30 / 94.30 / 92.60 |
| GPQA-D | Acc | 29.94 / 17.97 / **35.63** | 33.53 / 36.53 / **37.72** | 31.74 / 28.14 / **35.33** |
| ARC-E | Acc | 96.87 / 92.67 / **97.53** | 97.60 / 98.90 / 98.40 | 98.70 / 99.00 / **98.90** |
| ARC-C | Acc | 90.53 / 83.67 / **91.20** | 91.80 / 92.80 / **93.40** | 94.20 / 94.40 / **93.93** |
| MedQA | Acc | 60.10 / 21.84 / **61.50** | 64.56 / 67.84 / **69.49** | 70.42 / 71.60 / 69.72 |
| MBPP+ | Acc | 67.75 / 32.74 / **65.39** | 65.11 / 70.23 / **71.56** | 66.86 / 72.09 / 70.93 |

Qwen3-4B 上 SkillMem 在全部 6 个基准超过 LatentMAS 与三种替代 skill 表示，并在 6 个任务中的 5 个取得最高整体准确率；8B 上在 GSM8K、MedQA、MBPP+ 最佳；14B 上无一致优势（部分为天花板效应：GSM8K/ARC 基线已 >90%）。

**存储（Table 2a，Qwen3-8B）**：Text Skill 173 B/skill；LoRA Skill 30.7 MB/skill；KV Skill 13.0 MB/skill；SkillMem memory **9.6 KB/skill** + 共享 reader 34.5 MB。总量对比：

| 库规模 | SkillMem Total | vs KV | vs LoRA |
|---|---|---|---|
| N = 10 | 34.6 MB | 3.9× | 8.9× |
| N = 100 | 35.5 MB | **38.3×** | **86.6×** |
| N = 1000 | 44.1 MB | 308× | 696× |

**推理效率（Table 2b）**：TextMAS 延迟 33.65 s / 1.00×；LatentMAS 8.18 s / 4.11×；Text Skill 12.98 s / 2.59×；KV Skill 12.01 s / 2.80×；**SkillMem 7.95 s / 4.23×**（相对 LatentMAS+文本 skill 为 1.63×）。训练效率：10 个 MedQA skill，SkillMem 共享 reader 训练 **11.7 分钟**，LoRA per-skill adapter 需 **110 分钟**（9.4×）。

**消融（Table 3）**：
- *角色条件化*（Qwen3-4B，GSM8K/GPQA-D/ARC-E/ARC-C/MedQA 平均）：完整 75.15%；Role Agnostic **67.37%**（降幅最大）；Constant Emb. 73.71%；Shuffled Emb. 72.40%；Per-role Memory 72.52%（per-role 拆分无优势，支持共享 memory）。8B 上对应为 77.97% → 76.50%（role agnostic）。
- *内存容量*：默认 M=8 最佳（平均 64.08%），M=2 接近（63.63%，只用 1/4 向量），M=16 反而下降（GSM8K-4B 89.90→85.87，GPQA-D-4B 35.63→29.74）——关系非单调。
- *蒸馏目标*：完整平均 **64.55%**；去掉 L_token → 62.93%；去掉 L_shift → 62.43%（降幅最大）；去掉 L_safe → 62.47%。

## 局限性
- 作者自述：未来工作包括多 skill 检索与组合（含冲突解决）、把角色与当前推理状态纳入检索、skill memory 的在线更新。文中还提到"直接从成功/失败轨迹导出 latent memory"的 zero-training 变体"显著更不可靠"（Appendix F），说明文本中间层是必需的。
- 我的批判性意见：① **14B 上收益消失**（GSM8K 上 SkillMem 92.60 低于 TextMAS 94.30、LatentMAS 94.30），说明方法只在 backbone 弱时有价值，"紧凑记忆不牺牲能力"的表述在强模型上不成立；② M=8 最优但 M=16 变差，且 M=1/2/4/8 之间波动大（GSM8K-4B 从 87.67 到 82.00 再回到 89.90），容量选择的敏感性说明结论稳定性有限；③ 存储对比对 Text Skill（173 B）有利，但把 skill 文本放进 prompt 的**推理开销**未计入存储比较表，只在延迟中体现；④ Proposition 1 的误差界中 $\delta$（蒸馏误差）与 $\epsilon_{align}$（latent 对齐间隙）没有实测值，理论部分更多是叙事而非可验证结论；⑤ skill discovery 用同一个 backbone 生成文本 skill 再蒸馏回同一个 backbone，存在自我强化偏倚。

## 评估与建议
- 是否推荐深入阅读：**是**（latent multi-agent + 技能复用的效率设计值得参考）
- 适用场景：latent/连续表示的多智能体系统；需要大规模 skill 库存储优化的 agent 平台；小模型（≤8B）上的程序性知识注入
- 与知识库的关联：与 LatentMAS / LatentMem / KVComm、LoRA 技能编译（S2L）、行为蒸馏（SEED）、软提示（Soft Prompt）直接相关；也是"存储/延迟权衡"类论文的优质对照组
