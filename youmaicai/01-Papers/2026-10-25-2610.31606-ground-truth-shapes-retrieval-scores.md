## 核心贡献

> **检索分数依赖标注覆盖率（annotation coverage）**：同一批证据，只要把 ground truth 标注从 25 条扩到 37 条，"被识别出的证据数"就变化，但**检索排序完全不变** —— 这说明检索评测的分数部分地是"标注口径"的产物。

1. **提出证据感知的检索评测协议**（evidence-aware retrieval evaluation protocol），面向乳腺病变管理文献的临床 RAG 系统，明确处理"检索分数依赖标注覆盖"的问题
2. **相关性定义的精确化**：相关性由**证据 span 映射到所有包含它的 chunk** 定义；**等价证据的重叠 chunk 一律视为相关**
3. **构建小规模开发基准**：**18 篇文档语料** + **18 条查询开发集**，每篇文档配一个 **Yes/No 或 WH 问题**
4. **系统扫描检索配置**：chunk 大小 **128–1024 token**、重叠 **0–20%**、**4 种 retriever 配置**
5. **分离检索与生成评测**：检索用 R-Precision / Recall@K / MRR / nDCG@K；生成在 512-token 索引、K=1~5 上用 DeepEval claim-level 指标（judge = **deepseek-v4-pro**）以及 BLEU/ROUGE
6. **量化 ground truth 的影响**：扩充标注使 evidence spans **25 → 37**、accepted chunk targets **36 → 51**，而**检索排序不变**

## 技术方案

### 核心思想

```
临床文献语料 (18 篇)
      ↓ chunking (128–1024 token, 0–20% overlap)
   索引 (选定 512-token 索引用于生成评测)
      ↓
检索 = dense embeddings + BM25 + cross-encoder reranking
      ↓
相关性判定：evidence span → 映射到所有包含它的 chunk
          （重叠 chunk 且证据等价 ⇒ 视为相关）
      ↓
检索指标: R-Precision / Recall@K / MRR / nDCG@K
```

### 关键技术

| 技术 | 说明 |
|------|------|
| Evidence-span-to-chunk relevance mapping | 相关性不是"哪一块文本"，而是**哪些 chunk 覆盖了证据 span** |
| Overlapping-chunk equivalence rule | 携带等价证据的重叠 chunk **全部算相关**，避免因 chunk 边界切分而误判为不相关 |
| Hybrid retrieval + cross-encoder reranking | 三层组合：dense + BM25 召回，cross-encoder 重排；**cross-encoder 取得最高分** |
| Chunk-size / overlap sweep | 128–1024 token × 0–20% overlap 的系统扫描，**选定 384-token chunk + 20% overlap** |
| Separate generation protocol | 在 512-token 索引、K=1~5 上独立评估生成；judge 为 deepseek-v4-pro |
| Claim-level + lexical metrics 并列 | DeepEval claim-level 指标与 BLEU/ROUGE 同时报告 |

### 为什么"ground truth 形状"会改变分数

| 现象 | 机制 |
|------|------|
| 分数升高 | 更多 evidence spans → 更多"正确"目标被纳入分母外的相关集合 → recall 类指标口径变了 |
| 排序不变 | 扩充标注只是**补充**了原标注已隐含覆盖的相关 chunk，未改变相对次序 |
| 结论 | **分数变化 ≠ 检索能力变化**；排序稳定性说明检索器行为本身未受标注扩充影响 |

## 关键实验结果

| 维度 | 结果 |
|------|------|
| 语料 | **18 篇文档** |
| 开发查询集 | **18 条查询**，每篇文档一个 **Yes/No 或 WH 问题** |
| 最优检索配置 | 混合 retriever，**384-token chunk + 20% overlap** |
| Top-3 命中 | **17 / 18** 查询在**前三**个结果中检索到 accepted evidence |
| 检索指标 | **Recall@3 = 0.94**、**R-Precision = 0.94**、**MRR@3 = 0.94**、**nDCG@3 = 0.94** |
| 标注扩充 | evidence spans **25 → 37**；accepted chunk targets **36 → 51** |
| 扩充后的检索排序 | **未改变** |
| 生成评测 | 512-token 索引，K=1–5，DeepEval claim-level + BLEU/ROUGE，judge = **deepseek-v4-pro** |
| 结论 | **cross-encoder reranking 取得最高检索分数** |

## 关键结论

1. **检索分数是"分数 + 标注口径"的复合量**：同样的检索器，扩充 ground truth 后"识别出的证据数"从 25 涨到 37（+48%），accepted targets 从 36 涨到 51（+42%），但检索排序**一模一样**。
2. **因此报告检索分数必须同时报告标注口径**。否则两个系统的分数差异可能只反映标注详细程度。
3. **证据等价的重叠 chunk 必须全部算相关** —— 这是 chunking 参数（大小/重叠）与检索指标耦合的关键环节：重叠提高会改变相关集合大小，从而影响分数的可比性。
4. **cross-encoder reranking 在临床 RAG 上带来最高检索收益**，且 384-token / 20% overlap 是选定配置。
5. **检索强不等于生成强**：本工作把两者分开评（明确 K 与索引设置），这比端到端 RAG 分数更可诊断。

## 局限性

- **规模极小**：18 篇文档、18 条查询。**这是开发集，不是评测集**
- **语料单领域**：仅乳腺病变管理文献
- **ground truth 的扩充由检索信息驱动**（retrieval-informed curation）—— 作者自述这**要求独立验证**，且需要**放射科医师对证据充分性的评估**
- **生成侧结果未在摘要披露**，无法判断 DeepEval judge 在临床语境下的可靠性
- **judge 是 deepseek-v4-pro**，单一 judge 的偏差未做交叉验证
- 未与文献中的既有 RAG 基准做系统对比

## 实现建议

- **实现难度**: 中（需要自建小规模证据标注 + 检索调参 + 生成评测流水线）
- **适用场景**: 临床/垂直领域的小规模 RAG 效果验证；以及**设计检索评测协议**时的方法论参考
- **可操作建议**:
  1. 报告 RAG 检索分数时，**同时报告 evidence spans 数与 accepted chunk targets 数**
  2. 定义相关性时明确"**证据等价的重叠 chunk 全部算相关**"，否则 chunk 参数一改分数就不可比
  3. **检索与生成分开评**（固定索引与 K），否则无法定位问题出在哪一段
  4. chunking 扫描（大小 × 重叠）应作为检索评测的**标准前置步骤**
- **对多模态检索系统的启示**: 与 2026-10-24 日报中 RoSA（saliency collapse）同属"**评测口径本身会制造差异**"这一主题 —— 建议在多模态检索系统上同时做**标注覆盖敏感性分析**
