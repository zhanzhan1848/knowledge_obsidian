# Towards Foundation Decision Models: Drex

### 核心贡献
1. 提出 **decision model** 范式：给定问题 + 用户提供的候选选项集合，直接返回选项上的 **概率分布**，**不做 autoregressive decoding**——从而避免长 CoT 带来的输出不一致、需解析输出、以及成本与延迟问题。
2. 发布 **Drex 系列 4 个开源 decision model**：**8B（DLM）**、**9B（v1.5）**、**35B / 3B active（v2.0）**、**27B（Max）**；Max 版本额外做视觉调优。
3. 系统评测显示：Drex Max 在 **Decision Index 0.4.1** 公开套件上以 **67.52** 分刷新其所比较的 decision models 的 SOTA（对比 Jev 1.14.0 的 **60.70**）；在 **Decision Bench v4** 上与 d3-turbo、GPT-6 Sol 统计打平，仅落后 Claude Opus 5.5 **1.6 分**，并在 DecideBench 上取得 decision models 中最高准确率；典型请求延迟 **183 ms**（GPT-6 Sol 约 2.0 s，Claude Opus 5.5 约 3.5 s），且输出对选项顺序重排保持稳定。

### 技术方案
**核心思想**: 把「回答问题」重构为「对给定选项集合打分并归一化为分布」——决策模型只负责判别/评分，不负责展开式生成，因此可以用 RL 直接优化「选项正确率」，并天然获得可解析、确定性的输出。

| 技术 | 说明 |
|------|------|
| Decision model 输出形式 | 输入 state（文档、记录或 agent context，可选带图像）+ questions，每个问题要求在三种形式中作答：**多选一**、**yes/no 判断**、**有序量表上的打分**；输出为选项上的概率分布 |
| 非 autoregressive 解码 | 完全不做自回归展开，避免长 CoT 带来的「答案不一致、需后处理解析、成本与延迟」三重痛点 |
| SFT + RLAF | 训练结合 **supervised fine-tuning** 与 **reinforcement learning from adjusted feedback (RLAF)**；消融显示 RLAF 提升准确率 |
| Consistency loss | 一致性损失提升模型对 **选项顺序（option order）** 的鲁棒性；Drex Max 输出在选项重排下保持稳定 |
| Vision tuning | 仅 Max（27B）版本额外做视觉调优以支持带图 state |
| 模型规格梯度 | 8B(全激活) / 9B / 35B 仅 3B 激活（MoE 风格）/ 27B，覆盖从紧凑到多模态的多种部署形态 |

### 实验结果
- **数据集**: Decision Index 0.4.1（public suite）、Decision Bench v4、DecideBench（均为 decision-model 评测套件）
- **基线**: Jev 1.14.0、d3-turbo、GPT-6 Sol、Claude Opus 5.5
- **结果**: Decision Index 0.4.1 公开套件 **67.52 vs 60.70（Jev 1.14.0）**；Decision Bench v4 与 d3-turbo、GPT-6 Sol **统计打平**，落后 Claude Opus 5.5 **1.6 分**；DecideBench 上 decision models 中准确率最高；典型请求 **183 ms** vs GPT-6 Sol 约 **2.0 s**、Claude Opus 5.5 约 **3.5 s**（约 11–19× 加速）；输出对选项重排稳定

### 局限性
- 严重依赖 **用户/调用方提供候选选项集合**；开放域问题（无选项可枚举）无法直接适用
- Decision Bench v4 上仍 **落后 Claude Opus 5.5 1.6 分**，说明决策能力尚未完全追平最强通用模型
- 摘要未说明 RLAF 的具体调整反馈机制细节，以及 v2.0 的 3B active 推理速度数据
- 四个模型均为较大参数量（8B–35B），摘要未讨论资源受限场景下的最小可用版本

### 关键洞见
> 把「推理」从 **生成 token** 改成 **给选项打分**，就把任务从「语言生成问题」翻转成了「判别+排序问题」——于是训练目标（RL 直接优化选项正确率）、输出格式（天然可解析、顺序不变）、推理成本（183 ms）三者同时被解决。这是 foundation model 从「会说」转向「会判」的一条可行路线。
