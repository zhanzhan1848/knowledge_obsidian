## 核心贡献

> 提出 **search momentum（搜索动量）** 这一概念刻画 RAG 中**查询意图的漂移**，并提出 **MAPS** —— 宏自适应并行推理框架，调节动量、缓解 query-intent drift。

1. **问题**：interleaved reasoning-and-retrieval 的 RAG 方法存在
   - **冗余或无效的 sub-query**；
   - **query 探索多样性不足**；
   - 由于 reasoning 与 retrieval **紧密交织**，**演化中的推理过程如何影响 query 意图**并不清楚。
2. **概念 — search momentum**：捕获**历史 sub-query 变化在推理轨迹上积累出的检索趋势**。
3. **关键发现（momentum-based 分析）**：**query 生成过程倾向于沿既有检索轨迹持续演化** —— 即动量驱动 query-intent drift。
4. **MAPS 方案**：
   - **Macro 层**：保留检索到的知识 + 精炼的 reasoning state → **降低历史推理轨迹对后续 sub-query 生成的影响**；
   - **Parallel 层**：把常规顺序推理扩展为**并行推理** —— 每轮识别**互补的检索方向**，生成对应 sub-query **并行检索**，再整合检索到的证据更新 knowledge 与 reasoning state。

---

## 技术方案

| 层 | 机制 | 目的 |
|------|------|------|
| Macro | 保留知识 + 精炼 reasoning state | 抑制历史轨迹惯性 |
| Parallel | 识别互补检索方向 | 提升 query 多样性 |
| Parallel | 并行生成 sub-query + 并行检索 | 降低轮次、提升覆盖 |
| Consolidate | 整合证据 → 更新双状态 | 维持一致性 |

### 关键洞见

- "query 沿既有轨迹演化"是一个**自强化漂移**：第一次检索偏了，后续 query 会继承这个偏差。MAPS 的 macro 层用**状态精炼**打断这一惯性。
- Parallel + complementary directions 是**显式的多样性机制**，比单纯提高 top-k 更能防止检索塌缩。

## 实验结论

- **基准**：6 个 QA benchmark
- **结果**：跨不同 backbone 模型，**一致优于代表性 RAG 方法**。
- **代码**：https://github.com/NEUIR/MAPS

---

## 局限性

- 并行检索 → **检索调用数增加**，延迟与成本影响未量化；
- "互补检索方向"的识别依赖 LLM 判断，可能引入噪声；
- 未在长文档 / agentic RAG 上验证。

- **实现难度**：中（并行检索编排 + 状态管理）
