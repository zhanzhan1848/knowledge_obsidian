## 核心贡献

> 提出 **HiddenLens** —— 首个**专门用于检测、分类、提问并解决"隐藏假设"**（而非仅仅标记歧义）的六层 BERT-LLM 框架，并发布配套标注语料 **HLC**。

1. **被忽视的问题类别**：自然语言软件需求常省略关于**性能、运行条件、用户行为、领域约束**的假设；这类需求**表面清晰合理**，但会悄悄影响架构、测试与部署
2. **成本论证**：假设若**到实现阶段才被发现**，解决成本远高于早期处理
3. **现有研究缺口**：ambiguity 与 vagueness 被广泛研究，但**嵌在"看起来清晰"的需求里的假设**少有关注
4. **数据集 HLC**：**312 条需求**、**847 条隐藏假设**，覆盖 6 类 NFR —— 论文称是**首个专门为此任务构建的数据集**
5. **显著优于基线**：相对 keyword-based 与 QuARS-Adapted 基线分别高 **71%** 与 **61%**，端到端 **F1 = 0.79**

## 技术方案

### 六层流水线

| 层 | 方法 | 输出 |
|----|------|------|
| **L1** | **BERT attention entropy** | 定位**未解析的 span**（歧义所在） |
| **L2** | **CoT-prompted LLM reasoning** | 表述每条假设及其**失败风险** |
| **L3** | **fine-tuned BERT** 分类器 | 归入 6 类 NFR：performance / security / scalability / usability / reliability / domain |
| **L4** | **FS (few-shot) LLM prompting** | 生成**排序的澄清选项** |
| **L5** | **人工验证** | 确认 / 编辑 / 改写 |
| **L6** | LLM 重写 | 输出**显式、可测试、可追溯**的需求 |

### 关键设计思路

- **BERT 负责定位与分类，LLM 负责推理与生成** —— 各自发挥所长
- **Attention entropy** 作为"哪里没解析清楚"的信号，比纯 LLM 判断更精确
- **L5 的人工在环**是设计核心 —— 假设的解决必须由人确认，否则会引入错误假设

| 指标 | 结果 |

| 端到端 F1 | **0.79** |

## 局限性

- HLC 仅 **312 条需求 / 847 条假设**，规模偏小，泛化性有限
- 六层流水线**工程复杂度高**，需要维护多个 BERT/LLM 组件
- attention entropy 作为不确定性代理在某些需求文本上可能不稳定
- 论文自述首个数据集 —— 缺乏外部验证基准，改进幅度难以横向比较
- 依赖人工验证环节，实际吞吐受限

## 实现建议

- **实现难度**: 中高（六层组件 + 需构建标注语料）
- **适用场景**: 软件需求评审 —— 尤其在 AI 生成需求规模上升的当下
- **建议起点**: **跳过完整的六层**，先用 L1（attention entropy）+ L2（CoT）做一个轻量版，看能否在你的需求文档上找出值得追问的点
- **价值点**: "看起来清晰的需求里藏着假设"是个反直觉但高价值的视角 —— 这类问题的成本是在架构定型后才爆发的
