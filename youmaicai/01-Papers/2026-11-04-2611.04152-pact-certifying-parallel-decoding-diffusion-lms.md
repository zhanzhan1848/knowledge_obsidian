## 核心贡献
1. **识别出已发表 commit rule 的一个根本性盲点**：它们通过检验"预测分布"来决定提交哪些 token，但在采样解码下被写入的 token 是**抽取**出来的——测试根本看不见它们。论文定义"报告可靠性"与"实际可靠性"之差（Proposition 2），并证明 $\hat{R}(S) \ge R(S)$，等号成立当且仅当每个位置都取到最可能的 token；在 $T=1$ 时期望间隙为 $\sum_{i\in S}[H(p_i) - H_\infty(p_i)]$（熵与 min-entropy 之差）。结论：**只看分布的规则，在贪心解码下才成立其保证**。
2. **发现答案质量实际由"实际可靠性"驱动，而非计算量**：在四个模型、多族规则上，pass@1 更好地跟随**最弱步骤**的实际可靠性，而非"报告可靠性"，后者又远好于 forward pass 数。用构造的 stand-in 规则（分别固定其他量）验证这一关系，违反该关系的配置平均损失约 0.04–0.10 的 pass@1（Figure 2c）。
3. **提出 PACT（Post-draw Accumulated Certificate for Tokens）**：训练无关的 commit rule。它**先抽取 token**，按被抽 token 的对数概率排序，再提交使分数和 ≥ log τ 的最长前缀，并对同一步内的位置施加最小间隔约束。PACT 检验的正是它将写入的 token，因此**在任意温度下**其提交的集合都被认证（Proposition 3），且不增加任何 forward pass。
4. **证明了最优性**：无 spacing 时，PACT 提交的是满足 $R(S) \ge \log\tau$ 的**最大**集合；不存在具有同等保证的规则能提交更多位置（Proposition 3）。$\tau \to 1$ 时退化为每步一个位置，$g=1$ spacing 时 $\pi$ 不变。
5. **给出对数概率分解（Proposition 1）**：令 $P_S(x_S)$ 为模型在按提交顺序逐个揭示 token 时赋予该集合的概率，定义依赖项 $D(S) = \log P_S(x_S) - R(S)$，则
   $$\log P(x) = \sum_{k=1}^{K} R(S_k) + \sum_{k=1}^{K} D(S_k)$$
   其中第一项是"每步写什么"的可靠性（抽到后可检验），第二项是"一次写多个"的代价（单次 forward pass 无法揭示）。在固定集合与顺序、$T=1$ 下，并行解码从 $Q(x) = \prod_k \prod_{i\in S_k} p_i(x_i)$ 抽样，$\mathbb{E}_Q[\sum_k P_k D(S_k)] = -\mathrm{KL}(Q\|P) \le 0$。
6. **在四个模型上以更少 forward pass 达到已发表规则的质量**：对比 Fast-dLLM、Fast-dLLM++、EB-Sampler、KLASS、TACG、fixed-$k$（$k=4$）五种规则，在 HumanEval / MBPP / GSM8K / MATH500 / IFEval 五个基准上，速度—质量前沿优于全部基线；同等 pass@1 下相对各规则的加速比在 LLaDA-8B 上为 2.7×–3.1×（Fast-dLLM）、1.8×–2.7×（Fast-dLLM++）、3.1×（TACG）、2.2×（EB-Sampler）、2.4×（KLASS）、2.7×（fixed k）。
7. **spacer 机制反而降低总成本**：spacing 从每步移除位置，但后续步骤因此能写入更多 token，净效果通常是总 forward pass 下降。
8. **降低重复词错误**：在同等速度下，已发表解码器"连续两次写入同一个词"的比例远高于 PACT（Figure 1 底部：在各自速度下，含重复词的答案占比中位数 EB-Sampler 52%、fixed k 31%、Fast-dLLM 20%、Fast-dLLM++ 12%、TACG 7.1%、PACT **0.9%**）。

## 问题背景

掩码扩散语言模型（MDLM）从全掩码答案出发，每步填充若干位置；**commit rule** 决定每步填哪些位置。训练无关的 commit rule 已从"每步固定 $k$ 个位置"演进到"用一个测试来决定这个数量"，使解码加速数倍（Wu et al., 2026a；Ben-Hamu et al., 2025；Kim et al., 2025；Kasa et al., 2026；Wang et al., 2026）。这些模型在实际部署中常配合采样使用——RL 与 test-time scaling 都依赖采样获得多样答案（Olausson et al., 2026；Fang et al., 2026）。

但 commit rule 面临两个被忽视的问题。第一，**测试读的是预测分布而非被写入的 token**。采样下抽到的 token 可能远不如最可能的那个，而测试看不见这个差距。第二，**同一步内的 token 相互依赖**，而这种依赖无法从单次 forward pass 的分布中测出。论文 Figure 1 给出的例子极为直观：一个按 top-choice 排序并打分的规则接受了一次 `cleaned` 出现两次，而最终答案里每个副本的概率只有 0.001——分布测试通过了，但实际写入的东西毫无可靠性。

已有的 dependence-aware 规则从 attention、训练头、小型自回归模型或上下文不确定性中选择共同提交的位置（Kim et al., 2026；Ringel et al., 2026；Israel et al., 2025；He et al., 2026）。把同一步的位置**拉开距离**也被证明能削弱依赖（Luxembourg et al., 2026；Besnier et al., 2015）。但这些工作没有一个把"认证自己写入的 token"这件事内化进一个可证明的保证里。

PACT 的定位正是这个空白：**它把 commit rule 从"检验分布的启发式"变成"对写入内容持有证书的规则"**。

## 方法

### 1. 预备与两个可靠性量

MDLM 在每个 step 为每个掩码位置 $i \in M$ 给出分布 $p_i$，解码器从 $q_i \propto p_i^{1/T_i}$（温度 $T$）抽取 token $x_i$。commit rule 保留集合 $S \subseteq M$ 的已抽 token，其余保持掩码；每步一次 forward pass；已提交 token 不可修订。

规则由三部分构成：**每个位置的分数**、**位置上的顺序**、**结束有序列表的截断**。

论文区分两个量（式 1）：
$$\hat{R}(S) = \sum_{i \in S} \log p_i(\hat{x}_i), \qquad R(S) = \sum_{i \in S} \log p_i(x_i)$$
其中 $\hat{x}_i = \arg\max_v p_i(v)$ 为位置 $i$ 最可能的 token。$\hat{R}(S)$ 是**报告可靠性**（在最可能 token 上计算，阈值化 top probability 的规则只对这个量成立证书），$R(S)$ 是**实际可靠性**（在写入 token 上计算，只有抽完后才知道）。

### 2. PACT 的三处改动

**(a) 分数**：用 written-word score $s_i = \log p_i(x_i)$，即该位置**实际抽到**的 token 的对数概率。按 $s_i$ 排序得到顺序 $\pi = (\pi_1, \pi_2, \dots)$。

**(b) 截断**：提交使分数和达到 $\log\tau$ 的最长前缀（式 2）：
$$k^* = \max\Big\{ m : \sum_{j \le m} s_{\pi_j} \ge \log \tau \Big\}$$
若无前缀通过，则提交 $\pi_1$，保证每步有进展。这是**集合级**的 cut——测试整个提交集合而非逐位置测试。因为测试读的是被抽出的 token，PACT 认证的集合就是它写入的集合，**在任意温度下成立**。

**(c) 间距（spacing）**：集合级 cut 考虑了每个被提交 token 有多可靠，但未考虑同批 token 之间的依赖。相邻位置是最危险的一对——每个位置都是从缺少对方的上下文中决定的（Luxembourg et al., 2026）。因此对顺序 $\pi$ 做过滤：仅当某位置与已保留的所有位置距离至少 $g$ 时保留它（默认 $g=8$）。扫描在收集到 $k^*$ 个位置时停止；若合格位置太少，则逐步降低间隔。设保留位置按 $\pi$ 的顺序为 $\pi_g$，PACT 提交 $\pi_g$ 中最多 $k^*$ 个位置、且分数和 ≥ log τ 的最长前缀——**cut 在 $\pi_g$ 上重新计算**，因为低分位置可能把总和压到 τ 以下。spacing 只过滤顺序，不增加 forward pass。

### 3. 理论分析

**Proposition 1（分解）**：设 $S_1, \dots, S_K$ 为解码提交顺序中的集合，$R(S_k)$ 取 $S_k$ 提交时刻的状态值；$P_S(x_S)$ 为模型在按 $\pi$ 顺序逐个揭示 token 时赋予该集合的概率；依赖项 $D(S) = \log P_S(x_S) - R(S)$。则
$$\log P(x) = \sum_{k=1}^{K} R(S_k) + \sum_{k=1}^{K} D(S_k)$$
第一和是"每步写什么"的可靠性，规则在 token 抽出后即可检验；第二和是"一次写多个"的代价，单次 forward pass 无法揭示。阈值 τ 约束第一和的每一项，spacing 缩小第二和的项。

**Proposition 2（只看分布的测试）**：对任意 $S$，$\hat{R}(S) \ge R(S)$，等号成立当且仅当 $S$ 中每个位置都取到其最可能 token。若 $S$ 仅由分布选出，则 $\mathbb{E}_T[R(S)]$ 随 $T$ 非增，且当每个最可能 token 唯一时 $T \to 0$ 趋于 $\hat{R}(S)$。在 $T=1$ 时 $\mathbb{E}[\hat{R}(S) - R(S)] = \sum_{i\in S}[H(p_i) - H_\infty(p_i)]$。只看分布的规则在同一状态下无论温度都提交同一集合，但其写入的 token 随温度升高而损失可靠性；间隙只在贪心解码下闭合——那正是"对最可能 token 的保证"成立的场景。

**Proposition 3（最大认证集合）**：除"无前缀通过而提交单个位置"的情形外，PACT 提交的每个集合都满足 $R(S) \ge \log\tau$，**在任意温度下、且在任何只从 $\pi$ 中移除位置的过滤之后**成立。无 spacing 时 PACT 提交满足 $R(S) \ge \log\tau$ 的最大集合 $S$。

**依赖的 Markov 假设**：在 Markov 假设下，spacing 界定单步内的依赖。

## 关键洞察

1. **"证书"（certificate）这一概念是本文最有价值的迁移点**。几乎所有已发表的 commit rule 实际做的是"分布启发式"，只有贪心解码下才享有它们声称的保证；PACT 把它变成"对你将要写入的 token 集合的持证保证"，在任意温度成立。这是一个可以套用到任何"先决策后执行"的采样解码场景的模式。
2. **Proposition 1 的分解给出了 commit rule 的完整设计空间**：$\log P(x)$ 被拆成"可靠性"（可检）与"依赖"（不可从单次 forward pass 观测）两项之和。阈值 τ 控制第一项、spacing 控制第二项——这解释了为何 PACT 的两个组件看似独立却共同工作，也解释了为何"减少每步位置数"并不必然更慢（spacing 省下的位置会在后续步骤以更多 token 补回）。
3. **温度升高时"按 top-choice 排序"会退化，而按抽到 token 排序不会**——因为后者的分数定义直接就是实际可靠性。这解释了为什么已有的 confidence-based 规则在低精度解码（采样、RL、test-time scaling）场景中失效而在论文里看起来有效：论文的基线设定多为贪心或低温度。
4. **spacing 的"成本悖论"是个反直觉的实用发现**：一个看似只是限制的机制（每步少写几个位置）实际降低了总成本，因为延迟的步骤让后续步骤能写更多。这与直觉相反，值得在实现时注意。
5. **重复词是 commit rule 质量的低成本代理指标**：52% → 0.9% 的降幅说明 PACT 写出的答案内部自洽性显著更好，且该指标无需参考答案即可计算，适合做线上监控。
6. **Proposition 2 的 $\sum[H(p_i) - H_\infty(p_i)]$ 给出了"温度代价"的解析形式**：它正是"分布保证"与"实际可靠性"之间的期望间隙随温度增长的速率，为"什么时候必须用 PACT 而不能用传统 rule"提供了量化判据。

## 局限性

- **依赖 Markov 假设**来界定单步内 token 的依赖（论文明确标注），真实 MDLM 的多 token 联合分布远非独立。
- **PACT 增加了每步的计算开销**（抽 token、排序、间距扫描 + 集合级求和），论文主要报告"每 forward pass 写入的 token 数"这一吞吐指标与 forward pass 数，而**没有充分报告端到端 wall-clock 延迟的完整对比**（Figure 3 附近有"seconds per problem"的图，但摘要与正文未给出具体数值）。
- **τ 与 $g$ 需要调参**（默认 $g=8$，τ 需按任务选择），论文给出扫描但未给通用选取规则。
- **实验仅覆盖 4 个 MDLM**（LLaDA 家族 3 个 + Dream-7B），未含其他 MDLM 家族（如基于图像的 masked model）；结论对更强的 MDLM 是否成立未知。
- **基准限于 5 个**（HumanEval、MBPP、GSM8K、MATH500、IFEval），均为短答案/代码类；长文本生成、多轮对话、agentic 场景未测。
- **依赖项 $D(S)$ 未被直接测量**，只用间接证据（重复词率、spacing 的 ablation）支撑"spacing 缩小了第二和"这一说法。
- **Proposition 3 的最优性是相对于"只看实际可靠性这一单一度量"的规则**，而未考虑那些用不同度量（如联合熵、跨步稳定性）可能达成更大集合的规则。
- **LLaDA2.1-mini 上关闭了 spacing**（论文表格脚注），该模型上的 spacing 效果因此未被完整报告。
- **未与 dependence-aware 规则家族直接对标**（Kim et al., 2026 的 attention-based、Ringel et al., 2026 的训练头、Israel et al., 2025 的小 AR 模型、He et al., 2026 的上下文不确定性），而 PACT 的 spacing 本质上是这一思路的简化实现——这个对比缺失削弱了"最好"的论断强度。

## 适用场景

**适用**：
- 部署 LLaDA / Dream 等掩码扩散模型的推理服务，尤其是使用**采样**解码（RL 后模型、test-time scaling、多样性要求高）的场景——这正是传统 commit rule 保证失效之处。
- 需要在不训练模型的前提下提升 MDLM 解码吞吐的工程团队：PACT 是 training-free、零额外 forward pass、只改 commit rule 的 drop-in 替换。
- 对答案自洽性（重复词、局部矛盾）敏感的下游应用（如代码生成）。
- 正在设计"先决策后执行"式采样算法的研究者：PACT 的"先抽后检"模式可迁移。

**不适用**：
- 自回归模型（commit rule 概念不适用）。
- 贪心解码且极度看重单步确定性的场景：此时传统 top-confidence 规则的保证本就成立，PACT 的主要优势（温度鲁棒性）体现不出来。
- 需要绝对最低延迟且模型规模极大的场景：额外排序/扫描开销未被充分量化，需自行测量。
- 训练了专门的 dependence-aware selector 的模型家族（其头可以看 attention/训练信号，信息量大于 PACT 的位置间距启发式）。
