# H2R: Hierarchical Hint-Based Reward for Mathematical Reasoning via Reinforcement Learning

## 摘要
RLVR 已成为提升 LLM 数学推理的主流范式，但稀疏的 outcome reward 存在严重 credit assignment 问题：接近正确的推导得不到任何信号，而"答案对、推理烂"的 reward hacking 反而被强化；稠密的 process reward 又因步骤级标注成本高昂、跨域泛化不稳而难以规模化。作者提出 **Hierarchical Hint-based Reward (H²R)**：利用数学题内在的**子问题层级结构**（如 Q1→Q2→Q3 逻辑链）作为可验证的中间里程碑，在 GRPO 训练中作为结构化的 intermediate conditioning 信号，无需任何步骤级标注或架构改动。为验证该框架，作者提出 **HiMath** 基准：151 道分层结构的数学题，每题含三个逻辑依赖、难度递增的子问题，训练只用 105 题。实验显示：即使不做任务专门训练，hierarchical hints 在 8 个 LLM 上都稳定提升推理性能；接入 RL 后，Qwen2.5-Math-7B 在 HiMath 上从 30.4% 提升到 **39.1%**（Hier.-Hint），使用 Oracle Hierarchical Hints 可达 **45.6%**，且测试时完全不需要 hints。核心论断是：把可靠的中间检查点纳入 reward 设计，对维持复杂数学推理至关重要。

## 核心贡献
1. **HiMath 基准**：151 题分层数学题（三层逻辑链式子问题），每题引入新数学概念以降低记忆依赖、抗污染；105 题用于训练，46 题用于测试。
2. **H²R 奖励框架**：把子问题正确性作为 GRPO 内的中间奖励信号，与 LLM judge 的过程质量打分构成混合奖励，并配 **hard gate** 防 reward hacking。
3. **推理期 hint 消融**：设计 5 种 hint 条件（No-Hint / Sub1-Hint / Sub2-Hint / Hier.-Hint / Oracle Hier.-Hint），在 8 个未训练模型上证明增益源自逻辑结构本身而非任务微调。
4. **结构必要性消融**：Random-Hint 与 Unordered-Hint 对照，隔离"语义相关性"与"层级组织"两个成分的贡献。
5. **跨模型族泛化**：在 Llama-3.2-3B / Qwen2.5-7B / Qwen3-4B 三个模型族、HiMath / MATH500 / AIME24 三个基准上一致优于 GRPO、DAPO、SFT、SAGE 基线。

## 方法与架构
### 1. 层级 hint 定义
HiMath 每题包含三个顺序依赖的子问题 Q1、Q2、Q3，前序结果是后序的前提。子问题答案本身构成"天然的、可验证的中间目标"，编码了预期的推理轨迹，无需额外人工步骤标注。关键性质：**hints 只在训练期使用，测试时完全移除**，因此训练后的策略在部署时不依赖 hints 或分解提示（不同于 inference-time decomposition 方法）。

### 2. 五种 hint 条件
- **No-Hint**：不给任何中间上下文。
- **Sub1-Hint / Sub2-Hint**：分别给出 Q1 或 Q2 的 ground-truth 解答（oracle 级单个子问题），用于区分"基础性"与"临近性"中间结果哪个更 load-bearing。
- **Hier.-Hint**：给出更强外部模型（实验中用 **o3-mini**）生成的 Q1、Q2 解答，模拟无 oracle 监督的真实部署场景。
- **Oracle Hier.-Hint**：给出两个子问题的专家标注 ground-truth，作为性能上界。

### 3. H²R 奖励设计
第 i 条回复的奖励：

```math
s_i = \begin{cases}
\alpha + (1-\alpha)\cdot\min\left(1,\frac{p_i}{\tau}\right), & c_i = 1\\
0, & c_i = 0
\end{cases}
```

其中 $c_i\in\{0,1\}$ 为最终答案正确性（proof 型题目由 LLM judge 判定），$p_i\in[1,5]$ 为 judge 给出的推理过程质量分，$\alpha\in(0,1)$ 是答案正确性的基础权重，$\tau$ 是把离散过程分映射为连续 bonus 的归一化阈值。实验固定 **α = 0.6、τ = 4**，故正确答案的奖励落在 [0.6, 1.0]。

**Hard gate**：只要 $c_i=0$ 就把奖励置零，不允许用过程分补偿。作者指出 Q3 通常是"要证明的命题"，模型可以复制结论并填充无效步骤来伪装成正确推理；去掉 gate 会激励这种模式匹配。消融（Qwen2.5-Math-7B + Oracle Hier.-Hint）：

| Gate | Acc. | Avg. P | Incorr. $p_i\ge3$ (%) | Grad. |
|---|---|---|---|---|
| No Gate | 39.13 | 3.21 | 34.2 | None |
| Soft Gate | 41.30 | 3.45 | 18.7 | Partial |
| **Hard Gate** | **45.65** | **3.89** | **0.0** | Full |

超参敏感性：{α, τ} 网格中 (0.6, 4) 最优（45.65），且两个非 gate 变体都落在次优区域，说明 hard gate 是有原则的设计而非调参结果。

### 4. 训练与评测配置
- 算法：**GRPO**，实现于 **verl** 框架；group size $G=2$，clip epsilon 0.2，AdamW，学习率 **1e-6**，cosine 调度；最大响应长度 **2,048 token**（超长生成被过滤，论文称只影响可忽略比例且各 hint 条件分布均匀）。
- 训练模板含 `<prompt>`、`<hints>`、`<question>` 三段；judge 被要求输出 JSON，含 correctness（0/1）与 process_score（1–5），并遵循"若 correctness=0 则 process_score ≤ 3"的规则。
- 硬件：每次训练约 3–4 小时 / 4×NVIDIA H100；全部模型 × hint 条件 × 3 个随机种子累计约 **600 GPU hours**。
- 评测：HiMath 为 avg@3（3 个独立训练种子的平均准确率），MATH500 为 greedy pass@1，AIME24/25 为 temp 0.7 的 avg@5；HiMath 的证明题由 LLM judge（主 judge 为 o3-mini）依据人类参考解答判定"推导与结论是否一致"。
- 评测鲁棒性：另用 GPT-4o 与 DeepSeek-R1 作为独立 judge，绝对值略有差异但保持 No-Hint < Hier.-Hint < Oracle Hier.-Hint 的排序；并做了 25 条回复的盲评人工审核（20 条随机 + 5 条 judge 分歧样本），两名作者对 20 条随机样本中的 19 条判定与自动评测一致，25 条中 23 条与汇总人工审核一致。
- 统计检验：对 46 道测试题做 paired cluster bootstrap，10,000 次重复。

## 实验设置
- **模型**：hint 条件消融用 Qwen2.5-Math-7B 与 Qwen2.5-7B-Instruct；跨模型族泛化用 Llama-3.2-3B-Instruct、Qwen2.5-7B-Instruct、Qwen3-4B-Instruct-2507（文中简称 Qwen3-4B-Instruct）。
- **推理期评测**：8 个未训练 checkpoint × 5 种 hint 条件，指标为 Q3 的准确率（不给 hint 时）。
- **RL 对照基线**：GRPO（No-Hint）、DAPO（No-Hint）、SFT（Oracle Hier.-Hint）、SAGE / SAGE-Light（Self-Hint，作为外部参考，训练数据约 220K 题 vs H²R 的 105 题）。
- **结构消融**：Random-Hint（保留 hint 格式、标签与监督量但语义无关）、Unordered-Hint（用本题 gold hints 但倒序并去掉层级标签）。
- **数据集**：HiMath 151 题（105 训练 / 46 测试），主题覆盖 functions、sequences、sets、geometry；MATH500；AIME24 / AIME25。
- **训练开销**：单次运行 3–4 小时 4×H100；总计约 600 GPU hours；3 个随机种子。

## 实验结果
**推理期 hint 效果（8 个模型，Figure 3）**：Sub1-Hint 带来 **+2.8% ~ +13.8%** 的准确率提升，Sub2-Hint 带来 **+0.7% ~ +17.4%**；平均而言 Sub2-Hint 的边际增益比 Sub1-Hint 高近 50%（+8.0% vs +5.5%），说明**逻辑临近性**驱动 hint 有效性。Hier.-Hint 稳定优于 Sub1-Hint 与 Sub2-Hint（说明增益主要来自中间上下文的**完整性**），但又低于 Oracle Hier.-Hint（说明中间解的**准确性**同样关键，Q1/Q2 的错误会传播到 Q3）。Qwen 模型族内相邻规模之间经 pairwise bootstrap 检验无统计显著差异。

**HiMath 难度（不给 hint 的 Q3 准确率）**：o3-mini 66.9%、Gemini-3.1-pro 63.5%、Gemini-2.5-pro 59.3%；开源模型差距更大：Qwen2.5-Math-7B-Instruct 与 Qwen2.5-7B-Instruct 均约 20.7%、Qwen2.5-Math-7B 17.9%、Qwen3-4B 12.4%。对照之下这些模型在 MATH500 上常超过 75%。

## 局限性
作者自述：
- **数据规模**：HiMath 刻意小规模（151 题），优先保证结构深度与抗污染；虽在 MATH500 与 AIME24 上有提升，但不能据此确立广泛/通用推理能力，需要在更多任务与数据集上评估。
- **自动化评测**：依赖 LLM-as-judge；虽然用 o3-mini、GPT-4o、DeepSeek-R1 多 judge 与 25 条盲评人工审核验证了排序稳健性（20 条随机样本中 19 条一致，25 条中 23 条一致），但自动评测仍可能遗漏数学推理的细微之处。
- **无 PRM 基线**：HiMath Q3 是证明题、没有可用于自动标注中间证明状态的 canonical answer string，改造 PRM 需要额外的 judge 标注与完全不同的监督管线，成本过高，故未做忠实的 in-domain PRM 对照；作者把"面向证明的 PRM"列为未来方向。
- **验证域受限**：作者 conjectures H²R 可推广到物理推导、证明几何、多步编程等 STEM 场景，但数学之外的验证是未来工作。

我的补充批评：HiMath 每题引入"新数学概念"的设定使得它在 MATH500/AIME24 上的迁移增益更多体现为"学会利用中间信息"这一通用策略，而非数学能力本身；用 o3-mini 生成的 Hier.-Hint 本身携带了强模型能力，收益部分可能来自蒸馏效应而非 hint 结构——Random/Unordered 消融只控制了 hint 内容的语义与顺序，未控制 hint 的**生成质量**；此外 group size G=2 偏小，GRPO 的组内对比信号很弱，绝对数值需谨慎解读。

## 评估与建议
- 是否推荐深入阅读：是（作为"利用问题内在结构做 reward shaping"的简洁范例，对 design 过程奖励/中间监督的读者很有启发）
- 适用场景：设计 RLVR 奖励；构造带层级结构的数学/科学评测集；研究 credit assignment 与 reward hacking 防护；proof 型任务的自动评判设计。
- 与知识库的关联：与 GRPO/DAPO 类 RLVR 笔记、process reward model 与 self-consistency 相关工作形成对照；与 2610.39182（RL 是否带来真正推理的机制分析）、2610.40350（agent 上下文管理）同属"RL 究竟教了什么"的主题簇。
