# RECAST：通过可审计结构化轨迹重建思维链

| **摘要** | Large closed-source reasoning models expose only their final answers. The intermediate reasoning that produces those answers is hidden behind API surfaces, tool-call policies, and safety filters. Existing chain-of-thought (CoT) extraction methods assume a side channel: a visible reasoning field, a scratchpad carried through tool calls, or a signed/encrypted reasoning block. We reproduce three representative state-of-the-art extraction methods and find that, on Claude-Sonnet-5.5 accessed through the standard chat-completions interface, all three return zero CoT tokens. The failure is structural rather than a bug: the reasoning field is absent, named tool selection is rejected, free-text scratchpad arguments are filtered, and no replayable reasoning block is exposed. We therefore take a different route. We present RECAST, a reconstruction-based framework that conditions a decoder on the question and the target model's final answer, reconstructs a first-person structured rationale, cleans it, and builds SFT-ready data. To the best of our knowledge, RECAST is the first system to reconstruct CoT from frontier closed models such as Claude-Sonnet-5.5, GPT-6.1, and Gemini 3 without using hidden reasoning channels. We instantiate RECAST on Claude-Sonnet-5.5 and additionally obtain successful qualitative reconstructions on GPT-6.1 and Gemini 3 with the same answer-only protocol. The system is open-source and packaged as an agent skill: one prompt deploys it and runs the complete pipeline to produce SFT-ready CoT data. This preprint describes the system, its threat model, and a controlled artifact validation; it does not claim large-scale benchmark improvements. |

## 核心贡献

1. **问题**：大型闭源推理模型**只暴露最终答案**，中间推理隐藏在 API 表面、工具调用策略与安全过滤器之后。
2. **关键负面发现（本文最有价值的部分）**：复现**三个代表性的 SOTA CoT 抽取方法**，在通过标准 chat-completions 接口访问的 **Claude-Sonnet-5.5** 上，**三者全部返回零个 CoT token**。
3. **失败是结构性的而非 bug**：reasoning 字段不存在、命名工具选择被拒、自由文本 scratchpad 参数被过滤、**没有可重放的 reasoning block**。
4. **换路**：提出 **RECAST**，一个**基于重建**的框架 —— 用**问题 + 目标模型的最终答案**条件化一个**解码器**，**重建第一人称的结构化理由（first-person structured rationale）**，再清洗它并构建 **SFT-ready 数据**。
5. **声称**是首个**不使用隐藏推理通道**从 Claude-Sonnet-5.5、GPT-6.1、Gemini 3 等前沿闭源模型重建 CoT 的系统；在 Claude-Sonnet-5.5 上完整实例化，并在 GPT-6.1 与 Gemini 3 上用同样的"仅答案"协议获得成功的定性重建。
6. **系统以 agent skill 形式开源**：一个 prompt 即可部署并运行完整流水线产出 SFT-ready CoT 数据。
7. **作者明确声明**：本文描述系统、威胁模型与受控的 artifact 验证，**不声称大规模 benchmark 提升**。

### 关键发现

- **"三个 SOTA 抽取方法全部返回零 CoT token"** 是一个**有价值的负面结果** —— 它证伪了"CoT 可以被抽出来"这一在社区中广泛默认的前提。
- **"失败是结构性的而非 bug"** —— 作者进一步给出了四种具体机制（字段不存在/工具被拒/参数被过滤/无重放块），这让结论更可信。
- **答案是唯一的输入** —— 这就是"黑盒推理蒸馏"能走到的极限：**你只能重建一个与最终答案一致的合理解释，不能恢复真实的中间步骤**。这是一个**本质上不可恢复的信息**，论文诚实地用"重建"而非"抽取"来命名方法。
- 与 [[2026-11-02-2610.41769-stepwise-querying-distilling-reasoning-without-access-to-teacher-chain-o]] 是同一问题的**两条不同路线**：Stepwise Querying 向**教师**逐步提问（拿到的是教师真实生成的中间步骤），RECAST 从**答案反向重建**（拿到的是事后合成的解释）。**前者更接近真相，后者更易规模化**。
- 与 [[2026-11-02-2610.41803-what-standard-evaluations-hide-about-detectors-of-hijacked-llm-agents-ra]] 的"监控可被察觉"呼应：闭源模型在**对外接口层面已经系统性收紧了推理暴露** —— 这是行业演进的结果，不是可以绕过的工程障碍。

## 局限性

- **重建 ≠ 真实推理**。生成的理由是"与答案一致且合理"，其真实性无法验证 —— 用它做 SFT 有可能**注入系统性偏差**（模型学会"编造一个像样的推导"）
- 只有定性验证，无大规模量化效果
- 仅覆盖 3 个闭源模型与 1 个重建解码器
- 伦理与合规风险显著（重建他人模型的推理过程）
