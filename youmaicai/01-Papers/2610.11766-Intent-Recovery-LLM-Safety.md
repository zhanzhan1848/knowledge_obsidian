## 核心贡献

> 引入 UR (Understanding Rate) 与 ASR 联合报告，揭示同一无害输出可能源于截然不同的内部状态（拒绝/未识别/完全回答其他问题），证明 ASR 单独不足以反映真实安全水平。

1. 提出 **UR** (operative Understanding Rate)：响应是否识别并把任务视为"待回答任务"
2. ASR + UR 配对揭示 ASR 隐藏的差异
3. 在 FormalLogic 上：UR 高但 harmful assistance 也高 → **recovery ≠ safety**

---

## 技术方案

### 核心思想

LLM 安全评估常以 ASR（攻击成功率）衡量。但同一"非有害"输出可能源于：①识别任务并拒绝；②未识别任务；③回答了完全不同的东西。意图模糊（intent-obscuring）的 prompt 下，低 ASR 不能说明模型真正"处理"了任务。UR 显式区分这些情况。

### 关键技术

| 技术 | 说明 |
|------|------|
| ASR (Attack Success Rate) | 现有标准：输出是否包含有害内容 |
| UR (Understanding Rate) | 新增：响应是否把目标任务视为任务并尝试回答 |
| Controlled reconstruction | 用受控英文重建 prompt 测试 UR vs ASR 模式差异 |
| FormalLogic analysis | 揭示 UR 高 + harmful assistance 高同时存在 |

### 关键发现

- 相似 ASR 值背后可能 UR 差异巨大
- Prompt 越显式 → UR 越高，但 ASR 不一定跟随
- FormalLogic：UR 高时，harmful assistance 也频发
- **结论**：non-harmful outcomes 不等价于 model safety

---

## 公式

```math
\text{ASR} = \Pr[\text{harmful content in output}]
```

```math
\text{UR} = \Pr[\text{response identifies task AND treats it as task to answer}]
```

联合报告：$(\text{ASR}, \text{UR})$ 二元组取代单一 ASR。

---

## 实验结论

- **数据集**: 多个 LLM 安全评估接口，英文重建 prompt + FormalLogic
- **方法**: ASR + UR 配对报告
- **结果**: 
  - 相似 ASR 背后隐藏 UR 巨大差异
  - Prompt 显式性提升 UR，但不影响 ASR
  - FormalLogic：UR 高 ≠ 安全

---

## 局限性

- UR 的定义依赖"任务识别" 的精确化
- 主要在英文上验证
