## 核心贡献

> **事实核查分数由三个设计决策共同决定**，而现有基准没有一个同时规定了全部三个：核查哪些问题、在什么条件下核查每个声明、哪些来源算证据。JSFactCheckBench 是首个同时规定三者的日语基准。

1. **提出 JSFactCheckBench**：日语事实核查基准，**1,913 条声明**，全部来自 LLM 对"日本社交媒体上流传的误导性信息"类问题的回答
2. **三条件显式化**：每个声明标注了 (a) 事实性，**以参考时间点为准**；(b) 对该问题的重要性；(c) **从预选 Web 来源收集的证据**
3. **发现"直接回答声明 vs 补充声明"的系统性差距**：六个 LLM 上，直接回答问题的声明**全部**比补充性声明核查得更不准确 —— 而**聚合分数会掩盖这一差距**
4. **发现"证据定位难度"的退化**：当模型必须在**更长或多个来源中定位相关内容**时，分数下降
5. **发现上下文敏感退化**：对**全部四个开源模型**，加入周边问题与回答上下文后分数下降
6. **方法论结论**：这些弱点**只有因为基准记录了每个标签背后的条件才可见** —— 条件隐含的基准**无法暴露它们**

## 技术方案

### 核心思想：把分数分解到条件

```
LLM 回答 → 拆成原子声明
             ↓
   ┌─────────┴──────────┐
   ↓                    ↓
直接回答声明        补充性声明     ← 问题的角色
   ↓                    ↓
   └─────────┬──────────┘
             ↓
   事实性 @ 参考时间点  +  对问题的重要性
             ↓
   证据来源（预选 Web 源）
             ↓
     核查准确率（可按条件切片）
```

### 三个决定分数的设计决策

| 决策 | 说明 | JSFactCheckBench 的处理 |
|------|------|------|
| 哪些问题的声明被核查 | 问题的**角色**（直接回答 vs 补充） | 显式标注声明与问题的关系 |
| 每个声明在什么条件下被判断 | **参考时间点** + 问题/回答上下文的有无 | 每个标注都绑定 reference time 与上下文条件 |
| 哪些来源算证据 | 证据来源集合 | 标注使用**预选 Web 来源**的证据 |

### 关键技术

| 技术 | 说明 |
|------|------|
| Reference-time-anchored annotation | 事实性标注锚定在特定参考时间点，而非"永远真/假" |
| Importance annotation | 每条声明额外标注其对原问题的重要性，使加权/分角色分析可行 |
| Pre-selected evidence sources | 证据来自预选 Web 源，避免不同模型各自检索造成条件不可比 |
| Conditional slicing | 分数可按"是否加上下文""证据源数量/长度"等维度切片 |
| Japanese misinformation domain | 取材于日本社交媒体流传的误导性信息，属于现实且文化特定的核查场景 |

## 关键实验结果

| 维度 | 结果 |
|------|------|
| 数据规模 | **1,913 条声明**，来自 LLM 对日本社交媒体误导性信息类问题的回答 |
| 评测模型 | **6 个 LLM**（其中 **4 个开源模型**用于上下文敏感实验） |
| 直接 vs 补充声明 | **6/6 模型**：直接回答问题的声明**准确率更低**（aggregate score 掩盖此差距） |
| 证据定位难度 | 模型需在**更长**或**多个**来源中定位相关内容时，分数**下降** |
| 上下文敏感 | **4/4 开源模型**：加入周边问题与回答上下文后分数**下降** |
| 关键设计 | 弱点的可见性**依赖于基准是否记录标签背后的条件** |

> 摘要**未给出具体的准确率数值**，只给出定性方向（更低/下降）。具体 pp 差距需查正文表格。

## 关键结论

1. **"LLM fact-checker 分数"是一个复合量，不是模型属性**。不声明三个条件就报一个数字，等于隐藏了绝大部分测量内容。
2. **补充性声明比直接回答声明更容易核查** —— 反直觉但方向一致（6/6）。这意味着核查器在"顺着问题答"的声明上更弱，聚合分数会因大量补充声明而被稀释。
3. **上下文不是免费的**：给核查器看到原问题与回答，反而让它在 4/4 开源模型上变差 —— 说明模型会被相邻文本带偏。
4. **证据检索能力是独立瓶颈**：源更长、源更多 ⇒ 分数更低，与"核查能力"本身分离。
5. **评测设计的教训**：基准必须**记录标签条件**（时间点、上下文、证据来源、声明角色），否则上述三个弱点都无法被发现。

## 局限性

- **仅日语**：结论是否跨语言成立未验证（跨语言泛化是已知风险）
- **无具体数值披露**：摘要只给定性方向，无准确率、pp 差距
- **领域单一**：全部声明来自"社交媒体误导性信息"这一类问题，不覆盖医学、法律等高风险领域
- **参考时间点**依赖 Web 源的时效快照，历史快照获取方式与误差未说明
- **6 个模型、其中 4 个开源** —— 样本量对"6/6 一致"这类论断是必要的，但绝对水平未知
- **代码未在摘要提供**，基准复现门槛未知

## 实现建议

- **实现难度**: 中高（需日语文本理解 + Web 证据收集 + 精细标注流水线）
- **适用场景**: 为日语文本构建**事实核查评测集**；以及任何要**评测"LLM 核查器"而非"LLM 回答者"**的团队
- **建议动作**:
  1. 自建核查基准时，**强制为每条标注记录**：参考时间点、是否提供原问题/回答上下文、证据源清单
  2. 报告分数时**按"直接回答 / 补充声明"分层**给出，而不是只报一个 aggregate
  3. 增加"多来源 / 长来源"的证据定位切片，作为独立维度追踪
- **与相关工作互补**: 与 [[2026-10-25-2610.29767-alias-tla-plus-memorization]] 合起来构成 2026-10-24 日报"评测方法论批判"主线的两条新证据 —— 一个批**打分方式**，一个批**分数所依赖的条件未显式化**
