## 核心贡献

系统比较三种 RLVR 多域能力融合范式：

1. **Merge**：合并 expert task vectors（τ_i = θ_i - θ_0），无需额外训练
2. **Mix RL**：混合多域数据集，单次 RLVR 运行
3. **MOPD**（Multi-Teacher On-Policy Distillation）：同时利用 task vectors 和数据集

## 三种范式对比

| 维度 | Merge | Mix RL | MOPD |
|------|-------|--------|------|
| **复用 artifacts** | τ_i (task vectors) | D_i (数据集) | τ_i + D_i |
| **额外训练** | 无（分钟级） | 需要 | 需要 |
| **成本** | ~0 | 0.6× per-domain | 0.2× (+ experts) |
| **优点** | 便宜快速 | 无需 experts | 保留域内增益 |
| **缺点** | 冲突压缩 | 混合比例敏感 | 依赖 teachers |

## 关键发现

1. **平均性能差距 ≤1.4 分**，但单基准差距可达 **8.6 分**
2. **域间关系结构**（从 task-vector 几何中可见）：
   - Math, Science, Code 互相增强
   - Instruction Following, Agentic Tool Use 与其他域几乎正交
3. **pass@32 时三种范式均无明显优势**——fusion 提高单样本精度，但不扩展可解决问题集
4. **held-out 能力（事实回忆、长上下文）不受影响**——没有能力损失

## 实用指南

- **Merge**：当 experts 已存在、追求低成本融合时
- **Mix RL**：从头训练统一模型，按跨域转移调整域比例
- **MOPD**：域内增益保留比超越 teachers 或最小化端到端成本更重要时

## 实验设置

**模型**：Qwen3-4B-Instruct-2507, Qwen3-8B（非 thinking 模式）

**五域数据**：
- Math: 38,131 样本（Polaris 筛选）
- Science: 50,000 样本（OpenScienceReasoning-2）
- Coding: 19,169 样本（CodeContests + Open-R1）
- Instruction Following: 16,575 样本（WildChat-1M + Open-Instruct）
- Agent: 10,229 样本（WorkplaceAssistant）

**基准**：AIME 2025/2026, GPQA-Diamond, LiveCodeBench v5/v6, IFEval, IFBench, BFCL v3

## 局限性

- 主要在 Qwen3 系列验证，跨架构泛化未充分研究
- Merge 的 task-vector 冲突解决策略可进一步优化
- MOPD 的 end-to-end 成本（含 expert 训练）最高

## 建议
- **推荐使用**：是（针对多域 RLVR 融合场景）
- **适用场景**：需要将多个 RLVR 域专家合并为单一模型
- **关键洞察**：选择 fusion 方法前先评估域间关系
