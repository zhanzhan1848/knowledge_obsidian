## 核心贡献
1. 提出并操作化定义 **"可恢复能力前沿"（recoverable capability frontier）**：一个**策略依赖**的题目集合，其解在**直接解码下不可靠生成**，但能在**有界的轨迹级搜索**下被诱导出来。判据是：在模型参数固定、外部 verifier 判定的前提下，存在**从失败到成功的验证确认转移**。
2. 关键实证：**直接失败 ≠ 能力缺失**。在 Qwen3-VL-8B 上，对 243 题源集做 correct–incorrect 轨迹交叉，产生 **621 个 correct–failed 后代，其中 272 个被 verifier 确认为正确（后代级恢复率 43.8%）**——这是"失败轨迹中仍包含互补的可恢复推理信息"的直接证据。
3. 提出 **ReSI-Math** 四阶段框架：**Elicit → Repair → Consolidate → Reprofile**，实现"局部递归自我改进"（ReSI = **Re**cursive **S**elf-**I**mprovement）。
4. **Self-Judge 引导的进化搜索**：同一个模型从 Solver 角色切换为 Self-Judge，对候选轨迹做结构化分析（有用成分、潜在错误、互补信息），引导交叉算子重组互补推理结构。区分 **Blind Judge**（不看 verifier 结果/参考答案）与 **Guided Judge**（额外接收 verifier 反馈但仍隔离参考解）。Self-Judge 只做**搜索控制器**，正确性始终由**确定性 verifier** 判定。
5. **双信号 RLVR**：可恢复题目 → **Solver-RLVR**（在原题上直接用 verifier 奖励训练策略，而非模仿进化出的正确轨迹）；Self-Judge 与 verifier 的分歧 → **Judge-RLVR** 的轨迹级监督（识别出 **33 个假阳** + **35 个假阴**，共 **68 个显式自纠错信号**）。
6. **策略自适应序贯 one-shot RLVR**：每次策略更新后**重新 profile** 候选池并重算选择分数，再选下一个训练题——因为"最有信息量的题"会随策略演化而改变。
7. **主结果**：Qwen3-VL-8B 上三阶段序贯 one-shot RLVR 把 **MATH500 与 WE-MATH 平均从 78.71 提升到 80.16**；**匹配预算的单题 RLVR** 对比中，frontier-guided Q1 达 **54.16**，随机选择仅 **53.31**。
8. **关键的负面发现（同样重要）**：one-shot RLVR **不诱导单调的能力获得**。2B 表现出"稳定保持"，4B 表现出"目标退化"，8B 表现出"暂时遗忘后部分恢复"；进一步的再训练实验揭示**反向干扰**——改进目标能力会抑制先前已巩固的能力。
9. **跨规模规律**：候选池大小随模型规模变化——2B 为 69 题、4B 为 32 题、8B 为 28 题——说明**模型越小，共享问题分布中落在可恢复边界附近的比例越大**。

## 问题背景
RLVR 已成为提升 LLM 数学推理能力的有效手段（DeepSeek-R1 等）。但一个基础问题长期未被回答：**当模型解不出某题时，它是真的缺乏这个能力，还是只是这一次生成过程没有把能力诱导出来？**

推理期证据支持后者：重复采样与自我精炼能在失败后产生成功解（Best-of-N、Self-Refine）；CoTEvol 展示推理轨迹可通过交叉与变异演化。但这些工作多数关注**最终改进的 CoT**，而不是**在固定参数下失败是否可恢复**。

作者把这一问题操作化为"可恢复能力前沿"：**直接采样描述一个题被解得有多一致；搜索则探测能否通过检查并重组已生成的轨迹得到正确解。** 全程模型参数固定，外部 verifier 判定答案。frontier 因此是**相对于当前策略与指定搜索过程及预算**的操作性定义。

这一视角与数据高效 RLVR 直接相关：LIMR 展示了精选训练子集的价值，One-Shot RLVR 表明**单条数据**也能带来显著提升，DoPR 动态选择有信息量的样本。作者更进一步：**数据的价值是策略依赖的**——最有信息量的题会随策略自身演化而改变。

作者的实证动机来自 Figure 1：在 28 题候选池 × 16 rollouts 的 profile 上，从 base policy 到第三阶段，**全失败题从 18 降到 12，全通过题从 0 升到 4，总正确 rollouts 从 37/448 升到 128/448**——策略在变，因此候选池必须重新评估。

## 方法

### 1. Elicit：探测可恢复能力前沿
给定当前策略 $\pi$ 与数学题 $x$，采样得到轨迹集合 $\mathcal{T} = \{\tau_1, \dots, \tau_n\}$。每条轨迹由**规则化 verifier** 赋二元结果，分成 $\mathcal{T}_{correct}$ 与 $\mathcal{T}_{failed}$，构成后续修复的初始种子集。

关键区分：
- **直接表达能力（directly expressed capability）**：直接生成下 verifier 确认的成功；
- **可恢复能力（recoverable capability）**：参数固定时，存在有界的搜索或重组算子使得

$$
\exists\, \mathcal{S} \text{ (bounded search/recombination)}:\ \text{verifier}\Big(\mathcal{S}\big(\mathcal{T}_{failed}\big)\Big) = \text{correct}
$$

  成功的恢复表明能力存在于**当前策略诱导的轨迹分布中**，而非通过参数更新获得。

**前沿不等价于"对/错边界"**：直接采样可能同时产生正确与失败轨迹；甚至**两条失败的父轨迹也可能被重组为 verifier 确认正确的后代**（Failed–Failed-to-Correct）。因此**可恢复性不需要一个初始正确的父代**，判据是"有界结构化搜索下存在 failure-to-success 转移"，而非初始通过率。

### 2. Repair：Self-Judge 引导的进化搜索
模型参数在此阶段**保持固定**，搜索被限制在当前策略诱导的轨迹空间内。

**两种 Self-Judge 模式**：
- **Blind Judge**：评估推理，但**不接触** verifier 结果与参考答案；
- **Guided Judge**：额外接收 verifier 确认的结果反馈，但仍**隔离于参考解**。

Self-Judge 与 verifier 职责分离：**Self-Judge 提供搜索引导，verifier 提供外部正确性判据。**

给定父代 $\tau_p, \tau_q$ 及其 Self-Judge 反馈，生成后代轨迹：

$$
\tau_o = \text{Crossover}(\tau_p, \tau_q, \text{JudgeFeedback}(\tau_p), \text{JudgeFeedback}(\tau_q))
$$

交叉算子改编自 CoTEvol 的**reflective global crossover** 形式，用于**重组互补推理结构**而非逐字复现父代。每个后代由规则化 verifier 评估；从**至少一条失败父代**到正确后代的 verifier 确认转移即构成一次**实现的 failure-to-success 转移**（包括 Correct–Failed 与 Failed–Failed 两种情形）。

后代级恢复率定义为

$$
\text{RecoveryRate} = \frac{|\{\tau_o : \text{verifier}(\tau_o) = \text{correct}\}|}{|\{\text{generated correct–failed offspring}\}|}
$$

这一指标**区别于**"至少一次成功修复的源题比例"。

### 3. Consolidate：双信号 RLVR
搜索时可恢复 ≠ 能力能被稳定表达。因此 Consolidate 把进化中暴露的信号转化为参数级学习。

**Frontier-guided 问题选择**。对候选题 $x_i$，设 $n_i$ 为采样轨迹数、$c_i$ 为 verifier 确认正确数、$m_i$ 为成功解析输出数。定义：

- **rollout 成功率** $\text{rs}_i = c_i / n_i$
- **答案级分歧度**（基于成功解析输出中答案类别的分布）：

$$
\text{dis}_i = 1 - \max_{a}\frac{|\{o \in \text{parsed}(x_i) : \text{ans}(o) = a\}|}{m_i}
$$

- **有效输出率** $\text{val}_i = m_i / n_i$
- **frontier 选择分数**：

$$
\text{score}_i = w_1 \cdot \text{rs}_i + w_2 \cdot \text{dis}_i + w_3 \cdot \text{val}_i
$$

三个因子分别偏好：**非退化的 rollout 结果**、**高答案级分歧**、**可靠的输出解析**。选取得分最高者 $x^* = \arg\max_i \text{score}_i$ 作为**单题 Solver-RLVR** 的训练目标。

**Solver Consolidation**。对展现出 verifier 确认 failure-to-success 转移的题目，**不模仿进化出的正确轨迹**，而是**在原题上直接用 verifier 奖励训练当前策略**——目标是把"只能通过搜索诱导的能力"转化为"可通过直接生成更可靠表达的行为"。

**Judge Consolidation**。进化同时通过比较 Self-Judge 预测与 verifier 确认结果，暴露**自评估错误**。这些分歧为 **Judge-RLVR** 提供轨迹级监督，训练模型更好地判别候选推理轨迹是否达到正确结果。

### 4. Reprofile：局部递归自我改进
frontier 是**策略依赖**而非候选集的固定属性。策略从 $\pi_k$ 更新到 $\pi_{k+1}$ 后，同一批候选题的 rollout 分布会变：原本靠近 frontier 的题可能变得可靠可解（信息量下降），其他题则可能更靠近更新后的能力边界。

因此每次策略更新后**重新评估候选问题**。设第 $k$ 阶段候选池为 $\mathcal{P}_k$，在当前策略 $\pi_k$ 下重新采样，重算 frontier 选择分数，再用同样的 top-1 规则选出下一题：

$$
x_{k+1} = \arg\max_{x \in \mathcal{P}_k} \text{score}_{\pi_k}(x)
$$

在 $x_{k+1}$ 上训练得到 $\pi_{k+1}$，在 $\pi_{k+1}$ 下重新 profile 候选池，再进入下一轮。这个 **profile → select → update** 循环即"策略自适应序贯 RLVR"。

### 5. 训练配置
Solver-RLVR 与 Judge-RLVR 均用 **GRPO** + **LoRA** 适配。Solver-RLVR 每训练题 **16 次 online rollout**、batch size 1；Judge-RLVR 每个候选 prompt **8 次 rollout**。规则化 verifier、进化搜索配置与 RLVR 超参在附录 B。

## 关键洞察
1. **"解不出来"是关于策略与采样过程的陈述，不是关于模型能力的陈述。** 43.8% 的后代级恢复率意味着相当大比例的失败轨迹**内部已经包含正确解所需的互补结构**。这把"能力边界"从一个静态的评测概念变成了一个**可用搜索主动探测的对象**。
2. **可恢复性的判据是"失败→成功转移"，不是"通过率低"。** Failed–Failed-to-Correct 的存在说明**可恢复性甚至不需要一个初始正确的父代**——这比"高采样方差"强得多。传统上会把高方差题当作噪声丢掉，本文指出它们恰恰是最有训练价值的。
3. **训练数据的价值是策略依赖的，因此选择必须是动态的。** Fixed-Seq（同样的候选池、固定遍历顺序）在三个规模上全部**负增益**（−0.23 / −1.01 / −1.13），而策略自适应选择全部为正。frontier 随策略移动，这直接要求每轮重新 profile。
4. **极端低数据区间是最能暴露选择质量的区间。** Random-1 只涨 0.08 分且**跨维度不一致**（有的升有的降），frontier-guided 涨 0.93 分且在多个维度同时超过 base。在这个区间，"选哪一条数据"几乎就是全部。
5. **one-shot RLVR 不是单调的。** 这是本文最反直觉也最重要的负面发现：2B 稳定保持、4B 目标退化、8B 遗忘后恢复——单题梯度更新会产生**双向**后果，包括**反向干扰**（改进 A 能力压掉 B 能力）。这直接挑战了"one-shot RLVR 必然带来提升"的乐观叙事，也解释了为什么策略自适应（而非贪心重复训练）是必要的。
6. **搜索过程同时是能力探针和标注来源。** 一次进化搜索产出三类资产：可恢复题目（Solver 监督）、Self-Judge 错误（Judge 监督）、以及轨迹演化本身的数据。Judge-RLVR 把"自我评估的失败"变成训练信号——这是一个可以推广到任何"模型同时扮演生成器与评估器"场景的模式。
7. **Self-Judge 的 33 假阳 / 35 假阴说明"模型自评"仍有实质错误率。** 论文的处理方式值得借鉴：**用确定性 verifier 兜底，把 LLM judge 降级为搜索启发式**。这比把 LLM judge 当 oracle 的常见做法稳健得多。
8. **规模越小，frontier 越大。** 69 / 32 / 28 的候选池大小说明**小模型的低数据 RLVR 空间更宽**——这对"该给多大模型做极致数据效率优化"有直接决策含义。

## 局限性
- **frontier 是操作性的经验定义**，作者明确承认：它**不是**模型相对于训练数据的严格能力边界刻画，只在当前实验设置下成立。
- **实验范围窄**：主要限于 **Qwen3-VL 家族**与**数学推理**；Solver 与 Judge **分别优化**而非联合优化，联合优化的潜在收益未验证。
- **"可恢复"只在特定搜索算子与预算下成立**，换搜索方式或预算会得到不同的 frontier——因此 frontier 的划分有算子依赖性。
- **强依赖规则化 verifier**：数学题有客观答案可自动判定；**开放式/生成式任务没有这样的外部判据**，该框架难以直接迁移。
- **Judge-RLVR 在 Reasoning 维度反而下降**（75.51 → 73.47，−2.04），虽然总体上升 0.86；说明 Judge 训练存在维度间的迁移代价。
- **8B 上的最终提升（+1.79）小于 2B（+2.15）**，且 4B 上优势微弱（+0.36 vs Full-Batch 的 +0.93——**4B 上 joint GRPO 反而更好**），策略自适应相对 joint 优化的优势**依赖模型**，不能一概而论。
- **每阶段的 checkpoint 选择使用 DEV192，而 DEV192 包含在完整评测基准内**；附录 C 提供了排除这些开发题的结果，但主表的数字仍存在乐观偏差风险。
- **Ours-Q1 在 2B 上是负增益**（40.12 → 40.08），说明单次 front ier 选择也可能选错；三阶段的收益高度依赖前两阶段的表现。
- **反向干扰与遗忘的严重程度**只在附录 E.2 的 rollout profile 中展示，未给出系统性的量化缓解方案。
- 训练涉及完整的进化搜索（243 题 × 多轮采样 × 交叉）+ 3 阶段 RLVR，总成本虽标称"数据高效"，但**搜索本身的算力开销未被完整核算**。

## 适用场景
- **适用**：数学/可验证推理任务的数据高效 RLVR；需要为小模型榨取极致性能（2B 增益最大）；Self-Refine / Best-of-N 类自改进系统的算法设计；"哪个训练样本最有价值"这一问题的实践回答；希望把"模型自我评估的错误"转化为训练信号的场合。
- **不适用**：无客观 verifier 的开放式任务（写作、对话、创意生成）；需要单调稳定提升的微调流程（存在目标退化与反向干扰风险）；模型已经能稳定解决绝大多数候选题的场景（frontier 为空）；需要严格复现"能力边界"的科学结论（frontier 是操作性的）。
- **不适用**：对训练稳定性零容忍的场景——4B 的 target degradation 与 8B 的 forgetting/recovery 表明单题 RLVR 可能临时破坏已有能力。
