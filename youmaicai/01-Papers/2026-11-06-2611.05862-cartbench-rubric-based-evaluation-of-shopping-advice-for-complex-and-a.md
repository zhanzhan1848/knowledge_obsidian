# CARTBench: Rubric-Based Evaluation of Shopping Advice for Complex and Ambiguous Requests with Timelines

## 摘要
**CARTBench** 面向 LLM 购物助手的「复杂且模糊、带时间线的请求」评估。两大难点是**数据稀缺**与**难度标准难统一**。作者从 17 个零售领域的真实商业需求构造带时间戳的对话，配 1,603 条商品记录；并从成功订单中人工挑选优秀回复，蒸馏出 **Ideal Response Principles**，据此制定 case-specific rubric 与 **Principle-Guided CART Prompting** 结构化推荐策略。基准含 **1,328 条专家标注标准**（Core / Excellence / Safety 三档）。首次全量评测中：7 个商业 API 旗舰模型 + 35B+ 开源模型里，**10 个模型中仅 3 个在 Core 上超过 90%，而 Excellence 上无一超过 45%** —— 作者由此提出「**理解到执行的落差**」。

## 核心贡献
1. 构建 **CARTBench**：17 个零售领域、带时间戳的多轮对话 + 1,603 条商品记录，1,328 条专家标注标准（Core/Excellence/Safety）
2. 提出 **Ideal Response Principles** —— 从成功订单的优秀人工回复中蒸馏，作为 case-specific rubric 的依据
3. 提出 **Principle-Guided CART Prompting** —— 结构化推荐策略，同时作为 prompting 方法被评测
4. 识别并量化「**理解到执行的落差（understanding-to-execution gap）**」：Core 90%+ 但 Excellence < 45%

## 方法与架构
**数据构造**：真实商业购物需求（17 个零售领域），对话带时间戳，配 1,603 条商品记录。

**标准制定**：人工挑选成功完成订单中的优秀回复 → 蒸馏 **Ideal Response Principles** → 为每个 case 制定 **case-specific rubric**。

**Prompting 方法**：Principle-Guided CART Prompting，按原则组织推荐结构。

**评测**：7 个商业 API 旗舰模型（含 GPT-6.1-Sol、Claude-Opus-5）+ 35B+ 开源模型，rubric 冻结后做首次全量评测。

## 实验结果
- **Core 档**：10 个模型中 **3 个超过 90%**
- **Excellence 档**：**无一超过 45%**
- → 作者据此提出 **understanding-to-execution gap**（理解到执行的落差）
- 失败诊断集中在**商品证据缺失**与**未解决的需求**（随需求变化与决策过程而变）

## 局限性
- Excellence 档的 rubric 依赖人工从成功订单蒸馏，规模与代表性受限；
- 购物助手的结论对零售领域与商品目录结构敏感，跨域迁移未验证；
- 评测采用 rubric 评分而非端到端转化率，与商业指标的关联性未验证。

## 值得注意的点
「Core 90%+ vs Excellence <45%」这个对比是今日最有说服力的**能力剖面**之一：模型能识别『该做什么』但做不到『做好』。这类双档 rubric 设计比单一总分更能暴露真实短板 —— 呼应本批次多篇关于「聚合分数掩盖构造层问题」的教训。
