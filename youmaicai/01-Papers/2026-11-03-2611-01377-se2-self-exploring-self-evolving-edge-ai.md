## 核心贡献
1. **SE2 范式**：面向**自适应边缘 AI 开发**的**自探索（self-exploring）+ 自演化（self-evolving）**框架，核心思想是**不让 LLM 只做代码生成器**，而是**完全发挥其推理能力，让智能体在运行时自主决定自己的工作流**。
2. **四原子操作抽象**：受人类学习过程启发，把开发过程蒸馏为 **retrieve（检索）、reason（推理）、code（编码）、test（测试）** 四个原子操作。
3. **动态自适应算子选择**：智能体基于**当前上下文**动态地、自适应地选择下一个要执行的操作，从而**自主探索工作流**，而非遵循预先编排的固定流程。
4. **量化收益**：合成程序准确率**最高提升 26%**，资源消耗**降低 28%**，同时对**未预见的边缘 AI 场景**保持更优的适应性。

## 问题背景
LLM 展现出强大的代码生成能力，催生了自动化边缘 AI 应用开发的智能体系统。然而现有智能体通常依赖**固定的 agentic workflow** 与**预定义的设计空间（design space）**，难以应对真实场景中快速演变的需求——例如异构数据模态、多样化任务流水线等。当需求超出预设工作流的覆盖面时，固定流程会直接失效。而此前把 LLM 主要当作"遵循刚性流程的代码生成器"的做法，也没有发挥其推理能力去**动态规划流程**。

## 方法

### 四原子操作（蒸馏自人类学习过程）
| 操作 | 语义 |
|------|------|
| **retrieve** | 检索——获取必要信息、样例数据、参考实现 |
| **reason** | 推理——分析问题、选择方案、做出决策 |
| **code** | 编码——生成实现代码 |
| **test** | 测试——执行验证、评估结果、反馈 |

### 自探索工作流
- 智能体**不执行固定脚本**，而是在每个步骤根据**当前上下文**（已产生的代码、测试结果、检索到的信息、需求细节）**动态选择下一个原子操作**。
- 因此**工作流本身是被探索出来的**，而非被编排出来的——这是 SE2 中"self-exploring"的含义。
- **自演化**：智能体可基于执行反馈调整其后续操作与实现，闭环自我改进（self-evolving）。

### 设计动机
- 人类的学习/开发过程本质上是"按需选择行为"（何时查资料、何时思考、何时动手、何时验证），而非流水线。
- 把这一结构蒸馏为原子操作 + 上下文驱动的算子选择，使得工作流能**适配异构数据模态与多样任务流水线**，并对**训练/设计中未预见的需求**具备适应性。

## 实验结果

| 指标 | 结果 |
|------|------|
| 合成程序准确率 | 相比 SOTA 基线**最高提升 26%** |
| 资源消耗 | **降低 28%** |
| 适应性 | 对**未预见的边缘 AI 场景**保持更优适应性 |

摘要未给出：具体的边缘 AI 任务/数据集名称、基线系统名单与绝对数值，也未给出"资源消耗"的度量口径（时间/能耗/显存/调用次数）。

## 关键洞察
1. **准确率提升与资源下降同时发生**，说明固定工作流不仅是能力上限的约束，也是**算力浪费的来源**——固定流程会执行在当前情境下无必要的步骤。上下文驱动的算子选择同时省了"无用步骤"的钱和"错过必要步骤"的能力。
2. **把开发抽象为四个原子操作是关键的可迁移设计**：足够细以支持任意组合，又足够粗以让 LLM 的推理能可靠地做出选择粒度；这类似于把"思维"分解为可调度原语。
3. **适应性收益来自"工作流空间"而非"模型能力"**：当需求分布漂移（异构模态、新流水线）时，预定义设计空间必然失效，而开放式算子组合能构造出训练时未见过的流程——这是结构性的泛化，不是记忆。
4. **对 LLM 角色的定位转变是本文的方法论贡献**：从"指令跟随的代码生成器"变为"自主规划流程的智能体"，与 [[SE2]] 命名中的 self-evolving 呼应。

## 局限性
- 摘要未给出绝对数值、任务清单与基线细节，仅有相对提升百分比，难以判断在多大任务难度区间上成立。
- "资源消耗降低 28%"的口径未定义；准确率与资源的 trade-off 是否可通过调参进一步改善未知。
- 四原子操作抽象是否足够表达所有边缘 AI 开发活动（如数据标注、部署、监控、模型压缩）未讨论；摘要仅聚焦代码生成-测试闭环。
- 自探索/自演化的过程会带来**不可预测的调用成本与失败模式**，摘要未涉及成本上界、循环终止与沙箱安全性。
- 对"未预见场景"的自适应能力主要来自流程组合，未验证是否会引入低效甚至错误的操作序列（摘要只报告准确率提升）。
- 依赖 LLM 自身判断下一步操作，需要长上下文与可靠的指令遵循能力，摘要未说明模型规模与提示设计。

## 适用场景
- 边缘 AI 应用（移动端/嵌入式/IoT）的自动化开发流水线搭建。
- 需求多变、数据模态异构、任务流程不固定的 AI 应用原型与落地。
- 需要在准确率与资源占用之间同时优化的部署场景（尤其受功耗/延迟约束的端侧）。
- 受固定 agentic workflow 限制、希望让智能体自主规划步骤的 agent 系统改造。
