## 核心贡献

> 分阶段 pipeline 让 LLM 同时设计算法并用 Lean 证明其效率界——全程不做经验比较，保证纯由数学给出。

1. 提出分阶段 pipeline，让 LLM 同时做**算法设计**与**效率证明**：agent 先提出黑箱优化算法，由 Lean 过滤有缺陷的设计，再定义势函数并证明漂移界以保证期望运行时间优于基线。
2. 整个流程**全程不做经验性比较** —— 这是与 AlphaEvolve 等纯经验式 LLM 启发式设计的根本区别。
3. 在 8 个问题类上，前沿模型 15 次运行中有 12 次走完整条 pipeline；产出的算法在 CycleUncover 上达到期望运行时间 O(n²)，而经典 (1+1) EA 需要 e^{Ω(n)}。

## 技术方案

### 核心思想

已有工作分成两个互不相交的阵营：**AlphaEvolve 一类**用 LLM 设计优化启发式，纯经验、没有正确性保证；**LLM + Lean 一类**能证明给定的定理，但不设计算法。

这篇论文要问的是：能不能同时做到两件事 —— **设计一个算法，并给出它的效率保证**。

pipeline 按研究方法论分阶段组织：agent 提出黑箱优化算法，Lean 作为守门人过滤掉有缺陷的设计；随后 agent 定义势函数（potential function），并证明漂移界（drift bound），从而给出期望运行时间优于基线的保证。

最值得注意的方法论选择是：**流程中任何环节都不做经验性比较**。这意味着输出的不是一个「跑出来分数不错」的启发式，而是一个有数学保证的算法——运行时间界完全来自势函数分析，与实际跑分无关。这与 AlphaEvolve 的工作范式正好相反。

作者 Per Kristian Lehre 是进化算法理论领域的资深研究者，论文的定位因此相当扎实：它不是要证明 LLM 很聪明，而是要检验**LLM 能否承担理论工作的一部分**。

结果给出了具体的量级：在 CycleUncover 问题上生成的算法期望运行时间 O(n²)，而经典 (1+1) EA 需要 e^{Ω(n)} —— 这是一个质的差距。整数子模最小化上得到 O(n^{2+2c})，LeadingOnes 上则与经典的 O(n²) 持平。

### 关键技术

| 技术 | 说明 |
|------|------|
| 分阶段 pipeline | 提议 → Lean 过滤 → 势函数定义 → 漂移界证明，与演化算法的设计与分析研究方法论同构 |
| Lean 形式化验证 | 作为守门人自动剔除有缺陷的算法设计，保证进入证明阶段的候选在数学上可分析 |
| 势函数与漂移界 | 通过势函数的期望下降量给出期望运行时间的严格上界 |
| 全程无经验比较 | 不依赖任何跑分，算法保证纯由数学证明给出 |
| 多问题类评测 | 覆盖 8 个问题类，包括 CycleUncover、整数子模最小化、LeadingOnes 等 |

## 实验结论

- **数据集**: 8 类黑箱优化问题（含 CycleUncover、整数子模最小化、LeadingOnes）
- **基线**: 经典 (1+1) EA 与各问题类的已知最优理论界
- **结果**: 15 次运行中 12 次完整走通 pipeline。CycleUncover 上期望运行时间 O(n²)（经典 (1+1) EA 为 e^{Ω(n)}）；整数子模最小化 O(n^{2+2c})；LeadingOnes 与经典 O(n²) 持平。

- **最关键的方法论选择**：全程不做经验比较 —— 保证来自数学证明而非跑分，这是与 AlphaEvolve 式设计的根本分野。
- CycleUncover 上 O(n²) vs e^{Ω(n)} 不是渐进改进而是**量级跃迁**，说明 LLM 有能力产出接近手工推导的新分析。
- Lean 作为守门人是流水线设计的关键：它把「LLM 提了个坏想法」这类失败挡在证明阶段之前。
- LeadingOnes 上与经典 O(n²) 持平，说明 agent 能复现已知最优分析，而不只是产生新东西。
- 12/15 完成率说明该任务对当前模型仍具挑战，成功率本身是可用的模型能力探针。

## 实现建议

- **实现难度**: 高（需 Lean 形式化环境、势函数合成与证明自动化流水线）
- **适用场景**: 自动算法设计、形式化验证驱动的程序合成、进化算法理论、Agent-as-Researcher
- **建议**: 这条路线值得关注的不是「LLM 能证明定理」，而是**把 LLM 嵌入有守卫的研究流程**：让 LLM 负责提出候选，让形式化系统负责否决，再用理论工具给出保证。若要复现，必须配 Lean 环境，不能退化为经验搜索。

## 原始摘要

```
LLMs now prove hard theorems in Lean. Can they also design algorithms and prove their correctness and efficiency? LLM-guided design of optimisation heuristics (such as AlphaEvolve) is purely empirical. Automated theorem provers with LLMs prove given statements. So far, there has been little evidence that LLMs can do both: design an algorithm and guarantee its efficiency by a mathematical proof. We present a staged pipeline modelled after research methodology in design and analysis of evolutionary algorithms. The agent proposes black-box optimisation algorithms, and Lean guards filter out flawed designs. The agent then defines a potential function and proves drift bounds that guarantee an expected runtime improvement over the baseline algorithm. At no point in the pipeline are the algorithms compared empirically. The agent generates a black-box optimisation algorithm with expected runtime $O(n^2)$ on a CycleUncover problem, where the classical (1+1) EA needs runtime $e^{Ω(n)}$. The pipeline also designs and analyses a black-box optimisation algorithm for integer-valued submodular minimisation with expected runtime $O(n^{2+2c})$, and it matches the classical runtime $O(n^2)$ on LeadingOnes. Across 8 problem classes, 12 of 15 runs with frontier models complete the pipeline with a machine-checked expected-runtime bound. An ablation study shows that removing the staging and asking the agent to zero-shot an algorithmic design with a runtime guarantee leads to a copy of the seeded baseline algorithm (random search) or to incomplete proofs. Our study suggests that machine-checked specifications in Lean can replace empirical evaluation in open-ended algorithm discovery. To the best of our knowledge, this is the first example of an automated pipeline that designs efficient black-box optimisation algorithms with machine-checked runtime bounds in Lean.
```
