# More Agents, More Reliable? System-Level Reliability of Multi-Agent LLMs under Operational-Profile Uncertainty

> **arXiv**: [2611.07140](https://arxiv.org/abs/2611.07140)
> **发表日期**: 2026-11-04
> **分类**: cs.AI (及交叉分类 cs.MA)
> **会议/期刊**: Submitted for IEEE Software Magazine

## 📋 摘要

团队越来越多地用协作的 LLM agent 来构建软件，常常假定"更多 agent 就更可靠"。然而通常的证据——平均基准准确率——忽略了已部署系统实际面对的输入混合，以及合并各 agent 答案的那条规则。作者在 HIP-LLM（针对单个 LLM 的层级不精确概率评估）基础上，提出一个框架，将它与刻画系统失败逻辑的 Bayesian network 结合起来，用于多 agent 系统的评估。agent 的失败概率区间会沿着这张网络传播（其中合并规则自身也可能失败），最终得到一条 reliability envelope，揭示究竟是哪一条证据限制了可靠性主张。在一个抽取受监管化学品危害声明的 pipeline 中，三个模型的多数投票能抵御最弱的模型，但并未明显超过最好的那个；而如果某个投票者在 **5%** 的请求上失败，其相对中等模型的收益将基本被抹平。结论是：更多 agent 带来的是更站得住脚的可靠性主张，而不自动等于更可靠的系统。

## 🎯 核心贡献

1. **提出多 agent 系统级可靠性评估框架**：将 HIP-LLM（单 LLM 的层级不精确概率评估）与系统失败逻辑的 Bayesian network 结合，把 agent 的失败概率区间沿网络传播，形成 reliability envelope。
2. **显式建模"合并规则本身也会失败"**：把 answer-merging rule（如 majority voting）作为一个可能失效的节点纳入概率模型，这是仅看平均准确率的评测完全缺失的一环。
3. **揭示输入混合（operational profile）的重要性**：可靠性主张必须区分系统实际遇到的输入分布，而不是笼统的 benchmark 平均值。
4. **反直觉实证结论**：多数投票能保护系统免受最弱 agent 拖累，但并不稳定超越最强 agent；投票者只要在 5% 的需求上失败，其相对中间模型的收益就基本消失——"加 agent"更多是提升论证的可辩护性而非实际可靠性。

## 🔧 方法/架构

框架由两层组成：

- **第一层（单 agent）**：HIP-LLM（Hierarchical Imprecise Probability assessment of LLMs）为每个 agent 给出失败概率的**区间**（而非点估计），刻画单模型行为的不确定性。
- **第二层（系统）**：将各 agent 的失败概率区间注入一张 Bayesian network，节点对应各 agent 与"答案合并规则"本身，边表示依赖与失败传播路径。

区间沿网络传播的形式可写为：

$$
P(\text{system failure}) \in \bigl[\underline{p},\ \overline{p}\bigr]
$$

其中区间端点由各节点失败概率区间的上下界经 Bayesian 传播与边缘化组合得到。当合并规则（voting）自身带有失败概率 $p_{\text{combine}}$ 时，它会作为一个额外不确定源进入该区间。

最终得到的 **reliability envelope**（可靠性包络）以图示形式呈现：它同时表达"在给定证据下系统可靠性的可达范围"与"哪一条证据是限制瓶颈"，从而避免给出过于自信的点估计。

实证设置：在抽取 regulated chemical-hazard statements 的 pipeline 中，比较单模型、多模型 majority voting，并注入投票者失效（如 5% 需求上的失败）来考察敏感性。

## 📊 实验结果

- **Chemical-hazard extraction pipeline**：三模型多数投票可抵御最弱模型，但**未明显超过最强模型**。
- **投票者失效敏感性**：投票者在 **5%** 需求上失败时，其相对中间模型的性能优势被基本抹平（"largely erase its advantage over the middle model"）。

## ⚠️ 局限性

- 实证仅在一个特定 pipeline（受监管化学品危害声明抽取）上完成，任务域窄，结论的普适性待验证。
- HIP-LLM 与 Bayesian network 的区间宽度本身依赖基础假设（不精确概率模型的可信度），误差可能沿网络累积。
- 主要刻画的是**统计性/可重复性**可靠性，未涵盖安全鲁棒性、越权调用等系统级失效模式。
- 尚未被同行评审，结论属于初步证据。

## 💡 建议

- 是否推荐使用：是（作为**评估方法论**推荐；作为"多 agent 必然更可靠"的证据则不推荐）
- 适用场景：需要为多 agent LLM 系统做可靠性论证与合规交付的场景；架构评审中用来检查"加 agent"决策的真实收益；构建 agent 系统的风险评估报告时提供可辩护的可靠性区间表述。
