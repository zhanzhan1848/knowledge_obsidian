## 核心贡献

> SPARTA 把三值 SpMM/SpMV 与 bit-serial QK/PV 统一到同一条 conditional-accumulation 数据通路上，在 28nm 下实现 13.9 mm²、1.40 W、9,752 GOPS/W 的设计，相对 NVIDIA Jetson AGX Orin 提升 **3.9× 生成吞吐与 8.3× 端到端能效**（相对 AMD Ryzen 7 9700X 为 5.0× 与 81.7×），比 FIGLUT / TeLLMe / MCBP 提升 1.6–12.0× 吞吐、2.0–4.2× 能效、1.3–51.4× 面积效率。

1. **Phase-aware 稀疏数据流** — 识别并联合利用三类**异质稀疏性**：三值权重的零权重稀疏、attention 的 bit-level 稀疏、以及 query-dependent 的 KV 访问稀疏。跨 compute-bound 的 prefill 与 memory-bound 的 decode 协同调度，而非像既有加速器那样只优化其中一半。
2. **统一计算 fabric（datapath unification）** — 把 ternary SpMM/SpMV 与 bit-serial QK/PV 统一为同一个 outer-product conditional-accumulation 原语，同一组 PE 承载 prefill SpMM、decode SpMV、三值线性层与稀疏 attention。相对 TENET/TeLLMe 实现 **最高 2.2× 面积效率与 1.5× 能效**；把 MCBP 的 binary pattern 改成 ternary 的正/负两趟虽降面积但增加周期，面积与估算能效仅为 SPARTA 的 **7.3% 与 6.8%**。
3. **两阶段自适应注意力引擎** — page-level Top-k（利用每 feature 的 signed INT4 min/max 元数据筛掉 K 页）+ token-level Top-p（用 streaming histogram 做概率质量剪枝以减少 V 流量）。相对 full attention 降低 KV 流量 **4.1–4.8×**，相对 SOTA 稀疏注意力方案（Twilight）再降 **1.3–1.5×**，代价是任务相关的质量损失。
4. **首个支持 8K 以上序列长度的加速器** — 作者称据其所知是首个高效支持超过 8K sequence length 的 LLM 加速器，覆盖 1.7B–8B 规模的六个三值模型。
5. **相对商品平台的端到端实测优势** — 对 Jetson AGX Orin（50W 配置）几何平均吞吐 **3.9×**、能效 **8.3×**；Jetson 改用 INT4 KV cache 后优势升至 **4.8× 与 9.1×**（因为 llama.cpp 会在 attention 前反量化 cache）。对 Ryzen 7 9700X 为 **5.0× 与 81.7×**。
6. **消融揭示各机制的分工** — 零权重跳过、page Top-k 选择器、histogram Top-p 引擎三步在几何平均上分别把端到端延迟降低 **22%、9%、5%**，累计 **1.48×** 加速；零权重跳过主要缩短 prefill（**TTFT −29%**），Top-k 与 Top-p 只作用于 decode（**TPOT 分别 −26% 与 −16%**）。

## 技术方案

### 核心思想

论文的出发点是一个**瓶颈迁移**的观察：1.58-bit 三值量化（权重取 $\{-1,0,+1\}$）已把权重存储压到 8-bit 模型的五分之一，同时保留 **88–97%** 的全精度智能，几乎消除了权重存储作为主要瓶颈的问题。但当上下文增长到数万 token，KV cache 随序列长度线性增长，**成为每 token 内存流量的主导**。于是"压缩权重"这件事反而把 KV 流量推上了瓶颈位。

论文进一步指出既有加速器在三个层面上的不足：

1. **跨推理阶段的异质稀疏未被联合利用**。三值 LLM 有多种稀疏：静态零权重稀疏、attention 计算中的 bit-level 稀疏、以及动态 attention 稀疏。prefill 由 compute-bound 的 SpMM 主导（高权重复用），decode 由 memory-bound 的 SpMV 主导并反复流式访问权重与增长中的 KV cache。既有工作要么只优化三值线性计算（TENET、TeLLMe、BitNet.cpp），要么只优化稀疏 attention（PADE），**从未联合**。
2. **数据通路未统一**。线性层用三值权重，attention 却需要多比特计算以保精度。既有设计普遍采用 LUT-based 三值矩阵乘引擎——而 LUT PE 是为**稠密**三值计算优化的，无法高效同时支持稀疏 SpMM 与 SpMV，因而浪费了大量零权重稀疏，且常需为线性层与 attention 各配一条独立通路。
3. **稀疏 attention 方案不适合长上下文**。fixed-pattern（sinks + local window）无法捕捉 input-dependent 稀疏；fixed Top-k 施加刚性 token 预算——预算小则丢弃重要 token，预算大则引入冗余 KV 访问。论文实测（图 3b，BitCPM-3B，32K）：**覆盖 90% attention mass 所需的 token 数在各 head 间相差三个数量级**，任何固定预算都不可能同时适配。

SPARTA 的解法是把这三件事揉进一个统一设计：**一套共享的 PE fabric 同时执行三值线性与稀疏 attention，配合跨阶段的数据流调度，再叠加一个两级自适应选择引擎把 query 依赖的稀疏真正转成更少的 K/V 访问**。

### 统一计算 fabric

核心洞察是把两个看似不同的算子化为同一个原语。ternary SpMM/SpMV 是稀疏权重乘稠密激活；bit-serial QK/PV 是把 Q/P 的 bit plane 展开后对 K/V 向量做移位选择累加。两者都可以表达为**outer-product conditional-accumulation**：在某个 bit 位置或某个权重位置为 1 时，把对应的 K/V 向量（或激活行）以移位后的形式累加进 bank-local 累加器。

关键工程性质：

- **零跳过**：零权重与零 bit 直接跳过，不产生任何有效计算。
- **无需 LUT 或 pattern 重构**：与 TENET/TeLLMe 的 LUT 路线不同，SPARTA 直接用移位加法，不需要重建 bit pattern。
- **bank-local accumulation + conflict FIFO**：处理不规则访问的冲突；FIFO 深度扫参显示深度 8 即可达到深度 32 吞吐的 **96.7%**，而条目数只有四分之一。
- **整数操作数**：与 BitMoD 的 bit-serial exponent alignment 路线不同，SPARTA 保持整数操作数，更新只需移位和加法。

统一 fabric 的代价是**它在 8 个 compute slice 上被复制**，因而占 **47.6% 面积与 39.6% 功耗**——但换来的是同一套硬件在 prefill SpMM、decode SpMV、三值线性层、稀疏 attention 四种负载间可动态复用。

### 两阶段自适应注意力

**Stage 1 — page-level Top-k（减少 K-cache 访问）**：每个完成的 K page 记录每 feature 的 signed INT4 min/max 作为紧凑元数据。decode 时对 query 与该元数据做比较，筛出最相关的 top-$\rho_k$ 比例的页。Quest 采用的是 page-level Top-k 的软件版本，SPARTA 是其硬件化。$\rho_k$ 被实验证实是**主要的质量旋钮**：减小页预算一般会提高 perplexity。

**Stage 2 — token-level Top-p（减少 V 流量）**：在 Stage 1 选出的候选页内，计算精确的 QK 分数，再用 **streaming histogram** 估计 Top-p 阈值（保留累计概率质量 $\ge p$ 的最小 token 集合），剪掉其余 token 的 V 访问。$p$ 提供比 $\rho_k$ 更细的调节粒度。

两阶段是**互补**的：Top-k 降 K 流量，Top-p 进一步降 V 流量与 PV 计算。消融显示保留的候选比例 $\rho_p$ 只有 **2.9–10.9%**，且随上下文从 8K 增长到 32K 而下降。

工程实现上，作者用一个 **bitonic Top-k selector**（排序窗口 64 项）与一个 **streaming-histogram Top-p engine**（64 bins）落地这一数据流。选择用 histogram 而非 Twilight 的 binary-search 阈值：在同一 fabric 上替换后注意力慢 **2.0–3.0×**、TPOT 慢 **1.1–1.8×**。

### Prefill / Decode 数据流

**Prefill**：prompt 被切成固定大小 chunk 以约束片上工作集。Transformer 每层内，bitmap 压缩的三值权重在 chunk 内所有 token 间复用（QKV projection、output projection、FFN）。生成的 K/V 量化为 INT4 追加进 paged cache，每个完成的 K page 记录 per-feature min/max 元数据。Prefill attention 用 **online Softmax** 扫描已缓存的 K/V chunk，只有 running max、normalizer 与输出累加器 $(m,\ell,\mathbf{O})$ 跨 chunk 保留，从而约束片上 attention 状态同时产生**精确结果**。

**Decode**：每个生成 token 触发一次阶段重叠的选择与执行——Top-k 选择完全覆盖 K 访问（除 Bonsai 在 8K 时），Top-p 选择在所有情况下覆盖 V 访问。

```
三值 LLM 推理
 ├─ Prefill (compute-bound)
 │   ├─ chunk 化 prompt
 │   ├─ bitmap 压缩三值权重 × token 复用 (QKV / O proj / FFN)
 │   ├─ K/V → INT4 → paged cache; 每 K page 记 per-feature min/max
 │   └─ online Softmax 扫描 chunk (m, ℓ, O 跨 chunk 保留) → 精确结果
 └─ Decode (memory-bound)
     ├─ Stage 1: page-level Top-k (min/max 元数据筛页) → 降 K 流量
     ├─ Stage 2: token-level Top-p (histogram 阈值) → 降 V 流量 + PV 计算
     └─ 与统一 fabric 时分复用：Top-k 覆盖 K 生成, Top-p 覆盖 V 生成
```

### 关键技术

| 技术/方法 | 说明 |
|------|------|
| Phase-aware 稀疏数据流 | 跨 prefill/decode 联合利用零权重稀疏、bit-level 稀疏、query-dependent KV 稀疏 |
| 统一 conditional-accumulation 原语 | ternary SpMM/SpMV 与 bit-serial QK/PV 映射到同一 PE fabric，无 LUT、无 pattern 重构 |
| 三值权重（1.58-bit） | $\{-1,0,+1\}$ 权重，保留 88–97% 全精度智能，MAC 退化为加/减/跳过 |
| Bitmap 压缩权重 + 零跳过 | 相对 FIGLUT 的主要增益来源；主要缩短 compute-bound prefill（TTFT −29%） |
| Bank-local accumulation + conflict FIFO | 处理不规则 bank 冲突；FIFO 深度 8 达深度 32 的 96.7% 吞吐 |
| Page-level Top-k（硬件） | 用 per-feature signed INT4 min/max 元数据筛 K 页；$\rho_k=1/4$ 为默认 |
| Token-level Top-p（硬件） | streaming histogram（64 bins）估计概率质量阈值，剪枝 V 访问；$p=0.90$ 为默认 |
| Bitonic Top-k selector | 排序窗口 64 项；相比 16 项基线在 8K/16K/32K 分别降低 TPOT 8.8%/13.9%/18.5% |
| Online Softmax | Prefill 跨 chunk 保持 $(m,\ell,\mathbf{O})$，产生精确结果且约束片上状态 |
| Paged KV cache | K/V 存 INT4；BitCPM 用 per-token K/V scale，Bonsai 走 KIVI（per-channel K + per-token V） |
| Trace-driven cycle-level simulator | 用 Ramulator2 回放同一地址轨迹验证 HBM2 带宽；HBM2 访问能耗 4 pJ/bit |
| 28-nm ASIC 流程 | SystemVerilog 实现 + Synopsys Design Compiler 综合；SRAM 面积/能耗用 CACTI 估算 |

## 实验结果

### KV 流量与操作数削减（BitCPM-3B，8K context）

| 方案 | KV 流量削减 | 相对 full attention |
|------|------|------|
| SPARTA（Top-k + Top-p） | **4.1×** | 操作数 **5.9×** |
| Quest（仅 page Top-k） | 3.2× | — |
| MCBP | 更小（计入 predictor 开销后） | — |
| Twilight | 每 head 多读 **2.1×** KV bytes（8K）；带 INT4 辅助 cache 时 1.02× | — |

Top-p 引擎本身只占剩余操作数的 **4.2%**。

### 端到端吞吐与能效（几何平均）

| 对比对象 | 生成吞吐 | 端到端能效 |
|------|------|------|
| NVIDIA Jetson AGX Orin（dense attention，FP16 KV） | **3.9×** | **8.3×** |
| Jetson + INT4 KV cache | **4.8×** | **9.1×** |
| AMD Ryzen 7 9700X | **5.0×** | **81.7×** |

Jetson 改用 INT4 KV 反而在长上下文变慢，因为 llama.cpp 在 attention 前会反量化 cache——这抬高了 SPARTA 的相对优势。

### 相对 SOTA 加速器

| 阶段 | 对比 | 吞吐提升 | 能效提升 |
|------|------|------|------|
| Prefill | FIGLUT | 1.6× | 2.0–4.2×（对全部四个设计） |
| Prefill | TeLLMe | 2.3× | — |
| Prefill | MCBP | **8.8×** | — |
| Decode | FIGLUT | 2.5× | 2.6× |
| Decode | TeLLMe | 3.7× | 3.3× |

### 延迟分解与消融

- **Prefill 瓶颈转移**：linear 层占比从 2K 时的约 **82%** 降到 32K 时的 **28%**（dense attention 二次增长）。
- **Decode**：attention 占 TPOT 的比例在 32K 达到 **31–63%**；两级稀疏 attention 相对 dense attention 快 **4.0–6.2×**。
- **累积消融**（几何平均）：零权重跳过 **−22%**、page Top-k 选择器 **−9%**、histogram Top-p 引擎 **−5%**，累计 **1.48×** 加速。零权重跳过主要作用于 prefill（**TTFT −29%**）；Top-k 与 Top-p 只作用于 decode（**TPOT −26% 与 −16%**）。

### 质量与参数敏感性

- **默认工作点** $\rho_k = 1/4$、$p = 0.90$：六个模型中四个与稠密基线的差距在 **1.3%** 以内，其余模型中最差退化 **4.0%**。
- **感知质量退化**：最终配置与 full attention 的 PPL 差距最多 **0.61**；histogram 引擎相对 exact Top-p 只改变最多 **0.10** PPL。保留候选比例 $\rho_p$ 仅 **2.9–10.9%**，且随长度从 8K 到 32K 下降。
- **HBM 传输粒度**：实测传输字节仅比解析值高 **1.4–1.7%**。Top-k 在所有长度把读取降低 3.2×，Top-p 进一步提升到 BitCPM-3B 的 **4.3–4.4×** 与 Bonsai-4B 的 **4.9×**。由于只有 20–27%（BitCPM）与 37–47%（Bonsai）的被选页被完全剪掉，若按整页取 V 则只能拿到 3.5–3.6× 与 3.8–4.0×——这正是需要 token-granular V gather 的硬件动机。
- **设计空间**：FIFO 深度 8、16 PEs × 32 lanes、Top-k 窗口 64 项、Top-p histogram 64 bins 为选定配置；histogram 64 bins 相对 16 bins 降低 TPOT **6.1%**（p=0.90）与 **7.7%**（p=0.95），128 bins 再加不到 1 个百分点却把 histogram SRAM 从 1 KiB 翻到 2 KiB。
- **面积/功耗分解**：共享 fabric 占 47.6% 面积与 39.6% 功耗（因在 8 个 slice 上复制）；Top-k 与 Top-p 引擎合计仅占 **14.3% 面积与 16.6% 功耗**，说明两级选择的硬件代价很低。

## 局限性

- **质量损失是任务相关的，且不可忽略**：长文档摘要（GovReport、MultiNews）与检索式任务退化最明显——根源是"一个 page set 必须服务一个 KV group 的所有 heads"，只需少数 heads 的 page 可能落在预算外，而 **Top-p 无法救回被 Top-k 排除的页**。这是两级方案的固有局限。
- **短上下文不适配**：page-level Top-k 在页数少的短上下文上要么剪一半页造成大幅质量损失，要么保留太多页而省不下流量，因此短上下文任务必须**禁用 Top-k**（只保留 Top-p），削弱了统一性。
- **固定页预算是刚性上限**：即便 Top-p 是自适应的，被 Top-k 排除的页无法恢复，固定预算在高度扩散的 attention 分布下仍会丢重要 token。
- **全部为仿真而非流片验证**：硬件用 Synopsys DC 在 28nm 商业库上综合，面积为 **13.9 mm²**、功耗 **1.40 W** 为估算/综合结果；性能来自 trace-driven cycle-level simulator，HBM2 带宽通过 Ramulator2 回放同一地址轨迹校准，**未经真实芯片实测**。
- **能耗口径不完全可比**：SPARTA 的能耗含 HBM，CPU 是 RAPL package 功耗、Jetson 是模块供电轨测量，三者口径不同；与 ASIC 基线比较时 Table V 只列片上功耗。
- **加速器基线部分为作者复现**：FIGLUT、TeLLMe、TENET、MCBP 的 linear PE 由作者用自家 28nm 流程 RTL 复现并缩放到其公布宽度；MCBP 用正/负两趟映射 ternary 权重（作者称比直接映射更省面积省能，但也增加周期）。
- **速度提升的口径混合**：对 CPU/GPU 的 3.9×–81.7× 增益同时包含架构收益与稀疏 attention 收益（两个基线都用 dense attention），论文自己承认这一点。
- **模型规模有限**：仅覆盖 1.7B–8B 的三值模型；更长上下文（>32K）与更大模型未验证。

## 与知识库既有工作的关系

- 与知识库中 LLM 推理效率类工作（如 [[2026-03-11-ConFu-Speculative-Sampling]]、[[2026-03-13-SDSL-Speculative-Decoding-Scaling-Laws]]）同属"降低推理成本"主线，但本文走的是**硬件加速器**路线而非算法/采样路线。
- 延续"瓶颈会随技术演进迁移"的观察：在权重已被 1.58-bit 三值化压下去之后，**KV cache 成为新瓶颈**——这个"旧瓶颈被解决后新瓶颈浮现"的论证结构，与知识库中关于效率技术演进的讨论一致。
- 与 [[2026-03-13-MoE-Routing-Signatures]] 等"结构化稀疏"工作形成跨层呼应：本文是把稀疏性显式下沉到数据通路与调度层（零权重跳过、bit 稀疏、KV 稀疏的联合利用），可视为把模型侧稀疏假设兑现为硬件契约的范例。

## 建议

- **是否推荐使用**：有条件（作为硬件设计参考与方法论参考推荐；作为可采购方案不推荐——全部为仿真）
- **适用场景**：适合研究三值/低比特 LLM 的边缘部署、KV-cache 流量建模与稀疏 attention 硬件化；也适合作为"如何在同一 PE fabric 上统一异质算子"的设计范例；不适合作为长上下文质量保证方案（有明确的任务相关退化）。
- **可借鉴要点**：
  1. **两阶段稀疏选择的粒度阶梯值得直接借鉴到软件实现**：page-level Top-k（粗筛、降 K 流量）+ token-level Top-p（细剪、降 V 流量）的组合比单一 Top-k 更能在保持质量的同时降流量（4.1× vs 3.2×），且两阶段互补；软件侧同样可用"先按页/块粗筛、再按 token 精剪"的思路。
  2. **统一 PE / 统一算子原语是硬件与推理引擎共同的启示**：把看似不同的算子映射到同一个 conditional-accumulation 原语，可以像 SPARTA 那样让同一套硬件在 prefill SpMM、decode SpMV 与稀疏 attention 间时分复用；在软件侧这对应于统一 kernel 抽象以避免多路径带来的面积与能耗开销（FIGLUT/TeLLMe 的独立 attention 引擎占其 prefill 能量 73–76%，正是反面例证）。
  3. **消融报告应按阶段归因**：本文把每个机制拆到"作用于 prefill 还是 decode"（零权重跳过 → TTFT −29%；Top-k/Top-p → TPOT −26%/−16%），这种归因方式让"选哪个优化"变成可决策的问题，值得在自研推理优化时模仿。
