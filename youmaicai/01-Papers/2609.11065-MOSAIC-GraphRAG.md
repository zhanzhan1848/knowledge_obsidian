## 核心贡献
1. **问题**：GraphRAG 大多对所有查询使用共享探索程序，但直接事实需要紧凑局部邻域、比较需要多目标平衡覆盖、调解问题需要通过弱连接深入
2. **Mosaic 框架**：将 GraphRAG retrieval 制定为 per-query control problem
   - LLM analyzer 将查询特定的证据需求转换为关于 seed selection、graph traversal、stopping、evidence selection 的有界策略
   - 语料图、索引、评分函数、grounding 程序和答案生成器保持共享
3. **无需训练**：training-free framework

## 实验结果
- **GraphRAG-Bench**：
  - Medical: Answer Correctness 76.97（+5.13 vs 之前最强）
  - Novel: Answer Correctness 64.33（+4.43 vs 之前最强）
  - Medical: 95.1 Evidence Recall, 86.1 Context Relevancy
- 固定策略无法始终最优；Mosaic 比最强固定策略高 9.96 分
- 相比 Fixed Wide，评估路径减少 81.9%，保留证据减少 47.2%
- **迁移实验**：HotpotQA, MuSiQue, 2WikiMultiHopQA 无需 benchmark 特异性 retriever 训练

## 局限性
- 对极复杂查询的 policy 生成可能不稳定
- LLM analyzer 本身可能引入误差
