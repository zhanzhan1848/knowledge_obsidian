# Beyond Instruction Override: Benchmarking Indirect Prompt Injection with Task-Tampering Attacks

> **arXiv**: [2611.07640](https://arxiv.org/abs/2611.07640)
> **发表日期**: 2026-11-05
> **分类**: cs.CR (及交叉分类 cs.AI)
> **会议/期刊**: arXiv preprint

## 📋 摘要

间接提示注入（IPI）基准主要测试植入的指令是否把工具型 agent 重定向到攻击者选定的任务。然而攻击者控制的内容也可以**篡改正在进行的任务的结果**——买家的争议证据可以引用一条虚假的退款政策来抬高退款额，而完全不改变任务本身。作者按**权威（authority）而非指令式措辞**来定义 IPI：植入内容只要试图影响其来源无权决定的决策，即构成攻击。本文提出一个明确该边界的基准：在 90 个跨三种工具使用环境的验证案例中，用户请求明确指定了"解决目标决策的权威来源"；每个攻击都篡改良性任务所必需的某个决策，而非替换该任务。每个案例都包含具有相同有害结果的攻击，覆盖 agent 决策过程的至多六个部分：**目标（objective）、决策规则（decision rules）、可用动作（available actions）、预期后果（expected consequences）、对观测的解读（reading of observations）、以及对当前状态的信念（beliefs about the current state）**。无防御时，在五个 LLM 上，对另外五个目标中的三个（决策规则、可用动作、状态）的平均成功率**高于目标型攻击**。检测并移除的防御把目标型攻击降至 **2.4%** 成功率，但观测型与状态型仍分别停在 **9.5%** 与 **12.1%**，且在"针对检测优化"的重写下该差距依然存在。工具策略防御仍允许 **15.4%** 攻击成功率，与无防御的 **17.0%** 接近，因为这些攻击通常保留预期工具，只是操纵执行过程中取得的数值。

## 🎯 核心贡献

1. **以"权威边界"重新定义 IPI**：不再依赖"看起来像不像指令"的表层措辞，而以"植入内容的来源是否有权决定该决策"作为判据——这是本文最核心的概念贡献。
2. **任务篡改（task-tampering）攻击范式**：攻击不替换任务，而是篡改良性任务执行路径上的决策，从而绕开以"指令覆盖"为中心的防御假设。
3. **六类决策目标分解**：objective / decision rules / available actions / expected consequences / reading of observations / beliefs about current state——把"agent 决策"拆成可独立攻击的层面。
4. **评测方法论警示**：只测"重定向任务"或"只针对 objective"的评测会**高估防御的覆盖度**；并给出检测移除、工具策略两类防御的真实覆盖率缺口。
5. **可复现基准**：90 个验证案例、3 个工具环境、5 个 LLM，代码与数据开源（amazon-science/task-tampering-prompt-injection）。

## 🔧 方法/架构

- **攻击定义（按权威）**：植入内容影响一个"其来源未被授权决定"的决策 → 即为 IPI 攻击。
- **案例构造约束**：
  - 用户请求中**显式指定**解决目标决策的权威来源（source of authority）；
  - 每个攻击都**篡改良性任务所必需的决策**，而不是替换任务本身；
  - 每个案例包含多种攻击，**有害结果相同**，但攻击的决策目标不同（最多 6 类）。
- **攻击目标分类**：
  1. `objective`（目标）
  2. `decision rules`（决策规则）
  3. `available actions`（可用动作）
  4. `expected consequences`（预期后果）
  5. `reading of observations`（观测解读）
  6. `state beliefs`（当前状态信念）
- **防御评估**：
  - `detection-and-removal`：检测并移除注入内容；
  - `tool-policy`：限制可用工具；
  - 额外测试**针对检测优化（detection-optimized）的重写攻击**，检验差距是否可被消除。

## 📊 实验结果

- **基准规模**：**90 个验证案例**，跨 **3 个工具使用环境**，**5 个 LLM**。
- **攻击目标成功率排序（无防御）**：在另外五个目标中的三个——**决策规则（decision rules）、可用动作（available actions）、状态（state）**——平均成功率**高于目标（objective）型攻击**。
- **Detection-and-removal 防御**：
  - objective 型攻击 → **2.4%** 成功率；
  - observation 型 → **9.5%**；
  - state 型 → **12.1%**；
  - 该差距在 detection-optimized 重写下**依然存在**。
- **Tool-policy 防御**：仍允许 **15.4%** 攻击成功率（无防御为 **17.0%**），几乎无改善——原因是这些攻击**通常保留预期工具**，只操纵执行过程中取得的数值。
- **结论性警告**：仅测重定向任务 / 仅测 objective 的评测会**高估**上述防御的覆盖度。

## ⚠️ 局限性

- **仅 90 个案例、3 个环境**，相对于主流 IPI 基准偏小；攻击语义与领域（示例中的买家争议/退款场景）的覆盖度有限。
- 结论依赖于"用户请求显式指定权威来源"这一构造约束；现实 agent 中权威边界常常是隐含的、模糊的，benchmark 的清晰性可能高估了真实场景的可判定性。
- 5 个 LLM 的覆盖范围有限，未包含最强闭源模型；跨模型成功率方差未在摘要中量化。
- `state` / `observation` 类攻击的检测困难，本质上需要 agent 具备跨步骤的一致性推理，而当前防御只做"文本层面检测"，论文未探索更强的语义级防御。
- 成功率指标依赖"有害结果是否达成"的判定器，判定器本身可能存在漏判（尤其数值操纵类攻击）。
- 攻击由研究者构造，可能与真实攻击者的策略空间不匹配。

## 💡 建议

- 是否推荐使用：**推荐**（尤其推荐其评测设计，而非其攻击本身）
- 适用场景：构建 tool-using agent 的红队/安全评测流水线时，应把"任务篡改"作为独立攻击族纳入测试矩阵，并按六类决策目标拆分指标；评估现有防御时必须报告**分目标成功率**而非总体平均值，否则会高估防御有效性。工具白名单类防御在本文设定下几乎无效，应不作为主要防线。

## ⚠️ Warning

⚠️ **本文包含可直接用于攻击 agent 的提示注入攻击构造与基准**（90 个案例、含 decision rules / state belief 的具体篡写手法）。内容仅用于**防御性安全评测与红队验证**，且已在开源仓库中明文给出。**不得**用于攻击任何未获授权的系统、不得用于绕过真实产品的安全机制、不得用于生成针对真实用户的欺诈内容。复现时应在隔离的本地环境中进行。
