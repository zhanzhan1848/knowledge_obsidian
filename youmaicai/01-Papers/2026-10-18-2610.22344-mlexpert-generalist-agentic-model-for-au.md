## 核心贡献

> 提出 **MLExpert** —— 一个 **35B MoE agentic model**，通过 Hierarchical Agentic SFT + Windowed Interaction RL (WIRL) 做 autonomous long-horizon ML engineering；在 MLE-Bench Lite 上把 base 模型 medal rate 从 37.9% 拉到 **72.7%**，性能与 Kimi-K3 / GLM-5.3 相当。

1. **Kaggle-MLE Factory** —— 可执行的 MLE 任务构建 + 交互 harness（model-directed experimentation）。
2. **Hierarchical Agentic SFT** —— outcome-guided supervision 把通用 tool-use + coding 转 MLE。
3. **Windowed Interaction RL (WIRL)** —— 把 successive experiment results 之间的 multi-turn 决策视为 execution window，共享 outcome-based reward；**异步收集 + policy correction** 支持 trajectory 未结束前更新。
4. **跨任务泛化** —— 学到的 optimization 能力迁移到 NatureBench Lite / agent scaffold optimization / algorithm optimization。

---

## 技术方案

### 1. Kaggle-MLE Factory

- 提供**可执行**的 MLE 任务（基于 Kaggle 风格 problem）+ **interaction harness**。
- Harness 支持 **model-directed experimentation** —— 模型自主组织实验、根据 execution feedback 调整优化策略。
- 比 workflow-driven 系统更灵活；比 model-directed 系统更易训练。

### 2. Hierarchical Agentic SFT

- 把通用 tool-use / coding 通过 **outcome-guided supervision** 迁到 MLE。
- "Hierarchical" 含义：
  - **低层** = 单次实验的代码生成 / 调参 / 提交
  - **高层** = 多实验组合的优化策略选择

### 3. Windowed Interaction RL (WIRL)

- **核心难点**：长 MLE run 包含很多 costly experiments；每实验反馈是前序多个决策的混合结果。
- **方案**：
  - 把**两次相邻实验结果之间**的 multi-turn 决策视为一个 **execution window**
  - 给整个 window 一个**共享 outcome-based reward**
  - **异步收集** + **policy correction** → trajectory 未结束也能更新 policy
- vs 单 turn RL：避免 credit assignment 在 long horizon 上发散。
- vs 单 trajectory RL：避免等 trajectory 结束 → 提高 sample efficiency。

### 4. Asynchronous Collection & Policy Correction

- 在 trajectory 仍在执行时即可更新 policy（不阻塞）。
- Correction 机制保证更新前后的策略一致性。

## 实验结果

### MLE-Bench Lite

| 模型 | Medal Rate |
|------|-----------|
| Base | 37.9% |
| **MLExpert (35B MoE)** | **72.7%** |
| Kimi-K3 | ~ comparable |
| GLM-5.3 | ~ comparable |

### 跨任务迁移

- **NatureBench Lite**：显著提升
- **Agent scaffold optimization**：可迁移
- **Algorithm optimization**：可迁移

→ 学到的 optimization 能力是**通用的**，非 MLE-specific。

---

## 局限与展望

- 仅在 MLE-Bench Lite / NatureBench Lite 等 lite benchmark 上评估 → 真实 Kaggle 难度仍需验证。
- 35B MoE 模型大小决定部署成本较高 → 蒸馏潜力未知。
- WIRL 的 reward 共享粒度仍粗（window-level） → 内部 turn 区分度有限。
- 仅训练 long-horizon optimization → 与 short-horizon tool use 的协同未见。

## 实现建议

- **实现难度**: 高（需要完整 MLE harness + 大规模 SFT/RL infra）
- **预期性能**: 与 frontier 35–70B 模型相当
- **适用场景**:
  - 自动化 Kaggle 风格 ML competition
  - AutoML pipeline（data preprocessing / feature eng / model selection）
  - Research assistant 做 autonomous experiment design
- **不适用**: 实时交互 (< 1 s latency)、超大规模 (>100 experiments / 任务) 预算紧张场景

## 一句话总结

MLExpert 把 MLE 这种 long-horizon + costly experiment 的任务，用 **WIRL (window-level outcome RL)** + **hierarchical SFT** 训练出 35B MoE agent，medal rate 翻倍，性能对标前沿大模型。
