## 核心贡献

> 提出 **MemPABench** —— 一个面向 personal agent 记忆的**交互式环境**，用于 **on-policy** 评测 agent 是否学会并遵循"用户希望被如何协助"这类交互偏好。

1. **交互偏好而非事实回忆**：现有记忆基准聚焦事实召回与个性化问答，很少测试 agent 如何**学习并执行**交互偏好
2. **长程交互任务**：要求 agent 决定何时**澄清（clarify）**、何时**确认（confirm）**、何时**自主行动（act autonomously）**
3. **真实感模拟用户数据**：4 个 grounded simulated users，跨工作与个人场景共 **14 项偏好**，反馈覆盖 **99 个 session、4 个月**，每位用户含 **5 次事件驱动的偏好变更**用于测试记忆更新
4. **三维评测**：preference selection（选对偏好）、delivered behavior（实际行为）、对上下文与偏好变更的敏感性
5. **负结果清晰**：4 种记忆系统 × 4 个 LLM backbone 上，现有记忆对偏好选择的提升有限

## 技术方案

### 问题定位

个人智能系统承担越来越多日常任务，但**重复提问、不必要的确认、不想要的主动联系**会把"能干"变成"打扰"。降低这种负担要求 agent 记住"用户希望被如何协助"，而现有基准主要测"事实能不能记住"。

### 环境设计

| 组件 | 说明 |
|------|------|
| Simulated users | 4 个 grounded 模拟用户，跨工作与个人上下文 |
| Preferences | 每个用户 14 项交互偏好 |
| Sessions | 99 个 session，横跨 4 个月 |
| Preference change | 每用户 5 次事件驱动的偏好变更（用于测记忆更新） |
| Task type | 长程任务：clarify / confirm / act autonomously 的决策 |

### 评测维度

| 维度 | 关注点 |
|------|------|
| Preference selection | agent 是否在正确的时机/语境下召回正确偏好 |
| Delivered behavior | 偏好是否真的体现在交付行为中 |
| Context & change sensitivity | 上下文切换与偏好变更后，行为是否随之更新 |

### 对比的记忆系统

| 系统类型 | 代表 | 摘要结论 |
|------|------|------|
| No Memory | 无记忆基线 | 参照基线 |
| Retrieval-based | Mem0、MemOS、simple RAG | **未超过** No Memory |
| File-based | 文件式记忆 | 精度提升，但**在无关语境中过度套用偏好** |

---

## 实验结论

### 主要结果

| 维度 | 结果 |
|------|------|
| 检索式记忆 vs. No Memory | Mem0 / MemOS / simple RAG **均无提升** |
| 文件式记忆 | 精度提升，但偏好**过度应用**（applies preferences beyond relevant contexts） |
| 记忆系统整体 | 对 preference selection 的提升**有限** |
| 规模 | 4 个记忆系统 × 4 个 LLM backbone |

### 分析结论（论文给出的机制性解释）

- 当前记忆系统**难以检索到交互偏好**，也**难以适配偏好的变更**
- 即便正确偏好就在可及范围内，**覆盖 agent 默认交互习惯**本身仍然困难

具体数值（各系统的准确率等）未在摘要中列出，需查正文表格。

---

## 局限性

- 仅有 4 个模拟用户、14 项偏好，样本规模偏小，用户多样性有限（均为 grounded simulated 而非真人）
- 反馈来自模拟生成，虽覆盖 4 个月与 99 个 session，但与真实用户偏好的噪声与模糊性仍有差距
- 4 个 backbone 与 4 类记忆系统的覆盖范围有限，未必涵盖闭源商业 agent 的记忆实现
- 偏好"过度应用"与"检索失败"两类失败是否可用同一指标刻画，摘要未给出区分方案

## 实现建议

- **实现难度**: 中（需要构建多 session 交互环境与偏好状态机，工作量大但工程路径清晰）
- **适用场景**: 评估个人助理类 agent（邮件、日程、家务助手）是否过度打扰用户
- **建议起点**: 先在自有产品上埋点采集真实的"澄清/确认/自主行动"决策日志，复刻 MemPABench 的三维指标（选择、行为、变更敏感性）做小规模基线
- **价值点**: 这是第一份把"记忆"从事实召回推进到"交互负担"的基准，与用户真实痛点（"Why Bother Me Again?"）直接对齐
- **注意**: 结论偏负面——不要指望直接接入 Mem0/RAG 就能解决交互偏好问题，文件式记忆的"过度应用"是另一个坑
