# Beyond Truncation? Entailment-Licensed Elision and the Limits of Semantic Preservation in LLM Decoding

> **arXiv**: [2611.08975](https://arxiv.org/abs/2611.08975)
> **发表日期**: 2026-11-06
> **分类**: cs.CL
> **会议/期刊**: arXiv preprint（8 pages, 3 figures, 2 tables）

## 📋 摘要

指令微调的大语言模型（LLM）回答长度往往超出请求实际所需。本文提出核心问题：能否在解码回路内部放置一个**免训练（training-free）**控制器，在保留内容的前提下去掉这些冗余？评判标准被设定为最简单的可能基线——把模型自己的答案**截断**到同样的长度。首先，一个**熵门控（entropy-gated）logits 处理器**在 MT-Bench 开发集问题上移除了 **25.5%–34.9%** 的 token，在密封测试集上移除 **19.9%–34.2%**，且都在预注册的 BERTScore 非劣效（non-inferiority）边界内；然而作者通过证明与审计确认，它的输出**始终是未修改答案的一个前缀**——也就是说节省完全来自截断。随后对 **23 个免训练机制家族**的调研发现：没有任何一个能在没有 oracle 标签的情况下比截断更好地选择内容。因此作者提出 **ELIDE**（Entailment-Licensed In-Decoding Elision）：在每个句子边界处，只有当一个自然语言推理（NLI）模型判定该跨度被"已展示给读者的文本"蕴含时，才对读者隐藏该跨度，同时**不改变模型自身的生成**。ELIDE 在三个模型家族上优于等长截断；但人工阅读其在 670 个公开 prompt 上产生的 936 次省略后发现，**59% 的省略损害了答案**，且没有任何自动指标能检测出这一点。把许可范围收窄到其所属的 discourse unit 后，在两个新测试集上把有害比例降到约**十分之一**。

## 🎯 核心贡献

1. **提出并证明"熵门控 logits 处理器 = 截断"**：在满足 BERTScore 非劣效的前提下移除 25.5%–34.9%（dev）/ 19.9%–34.2%（test）token，但其输出恒为原答案前缀，揭示其"节省"没有语义选择性。
2. **系统调研 23 个免训练机制家族**：证明在没有 oracle 标签的条件下，没有任何一个能比简单截断更好地选择要保留的内容——这是对"免训练长度控制"这一整类方法的负面结论。
3. **提出 ELIDE**：基于 NLI 蕴含判定的解码内省略，在句子边界处仅当某跨度被已呈现文本蕴含时才向读者隐藏，且**不改动模型的生成过程**。
4. **揭示"语义保持"的度量失效**：ELIDE 优于等长截断（三个模型家族），但人工审计 936 次省略发现 **59% 有害**，且**没有任何自动指标能检出**这些有害省略。
5. **给出改进方案并量化**：把许可范围限定到该跨度的 discourse unit，使有害比例降到约 **1/10**（两个新测试集）。

## 🔧 方法/架构

- **长度控制的目标设定**：把"省 token"的收益，与"相对同长度截断是否保留了更多有用内容"分开评估；基准线是**等长截断**。
- **熵门控 logits 处理器**：在解码时基于 token 熵（或其门控阈值）决定是否输出，从而压短答案。作者证明并经审计确认其输出恒为原答案的前缀（prefix），因此其收益等价于截断。
- **BERTScore 非劣效检验**：使用**预注册**的 non-inferiority margin，检验被压缩答案与原答案在语义相似度上是否显著不劣；dev/test 分别报告，且 test 为密封集（sealed test split）。
- **ELIDE 主方法**：在**句子边界**处启动判断；引入 NLI 模型，对候选跨度做蕴含判定——只有当该跨度被"已展示给读者的文本"蕴含时才予以省略（"entailment-licensed"），即该跨度对读者而言是冗余信息。模型自身的生成不受影响，省略只发生在**呈现层**。
- **人工审计**：在 670 个公开 prompt 上阅读 936 次省略，标注其是否损害答案；并检查是否存在可检出这些问题的自动指标。
- **许可范围收窄（scoped licence）**：把 NLI 许可限定在跨度所属的 discourse unit 内重新评测。

$$
\text{ELIDE: hide span } s \text{ at boundary } b \quad \Longleftrightarrow \quad \text{NLI}(t_{\text{shown}},\, s) = \text{entailed}
$$

（以上为本笔记对该方法核心判定的形式化表述，摘要中未给出具体公式。）

## 📊 实验结果

- **熵门控处理器（MT-Bench dev）**：移除 **25.5%–34.9%** token；**密封测试集**上移除 **19.9%–34.2%**；均在预注册 BERTScore 非劣效边界内。
- **关键审计结论**：该处理器输出**恒为未修改答案的前缀** → 其节省即截断。
- **机制调研**：**23 个**免训练机制家族，无一在无 oracle 标签下优于截断。
- **ELIDE vs 等长截断**：在**三个模型家族**上优于等长截断。
- **人工审计**：670 个公开 prompt、**936 次**省略 → **59%** 损害答案；**无自动指标可检出**。
- **scoped licence**：两个新测试集上，有害省略比例降至约**十分之一**。

## ⚠️ 局限性

- **NLI 模型的蕴含判定本身有噪声**，且"被已展示文本蕴含"在实践中常被过度触发（蕴含偏置），这正是 59% 有害省略的主要来源之一。
- **有损的呈现层设计**：省略会改变读者看到的答案，而模型生成不变——这造成了"模型认为的答案"与"读者读到的答案"之间的系统性错位，对需要引用原文的场景尤其危险。
- **依赖句边界切分**，对无标点或结构松散的长文本效果退化。
- **BERTScore 等自动指标被证明不可靠**：既然自动指标无法检测有害省略，ELIDE 优于截断这一结论本身也只能靠人工验证支撑。
- **省下的 token 未必等于省下的成本**：隐藏输出仍被模型生成，计算成本不会下降（若实现上仍全量生成）。
- **未在多轮/工具调用场景验证**：省略改变了对话历史的一致性，影响未评估。

## 💡 建议

- 是否推荐使用：**有条件推荐**（作为研究工具与"免训练长度控制不可行"的判据；生产部署需谨慎）
- 适用场景：研究"在保持语义的前提下压缩输出"这一问题本身；对语义冗余极高、结构清晰的答案（如清单式回答）尝试安全的长度控制；建立长度控制方法的人工评测基线。
- 落地建议：若采用，必须配套人工/强模型审查，且把 licence 范围收窄到 discourse unit（有害率降至 1/10）；同时不要把 token 节省记作实际算力节省。
