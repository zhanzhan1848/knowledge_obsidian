## 核心贡献

> 受 Kahneman 快慢思考启发的 **双过程记忆框架**：小模型做并行快证据选取 + 大模型做串行慢验证与记忆更新。

1. **Dual-process memory 范式**：System 1（小 LM）从 raw context chunks 中做并行 evidence selection；System 2（大 LM）按文档顺序做 memory verification + update。
2. **三阶段训练管线**：① SFT System 1 选取；② GRPO 训练 System 2 验证/重写；③ 两策略联合优化协调。
3. **大规模效率提升**：相对 RL-MemAgent 在 RULER-HQA / LongBench v2 / 2WikiMultiHopQA 上 **9.74×** 端到端加速，输出 token **-73.91%**。

---

## 技术方案

### 核心思想

把"无限长上下文推理"的 trade-off（性能 vs 效率）显式拆到两个过程的协作上：
- 小模型充当 **System 1**：廉价、并行、对 chunk 做 fast evidence filtering。
- 大模型充当 **System 2**：保留长程 coherence，按序做 memory update verification。
- 二者通过 **document-order memory state** 交换信息，由联合训练保证两者节奏一致。

### 关键技术

| 技术 | 说明 |
|------|------|
| Fast/Slow system 划分 | Kahneman 启发；用小模型做并行 evidence selection |
| GRPO for System 2 | Group Relative Policy Optimization 训练验证 + 记忆重写策略 |
| 三阶段训练 | SFT1 → RL1 → Joint Optimization |
| Recurrent memory state | 与原文顺序耦合的滚动记忆 |
| 端到端异步推理 | 小模型并行 chunk 处理 + 大模型串行验证 |

### 算法骨架

```text
for chunk in document:
    candidates = System1.select(chunk)         # small LM, parallel
    verified   = System2.verify(history, candidates)  # large LM, sequential
    if verified:
        memory.update(candidates, order=document)
answer = System2.readout(memory)
```

## 实验结论

- **数据集**: RULER-HQA, LongBench v2, 2WikiMultiHopQA
- **基线**: RL-MemAgent（单 LLM recurrent memory agent）
- **结果**:
  - 端到端推理 **9.74×** 加速
  - 输出 token **-73.91%**
  - 随 context 增长 trade-off 持续保持

---

## 局限性

- 双过程耦合 → 联合训练稳定性需要仔细设计（小模型错误会污染 System 2 验证信号）。
- System 1 的选取精度受小 LM 容量上限限制。
- 仅在 QA 类长上下文任务评估，对 code / agent 长 horizon 任务的外推性未知。
