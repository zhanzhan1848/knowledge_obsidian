## 核心贡献

1. **Forget-adjacent utility loss** 的概念：标准 unlearning 评估（target suppression + clean retain utility）漏掉 "接近 forget domain 的 benign reasoning" 退化
2. **RA²**：在 latent space 把 forget-token states **吸引到 nearby retain-supported representations**，同时保护高层 retain behavior
3. **方向性洞察**：unlearning 成功不仅在于 forget representations 离开 harmful computation，更在于 **redirect 方向**

## 方法

### Forget-adjacent utility loss

- Standard retain prompt：保 99% utility
- Forget-adjacent prompt（benign，但 topic 接近 forget domain）：可能掉 20-30%

### RA² algorithm

```python
def unlearning_step(forget_data, retain_data):
    # 1. Get forget representations
    forget_repr = model.encode(forget_data)
    # 2. Find nearby retain-supported representations
    nearest_retain = find_nearest_retain(forget_repr)
    # 3. Attract forget → retain (latent space)
    loss_attraction = ||forget_repr - nearest_retain||²
    # 4. Preserve high-layer behavior on retain data
    loss_retain = behavior_preservation(retain_data)
    # 5. Combined loss
    loss = loss_attraction + λ * loss_retain
    return loss
```

### 与传统方法的对比

| 方法 | 思路 |
|------|------|
| Gradient ascent | 让 forget loss 上升 |
| Negative preference optimization | 显式 forget 反例 |
| **RA²** | **方向性吸引到 retain-supported 区域** |

## 实验结果

- WMDP + MUSE benchmarks
- vs strong unlearning baselines
- **Higher forget-adjacent utility** at similar broad-utility levels

## 局限性

- 需要定义 "nearby retain-supported representations"（依赖 embedding space）
- 仅在 2 个 unlearning benchmark 上验证
- λ 超参需要调节
- Latent-space 操作对 model architecture 敏感

## 建议

- **是否推荐使用**：是
- **适用场景**：LLM unlearning / model 编辑 / 数据删除合规（GDPR 等）
- **运营价值**：避免 "删了 A 但伤了 A 附近的所有推理" 的常见 unlearning 副作用
