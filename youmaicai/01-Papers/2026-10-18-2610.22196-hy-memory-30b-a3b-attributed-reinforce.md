## 核心贡献

> 提出 **Hy-Memory-30B-A3B** —— 一个 **compact long-term memory writer**，统一支持 Mem0 / MemOS / Hy-Memory 三套 memory framework。两阶段训练：**Memory On-Policy Distillation**（framework-specific protocols）+ **Memory RL**（dense per-chunk probes + attributed cross-chunk rewards + chunk-level GRPO）。**四个 harness 均第一**（含 held-out EverMemOS），**55.49% macro** vs Claude Opus 5 的 54.62%。

1. **统一 memory writer**：跨 Mem0 / MemOS / Hy-Memory / **held-out EverMemOS** 都 work。
2. **Memory On-Policy Distillation**：framework-specific write protocols 学在 student-generated states 上。
3. **Memory RL 四件套**：
   - Dense per-chunk probes
   - Attributed cross-chunk rewards
   - Over-storage controls
   - **Chunk-level GRPO**
4. **关键设计**：policy-written banks **跨 window 携带** → 训练与部署对齐。
5. **vs general-purpose LLM behind prompts**：serving cost ↓ + unified writer 可迁移。

## 技术方案

### Motivation

- External-memory system 质量取决于 **write-path model**（什么 retain、如何 represent、evidence 如何更新 persistent state）。
- 现有方案：通用 LLM + framework-specific prompt → serving cost 高 + writer 在 framework A 上训练无法直接迁移到 framework B。
- → 想要 unified compact memory writer 跨多 framework work。

### Hy-Memory-30B-A3B

- **30B-A3B** = 30B parameters, **3B active**（MoE）
- **Compact** → 低 serving cost

#### Stage 1: Memory On-Policy Distillation

- 在 student-generated states 上学 framework-specific write protocols
- 关键：**on-policy**（student 自己 rollouts）→ 避免 teacher-student 分布偏移

#### Stage 2: Memory RL

四组件：

| 组件 | 作用 |
|------|------|
| **Dense per-chunk probes** | 评估每个 chunk 的 quality |
| **Attributed cross-chunk rewards** | 跨 chunk 关联性奖励 |
| **Over-storage controls** | 防止过度写入 |
| **Chunk-level GRPO** | group-relative 优化 |

### Policy-Written Banks 跨 Window 携带

- 训练时：把 policy 当前写的 bank 带入下一个 window 的 context
- → 训练分布 ≈ 部署分布（bank 内容始终来自 policy）

### 测试设置

- **固定 20% benchmark subsamples**（避免信息泄露）
- 评估 4 个 harness（含 held-out **EverMemOS**）

---

## 实验结果

### Benchmark 排名（4 个 harness × 20% subsamples）

| Harness | Hy-Memory-30B-A3B | Claude Opus 5 |
|---------|------------------|---------------|
| Mem0 | **#1** | #2 |
| MemOS | **#1** | #2 |
| Hy-Memory | **#1** | #2 |
| EverMemOS (held-out) | **#1** | #2 |

### Macro Average

| 模型 | Macro Avg |
|------|-----------|
| **Hy-Memory-30B-A3B** | **55.49%** |
| Claude Opus 5 | 54.62% |

→ 30B-A3B（3B active）击败 Claude Opus 5 在 4 个 memory harness 上的平均表现 → **efficiency + generalizability 同时达成**。

### Generalization

- 训练在 Mem0 / MemOS / Hy-Memory → **零样本迁移到 EverMemOS** 仍第一 → 真正学到了 framework-agnostic memory write 能力。

---

## 局限与展望

- 仅在 4 个 memory harness 上评估 → 其他 memory framework (Letta, LangMem) 未覆盖。
- "Over-storage controls" 机制细节未充分描述。
- 训练两阶段成本未量化（on-policy distillation + RL）。
- "Held-out" 仅 EverMemOS 一个 → 更多 framework 的真正 OOD 能力待验证。
- Memory read-path 模型（与 writer 配合）未在 paper 中评估。

## 实现建议

- **实现难度**: 高（两阶段训练 + chunk-level GRPO + policy bank carrying）
- **预期性能**: 4 memory harness 上 **#1**，macro 击败 Claude Opus 5
- **适用场景**:
  - **生产级 LLM agent memory**（需要支持多个 framework）
  - Long conversation 助手（multi-session continuity）
  - Personal AI 助手（user preference retention）
- **不适用**: 短会话场景（over-engineering）；超大规模 memory bank（chunk-level RL cost）
- **部署提示**:
  - **On-policy distillation** 阶段必须有足够 student rollouts → 高质量数据需求
  - Over-storage controls 可**独立调参**（按应用场景）
  - MoE 部署需 MoE-aware inference engine

Hy-Memory-30B-A3B 用 On-Policy Distillation + Memory RL (chunk-level GRPO) 训出 unified long-term memory writer，3B active 在 4 memory harness 上击败 Claude Opus 5（含 held-out），framework 切换零样本迁移。
