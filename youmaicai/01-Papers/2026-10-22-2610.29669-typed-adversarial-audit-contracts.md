## 核心贡献
1. 提出 BiasGuard-D：两个来自不同模型家族的 adversarial 角色交换 typed claim documents，再由 three-model quorum 以多数投票裁定，最后用一个 combined referential-plus-semantic invariant 校验判决。
2. 实验证明 semantic 分量能捕获 referential checks 遗漏的判决；移除 iterative loop 会使 invariant satisfaction 急剧下降，验证了迭代审议层的必要性。
3. 审议层（deliberation layer）可通过仅改变 role-framing 就从 stereotype remediation 迁移到 hallucination remediation，在 HaluEval QA 上把 right-answer recovery 提升 49 个百分点。
4. 每一条 claim、vote、instruction 都以 typed record 存储，为运营者提供可在新兴 AI 法规下审计的 provenance trail。

## 问题动机
LLM 生成的 record 正在大量涌入生产信息系统，并被当作 data asset 对待——它们承担着与操作型数据库 record 相同的质量期待。但这类 record 存在一个特殊困难：同一条 record 可以**同时满足又违反**同一条质量规则（例如一个 grounded fact 紧挨着一个 hallucination，一个有用的答案紧挨着一个刻板印象）。经典数据清洗无法解决，因为对同一 span 的两个判断是互相矛盾的；单一 LLM judge 也无能为力，因为它共享了制造该冲突的同一批训练偏差。现有的 prompt engineering、chain-of-thought、RLHF 等干预手段虽然降低了表面错误率，但既不提供审计链路，也无法区分"真正修复"与"全面压制"。论文据此提出核心问题：对结构化的 inter-agent record 做确定性检查，能否捕获纯 referential 检查所遗漏的缺陷？

## 方法
**BiasGuard-D 架构**由四层构成：

1. **Adversarial role pair**：两个来自**不同模型家族**的对抗性角色，交换 typed claim documents（类型化的声明文档）。
2. **Three-model quorum**：第三个模型参与的多数投票裁决机制。
3. **Referential + semantic invariant**：一个合并的复合不变量来验证裁决结果。摘要强调 semantic 分量会在 referential checks 未能捕获的地方触发。
4. **Iterative loop**：反复迭代审议；实验表明移除该 loop 后 invariant satisfaction 显著下降。

5. **Triage gate（分流门）**：摘要提到 triage gate 需要一个跨家族的第二审计员 (cross-family second auditor) 才能在 objective hallucination 上维持 recall。

关键工程设计是**一切都是 typed record**：claim、vote、instruction 全部结构化存储，从而构成可审计的 provenance trail。

## 实验设置与结果
- 数据/基准: HaluEval QA（用于 hallucination remediation）；stereotype 场景的基准在摘要中未明确命名。
- 对比方法: 摘要未列出具体 baseline；提到的是消融（移除 iterative loop）与不同配置（三模型 quorum、triage gate 是否配置跨家族第二审计员）。
- 主要结果:
  - 审议层仅通过 role-framing 改动即从 stereotype 迁移到 hallucination 修复，在 HaluEval QA 上 right-answer recovery **提升 49 个百分点**。
  - semantic 分量能捕获 referential checks 遗漏的判决；移除 iterative loop 使 invariant satisfaction 急剧下降（摘要未给具体数值）。
  - triage gate 若无跨家族第二审计员，则在 objective hallucination 上 recall 无法维持。

## 关键技术细节
- 跨模型家族（cross-family）是设计的核心约束：同家族模型共享训练偏差，quorum 会被同向偏置污染。
- 全文篇幅较短（arXiv PDF 仅 84 KB），符合 CoopIS 2026 会议论文的体量。
- 采用 deterministic/invariant-based 校验而非单纯依赖 LLM judge，这是与"LLM-as-judge"路线的根本分野。

## 局限性
- 摘要未报告具体数据集规模、quorum 的误报/漏报数值、49 个百分点的 baseline 具体分数。
- 依赖"两个 adversarial 角色来自不同模型家族"，因此实际效果受可用模型家族多样性限制；同一 API 后端微调出的多个模型不满足该前提。
- 三模型多数投票带来明显的推理成本与延迟，摘要未讨论成本。
- 针对 stereotype 与 hallucination 两类缺陷的有效性是否可推广到其他类型缺陷（如数值错误、越权建议、版权风险）未在摘要中说明。
