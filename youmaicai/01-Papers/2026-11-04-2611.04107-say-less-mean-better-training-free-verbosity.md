## 核心贡献
1. 提出 **MinimalLM**：一个完全 training-free 的推理期冗长度控制框架，核心设计原则是把「何时想停」与「停下在结构上是否合适」彻底解耦——前者由 length-dependent、uncertainty-aware 的 stop-token logit 调整负责，后者由 structural completeness gate 负责，二者与 response-level 指令、生成后 final completion check 协调配合，不修改任何模型参数、不引入辅助模型。
2. 大量实验覆盖 3 个开源 LLM（Mistral-7B-Instruct-v0.2 / Llama-3.1-8B-Instruct / Qwen2.5-3B-Instruct）× 330 道题 = 990 个答案/配置，共 **5,940 个响应**，主实验 token 削减 **47.6%**（95% CI 45.7%–49.5%），单请求延迟改善 **19%–68%**，主评估中 **0.0%** 结构截断。
3. 消融实验给出清晰结论：仅有 stop-token boost（w/o guardrails）虽然砍掉 32.6% token，但 **59.3%** 的回答被结构截断；去掉 completeness gate 后有 17.3% 截断；去掉指令后 token 节省降到 19.8%。指令（prompting）与 guardrail 是**互补**关系，而非可替代。
4. 建立了长度匹配的**直接截断基线**，证明 MinimalLM 优于截断而非仅仅"因为提前停"：同等 token 削减下直接截断得分 6.46（截断到末句 6.82），MinimalLM 8.04；judged complete 比例分别为 11% / 40% / **77%**。
5. 提出并强调评估方法论层面的警示：**相似度高 ≠ 结构完整**。早期版本 stop-boost 单独使用就能满足预设 BERTScore 相似度阈值，却频繁在句子中间截断——因为提前停止只保留原输出的前缀，文本相似度会掩盖结构缺陷。
6. 分离"结构完整性"与"信息覆盖度"两个概念：停在合法边界并不保证覆盖了用户请求的全部细节；自动 judge 报告 MinimalLM 有 22.9% 回答缺失请求信息（baseline 12.6%），但与人工标注的一致性有限，需谨慎解读。

## 问题背景
LLM 普遍生成超出必要长度的回答，这直接抬高推理延迟与算力成本。指令微调与偏好优化（RLHF）会进一步放大 verbosity bias（Singhal et al. 2023; Saito et al. 2023）——长度与质量在偏好标注中高度相关。

现有效率工作大致分三类：(a) 投机解码、prompt token 剪枝（LazyLLM/SlimInfer）、动态输入剪枝等**降低每个 token 成本**的方法，它们完全不改变输出 token 数；(b) TokenSkip 这类需要 LoRA 微调的方法；(c) 纯 prompt 层的"请简洁些"和 token cap / stop-token boost 的**早期停止**。第三类最轻量但最危险：token cap 会在任意位置砍断答案，作者强调 "Only methods that reduce output tokens can cut answers off"。

关键 gap 在于：直接对已有长回答做截断，与让模型在生成过程中自行收敛到简洁，**在相同 token 预算下产出质量完全不同**。作者实测 MinimalLM 相对 baseline 的内容保留率只有 37%（截断基线为 58%），说明"生成一个简洁答案"与"截断一个冗长答案"是两种不同的机制，效果不可互相替代。此外，自动评估的盲区——BERTScore 之类的相似度指标对结构截断不敏感——构成一个被忽视的方法论陷阱。

## 方法

### 1. 三阶段整体架构
MinimalLM 分为三个阶段（Figure 1），完全在推理期实现：

1. **生成前**：注入 response-level 系统指令，引导模型规划简洁但完整的回答；
2. **解码中**：custom logits processor 同时执行 stop-token boost（带 entropy gate）与 structural completeness gate；
3. **生成后**：final completion check 处理触及 max_new_tokens 上限的回答。

基础 LLM 保持不变，无需重训练、无需辅助网络。

### 2. Stop, not skip：为什么不做 token 级删除
作者的前期实验发现，一个语义冗余信号在 24,021 次 greedy decoding 决策中只改变了 **12** 次；且在冗余内容处停止常常丢弃了回答后面仍然有用的信息。根因是自回归结构：decoder 无法"跳过"一段已生成的冗余文字再假装它从未存在——删除已生成文本并不能回收其计算成本。因此框架聚焦于**受控的提前终止**而非 token 级内容删除。

### 3. 长度与不确定性感知的停止
在解码步 $t$，logits processor **只调整 stop token 的分数**：

$$
\tilde{s}_t = s_t + \underbrace{\alpha \cdot \sigma\!\left(\frac{t - t_{\min}}{t_{\max} - t_{\min}}\right)}_{\text{长度依赖项}} \cdot \underbrace{\phi(H_t)}_{\text{不确定性因子}}
$$

其中

$$
\phi(H_t) = \mathbb{1}\!\left[H_{\min} \le H_t \le H_{\max}\right]
$$

为由下一 token 分布的**熵**决定的不确定性因子，$H_t$ 以 nats 计；

$$
\Delta_t = z_t^{\max} - z_t^{\max,\text{stop}}
$$

为最高分 token 与最高分 stop token 之间的 logit gap。实际实现中 $\alpha=1$，熵带宽度为 2 nats，模型特定阈值 $t_{\min}=253$、$t_{\max}=405$，取自开发集回答长度的约 25/50 百分位。在这些设置下，停止干预**仅在约 380 个生成 token 之后**才生效。

在无 gate 的情况下（$\phi=1$），只要 logit gap 为正，调整后的 stop 分数就会达到或超过原始最高 token 分数。

### 4. Structural completeness gate
核心机制：**停止调整仅在生成文本到达识别到的完成边界时才被允许**：

$$
\text{gate}(t) = \mathbb{1}\!\left[\text{valid\_boundary}(y_{1:t})\right], \qquad
\tilde{s}_t = s_t + \text{gate}(t)\cdot \alpha\cdot\sigma(\cdot)\cdot \phi(H_t)
$$

有效边界包括：句子结束标点（需排除缩写与列表标记）、闭合的 code fence、配平的括号。当检测不到有效边界时，gate 抑制停止调整，生成继续。边界校验**仅在停止机制本将触发终止时才执行**，因此额外解码开销极小。

### 5. Response-level 指令与 final completion check
系统指令要求："Always give a complete answer: address every part of the user's request, and finish every sentence, list and code block that you start. Never stop in the middle of a sentence. Put the most important information first and do not repeat yourself. Keep the whole answer within about 200 words, and plan it so that everything requested fits and the answer ends with a complete sentence."

final completion check：触及 max generation limit 的回答若在句中结束，则裁剪回最后一个识别到的完整句子。该后处理不需要额外模型推理。

**Proposition 1**：在实现的边界检测规则下，只要存在这样一个边界，停止干预与 final completion check 共同保证展示给用户的回答结束于一个被识别的完整句子或闭合结构块。此性质只涉及**结构终止**，不涉及语义完整性。

### 6. 部署接口
```python
proc = MinimalLMProcessor(stops, plen, t_min=253, t_max=405, tokenizer=tok)
out  = model.generate(**enc, max_new_tokens=1024, logits_processor=[proc])
text = final_check(tok.decode(out[0, plen:]))
```
两个关键部署参数：指令级词预算（影响简洁度与信息覆盖的权衡）与停止阈值 $t_{\min}/t_{\max}$（需按模型典型回答长度校准）。

## 实验结果
- **Dataset/Task**: MT-Bench 首轮对话 80 题 + AlpacaEval 150 题 + Arena-Hard-Auto 100 题 = 330 题（开发集题目不重叠）；域泛化额外测试 8 个学科（health/history/economics/programming/science/mathematics/writing/law），每类 1 道代表题。模型为 Mistral-7B-Instruct-v0.2 / Llama-3.1-8B-Instruct / Qwen2.5-3B-Instruct，fp16、greedy、max_new_tokens=1024、单个 NVIDIA A40。6 个系统配置 × 990 答案 = 5,940 响应。
- **Main results**:

| System | TRR | Cut off | Incompl. | Score(1-10) |
|--------|-----|---------|----------|-------------|
| Baseline | – | 5.7% | 14.7% | 8.42 |
| Instruction only | 45.3% | 0.6% | 22.0% | 8.07 |
| w/o guardrails | 32.6% | 59.3% | 55.2% | 7.51 |
| w/o gate | 50.8% | 17.3% | 31.6% | 7.83 |
| w/o instruction | 19.8% | 0.3% | 21.7% | 8.22 |
| **MinimalLM** | **47.6%** | **0.0%** | 23.4% | **8.04** |

  分模型 token 削减：Mistral-7B 23.1%、Llama-3.1-8B 47.5%、Qwen2.5-3B 68.8%。990 个回答中仅 **5** 个需要末尾裁剪，说明节省主要来自生成减少而非后处理。

- **Ablations**:
  - 无 guardrail 时 MT-Bench 上 **82%** 的缩短回答提前终止，有时直接漏掉后面被请求的条目（Figure 2 实例：请求 5 个例子，第 3 个例子中间被切断，390 tokens；MinimalLM 完整给出 5 例并以完整句结束，421 tokens；baseline 618 tokens）。
  - Instruction-only 的 token 削减跨模型差异巨大：Mistral-7B 仅 17.5%，Qwen2.5-3B 达 68.4%。
  - 去掉 completeness gate → 17.3% 结构截断；去掉指令 → token 节省降至 19.8%。
  - 与直接截断对比（Figure 3）：MinimalLM 达到的 token 削减水平上，直接截断得分 6.46，裁到末句 6.82，MinimalLM 8.04；judged complete 比例 11% / 40% / 77%。无 guardrail 的停止机制与截断表现接近（7.51 vs 7.36），完整性更低（45% vs 57%）。
  - 延迟与吞吐：单请求加速 19%–68%（Mistral 10.1s→8.2s；Qwen2.5-3B 10.8s→3.5s）；每 token 额外解码开销 < 0.8%（ms/token 几乎不变，30.8→31.0 等）；固定 batch 下 GPU 时间下降 5%–55%，但**不与 token 节省成比例**，因为 batch 完成取决于最长响应。
  - 域级（Mistral-7B，baseline/MinimalLM）：programming 784→300 tokens（-62%，24.7s→9.5s）、science 629→330（-48%）、health 669→407（-39%）、history 645→405（-37%）、law 429→286（-33%）、economics 520→383（-26%）、writing 374→288（-23%）；mathematics 183→260（**+42%**，baseline 本身已很短，固定预算反而拉长）。所有 8 域均 100% 结构完整。
  - 信息覆盖：自动 judge 判定 MinimalLM 22.9% 缺信息 vs baseline 12.6%，但与人工评估一致性有限；人工检查的 24 个 MinimalLM 回答中 0 个被判定不完整，而无 guardrail 组 24 个中有 16 个不完整。

## 关键洞察
1. **结构完整性与信息覆盖必须分开测量。** 论文最有价值的概念区分：MinimalLM 做到了 0% 结构截断，却仍可能有 22.9% 的回答缺失用户请求的某些细节（相对 baseline 的 12.6%）。把"回答在合法边界结束"当成"回答完整"是常见且危险的错误。
2. **早期停止的评估需要长度匹配的截断基线。** 没有这个基线，"stop-boost vs prompt" 的比较毫无意义；有了它，才能区分"提前停"（7.51，与截断相当）还是"让模型重新收敛到简洁"（8.04，显著更优）。二者的内容保留率差 37% vs 58%，机制本质不同。
3. **相似度指标对结构缺陷系统性失明。** BERTScore 阈值对早期停止毫无阻力，因为前缀保留天然保证高相似度。任何长度控制方法的安全性评估都需要显式的 completeness check。
4. **token 节省 ≠ 吞吐提升。** 固定 batch 下一个超长响应会拖住整批，GPU 时间只降 5%–55% 而非 47.6%。真实收益取决于 continuous batching（论文未测）与响应长度方差。
5. **固定预算对短回答是反向优化。** 数学域出现 +42% token 增长，说明统一词预算在"本身就简短"的问题上会造成负收益；有效的 verbosity control 应按请求的信息需求自适应。
6. **指令与 guardrail 是互补而非冗余的。** 指令负责让模型**规划**在预算内完成全部请求内容，guardrail 负责保证**终止位置**合法。只有指令 → 跨模型不稳定（17.5%–68.4%）；只有 guardrail → 59.3% 截断。

## 局限性
- 仅评测 3 个 3B–8B 开源模型、单一 GPU 型号（A40）、仅 greedy decoding；更大模型、采样解码、其他硬件配置均未探索。
- 质量主要靠自动评估（Phi-4 作为 blind judge），人工检查样本很小（96 份阅读，其中 cut-off 子集 24 份），统计效力有限。
- 信息覆盖的自动指标与人工判断一致性不佳，22.9% 缺信息率这个数字本身可信度有限。
- 域实验每个类别只用 1 道代表题，在固定 200 词预算下评估，不构成领域基准。
- 未评估 continuous batching（论文自己指出这是吞吐未达标的主因）；也未与真正的系统级服务栈（如 vLLM）集成测量。
- 阈值 $t_{\min}=253/t_{\max}=405$ 与熵带 2 nats 是基于开发集长度百分位手工校准的，模型/任务迁移性未知。
- 未处理多轮对话中"简洁"的语义漂移（例如用户在追问时需要更长的回答）；也未考虑多语言下的句法边界差异。
- Proposition 1 的边界检测依赖启发式规则（缩写、列表标记、code fence、括号），对 Markdown 表格、LaTeX、代码块内嵌套引号等场景的鲁棒性未评估。

## 适用场景
- **适用**：对开源 3B–8B 模型的低风险问答服务做推理成本压降（客服问答、文档摘要、知识问答、简单编程解释）；需要"回答必须以完整句/闭合代码块结束"的硬性产品约束的场景；对延迟敏感且请求以单轮为主的服务。
- **不适用**：需要长篇幅深度论述或推导的任务（数学/法律分析报告会因固定预算而受损）；多轮对话中同一会话需要差异化长度策略的场景；已使用强推理模型做长 CoT 的场景（该框架不针对 reasoning token）；要求严格全覆盖的任务（因为信息覆盖反而下降）。
- **不适用**：以提升质量为目标的研究（baseline 8.42 > MinimalLM 8.04，质量有实质损失）；无法修改推理管线的部署形态。
