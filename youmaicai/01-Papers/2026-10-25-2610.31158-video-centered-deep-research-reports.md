## 核心贡献

> 现有的 deep research agent 基准只评「基于开放网络证据的长报告」，不评「**以某个视频为源**的研究」。本文提出 **Video-Centered Deep Research Report Generation** 任务、**OmniDR-Bench** 基准，以及 **Omni Atomic Rubric Trees（Omni-ARTs）** 这一层级化评测方法 —— 18 个 agent 配置中最好成绩为 **63.3 / 100**。

1. **提出新任务**：给定一个视频与用户请求，agent 需**识别研究问题（identify research questions）** → **检索外部多模态证据** → **产出与视频相关时刻（relevant video moments）联动的交互式报告**。
2. **论证任务的实际价值**：该报告帮助用户**定位相关时刻、核查论断、复现演示的流程（reproduce demonstrated procedures）、基于视频内容做出决策**。
3. **提出 Omni-ARTs（Omni Atomic Rubric Trees）评测法**：每棵树包含 **3 个维度（dimensions）**、**23 个共享方向（shared directions）**、以及**任务专属的原子化二元判据（task-specific atomic binary criteria）**；三个维度考察 **视听锚定（audiovisual grounding）、多模态证据使用（multimodal evidence use）、交互式呈现（interactive presentation）**。
4. **提出 ARC（Audited Rubric Construction）构建流程**：**独立证据收集 → 自动化检查 → 行为校准（behavioral calibration）→ 迭代人工复核**，以保证 rubric 本身的可信度。
5. **OmniDR-Bench 数据规模**：**50 个中英任务**、覆盖 **19 个真实世界子类别**、包含 **6,414 条判据**；代码与数据已开源。

## 技术方案

### 核心思想

**「Watching + Searching」的旧范式不足**：现有 deep research agent 流程是「**看视频 + 搜网页**」，产出文本报告。但视频本身是**一手材料**，报告应当**与视频时刻双向链接** —— 用户点了报告里的论断，能直接跳到视频里对应的时刻去核验。

**任务定义（Video-Centered Deep Research Report Generation）**：
```
(video, user request) → agent:
   ① 识别研究问题 (research questions)
   ② 检索外部多模态证据 (external multimodal evidence)
   ③ 产出交互式报告，且报告锚点链接到相关视频时刻
```

**为什么要「原子化二元判据」**：长报告的质量无法用一个分数可靠刻画。作者把报告质量拆成**树状结构**：顶层 3 维度 → 23 个共享方向 → 每个任务专属的**原子判据**（每条是二元的：满足 / 不满足）。这带来两个好处：**可审计**（每个判定有明确依据）与**可加权**（方向可跨任务共享，任务判据可特化）。

**ARC 流程的自检逻辑**：
- **independent evidence collection** —— 收集 rubric 所需证据，避免单人/单次判断；
- **automated checks** —— 机器可查的判据先自动化；
- **behavioral calibration** —— 用模型/agent 的实际行为来校准判据难度与表述（避免判据过严或过松）；
- **iterative human review** —— 迭代人工复核收口。

**Skill-based workflow**：论文提出一个基于 skill 的工作流 —— 与 2026-10-24 那批工作（Adaptive Skill Granularity、IQuest-Q1 多 scaffold）属同一趋势：**把可复用流程显式化为 skill，而非塞进 prompt**。

### 关键技术

| 技术 | 说明 |
|------|------|
| **Video-Centered Deep Research Report Generation** | 新任务范式：源视频 + 用户请求 → 交互式研究报告 |
| **Omni-ARTs** | Omni Atomic Rubric Trees；**3 维度 / 23 共享方向 / 任务专属原子二元判据** |
| **Audited Rubric Construction (ARC)** | 独立证据收集 → 自动化检查 → 行为校准 → 迭代人工复核 |

## 关键实验结果

| 项目 | 结果 |
|------|------|
| **任务数** | **50**（中文与英文） |
| **真实世界子类别** | **19** |
| **判据总数** | **6,414** |
| **Omni-ART 结构** | 每棵树 **3 个维度 + 23 个共享方向 + 任务专属原子二元判据** |
| **评测的 agent 配置数** | **18** |
| **最好成绩** | **63.3 / 100** |
| **当前 agent 的短板** | 需要**更广的内容覆盖（broader content coverage）**、**跨模态的更强因果与逻辑分析**、**更准确的引用支撑（more accurate citation support）** |

## 关键结论

1. **「视频中心的深度研究」是一个真实缺口，不是人造任务。** 报告链接到视频时刻，直接服务**定位、核查、复现、决策**四类真实需求 —— 报告与源材料的可追溯性是长报告可信度的核心。
2. **Omni-ART 的设计解决了「长报告怎么评」的老问题。** 3 维度 / 23 共享方向 / 原子二元判据 + ARC 审计流程，让评测从「整体打分」变成**可逐条追责的结构化判定** —— 这是本文最可迁移的评测方法论贡献。
3. **当前 agent 远未达标：18 个配置最好只有 63.3/100。** 且失败模式被清晰归为三类：**覆盖不足、跨模态因果/逻辑分析弱、引用支撑不准**。其中「引用支撑不准」对研究类 agent 是**可信度杀手**。
4. **评测对象是「配置」而非「模型」。** 作者分别分析 model / harness / skill 配置 / 视频类别 / 研究轨迹 —— 说明**agent 能力是模型 × 脚手架 × skill 的乘积**，单看模型分数会误判。

## 局限性

- **最好 63.3/100 的分数含义依赖 Omni-ART 的判据难度设定** —— 原子判据由 ARC 流程构造，但**难度基准未做外部校准**（没有人类专家对照的分数锚点），因此「63.3」在不同 rubric 下的含义不同。
- **任务数仅 50**，覆盖 19 个子类别 —— 每个子类别平均不足 3 个任务，**子类别内的统计可靠性有限**。
- **判据总数 6,414 但未披露「一致通过率」** —— 未说明人工复核的一致性（inter-annotator agreement）数值，rubric 的可靠性缺一个硬指标。
- **评测配置 18 个，但未列出具体是哪些模型 / harness / skill 组合**，也未给出**逐配置分数**与方差，读者无法判断 63.3 是否稳定领先。
- **「行为校准」这一步存在**用模型行为反推判据松紧的**潜在循环论证**风险 —— 摘要未说明是否有独立的人类锚定。
- **中文与英文任务混在同一池中报告总分**，**未报告语言间的分数差异** —— 对一个明确以中文任务为主的基准（中英各占一部分）而言，这是重要缺口。
- **视频规模与时长未披露**（多少个视频？多长？），影响任务难度判断。
- **交互式报告的评测维度**（维度三）如何客观衡量「交互」质量，摘要未展开。

## 实现建议

- **实现难度**：中-高（评测框架本身可复用；视频理解与报告生成依赖现成 agent harness）
- **预期性能**：18 个配置最好 **63.3/100**；当前 agent 的三大短板为覆盖广度、跨模态因果推理、引用准确性
- **适用场景**：**视频内容分析 / 教程复现 / 视频证据核查类 agent 的选型与评测**；做研究型 agent 产品的团队可直接借鉴 Omni-ART 的 rubric 组织方式
- **团队行动**：评测长报告质量时，**照搬「维度 → 共享方向 → 原子二元判据」三层结构 + ARC 审计流程**；同时**分开报告推理链质量与最终结论**（参考 [[2026-10-25-2610.31000-seclog-bench-cyber-log-reasoning]]）
