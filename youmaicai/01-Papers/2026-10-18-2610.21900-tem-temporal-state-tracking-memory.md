## 核心贡献

> 提出 **TEM** —— **training-free framework**，把 facts 存为 **versioned records linked to sources**，**label historical records**（标"已过期/历史"），4 个 open-weight models 上 key-entity hit rate **75.71–97.62%**，historical-residence subset **96.67–100%**。证据仅 **94–118 tokens** per answer，**比 session-aware RAG 少 48.75–56.73%**。1,540 LoCoMo questions 上超 session-aware RAG，**+7.92 / +10.58 pp**。

1. **新 memory 抽象**：facts as **versioned records** linked to sources。
2. **历史 labeling**：retrieve 后 **place in source order + label historical records** → 显式传递 temporal status 给 generator。
3. **Multi-source evidence**：event memory + original dialogue turns 补 structured fact 缺失。
4. **Training-free**：仅靠 prompt engineering + retrieval 排序。
5. **Strong + efficient**：hit rate 高 + 证据 token 少 **近一半**。

## 技术方案

### Motivation

- Agent memory 跨 conversation 信息变化：
  - 新 fact 可替代旧 value
  - 但旧 value **仍可对后续 question 重要**（如 "你前公司地址？" — 当前公司 ≠ 该问题答案）
- 现有 memory 框架：**统一 latest** 或**平铺所有 versions**（无 temporal 区分）

### TEM 框架

```
Facts as versioned records linked to sources
        ↓
Retrieve relevant versions
        ↓
Place in source order
        ↓
Label historical records ("outdated" / "historical")
        ↓
Pass evidence to answer model
        ↓
Event memory + original dialogue turns (fill gaps)
        ↓
Answer
```

### 关键设计

#### 1. Versioned Records

- 每条 fact：**value + timestamp + source link**
- 版本可继承 / 替换 / 补充

#### 2. Source-Ordered Retrieval

- Retrieve 时按 **source 出现时间排序**
- 最新版本自然在前

#### 3. Historical Labels

- **显式 label** "this is outdated / historical" 在 prompt 中
- → Generator **知道哪些 versions 是当前的，哪些是历史的**

#### 4. Multi-Source Evidence

- Structured facts（versioned records）
- Event memory（high-level events）
- Original dialogue turns（细节）
- → 互补信息组合

### Training-Free

- 无 fine-tuning
- 仅靠 prompt + retrieval ordering + historical labeling

## 实验结果

### Setting 1: 420 Questions / 600 Sessions / 60 Personas

| Model | Overall Key-Entity Hit Rate | Historical-Residence Subset |
|-------|----------------------------|----------------------------|
| 4 open-weight models | **75.71 – 97.62%** | **96.67 – 100.00%** |

→ 历史 residence 子集上**几乎完美**（说明 historical labeling 关键）

### 关键 Ablation：Historical Labels

| Variant | Overall Hit Rate |
|---------|------------------|
| Without historical labels | baseline |
| **With historical labels** | **+17.14 – 55.95 pp** |

→ Historical labels 是核心：补 labels 后 overall hit rate 大幅提升。

### 证据 Token 效率

| Method | Tokens per Answer |
|--------|-------------------|
| Session-aware RAG | ~250+ (估计) |
| **TEM** | **94 – 118** |

→ **节省 48.75 – 56.73%** tokens

### Setting 2: 1,540 LoCoMo Questions

| Method | Score |
|--------|-------|
| Session-aware RAG (backbone A) | baseline |
| **TEM (backbone A)** | **+7.92 pp** |
| Session-aware RAG (backbone B) | baseline |
| **TEM (backbone B)** | **+10.58 pp** |

→ **两个 backbone 都超 session-aware RAG**，**conservative** delta（最保守估计）即 +7.92 / +10.58 pp。

### Hybrid Memory（fixed evidence budget）

- TEM 限 evidence budget 下仍超 session-aware RAG
- → 在 cost-sensitive 场景也 valid

---

## 局限与展望

- 仅 4 open-weight models → closed-source (GPT-4o, Claude 3.5) 表现未知。
- "Historical labels" 触发机制 → 何时视为"outdated" 由系统决定，**需 fine-tune retrieval policy**。
- 60 personas → 多样性有限。
- Long-term (>1 year) 跨 session temporal drift 未充分测。
- "Source link" 来源追踪要求**所有 fact 有 source** → bootstrap 阶段可能无 source。

## 实现建议

- **实现难度**: 低-中（无需训练，仅需 versioning + labeling）
- **预期性能**: LoCoMo 等 long-conversation benchmark **+7–10 pp** over RAG
- **适用场景**:
  - **长对话助手**（user preferences 多次更新）
  - **Customer service**（account info 跨 session）
  - **Personal AI**（life events tracking）
- **不适用**:
  - 短对话（无 version 问题）
  - 无 source 来源的 data（bootstrap 困难）
- **工程提示**:
  - Versioning 可**lazy**：只在冲突时升级
  - Historical labels 应**always-on**（cost 低，gain 大）
  - 与 RAG **互补**：RAG 找 facts，TEM 加 versioning + labeling

---

## 一句话总结

TEM 用 **versioned records + source order + historical labels** 把 long-conversation memory 从 "latest 覆盖历史" 升级为 "显式 temporal 区分"，training-free 即获 LoCoMo **+10 pp** over session-aware RAG 且 token **减半** — **长 memory 的轻量方案**。
