## 核心贡献

> 提出 **Continual Learning Exam (CLE)**：由 **50+ 行业专家**撰写的 **120 个任务 × 5 级阶梯 = 600 个 level**，覆盖 **89 个职业角色、12 个职业领域**，配有 **23,981 个真实输入文件、19 个有状态模拟应用（1,024 个 API）、16,125 条人写评测标准**；在 **17 个 harness–model 配置**下，**即使给诊断反馈和一次重交（+5.3 pp 中位增益），最好的 Claude Code + Opus 5 也只通过 47.67% 的 level**，五级全通仅 **23.33%**（28/120 个任务）——从经验中持续学习对当前前沿 LLM 仍是硬骨头。

1. **阶梯式耦合任务设计** — 每个任务是一个 **5 级阶梯**（L1…L5），代表同一职业角色与工作语境下的五段连续委托；**必须通过当前 level 才能解锁下一级**，后一级的新任务会**依赖前几级积累的经验与产物**（Data Dependency 类）。
2. **五种可迁移知识形式** — 任务阶梯围绕五类知识组织：**Tools and Skills**（工具与技能用法）、**Data Dependency**（信息与产物依赖）、**Strategy**（方法选择与避坑）、**User Context**（用户偏好）、**Domain Knowledge**（专业规则与惯例）——把"经验"拆成可考核的载体而非泛泛而谈。
3. **可执行环境 + 人写 rubric** — **19 个有状态 mock 应用暴露 1,024 个 API**，状态可跨 level 延续；提交由一个多轮 **evaluation agent**（DeepSeek V4 Flash）对照 **16,125 条人写 checklist** 评分（平均每 level 26.9 条、每任务 134.4 条），每条标准指定唯一预期结果与验证证据；该 evaluator 与仲裁后的人工标签在 rubric-item 级一致率 **96.86%**。
4. **双重质量门构建流程** — 任务先由领域专家从自身真实工作起草，经 task-review agent 审计（格式合规、输入文件真实性、答案泄漏、rubric 可验证性、持续学习设计），并**由 review agent 亲自端到端跑一遍任务**验证难度递进，再交**两名随机分配的人类审稿人**独立全量评审，两者均接受才入库；共 120 个任务通过。
5. **反馈与修订的价值被量化但被证明不足以弥合差距** — 17 个配置中 **16 个**在 Trial 2 完成率更高，**中位提升 5.33 pp**；但**L1 中位通过率 62.50% → L5 仅 8.33%**，且改进**不必然外溢到更高 level**（Qwen3.8-Max 两个配置在 L1–L3 上升但 L4–L5 不变）。
6. **Harness 差异大于模型差异** — 在共享 6 个 backbone 的对照中，**Hermes-Agent 在所有 backbone、两种提交预算下完成率都高于 OpenClaw**，Trial 1 平均优势 **9.56 pp**、Trial 2 扩大为 **11.42 pp**（两者 Trial 2 平均完成率 28.17% vs 16.75%）；反馈增益也随 harness 分化（DeepSeek V4 Pro：Hermes +5.50 pp，OpenClaw **−1.33 pp**）。

## 技术方案

### 核心思想

现有 agent 基准几乎都是**单任务打分**的：任务独立呈现、独立计分，因此衡量的是"解题能力"，而不是"**是否因为积累了经验而变得更好**"。持续学习（CLE）的定义式要求恰好相反——必须沿着一条**受控的长任务序列**追踪表现，看经验是否带来持续提升且不牺牲既有能力。

CLE 用**阶梯 + 解锁 + 跨级依赖**三件套把"持续"变成结构性的：

```
任务 i 的五级阶梯 L1 → L2 → L3 → L4 → L5
   │   └─ 通过才解锁下一级（gate）
   ├─ 每一级内含若干学习阶段 n（可多次交互）
   ├─ 动作 → 环境观察；提交 → rubric 评估
   └─ 失败（K=2 时）返回诊断反馈 → 修订 → 再提交
                 │
                 ▼
        交互历史 + 反馈  =  经验 e_n
                 │
        更新算子 U_n(θ_n, s_n, e_n)
                 │
   θ_n = 模型参数（本文全部冻结）  s_n = harness 持久状态（memory / skills / 经验）
```

论文用统一形式 `(θ_{n+1}, s_{n+1}) = U_n(θ_n, s_n, e_n)` 覆盖两种学习路径：**参数化学习**（SFT/RL 更新 θ）与**非参数化学习**（只更新持久 harness state，θ 冻结）。CLE 的主评测设定是**冻结参数 + 保留 harness 状态跨任务**，即 `U_n(θ_n, s_n, e_n) = (θ_n, s_{n+1})`——因此测的是**经验在 harness 中的留存与复用**。

**能力分层 T1–T5**（按学习决策的自主性与研究设计自主性划分，逐层递进）：T1 预定义规则决定学什么/何时学/如何留存；T2 agent 在给定任务目标下自主做学习决策并用反馈自检修正；T3 自主适配到陌生领域并迁移既有知识；T4 自主设计调查来生成并验证新知识（自主提出可检验子问题、选实验、判定发现）；T5 自主设定研究目标与优先级并随发现修订研究议程。当前前沿系统基本停在 T1–T2。

### 关键技术

| 技术/方法 | 说明 |
|------|------|
| Five-level gated ladder | 每任务 5 级，必须逐级通过解锁；后级构建在前级经验之上 |
| 5 forms of transferable knowledge | Tools and Skills / Data Dependency / Strategy / User Context / Domain Knowledge |
| Continual learning formulation | `(θ_{n+1}, s_{n+1}) = U_n(θ_n, s_n, e_n)`；冻结模型 + 保留 harness state |
| Capability hierarchy T1–T5 | 按学习决策自主性、跨域适应、研究设计自主性递进 |
| Stateful mock applications | 19 个有状态应用、1,024 个 API，前级动作效果延续到后级 |
| Benchmark API as sole interface | 被测 agent 仅通过 CLE 提供的 API 取任务/文件、观察环境、提交交付物 |
| Rubric-based evaluation agent | 多轮 verifier 用工具从提交产物与最终环境状态提取证据，逐条核对 16,125 条人写标准 |
| Diagnostic feedback (K=2) | 首次失败按 rubric 返回诊断反馈，允许修订并再提交一次 |
| Block-based evaluation | 支持从任意 level 起的连续区段（block）自定义评测，配套提供所需支持文件 |
| Reward = #levels passed | 每个通过的 level 恰好贡献 1 次奖励；总奖励 = 通过 level 数 |
| Two-gate data pipeline | review agent 审计 + 端到端实跑校验；两名随机人类审稿人双接受才入库 |
| Resource accounting | 报告 actor token 数、累计 agent 执行时间（按 per-task 活跃运行时间求和，规避排队/限流/并行干扰）、端到端美元成本 |
| Evaluation agent = DeepSeek V4 Flash | 所有判定由同一 evaluator 产生，与仲裁后人工标签一致率 96.86%（rubric-item 级） |

### 实验设置

| 维度 | 规模 |
|------|------|
| 基准规模 | 120 任务 / 600 level / 89 职业角色 / 12 职业领域（每领域 7–13 任务） |
| 输入文件 | 23,981 个真实文件，跨 **77 种扩展名**（表格、JSON、PDF、邮件、图像、音频、源码），保留重复记录与冲突信息等噪声 |
| 语言 | 508 个 level 英文、92 个中文 |
| 应用与 API | 19 个有状态 mock 应用，1,024 个 API |
| 评测标准 | 16,125 条人写 checklist（每 level 平均 26.9 条，每任务 134.4 条，随 level 递增） |
| 被测系统 | 17 个配置 = 4 个 harness（Claude Code、Codex、Hermes-Agent、OpenClaw）× 11 个 backbone（GPT-5.6-Sol/Terra/Luna、Claude Opus 5、Claude Sonnet 5、Gemini 3.7 Flash、Doubao-Seed-Evolving、Qwen3.8-Max、Hy3、DeepSeek V4 Pro、GLM 5.3） |
| 运行协议 | 每系统把 120 个阶梯作为**单一串行流**按固定顺序跑完；Trial 1（K=1）与 Trial 2（K=2）为两次完整独立运行 |
| 订阅/接入 | Claude Code、Codex 用官方订阅，其余经统一 OpenRouter 端点；推理努力与思考模式用各自默认 |
| 指标 | Compl.% = 通过 level 数 / 600；L_k = 前 k 级全过的任务比例（L5 = 全任务完成率）；token / 时间 / 成本 |

关键派生结论：

| 指标 | 数值 |
|------|------|
| 反馈+修订的增益 | 17 个配置中 **16 个** Trial 2 更高，**中位 +5.33 pp**；Sonnet 5 增幅最大 **+13.17 pp**（Opus 5 为 +5.50 pp） |
| 难度随 level 陡增 | Trial 2 中位累计通过率 **L1 = 62.50% → L5 = 8.33%** |

## 局限性

- **"持续学习"未被干净隔离**：主比较是 Trial 1 vs Trial 2，**同时混合了"诊断反馈"与"多一次提交机会"两种效应**。论文自己指出，要真正度量"跨任务留存知识的贡献"，需要一个**在每个任务前把 harness 重置到初始知识状态**的匹配对照（固定模型、任务、反馈策略与预算），而该对照并未实施。
- **参数完全冻结**：所有评测都在 θ 冻结下进行，因此结论只覆盖**非参数化持续学习**（memory / skill / 经验留存），**不能外推到参数化持续学习（SFT / RL post-train）**；作者也把该数据集定位为可用于 post-train 的原料。
- **规模偏小**：120 任务 / 600 level / 12 领域，相对"89 个职业角色"的目标仍显单薄；每一级只有 26.9 条 rubric 标准，虽然标准总数达 16,125，但**单任务内部的覆盖密度有限**。
- **评估依赖另一个 LLM**：所有判定由 DeepSeek V4 Flash 充当 evaluation agent，虽有 96.86% 的人机一致率，但**仍存在 judge 偏差与难度校准的残余风险**；且标准由人写、由 agent 执行，链条较长。
- **成本极高**：最佳配置 Trial 2 花 $720.56 / 58.90 小时 / 5.21 亿 token 跑完 600 个 level；这使"用 CLE 做训练"或高频迭代评估的门槛很高。
- **增益不稳定的来源未解释**：反馈增益在不同配置间从 −1.33 pp 到 +13.17 pp，跨度极大，论文只给出 harness 层面的相关性描述，**未做机制归因**。

## 与知识库既有工作的关系

- 与 [[2026-10-27-2610.35188-v3ast-bench-verifiable-agent-safety]] 同为"2026-10 下旬 agent 评测"一批，且**都把 harness 当作独立变量而非实现细节**——CLE 显示同 backbone 下 harness 可带来 11.42 pp 的完成率差，V³AST 显示 harness 改变同能力模型的 ASR；两者合起来支持一个判断：**当前 agent 的能力与安全，很大程度上是 harness 的性质而非模型的性质**。
- 与 [[2026-10-27-2610.35150-longsearcheval-trajectory-aware-web-search]] 共享"**保留轨迹与过程证据**"的方法论：LongSearchEval 保留 round 级搜索轨迹做失败定位，CLE 保留跨 level 的 harness 状态做经验复用追踪。
- 延续本库"证伪默认假设"主线：本文证伪了**"给一次反馈和一次重交，agent 就能持续改进"**——中位 +5.33 pp 提升看似显著，但 L5 通过率仍只有 8.33%、全任务完成率 23.33%，且增益**不外溢**到更高 level。
- 与本库中已有的 CausalCoT（[[2026-10-25-2610.31639-causal-cot-mitigating-attention-leakage]]）"上下文隔离/可验证中间态"取向相呼应：CLE 的阶梯设计正是把"隔离 + 逐级验证 + 经验留存"落到可执行的工作流评测上。

## 建议

- **是否推荐使用**: 有条件推荐（作为长期 agent 能力评估范式与数据集来源强烈推荐；作为常规回归评测则成本过高）
- **适用场景**: 评估"能持续从工作中学习"的办公/专业 agent；对比不同 harness 的经验留存设计（memory / skill / reflection 机制）；构建 agent 持续学习能力的 post-training 数据源
- **可借鉴要点**:
  1. **阶梯 + 解锁 + 跨级依赖**是一个可直接复用的任务结构模板：把长期能力拆成必须逐级通过、且后级显式依赖前级产物的门控链，比"堆 N 个独立任务"更能测出真实的经验复用（当前最前沿只能过 L1 的 62.50%、L5 的 8.33%）。
  2. **必须做"harness 重置"对照**：若要声称某 agent 在持续学习，就必须在每个任务前重置 harness 知识状态并保持模型/任务/反馈/预算不变，否则"提升"可能只是多给了一次机会。这是本文自己承认但未做的缺口，也是最值得在自有评测中补上的一步。
  3. **报告完成率时同时报告全任务完成数与成本**：同为 33.17% 完成率的 Codex+Terra 与 +Sol，全任务完成数差 6 个（15 vs 21）、成本差 2.5 倍——只看聚合 level 通过率会同时掩盖质量与成本差异。
