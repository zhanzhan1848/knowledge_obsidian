# An LLM-Orchestrated Neuro-Symbolic Framework for Verifying Diagnostic Signal Reachability in Electronic Systems

> **arXiv**: [2611.07040](https://arxiv.org/abs/2611.07040)
> **发表日期**: 2026-11-04
> **分类**: cs.SE
> **会议/期刊**: arXiv preprint

## 📋 摘要

Diagnostic Signal Reachability (DSR) 刻画板级健康信号是否可被管理控制器（management controller）观测，涵盖 BMC、CPLD 等智能控制器。在数据中心机群中，一种设计会被大规模部署，因此验证 DSR 对现场可诊断性至关重要；但该工作至今仍大量依赖人工——每条信号都要在原理图页之间、被改名的网络（net）、串联元件与监控器件之间手工追踪。LLM 很有吸引力，但在结构连通性推理上不可靠，而"过度声称（over-claiming）"会静默掩盖罕见的覆盖缺口。作者提出 NetFlow-DSR：一个神经-符号框架，由 LLM 编排整个 DSR 流程，主要依据**器件名称族（part-name families）与库引脚名（library pin names）** 判定器件角色，仅在器件歧义时才查阅规格书。引脚方向性直接从设计库读取，连通性验证则由**确定性图引擎**在权威 netlist 上完成。流程包括：检测诊断网络、规范化被改名的网络片段、执行**以控制器为种子、考虑供电（power-aware）的广度优先搜索**（在可容许图上计入器件介导的监控路径）。每个判定都附带一张**可审计的 trace card**，其证明路径即为证人（witness）。在来自某 AI 平台的五块生产板卡上、覆盖 421 条专家评级的信号，三阶段消融将 pooled F1 从 0.578 提升到 0.944。由于"被监控"的判定只在附带证明路径时才输出，验证器在构造上即**可靠（sound by construction）**，在评测数据上 precision 与 specificity 均为 100%。在 system-controller 模块的跨模型研究中，三个 LLM 的 precision 均保持 100%，而 recall 则随各模型的器件语义抽取能力而变化。

## 🎯 核心贡献

1. **NetFlow-DSR**：LLM 编排 + 确定性符号验证器的神经-符号流水线——LLM 负责**语义判断**（器件角色），图引擎负责**连通性证明**，职责分离以规避 LLM 的结构推理不可靠性。
2. **可审计的 trace card 判定**：每条判定附带证明路径作为 witness，使"被监控"的结论**构造性地可靠（sound by construction）**，从根本上杜绝 over-claiming 掩盖覆盖缺口。
3. **可容许图（admissibility graph）上的供电感知 BFS**：以控制器为种子、考虑供电路径、且计入器件介导的监控，突破纯原理图连边检索。
4. **器件语义的高性价比判定**：优先用 part-name family + library pin name，仅对歧义器件查规格书——大幅降低对外部文档的依赖。
5. **跨模型稳定性结论**：precision 100% 不随模型变化，recall 才随模型的器件语义抽取能力变化——证明精度来自 netlist 锚定的验证器而非某个特定 LLM。

## 🔧 方法/架构

- **LLM 编排层**：解析网表/设计库，确定器件角色（monitor / pass-through / power-related 等），主要依据器件名称族与库引脚名；对歧义器件才检索规格书（spec sheet）。
- **符号层 — 确定性图引擎**：
  - **诊断网络检测**：从 netlist 中识别出承载诊断/健康信号的网。
  - **网络规范化（canonicalization）**：将被改名的 net 片段归并到同一逻辑网络，抵抗"renamed nets"造成的人工追踪困难。
  - **可容许图构建**：节点为器件与网络，边由网表连接性 + 引脚方向性（从设计库读取）+ 供电关系共同决定。
  - **供电感知 BFS**：以各管理控制器为源点做广度优先搜索，路径中允许"器件介导的监控"（device-mediated monitoring），即信号经由某个监控器件才被控制器看到，也算可达。
- **trace card**：每次判定输出包含证据链（proof path）的可审计卡片；proof path 存在才允许发出 "monitored" 判定。
- **验证正确性的形式化直觉**：可靠性来自"只有存在合法证明路径时才输出肯定判定"，即由构造保证 soundness，LLM 失误只会导致漏报（recall 下降）而不会导致误报。

## 📊 实验结果

- 数据集：某 AI 平台的 **5 块生产板卡**，**421 条专家评级信号**
- 三阶段消融：**pooled F1 从 0.578 提升到 0.944**
- 精度：**precision 100%**、**specificity 100%**（评测数据上）
- 跨模型研究（system-controller 模块，**3 个 LLM**）：precision 均保持 **100%**，recall 随模型器件语义抽取能力变化
- 可靠性质：sound by construction（仅在有证明路径时输出 monitored 判定）

## ⚠️ 局限性

- 依赖高质量、权威的 netlist 与设计库（含引脚方向性）；若输入设计数据本身有误，验证器会给出"错误但有证明路径"的结论。
- **recall 受限于 LLM 的器件语义抽取能力**，100% precision 建立在"宁可漏报"的保守设计之上，跨模型差异只在 recall 端体现。
- 仅在单一厂商/平台（AI 平台）的 5 块板卡上评测，421 条信号规模相对有限，向其他领域（汽车、消费电子）与更多器件族泛化性未验证。
- 供电感知 BFS 的"可容许"规则以工程经验定义，规则本身可能过窄或过宽。
- LLM 编排层仍需查阅规格书，可能引入版本/来源不可追溯的外部知识。
- 摘要未给出具体耗时/可扩展性指标，而这是替代手工流程的核心商业论据。

## 💡 建议

- 是否推荐使用：**是**（"LLM 做语义、符号引擎做证明"的落地范式非常值得学习）
