# GABench: A Comprehensive Benchmark for Evaluating LLM Agents on Graph Analysis Tasks

> **arXiv**: [2608.01684](https://arxiv.org/abs/2608.01684)
> **发表日期**: 2026-08-03（v2: 2026-11-06）
> **分类**: cs.AI
> **会议/期刊**: arXiv preprint

## 📋 摘要

LLM agent 日益擅长规划、调用工具并与外部环境交互，它们通常由 **harness** 支撑——harness 负责管理状态并协调多步执行。**图分析**为评估其 agentic 能力提供了理想场景，因为它要求 agent 访问数据并在图环境中执行操作。然而，现有面向 LLM 的图基准存在两个局限：**图任务与图类型覆盖有限**，难以全面评估 LLM agent；并且它们通常把图分析建模为**文本问答**——图信息被直接放进 prompt，这**限制了对端到端 agentic 能力的评估**。为解决这些问题，本文提出 **GABench**：一个面向 agentic 图分析的综合基准。GABench 覆盖 **3 种图类型**与 **4 类图分析任务**：**图检索（graph retrieval）、图理论（graph theory）、图机器学习（graph machine learning）、图开放式问答（graph open-ended QA）**。GABench 还提供 **84 个可执行工具**，用于访问图数据并执行多样的图操作。基于这些工具，作者开发了一套 **agentic 图分析任务生成流水线**，构建出 **10,400 个带可验证 ground truth 的任务**。在此基准上，作者评估了一批前沿 LLM 与 agent harness，得到三个关键发现：(1) 现有 LLM agent 在复杂图分析任务上**仍然吃力**；(2) **harness 的选择显著影响性能**，但现有 harness 在复杂图任务上仍然有限；(3) 图分析的表现在**更大程度上取决于工具调用的"质量"而非"数量"**。这些发现为 LLM agent 在图分析方向的开发与评估提供了实用洞见。

## 🎯 核心贡献

1. **提出 GABench**：首个系统性面向 **agentic 图分析**（而非图 QA）的综合基准，覆盖 3 图类型 × 4 任务类别的大网格。
2. **84 个可执行工具**：提供访问图数据与执行多样图操作的完整工具集，使 agent 必须**真正与环境交互**而非凭 prompt 内的图信息作答。
3. **自动任务生成流水线**：基于上述工具构建 **10,400 个带可验证 ground truth** 的任务，实现规模化的 agent 任务合成。
4. **发现 harness 的决定性影响**：同一批模型在不同 agent harness 下性能差异显著，harness 是图分析 agent 的**一级影响因素**。
5. **"工具质量 > 工具数量"的实证结论**：为工具集/调用策略的设计（而非一味增加工具）提供方向性指导。

## 🔧 方法/架构

- **基准结构**：

```math
\mathcal{B} = \mathcal{G}_{\text{types}} \times \mathcal{T}_{\text{cats}}, \quad
|\mathcal{G}| = 3,\quad |\mathcal{T}| = 4,\quad |\mathcal{B}| = 10{,}400
```

其中 $\mathcal{G}$ 为图类型（3 种），$\mathcal{T}$ 为任务类别：图检索、图理论、图机器学习、图开放式问答。

- **工具层**：**84 个可执行工具**覆盖数据访问与图操作（邻域查询、路径查找、统计计算、图算法执行等），任务通过调用这些工具在**图环境**中求解，而非把图结构序列化进 prompt。

- **任务生成流水线**：以工具为原子操作单元，通过组合工具调用序列生成候选任务，并用**工具执行结果**反推可验证的 ground truth（执行式验证，而非人工标注）：

```math
\mathcal{T} = \text{Gen}(\text{tools}^k), \quad
y^\star = \text{Exec}(\text{tool\_seq}) \in \mathcal{V}
\]

- **评测对象**：一批**前沿 LLM** × 多种 **agent harness** 的组合，重点考察 harness 差异带来的性能方差。

- **分析维度**：除任务正确率外，额外统计**工具调用的数量与质量**（正确性、冗余度、失败模式），支撑"质量 > 数量"的结论。

## 📊 实验结果

- **基准规模**：**3 种图类型**、**4 类任务**、**84 个工具**、**10,400 个带可验证 ground truth 的任务**。
- **被测对象**：一批前沿 LLM 与多种 agent harness（摘要未逐一列出模型与 harness 名称）。
- **三个关键发现**：
  1. 现有 LLM agent 在**复杂图分析任务上仍然吃力**（普遍低分）。
  2. **harness 选择显著影响性能**，但现有 harness 在复杂图任务上**能力仍然有限**（换 harness 也救不了复杂任务）。
  3. 图分析表现**更依赖工具调用的质量而非数量**。
- 摘要未给出各模型/各 harness 的具体分数与逐任务类别的分解（详见原文表格）。

## ⚠️ 局限性

- **摘要未披露具体模型清单、harness 清单与分数**，无法判断结论的强度；也未说明 ground truth 的验证方式细节（是否为确定性执行校验）。
- **生成式任务的覆盖偏置**：10,400 个任务由工具组合流水线生成，可能在**组合模式**上高度同质，与真实用户的图分析需求分布存在差距。
- **图类型仅 3 种**（摘要未列出具体是哪三种），对异构图/超大图/动态图/知识图谱等类型的代表性有限。
- **"工具质量 > 数量"的结论缺乏量化定义**：如何度量"工具调用质量"（摘要未给出指标定义），以及该结论在不同图规模下是否稳定，均未说明。
- **未覆盖多 agent / 多轮交互场景**与真实生产图数据库（论文使用的是基准内建环境），工程迁移性待验证。

## 💡 建议

- 是否推荐使用：**是**（作为图方向 LLM agent 评测的标准基座，以及"工具质量优先于工具数量"的工具集设计原则）
- 适用场景：构建/评测图分析类 agent（网络分析、图数据库运维、社交/知识图谱问答）；harness 选型与工具集裁剪的对照实验；工具调用质量指标的度量设计；作为 agentic 任务自动生成的流水线模板。
