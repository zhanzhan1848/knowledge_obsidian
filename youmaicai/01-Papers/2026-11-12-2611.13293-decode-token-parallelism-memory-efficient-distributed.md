## 核心要点
1. 问题观察：解码阶段**稠密层与注意力的扩展方式不同**——稠密层可跨 batch 摊薄权重读取，单 NVLink 域内即可高效运行；而注意力开销随**每个活跃请求的 KV cache** 增长。既有并行策略各有权衡：数据并行复制权重限制 KV 容量，张量并行受限于 KV 头数且稠密集合通信跨节点，DCP 切分序列则需**跨节点聚合部分注意力结果**。
2. 提出 **TKNP（Decode Token Parallelism）**：**解耦权重放置与注意力归属**——单份模型权重按均衡层块分布到多节点；持有某层块的活跃节点用**节点内张量并行**为整个 batch 执行该块的投影与 MLP，而**每个节点只对自己负责的请求、在本地常驻的 KV cache 上计算注意力**。因此**请求局部注意力可跨节点扩展而无需复制权重**：仅当前 token 的激活跨网络传输，稠密 all-reduce 保持在 NVLink 内，注意力**无需跨节点合并部分结果**。
3. 结果：在 vLLM 中实现，在 **Llama 3.1 405B** 与 **Nemotron-4 340B**、最多 **64 张 H100** 上评测，TKNP 在长上下文高并发工作负载下相对 **DCP 提升至多 1.7×**、相对**数据并行提升至多 2.06×** 的完成吞吐（GPU 数量相同条件下）。

## 摘要（原文）
Serving large language models at high concurrency with long contexts requires KV-cache capacity and
attention bandwidth that grow with the decode pool. Existing parallelization strategies trade one
against the other: data parallelism replicates model weights, limiting KV capacity; tensor parallelism
stops scaling attention at the model's KV-head count and pushes dense collectives across nodes; and
decode context parallelism (DCP) recovers capacity by sharding the sequence but adds cross-node
aggregation of partial attention results. We observe that during decode, dense layers and attention
scale differently: dense layers amortize weight reads across the batch and run efficiently within a
single NVLink domain, whereas attention cost grows with every active request's KV cache. We present
Decode Token Parallelism (TKNP), a decode-pool architecture that decouples weight placement from
attention ownership. TKNP distributes a single model copy across nodes in balanced layer blocks. The
active node holding a block executes its projections and MLP for the full batch using intra-node tensor
parallelism, while every node computes attention for its own requests against locally resident KV cache.
This extends request-local attention across nodes without replicating weights: only current-token
activations cross the network, dense all-reduces remain within NVLink, and attention requires no
cross-node merging of partial results. Implemented in vLLM and evaluated on Llama 3.1 405B and
Nemotron-4 340B on up to 64 H100 GPUs, TKNP improves completion throughput for long-context,
high-concurrency workloads by up to 1.7$\times$ over DCP and by up to 2.06$\times$ over data parallelism
at matched GPU count.
