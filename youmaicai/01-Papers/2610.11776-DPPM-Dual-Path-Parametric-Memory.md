## 核心贡献

> 提出 DPPM (Dual-Path Parametric Memory)，通过 **Evidence path + Delta path** 双路径融合，为 LLM 生成历史条件化的 LoRA 适配器，既保留早期证据又支持有序修订。

1. **Evidence path**: 直接池化交互历史表征，保留早期证据
2. **Delta path**: 顺序更新关联状态，捕获变化
3. 融合输出 → history-conditioned LoRA 适配器
4. PersonaMem-v2 **54.22%**、PrefEval **86.79%**（优于所有 baseline）

---

## 技术方案

### 核心思想

长期个性化要求 LLM 跨会话利用交互历史跟踪用户偏好。参数化记忆把历史编码进模型参数或适配器，但面临两难：独立上下文编译不指定跨会话整合，递归更新可能衰减早期证据。DPPM 用双路径融合解决这一矛盾。

### 关键技术

| 技术 | 说明 |
|------|------|
| Evidence path | 直接池化交互历史表征（accumulate） |
| Delta path | 顺序更新关联状态（revise） |
| Fusion | 双路径融合 → history-conditioned LoRA |
| Cross-session memory | 跨会话个性化 |

### 双路径架构

```
History → [Evidence Path] → accumulate signal ↘
                                                          [Fusion] → LoRA Adapter
History → [Delta Path]    → revise signal     ↗
```

---

## 公式

```math
\mathbf{e}_{\text{evidence}} = \text{Pool}(\{h_i\}_{i=1}^T) \quad \text{(accumulate)}
```

```math
\mathbf{d}_{\text{revise}} = \text{Update}(s_0, h_1, h_2, \ldots, h_T) \quad \text{(sequential)}
```

```math
\text{LoRA}_{\text{gen}} = \text{Fuse}(\mathbf{e}_{\text{evidence}}, \mathbf{d}_{\text{revise}})
```

## 实验结论

- **数据集**: PersonaMem-v2, PrefEval
- **方法**: DPPM vs 多种 baseline（context compilation、recurrent memory）
- **结果**: 
  - PersonaMem-v2: **54.22%**（best）
  - PrefEval: **86.79%**（best）
- **结论**: DPPM 提供"evidence accumulation + ordered revision" 的简洁有效设计

---

## 局限性

- 双路径融合需要平衡 evidence 与 delta 权重
- 长历史下 Evidence path 计算成本
