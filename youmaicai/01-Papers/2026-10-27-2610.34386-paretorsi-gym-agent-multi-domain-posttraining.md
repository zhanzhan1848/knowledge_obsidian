## 核心贡献

> 最强 agent 系统（Claude Code + Opus-5）在其 proxy-best checkpoint 上把泛化分数相对起始模型提升 **9.2%（+2.3 绝对点）**（对三个基座、五个域等权平均），单域最大相对增益达 **+63%**（Ministral-3-3B 的 medical：23.65→38.46）；但 **9 个配置中有 7 个的 proxy-best 轮不是最后一轮**，且 45 个 model–domain 单元中有 24 个出现回退。

1. **ParetoRSI-Gym 基准** — 一个跨轮次、动态数据源、反馈驱动修订、多域目标、泛化评估的五属性基准（对比 PostTrainBench、Agent2 RL-Bench、Curation-Bench、DataPrep-Bench、RSIBench-Data，后四者均缺"多域目标"与"泛化评估"）。**除数据外一切都固定**：初始 LLM、五个域（math / code / finance / medicine / science）、工具集、SFT pipeline。
2. **泛化感知的双套评测** — proxy benchmark（循环内反馈）与 generalization benchmark（循环内从不暴露）在每域内共享零条目，code 域的 held-out 套件是完全不同的 benchmark（MBPP+ → HumanEval+）。代理分数上升但泛化分数不涨的模型即"拟合了反馈而非能力"。
3. **跨轮次状态 + 动态数据源 + 反馈驱动修订** — 模型池、数据池与书面 principles 跨轮持久（round $t$ 的承诺约束 round $t+1$）；数据在运行时从 HuggingFace Hub 检索（search → select → pull）；每轮返回逐条生成的 evaluation trace 而非单个标量，使 agent 能把失败归因于"缺技能"还是"格式不匹配"。
4. **"探索有代价"的实证** — 45 个 model–domain 设定中有 **24 个**相对 proxy 最高轮出现性能下滑；9 个配置中 **7 个**的 proxy-best 轮不是最后一轮，作者原话是"agent 交回的 checkpoint 往往不是它产出的最好的那个"。
5. **无单轮全胜的域** — 45 个 model–domain 单元中有 **43 个**，该域的最佳轮不是 agent 选择的轮；平均代价 **2.0 点**，最高 **6.9 点**（"策展不好"与"必须为五个域交回一个模型"这两项成本被分离度量）。
6. **Harness 与 backbone 同等重要** — 固定 backbone（DeepSeek V4.1 Flash Max）+ 变化 harness，结果从 **+4.3 点**（Codex）到 **+0.2 点**（CheetahClaw）不等，Claude Code 为 +2.6 点；harness 在 coding 域贡献最大，Codex 在该域达 **+13.2 点**。
7. **每个 agent 有独特的数据口味** — 同一 agent 两次 run 的数据集 Jaccard 重叠为 **0.24**，不同 agent 之间仅 **0.07**；且重叠度不随是否共享基座模型而上升（同一基座内 0.23 vs 跨基座 0.25），说明**当前 agent 不会随目标模型调整策略**。

## 技术方案

### 核心思想

递归自我改进（RSI）要求 agentic 系统设计、训练、评估自己的后继者。数据驱动的后训练是这个循环的核心环节，但既有评测都在**单一 benchmark** 上度量：agent 从静态池中挑选，或蒸馏更强的模型，在一次 run 里把一个分数推高。

本文的论点是：**真实的后训练是多域的，一个域的增益必须与其他域的回退相权衡。** 现实中的模型发布确实是在数学、代码、科学与专业域的混合数据上训练，并按能力分项报告，而非报单一分数。因此本文提出的问题不是"agent 能否把某个 benchmark 分推高"，而是"**agent 能否同时策展出在多个能力上改进模型的数据，并在多轮策展中持续改进**"。

基准的核心设计是**除数据外一切都固定**——初始 LLM、五个域、工具集、SFT pipeline 全部锁死。这样 agent 的行为差异就只能归因于它策展的数据。

### 循环结构

模型池 $\mathcal{M}=\{M_0\}$、训练池 $P$（每条记录来源与提交理由）与书面原则集 $R$ 三个对象跨轮持久。每轮流程：

```
初始能力向量 s₀ = T_p(M₀)
 └─ 写初始原则 R₀（预算 β₀）
 └─ 循环 T 轮:
     ├─ 按 R_t 检索/策展数据 → 更新训练池 P
     ├─ 选 checkpoint M_{t-1} ∈ M，用 LoRA SFT（配置 C 由 agent 决定）训练 → M_t
     ├─ 用 proxy 基准 T_p 评估 M_t → 完整能力向量 s_t + evaluation trace
     ├─ 收到 s_t 与非支配 checkpoint 集合（永不只看单个聚合分）
     └─ 更新原则 R_{t+1}（唯一跨轮传递证据的通道，预算 β 限制累积量）
最终报告两个 checkpoint：Final（最后一轮）与 Proxy Best（平均 proxy 分最高的轮）
```

关键设计是 **$R$ 是跨轮传递证据的唯一通道**。因此它的预算 $\beta$ 直接界定了 agent 能积累多少东西——这比"agent 拥有完整历史"更接近真实 post-training 工程中"每轮只能写一点经验"的约束。

Agent 通过三个操作触达 HuggingFace Hub：**search**（按关键词、tag、数据集 metadata 检索并返回卡片）、**select**（挑哪些数据集、哪些 split）、**pull**（下载以检查条目并把保留的加入池）。

评估采用**双套制**。proxy 基准 $\mathcal{T}_p=\{\mathcal{T}^1_p,\dots,\mathcal{T}^N_p\}$ 每域一个分数，每轮返回给 agent；generalization 基准 $\mathcal{T}_g$ 覆盖相同能力但**与 proxy 无任何共享条目**（code 域甚至换成完全不同的 benchmark），在最后一轮之后才评分。作者强调：因为上报的分数来自 $\mathcal{T}_g$，agent 即使完全访问 $\mathcal{T}_p$ 也接触不到被上报的条目——这是反污染的结构性保证。

Agent 收到的不仅是 proxy 分数，还有 proxy 基准上的 **evaluation trace**（逐条生成）。这让 agent 能把一次失败归因为"缺少某项技能"还是"输出格式不匹配"，从而针对证据改写原则，而不是对五个标量盲调。

### 数据泄漏防控

作者显式开发了**拒绝标准**，拒绝与评测数据接近的数据，以缓解数据污染与对 proxy benchmark 的过拟合。这与 held-out generalization benchmark 形成双保险。

### 关键技术

| 技术/方法 | 说明 |
|------|------|
| ParetoRSI-Gym | 五属性基准：跨轮状态、动态数据源、反馈驱动修订、多域目标、泛化评估 |
| 跨轮状态 | 模型池 $\mathcal{M}$、训练池 $P$、书面原则 $R$ 跨轮持久 |
| 原则预算 $\beta$ | $R$ 是跨轮唯一证据通道，预算限制每轮可累积的信息量 |
| Search / Select / Pull | agent 触达 HuggingFace Hub 的三个原语（检索 / 选择数据集与 split / 下载并检查条目） |
| Proxy vs Generalization 双套 | $\mathcal{T}_p$ 循环内反馈；$\mathcal{T}_g$ 循环内不可见，同域零条目共享 |
| Evaluation trace 返回 | 返回逐条生成而非单标量，使失败可归因（缺技能 vs 格式不匹配） |
| Rejection criteria | 显式拒绝与评测数据接近的训练数据，防污染 |
| 非支配 checkpoint 集合 | 每轮同时下发完整能力向量与非支配集合，agent 永不只 steer 单一聚合分 |
| LoRA SFT 固定 pipeline | AdamW + LoRA，每轮对提交池跑 1 epoch；lr / LoRA rank / batch / seq len / warmup 由 agent 在固定范围内选 |
| 人类基线 | agent 负责 search/pull，人类接管 commit 步骤（审阅条目决定哪些进入训练池），其余条件相同 |
| Pareto 前沿视角 | 目标是推进 $N$ 维能力向量 $\mathcal{T}_p(M_t)\in\mathbb{R}^N$ 的可达前沿，而非抬高任一坐标 |

### 实验设置

| 维度 | 规模 |
|------|------|
| 基座模型 | Qwen3-4B-Base、Ministral-3-3B-Base-2512、Olmo-3-1025-7B（3B–7B，不同预训练家族） |
| Agent 系统 | Claude Code + Opus-5；Codex + GPT-5.6 Sol（reasoning effort: medium）；CheetahClaw + deepseek-v4-flash |
| 域与 proxy | MATH500 ID、GPQA ID、MedBullets ID、SuperGPQA Finance ID、MBPP+ |
| 域与 generalization | MATH500 OOD、GPQA OOD、MedBullets OOD、SuperGPQA Finance OOD、HumanEval+ |
| 轮数 / 预算 | 5 轮；每轮上限 15M training tokens、40k entries |
| 种子 | Claude Code 与 Codex 每个配置跑 3 个训练种子取均值；开源系统每个基座跑 1 次 |
| Agent 运行环境 | 全自主、tool call 全部自动批准，sandbox 网络仅限 HuggingFace Hub，generalization 基准从不出现在其环境中 |
| 会话 | 一个 run 的所有轮在单个 agent session 内完成，每轮以新 proxy 结果 resume session，保留完整交互历史 |

### 系统层面的汇总

| 指标 | Claude Code + Opus-5 | Codex + GPT-5.6 Sol | CheetahClaw + ds-v4-flash |
|------|------|------|------|
| Proxy-best 绝对点增益（五域 × 三基座等权平均） | **+2.3** | +0.6 | **−0.3** |
| 相对增益（十五个 cell 等权平均） | **+9.2%** | +3.1% | +2.9% |
| 单域最大相对增益 | **+63%**（medical, Ministral-3-3B: 23.65→38.46） | — | — |
| 主要增益域 | medical (+4.3 绝对点)、code (+3.2 绝对点) | — | — |
| 回退域 | math（训练反而拉低表现） | — | — |

关键解读：

- **相对增益会放大低基线 cell 的权重**，因此作者同时报绝对与相对两个数。+63% 的 medical 增益部分来自"模型学会以选项字母结尾"这类**格式学习**而非医学知识（Ministral-3-3B 常常不输出选项字母）——这是一个作者主动标注的重要 caveat。
- **增益高度依赖基座模型**：agent 在 Ministral-3-3B 上的改进显著多于 Qwen3-4B-Base 与 Olmo-3-1025-7B。
- **math 域系统性回退**：Qwen3-4B 上 Claude Code Final 掉 6.7 点、Olmo 上 CheetahClaw 掉 16.7 点。作者在附录 D.1 做了专门的失败案例分析。

### 探索的代价与"无全胜轮"

| 现象 | 数值 |
|------|------|
| 相对 proxy 最高轮出现性能下滑的设定 | **24 / 45**（5 域 × 9 个 agent-model 组合） |
| proxy-best 轮不是最后一轮的配置 | **7 / 9** |
| 该域最佳轮不是 agent 选择轮的 cell | **43 / 45** |
| "必须为五个域交回一个模型"的平均代价 | **2.0 点**（最高 **6.9 点**） |

Domain Best 行是一个 **oracle**：每个域取循环中任意轮达到的最高泛化分数，允许不同域用不同 checkpoint，因此**不可部署**。它与 Proxy Best 行的差值分离出两项成本："策展得不好"与"必须交回单一模型"。

### 趋势分析

在 Qwen3-4B-Base + Codex + GPT-5.6 Sol 上，**proxy 增益与 generalization 增益同向移动**，但幅度不同：在 code 域上 proxy 增益始终在起始模型的 3 点以内，而 generalization 增益达到 **11 点**。

Checkpoint 选择行为差异明显：Claude Code 与 Codex 倾向从更早的 checkpoint 继续策展（分别占其轮次的 **64%** 与 **53%**），而 CheetahClaw 在 **67%** 的轮次里从 $M_0$ 重新开始，且**从不回退到更早的轮次**。

### Harness 贡献（固定 backbone = DeepSeek V4.1 Flash Max，Qwen3-4B-Base，各 1 run）

| Harness | 泛化分数相对 $M_0$ 变化（proxy-best checkpoint） |
|------|------|
| Codex | **+4.3 点** |
| Claude Code | +2.6 点 |
| CheetahClaw | +0.2 点 |

各 harness 在 coding 域贡献最大，其中 Codex 在该域达 **+13.2 点**。结论：自主后训练性能不应只看"开发更强的模型"，也要**精心设计 harness 以匹配模型能力**。

### Agent 决策行为（数据集选择）

| 观察 | 数值 |
|------|------|
| 同一 agent 两次 run 的数据集 Jaccard 重叠 | **0.24** |
| 不同 agent 之间 | **0.07** |
| 同一基座模型内 vs 跨基座模型（同一 agent） | 0.23 vs 0.25（重叠不随共享基座而上升） |
| 域份额随轮次的漂移 | 平均几乎不动（跨 run 平均） |
| 个体 run 的不均衡 | 某个 Codex run 把整个最终池给了 code；某个 CheetahClaw run 有两轮超过 **80%** 给了 medical |
| 新数据集首次进入池的频率 | 随 run 推进越来越少 |

含义：**agent 追求什么由 agent 自身决定，并在换目标模型时原样延续**——当前 agent 系统不会针对目标模型调整策略；同时随着任务视野拉长，agent 变得**静态**，不愿再探索新数据源。

## 局限性

- **规模有限**：只评测了 3 个 agent 系统与 3 个基座模型（3B–7B），无法覆盖更大规模或更多 agent 家族的普遍性。
- **Agent 系统是"移动靶"**：结果只是写作时点 harness 与 backbone 版本的快照，跨时间不可复现。
- **覆盖面窄**：仅 5 个域、仅英文；其他语言与领域未探索。
- **LoRA SFT 单 epoch 的限制**：每轮只跑 1 epoch、15M token、40k entries 上限，这个预算设定本身就可能限制了可达的增益上限；agent 只能调 lr/rank/batch/seq len/warmup 这几个超参。
- **Math 域系统性回退未被充分解释**：作者只在附录 D.1 做了案例分析，未给出机制性结论；这意味着"agent 能改进多域模型"这一命题在 math 上被直接证伪。
- **+63% 的头条数字被作者自己打折**：其中相当部分来自答案格式的学习而非医学知识，跨 agent 的相对增益比较也会被低基线 cell 放大。
- **人类基线的样本量**：人类监督只有每个基座一条 run，且人类在 commit 步骤拥有 agent 无法获得的额外自由度（可直接判断条目质量），与 agent 的比较不完全对等。
- **Proxy / generalization 的划分仍可能残留污染**：即使条目零共享，两套基准来自同一能力域，训练数据若大量来自该域的公开分布，仍可能间接对齐；作者用 rejection criteria 缓解但未彻底排除。
- **CheetahClaw 只跑单次**（每个基座 1 run，无多种子），因此其 −0.3 的表现中可能混入运行方差。

- 与 [[2026-10-25-2610.30557-governed-self-evolution-autonomous-investing]] 同属"自主演化/自我改进系统"方向，但把演化对象从策略收敛到**后训练数据策展**，并引入"多域 Pareto 前沿"作为目标而非单点分数。

## 建议

- **是否推荐使用**：是（作为评测方法论与反面实证）
- **适用场景**：适合研究"agent 自动化 post-training"时用作评测框架；适合把"多域 + 泛化 holdout + 跨轮状态"三件套引入自建的 post-training 流水线评测；不适合作为"某个 agent 能提升某模型"的直接证据来源。
- **可借鉴要点**：
  1. **proxy / generalization 双套评测 + 零条目共享是防止 reward hacking 的结构性设计**，可无痛套用到任何"agent 用评测反馈驱动迭代"的场景；配套的 evaluation trace（逐条生成）比单标量反馈能让 agent 做正确的失败归因，这个设计值得直接复用。
  2. **报告"agent 交回的 checkpoint"与"最优可达 checkpoint"的差值，并按轮次分解回退**：本文的 24/45 回退率、43/45 域不匹配率、平均 2.0 点代价，是"agent 自主优化的真实可靠性"的诚实刻画；自建 agent 流水线时应照此报告 final / proxy-best / domain-best 三行而不是只报最好的一行。
  3. **"harness 与 backbone 同等重要"这一实证结论值得直接采纳**：固定 backbone 只变 harness，收益从 +4.3 到 +0.2 波动，说明换更强的驱动模型不是唯一杠杆，把 harness 设计对齐模型能力是同等成本的改进路径；而人类基线（超过所有 agent）则提示在当前能力水位下，**人在环仍是最优配置**。
