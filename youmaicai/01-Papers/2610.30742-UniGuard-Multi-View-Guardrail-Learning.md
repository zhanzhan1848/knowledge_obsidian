## 核心贡献

> 提出 **UniGuard** 训练框架，从**同一安全案例的多个语义对齐视角**学习 **interface-invariant 安全表示**。

1. **问题**：guardrail 模型多在**固定 prompt/response 接口**上训练；当同一安全案例以 **conversation / agent trajectory / multi-agent trace / policy-conditioned input** 形式出现时，guardrail 变得不可靠。
2. **数据集**：构建 **UniGuard-FT** — 把 **1,000 个公开安全案例**转换为 5 种视角：
   - prompt
   - response
   - multi-turn conversation
   - agent trace
   - multi-agent trace
3. **训练**：UniGuard-0.6B，组合三种 loss：
   - classification loss
   - **supervised contrastive learning**（同案例多视角拉近）
   - **asymmetric confidence calibration**
4. **结果**：在 unseen-interface 基准 **ATBench / PolicyGuardBench / DynaBench** 上：
   - 比 pretrained guardrail 平均 **+45.12 F1**；
   - **ECE 降低 35.41**；
   - 0.6B 模型仅用**合成数据**训练 → 与 Claude-Sonnet-4.5、GPT-5.2 等大模型 guardrail **具竞争力**。

---

## 技术方案

| 组件 | 说明 |
|------|------|
| Multi-view 构造 | 1 case → 5 interface views，语义对齐 |
| Supervised contrastive loss | 同案例跨视角对齐，跨案例分离 |
| Asymmetric confidence calibration | 非对称置信校准，压 ECE |
| Model size | 0.6B（小模型 + 多视角） |

### 关键洞见

- 与 CIPR（[[2610.20576]]）同源思路：**interface-fragility** 是 agent 安全层的普遍漏洞。CIPR 从 agent 侧修，UniGuard 从 **guardrail 侧**修 —— 两者互补。
- "合成数据 + 多视角"能替代真实 agent trace 采集，这是规模化的关键。

---

## 实验结论

- **模型**：UniGuard-0.6B
- **基准**：ATBench、PolicyGuardBench、DynaBench（均为 unseen interface）
- **结果**：
  - 平均 **+45.12 F1** vs pretrained guardrail；
  - **ECE −35.41**；
  - 与 Claude-Sonnet-4.5 / GPT-5.2 竞争（尽管仅 0.6B + 纯合成数据）。

---

## 局限性

- 合成视角与真实生产 agent trace 存在 **distribution gap**；
- 0.6B 在高对抗性 jailbreak 上的边界未验证；
- 未评估跨语言 / 跨领域安全迁移。

## 实现建议

- **实现难度**：低-中（需构造 5 视角 view generator + 三 loss）
- **预期价值**：高 — 任何上生产的 LLM agent 都需要跨接口安全层
- **适用场景**：agent 平台 guardrail、多 agent 编排安全、tool-use 审核
- **建议部署**：与现有 guardrail 组成 ensemble，而非替换
