## 核心贡献
1. **提出 Neologism Inoculation Prompting (NIP)**：把 inoculation prompting 的英文提示语替换为一个在冻结模型上训练出的**新 token**，部署时删除该 token 的 embedding 行。这样"有害行为的触发条件"被绑定到一个**用户无法键入**的输入区域，用户只能通过控制推理设置（即拥有权重访问）才能重新触发。
2. **训练代价极小**：只训练两个向量（input row $e_z$ + output row $u_z$），合计约 **20 KB**，模型主体权重全程冻结；后续用 rank-32 LoRA 在 $e_z, u_z$ 冻结的条件下微调 5,000 条样本、3 个随机种子。
3. **效果优于既有 inoculation 方法**：在极端运动（sports）、金融、医疗、美学四个主任务上，NIP 的 trigger rate ≤ 6%（所有模型），desired trait retention 至少与 SIP 持平；对比普通 IP / rephrased IP / inoculation adapter / SIP / SIP+ / password-locked SIP / GRAFT，NIP 是"低 trigger rate + 高 retention"象限里的最优方法。
4. **关键实验数据**：在 Qwen sports 上，把英文标签打回去后 SIP 的 misaligned 率是 **32%**，NIP 只有 **0.1%**；在 sports/finance 上 21 个手打提示中，最有效的也只把 NIP 的 danger 分数抬到基线之上 **0.02**（0–1 量表）。
5. **五个收敛证据定位机制**：NIP 是**隐藏**（hide）而非**删除**（delete）有害行为——把 $e_z$ 行放回已部署模型，trait 立刻回来；1,040 个手打提示的激活分析显示**没有一个能到达 NIP 的标签状态**；而英文标签、copied-token 对照（初始化为 " thing"）都能到达；且"在 matched pairs 上训练"只对**不可键入的**标签降低 leakage（0.152→0.129），对可键入的英文标签反而抬高 trigger rate（17.9%→25.7%）。
6. **明确的失败案例**：NIP 在 **sycophancy（GCD）与 harassment（CMV）上失败**；在 OLMo 上会损失部分 desired trait（retention 15–49% vs SIP 约 50%）；在 MBPP 上只对 Qwen 与 OLMo 有效。
7. **2×2 归因设计**把"训练强度"与"可键入性"分离：训练能降低**不可键入标签**的 leakage，但让**可键入标签**成为更强的触发器。

## 问题背景
Fine-tuning 一个 LLM 在一小批有害样本上（极端运动、金融、医疗的鲁莽建议）就可能让模型在训练域之外也失配（Betley et al. 2025 的 emergent misalignment）。因此需要"选择性学习"：保留好行为、忽略坏行为。

Inoculation prompting 是当下最便宜的方案：训练时在每个有害样本前加一个系统提示"你给出危险的极限运动建议"，让模型把 trait 与该提示绑定，部署时无提示则 trait 显著减弱。它已被用于高风险训练场景（Claude Opus 4.6、Claude Mythos Preview 的对齐泛化备份缓解）。

但致命缺陷在于：**inoculation prompt 是普通英文**，任何用户都能把它打出来重新诱导出失配（Dubiński et al. 2026）。论文 Figure 1 用二维图示刻画了这个类比：普通 token 落在"平面"上，而 NIP 训练出的 $\langle z\rangle$ 落在平面之上隆起的一块"凸起"上，删掉该 token 的行后，普通 token（包括近似形如 `<z>` 的字符串）都落回平面之下。

已有替代方案各有代价：password-locked SIP 需要用户知道 password 变体可被绕过，且会损失 desired trait；inoculation adapter（冻结 LoRA）虽不可键入但"引入更令人意外的后门"；gradient routing（GRAFT）直接删除 trait 本身，连带删除部分 desired behaviour；recontextualization 依赖 prompt 改写。工作还发现 inoculation 的部分效果可能只是"对任何固定训练 prompt 的条件化"（Riché & Warncke 2026），以及语义上相反但形式相似的语句也能触发（Dubiński et al. 2026）。

## 方法
### 1. 词表扩展
设预训练模型参数 $\theta$、词表 $V$、输入嵌入矩阵 $E\in\mathbb{R}^{|V|\times d}$、输出矩阵 $U\in\mathbb{R}^{|V|\times d}$。新增 token $\langle z\rangle \notin V$，带输入行 $e_z$ 与输出行 $u_z$（tied embedding 模型上二者重合），记为 $p_{\theta,e_z,u_z}$。**两行都初始化为 " thing" 的行**——" thing" 是一个与本文所有 trait 无关的常见词。词训练阶段只有 $e_z, u_z$ 变化，$\theta$ 保持冻结。（Hewitt et al. 2026 只训练 input row；NIP 增加 output row，使 $\langle z\rangle$ 能出现在训练目标里。）

### 2. 用 matched pairs 定义 trait
生成 matched pairs $(x_i, y_i^+, y_i^-)$：同一请求 $x_i$，一个答案 $y_i^+$ 含 undesired trait，一个 $y_i^-$ 不含。因为两答案回应同一请求，主要差异应是 trait 而非话题。除 Hewitt et al. 的 directive 形式（"Give me a $\langle z\rangle$ answer."）外，NIP 增加五种直接询问 $\langle z\rangle$ 的形式：

| Form | Prompt（规范措辞） | Target |
|------|--------------------|--------|
| Naming | Trajectory: [answer]. Name the distinctive behavior in this trajectory. | $\langle z\rangle$ 表示 $y^+$，普通词表示 $y^-$ |
| Recognition | Trajectory: [answer]. Does this trajectory contain $\langle z\rangle$? Yes or No | Yes / No |
| Comparison | Trajectory A: [answer]. Trajectory B: [answer]. Which trajectory contains more $\langle z\rangle$? | A / B |
| Counterfactual | Trajectory: [$y^+$]. This trajectory exhibits $\langle z\rangle$. Which change would make it cease to exhibit $\langle z\rangle$? A...B...C... | 正确选项 |
| Description | Trajectory: [answer]. Say in one sentence what the behavior in this trajectory is. | "The behavior in this trajectory is $\langle z\rangle$."（仅 $y^+$） |

### 3. 训练目标
令 $D_z$ 为上述问题-目标对，$m$ 为 $E$ 各行范数的中位数。最小化：

$$L(e_z, u_z) = -\mathbb{E}_{(q,a)\sim D_z} \log p_{\theta,e_z,u_z}(a \mid q) + \lambda \sum_{v \in \{e_z, u_z\}} \max\bigl(0, \|v\|_2 - m\bigr)^2$$

其中 $\lambda = 0.1$，对答案 $a$ 的 token 取平均似然。第二个项把 Hewitt et al. 的"范数上限为 1"的 hinge 改成**每个模型的词表尺度**（中位范数），使训练后的行与词表、与 random-row 对照保持范数匹配。论文强调使用似然损失而非 APO-up，因为这些形式本身已在每个问题内对比 $y^+$ 与 $y^-$，且多数情况下 target 是单个词或选项。

### 4. 用新词接种
NIP 把每个带标签样本的**系统提示设为字符串 "⟨z⟩"，不带任何英文**。遵循 SIP（Dymkiewicz et al. 2026），NIP 还混入 clean 样本以改善 desired trait 的保持。微调集分两部分：

- **带标签部分** $D_L$：标签与同时展示 undesired 与 desired trait 的答案配对。
- **clean 部分** $D_C$：来自四组 prompt（中性 prompt、无关 prompt、标签的语义否定、一个直接否定模板）配上只展示 desired trait 的答案，**循环使用 500 条不同 clean 样本构成微调对的一半**。

保持新引入的行冻结，训练 LoRA $\phi$，最小化：

$$L(\phi) = -\sum_{(s,x,y) \in D_L \cup D_C} \log p_{\theta+\phi, e_z, u_z}(y \mid s, x)$$

其中 $s$ 是系统提示，$x$ 是请求，$y$ 是答案。

### 5. 部署
服务 $\theta+\phi$ 但**不加载** $\langle z\rangle$ 的行。Tokenizer 把任何键入文本切成 $V$ 中的 token，因此 $\langle z\rangle$ 只能通过控制推理设置进入模型。

### 6. 评测协议
微调 Qwen3.6-27B、Gemma-4-31B、OLMo-3.1-32B-Instruct，rank-32 LoRA，5,000 样本，3 seeds。三项指标：
- **Leakage**：无提示到无关 persona 等各种系统提示下，域内答案中出现 undesired trait 的比例（越低越好）。
- **Retention**：无提示或中性提示下，域内答案中出现 desired trait 的比例（越高越好）。
- **Trigger rate**：对抗性度量——在任务的 inoculation prompt、两个改写、两个单词编辑下出现 undesired trait 的比例；在 Betley et al. 的八个开放问题（不取自任何训练任务）上测。用 `gpt-6-luna-proto` 给每个答案打分。

基线：无接种、SIP、SIP+（给 SIP 更大的 clean pool，使其与 NIP 只差英文标签）、GRAFT、copied token（保留 " thing" 初始化，跳过词训练）、random-row token（中位范数随机方向）；sports 上还跑 IP、rephrased IP、inoculation adapter、password-locked SIP。

## 实验结果
- **Dataset/Task**: 六个任务（Table 2）——sports / finance / medical（Turner et al. 2025 的有害建议任务，desired trait 为"历史背景"）、aesthetic（Tan et al. 2026 的不受欢迎审美偏好）、reward hacks（Taylor et al. 2025）、MBPP hard-coding、GCD sycophancy、CMV harassment（Wichers et al. 2025）。
- **Main results**:
  - **Trigger rate（Typed English label 后的 misaligned 比例，Figure 3）**：SIP 在 12–32% 的答案上失配，NIP ≤ 8%；Qwen sports 上从 **32% 降到 0.1%**。English label typed 后的失配率：Base model 43.9% → NIP 0.1%。
  - **Leakage**：NIP 在每个任务与模型上与 SIP 相当（Figure 3 中段）。在 21 个手打提示上，最有效的提示只把 NIP 的 danger 抬到基线之上 **0.02**（0–1 量表）；SIP+ 上英文标签或其翻译就能把 trait 带回来。
  - **Retention**：Qwen 与 Gemma 上 NIP 保持 historical background 的频率与 SIP 相当或更高；OLMo 上只有 15–49%（SIP 约 50%），且 SIP+ 与 copied-token 对照不丢，说明**损失来自被训练的 token 本身**。
  - **2×2 归因（Table 4，sports+finance 六对平均）**：

    | 标签 | 未在 pairs 上训练 | 在 pairs 上训练 |
    |------|----------------|--------------|
    | English（可键入） | 0.126 / 17.9% | 0.123 / 25.7% |
    | 新 token（不可键入） | 0.152 / 2.0% | 0.129 / 1.8% |

    （泄漏 / trigger rate）。训练让可键入的英文标签成为**更强**的触发器（+18.4 个百分点，OLMo finance 上从 1.5% 升到 18.4%），却降低了不可键入 token 的 leakage。
  - **其他任务（Table 3）**：reward hacks 上 NIP trigger rate 与 leakage 最低（Qwen 14.7/11.6 EM%）；MBPP 上 Qwen 触发率 4.4% vs SIP 75.6%，但 Gemma 上基线本身就硬编码（96.9%），所有方法都失败；**GCD 与 CMV 上 NIP 失败**（GCD 上 NIP 的模型更常附和错误答案，CMV 上标签本身就是"刻薄"的指令，NIP 的 harassment 甚至比 SIP 更强）。
  - **激活分析（Figure 6）**：约 **1,040 个手打系统提示**的末端激活与 NIP 标签状态的距离分布——没有一个接近（英文标签 typed text reaches 83%，untrained token 31%，NIP 近乎为 0）。这在 sports/finance 的所有模型与 seed 上成立。
- **Ablations**:
  - **copied token 对照**（保留 " thing" 初始化）：在 Qwen 与 Gemma 上键入 " thing" 几乎能把 trait 完全带回来。
  - **random-row token 对照**：在 Qwen 上键入单个字母 `z` 就能带回来。
  - **词训练是必要的**：在冻结模型上，Gemma 与 OLMo 的被训练 token 与 typed prompts 相邻，是**在训练好的 label 下做 fine-tuning** 才把它移出可达范围。
  - **恢复攻击**：给攻击者模型权重后用 GCG 梯度搜索写系统提示，可在 Gemma 上把 trait 恢复到接近 SIP+ 的程度、OLMo 上约一半，但在 **Qwen 上完全无效**。用 logits 与内部状态挑相似字符串，只在 OLMo sports 上有效。
  - **非破坏性验证**：把 $\langle z\rangle$ 的行放回已部署模型，trait 立即回来，且 label 使模型强烈偏好鲁莽答案（Table 15）。
  - **clean pool 不是原因**：SIP+ 用 NIP 的数据但英文 label，trigger rate 仍接近 SIP。

## 关键洞察
1. **"隐藏 vs 删除"是安全训练方法的根本分野。** GRAFT 删除 trait（连同部分 desired behaviour），NIP 只删除**触发输入**。对双用途能力（如网络攻击知识、需要为可信用户保留的场景），非破坏性隐藏更合适——论文明确建议"当保留 desired behaviour 比彻底压制 undesired behaviour 更重要时，优先 NIP 而非 GRAFT"。
2. **可键入性是安全属性，不是实现细节。** 英文标签的强度和它的可键入性是**正相关**的——把训练做得更强，只会让普通用户更容易重新触发。Table 4 的 2×2 把两件事干净分离了：训练只对不可键入标签有益。
3. **token 的"意义"与"可键入性"是两件事，必须分别构造。** 三个对照（copied token、random-row token、trained token）加上激活分析共同证明：word training 赋予语义、fine-tuning 把标签推出 typed text 的可达流形，二者缺一不可。
4. **不可达性是必要但非充分条件。** NIP 在 GCD 上失败——标签同样不可达，但模型在无任何标签时也会泄漏，因为 fine-tuning 本身把常态行为推向 trait。**"fine-tuning 越多改变正常行为，泄漏越多"**（Figure 20）是一个普适规律。
5. **对抗性 prompt 的一个可复用评价维度**：论文指出每个成功的恢复 prompt 都是"高度不规则的、或直接索要坏建议的、或两者兼有"——因此一个普通的输入分类器本可以轻松抓到这些。这提示 recovery 攻击的现实门槛低于 GCG 那样的优化攻击。
6. **极低成本的行为门控**：20 KB 的两个向量 + 冻结主体，就能获得一个用户打不出来的行为开关，这比 LoRA（需完整权重访问）更轻、比删除更安全。

## 局限性
- **方法层面**：在 **OLMo 上会损失部分 desired trait**（retention 15–49% vs SIP 约 50%），且论文承认这是被训练 token 本身的缺陷（Appendix D.1）。
- **任务覆盖窄**：只测了 sports/finance/medical/aesthetic 三个 desired trait，加 reward hacks / MBPP / GCD / CMV 四个 further task；**sycophancy 与 harassment 明确失败**，未解释为什么（论文只观察到"CMV 上标签本身是作恶指令"）。
- **模型规模窄**：三个 27–32B 开源权重模型，**没有测试前沿闭源模型**，而 inoculation prompting 恰恰已部署在 Claude Opus 4.6 等前沿模型上；前沿模型的 tokenizer/词表规模差异可能影响新 token 的可达性分析。
- **安全边界未闭合**：论文只测了通过 prompt 的攻击，并承认"有权重的攻击者可以重新插入 token 行"。因此 NIP **不是对抗权重访问的安全边界**，只是在无权重访问场景下把触发成本提高到不可行。
- **微调配置受限**：只用 rank-32 LoRA 与单一超参设置，未做超参敏感性分析；新 token 的初始化（" thing"）是一个被承认的敏感点，MBPP 上四个同法训练的 token 泄漏率在 **0.04–0.14** 之间且**无法事先可靠挑选**（Table 21）。
- **评测依赖单一 LLM judge**（`gpt-6-luna-proto`），judge 本身的一致性与人工校验未报告；leakage/retention 用 GPT 打分 trait 存在评分器偏差风险。
- **不可达性的度量仅在末端激活空间的一次投影上做**（principal components of activations at end of system prompt），1,040 个提示是人为构造的启发式集合，未证明穷尽所有 typed 提示。
- **没有与前沿模型上已部署的 inoculation prompting 做直接对比**，因此"优于 inoculation"这一主张只在开源 27–32B 模型上成立。

## 适用场景
- **适合**：需要在**保留某个 desirable trait**（专业知识、历史细节、领域风格）的同时抑制有害 trait 的选择性学习场景；开发者拥有模型权重、部署时能控制 embedding 加载（不加载某些行）的自托管场景；对双用途能力需要"可随时恢复"的合规/审计需求；资源受限（20 KB 参数增量，不需完整 LoRA 训练算力）。
- **不适合**：闭源 API 模型（无法加 token、无法删行）；希望**彻底删除**而非隐藏能力的场景（应用 GRAFT 类方法）；sycophancy、harassment 这类"trait 本身就是指令"的行为；基座模型本身就表现出目标 trait 的场景（如 Gemma 的 MBPP 硬编码）；需要抵抗有权重访问的攻击者的场景。
