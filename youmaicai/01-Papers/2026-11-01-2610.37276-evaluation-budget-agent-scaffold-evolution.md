# Where Should the Evaluation Budget Go in LLM-Driven Agent Scaffold Evolution?

## 摘要
LLM 驱动的 agent scaffold evolution 通过迭代式候选生成与评估改进 agent workflow。评估既引导后续搜索，又决定最终返回的 scaffold，但对每个候选都在完整任务集上评估代价高昂。本文把"评估预算如何在两种角色间分配"作为决策依赖问题来研究：实验表明稀疏反馈足以维持有效的进化，而针对最终选择的定向评估能提升最终性能；replay 分析进一步表明，共享的信息量大题目与稳定的评分参考（common scoring reference）支撑了相近候选之间的可比性。据此提出 EvalAlloc：搜索阶段用共享核心 + 固定 response model 提供稀疏反馈，搜索后 refit 模型并用 warm-started paired successive halving 做最终确认，复用已积累观测、只补跑缺失评测。在四个 benchmark 与两个 evolution framework 上，EvalAlloc 在多数设定下平均性能高于 full evaluation，而评测 cell 数约为其一半。

## 核心贡献
1. **问题重构**：把 scaffold evolution 的评估视为"决策依赖"问题——search-time feedback 只需便宜且可比，final selection 需要能可靠区分近似打分的竞争候选。
2. **三条实证发现**（Takeaway 1-3）：稀疏评估反馈可维持有效进化（完全去掉反馈会显著劣化）；共享信息量大题目 + 共同评分参考能提升 close-pair agreement 并降低 archive regret；搜索改进集中在早期迭代，而最终选择对 top 候选间的不确定性敏感。
3. **EvalAlloc 框架**：Core Calibration（短期全评估 warm-up）+ Shared-Core Evolution（共享信息核心 + 固定 response model 的稀疏评估）+ Warm-Started Selection（refit + paired successive halving）三阶段，可作为 drop-in evaluator 接入原生框架。
4. **完整基线对比**：Skip Eval / Successive Halving / Random / Cascade / Full，四个 benchmark（HotpotQA、HoVer、DROP、IFBench）× 两个 evolution framework（ShinkaEvolve、AdaEvolve）× 3 seeds。

## 方法与架构
**形式化**：scaffold $c$ 在任务集 $D_s=\{x_i\}_{i=1}^N$ 上执行得分数 $Y^{(r)}_{ci}\in[0,1]$（$r$ 为重复执行索引），期望适应度 $F(c)=\frac{1}{N}\sum_i \mathbb{E}[Y^{(r)}_{ci}]$，全量参考分 $F_{ref}(c)=\frac{1}{N}\sum_i Y^{(1)}_{ci}$。一个 scaffold–item 执行称为一个 **evaluation cell**。优化目标：
```math
\max_{\pi}\ \mathbb{E}\!\left[F\!\left(c^{\pi}_{pick}\right)\right]\quad \text{s.t.}\quad \mathbb{E}[C^{\pi}_{eval}] \le B
```

**阶段 1 — Core Calibration**：前 $W$ 个有效候选在全部 $N$ 个 SEARCH item 上全评估。item 信息量用 Beta 后验估计，全对概率 $p_i \sim \mathrm{Beta}(a_i+1, n_i-a_i+1)$，保守信息量估计：
```math
I_i = 4\left(\mathbb{E}[X_i] - z\cdot sd[X_i]\right),\quad X_i = p_i(1-p_i)
```
（分数部分正确按失败计；$z$ 为不确定性惩罚，默认 $z=2$。）同时用低秩 logistic response model（MIRT 形式）拟合 warm-up 的稠密响应矩阵：
```math
q_{ci} = \sigma\!\left(\mu + \eta_i + b_c + u_i^{\top} v_c\right),\quad u_i, v_c \in \mathbb{R}^{d}
```
以正则化 fractional cross-entropy 最小化拟合（默认 $d=2$、$\rho=1$）。warm-up 候选拟合出的 candidate 参数同时作为后续候选的高斯先验。

**阶段 2 — Shared-Core Evolution**：每个新候选在 $k=60$ 个（$N=300$ 的 20%）SEARCH item 上评估。固定共享核心 $S_0$（$k_0=54$，占 $k$ 的 90%）来自信息量 top-$k_0$；其余 $k-k_0$ 个用 Gumbel-top-$k$ 采样，logits 为 $I_i/\tau$（默认 $\tau=0.001$），即"取当前最有信息量的题目 + 随机 tie-break"：
```math
S_c = S_0 \cup A_c,\qquad |S_0| = k_0,\quad |S_c| = k
```
搜索期间 global intercept $\mu$、item 参数与 candidate 先验保持**固定**，仅对新候选用 MAP 推断 $(b_c, v_c)$，从而维持统一的 full-SEARCH 评分尺度、避免反复 refit 与重打分历史档案。完整分数估计：
```math
\hat{F}(c) = \frac{1}{N}\left(\sum_{i\in S_c} Y_{ci} + \sum_{i\notin S_c} q_{ci}\right)
```
共享核心降低成对比较方差的原因（common random numbers 视角）：
```math
\operatorname{Var}(\bar{Y}_a - \bar{Y}_b) = \frac{\sigma_a^2 + \sigma_b^2 - 2\operatorname{Cov}(Y_a,Y_b)}{k_0}
```
若各候选独立抽题，协方差项消失；而演化后的候选响应高度相关，共享题目能显著降噪。

**阶段 3 — Warm-Started Selection**：先按去除 docstring 后的 AST 合并重复候选，再对 SEARCH item 构造共享随机排列与递增前缀 $P_1\subset P_2\subset\cdots\subset P_R$，$P_R=D_s$。令 $O_c$ 为候选 $c$ 在搜索期已观测 item，$U^r_c = O_c \cup P_r$，只执行缺失观测。第一轮用 union 均值：
```math
\hat{F}_1(c) = \frac{1}{|U^1_c|}\sum_{i\in U^1_c} Y_{ci}
```
第二轮起用回归（difference）估计量校正不同 item 集难度差异：
```math
\hat{F}_r(c) = \frac{1}{|U^r_c|}\sum_{i\in U^r_c} Y_{ci} + \lambda_r\left(\frac{1}{N}\sum_{i=1}^N \tilde{q}_{ci} - \frac{1}{|U^r_c|}\sum_{i\in U^r_c}\tilde{q}_{ci}\right)
```
$\lambda_r$ 由数据估计（存活候选上的 pooled within-candidate 回归斜率，裁剪到 $[0,1.5]$）：
```math
\lambda_r = \frac{\sum_{c\in C_r}\sum_{i\in U^r_c}(Y_{ci}-\bar{Y}_c)(\tilde{q}_{ci}-\bar{\tilde{q}}_c)}{\sum_{c\in C_r}\sum_{i\in U^r_c}(\tilde{q}_{ci}-\bar{\tilde{q}}_c)^2}
```
采用 two-fold cross-fitting 避免用候选自身观测拟合 item 参数；最后一轮观测全部 $N$ 个 item 时退化为观测均值，故最终选择永远由实测结果决定。

**总成本模型**：
```math
C_{eval} = WN + (M-W)k + C_{SH,new}
```
默认 $W=10$、$k=60$ 时搜索阶段占 full evaluation 的 30%。

## 实验设置
- **Benchmark 划分**：SEARCH 300 / DEV 150 / TEST 300（IFBench TEST 为 294）。SEARCH 用于演化与最终选择，DEV 仅用于辅助审计，TEST 只用于给被选中的 scaffold 打分。四个 benchmark：HotpotQA、HoVer、DROP、IFBench。
- **Evolution framework**：ShinkaEvolve；AdaEvolve（用 SkyDiscover 实现）。每次运行从同一初始程序出发做 80 次 proposal，3 seeds。
- **模型**：executor 为 Qwen3.5-9B（temperature 0、关闭 thinking、最多 16,384 output tokens）；proposer 为 DeepSeek-V4-Flash-0731；两者均用 vLLM 本地部署在单节点 8× NVIDIA H20 GPU。
- **EvalAlloc 超参**：搜索阶段占 full budget 的 30%，$W=10$ 全评估 warm-up，$k=60$（20% of SEARCH），$k_0=54$（90% of $k$），Gumbel 温度 $\tau=0.001$；最终选择 $R=4$ 轮 successive halving，累计 item 前缀 30/60/120/300，分别保留 30/15/8/1 个候选；response model $d=2$、$\rho=1$、$z=2$。
- **基线**：Skip Eval（搜索与选择都不评估，取最后一个有效程序）、Successive Halving（搜索不评估，最终用 SH）、Random（随机采样 50% SEARCH item）、Cascade（先 20% item，达 top-25% 阈值则升级全评估）、Full（全量评估）。
- **指标**：TEST 均分（3 seeds，附标准差）、evaluation cost（占"每个 proposal × 全部 300 SEARCH item"的比例，ShinkaEvolve 为 80×300 cells，AdaEvolve 为 81×300）、executor token 成本。

## 局限性
作者在文中指出的限制：warm-up 长度与 search budget 的最优取值差异落在 seed 间波动范围内；搜索期预算增加并不一致地改善最终表现；evaluation-cell 数与 token 数不成比例，"把评测集中到信息量大且竞争力强的候选"反而偏向更贵的执行 cell；不同 proposer/executor 配置下各评估策略的相对优劣会变化，说明收益依赖底层模型。文中未设独立 Limitations 章节。

我的补充批判：(1) 最终选择阶段的 SH 与基线中的 SH 共享同一"免费对比"设定，EvalAlloc 的增益主要来自搜索期反馈，但与 Full 的差距很小（ShinkaEvolve 0.7084 vs 0.6973，落在标准差范围内），统计显著性未被严格检验；(2) response model 的 $d=2$ latent 维度是超参而非学得结构，模型假设（logistic + MIRT）未与更灵活方法对比；(3) 评测任务是 QA/DROP/IFBench 类短程任务，与真实多步 agent 的长 horizon 成本结构差异很大；(4) 评测 cell 的成本并未反映 executor token 的真实开销，token 占比反而更高（64.76% vs 52.13%），"省一半成本"的说法需要打折。

## 评估与建议
- 是否推荐深入阅读：**是**。它把"评估预算分配"这一常被忽略的工程问题形式化，并给出可迁移的框架。
- 适用场景：agent/workflow 自动进化（ADAS、AFlow、ShinkaEvolve、AlphaEvolve、GEPA 等）的成本优化；LLM 评测效率（tinyBenchmarks、SparseEval、CollabEval、Hyperband/SH 的交叉参考）；任何需要"稀疏反馈 + 精确认终选择"两阶段决策的系统设计。
- 与知识库的关联：可与 IRT / MIRT 模型、SparseEval 与 CollabEval 的评分估计、Hyperband 与 irace 的序贯资源分配、common random numbers 方差缩减理论形成方法论链条；与 LLM-as-judge 可靠性和 benchmark 评测成本主题直接相关。
