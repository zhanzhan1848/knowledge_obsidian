## 核心贡献

> 用 **40 个单词级答案**就能精确识别 API 背后的模型：**92.5%** 准确率 vs 随机 **1.1%**。方法基于「模型 profile」—— 每个问题下各答案的输出频率。成本每端点仅几分钱。

1. **Profile 归因法**：为每个模型建立「问题 × 答案」频率档案，新答案归因给最可能给出它的模型
2. **面板验证**：94 个模型的面板上，40 个答案 **92.5%** 时间精确定位正确模型
3. **OpenRouter 实战**：在盲标下识别出 DeepInfra 提供的全部 10 个模型
4. **发现真实问题**：
   - 13 个开源模型的 96 个端点中 92 个自报身份正确
   - **1 个以 Llama 4 Maverick 之名提供 Gemma 4**（自报 Gemma 4，且每条消息按 Gemma 4 计 token）
   - 1 个关闭推理后与声称模型匹配
   - 2 个未解决
5. **计费异常**：Grok 4.7 一行问题被计 **1,247 input tokens**（GPT-4o 仅需 12）；5 个模型回答当前日期却未因此计费
6. **System prompt 影响**：加入 system prompt 使准确率**下降 6–16 个百分点**

## 技术方案

### Profile 归因

对每个模型 $m$ 建立档案：

```math
P_m(q, a) = \Pr[\text{model } m \text{ answers } a \text{ to question } q]
```

对观测到的答案序列，取似然最大的模型：

```math
\hat{m} = \arg\max_m \prod_i P_m(q_i, a_i)
```

### 关键工程细节

| 设计选择 | 影响 |
|---------|------|
| 问题来自**公开的模型默认行为普查** | 问题集本身可复现、无对抗性 |
| **单词级**答案 | 低熵、高模型特异性、便宜 |
| 无 system prompt | 有 system prompt 会掉 6–16pp —— 干扰了默认行为指纹 |

## 实验结论

| 实验 | 结果 |
|------|------|
| 94 模型面板，40 答案 | **92.5%** 精确定位（随机 1.1%） |
| DeepInfra 10 模型盲标 | **10/10** 识别成功 |
| 13 开源模型 96 端点 | **92** 自报一致 |
| 发现冒充 | **1 个**：以 Llama 4 Maverick 命名实为 Gemma 4 |
| System prompt 影响 | 准确率 **-6 ~ -16 pp** |
| 成本 | 每端点几分钱 |

---

## 局限性

- 需先为每个模型建立 profile（需对每个模型发请求，有前置成本）
- 依赖模型的**默认行为** —— 微调、精调、system prompt 定制会破坏指纹
- 论文摘要为单作者工作，缺乏独立复现
- 未解决：2 个端点身份不明
- "Gemma 4 / Llama 4 Maverick"等型号名的真实性需外部确认

## 实现建议

- **实现难度**: 低（只需 API 调用，无白盒访问）
- **适用场景**: **采购审计 / 供应商验证 / 路由合规检查** —— 确认你付费买的模型确实是声称的模型
- **⚠️ 伦理提示**: 该技术同时是**审计工具**和**追踪工具**；用于绕过供应商 ToS 或追踪用户是不当使用
- **建议起点**: 用公开默认行为普查题集，禁用 system prompt，逐端点采样建档；可与计费记录交叉验证（本文正是用 token 计费异常佐证了冒充）
