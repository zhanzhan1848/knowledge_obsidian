# ROSTrans：LLM 在 ROS1 到 ROS2 迁移上的实证基准

> **原题**: ROSTrans: Empirically Benchmarking LLMs for ROS1-to-ROS2 Migration

| **摘要** | Although large language models have shown strong capabilities in domain-specific code generation, their performance in robotics software development, especially for the Robot Operating System (ROS), remains largely unexplored. ROS code generation presents distinctive challenges, including complex inter-node coordination, middleware configuration, and lifecycle semantics that go far beyond standard coding benchmarks, and many important correctness properties become observable only once migrated nodes are launched and communicate. We present ROSTrans, a benchmark for evaluating LLMs on ROS1-to-ROS2 code migration, a representative and practically important setting for ROS code generation. ROSTrans comprises 108 scaffolded completion tasks drawn from a diverse set of 70+ open-source ROS1 repositories and organized into a hierarchical taxonomy assessing interface-level, behavioral-level and system-level correctness. For every task we establish an executable reference: a verified ROS2 implementation, a runtime test suite that launches the nodes and exercises their topics, services, actions and parameters, and a container ensuring reproducibility. Candidates are scored by injecting only their target files into an otherwise fixed copy of the reference package, so a candidate can neither supply nor weaken the tests it is judged by. Evaluating six frontier LLMs over five stochastic generations per task, we find pass@1 below 10.9%, and that 56.5% of all samples build successfully and then fail at runtime,and 32.0% fail runtime assertions on the migrated interfaces, a class of error no compile-only oracle can detect. Execution-guided repair further improves task success, reaching 49.1% and 47.2% for Claude Opus 4.6 and GPT-5.5 after three rounds, respectively. |

## 核心贡献

1. **空白**：LLM 在领域代码生成上能力强劲，但在**机器人软件开发（特别是 ROS）**上的表现基本未被探索。
2. **ROS 代码生成的特殊性**：复杂的**节点间协调**、**中间件配置**、**生命周期语义**，远超标准编码基准；且**许多重要的正确性属性只有在迁移后的节点被启动并通信后才可观测**。
3. **ROSTrans 构成**：**108 个脚手架补全任务**，取自 **70+ 个开源 ROS1 仓库**，组织为**层级分类法**：接口级、行为级、系统级正确性。
4. **关键设计 —— 可执行参照**：每个任务配备
   - 一个**已验证的 ROS2 实现**
   - 一个**运行时测试套件**，启动节点并实际调用其 topics、services、actions 与 parameters
   - 一个确保可复现的**容器**
5. **评分防作弊设计**：候选实现被**仅注入其目标文件**到参照包的固定副本中 —— 因此候选**既无法提供也无法削弱**评判它所用的测试。
6. 评估 **6 个前沿 LLM × 5 个随机种子**。

### 关键发现

- **"只有节点启动后才可观测的正确性"** 是本文最重要的观察 —— 它解释了为什么标准"代码看起来对不对"的评测会严重高估 LLM 在 ROS 上的能力。**真实正确性是运行时的属性**。
- **"仅注入目标文件"的沙箱评分** 是一个值得其他领域借鉴的评测设计：它同时防止了候选**弱化测试**（提交测试文件）和**自带测试**（作弊），防作弊做得比多数基准更严。
- 与 [[2026-11-02-2610.38977-beyond-passing-tests-a-systematic-review-and-controlled-re-evaluation-of]] 的抗污染发现呼应：基准的可信度取决于**能否被绕过**，ROSTrans 在这一点上比多数 LLM 基准做得好。
- 与 [[2026-11-02-2610.41552-enhancing-knowledge-entity-relation-extraction-in-abstracts-and-full-tex]]（知识关系抽取）同为学术 NLP 场景的具体评测，方向不同但都在补"真实任务"的空白。

## 局限性

- 摘要未给出 6 个模型的具体分数（需查原文）
- 108 个任务在 70+ 仓库上抽样，任务覆盖度可能不足以代表真实迁移工作
- ROS 版本生态复杂，跨 ROS2 发行版的泛化性未讨论
