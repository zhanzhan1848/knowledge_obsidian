## 核心贡献

> prefill 呈线性 + 二次双重标度而 decode 线性——长上下文的边际成本比直觉更高。

1. 系统刻画 LLM **prefill 与 decode 两个阶段**的计算时间与能耗随 token 长度的标度关系，这是既有工作普遍缺失的一半（它们只看输出 token）。
2. 用广义线性模型（GLM）拟合得出：decode 的计算时间与能耗随输出长度**线性**增长，而 prefill 呈**线性 + 二次**双重标度。
3. 证明**计算时间是能耗的可靠代理**，并给出可用于精确能耗估算的映射框架，支持 agentic 部署的可持续性决策。

---

## 技术方案

### 核心思想

LLM 融入 agentic 架构后，token 消耗量激增，能耗足迹也随之成为关注点。但针对专有 API 模型，能耗估算一直很困难；而现有方法**主要关注生成的输出 token，却忽略了 agentic 工作流中巨大的输入上下文**。

这个忽略是有代价的。论文通过在广泛的 prefill（输入）与 decode（输出）token 长度范围内做系统 profiling，用广义线性模型拟合出两条不同的标度规律：

- **decode**：计算时间与能耗随输出长度**线性**增长
- **prefill**：呈**线性 + 二次**双重标度

二次项的出现是本文的关键含义。在短上下文下，prefill 的成本可以近似忽略；但在 agentic 场景中，上下文通常很长，二次项开始主导。这意味着**输入上下文在长上下文工作负载下是一个实质性的成本因子** —— 而不只是「多花一点」。

第二个实用结论是：**当无法直接测量能耗时，计算时间是能耗的可靠代理**。这让工程师可以在只有 GPU 时间计数的生产环境中做出能耗估算与优化决策。

### 关键技术

| 技术 | 说明 |
|------|------|
| 双阶段 profiling | 分别测量 prefill（输入）与 decode（输出）token 长度对计算时间与能耗的影响 |
| 广义线性模型拟合 | 用 GLM 刻画标度关系：decode 线性，prefill 线性 + 二次 |
| 计算时间作为能耗代理 | 在无直接能耗测量时用 compute time 可靠估算能耗 |
| 宽范围 token 长度扫描 | 覆盖从短到长上下文的完整区间以暴露二次项 |
| agentic 场景映射 | 把标度关系转化为可用于部署决策的估算框架 |

## 实验结论

- **数据集**: 跨越广泛 prefill / decode token 长度范围的受控 profiling 实验（本地开源模型推理）
- **基线**: 线性拟合模型、仅考虑输出 token 的既有估算方式
- **结果**: decode 计算时间与能耗随输出长度线性增长；prefill 呈线性与二次双重标度；计算时间可作为能耗的可靠代理。

- **prefill 的二次项**是全文最重要的发现 —— 它解释了为什么「输入长」在 agentic 场景下比直觉更贵。
- 把「只看输出 token」这一既有做法明确指出为方法论缺陷，对能耗核算的规范化有意义。
- **计算时间可代理能耗**这一结论让该方法在没有功耗计数的生产环境中立刻可用。
- GLM 而非简单线性拟合是恰当的方法选择，能表达非单调的标度结构。

## 局限性

['基于本地开源模型 profiling，专有 API 模型的实际能耗特征（不同硬件、不同调度）需另行标定。', '能耗测量受硬件、批处理、并行度影响，跨平台迁移需重新拟合。', '未考虑 KV cache 复用、前缀缓存等实际部署中的显著优化手段对成本的影响。', '二次项在多大上下文长度下开始主导，论文未给出明确阈值指引。']

## 实现建议

- **实现难度**: 低（主要是受控 profiling 与 GLM 拟合）
- **适用场景**: LLM 部署成本核算、agentic 系统的可持续性评估、算力规划、上下文长度策略制定
- **建议**: **给 agent 设计上下文预算时，必须把 prefill 的二次标度算进去** —— 长上下文的边际成本比线性直觉高得多。同时可以放心地用 GPU 时间作为能耗代理，快速估算不同架构方案的总成本。

## 原始摘要

```
The integration of Large Language Models (LLMs) into agentic architectures has substantially increased token consumption, raising concerns about their energy footprint. Yet, estimating the energy consumption of proprietary API-based models remains challenging, and existing approaches focus primarily on generated output tokens while overlooking the impact of the large input contexts characteristic of agentic workflows. To address this gap, we systematically profile compute time and energy consumption across a wide range of prefill (input) and decode (output) token lengths. Using generalized linear models, we show that decode compute time and energy scale linearly with output length, whereas prefill compute time and energy exhibit both linear and quadratic scaling with input length. These findings demonstrate that input context becomes a relevant factor for large-context workloads. Furthermore, we show that compute time serves as a reliable proxy for energy consumption when direct energy measurements are unavailable. Our mapping framework enables precise energy estimation and supports more sustainable deployment decisions for agentic AI.
```
