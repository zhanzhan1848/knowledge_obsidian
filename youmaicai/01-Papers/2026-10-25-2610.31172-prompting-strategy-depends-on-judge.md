## 核心贡献

> 用 **9 种 prompting 策略 × 4 个开源 judge 模型 × 27 种语言 × 4 个任务 × 13 个数据集**（超 **100 万**条 pointwise 打分）证明：**prompting 策略的效果不可迁移 —— judge 模型的选择比 prompting 策略的选择重要得多，策略效应在不同 judge 之间甚至会反向**。

1. **填补双语（bilingual）空白**：现有 prompt-sensitivity 研究**以英语为中心（English-centric）**，现有多语言 judge 研究**固定 prompt 模板** —— 本文首次把**prompting 策略**与**judge 模型**同时作为变量，系统测量其交互
2. **规模空前**：**9 种 prompting 策略、4 个 open-weight judges、27 种语言、4 个任务、13 个数据集**，产出 **over 1M pointwise scores**，且**对照人工判断做过验证**
3. **核心发现 —— 不可迁移性（not transferable）**：
   - **judge 模型的选择压倒 prompting 策略的选择**
   - **策略效应在不同 judge 之间会反向（reverse direction）**
   - **稳定性在低资源语言中退化**，而**聚合报告会把这些效应掩盖掉（concealed by aggregate reporting）**
4. **给出实践准则**：prompting 策略**必须在目标评测设定下做验证**；跨研究比较**必须同时说明 judge 与 prompt 配置**

## 技术方案

### 核心思想

多语言 LLM-as-a-Judge 的评测结果 `score = f(prompting_strategy, judge_model, task, language)`。本文主张这个函数**几乎不可分解** —— 你不能问"CoT 是不是更好"，只能问"在 judge=J、任务=T、语言=L 下 CoT 是不是更好"。

```
朴素假设：prompting_strategy → 评测质量（judge 无关、语言无关）
实际：    prompting_strategy × judge_model 存在强交互，且效应符号可变
```

### 关键技术

| 技术 | 说明 |
|------|------|
| **9 种 prompting 策略** | 包含 Chain-of-Thought、Role Conditioning 等（摘要明确点出这两类为研究焦点） |
| **4 个 open-weight judges** | 全部为开源权重模型，避免闭源 API 不可复现 |
| **27 种语言** | 覆盖高低资源语言，用于测稳定性退化 |
| **4 个任务 / 13 个数据集** | 多任务多数据集，避免单一任务结论 |
| **Pointwise 打分** | **超过 100 万条** pointwise scores（非 pairwise） |
| **Gold-reference 输出** | 在**参照标准的输出**上打分（gold-reference outputs），控制被评内容质量 |
| **人工判断校验** | 打分结果**对照人工判断做了验证** |
| **聚合 vs 分层报告对比** | 显式展示"aggregate reporting 掩盖效应"的现象 |

### 实验规模总览

| 维度 | 规模 |
|------|------|
| Prompting 策略 | **9** |
| Judge 模型 | **4**（open-weight） |
| 语言 | **27** |
| 任务 | **4** |
| 数据集 | **13** |
| 打分总量 | **over 1M pointwise scores** |

## 关键实验结果

### 三条核心结论

| 结论 | 性质 |
|------|------|
| **Prompting 策略不可迁移（not transferable）** | 换 judge 就换结论 |
| **Judge 选择 > Prompting 策略选择** | 效应量级上，judge 是主导因素 |
| **策略效应在不同 judge 间反向** | 同一策略在 judge A 上提升、在 judge B 上降低 |
| **低资源语言稳定性退化** | 策略效应方差增大 |
| **聚合报告掩盖效应** | 只看平均分会看不到上述不稳定 |

### 论文给出的直接建议

1. **Prompting 策略必须为"预期的评测设定"做验证**（intended evaluation setting），不能从英语基准直接迁移到多语言场景
2. **跨研究的比较必须同时报告 judge 与 prompt 配置** —— 否则比较无效

## 关键结论 / 局限性

### 关键结论

1. **多语言评测中，"哪个 prompt 更好"是个伪问题**，除非同时固定 judge、任务、语言
2. **聚合报告是危险的**：把 27 种语言或 4 个 judge 的分数一平均，效应就消失了 —— 这意味着**当前大量多语言评测论文的"prompt 提升 X%"结论可能是聚合假象**
3. **与 2610.31148（Prompt Sensitivity）互证**：那篇发现加工具放大措辞敏感性（在英文、单模型对比较语境下），本文在多语言多 judge 语境下发现 judge 主导 —— **共同结论：prompt 层的不确定性必须被显式报告，而不是被平均掉**

### 局限性

- **摘要未给出具体数值**：没有报告效应量（如 CoT 在英语 vs 低资源语言的分数差）、人工校验的具体一致率（agreement）、或 27 种语言的名单 —— 这些需查正文 23 页
- **judge 数量偏少**：**4 个** open-weight judge，无法代表闭源商业 judge（如 GPT/Claude 系 judge）的行为 —— 而实际多语言评测**大量依赖闭源 judge**
- **pointwise 而非 pairwise**：pointwise 打分受绝对尺度漂移影响（参见 [[2026-10-24-2610.31090-reward-scores-across-prompts]] 的批评）
- **"9 种策略"是有限集合**：未涵盖全部可能的 prompt 变体，结论限于所选策略
- **任务覆盖**：仅 **4 个任务、13 个数据集**，无法证明任务无关
- 无代码链接，数据构造细节不可见
