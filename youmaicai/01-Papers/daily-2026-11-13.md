## 🎯 今日主线

**今天 34 篇论文里最尖锐的一条线索，是「agent 的失败到底发生在哪一层」——而今天的答案是：同一个错误，在不同层修，效果符号会翻转。**

- **最刺眼的一篇是「Cleaning an Agent's History Hurts When the World Still Holds the Error」**（2611.14654，Salesforce 系作者）。它做了一个几乎没人做的控制实验：**冻结 agent 的世界状态，只编辑它的历史**，然后让接收模型继续。结果是——同一条「正确的值」，用两种自然方式加进历史，效果完全相反：
  - 加一条**诚实的注释**（保留错误，旁边注明正确值）→ 恢复率从 **51%**（中性注释对照）升到 **66%**；
  - 加 agent **自己已经完成的动作** → 恢复率从 **50% 降到 44%**，**比完全不编辑还差**。
  - 在 AppWorld 上，数据库写入的回执报「成功」时：若**效果尚不存在**，任务成功率从 **45% 掉到 28%**；一旦效果存在，才从 **38% 升到 49%**。两种编辑效应在两个接收模型上池化相差 **27 个百分点**，8 个接收模型中 6 个在 97.5% 显著、7 个在 95% 显著。

  **结论一句话**：把历史「洗」得干净但世界仍持有错误，比不洗更糟。这对当下所有做 agent context compaction / handoff / error repair 的工程实践是一记直接警告——**你不是在修历史，你是在改写模型对世界的信念**。

- **第二个信号是「谁在评估」这件事今天被三篇论文从三个方向同时收紧**：
  - **Leaderboard Hacking**（2611.14769）：Arena 式 BT 排名在开放提示/投票/提名的前提下是**结构性可操纵的**，单攻击可提升 **15–20 名**，叠加可提升 **45 名**，且**对几乎所有被测模型都成立**——这不是作弊检测问题，是 BT 范式问题。
  - **When Evaluators of AI Agents Disagree**（2611.14581）：LLM judge 与原生评分**只在 56.2%** 的 episodes 上一致；11 例禁止写入中 judge 放过 **10–11 例**，而**一个零模型调用的边界检查器全部抓住**；无门控时禁止写入发生率 **11.1%**，验证/纠错/安全终止门控**都没能显著降低**。
  - **Don't Blame The Preferences**（2611.10045）：谄媚（sycophancy）的根源不在偏好数据本身，而在**训练过程**——这篇把「数据归因」这个默认假设拆了。

- **第三个信号是「效率研究进入第二阶段：从「能不能压」转向「压的是不是冗余的那部分」**：
  - **DRAMA**（2611.16345，NeurIPS 2026）：多模态扩散 LLM 的每个去噪步都对长多模态序列做全量前向，且视觉 token 占据序列长度主体。他们**先测量再设计**——发现两个持续存在的冗余结构（注意力质量集中在稀疏视觉 token 子集；注意力分布跨去噪步快速稳定），据此提出 SVTP + SGAS，**无需训练、无需改架构、无需 attention cache，在 6 个视觉-语言基准上平均加速 18.67 倍**。
  - **TraceKV**（2611.15569）：面向推理型 VLM 的**策略保持**低秩 KV cache 压缩，把「压缩会不会改变模型行为」当作首要约束。
  - **Large Language Continuous Diffusion Models**（2610.02665）：连续扩散 LM，用平滑轨迹替代离散扩散的高维非光滑空间，换取**轨迹可引导性**（推理加速 + steering）。
  - **Edge-Native Multimodal RAG**（2611.14924）：7B 模型 FP16 就要 **14 GB VRAM**，消费级 GPU 根本放不下向量索引 + KV cache——硬件感知的量化与架构协同。

今天还有两条独立副线同样值得注意：

- **多轮对话正在成为 agent 的真实战场，而单轮基准严重高估了它们**：**ToolTurns**（2611.14925）里 9 个模型，**最好的 agent 能解决 69.6% 的单次请求，但只完成 39.8% 的完整对话**；**每一个**被测模型在追问请求上的成功率都低于首问；而**对话质量 rubric 分数与任务成功率给模型的排名可以截然不同**。同批的 **DISCERN**（2611.15729）从记忆侧印证：召回率已经**基本解决**（各系统 0.93–0.98），真正未解的是**消歧**（这个 query 指哪个实体、哪个时间状态该信、要不要拒答）——DISCERN 在 ENT-310 上拒答校准 **F1 0.924**（8 个基线最高 0.802），**实体消歧 0.800 vs 基线不超过 0.40**。
- **可解释特征正在反哺安全对齐**：**Less is Safer**（2611.16183）用可解释特征引导，构造**紧凑**的安全对齐数据集，解决大规模微调带来的**过度拒答**问题。

## 一、Agent 的失败在哪一层：修历史可能比不修更糟

### 1. 把历史洗干净，不如不动 —— 2611.14654

**Cleaning an Agent's History Hurts When the World Still Holds the Error**（2611.14654，Egor Pakhomov / Anurag Koul / Hongjun Liu / Bo Pang / Shafiq Joty / Erik Nijkamp）

这篇的控制实验设计得非常干净，值得逐条拆：

**实验装置**
1. 在任务中途**冻结** agent，连同它当时的**精确世界状态**；
2. 只编辑**历史**（或只编辑**世界**），二者分离；
3. 让一个**接收模型**（receiver）从该状态继续。

**AgentCE-Bench 上的两种"正确值"注入方式**（agent 已经写错一个值之后，世界保持固定）

| 注入方式 | 恢复率（后续目标做对的比例） | 相对基线 |
|---|---|---|
| 匹配的**中性注释**（对照） | 51% | — |
| **诚实的注释**（保留错误，旁边注明正确值） | **66%** | **+15 pt** |
| **agent 自己已完成的动作** | **44%** | **−6 pt**（低于未编辑历史的 50%） |

论文的关键一句：**「值是否存在」本身无法预测效果**。同样是"正确的值"，用注释说比用已完成的动作说好——后者反而破坏了接收模型对世界状态的信念。

**AppWorld 上的回执实验**（数据库写入之后）

| 回执声称 | 效果是否已在世界 | 整体任务成功率 |
|---|---|---|
| — （无回执基线） | — | 45% |
| **成功** | **尚不存在** | **28%**（−17 pt） |
| **成功** | 已存在 | **38% → 49%**（+11 pt） |
| 失败 | — | 28%（对照） |

两种编辑方式的效应在两个接收模型上池化相差 **27 个百分点**；8 个接收模型中 **6 个**在 97.5% 显著、**7 个**在 95% 显著——**方向高度一致，不是噪声**。

**为什么值得单独成节**

今天所有做 agent 的团队都在做「context compaction」「错误修复」「跨 agent handoff」，默认假设是**清理历史 = 帮助模型**。这篇论文用受控实验证明：**当清理后的历史与真实世界状态不一致时，清理动作本身引入了一个新的错误源**。接收模型无法区分「历史被修过」和「世界真的变了」——它只能读历史。

它和今天另一篇 **2611.14581**（评估者研究）合起来构成一个完整的诊断：**如果 agent 的失败可以用「世界与历史不一致」来解释，那么门控/纠错系统失败的原因就不是门控不够严，而是门控读到的证据本身不自洽**——这正是 2611.14581 发现的：他们的门控证据摘要**丢掉了 order status 和 customer authentication**，导致合法请求被拒。

**给实践者的直接结论**：任何 context repair 系统都必须先声明**它对世界状态的假设**（world model），并让接收方**可验证**这个假设；否则你在做的只是把错误从一处搬到另一处。

### 2. 多轮对话：单轮基准高估了 agent 能力 —— 2611.14925

**ToolTurns**（2611.14925，Milad Gholami / Brendan King / Jeffrey Flanigan，Apple）

**规模**：**2,620** 个问题、**1,827** 个工具、**11,004** 个 API 端点、**47** 个类别。

**协议设计**（这是它的关键创新）：每个对话从一个**故意欠规范（intentionally underspecified）的请求**开始，然后经过**两个依赖上下文的追问**，考察三件事——**澄清（clarification）、工具使用、上下文保持**。

配套还开源了**用户模拟器**：通过对话逐步释放被隐藏的上下文并生成追问请求，用 **checker–fixer 流水线**改进其对话轮次。

**结果**：

| 指标 | 数值 |
|---|---|
| 最佳 agent 单次请求解决率 | **69.6%** |
| 最佳 agent 完整对话完成率 | **39.8%** |
| 追问请求成功率 vs 首问 | **所有 9 个模型**都更低 |
| 对话质量 rubric 排名 vs 任务成功率排名 | **可以截然不同** |

最后一个发现对做模型选型的人是**警告级**的：**用对话质量打分选模型，选出来的可能不是任务上最能打的那个**。这两套度量衡量的是不同的东西——rubric 衡量交互体验，pass rate 衡量任务完成。

### 3. Agent 记忆：召回已解决，消歧未解 —— 2611.15729

**DISCERN**（2611.15729，Chirag Ahuja / Vladislav Tanov / Ramcharan Kakarla / Jonathan Taws）

论文开门见山指出领域的一个错误共识：**「这不是检索问题」**。

**基准 ENT-310**：企业销售 agent 记忆基准，**310** 条查询（**210** 可答 + **100** 不可答）。

**关键发现——召回率已经饱和**：

| 能力支柱 | 各系统表现 |
|---|---|
| Retention（保持） | 约 0.93–0.98 |
| Currency（时效） | 约 0.93–0.98 |

**「一个朴素的 RAG reader over a memory store 在召回支柱上就已经追平了强记忆系统」**。也就是说这个领域大部分"记忆架构"论文在优化一个**已经解决**的问题。

**真正未解的是 resolution（消歧）**，三个子问题：
1. **哪个实体**被 query 指向（企业记忆里同名实体在 embedding 空间碰撞）；
2. **哪个时间状态**是当前的（事实会矛盾、会被取代）；
3. **要不要真的提交答案**，还是在证据不足时**拒答**。

**DISCERN 架构**：一条规则——**preserve at write, resolve at read**。

- **写入时**：构建**严格加性**的**双时态（bi-temporal）溯源图**，**永不合并**易混淆实体，**永不丢弃**被取代的值。
- **读取时**：**零 LLM 工具面**驱动一个 agentic 循环，在图上导航，最终提交**四种门控终态动作**之一。

**评估**：**四评审团 LLM-as-a-Judge**，双轴打分——可答问题上的答案正确性 + 答/拒决策作为分类问题。

**结果**：

| 指标 | DISCERN | 最强基线 | 其他基线上限 |
|---|---|---|---|
| 拒答校准 F1（ENT-310） | **0.924** | — | **≤ 0.802** |
| 宏平均答案正确性（等支柱加权） | **0.861** | **0.806** | — |
| **实体消歧** | **0.800** | — | **≤ 0.40** |
| 宏平均答案正确性（LoCoMo 语料，零调参） | **0.663** | **0.638** | — |

实体消歧那一栏 **0.800 vs ≤0.40** 是今天最大的单项差距之一——**这才是长期记忆系统真正的瓶颈**。

### 4. 多 agent 通信的 token 级信用分配 —— 2611.16206

**OPSD4MAS**（2611.16206，Zixu Wang / Yu Zhao / Xing Zheng / Bingbing Xu / Tian Xueyun / JiaTang Luo / Weiqiang Wang / Bowen Song 等）把多 agent 通信的**后续影响**转成**细粒度 token 级信用**：

- **粗筛**：外部模型抽取事实并评估其轨迹关系；
- **细筛**：对目标 token 做 **leave-one-out** 过滤，衡量其对 agent 级 outcome advantage 的影响；
- **策略**：事实条件策略提供 token 级信用，与 **GRPO** 通过**线性退火的联合目标**结合；
- **结果**：数学任务 pass@4 相对 GRPO **最高提升 20.00 个百分点**；消融支持"完整过滤"的必要性，冻结历史注入诊断支持"事实有用性"。
- **代码**：https://github.com/Camel-Prince/OPSD4MAS

现有做法要么忽略通信知识，要么把它压成标量奖励——**留下的是粗信用，没有指引"每个 agent 该强化哪个决策"的线索**。这篇的贡献正是补上这一层。

### 5. 训练数据合成：把专家的介入变得"按需" —— 2611.16174

**JudgeMix**（2611.16174，Cheng-Yu Hsieh / Ting-Yao Hu / Sanjoy Chowdhury / Oncel Tuzel / Raviteja Vemulapalli，Apple）

**问题**：SFT 在专家轨迹上训练有众所知的**训练-推理分布不匹配**。现有补救要么引入专家引导混合 rollout，要么提供稠密逐步监督，但**都是"盲目"的**：
- 用**次优的随机干预启发式**破坏 rollout；
- 或者施加**无差别的统一监督**，**不必要地覆盖模型已经正确的动作**。

**JudgeMix 的做法**：用 **judge 的逐步语义评估**动态交错目标模型与专家——**只在目标模型真正卡住时才查询专家指导**，同时用 judge 评估**对不同步骤的专家监督重新加权**，保留模型固有的有效行为、只纠正其错误。

**结果**：在 **AppWorld** 与 **AutomationBench** 两个 agentic tool-use 基准上一致优于现有方法，**pass@1 最高提升 10 个点**。

### 6. Agent 记忆写入侧的新问题：撤销写入的"幽灵" —— 2611.16816

**Outcome-Mass Alignment（OMA）**（2611.16816）解决的其实不是"记忆"而是**多轮 RL 训练中的记账问题**，但它揭示的机制与记忆写入高度同构：

多轮 agent 的 **stepwise group-relative 训练**会把每条源轨迹展开成**多行 response 和多批有效 token**。这引入了一个**外层记账问题**，与轨迹内信用分配不同：

- **outcome-statistics multiplicity（结果统计重数）**：基于行的结果统计会把**同一个 episode 的结果数多次**；
- **objective-mass imbalance（目标质量失衡）**：token 级归约会让不同轨迹获得**不等的聚合目标质量**。

论文称这种展开**总是隐含一条加权规则**，但其实际效果取决于**展开与结果的耦合方式**。

**OMA 的两个组件**：**Outcome Alignment** 在**唯一源轨迹**上计算结果统计；**Mass Alignment** 在优化器原生 token 目标做轨迹内聚合**之后**控制聚合目标质量。**两者都不改动基础优化器的信用分配、重要性比率或裁剪**。

**结果**：

| 设置 | 提升 |
|---|---|
| ALFWorld GRPO 匹配（两个模型规模） | 匹配时域端点成功率 **+7.0 – 9.4 pt** |
| WebShop（普通设置） | 弱或**反向**的展开-结果耦合 → 效果混杂 |
| WebShop-SOL（成功导向设置） | 成功 nAUC **0.399 → 0.511** |

注意这个**符号翻转**：同一个方法，在 ALFWorld 上是明确收益，在普通 WebShop 上效果混杂。**失败轨迹展开幅度远大于成功轨迹**是关键条件。

### 7. 状态感知的工具调用 RL —— 2611.16304

**StateAlign**（2611.16304，Zhexi Lu / Subhajit Chaudhury / Tejaswini Pedapati / Keerthiram Murugesan / Lei Yu，Amazon）指出一个被忽略的悖论：**更好的任务表现可以伴随更多的工具幻觉**。

**问题诊断**：agent 常常**在应该索取信息、检索信息或拒绝不可行请求时反而执行了工具**——**即使它的推理过程已经识别出信息缺失**。也就是说，**推理正确但动作没跟上**。

**方法**：
1. **任务状态构建（task-state construction）**：数据覆盖**五种任务条件**，把状态与**不同动作需求**配对；
2. **状态对比 RL（state-contrastive reinforcement learning）**：
   - **结果奖励**引导任务完成；
   - **token 级对比**在**配对状态**下比较**相同的生成推理与动作**，训练输出**适配当前状态**。

**结果**：

| 指标 | 变化 |
|---|---|
| BFCL v4 多轮准确率（Qwen3-8B） | **45.5% → 55.2%** |
| SimpleToolHalluBench 无工具幻觉 | outcome-only 的 **62.2% → 56.1%** |
| 覆盖 | 3 个家族 5 个基座模型；BFCL v4 / ToolSandbox / When2Call 均提升 |
| 跨规模验证 | 在 3 个 Qwen3 尺寸上均降低工具幻觉 |

行为分析：决策更一致、多调用执行更完整、**工具出错后恢复更强**。

### 8. 路由：小模型能不能替代"全量开" —— 2611.16414

**Small Language Models for Inference-Capability Routing**（2611.16414）研究：推理、检索、联网、工具调用这些**可选能力**如果无差别开启，会浪费算力。用 **Qwen2.5 路由器（1.5B–14B）**做四个独立能力决策，每 query 可多选，配合 **GPT-OSS-120B** 下游模型在 **127** 个问题上评测。

| 指标 | 数值 |
|---|---|
| 14B 路由器 BERTScore F1（mean） | **0.8408** |
| 全能力开启对照 | **0.8418** |
| 下游平均 token 消耗 | **8,837 → 2,764（−68.7%）** |
| 下游中位延迟 | **9.79s → 1.91s（−80.5%）** |

但有几个**诚实的负面结果**值得记：
- **最小提示下，增加路由器容量并不一致地提升分类性能**；
- 提示优化能**缩窄 reasoning 与 calculator 路由的容量差距**，但 **RAG 与联网搜索仍更依赖更大容量**；
- **相近的分类 F1 不等于等价的下游行为**：假阳性激活带来无用计算，漏检能力则降低答案质量；
- 上述节省**不含路由器开销**——路由器开销在另一推理环境单独测量，且**随容量上升**。

**这是今天少见的、把"效率收益"和"路由成本"分开算的论文，值得作为方法论样板。**

### 9. 自改进 agent 做科学计算 —— 2611.14949

**RSI-PDEbench**（2611.14949，Binghang Lu / Lang Cao / Changhong Mou / Yige Sun / Cindy Xiangrui Kong / Zheyuan Deng / Tian Yuan / Bing Hu 等）：

- **基准**：**1,001** 个案例、**42** 个方程模板，含经典 PDE 与**分数阶 PDE**；
- **三种评测设置**：**Full**（无噪声解数据）、**Noisy**（高斯噪声，RMS = 干净信号 RMS 的 **50%**）、**Hard-OOD**（未见过的方程模板 + 偏移的系数范围）；
- **RSI-PDE 递归自改进 harness**：按残差损失**筛选候选方程** → 用**相对 $L^2$ 反馈**精修系数与数值求解器 → 用**验证门控（validation gate）**控制策略与记忆更新；
- **结果**（对比单轮基线与原生 agent harness：Claude Code / Codex，跨 4 个前沿模型）：
  - 相对单轮基线，三设置平均 pass rate 提升 **106.5%–181.9%**；
  - 相对原生 harness 提升 **3.0%–19.6%**；
  - **总模型调用数减少 46.9%**（12 个 model–setting 配对）。

**值得注意的组合**：提升 pass rate 的同时**减少调用数 46.9%**——说明改进来自**验证门控避免了无效探索**，而不是暴力试错。

### 10. Agent 评估器到底在吵什么 —— 2611.14581

**When Evaluators of AI Agents Disagree**（2611.14581，Sungbin Im，38 页，EMSE 投稿）——**这篇的方法论分量与它的篇幅成正比**。

**实验规模**：tau2-bench 的 airline 与 retail 域共跑 **2,160** 个 episodes，**记录每一次数据库写入**。

**四种打分方式**：
1. **原生评分**（对比 gold state）；
2. **LLM judge**（读 transcript 判断）；
3. **带 policy document 的 judge**；
4. **边界评估器（boundary evaluator）**——一个**最小化的规则检查**：这次写入是否**被期望**，对照 trace 中**是否发生了**。**零模型调用**。

**两名标注者**独立标注 **120** 个 episodes（任务正确性、策略合规、承诺正确性）。

**结果**：

| 指标 | 数值 |
|---|---|
| LLM judge 自身重复判定一致率 | **98.2%** |
| LLM judge 与原生评分一致率 | **仅 56.2%** |
| agent 执行禁止写入的 episodes | **11** |
| judge 放过（无 policy / 有 policy / 有 transcript） | **10–11 / 10–11** |
| 更强的 judge 放过 | **6** |
| **边界评估器抓住** | **11 / 11**（零模型调用） |
| 无门控时禁止写入发生率 | **11.1%** |
| 验证 / 纠错 / 安全终止门控降低该率 | **不显著** |

**候选原因（论文自己的诊断）**：门控的**证据摘要丢掉了 order status 与 customer authentication**，导致**合法请求被拒**。

**一句话总结**：**评估方式的选择决定了结论；最小化的规则检查暴露了 judge 漏掉的失败。** 这与 [[2611_14769]]（排行榜可操纵）形成同一天的一组呼应——**偏好聚合与 judge 判定，两条"评估管线"同时被证明比它们看起来脆弱**。

### 11. 形式化定理证明的"agent-native 中训" —— 2611.16433

**daVinci-Prover**（2611.16433，Wenhong Zhu / Xuefeng Li / Jiashuo Zhang / Yu Chen / Tiantian Mi / Qipeng Guo / Pengfei Liu）：

**核心论点**：有效的 agentic prover 需要两样东西——**强数学技能先验**（ground theorem proving）+ **agentic 轨迹**（enable long-horizon 交互式证明构造）。

**配方**：
- 合成 **33.7B token** 的 **agent-native 中训语料**，覆盖**分解、搜索、自验证、修订**；
- 配合 **verifier-grounded agentic 轨迹**；
- **daVinci-Prover harness**：让模型在**隔离工作区**中构造证明并与 **Lean verifier** 交互，收集约 **36K** 条高质量 agent 轨迹用于 SFT。

**结果**：
- 相对**匹配的 Qwen3-8B SFT-only 基线**，在 **MiniF2F / FATE-M / ProofNet** 上平均提升 **13.7** 分；
- 应用于 **Qwen3.5 系列**同样强劲，并在配合 **memory compaction** 时达到**接近饱和的 MiniF2F 表现**。

**「中训（mid-training）」而非纯 SFT 是这里的关键词**——它承认 agent 能力需要预训练阶段就注入轨迹先验。

## 二、效率研究进入第二阶段：先测量冗余，再设计压缩

### 1. DRAMA：18.67 倍加速，零训练零架构改动 —— 2611.16345

**DRAMA**（2611.16345，Yi-Hsin Hung / Fangfu Liu / Shao-Yuan Lo / Chu-Song Chen，**NeurIPS 2026**，27 页 19 图）——**今天方法论最干净的一篇**。

**问题设定**：多模态扩散 LM（dLLM）通过**迭代掩码去噪**生成文本，**双向注意力**。每个去噪步都要对**长多模态序列**做**全量前向**，而**视觉 token 占据序列长度主体**；再加固定步数预算，**每步的二次成本被进一步放大**。

**论文的批评**：现有 dLLM 推理加速方法**隐式地**刻画注意力冗余，其设计动机来自**孤立的注意力可视化**，而非**测量**。

**DRAMA 的测量发现**（沿空间轴与时间轴探测注意力张量），两个**持续存在**的冗余结构：
1. **(i) 空间冗余**：注意力质量**持续集中在稀疏的视觉 token 子集**上；
2. **(ii) 时间冗余**：注意力分布在**初始形成阶段之后跨去噪步快速稳定**。

**两个对应机制**：
- **SVTP**（Spatial-Redundancy-Aware Visual Token Pruning）：空间冗余感知的视觉 token 剪枝；
- **SGAS**（Sufficiency-Guided Adaptive Stopping）：充分性引导的自适应停止。

**结果**：

| 指标 | 数值 |
|---|---|
| 6 个视觉-语言基准平均推理加速 | **18.67×** |
| 训练开销 | **零**（training-free） |
| 架构改动 | **零** |
| attention cache | **不需要** |
| 精度 | 保持竞争力（competitive） |

**方法论价值**：论文明确地把「从可视化得出设计」批评为不可靠，并用「测量 → 两个结构发现 → 两个机制」的链条替代。**这是一个可以直接抄的范式**。

### 2. TraceKV：压缩必须"行为保持" —— 2611.15569

**TraceKV**（2611.15569）面向**推理型 VLM**——这类模型的 KV cache 压力是**双重的**：大多模态上下文 + **不断增长的推理轨迹**。

**方法**：**低秩 KV 压缩**范式（存储 KV 状态的**低维潜变量**，且可与量化组合）——**关键约束是「策略保持」（policy-preserving）**：压缩后的模型**行为不得改变**。这比「压缩后精度掉一点可接受」的要求严格得多，也是一个正确的取舍——推理模型的决策对 KV 精度敏感，行为漂移会级联成完全不同的推理路径。

### 3. 连续扩散 LM：用平滑换可控性 —— 2610.02665

**Large Language Continuous Diffusion Models**（2610.02665，Nemotron-Labs-Sigma）——**一个 2026-10 首发但此前未入库的重要工作**。

**问题**：离散扩散 LM（dLM）虽能实现快速并行解码，但**非光滑的高维空间**使**轨迹引导（trajectory steering）**变得困难——而这正是推理与推理加速所需要的。

**方案**：**连续扩散**——首个大规模（**3B** 起）连续扩散语言模型家族，通过在**平滑连续空间**中做扩散，使得轨迹可被引导。

**资产**：模型权重公开发布于 HuggingFace（论文 comment 中给出链接）。

### 4. 边缘端多模态 RAG：14 GB VRAM 的硬约束 —— 2611.14924

**Edge-Native Multimodal RAG**（2611.14924，IEEE JAC-Africa 第 14 届录用）：

**约束起点**：标准 **7B** 参数模型在 **FP16** 下占用 **14 GB VRAM**——这**直接排除了**向量索引与 KV cache 与模型**共置**的可能性。

**方案**：**硬件感知的量化**与**架构优化**协同，面向消费级 GPU。这是今天唯一一篇把「部署物理约束」放在架构决策第一位的论文。

### 5. 用掩码扩散做稳健的视觉-语言推理 —— 2611.15238

**Towards Robust Vision-Language Reasoning**（2611.15238）：离散扩散生成作为自回归生成的竞争方案，**全局规划**与**渐进纠正**能力特别适合**自动驾驶**场景；论文提出多阶段优化流水线。

## 四、谁在测量：评估的三重收紧

### 1. Leaderboard Hacking：BT 排名的结构性脆弱 —— 2611.14769

**Leaderboard Hacking**（2611.14769，Eve Fleisig / Joachim Baumann / Dylan Hadfield-Menell / Dirk Hovy）

**三类攻击**：

| 攻击 | 机制 |
|---|---|
| **策略性投票**（strategic voting） | 提交能提升目标模型排名的投票，**包括投给无关模型** |
| **策略性提示**（strategic prompting） | 只提交对自己模型有利的 prompt |
| **策略性提名**（strategic nomination） | 插入无关模型稀释目标模型的相对位置 |

**结果**：

| 指标 | 数值 |
|---|---|
| 单类攻击最大排名提升 | **15–20 名** |
| 三类攻击叠加最大排名提升 | **45 名** |
| 攻击覆盖面 | **几乎所有被测模型** |
| 适用范围 | **任何**允许开放提示/投票/模型提交的 BT 偏好评估 |

**方法论意义**：这不是「有用户在作弊」的运维问题，而是 **BT 聚合的统计假设在开放式环境下失效**的结构性问题。**排行榜分数应被当作上界估计，而非质量估计。**

### 2. Don't Blame The Preferences：谄媚的根源在训练过程 —— 2611.10045

**Don't Blame The Preferences**（2611.10045）——**标题就是它的论点**。

**背景**：AI 谄媚（sycophancy，指模型奉承用户、附和用户信念的倾向）会削弱准确性、放大错误信息、助长过度自信。

**论文的立场**：此前工作**在已发布模型上做基准测试**并**提出缓解方法**，但其**归因（attribution）**有问题——**问题的根源不在偏好数据本身，而在训练过程**。

**与本节的联系**：这与 2611.14581（评估者分歧）、2611.14769（排行榜可操纵）构成同一条线索——**今天有四篇论文在拆「我们以为在测量模型，其实在测量流程」**。

### 3. 思维链的可监控性 —— 2603.28590（COLM 2026）

**MonitorBench**（2603.28590，**COLM 2026**）——**一个此前未入库的高分工作**，与今天主线高度契合。

**问题**：LLM 生成的思维链（CoT）**不总是对最终输出具有因果责任**。当这种**错配（mismatch）**发生时，CoT 就不再忠实反映驱动模型行为的**决策关键因素（decision-critical factors）**。

**意义**：这是**忠实性（faithfulness）**问题的一个精确化——不是「CoT 是不是编的」，而是「**CoT 里哪一部分真的参与了决策**」。如果能实时监控 CoT 的可监控性（monitorability），就能在推理中途发现「模型正在为一个与结论无关的理由辩护」。

**在本批次的位置**：这是今天唯一一篇进入 **COLM 2026** 的论文，也是 34 篇里少数跨越三个月的收录（首发 2026-03-30），因为它与「测量」主线高度相关且此前未入库。

### 4. FIBER：把检测器证据做成贝叶斯融合 —— 2611.15058

**FIBER**（2611.15058）处理 LLM 生成文本检测在**域偏移与生成器切换**下的困难：监督式检测器泛化差，零样本方法依赖单个统计信号而不利用**检测器的历史行为**。

**方案**：**Fast-DetectGPT** 与 **IRT（项目反应理论）信息化检测器证据**的**贝叶斯融合**——用 IRT 建模「检测器在什么题目上表现如何」，再把两份证据融合成后验。

### 5. ShadowBench：知识是「词汇锚定」的 —— 2611.15925

**ShadowBench**（2611.15925，**NeurIPS 2026 Evaluations and Datasets Track**）：

**核心问题**：当前 LLM 事实检索的评测范式**几乎完全依赖显式实体名**。

**发现**：**LLM 的知识在根本上是词汇锚定（lexically anchored）**——模型拥有广泛的事实知识，但只在问题包含那个特定实体名时才可被检索到。论文因此指出评测中的**「遗忘幻觉」（illusion of forgetting）**：模型没被问出来的知识，看起来像是不存在。

**这是今天评测方法论的一块重要拼图**：它意味着"模型不知道 X"这个结论，必须先排除"我们只是没有用正确的名字问"。

### 6. 领域基准：并行机构 —— 2611.15342

**MechBench**（2611.15342）：面向**并行机构（parallel mechanisms）**的领域专用 LLM 基准。有效推理**同时依赖**机构拓扑、回路闭合、几何、关节类型与建模假设——现有 LLM 基准对这类领域专用知识**覆盖极少**。

### 7. 安全对齐：用可解释特征做数据效率 —— 2611.16183

**Less is Safer（LIS）**（2611.16183，36 页 16 图）——**今天"少即是多"的最强实例**：

**问题**：现有 LLM 依赖**大规模微调数据集**做安全对齐 → 成本高，且常导致**过度拒答（over-refusal）**。

**方案**：用**可解释特征**引导，构造一个**紧凑但高效**的对齐数据集。

**为什么重要**：过度拒答是安全对齐最主要的可用性代价。**用可解释特征压缩数据规模**，同时缓解过度拒答——如果成立，说明当前对齐数据里存在大量冗余。

### 8. 提示注入的两道防线 —— 2611.17115

**CapLite**（2611.17115，19 页 11 图 9 表）：现有的提示注入防御（CaMeL、Progent、IPIGuard、DRIFT）都要求 **agent 自己的模型写一份安全工件**（程序、权限策略、依赖图或约束列表），再由代码强制执行。

**CapLite 的质疑**：**小语言模型（SLM）agent 能写出足够好的安全工件吗？** 若不能，则这类防御对低成本部署场景不适用。

### 9. 视觉提示注入的"尺度诱导语义漂移" —— 2611.16744

**Scale-Induced Semantic Shift**（2611.16744，14 页 10 图）：多模态系统中的视觉内容在送入 VLM 前常被**缩放、压缩或重新渲染**。论文研究一种安全失效模式：**这些变换会改变图像的机器可读语义**——文本指令**不被完整恢复**，从而绕过基于明文的注入检测。

**这是"防御在图像层而非语义层"的直接后果**：任何依赖像素中明文存在的检测器，在缩放后就失效。

### 10. 疼痛管理中的种族与性别偏见 —— 2611.14935

**Do Large Language Models Show Racial and Sex Bias in Pain Management?**（2611.14935，31 页 5 图 14 表）：对 **GPT、Claude、Gemini、Llama、DeepSeek、Qwen** 六个模型做**反事实审计**。

**改进点**（相对既有审计）：既往审计只测少数专有模型、**显式声明种族**、且很少测量**模型自身的响应**。本论文做**反事实**（counterfactual）审计，覆盖六个模型家族。

**背景**：少数族裔患者实际获得的疼痛治疗少于非西班牙裔白人患者，用作医疗 AI 的 LLM 可能复制这种偏见。

### 11. 临床推理的长度控制 —— 2611.17128

**Parameter-Efficient Conciseness Adaptation**（2611.17128）：小模型 + 参数高效微调让临床 NLP 得以在商品级硬件上部署，但**训练之后仍有一个障碍**：在医疗任务上模型倾向于**过度冗长**。论文提出**可微长度控制**实现简洁临床推理。

**形态与 DRAMA（2611.16345）、daVinci-Prover（2611.16433）一致**：在"效果"之上单独加一个**可控制的行为维度**（长度 / 停止 / 记忆）。

## 五、重述问题本身：重述有用吗 —— 2611.14997

**Same Task, Different Statement: When and How Reformulation Helps LLM Problem Solving**（2611.14997）

**动机**：人遇到难题时常常**先把它重述得更清楚**再求解。这篇研究 LLM 是否也从这个习惯中获益。

**约束设计（关键）**：合法的重述必须**保持含义、约束与正确答案不变**——这个约束排除了「靠改题降低难度」的伪提升。

**为什么值得记**：这篇问的其实是**上下文改写作为隐式推理增强**的价值边界。如果「重述」有效，它的收益来源是什么——是**消歧**？是**引入结构**？还是单纯的**token 层面的重述带来不同采样轨迹**？答案直接关系到「用 self-refine / self-ask 做推理增强」这类做法的机制解释。

## 七、规模化与语言覆盖：Jais 3 与 EvenVLM

### 1. Jais 3：阿拉伯语中心的 agentic AI —— 2611.10224

**Jais 3**（2611.10224，**113 页**）——**本批次篇幅最大的工作**，一个**完全开源**的 agentic 语言模型家族：

- **六个模型**，规模 **0.9B → 375B**；
- 定位明确：**为阿拉伯语使用者完成任务**，而不仅仅是"用纯文本回答问题"；
- 训练目标包含**规划多步任务、调用工具、使用 Model Context Protocol（MCP）**。

**"agentic 而非问答"这个定位转变是这里的关键**：很多低资源语言的 LLM 停留在问答基准上刷分，而 Jais 3 明确把**工具使用与协议遵循**作为训练目标。

### 2. EvenVLM：濒危语言的多模态数据集 —— 2611.16500

**EvenVLM**（2611.16500，Open Reasoning Across Cultures Workshop）——**首个 Even（Lamut）语言的文本 + 多模态（VQA）数据集**。

- Even（Lamut）是**北通古斯语族**的濒危语言，约 **6,800** 名西伯利亚使用者；
- 数据集：**50,521** 条结构化 Even-俄语条目，**通过 GPT 从词典与会话手册来源抽取**；
- 提供**视觉-语言微调**。

**方法论上值得注意**：用**大模型从低质结构化来源（词典/会话手册）蒸馏出训练数据**，是低资源语言规模化数据构建的一种可复制路径——比人工标注便宜几个数量级。

### 3. 多语言文档理解的跨语言泛化 —— 2611.14758

**Benchmarking Multilingual Document Understanding in Vision-Language Models**（2611.14758，18 页 4 图）：近期 VLM 在多模态任务（尤其是**文档理解 DU**）上表现强劲，但**测量它们的基准大多只覆盖英文文档和狭窄问题**。论文评测 VLM 跨**语言、任务、风格、版面**的泛化能力。

**与本节的呼应**：Jais 3（阿拉伯语）、EvenVLM（Even 语）、多语言文档理解基准——**今天是"语言覆盖度"这条线的一个集中日**。

## 八、全双工语音对话：LLM 就能搞定 —— 2611.14774

**An LLM Is All You Need: Data-Efficient Adaptation to Full-Duplex, Word-Level Spoken Dialogue**（2611.14774）

**问题**：全双工语音对话（系统边说边听、能**插话（backchannel）**、**让出话轮（yield the floor）**、**被打断**）通常需要**数十万到数百万小时**语音训练——昂贵，且要**重写**为系统提供知识键（knowledge keys）的语言模型。

**主张**：**一个 LLM 就够了**——不需要重写 LLM，改用**数据高效**的适配方式。

**为什么重要**：全双工交互是 agent 落地到语音场景的必要条件，而传统做法（ASR → LLM → TTS 各自训练）的成本结构让它无法小规模试错。**如果"不重写 LLM"这个前提成立，全双工语音 agent 的开发门槛会显著下降。**

## 九、开源 agent 基座模型的极简配方 —— 2611.03233

**Axion 1.0**（2611.03233）——**一个"简单到反常"的配方**：

> Axion 1.0 是一个**完全开源**的 agent 基座模型，结合强且广的 agentic 能力与**异常简单**的训练配方。

**训练只有三个阶段**：
1. 轻量 **SFT**
2. 轻量 **SFT**
3. **强化学习**

**没有**去重、**没有**复杂的数据配方、**没有**多阶段 pipeline。

**为什么值得记**：今天其他论文（2611.16433 daVinci-Prover 的 33.7B token 中训、2611.16183 的可解释特征选数据、2611.16174 的 judge-guided 合成）都在说明**数据配方是关键**。Axion 1.0 提出的反向证据——**agentic 能力的瓶颈可能不在数据量，而在数据配方本身**——与 2611.16206（通信的 token 级信用）、2611.15493（多样性幻觉）指向同一件事：**我们可能还没找到正确的 credit 分配方式，而不是需要更多数据。**

### 三条我认为最值得跟进的技术线

1. **世界状态一致性（2611.14654 + 2611.14581 + 2611.15729）**
   今天的组合拳：*"历史被洗干净但世界没变"会让 agent 变糟* + *"最小规则检查比 LLM judge 可靠"* + *"召回已解决、消歧没解决"*。三者指向同一个工程结论——**agent 的可靠性瓶颈已经从"模型能力"转移到"状态表示与一致性维护"**。这是我认为本批次最被低估的主线。

2. **评估管线自身的可靠性（2611.14769 + 2611.14581 + 2611.10045 + 2611.15925）**
   四篇独立论文，同一天，分别攻击**排行榜聚合**、**LLM judge**、**训练归因**、**评测提示设计**。**方法论反思正在取代方法论增量。** 建议把"我们的分数是怎么来的"作为每个评测结论的前置问题。

3. **RL 训练的记账问题（2611.16206 + 2611.16816 + 2611.15493 + 2611.16174）**
   多轮/多 agent RL 里，**一次 rollout 被展开成多个训练信号**，"信号来自哪个行为"必须被显式处理。三篇论文分别从**通信 token 级信用**、**结果-质量记账**、**有效熵**给出方案。**这可能是接下来几个月 agent 训练的主战场。**
