## 核心贡献

> LLM 训练显存是瓶颈。已有两类应对：
> - **Activation checkpointing**：减少存储 + **recompute**
> - **Lossy compression**：直接压存储 + 损失精度
>
> ReLU / ReLU² activations 的 **sparsity 回潮** → 出现第三种机会：**无损压缩激活缓存本身**。

1. 提出 **BitSparse**：GPU-resident **lossless** compression format for sparse activations。
2. 压缩 + 重建用 **Triton kernel** 实现，融合到 autograd function。
3. 支持 **BF16 + FP8** activations。
4. 可选 **sign-bit packing** → 接近理论极限压缩。
5. **完全精确** 恢复（用于 backward pass），无精度损失。

---

## 技术方案

### ReLU Sparsity 优势
- ReLU 输出 ≥ 0 → 大量 0 → sparse 存储天然友好。
- ReLU² 类似。

### BitSparse Format
- 对 sparse activation：
  - **values 数组**（只存非零）
  - **indices 数组**（位图 / CSR）
- Optional sign-bit packing：value 可表示为 (sign_bit) + (magnitude bits)。
- Compression ratio 接近 **1/sparsity_ratio**。

### Kernel
- 自定义 Triton kernel：
  - 压缩：forward 时直接以 BitSparse 格式存
  - 重建：backward 时 on-the-fly 反向到 dense
- 全部在 GPU 内 → 不增加 CPU ↔ GPU 传输。

---

## 实验结论

- 在 ReLU / ReLU² LLM 训练上：
  - 显存峰值**显著下降**（vs checkpointing、vs dense）
  - **无精度损失**（vs lossy compression）
  - 接近理论最优 compression ratio
- 与 activation checkpointing **正交**，可叠加。

---

## 关键洞察

- **ReLU 复兴**：传统 Transformer 用 GELU / SwiGLU，**ReLU 回来**了（sparsity 优势）。
- **无损 vs lossy**：当 activations 本身可无损压缩（稀疏结构）→ 不必做 lossy。
- 三种方法可**叠加**：checkpointing (减少存储的) + BitSparse (压缩存储的) + 量化 (数值精度)。

## 实现建议

- **实现难度**：中（Triton kernel + 与 PyTorch autograd 集成）
- **预期性能**：训练显存降 30-50%（取决于 sparsity）
- **适用场景**：大模型训练（特别是 ReLU 架构如 ReLU LM）

---

## 局限性

- 仅对 **ReLU / ReLU²** 类稀疏激活有效。
- 索引存储开销在 **sparsity < 50%** 时性价比下降。
- Triton kernel 需要适配不同 GPU。
