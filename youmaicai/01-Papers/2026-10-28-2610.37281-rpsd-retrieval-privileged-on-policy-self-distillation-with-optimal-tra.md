## 核心贡献

> **LLM 做生成式推荐时，GRPO 式的后训练有两个结构性缺陷 —— 信用盲（credit-blind）与协作盲（collaborative-blind）。RPSD 用「特权教师的在策略自蒸馏」解决前者，用「跨用户的时序感知最优传输」解决后者。**

1. **背景**：序列化推荐预测用户的下一次交互。近期基于 LLM 的方法把该任务重构为**生成式推荐**，并越来越多地用 **GRPO** 等强化学习做后训练。
2. **识别两个局限**：
   - **① Credit-blind optimization（信用盲优化）**：**序列级奖励被平摊到所有生成的 token 上**
   - **② Collaborative-blind supervision（协作盲监督）**：**每个训练信号只来自单个用户，忽略了相似用户共享的行为模式**
3. **提出 RPSD（Retrieval-Privileged on-policy Self-Distillation）**：
   - **针对信用盲 —— OPSD（on-policy self-distillation，在策略自蒸馏）**：
     - 一个**拥有特权知识的教师**重新评估学生的**在策略响应**
     - **学生与教师之间的 token 级置信度差**，把共享的序列级优势**重塑为 token 级信用**
   - **针对协作盲 —— 让教师扎根于跨用户的协作性行为证据**：
     - 用**时序感知的最优传输（OT）**跨用户比较交互轨迹，**同时考虑物品相似性与时间结构**
     - 施加**多样性感知选择（diversity-aware selection）**以保留互补轨迹作为特权证据
4. **声称的贡献（首次）**：
   - **首个将 on-policy self-distillation 引入序列化推荐的工作**
   - **首个使用跨用户行为作为其特权信号**
5. **结果**：在多个真实数据集上的大量实验中达到 **SOTA**

## 技术方案

### 核心思想

GRPO 在序列推荐里有两个结构性缺陷。RPSD 的两个组件一一对应：

```text
❌ GRPO 在序列推荐:
   序列级 reward r → 均匀分给所有 token
   → 有效 token（真正决定推荐的）和其他 token 权重相同
   → 且每个用户的信号孤立 → 浪费跨用户的共性

✅ RPSD:
   ① token 级信用:
      教师（特权）重评学生的在策略响应
      Δ_confidence(token) = conf_teacher(token) - conf_student(token)
      → 把序列级优势重塑为 token 级信用
   ② 特权证据来自跨用户:
      用时序感知 OT 在用户间对齐轨迹 (物品相似性 × 时间结构)
      → 多样性感知选择保留互补轨迹
      → 教师基于这些「特权证据」给出 token 级信号
```

### 关键技术

| 技术 | 说明 |
|------|------|
| **OPSD（在策略自蒸馏）** | 教师重评学生在策略响应，产生 token 级信用 |
| **Token 级置信度差** | 把序列级优势重塑为 token 级信号 |
| **特权知识（privileged knowledge）** | 教师看到学生看不到的信息 |
| **时序感知最优传输** | 跨用户轨迹对齐，同时考虑物品相似性与时间结构 |
| **多样性感知选择** | 保留互补轨迹作为特权证据 |
| **跨用户行为作特权信号** | 解决协作盲 |
| **GRPO 基线** | 被改进的对象 |

## 公式

```math
\text{GRPO 的序列级优势（信用盲）}:\quad
A^{\text{GRPO}} \;=\; \frac{r(\tau) - \mathbb{E}[r]}{\text{std}(r)}
\qquad
\text{同一 } A \text{ 作用于序列中每个 token}
```

```math
\text{在策略自蒸馏的 token 级信用}:\quad
\hat{A}(t) \;=\; \lambda \cdot \big( \underbrace{\log p_{\text{teacher}}(t)}_{\text{特权教师置信}} - \underbrace{\log p_{\text{student}}(t)}_{\text{学生置信}} \big)
\qquad
\text{（ } t \text{ 遍历响应 token）}
```

```math
\text{特权教师}:\quad
p_{\text{teacher}}(t \mid x, \mathcal{E}) \;=\; p_{\text{base}}\big(t \mid x,\; \mathcal{E}^{+}\big)
\qquad
\mathcal{E}^{+} = \text{特权证据（含跨用户轨迹）}
```

```math
\text{时序感知 OT（跨用户轨迹对齐）}:\quad
\gamma^{\ast} \;=\; \arg\min_{\gamma \in \Pi(\mu,\nu)}
\;\Big\langle \gamma,\; C\Big\rangle,
\qquad
C_{ij} \;=\; \underbrace{\text{sim}_{\text{item}}(u_i, v_j)}_{\text{物品相似性}}
\;+\; \lambda \cdot \underbrace{\text{dist}_{\text{temporal}}(u_i, v_j)}_{\text{时间结构}}
```

```math
\text{多样性感知选择}:\quad
\mathcal{E}^{+} \;=\; \text{GreedySelect}\Big(\mathcal{S},\; \text{sim}_{\text{item}},\;
\underbrace{\text{MMR}\text{式多样性惩罚}}_{\text{避免冗余}} \Big)
```

```math
\text{RPSD 目标}:\quad
\mathcal{L}(\theta) \;=\; \mathcal{L}_{\text{GRPO}}(A^{\text{GRPO}})
\;+\; \beta \sum_{t} \hat{A}(t) \cdot \log \pi_\theta(t \mid s_t)
\qquad
\text{（序列级 + token 级双层信用）}
```

## 代码片段

```python
# 概念性伪代码：RPSD 的两个组件
import torch

def opsd_token_credit(student_logits, teacher_logits, seq_advantage, lam=1.0):
    #     ① OPSD：token 级信用
    #     student_logits: (B, T, V)  在策略响应的 token 分布
    #     teacher_logits: (B, T, V)  特权教师在相同上下文下的分布
    log_p_student = torch.log_softmax(student_logits, dim=-1)
    log_p_teacher = torch.log_softmax(teacher_logits, dim=-1)

    # token 级置信度差
    conf_delta = log_p_teacher - log_p_student                 # (B, T, V)

    # 取实际采样 token 上的差值作为该 token 的信用
    chosen = student_logits.argmax(dim=-1)                     # (B, T)
    token_credit = conf_delta.gather(-1, chosen.unsqueeze(-1)).squeeze(-1)  # (B, T)

    # 与序列级优势结合：序列级定方向，token 级分配权重
    return lam * token_credit + seq_advantage.unsqueeze(-1)


def temporal_aware_ot(user_trajectories, item_sim_fn, temporal_fn, lam=1.0):
    #     ② 时序感知 OT：跨用户对齐交互轨迹
    # 代价矩阵：物品相似性 + 时间结构
    C = torch.zeros(len(user_trajectories), len(user_trajectories))
    for i, u in enumerate(user_trajectories):
        for j, v in enumerate(user_trajectories):
            C[i, j] = item_sim_fn(u, v) + lam * temporal_fn(u, v)

    # 求解最优传输计划
    mu = torch.full((len(user_trajectories),), 1.0 / len(user_trajectories))
    gamma = solve_sinkhorn(C, mu, mu, reg=0.05)
    return gamma


def diversity_aware_select(trajectories, gamma, k=3):
    # 从匹配用户中保留互补轨迹作为特权证据。
    selected = []
    # 按传输质量排序取候选
    candidates = torch.argsort(gamma.max(dim=1).values, descending=True)
    for idx in candidates:
        cand = trajectories[idx]
        # MMR 式：若与已选轨迹太相似则跳过
        if all(min_sim(cand, s) < threshold for s in selected):
            selected.append(cand)
        if len(selected) >= k:
            break
    return selected


def rpsd_step(student, teacher, batch, advantages):
    # RPSD 完整训练步。
    # 教师用特权证据（跨用户轨迹）重新评估学生的在策略响应
    with torch.no_grad():
        evidence = [diversity_aware_select(batch.user_trajs, g) for g in batch.ot_plans]
        teacher_logits = teacher.forward_with_evidence(batch.responses, evidence)

    # token 级信用 + 序列级优势
    token_adv = opsd_token_credit(student.logits(batch.responses),
                                  teacher_logits, advantages)

    # 双重信用：序列级（GRPO）+ token 级（OPSD）
    loss = -(token_adv * student.log_probs(batch.responses)).sum(-1).mean()
    return loss
```

## 局限性

1. **无任何数值结果** —— 「SOTA」无表格、无数字，无法判断提升幅度
2. **数据集名称未给** —— 真实推荐数据集（如工业数据集）通常难复现
3. **「特权教师」的实现代价不明** —— 教师需要「特权证据」（跨用户轨迹），这在**在线部署时是拿不到的**（隐私限制！跨用户行为本身就难获取）
4. **跨用户行为作为特权信号存在隐私合规问题** —— 推荐系统里跨用户数据共享受严格限制。这是从论文到落地的重大障碍，摘要未提
5. **OT 的计算复杂度** —— 跨用户轨迹的两两代价矩阵与 Sinkhorn 求解，在用户量大时不便宜
6. **「时序感知 OT」的时序建模细节未给** —— temporal_fn 具体是什么？
7. **两个组件的消融未给** —— OPSD 与 OT 各自的贡献占比不明
8. **推荐任务与 LLM 领域主线的关系** —— 这本质上是推荐系统论文，LLM/NLP 社区关注度低
9. **是否需要真实在线验证** —— 序列化推荐的离线指标与线上收益经常背离

## 实现建议

- **实现难度**: 高（在现有 GRPO 框架上要加教师模型 + OT 求解 + 证据检索）
- **预期性能**: 摘要称 SOTA，**但无数据，需自行验证**
- **适用场景**: **序列化推荐 / 生成式推荐的后训练** —— 尤其当你有大量跨用户行为数据且有合规渠道
- **落地注意**:
  1. **先做组件拆解** —— OPSD（token 级信用）相对独立、隐私约束小，**建议先只做这一半**。它解决的是 GRPO 的信用盲，这个痛点更通用
  2. **跨用户特权的隐私合规是硬门槛** —— 先确认数据可用性，再谈方法
  3. **可迁移性考虑** —— OPSD 的思想（特权教师重估在策略响应，产生 token 级信用）**完全可以用于通用 LLM 后训练** —— 任何有「序列级奖励但 token 级信用不明」的场景都适用。这是本文对我更大的价值
  4. **OT 实现可用 Sinkhorn 近似**，注意正则化系数与用户量的关系

## 我的评注

> 这篇的核心贡献其实是**两个相当正交的思想**，被打包在一个名字下。
>
> **第一个（OPSD）更有普适价值**：GRPO 里的信用盲是 LLM 后训练的**共性问题** —— 序列级奖励平摊到每个 token，导致「真正决定成败的 token」和「凑数的 token」权重一样。特权教师重估学生的在策略响应，用**师生置信度差**把序列级优势重塑为 token 级信用 —— 这个机制**不限于推荐任务**。任何「有序列级奖励但 token 级信用不明」的场景都能用：数学推理、工具调用、多步规划、代码生成。这是我从这篇里能带走的最大收获。
>
> **第二个（时序感知 OT 做跨用户特权）** 是针对推荐场景的专门设计，**思想上也很有意思**：它把「相似用户」从语义相似度改成了**最优传输**（同时考虑物品相似性和时间结构），并用多样性感知选择保留互补轨迹。这比「找 k 个最相似的用户」更精细 —— 传输计划保留了匹配的整体结构，而不只是 top-k。
>
> 但落地障碍明显：**跨用户行为作为特权信号在推荐系统里受严格隐私约束**。论文完全没讨论这一点，而这是从论文到部署最硬的墙。
>
> 保留意见：
> - **零数值**。整篇摘要没有一个数字，「SOTA」无从验证。
> - **两个组件的贡献未分离**。OT 的实现复杂度相当高，如果消融显示 OPSD 贡献占 90%，那 OT 部分就是复杂度不划算的负担。
> - **教师模型的成本**。每个训练步都要跑教师前向（还要带特权证据），训练成本上升多少未提。
>
> 落地判断：**把 OPSD 抽出来单独用** —— 它是通用的 token 级信用分配机制，在任何 RLHF/GRPO 风格的后训练里都值得试。OT + 跨用户那部分，除非你在推荐系统内部、有数据合规渠道，否则先放着。
