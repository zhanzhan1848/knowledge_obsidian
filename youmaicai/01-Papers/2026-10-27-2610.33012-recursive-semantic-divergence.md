## 核心贡献

> **RSD**：一个无监督的、**轨迹级**的 agent 一致性度量 —— 改编自强化学习的**双模拟（bisimulation）**度量，用自然语言推理检测逻辑不一致。

1. **指出既有评估的两个盲区**：
   - 主流指标用**完成度分数**衡量任务正确性，**无法刻画跨执行的一致性**
   - agent 行为分析要么在 **token 级**（概率分布），要么在**单响应级**（语义聚类）—— **两者都无法刻画不一致如何沿轨迹的未来轮次传播**
2. **提出 RSD**：测量「同一状态下两次独立 rollout 之间的期望累积语义分歧」，用 **NLI** 检测逻辑不一致。
3. **递归定义**于未来状态之上，并由在独立 rollout 上训练的**神经网络近似**。
4. **关键实用性质**：学到的度量**从当前状态预测未来分歧** —— 因此**每一轮都能给出一致性分数，无需等待完整轨迹结束**。
5. **作为奖励信号**：用 RSD 微调后，任务进展的**方差**从 tau2-bench 的 **132% 降到 91%**，从 toolsandbox 的 **90% 降到 44%**，同时**跨基准与模型规模提升性能**。
6. **无需真值标签**：RSD 作为额外奖励信号训练，效果**匹配监督微调**，但**方差显著更低**。

## 技术方案

### 核心思想

借用 RL 的**双模拟度量**思想：两个状态如果"看起来"对 agent 是等价的（future behavior 分布相同），就认为它们"bisimilar"。RSD 反过来用这个框架**度量两条轨迹的分歧**。

```text
状态 s ──rollout A──▶ s' ──rollout A'──▶ ...
   │
   └──rollout B──▶ s' ──rollout B'──▶ ...

RSD(s) = E[ Σ_t  semantic_disagreement(A_t, B_t) ]
         ↑ 递归定义于未来状态
         ↑ 用 NLI 检测逻辑不一致
         ↑ 用在独立 rollout 上训练的神经网络近似
```

### 关键技术

| 技术 | 说明 |
|------|------|
| **Bisimulation 改编** | 从 RL 的等价性度量迁移到 LLM agent 的语义轨迹 |
| **NLI 检测不一致** | 用自然语言推理判断两条回复是否**逻辑矛盾**（而非仅字面差异） |
| **递归 + 神经网络近似** | 避免需完整轨迹即可计算 |
| **逐轮可用性** | 从当前状态预测未来分歧 → 每轮给出分数（**在线可用**） |

### 与既有度量的差异

| 维度 | 既有做法 | RSD |
|------|---------|-----|
| 粒度 | 单次响应 | **完整轨迹** |
| 传播 | 不建模 | **递归建模未来轮次传播** |
| 不一致检测 | 聚类 / 概率 | **NLI 逻辑矛盾** |
| 可用时机 | 轨迹结束 | **每轮即可** |
| 监督 | 常需真值 | **无监督** |

## 实验结论

- **基准**: tau2-bench, toolsandbox
- **指标**: 任务进展的**方差**（一致性）+ 整体性能
- **结果**:
  - tau2-bench 方差: **132% → 91%**
  - toolsandbox 方差: **90% → 44%**
  - 跨基准与模型规模**性能提升**
  - 作为额外奖励信号训练：**匹配监督微调性能**，**方差显著更低**，且**无需真值标签**
- **发表**: NeurIPS 2026

---

## 局限性

1. **NLI 判别器的可靠性** —— RSD 的质量上限受 NLI 模型制约；NLI 误判会直接污染奖励信号
2. **需要多次独立 rollout** —— 测量本身有成本（要跑至少两次完整轨迹）
3. **方差降低 ≠ 一致性提升** —— 任务进展方差下降可能来自「更保守」而非「更一致」，两者需区分
4. **NeurIPS 2026 论文**，审稿意见与实验细节需查原文

## 实现建议

- **实现难度**: 中（需 NLI 判别器 + 神经网络近似训练 + 多次 rollout 收集）
- **预期性能**: 方差 tau2-bench 132%→91%，toolsandbox 90%→44%；性能不低于 SFT
- **适用场景**: **对稳定性要求高的生产 agent** —— 客服、工具调用、流程自动化；「同样输入两次不同结果」是部署痛点
- **落地注意**:
  1. 先用 **RSD 作为离线评估指标**跑基线，不急于用它做奖励
  2. 若用作奖励，务必监控「是否因过度保守而方差下降」

## 我的评注

> 这篇的优雅之处在于**借用**。RL 里的 bisimulation 度量早已解决「两个状态对智能体是否等价」的问题，RSD 把它搬到语义轨迹上，并且用 NLI 代替数值距离 —— 这一步是关键，因为 LLM 输出的「差异」用嵌入距离衡量会漏掉**逻辑矛盾但字面相近**的情况。
>
> 「逐轮可用」这个性质比论文自己强调的更重要：它让 RSD 可以做成**在线监控指标**，而不只是离线 benchmark 分数。这对生产部署很有价值 —— 能在 agent 跑偏**之前**发现。
>
> 一个必须警惕的点：论文主打「方差降低」，但**方差低可能来自保守**。如果 agent 因为怕分歧而不敢做决策，看起来稳定却不再完成任务 —— 这是自训练式一致性奖励的经典失败模式。摘要未区分这两者。复现时建议**同时报告任务成功率**。
>
> 与 [[Position, Role or Label?]] 同批次出现，共同点是**都放弃了单一 completion score，转而度量过程性质**（分歧 / 冲突）。这是 LLM 评估从「答对了吗」走向「行为稳不稳」的一个信号。
