## 核心贡献

> 提出 **MAS-Guard** —— 统一护栏框架，同时覆盖「可插桩 agent」与「不透明 agent」构成的单/多 agent 系统，弥合局部执行、系统级交互与执法机制之间的碎片化防护缺口。

1. **三层架构**：Agent Guardrail（A-Guard，局部）→ Agent Charter + Control Plane（系统级）→ 共享干预集
2. **Agent Charter**：开发者拥有的 agent 契约
3. **确定性 + 语义双轨检查**：路由 / 能力 / 消息格式做确定性结构检查；角色与消息内容做语义评估
4. **统一干预动作**：allow / reflection / confirmation / block

---

## 技术方案

### 三层防御

| 层级 | 组件 | 职责 |
|------|------|------|
| 局部（可插桩 agent 内） | **A-Guard** | 任务特定专家评估 agentic event |
| 系统级 | **Agent Charter** | 开发者拥有的 agent 契约（身份/权限声明） |
| 系统级 | **Control Plane** | 确定性结构检查 + 语义评估 |

### Control Plane 的双轨检查

| 检查类型 | 覆盖内容 | 性质 |
|---------|---------|------|
| 确定性结构检查 | 路由（route）、agent 能力（capability）、消息格式 | 可验证、无需 LLM |
| 语义评估 | 角色（role）、消息内容（content） | 需要模型判断 |

### 干预集

```math
\mathcal{I} = \{\texttt{allow},\ \texttt{reflection},\ \texttt{confirmation},\ \texttt{block}\}
```

对**可插桩和不透明 agent 混合**的系统统一生效 —— 这是与既有工作的关键差异（既有防御要么只管单个 agent，要么假设全可观测）。

## 实验结论

| 指标 | 结果 |
|------|------|
| 整体攻击成功率降低 | **71.5% – 86.3%**（相对无防护 agent） |
| 良性任务效用 | 满足 utility reference criterion |
| 覆盖 | 6 个基准 × 3 个不同厂商的 agent LLM |

---

## 局限性

- 系统级语义评估依赖 LLM 判断，引入额外延迟与成本
- Control Plane 的确定性检查对非常规路由/私有协议可能覆盖不足
- 不透明 agent 无法在其内部插桩，全部防护依赖 charter 声明的诚实性
- 论文摘要未披露具体延迟开销

## 实现建议

- **实现难度**: 中（需在 agent runtime 加控制平面 + charter 机制）
- **预期性能**: 攻击成功率降 71.5–86.3%，良性任务无明显效用损失
- **适用场景**: 多 agent 生产系统，特别是含第三方/不透明 agent 的编排
- **建议起点**: 先落地确定性结构检查（零成本、低延迟），再叠加语义评估；`confirmation` 而非直接 `block` 是降低误伤的关键设计
