## 核心贡献

> 把 zero-shot tool selection 从 **relevance ranking** 升级到 **validity 验证**，揭示并解决 transfer-validity gap。

1. **Transfer-validity gap 概念**：语义相关的工具，迁移到新领域 / context 后可能 functional 或 contextual 不兼容。
2. **Progressive validation framework**：semantic relevance → endpoint-grounded functional compatibility → task-conditioned contextual evidence 三阶段。
3. **跨域 / 跨数据集 transfer 一致增益**，在 functional / contextual 模糊场景下增益更大。

---

## 技术方案

### 核心思想

LLM agent 越来越面对 unseen domains / execution contexts → 零样本工具选择成为关键能力。

现有主导方法（relevance ranking）只看语义匹配，不保证：
- **Functional compatibility**：调用 endpoint 的 schema、参数、返回结构是否真的匹配？
- **Contextual applicability**：在新 context（task domain、execution context）下是否依然有效？

新方法 progressive validation：
1. Semantic relevance 初筛；
2. Functional validation：endpoint-grounded schema / signature check；
3. Contextual validation：task-conditioned evidence。

### 关键技术

| 技术 | 说明 |
|------|------|
| Transfer-validity gap 概念 | 揭示 relevance ≠ applicability |
| Progressive 3-stage pipeline | relevance → functional → contextual |
| Endpoint-grounded check | schema / 参数 / 返回 |
| Task-conditioned evidence | 当前任务上下文证据 |
| Cross-domain / cross-dataset transfer | 评估泛化性 |

---

## 实验结论

- **评估**: cross-domain + cross-dataset transfer
- **基线**: relevance ranking methods
- **结果**:
  - capability ranking 一致提升；
  - functional / contextual ambiguity 场景下增益更大；
  - ablation 验证 functional + contextual 是**互补**的。

---

## 局限性

- 三阶段 pipeline 推理成本高于单阶段 relevance；
- functional / contextual 验证的 ground-truth 信号可能不完善；
- 当工具文档不全 / schema 不规范时效果下降。
