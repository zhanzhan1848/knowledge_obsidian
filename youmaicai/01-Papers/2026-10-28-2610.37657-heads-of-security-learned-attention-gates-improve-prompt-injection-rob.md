# Heads of Security: Learned Attention Gates Improve Prompt Injection Robustness

## 元信息

## 核心贡献

> **用一组「按头学习的注意力门（per-head attention gates）」在架构层面强制指令-数据分离** —— 模型学会「每个头该把多少注意力分配给可信 token、多少给不可信 token」，从而能**推理不可信内容而不执行其中的注入指令**。

1. **提出 Heads of Security (HoS)**：
   - 通过**少量学习到的 per-head 注意力门**强制**指令-数据分离（instruction-data separation）**
   - 门学习**每个头如何在可信（trusted）与不可信（untrusted）token 之间重分配注意力**
2. **对比基线**：
   - **SecAlign++**：SOTA 的**基于微调**的防御
   - **ASIDE**：与 HoS 一样把指令-数据分离**建进模型架构**的防御
3. **核心结果**：
   - 对**自适应攻击（adaptive attacks）**鲁棒性更强
   - 标准 utility benchmark 上性能更好
   - 标准 agentic prompt injection benchmark 上**持平最佳**
   - **黑盒 RL-Hammer 攻击**：GPT-OSS-20B 上 ASR **97%**，SecAlign 上 **85%**，**HoS 上仅 10%**
   - **白盒 SOTA 攻击 Claudini**（经 autoresearch 针对 HoS 强化）：要达到同等 ASR，在 HoS 上需要 **3 倍 FLOPs**
   - **保持基座 utility**：在标准多选基准与提示设置下保持基座能力；**SecAlign 与 ASIDE 在 few-shot 设置下会退化**
   - **Agentic 基准（静态攻击）**：HoS 与 SecAlign 表现相近，均大幅改善安全-效用权衡
   - **ASIDE 在工具使用上挣扎**，utility 仅 **10%**

## 技术方案

### 核心思想

Prompt injection 的本质是：**模型无法可靠区分「我要执行的指令」和「我应该只读取的内容」**。传统解法是微调让模型学会区分（SecAlign++），或者在架构上加一个独立通道（ASIDE）。

HoS 走第三条路：**不新增通道，而是约束现有注意力头的分配方式**。每个头获得一个门控参数，决定它在「看指令」和「看数据」之间如何分配注意力预算。学出来的门自动决定：哪些头适合做指令理解（应多看可信 token），哪些头适合做内容处理（应多看不可信 token）。

```text
标准注意力:  head_h(Q,K,V) = softmax(Q_h K_h^T / √d) V_h
HoS 注意力:  head_h(Q,K,V) = softmax( (Q_h K_h^T / √d) ⊙ g_h^(trusted/untrusted) ) V_h
                                                 ↑
                        每个头一组门控参数，学习「可信/不可信 token 的注意力预算分配」
```

### 关键技术

| 技术 | 说明 |
|------|------|
| **Per-head attention gates** | 每个注意力头独立的门控参数 |
| **可信/不可信标记** | token 按来源标注（系统指令 vs 外部数据） |
| **注意力预算再分配** | 门决定该头在两类 token 间的注意力分配比例 |
| **少量可学习参数** | 相比微调整个模型，参数开销极小 |
| **架构式防御** | 不依赖 SFT 数据，与 ASIDE 同类但机制不同 |
| **自适应攻击评估** | RL-Hammer（黑盒）与 Claudini（白盒） |

## 公式

```math
\text{带门注意力}:\quad
\tilde{H}_h \;=\; \mathrm{softmax}\!\left(
\frac{Q_h K_h^{\top}}{\sqrt{d_h}}
\;\odot\; G_h \right) V_h
```

其中 $G_h \in \mathbb{R}^{L \times L}$ 为第 $h$ 个头的门控矩阵，按 token 的可信性分块：

```math
G_h = \begin{bmatrix}
g_h^{\text{tr}} & \mathbf{0} \\
\mathbf{0} & g_h^{\text{un}}
\end{bmatrix}
\qquad
g_h^{\text{tr}}, g_h^{\text{un}} \in \mathbb{R}^{L \times L}
```

```math
\text{门控损失（指令-数据分离）}:\quad
\mathcal{L}_{\text{gate}}
\;=\; \mathcal{L}_{\text{task}}
\;+\; \lambda \cdot \Big(
\big\| A_h^{\text{tr}} \big\|_1 - \big\| A_h^{\text{un}} \big\|_1
\Big)
```

```math
\text{攻击鲁棒性（ASR 视角）}:\quad
\text{ASR} \;=\; \frac{\#\{\text{注入成功次数}\}}{\#\{\text{攻击尝试次数}\}}
\qquad \text{目标}:\; \text{ASR} \downarrow
```

## 代码片段

```python
# 概念性伪代码：Heads of Security 的注意力门
import torch, torch.nn as nn

class HeadsOfSecurity(nn.Module):
    # 给每个注意力头学习一组门，控制可信/不可信 token 的注意力预算。

    def __init__(self, n_heads, head_dim, n_layers, gate_init=1.0):
        super().__init__()
        # 每层每头两组标量门（可信 / 不可信），可学习
        self.gate_tr = nn.Parameter(torch.full((n_layers, n_heads, 1), gate_init))
        self.gate_un = nn.Parameter(torch.full((n_layers, n_heads, 1), gate_init))
        # 可选：按头粒度的重分配矩阵（更细粒度版本）
        self.delta = nn.Parameter(torch.zeros(n_layers, n_heads, 2))

    def forward(self, attn_scores, token_trust_mask, layer, head):
        #         attn_scores:   (B, H, L, L)  原始注意力分数
        #         token_trust_mask: (B, L)  1.0 = 可信（系统指令）, 0.0 = 不可信（外部数据）
        tr = token_trust_mask[:, None, :, None]          # (B,1,L,1)
        # 可信 token 乘 gate_tr，不可信 token 乘 gate_un
        g = torch.where(tr.bool(),
                        self.gate_tr[layer, head].view(1, 1, 1, -1),
                        self.gate_un[layer, head].view(1, 1, 1, -1))
        gated = attn_scores * g
        return gated
```

```python
# 训练目标：任务损失 + 指令-数据分离约束
def train_hos(model, trusted_data, untrusted_data, lam=0.1):
    out = model(trusted_data, attn_gate="hos")
    loss_task = out.loss
    # 约束：可信 token 上的注意力质量应高于不可信 token
    attn_mass_tr = out.attn_mass[out.trust_mask]
    attn_mass_un = out.attn_mass[~out.trust_mask]
    loss_sep = (attn_mass_tr.mean() - attn_mass_un.mean()).abs()
    return loss_task + lam * loss_sep
```

## 实验结论

- **模型**: Llama-3.3-70B-Instruct, GPT-OSS-20B

| 攻击 / 基准 | GPT-OSS-20B | SecAlign++ | **HoS** | ASIDE |
|---|---|---|---|---|
| **RL-Hammer（黑盒）ASR** | 97% | 85% | **10%** | — |
| **Claudini（白盒）** | 基准 FLOPs | 基准 FLOPs | **需 3× FLOPs** | — |
| **Agentic 静态攻击** | 基座 | 持平 HoS | **持平最佳** | 工具使用 utility 仅 **10%** |

- **Utility 保持**：HoS 在标准多选基准与提示设置下保持基座能力；**SecAlign 与 ASIDE 在 few-shot 设置下退化**
- **自适应攻击**：HoS 表现更强（RL-Hammer 10% vs 85-97%）

## 局限性

1. **需要 token 可信性标注** —— 「哪些 token 可信、哪些不可信」必须由外部提供。这是**部署时的硬前提**：Web 检索、RAG、工具输出、用户上传文件的可信性判定怎么处理，摘要未说明
2. **假设了「可信标记的存在」** —— 而现实中最难的部分恰恰是判定什么可信
3. **注意力门是「架构式」约束，但不改变信息流拓扑** —— 与 ASIDE 同类，理论上仍存在绕过路径（摘要未讨论）
4. **对模型家族的依赖** —— 门是学出来的，不同模型上需重新学；可迁移性未测
5. **FLOPs 对比的公平性** —— 「3× FLOPs 达到同等 ASR」是攻击方预算的口径，防守方自身的推理开销未提及
6. **few-shot 退化只在基线出现** —— HoS 的 few-shot 表现为何更好，未做机制分析
7. **未报告的工具使用场景细节** —— ASIDE 只有 10% utility 说明工具调用链路脆弱，但 HoS 在复杂多步工具链上的表现未给具体数字

## 实现建议

- **实现难度**: 中高（需改写注意力前向、可信性标注管线、少量训练）
- **预期性能**: **黑盒 ASR 从 85-97% 降到 10%**，utility 基本无损 —— 这是本批次最亮眼的安全数字
- **适用场景**: **RAG / agent 场景中外部内容占比高、对注入敏感的系统** —— 文档问答、网页摘要、多步工具代理
- **落地注意**:
  1. **先解决可信性标注问题** —— 这是真正的工程难点，不是模型问题。建议起点：系统指令 + 用户直接输入 = 可信；检索文档、工具输出、网页内容 = 不可信
  2. **门控参数开销极小** —— 可在已有 SFT 模型上快速加训一遍
  3. **和 ASIDE 一起评估** —— 两者都是架构式，可叠加，但注意 ASIDE 的工具调用 utility 只有 10%
  4. **别忘了评估白盒自适应攻击** —— HoS 对黑盒极强，但论文自己在 Claudini 上做了强化攻击，说明这是真实的攻防面

## 我的评注

> **10% vs 85-97%** 这个对比是今天所有论文里最硬的安全数字。而且它是在**自适应攻击**（攻击方知道防御机制并针对性优化）下取得的，这个口径比很多论文的「标准攻击」诚实得多。
>
> 我尤其欣赏它与 ASIDE 的对照：两者都是架构式防御、都做指令-数据分离，但 HoS 在 agentic 基准持平最佳、而 **ASIDE 在工具使用上 utility 只有 10%**。这个对照说明「做架构式分离」本身不够，**分离的实现位置**很关键 —— ASIDE 显然在工具调用链路上做错了什么。
>
> 方法论上，per-head gate 的优雅之处在于：它把「模型该在哪里信任什么」这个**软性的、靠 SFT 学的**问题，转化成了「每个头各配多少预算」的**显式可学参数**。而且不同头可以形成分工 —— 有的头专注指令，有的头专注内容。这比 ASIDE 的固定通道设计更灵活。
>
> 保留意见集中在一点：**可信性标注是整个方案的前提，而摘要对此几乎不提**。论文写的是「trusted vs untrusted token」，但现实中「这条检索结果可不可信」「这个工具返回的数据能不能信」是极难的判断。攻击者甚至可以伪装成可信来源（这正是间接注入的机制）。**如果可信标注来自攻击者可影响的通道，HoS 的 10% 会不会退回去？** 摘要没做这个分析，我认为是最大的缺口。
>
> 落地判断：这是**今天最值得立刻试的一篇** —— 改一处注意力前向 + 标一次可信性，就可能把注入 ASR 从 90%+ 拉到 10%。
