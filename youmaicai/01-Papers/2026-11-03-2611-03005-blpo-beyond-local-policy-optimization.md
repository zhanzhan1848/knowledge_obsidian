## 核心贡献
1. **问题定位**：逐步分组强化学习（stepwise group-based RL）相比轨迹级监督提供了更细粒度的信用分配，但可靠的比较必须**控制交互历史（interaction history）的差异**；而在每个任务的有限 rollout 内强行保证这种一致性，会导致**用于估计动作偏好的支撑不足**。
2. **BLPO 框架**：从**跨任务、跨训练更新**共享的经验中估计**任务进度优势（task-progress advantages）**，突破"局部"（单个任务内）的限制。
3. **轨迹前缀摘要为任务进度状态 + 按功能抽象动作**：使**不同任务中的对应决策**可以贡献于共享估计。
4. **全局记忆机制**：在全局记忆中累积**上下文相对回报（context-relative returns）**，采用**平衡聚合（balanced aggregation）**与**可靠性加权（reliability weighting）**来控制异质任务带来的偏差与噪声。
5. **无需 critic、无需额外 rollout**：全局优势与局部比较（归一化动作上的比较）和轨迹级信用**互补**，且不依赖学习式价值函数或额外采样预算。
6. **实验验证**：在 ALFWorld 与 WebShop 上用 1.5B 与 7B 策略，在**匹配训练预算**下取得优于所评基线的任务成功率，并有更快学习、更短轨迹、几乎无额外计算开销。

## 问题背景
长程（long-horizon）任务要求 LLM agent 协调**相互依赖的动作**，这是自动化复杂工作流的核心能力。RL 的一个基本问题是信用分配：逐步分组 RL（stepwise group-based RL）比轨迹级监督粒度更细，但它隐含假设——同一任务内用于比较的一组 rollout，其交互历史足够一致，这样动作之间的差异才能归因于动作本身。问题在于，**任务内的可用 rollout 有限**，强行维持历史一致性（如同前缀约束、同轨迹配对）会急剧削减可用于比较的样本量，导致动作偏好估计的统计支撑不足。本文提出把"经验"的范围从"本任务本轮"扩展到"跨任务跨更新"，从而在不加 rollout 成本的前提下补充支撑。

## 方法
### 1. 任务进度状态（Task-Progress States）
把**轨迹前缀**摘要为一个"任务进度状态"。这一步把长轨迹压缩成一个可比较的抽象，使不同任务、不同长度、不同表面形式的轨迹能在同一空间里对齐。

### 2. 按功能抽象动作
把具体动作按其**功能（function）**抽象，而非按表面形式（表面 token 序列）。这样"在 A 任务中打开抽屉"与"在 B 任务中获取物品"若功能同构，就被视为同一抽象动作，从而可共享其优势估计。

### 3. 全局记忆中的上下文相对回报
$$\text{global memory} \leftarrow \text{accumulate}(\text{context-relative returns})$$
- **上下文相对回报**：不是绝对的累计回报，而是在**当前上下文/任务进度**下相对的回报——这使得跨任务的回报可比。
- **平衡聚合（balanced aggregation）**：防止某个任务（或某类任务进度状态）因样本多而主导全局估计。
- **可靠性加权（reliability weighting）**：按估计本身的可靠性对各条贡献加权，控制噪声。

### 4. 优势组合
BLPO 的优势由两部分互补构成：
- **局部优势**：在**归一化动作**上的组内比较（stepwise group-based RL 的局部信号）；
- **全局优势**：来自跨任务、跨更新的共享任务进度估计。
- **轨迹级信用**：仍然保留。

三者组合，**不需要学习式 critic，也不需要额外 rollout**。

### 5. 关键设计决策
| 决策 | 理由 |
|---|---|
| 跨任务共享而非仅任务内比较 | 任务内 rollouts 有限，无法同时满足"历史一致"与"支撑充分" |
| 前缀摘要为进度状态 | 使不同任务的轨迹可比 |
| 按功能而非表面抽象动作 | 跨任务的动作对应关系 |
| 平衡聚合 + 可靠性加权 | 异质任务带来的偏差与噪声 |
| 不用 critic、不加 rollout | 保持训练预算可比 |

摘要未给出：进度状态的具体摘要实现（是否用 LLM 摘要或规则）、动作功能抽象的具体方法（聚类？LLM 标注？）、全局记忆的具体数据结构与容量、优势组合的权重（超参数）、归一化动作的具体定义、以及损失函数形式。

## 关键洞察
1. **"历史一致性"与"统计支撑"之间存在硬性权衡，这是逐步 RL 在长程任务上的根本瓶颈**。要可靠比较动作，就得控制交互历史；但控制历史就意味着配对约束，样本量随之下降。本文的重新表述很有价值：问题不是"信用分配不够细"，而是"在保证可比性的前提下，可用样本不够"。
2. **跨任务共享是对有限样本的根本解法，而不是权宜之计**。用"轨迹前缀摘要 + 按功能抽象动作"把异质任务的对应决策对齐到同一空间，从而让不同任务的样本为同一类动作决策提供证据——这是在不增加 rollout 预算的前提下扩大支撑的唯一可行路径。
3. **"不训练 critic、不加 rollout"是本文最有工程价值的部分**。在长程 agent 训练中，critic 难训、rollout 昂贵；把跨任务经验放到一个带平衡与可靠性加权的全局记忆里，等价于用一个**非参数化、持续更新的经验先验**替代价值网络，同时保持训练预算可比——这使 BLPO 的增益归因更可信。
4. **更快学习 + 更短轨迹同时出现**是一个值得注意的组合：全局优势让策略更早学会"该做什么"，而更短的轨迹通常意味着更少的错误累积。若全局优势只是让探索更激进，轨迹反而会变长；两条同时改善暗示优势信号确实在减少无效步骤，而不只是提高探索熵。
5. **上下文相对回报 + 可靠性加权，本质是在做"跨任务信用分配的稳健估计"**。这类加权与分层/混合效应统计中的方差缩减思路同源，值得迁移到其他"异质数据 + 弱监督"场景。

## 局限性
- 摘要未提供任何绝对数值（成功率、基线分数、提升幅度），因此**无法判断增益的实际规模**；"优于所评基线"缺少量化语境。
- 摘要未说明所评基线的名称，也没有与近期同类方法（如 step-wise RL 的变体、trajectory-level RL/RFT、critic-based 方法、过程奖励模型 PRM）的直接对比细节。
- 未说明全局记忆的规模与实现代价；"little computational overhead" 是相对训练总时长而言，但摘要未给出绝对开销数字。
- 关键设计细节缺失：进度状态的摘要方式、动作功能抽象的实现、平衡聚合与可靠性权重的具体算法、优势组合权重（超参）——**可复现性弱**。
- 只在两个基准（ALFWorld、WebShop，1.5B 与 7B）上验证；两者均为**短程网页/文本交互环境**，与真实长程工作流（多工具、多应用、跨天任务）的差距未讨论。
- 动作功能抽象可能依赖人工或 LLM 定义的功能空间；功能划分不当会造成**错误的跨任务对应**，这类噪声的敏感性未分析。
- 上下文相对回报在任务难度差异极大时可能不可比；摘要未讨论任务异质性最强时的表现。
- 未报告消融与超参敏感性，因此"全局优势"这一核心组件的独立贡献无法分离。

## 适用场景
- **长程 agent 训练**：需要协调相互依赖动作的工作流自动化（多步工具调用、网页/桌面操作链）。
- **rollout 预算昂贵、critic 难训**的 RL 场景：BLPO 在不训练价值网络、不增加采样的条件下补充信用分配信号。
- **多任务 / 多环境联合训练**：通过功能抽象动作实现跨任务的策略共享（比直接混合 rollout 更省算力）。
- **训练稳定性问题**：当逐步 RL 因样本支撑不足而方差大时，用带可靠性加权的全局经验先验做方差缩减。
- 可作为**长程信用分配**研究的一个干净基线（提供了明确的训练预算对齐协议）。
