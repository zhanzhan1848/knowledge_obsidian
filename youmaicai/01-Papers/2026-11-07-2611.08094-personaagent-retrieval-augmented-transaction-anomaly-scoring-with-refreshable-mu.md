# PersonaAgent: Retrieval-Augmented Transaction Anomaly Scoring with Refreshable Multi-Entity Persona Memory

### 核心贡献
1. 提出 PersonaAgent：一个 agentic 交易异常检测框架，把各实体（卡、商户等）最新的行为信号表示为 persona（人格化画像）并存入可刷新记忆（refreshable memory）。
2. 采用离线/在线分工：离线由每周调度的批处理作业抽取最新行为信号并更新记忆；在线由一个轻量 adapter 从记忆中检索每笔交易对应的实体行为信号，增强基础异常分类器的打分。
3. 在 Visa 的生产环境中全面验证有效性：打分高效（1,000 笔交易的 CPU 批处理仅需 1–2 ms），PR-AUC 相对提升 0.65%–6.58%，生产业务指标相对提升 8.93%–14.24%。

### 技术方案
**核心思想**: 用「persona 记忆」替代静态的实体 embedding 表——以 persona 作为实体的行为语义表示，既保留多实体的上下文（谁在跟谁交互），又通过周期性刷新跟上行为模式的漂移。

| 技术 | 说明 |
|------|------|
| Persona 表示 | 将实体最新行为信号表示为 persona，存入可刷新记忆，取代高基数、稀疏交互的实体 embedding 表 |
| Refreshable memory | 记忆支持周期性刷新；离线每周调度批处理作业抽取最新行为信号并写回记忆 |
| 轻量 retrieval adapter | 推理时 adapter 从记忆中检索每笔交易对应实体的行为信号，用于增强基础异常分类器的打分 |
| 离线/在线解耦 | 重刷新放在离线批处理，在线只做检索与打分，保证毫秒级延迟 |
| 多实体交互建模 | 利用实体（卡、商户等）及其交互关系作为关键信号，解决 embedding 表高基数与稀疏问题 |

### 实验结果
- **数据集**: Visa 内部生产支付网络交易数据（摘要未公开数据集名称与规模）
- **基线**: 多种现有的异常检测模型作为基础异常分类器（摘要未逐一列名），及无 persona 增强的基线
- **结果**: 1,000 笔交易 CPU 批处理耗时 1–2 ms；PR-AUC 相对提升 0.65%–6.58%；生产部署中业务指标相对提升 8.93%–14.24%

### 局限性
- 数据与业务指标均为 Visa 内部生产数据，外部可复现性有限（摘要未说明是否公开数据）
- 记忆刷新为每周粒度，无法捕捉周内的快速行为漂移；刷新频率的敏感性分析摘要未说明
- 业务指标提升 8.93%–14.24% 的相对提升幅度较大，但未给出绝对值与统计显著性
- persona 抽取依赖离线 LLM/规则流程，其抽取成本与错误传播影响摘要未说明

### 关键洞见
> 支付网络里的实体 embedding 表之所以失效，不只是因为它陈旧，更因为它用「一个固定向量」去表示一个「持续演化的多实体交互关系」；把人化为 persona 并放进可刷新记忆，等于把表征的更新频率从「模型重训周期」解耦到「记忆刷新周期」，于是行为漂移不再需要重训模型就能被感知——这正是 PR-AUC 提升幅度不大（<7%）而业务指标提升幅度显著（接近 15%）的原因：业务指标吃的是最新性，而 PR-AUC 更受召回边界制约。
