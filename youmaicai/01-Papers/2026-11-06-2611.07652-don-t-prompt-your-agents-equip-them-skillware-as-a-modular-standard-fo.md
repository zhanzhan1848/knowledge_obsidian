# Don't Prompt Your Agents. Equip Them: Skillware as a Modular Standard for Sovereign, Auditable, and Deterministic Capability Execution for Logical Systems

## 摘要
当前自主逻辑系统依赖一个**脆弱假设**：语言模型应当动态编写代码、猜测 API 载荷，并通过 prompt 工程**记忆操作约束**。实践中这会烧掉巨大的上下文窗口、抬高 API 账单，并产出在生产中**不可预测地失败**的脆弱 agent。本文提出 **Skillware** —— 一个开放的架构框架与**能力注册表**，形式化分离「agent 想做什么」与「该任务如何执行」。**Skillware 不再把松散文本指令或被草草地称为「skill」的 markdown 文件塞给模型，而是用模块化、版本化的软件能力包来装备它们** —— 类似电子游戏中的技能热键，在固定世界规则下确定性执行。每个能力包包含：**类型化 JSON 输入契约、确定性 Python 代码、任务指令、捆绑数据集、自动化单元测试**。**进程内适配器**把这些能力翻译成任何模型的原生工具声明（从前沿云 API 到本地开放权重运行时），**零网络延迟**。在 **23 个前沿与开放权重模型 × 368**（组合）的评估中给出结果。

## 核心贡献
1. 指出当前 agent 范式的**根本脆弱假设**（让模型动态写代码、猜载荷、靠 prompt 记约束）及其三项代价：上下文消耗、API 账单、不可预测的失败
2. 提出 **Skillware**：把「意图」与「执行」**形式化分离**的架构框架 + 能力注册表
3. 定义**能力包规格**：类型化 JSON 输入契约 + 确定性 Python 代码 + 任务指令 + 捆绑数据集 + **自动化单元测试**
4. **进程内适配器**把能力翻译为任意模型的原生工具声明，**零网络延迟**（含本地开放权重运行时）
5. 在 **23 个前沿与开放权重模型 × 368 组合**上评估

## 方法与架构
**能力包（Skillware Bundle）**：
```
┌─────────────────────────────────┐
│ Typed JSON input contract       │  ← 形式化输入契约
│ Deterministic Python code       │  ← 确定性执行
│ Task directives                 │  ← 任务意图（与执行分离）
│ Bundled datasets                │  ← 捆绑数据
│ Automated unit tests            │  ← 自动验证
└─────────────────────────────────┘
```

**进程内适配器**：把能力包翻译为任意模型的原生工具声明（云 API / 本地运行时），**零网络延迟**。

**执行模型**：类似游戏技能热键 —— **在固定世界规则下确定性执行**。

**评估**：23 个模型 × 368 组合。

## 实验结果
- **Skillware** 框架：能力包规格 + 注册表 + 进程内适配器
- **23 个前沿与开放权重模型 × 368 组合**的评估
- 核心主张：确定性执行替代模型动态生成 → 更少上下文、更低账单、更可预测失败

## 局限性
- 「确定性代码」意味着能力包需人工编写与维护，**初始成本高**、覆盖面扩展慢；
- 摘要未给出量化结果（368 组合的具体指标），需查正文；
- 单元测试保证的只是包内行为正确，**不保证包被正确选择**（选择仍是模型任务）。

## 值得注意的点
「**自动单元测试是能力包的强制组成**」这一点是本文最有工程价值的制度设计 —— 它把「能力正确性」变成 CI 可检查的属性，而不是靠人肉评审。这也与今日 2611.06545（自述摘要不可信）、2611.06806（用可枚举行为替代不可测伤害）是同一世界观：**能自动验证的就不要交给模型**。
