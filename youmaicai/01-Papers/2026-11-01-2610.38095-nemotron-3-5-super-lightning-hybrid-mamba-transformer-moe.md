# Nemotron 3.5 Super and Lightning: Open, Efficient Mixture-of-Experts Hybrid Mamba-Transformer Models for Agentic AI

## 摘要
NVIDIA 发布 Nemotron 3.5 Super 与 Nemotron 3.5 Lightning 两个开源 MoE 混合 Mamba-Transformer 模型，面向推理、长上下文理解与 agentic 工作负载。Super 为 120B 总参数 / 12B 激活的多模态模型，Lightning 为 30B 总参数 / 3B 激活的纯文本模型。两者结合大规模蒸馏、长上下文训练与原生 speculative decoding（MTP），Super 额外加入 Indic continued pretraining 与 agentic 软件工程 mid-training。后训练管线覆盖 SFT、RLVR 与 RLHF，Super 还包含专用 teacher 训练与多 teacher on-policy distillation（MOPD）。关键数字：Indic continued pretraining 使印度语基准最高提升 9.82 个百分点；post-trained Super 在 SWE-bench Pro 上达 51.78%，以约 4.6× 更少激活参数超过 Nemotron 3 Ultra；MTP boosting 使 speculative decoding 平均接受长度最多提升 21.8%（probabilistic draft sampling 下）；NVFP4 量化相对 BF16 取得 99.62% 的中位精度恢复；GB200 上输出可达 4,856 tokens/s/GPU，同时维持至少 50 tokens/s/user，NVFP4 吞吐为 BF16 的 2.43×，Super 分别为 Qwen3.5 与 Qwen3.8 Flash-Next 的 2.34× 与 1.90×。论文同时释出 base / BF16 post-trained / NVFP4 量化 checkpoint、独立并行 drafter（LiLiCorr、DFlash、DSpark）、model card、数据集与训练 recipe。

## 核心贡献
1. **两个混合架构 MoE 模型**：Super 120B-A12B（多模态，C-RADIO vision encoder + hybrid Mamba/attention 骨干，每 MoE 层 512 个 routed experts + MTP head），Lightning 30B-A3B（纯文本）。
2. **完整预训练-后训练-量化-推理全栈 recipe**：MTP warm-up → 1T token 蒸馏 → long-context → Indic CPT → agentic mid-training → SFT/RLVR/RLHF → MOPD → MTP boosting → NVFP4 PTQ/QAD → vLLM 推理优化。
3. **MOPD（Multi-teacher On-Policy Distillation）**：两阶段把 agentic / reasoning / alignment / vision tool-use / video reasoning 五类专精 teacher 的能力蒸馏进单一 student。
4. **测试时扩展**：并行 agent 执行 + 自验证（LAV + Probabilistic Pivot Tournament），Terminal-Bench 2.1 从 62.7% → 71.9%。
5. **效率工程**：NVFP4 量化 + 量化感知蒸馏、ReplaySSM checkpointing replay、Mamba 细粒度 prefix checkpoint、并行 speculative drafter LiLiCorr/DFlash/DSpark。

## 方法与架构
### 1. MTP（Multi-Token Prediction）与递归 speculative decoding
Super 把 Nemotron 3 Super Base 原有的两个非共享 MTP head 合并为**单个递归共享 head**（仅保留第一个 head 的权重）；Lightning 从 Nemotron 3 Super Base 初始化 MTP head，先把 latent MoE 投影融合进 experts 的 up/down-projection 矩阵，再裁剪：hidden size 4096→2688、MoE intermediate size 2688→1856、routed experts 512→128。两者均做 **100B token 的 MTP warm-up**（冻结 backbone，只训 MTP head）。

Super 引入 **hidden-state mixing** 以缓解 train–inference conditioning mismatch：标准递归 MTP 训练时第 k 步只条件于第 k−1 步的 ground-truth 隐状态，而推理时条件于骨干隐状态与前序 MTP 合成状态的混合分布。作者改为在第 k 步从步骤 1..k−1 产生的状态序列中采样输入隐状态。

### 2. 蒸馏（1T token）
- Lightning 3.5 Base：teacher 为 Super 3 Base，数据为 1T token 的 Ultra 3 Phase 2；取 teacher **top-128 logits**，用 forward KL + 一个额外 sink token 捕获 top-128 之外的残余概率；KL 与 cross-entropy 权重 **0.9 / 0.1**；LR 从 Nano 3 Base 最小值 **1e-5** 缓慢升到 **1e-4**（200B token 内），再在剩余 800B token 线性衰减回 1e-5；MTP loss scaling factor 0.1。
- Super 3.5 Base：teacher 为 Ultra 3 Base，蒸馏损失改为 **Skew Reverse KL（α=0.1）**；MoE sequence load balancing loss 系数 1e-5（Lightning 为 1e-4）；LR 以 Super 3 Base 为锚点，最小 **4.5e-6**、最大 **4.5e-5**。

### 3. Indic continued pretraining（仅 Super）
预算 100B token：10%（10B）为合成 + 自然 Indic 数据，90%（90B）沿用前一训练 mixture 的相对比例。语料 **Nemotron-Pretraining-Indic-v1** 共约 **2.83T** token（输出侧 2,825.6B），覆盖 **22 种印度语言、34 种语言-书写系统配置**：12 种优先语言（native + romanized，2,273.8B native + 224.6B romanized 合计 2.50T）与 10 种低资源语言（仅 native，327.2B）。翻译模型 **Gemma-4-31B-it**（翻译/质检/重写），源文档选自 Nemotron-CC、每篇少于 4,096 Gemma-4 token、不切分；四阶段流水线：翻译 → 质量打分（0–100）→ 针对错误重写 → 终检，**阈值 75**（低于则重写，重写后仍需过检）。罗马化从 native-script 文本出发，用同一模型换 script-specific prompt 后重复质检流程。10 种低资源语言用 Bodhan-MT 翻译 + Gemma-4-31B-it 质检（语言特定阈值），Santali 用重叠窗口，Manipuri 由孟加拉文转写为 Meitei Mayek。流水线效率优化（并发翻译与质检、speculative decoding、FP8 权重、FlashAttention）把每百万英文输入 token 的翻译中位成本从 **0.835 降到 0.335 GPU-hours（约 −60%）**，等价每 GPU-hour 处理 2.49× token 量。

### 4. Long context 与 mid-training
- LC-Phase：1M token 上下文 CPT；Lightning 21B token（constant LR 1e-5，GB200，8-way CP/8-way TP/8-way EP/2-way PP），Super 35B token（constant LR 4.5e-6，GB300，16-way CP/8-way TP/64-way EP）。
- Mid-training（仅 Super）：**65.4B token @ 256K 序列长度**，LR reset 后线性 warmup 到 1e-5 后保持。数据配比：Issue–PR 41%、完整仓库 20%、pretraining replay 20%、agentic traces 10%（唯一 SFT 式数据，tool response 被 loss mask）、commit diffs 3%、build/CI logs 1%、long-context data 5%。所有数据对 SWE-bench 与 Terminal-Bench 去污染并移除 secrets。
- **长上下文恢复阶段**：256K mid-training 使 RULER-1M 从 79.9 掉到 33.5，故追加 **9B token** 恢复阶段（同样 recipe），RULER 恢复到 **81.0**。

### 5. 后训练
- **SFT（Super 两阶段）**：先混合 vision/reasoning/chat/long-context/safety/agentic 数据，再小规模第二阶段调整配比。Vision 数据来自 Nemotron 3 Nano Omni 语料 + Qwen3.5 生成的图表/grounded perception/GUI/多模态编码数据；agentic vision 用 Kimi K2.6/K3 生成工具操作与 SpatialClaw 轨迹（最终 **14,169 条轨迹、81,366 个 assistant action**）。Reasoning teacher：数学/STEM 用 Kimi K3、数学证明用 DeepSeek V4 Pro、竞赛编程用 GLM-5.2；过滤掉短于 5,000 token 的回答。训练：packed sequence 最长 524,288 token、global batch 32、LR warmup 后保持 1e-5、Adam β1=0.9/β2=0.95、weight decay 0.1、grad clip 1.0、两层共享权重 MTP 的 aux loss 系数 **0.3**。
- **RL**：RLVR + RLHF 联合，加入 **router replay** 与 **FP32 LM head** 两项优化，使训练与推理引擎的 KL error 降低一个数量级以上。global batch 8,192、每 sample 16 rollouts，最大生成长度先 80K 后提升到 128K。竞赛编程环境含 2,847 训练题 + 372 验证题（二值奖励）；finance-agent 环境基于 NeMo Gym 复刻 Vals.ai Finance Agent 的 SEC 检索/文档解析/证据检索工具。
- **Teacher 模型**：Agentic Teacher（64 prompts × 16 generations，batch 1024，每 rollout 超时 2 小时）；Reasoning Teacher（25,600 例课程，90% 科学/5% 数学/5% 竞赛代码，batch 256×16=4,096，max generation 131,072，LR 4e-6，取第 80 步）；Video reasoning/tracking teacher（128 prompts×16，batch 2,048，LR 3e-6 常数，128×GB200，取第 60 步）；Vision tool-use teacher；Vision reasoning RLVR（第一阶段 16,090 例，第二阶段 13,848 例 = 8,366 chart + 5,482 doc/table/OCR）。
- **Alignment teacher**：主要用 RLHF；用带 reasoning length penalty 的 Nemotron 3 Ultra GenRM 变体；与固定的 **Gemma 4 31B-it** 响应做对比（非循环自比较），按各 rubric 分的均值评分；混合 Nemotron 3 Ultra 的 abstention 训练策略。
- **MOPD（两阶段）**：学生为 RL 第 120 步 checkpoint；每个 token 由 domain teacher 给出 p_T，token-local 更新最小化 reverse KL：

```math
\hat{A}_t = \mathrm{sg}\left[\log \pi_T(y_t|c_t) - \log \bar{\pi}_S(y_t|c_t)\right]
```

```math
\Delta\theta \propto \mathbb{E}_{y\sim\bar{\pi}_S(\cdot|q)}\left[\sum_t \hat{A}_t \nabla_\theta \log \pi_S(y_t|c_t)\right]
```

其中 $\bar{\pi}_S$ 是更新前的冻结快照，stop-gradient；教师前向一次即给每个生成 token 稠密 advantage，无需 verifier、不从教师采样。异步训练下 token 按 $\bar{\pi}_S/\bar{\pi}_{S-1}$ 做重要性加权，权重落在 [0.2, 5] 之外的 token 被 mask。Stage 1：agentic 35% / reasoning 25% / alignment(RLHF) 20% / vision tool-use 15% + 5% self-anchor，batch 512 prompts、生成上限 48K（上下文 128K）、LR 2e-6、30 步。Stage 2：alignment 30% / vision tool-use 20% / vision reasoning 20% / video reasoning & tracking 20% + 10% self-anchor，batch 1,024、LR 3e-6、40 步；并用 trust-region policy distillation 的 proximal-teacher 平滑目标 $\alpha\pi_T + (1-\alpha)\bar{\pi}_S$（$\alpha=0.2$），把 advantage 下界限制在 $\log(1-\alpha)\approx-0.22$。
- **MTP boosting**：backbone 冻结，仅训 MTP head；先从 SFT checkpoint 训 4k steps，再用该 head 初始化最终 boosting 阶段再训 25k steps（Lightning 只做 48k steps boosting）；改用 **LK loss**（而非 Ultra 的 temperature-scaled forward-KL）；数据来自 Nemotron-Post-Training-Dataset-v2 与 Nemotron-RL-Super-Training-Blends，temp=1 采样、序列截断 8K token、只对 assistant 响应 token 累积损失。

### 6. 量化
- 发布配方为 "aggressive"：MoE 与 shared GEMM 用 NVFP4，attention projection 与 Mamba linear 用 FP8；whole-model BPE = $8S/N$，$S=74.987$ GB、$N=124.453$ B，得 **4.82 BPE**（含 vision/MTP/未量化模块，排除 runtime cache 与 activation）。
- **AutoQuant** 敏感度约束混合精度搜索：

```math
\min_{\{q_i\}}\sum_i S_i(q_i)\quad \text{s.t.}\quad \sum_i n_i b(q_i) \le \bar{b}
```

  $q\in\{\text{NVFP4},\text{FP8},\text{BF16}\}$，$S_i$ 由量化输出误差乘以平方任务损失梯度估计；Q/K/V 投影与 MoE 层内 routed experts 各自作为一个搜索决策。敏感度极不均匀：lm_head 占 NVFP4 敏感度近一半，attention 与 Mamba 投影次之，MoE experts 相对鲁棒。
- **QAD（量化感知蒸馏）**：从 PTQ checkpoint 初始化，只优化启用 quantizer 的 LM GEMM 权重，其余冻结（含 embedding、vision encoder/projector、MTP 模块），router-bias 更新显式关闭；目标为 KL，关闭 hard-target CE、MTP CE 与 MoE load-balancing 辅助损失；AdamW β1=0.9/β2=0.95/ε=1e-8、weight decay 0.1、grad clip 1.0；LR 从 0 线性升到 **5e-6**（9,100 条原始记录）后恒定；512×GB200，100 iterations ≈ 2 小时（1,024 GB200 GPU-hours）。校准用 512 个 packed 多模态样本（每条最长 524,288 token，packing buffer 含 5,000 源样本），PTQ 单候选约 50 分钟（≈27 GB200 GPU-hours）。权重 scale 选择比较 Max / MSE / MSE 4-over-6，**MSE 最优**（Score Recovery 100.06%）。

### 7. 推理与部署
- **ReplaySSM（checkpointing replay）**：Mamba-2 的递推状态 $S_{new}=\alpha S_{old}+k^\top v$、$o=qS_{new}$ 在 speculative decoding 中需为每个候选 token 写出状态，导致显存带宽瓶颈。方法：存 checkpoint $S_{ckpt}$ 与其后的 $k_i,v_i,\alpha_i$ 小缓冲，按

```math
S = \left(\prod_i \alpha_i\right) S_{ckpt} + \sum_i \left(\prod_{j>i+1}\alpha_j\right) k_i^\top v_i
```

  按需重建状态，不引入超出 $S_{ckpt}$ 的量化误差。
- **Mamba 细粒度 prefix checkpoint**：一个 Mamba cache page 至少占约 4K token 的 attention KV cache 字节数，导致 prefix 命中后仍需重放 $T-L_{page}$ 到 $T$ 的 token；作者在 speculative replay 边界附近额外保留一个 Mamba cache page（如把 checkpoint 放在 $T-16$ 而非 $T-L_{page}$）。
- **并行 drafter LiLiCorr**：在每个 block 位置保留 drafter body 边际分布的 top-K 候选，用小 Transformer 联合处理 $(B-1)\times K$ 候选 lattice，head 输出 unit-norm 的 out/in 向量，兼容度为余弦相似度：

```math
\varphi(s,k,k') = \sigma\,\cos(o_{s,k},\, i_{s+1,k'}),\qquad \hat{c}_s = \arg\max_k \varphi(s-1,\hat{c}_{s-1},k)
```

  drafter 1.13B 参数（其中 head 37M），block $B=8$（7 个 drafted slot），每层使用 DFlash2 风格的 grouped dynamic convolution。目标改为蒸馏目标模型的完整 next-token 分布（而非 CE），保留 DFlash 的指数位置衰减。

## 实验设置
- **评测工具**：NeMo Evaluator SDK + NVIDIA 开源 lm-evaluation-harness 容器（base 评测）；后训练评测用 **NeMo Gym**。
- **Agentic**：SWE-bench Verified / Multilingual / Pro（OpenCode harness，禁 web search/fetch，3 次平均 resolve rate）、Terminal-Bench 2.1（Terminus 2，3 小时任务超时，8 次平均）、τ²-Bench（Retail/Airline/Telecom，8 次平均，用户模拟器 Qwen3-235B-A22B-Instruct-2507）、τ³-Bench Banking（GPT-5.4-mini 作用户模拟器，BM25 + grep）、GDPVal-AA-v2、BrowseComp（NeMo Gym 开源 harness，Exa deep mode；400 题子集）。
- **数学/科学**：GPQA-Diamond（8 次）、MATH Arena Apex-Shortlist（16 次）、CritPt（70 题 × 5 samples）、HLE（2,158 道纯文本题，分无工具/有工具两种）、AA-Omniscience（600 题，10 次平均，GPT-5.6 Luna 评分）。
- **多模态**：BabyVision、CharXiv-RQ、MathVision、MMLongBench-Doc、OCR-Reasoning、OCRBench-v2、V*、Video-MME-v2。
- **Speculative decoding**：SPEED-Bench qualitative split，draft length 7，报告 per-sample acceptance length (AL)，temp=0（greedy）与 temp=1（probabilistic draft sampling）。
- **量化评测**：36 个 benchmark 的 median accuracy recovery 与 verbosity（completion token 数）。
- **硬件**：训练用 GB200/GB300；推理评测用 vLLM，20-turn agentic proxy workload（每轮 2K input / 1K output token，50k prefix），平台覆盖 A100、H100、B200、GB200、GB300、DGX Spark/Station、RTX。

## 局限性
作者自述的注意事项：
- Indic CPT 的评测只反映**合并阶段**效果，无法分离合成 Indic 文本与自然 Indic 文本各自的贡献；用同一模型（Gemma-4-31B-it）做翻译与评分可能偏好自己的翻译。
- Indic 配比消融在 Lightning 3.5 研究实验上进行，不能直接确定 Super 的最优配比；发布版 Lightning 并未包含 Indic CPT。
- 翻译效率提升仅适用于翻译环节，质检与重写另有成本。
- 精度推荐部分自述局限：未实验 W16A4，结论依赖具体 checkpoint。
- 部分 benchmark 使用内部实现与内部脚手架（BabyVision、CharXiv-RQ、MathVision、MMLongBench-Doc、OCR-Reasoning、OCRBench-v2、V*、Video-MME-v2、NV Chat Benchmark），跨模型比较的可复现性受限；BrowseComp 无标准 harness，结果随搜索引擎/工具/步数预算波动（仅用 400 题子集）。
- 文档内数字不一致：结论段写 NVFP4 精度恢复 99.52%、MTP boosting greedy 提升 10.1%，而摘要与正文为 99.62% 与 21.8%（probabilistic）。

我的批评：这是一篇典型的工业界"全栈 recipe"报告，方法新意集中在 MOPD、ReplaySSM、MTP boosting 与 AutoQuant，但这些组件的消融都不充分（例如 MOPD 的两阶段配比 35/25/20/15/5 与 30/20/20/20/10 无对照实验；AutoQuant 明确"被探索但未发布"）；同时大量对比结果是"同 harness 自评"，SWE-bench Pro 与 Terminal-Bench 2.1 上 Super 并非最优（落后 Qwen3.8 Flash-Next 明显），"超越 Nemotron 3 Ultra"的表述只在 SWE-bench Pro 一项成立。混合 Mamba-Transformer 的复杂度也带来工程负担（cache page 粒度粗、replay 开销大）。

## 评估与建议
- 是否推荐深入阅读：是（作为 MoE 混合架构 + agentic 后训练 + 量化/推理工程的一体化参考，尤其 MOPD、MTP boosting、ReplaySSM 三节）
- 适用场景：设计 agentic 模型的 SFT/RLVR/RLHF/MOPD 管线；混合 Mamba-Attention 模型的 serving 优化；NVFP4 量化与 QAD 配方设计；多语言（Indic）数据合成流水线搭建。
- 与知识库的关联：与 Mamba/SSM 混合架构、speculative decoding（LiLiCorr/DFlash/DSpark）、KV cache 量化（可与 2610.39853 对照）、多语言合成数据等相关笔记互补；也可作为长上下文 agent 的对照基线。
