## 核心贡献

> 提出 **steering agent** —— 一个监督 LLM agent / multi-agent 执行的 controller，**实时检测 goal drift + 介入纠偏**。**双路径**（fast / slow path）联合训练（pairwise ranking + GRPO），steering intelligence 可 OOD 任务 / unseen executors 迁移。

1. **Steering agent**：观察 execution context，决定**何时介入**（low-cost fast path）+ **如何介入**（high-cost slow path）。
2. **双路径联合 RL**：pairwise ranking（教何时介入）+ GRPO（教如何介入）。
3. **泛化性**：steering intelligence **跨 OOD 任务迁移**、**unseen executors 迁移**、**可控介入频率**无需重训。

---

## 技术方案

### Goal Drift 问题

- long-horizon tool use / multi-agent 协作中**执行漂移**（drift from overall goal）→ 浪费资源 / 偏离目标。
- 现有方案：fixed orchestration / hard-coded intervention rules → 不通用。

### Steering Agent 架构

```
                    ┌─────────────┐
   Context ────────►│ Steering    │─────► Fast: when? (low-cost)
                    │ Agent       │
                    └─────────────┘─────► Slow: how?  (high-cost)
```

- **Fast path**：判断**是否需要介入**（drift 信号）
- **Slow path**：决定**具体如何介入**（纠偏指令 / 中断 / 重启）

### 双路径训练

| 路径 | 训练目标 | 方法 |
|------|---------|------|
| Fast path | when to intervene | pairwise ranking（"这状态 vs 那状态，更需要介入？"） |
| Slow path | how to intervene | GRPO（group-relative policy optimization） |

**联合训练**（不是分离训练）→ 两路径相互适应。

### 推断时控制

- 可在**不重训**的前提下调整介入频率阈值。
- 提供可控 trade-off（drift 容忍度 vs 介入成本）。

## 局限与展望

- 仅 information-seeking 任务评估 → code agent / creative writing 等长 horizon 任务未验证。
- 双路径架构意味着**双推理成本**（即使 fast path 也有开销）。
- Steering agent 本身可能 drift → 需要 self-monitoring。
- 在 multi-agent 中如何决定"介入哪个 agent" 论文未详细。

## 实现建议

- **实现难度**: 中（需要 RL infra + 双路径 policy）
- **预期性能**: 对 long-horizon agent 显著 efficiency 提升
- **适用场景**:
  - 长时间 tool-use agent（code agent / research agent）
  - 多 agent 协作（dev team 模拟 / committee decision）
  - 高成本 tool 调用场景（节省 tool budget）
- **不适用**: 极短 horizon（fast path 开销相对过大）
- **工程提示**: steering agent 与 executor 可**解耦部署**（API 调用）→ 易集成

## 一句话总结

Steering agent 把 multi-agent 系统的 "drift 检测 + 纠偏" 学成可迁移的双路径策略（when + how），联合训练提升泛化，无需重训即可调介入强度。
