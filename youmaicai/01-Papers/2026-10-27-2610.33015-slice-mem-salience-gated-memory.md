## 核心贡献

> 用**非生成式**的在线流水线替代 LLM 生成式记忆构建，在几乎不损失准确率的前提下把 token 消耗降低 **92%–99.5%**。

1. **识别出记忆系统的成本结构问题**：LLM agent 的长期记忆需要在**准入（admission）**、**抽取（extraction）**、**组织（organization）** 三步反复调用 LLM 推理 → 大量成本与延迟。
2. **提出 SLICE-Mem 两个核心机制**：
   - **显著性门控准入**（salience-guided admission）：一个**紧凑分类器**判断哪些用户回合值得保留
   - **谓词中心信息抽取**（predicate-centered information extraction）：基于**语义依赖**的抽取器，把保留的回合转成简洁记忆条目
3. **架构关键**：**在线流水线完全不需要生成式 LLM 调用**；**跨条目调和（reconciliation）推迟到离线整合阶段**。
4. **结果**：在 Qwen3-30B 配置下对比生成式记忆基线 **MemOS**：
   - Memora Weekly：FAMA **46.60 vs 46.68**（几乎持平）
   - LongMemEval-S：准确率 **56.8% vs 59.3%**（小幅下降）
   - **总 LLM token 消耗降低 92.4% / 99.5%**

## 技术方案

### 核心思想

记忆构建的本质是「**筛 + 抽 + 理**」，但传统做法三步全用 LLM 生成完成。SLICE-Mem 的洞察是：**在线路径不需要生成能力，只需要判别能力**。

```text
用户回合
   │
   ▼
┌─────────────────────────┐
│ 紧凑分类器 (salience)     │  非生成式 —— 判断「值不值得留」
└─────────────────────────┘
   │ 保留的回合
   ▼
┌─────────────────────────┐
│ 语义依赖抽取器 (predicate) │  非生成式 —— 提取谓词中心条目
└─────────────────────────┘
   │ 记忆条目
   ▼
┌─────────────────────────┐
│ 离线整合 (consolidation)   │  生成式 —— 跨条目调和（不在热路径）
└─────────────────────────┘
```

### 关键技术

| 技术 | 说明 |
|------|------|
| **显著性门控准入** | 紧凑分类器筛出值得保留的用户回合 —— 用**判别**替代生成 |
| **谓词中心抽取** | 基于**语义依赖**结构提取记忆条目，而非自由生成摘要 |
| **在线/离线分离** | 在线零生成调用；跨条目调和挪到离线 —— **热路径成本大幅下降** |
| **FAMA 指标** | Forgetting-Aware Memory Accuracy —— 针对「记忆遗忘」的评估指标 |

## 实验结论

- **数据集**: Memora（weekly subset）、LongMemEval-S
- **基线**: **MemOS**（生成式记忆基线）
- **模型**: 8B 与 30B Qwen 骨干，用于记忆构建与整合
- **结果**:
  - Memora Weekly: **46.60 vs 46.68** FAMA（差 0.08）
  - LongMemEval-S: **56.8% vs 59.3%**（差 2.5 点）
  - **Token 消耗 −92.4% / −99.5%**

---

## 局限性

1. **准确率有下降**：LongMemEval-S 上 2.5 点的差距 —— 换来了 99.5% 的 token 节省，**性价比极高但非免费**
2. **离线整合阶段仍需生成式 LLM** —— 成本被推迟而非消除；整合质量对最终效果的影响未充分拆解
3. **紧凑分类器的训练数据与泛化性**未在摘要说明
4. 摘要未说明**延迟**的绝对数字（只给了 token 消耗）

## 实现建议

- **实现难度**: 中（需训练紧凑分类器 + 语义依赖抽取器；离线阶段沿用现有生成式流程）
- **预期性能**: Memora FAMA 几乎持平，LongMemEval-S −2.5 点，token −92~99.5%
- **适用场景**: **高请求量**的 agent 记忆系统 —— token 成本随请求量线性放大，节省 99% 是决定性的
- **落地注意**:
  1. 与 [[Agent Memory as Recommendation]]（零 LLM 调用）**二选一或组合**：SLICE-Mem 管「写入」，AgentMemRec 管「读取」
  2. 离线整合阶段应安排在低峰期

## 我的评注

> 数字很有说服力：**56.8% vs 59.3% 换来 99.5% 的 token 节省** —— 这是极高性价比的交易。Memora 上 46.60 vs 46.68 基本无损。
>
> 最聪明的是**在线/离线分离**这个架构决策。记忆系统天然被拆成「热路径」（每次交互都要跑）和「冷路径」（可以慢慢做）两类工作，很多设计把两者混在一起用 LLM 生成，于是热路径被拖垮。SLICE-Mem 重新划分后，热路径只剩**判别**任务。
>
> 与同批次 [[Agent Memory as Recommendation]] 正好构成互补：SLICE-Mem 优化**写入端**（构建记忆贵），AgentMemRec 优化**读取端**（选记忆贵）。两篇同批次出现，说明「agent 记忆的成本结构」已成为独立议题。两者结合是自然的工程选择。
