## 核心贡献
1. **提出核心问题**：能否**在模型解释完 skill 之后、在它生成或执行任何动作之前**检测恶意行为？这在"表层静态检查"与"昂贵的执行式分析"之间开辟了一个中间地带。
2. **发现 prefill 阶段的 hidden states 已包含"任务–操作一致性"的可读信息**，且在**未见过的表达形式**上仍然可预测（跨形式泛化）。
3. **用 matched Operation-state 干预证明功能影响**：替换操作相关的状态会**影响后续的 Boundary 状态**，并把固定的风险读数**推向供体（donor）的标签**——即这些状态不只是相关，而是有因果作用。
4. **提出 LatentTriad**，由三个分支构成，**共享同一次 prefill**：
   - **Boundary 分支**：读取完整上下文（最终 prompt 位置的状态）
   - **Operation 分支**：把操作性状态投影到学习到的风险方向上，并做**组内调整（group-adjusted）**
   - **Geometry 分支**：度量技能**声明目的、操作、上下文之间良性关系的偏离**
5. **完全 execution-free**：检测不生成任何输出 token、不调用任何工具、不执行任何 skill 提供的代码。
6. **主结果**：在 **5,830 个 skill 包**、**5 个来源数据集**、**7 个模型 backbone** 上，达到 **99.0–99.2% pooled F1** 与 **93.0–94.6% source-macro F1**。
7. **延迟**：一个单独测量的紧凑实现，prefill + 检测的**中位延迟 259–284 ms**，而基于沙箱的 SkillDetonate 报告约 **153 秒/技能**——约 **540× 的差距**。
8. **三种状态的形式化**（式 1）：对输入 $x$，令 $D(x)$、$O(x)$ 为分配给 Declaration 与 Operation 的 token 位置，$T$ 为最终 prompt token 位置。在第 $\ell$ 层：
   $$h^D_\ell = \text{mean}_{t \in D(x)} h_{\ell,t}, \quad h^O_\ell = \text{mean}_{t \in O(x)} h_{\ell,t}, \quad h^B_\ell = h_{\ell,T}$$
   对包检测，$D$ 覆盖 root front matter、标题与首个 prose 段；$O$ 覆盖其余 root 文本与可读的辅助文件。**这些与标签无关的 mask 遵循文档结构**，因此 $O$ 同时包含 prose 与代码。

## 问题背景

LLM agent 越来越多地通过可复用的 **skills** 扩展——即包含指令、脚本与配置的包，提供专门能力。公共 skill 生态已相当庞大（如 SkillsMP 索引超过 **318 万** 个公开 SKILL.md 文件）。但加载不可信 skill 也带来安全风险：其指令与可执行组件可能把 agent 引导到违反用户可信任务的操作。

检测困难的原因是**skill 风险是上下文依赖的，且可能分布在多个组件之间**。单独看benign的指令、脚本与配置，联合起来可能诱导出一个未授权操作；而敏感操作（文件或网络访问）在任务需要时又是合法的。因此基于关键词或代码模式的静态规则难以捕捉**行为意图**。动态分析提供更强的行为证据，但需要生成、沙箱执行与运行时监控，对大规模筛查而言过于昂贵。

论文的威胁模型设定非常具体：攻击者控制 skill 包，寻求可信任务之外的操作（凭据外泄、未授权文件修改），可以跨文件分发或混淆内容，但**不能修改可信 prompt、模型权重、运行时 hook 或检测器标签**；防御者控制 prompt 组装与动作权限，对 hidden states 有**白盒访问**，在生成或工具使用前筛查已加载输入；**运行时强制执行 verdict**（因为文本拒绝不保证工具调用安全）。

论文强调一个具体的例子：备份任务可以授权读取项目文件并写入某个批准目录；一个把文件上传到配置所指定目标的脚本就**跨越了边界**，即使声明仍承诺本地备份。**检测器需要任务、脚本、目的地三者齐备；声明提供的是主张，不是授权。**

## 方法

### 1. 三种状态的定义

- **Declaration**：描述 skill 的**声明目的**（root front matter、标题、首个 prose 段）
- **Operation**：包含其**操作指令、脚本、配置与可读的辅助内容**（其余 root 文本 + 可读辅助文件）
- **Boundary**：完整任务与 skill 之后的**最终 prompt 位置**，生成之前

三者都用 mean-pooling 或位置采样得到（式 1），构成 $h^D_\ell$、$h^O_\ell$、$h^B_\ell$。$B$ 被明确说明为**采样位置，不是授权变量**。

### 2. 跨表达形式的泛化性检验（§3.1）

研究使用 **800 个 task–operation 样本**，跨 **10 个领域**、**4 种形式**（自然语言、Python、JSON、混合文本）。用 **5 个按领域分组的 fold** 把相关变体放在一起（避免泄漏）。在 Llama-3.1-8B、Qwen2.5-7B、Mistral-7B-v0.3 上拟合紧凑的 **32 维** $D$、$O$、$B$ 诊断读出（固定 probe 容量以隔离不同深度的表示内容、避免过拟合），**不使用测试数据**。每个留出的形式同时不在训练与开发集中，其测试样本也来自留出领域——这**把"迁移到新表达形式"与"认出拟合时见过的变体"分离开**。

**结果**：
- 在 Llama 上，$O$ **更早变得可预测但在后期层变弱**；$B$ **在所有层都高度可预测**（不同深度上 O 与 B 承载的风险信息不同）。
- 所有形式都在训练集中时，$B$ 与 $O$ 达到 **98.86–100.00% 的 out-of-fold AUROC**，而 **Declaration、TF-IDF 与长度控制在接近随机**。
- 每个测试形式被留出训练与开发后，**Boundary AUROC 仍在 90.09–100.00%**。
- 论文指出：即使形式变化主导整个向量的距离，风险仍可读——这正是需要**学习式读出**而非原始距离阈值的原因。

论文也谨慎处理 Declaration 的近随机结果：这**不使声明变得无关**，因为它的声明目的仍可为解释操作性内容提供参照；$O$ 与 $B$ 的不同轨迹显示**为何单一端点不必同等暴露每个预测方向**。

### 3. Operation 状态影响后续计算（§3.2）

可读性本身不建立下游影响。论文用**匹配的 donor** 替换 $O$（donor 按行为匹配），做受控状态干预：改变与 skill 操作相关的表示会**改变后续的模型状态**（Boundary）与**风险预测**，并把固定风险读数**推向 donor 的标签**。

### 4. LatentTriad 三个分支

| 分支 | 输入 | 作用 |
|------|------|------|
| **Boundary** | $h^B$ | 读取完整上下文 |
| **Operation** | $h^O$ | 投影到学习到的风险方向；**组内调整**（group-adjusted） |
| **Geometry** | 三者关系 | 度量相对良性参考图的**偏离**（departures from benign state relationships） |

**Geometry 分支**的思路值得注意：它不直接看单个状态，而是看**声明目的、操作、上下文之间的关系**是否偏离良性地图（benign reference map）。这与论文的核心论断一致——风险是"任务–操作一致性"问题，是**关系**而非单点属性。

所有分支**共享一次 prefill**。检测不生成输出 token、不调用工具、不执行 skill 代码。

### 5. 评估

5,830 个 skill 包，5 个来源数据集，7 个模型 backbone。此外做 **source-holdout**（跨生态系统的泛化）与 **composition study**（任务依赖的 skill 组合）。

## 实验结果

- **Dataset/Task**: 5,830 个 skill 包 / 5 个来源 / 7 个 backbone；受控研究另用 800 个 task–operation 样本 / 10 领域 / 4 形式 / 5 折。

- **Main results**:

| 指标 | 值 |
|------|-----|
| Pooled F1 | **99.0–99.2%** |
| Source-macro F1 | **93.0–94.6%** |
| 紧凑实现的 prefill + 检测中位延迟 | **259–284 ms** |
| SkillDetonate（沙箱基线）报告延迟 | **~153 s/技能**（约 540×） |

  跨形式 AUROC（受控研究）：

| 配置 | AUROC |
|------|-------|
| 所有形式在训练集中，$B$ / $O$ | **98.86–100.00%** |
| 留出某形式后，Boundary | **90.09–100.00%** |
| Declaration / TF-IDF / 长度控制 | **接近随机** |

- **Ablations**: (1) **跨表达形式留出**（核心泛化性检验）；(2) **matched Operation-state 干预**（因果影响证据）；(3) **mask 敏感性测试**（Appendix G.3）；(4) **source-holdout** 评测（跨生态泛化）；(5) **composition study**（任务依赖的 skill 组合）；(6) **深度扫描**（AUROC 随层变化，Figure 3）；(7) **可选的 source attribution**（右面板，识别风险来自哪个来源）；(8) **紧凑实现的延迟单独测量**（与主 F1 实验分离）。

## 关键洞察

1. **"检测窗口"的重新定义是最有价值的贡献**：不需要执行 skill，也不只需要看表面文本——**prefill 之后的 hidden state 已经是一个足够好的证据源**。这把 agent 供应链安全的成本从"沙箱执行"（秒级/技能）降到"一次 prefill"（百毫秒级），使**大规模筛查在工程上可行**。
2. **风险是关系属性，不是文本属性**：论文的 backup 例子说明，一个上传脚本在**声明承诺本地备份**时就已经越界。因此检测器需要**任务 + 脚本 + 目的地三者齐备**；声明提供的是主张而非授权。Geometry 分支正是把这一点做成了机制。
3. **$O$ 与 $B$ 的深度轨迹不同，解释了为何单一端点不够**：$O$ 早期可预测但后期变弱，$B$ 全程稳定。这提示单一层的读出会丢失预测方向——这是"多层/多位置读出"的实证依据。
4. **形式变化主导向量距离但风险仍可读** → **必须用学习式读出，不能用原始距离阈值**。这是一个可以直接推广到其他"表面形式变化但语义不变"检测任务的设计原则。
5. **可读性 + 干预证据的双重论证**：论文没有停在"状态里含有信息"（相关），而是补上了 matched intervention 证明这些状态对后续计算有**功能影响**。这个组合使结论比单纯的 probe 结果强得多。
6. **Declaration 近随机并不矛盾**：声明是"主张"，其价值在于为解释操作性内容提供参照（Geometry 分支的用法），而非直接承载风险标签。这个区分避免了把"declaration 不含风险信号"误读为"声明无用"。

## 局限性

- **依赖白盒 hidden states**：防御者需对 hidden states 有白盒访问。这排除了纯 API 场景（GPT/Claude 等托管模型无法取 hidden state）。
- **仍需 prefill**：虽然比执行便宜，但 prefill 长 skill 包的开销随包大小增长；259–284 ms 是"紧凑实现"的中位数，实际更大或更复杂的包未测。
- **检测的是"任务–操作不一致"，不是"恶意"**：论文的 framing 是行为授权边界而非恶意意图。一个奇怪但无害的 skill 也可能被标记；误报代价未充分讨论。
- **阈值与 F1 是在标注数据上选的**：5,830 个包 / 5 个来源 / 7 个 backbone 的 F1 很高（99%），但**在新的、训练分布外的 skill 生态上**是否会退化，取决于 source-holdout 的结果（论文提到该研究但摘要未给出数字）。
- **只能检测执行前可观测的风险**：论文明确承认"只在后续下载或环境交互中才显现的效果需要运行时检查"。
- **干预实验是受控的**：matched donor 替换是人工构造的，其结论向真实攻击场景的外推有限。
- **未评估对抗性规避**：攻击者知道检测器存在时，能否构造出既触发风险又让 prefill 状态不可读的 skill 包？论文的威胁模型假设攻击者不能修改模型权重或标签，但**可以自由设计内容**——这是一个未触及的对抗维度。
- **32 维 probe 是在三个模型上拟合的**：跨模型迁移性（用 A 训练的 probe 在 B 上用）未报告。
- **组合风险（composition）的评估规模不明**：多个良性 skill 联合诱导出未授权操作的场景是论文强调的难点，但摘要未给出该研究的具体数字。
- **延迟对比不完全公平**：259–284 ms 与 153 s 的对比是"紧凑实现 vs 沙箱基线"，但两者检测的判据、覆盖的 skill 类型与误报率不同。
- **无公开的威胁模型对照**：未与 SkillScanner、SkillFortify、SkillScan、SkillSieve、RouteGuard 等已有检测器在同一数据上做定量对比（论文有定性表格 Table 1）。

## 适用场景

**适用**：
- **agent skill 供应链安全**：在加载第三方 skill 前做大规模筛查（marketplace 审核、企业内部 skill 仓库审计）。
- **对成本敏感的实时筛查**：需要"生成任何 token 之前"就给出 verdict 的场景。
- **多文件 skill 的整体分析**：需要把声明、指令、脚本、配置一起考虑的场景（单文件静态检查做不到）。
- **机制可解释性研究**：pre-action hidden state 是否编码"授权边界"这一问题本身有价值。
- **白盒部署的本地/自托管 agent**：可访问 hidden states 的部署形态（开源模型、本地推理栈）。

**不适用**：
- **托管闭源模型 API 场景**（无 hidden state 访问）。
- **需要检测"执行时才显现"的风险**（如按需下载的 payload、环境相关的行为）。
- **强对抗性攻击者**场景（本文未做对抗性评估）。
- **判定"恶意意图"而非"行为越界"**的任务。
