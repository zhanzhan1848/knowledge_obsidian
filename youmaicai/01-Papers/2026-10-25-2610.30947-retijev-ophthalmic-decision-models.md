## 核心贡献

> 眼科临床决策支持需要**快速、准确、隐私保护**的推理，但**自回归 LLM 在「从预定义动作中做选择」这类任务上延迟与算力开销都很高**。RetiJev 提出**面向决策（decision-oriented）的替代方案**：不做生成式推理，而是**直接给候选答案打分**；配套发布 **RetiJev-Data**（source-grounded 眼科语料）与 **0.8B–9B 的 RetiJev 决策模型族**。

1. **提出「决策式」范式替代生成式推理**：模型**不进行 autoregressive decoding**，而是**直接对候选答案打分（directly score candidate answers）** —— 与 [[2026-10-25-2610.31586-llm-spanish-mir-residency]] 中「不确定性不可靠、图像未被使用」的诊断形成呼应。
2. **发布 RetiJev-Data：source-grounded 眼科语料**：
   - **78,158** 条**临床决策与诊断问题**，源自 **PubMed Central** 的文章；
   - 配套 **MeSH 词表**，覆盖 **531 种眼病**；
   - **50,074** 条**指南分级（guideline-grading）问题**，覆盖 **11 套分级系统**；
   - 另有 **24,662 题的评测基准**。
3. **RetiJev 模型族（0.8B–9B）**：在**所有模型规模上**，指南分级任务均**超过一个 27B LLM 与商用 Jev 1.13 决策模型 10.4–23.0 个点**。
4. **临床决策任务**：**RetiJev-9B 取得最高准确率**，相对两个基线**提升 5.4–6.5 个点**，同时在**诊断任务上与基线持平**。
5. **延迟优势**：**单 GPU 上 158 ms** 回答一个病例 —— 比 **LLM 生成快 3.5 倍**，比 **reasoning（推理模型）快 470 倍**。

## 技术方案

### 核心思想

**观察**：很多医疗「LLM 应用」其实并不需要生成 —— 给定一个病例和一组**预定义动作**（诊断、处置、分级选项），需要的是**哪个最对**。这是**排序/选择问题**，不是**生成问题**。用自回归 LLM 做选择，等于**用最贵的解码过程去输出一个标签**。

**RetiJev 的做法**：
- 训练一个**决策模型**：给定问题与候选项，**直接输出各候选的分数**，不逐 token 解码；
- 因此**延迟与输出长度无关** —— 这就是 158 ms 的来源，也是 3.5×/470× 的来源。

**Source-grounded 的含义**：训练数据来自 **PubMed Central 的真实文献**（source-grounded），而不是合成 —— 每个答案可溯源到文献依据；MeSH 词表提供**531 种眼病的标准化疾病实体**，支持实体级标注与泛化。

**两级任务设计**：
| 任务 | 规模 | 难度性质 |
|------|------|---------|
| **Guideline grading（指南分级）** | 50,074 题，11 套分级系统 | 需理解**分级标准**（如严重度分级）与影像/临床表现对应 |
| **Clinical decision（临床决策）** | 78,158 题 | 需从动作集中选出恰当处置 |
| **Diagnosis（诊断）** | 同上语料 | 需给出疾病名称 |

**评测基准独立**：24,662 题的评测集与训练数据分离，用于验证泛化。

### 关键技术

| 技术 | 说明 |
|------|------|
| **Decision-oriented modeling** | 直接对候选答案打分，取代生成式推理 |
| **No autoregressive decoding** | 推理延迟与生成长度解耦 |
| **RetiJev-Data** | source-grounded 眼科语料（PubMed Central 派生） |
| **MeSH vocabulary (531 diseases)** | 标准化疾病实体词表，支持实体级标注 |
| **Guideline-grading questions (11 systems)** | 覆盖 11 套临床指南分级体系 |
| **RetiJev model family (0.8B–9B)** | 覆盖多个规模，含决策专用小模型 |
| **Jev 1.13 (commercial baseline)** | 商用眼科决策模型对照 |
| **27B LLM baseline** | 生成式大模型对照 |
| **Reasoning model baseline** | 推理型模型对照（延迟差距达 470×） |
| **Single-GPU inference** | 单 GPU 158 ms / 病例 |
| **Privacy-preserving deployment** | 小模型自托管，医疗数据不出域 |

## 关键结论

1. **「决策」与「生成」应当用不同的模型范式。** 在**预定义动作集上的选择**这一任务上，0.8B–9B 的打分模型**全面超过 27B LLM 与商用决策模型 10.4–23.0 个点**，且**延迟快 3.5–470 倍**。用生成式 LLM 做分类是**范式错配**。
2. **延迟优势随基线能力提升而放大。** 对比 reasoning 模型时达到 **470 倍** —— 越是「让模型多想」的基线，代理解码的开销越大，而 RetiJev 的成本**与输出长度无关**、是常数。
3. **Source-grounded 数据 + MeSH 实体词表是性能的可能来源。** 531 种眼病的标准化实体 + PubMed Central 溯源语料，使小模型能学到**临床分级的细粒度判据**；这也是**指南分级提升最大（10.4–23.0 点）**这类知识密集任务的原因。
4. **诊断任务上「持平」而非「超越」是有信息量的。** 诊断是**开放生成**式的（病名有无穷多种），打分模型的表达力受限；而**分级与决策是闭集的** —— 这印证了「闭集决策适合打分模型，开放诊断仍需生成模型」的分工判断。
5. **对自建部署的卫生系统，这是可落地的形态**：小模型 + 单 GPU + 158 ms + 数据不出域，同时**隐私与成本**两项约束同时满足。

## 局限性

- **「诊断任务持平」意味着该范式不覆盖所有眼科任务** —— 摘要未说明是否有闭集设定下的诊断评测，或是否计划扩展。
- **候选动作集的构造方式未披露** —— 打分模型需要一个候选池，**候选从哪来（MeSH？指南枚举？检索生成？）** 是复现的关键，摘要未给。候选池大小也未报。
- **关键数字的对照口径不清**：指南分级上「10.4–23.0 个点」是**哪个基线、哪个模型规模**的对比（摘要说「outperforms both a 27B LLM and the commercial Jev 1.13」，但逐项对应关系不明）；临床决策的 **5.4–6.5** 同理。
- **延迟数字的对比条件未给**：158 ms 是**哪个模型规模**、batch size、输入长度、GPU 型号、是否含检索；**3.5×/470×** 的基线延迟绝对值未给，无法判断是否公平。
- **评测基准与训练语料同源**（PubMed Central 派生）—— **可能存在分布重叠与泄漏风险**，摘要未说明 24,662 题评测集与 78,158 / 50,074 训练题的**去重与切分策略**。这是本文最需要核实的可信度点。
- **未报告与真实眼科医生或指南委员会一致性的对照** —— 「超过基线」不等于「临床正确」；缺少**专家金标准**校验。
- **未涉及多模态**：眼科高度依赖影像，本文**全是文本问题**（摘要未提影像），这大幅限制了实际可用性，也解释了为何诊断任务只是持平。
- **未评估不确定性/弃答** —— 恰好是 [[2026-10-25-2610.31586-llm-spanish-mir-residency]] 发现的开源模型最弱环节，本文避开了这一维度。
- **无外部第三方复现**；仅提供 GitHub 仓库与模型，未见独立评测。

## 实现建议

- **实现难度**：中（打分式决策模型的训练与候选集构造需要自己补齐；数据与模型已开源）
- **预期性能**：指南分级超 27B LLM / Jev 1.13 **10.4–23.0 点**；临床决策（9B）**+5.4–6.5 点**、诊断持平；**158 ms/病例（单 GPU）**，比生成快 **3.5×**、比 reasoning 快 **470×**
- **适用场景**：**医院自建部署的眼科决策支持**（分级、处置选择）；**隐私敏感的院内推理**；作为 LLM 的**前置快速路由/预筛层**
- **团队行动**：
  1. 优先落地**闭集分级/决策**任务（收益最大），把**开放诊断**继续交给生成式模型；
  2. 复现时**必须核查评测集与训练语料的去重与切分**，否则 10.4–23.0 的增益可能大幅缩水；
  3. 补做**专家金标准校验**，不要只比基线；
  4. 若要从零做决策模型，参照 [[2026-10-25-2610.30970-compact-encoders-closed-set-decisions]]：**从 reranker 式初始化出发**，否则 per-option/候选打分的优势可能消失
