## 核心贡献

> LLM agent 默认每步都做 reasoning，浪费算力。RACE 用**去除 reasoning 后后续 action likelihood 下降**作为信号判断"何时 reasoning 已足够、何时需要新 reasoning"，跨 4 个 agent benchmark 大幅降低 reasoning cost 同时保持 / 提升任务性能。

1. 提出 **RACE**（Reasoning Adaptation through Cross-Turn Estimation）：基于**轻量信号**估计 cross-turn action support，决定何时 reasoning、何时直接 act。
2. 关键观察：**删除一段 reasoning 后 reference action 的 likelihood 下降幅度**，与该 action 是否"可被早前 reasoning 恢复"高度相关——这是一个无 generation-based verification 的轻量信号。
3. 设计 **LoGiC**（Likelihood-Guided Progressive Reasoning Cover Detection）：渐进式识别"移除影响有限"的 reasoning turn。
4. 把信号融入 SFT + agentic RL，让 policy 学会"该想时才想"。
5. 在 4 个 agent benchmark 上大幅**降低 reasoning cost** 同时**保持 / 提升**任务性能。

---

## 技术方案

### 核心思想

LLM agent 通常每步都做 reasoning（think → act），但 reasoning 是昂贵的——尤其是当早前的 reasoning 仍然有效时。判断"何时 reasoning 已足够"是开放问题。传统 RLF 验证靠 generation-based rollout（昂贵）。本文发现一个**轻量信号**：删除一段 reasoning 后，reference action likelihood 的下降幅度 ≈ 该 reasoning turn 对后续 action 的真实支持度。基于此，无需 rollout 即可判断 reasoning 是否可省略。

### 关键技术

| 技术 | 说明 |
|------|------|
| Cross-turn action support estimation | 用 likelihood 下降估"未来 action 对当前 reasoning 的依赖" |
| LoGiC procedure | 渐进式检测"移除影响有限"的 reasoning turn |
| SFT + agentic RL integration | 把推理必要性信号融入 SFT + RL 训练目标 |
| Adaptive reasoning policy | 模型学会"该想时才想"，避免每步都 think |

### 训练流程

```
Step 1: 正常 rollout（每步都 reasoning）
Step 2: LoGiC 检测哪些 turn 的 reasoning 是"可省略的"
Step 3: 把"可省略"信号作为训练目标：
  - SFT：用标注的"何时该 reasoning"训练策略
  - RL：reward 包含 reasoning cost 维度
Step 4: 训练 → 自适应 reasoning 策略
```

### 与传统方法对比

| 方法 | 验证信号 | 成本 | 决策时机 |
|------|---------|------|---------|
| 固定每步 reasoning | 无 | 高 | 不决策 |
| Generation-based verify | rollout 输出 | 很高 | 每次 |
| **RACE (likelihood-based)** | **action likelihood drop** | **低** | **实时** |

---

## 实验结果

- **4 个 agent benchmark**：reasoning cost 大幅降低
- 任务性能：保持 / 提升
- 无需 generation-based verification，**毫秒级**决策
- SFT + RL 两阶段训练均有效

---

## 关键 takeaway

- **Reasoning 应是有成本的资源**：agent 设计不应是"免费 think"，而是"按需 think"。
- **Likelihood-based 信号**远轻量于 generation-based verification，是 agent 推理优化的关键洞察。
- 跨 turn 的 reasoning 复用是 agent 效率的关键——**一次推理支持多个 action**。

---

## 局限性

- 仅在 agent 场景验证，单轮对话 / 离线推理未涉及
- LoGiC procedure 需要 reference action，可能不适用无监督场景
- "Reasoning cost 降低"的 trade-off 与具体任务难度有关
