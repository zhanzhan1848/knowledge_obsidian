## 核心贡献

> **任务中心（task-centric）视角的综述**：不按架构/技术路线组织，而是按"任务瓶颈如何决定技术选择"来组织长文档 VQA，把它拆成四个组件并逐个建立细粒度分类。

1. **四组件分解**：长文档 VQA 被分解为 ① **document parsing**、② **evidence organization and retrieval**、③ **generator organization and learning**、④ **evaluation**
2. **每个组件配套细粒度 taxonomy**，并追溯其 **motivations、technical responses、cross-component connections**
3. **聚焦显式检索（explicit retrieval）**，同时覆盖直接阅读（direct reading）
4. **时间线分析**：研究重点从"多模态内容理解" → "**充分且高保真的证据获取**" → "**持续的证据管理**"
5. **未来方向**：① 证据充分性（evidence sufficiency）、② 可验证且可纠正的理解（verifiable and correctable understanding）、③ 预算感知的协同（budget-aware coordination）
6. **展望持续文档理解**（continual document understanding）

## 技术方案

### 核心思想：任务瓶颈决定技术选择

| 传统综述 | 本文综述 |
|----------|----------|
| 按**架构**或**技术方法**分类 | 按**任务瓶颈**分类 |
| 关注"用了什么模型" | 关注"瓶颈是什么 → 因此该做什么技术选择" |
| 组件间关系作为附注 | **cross-component connections** 作为显式分析维度 |

### 四组件 taxonomy

| 组件 | 关注的问题 | 摘要明确的范围 |
|------|-----------|----------------|
| ① Document parsing | 视觉丰富的文档如何被切分与结构化 | 解析质量决定下游证据可得性 |
| ② Evidence organization and retrieval | 证据如何被组织与检索 | **聚焦 explicit retrieval**，同时覆盖 direct reading |
| ③ Generator organization and learning | 生成器如何组织与学习 | 证据如何被注入 / 训练 |
| ④ Evaluation | 如何评估 | 独立成组件 |

### 时间线：优先级的三次迁移

```
多模态内容理解
      ↓
充分且高保真的证据获取   ← 关注点：证据够不够、忠不忠实
      ↓
持续的证据管理           ← 关注点：证据随时间/流程的维护
```

### 关键技术（综述所覆盖的技术族）

| 技术 | 说明 |
|------|------|
| Explicit retrieval | 从长文档中显式检索证据作为主要范式 |
| Direct reading | 直接阅读整篇长文档，与检索形成对照 |
| Evidence organization | 证据的组织形式（层次化、结构化） |
| Generator learning | 生成侧的学习策略 |
| Evidence sufficiency | 未来方向：判断证据是否充分 |
| Verifiable & correctable understanding | 未来方向：理解可验证、可纠正 |
| Budget-aware coordination | 未来方向：解析/检索/生成之间的预算分配 |
| Continual document understanding | 展望：持续演化的文档理解 |

## 关键结论

1. **长文档 VQA 的瓶颈已从"看懂"转向"取证"**：研究重点从多模态内容理解迁移到"获取**充分且高保真**的证据"，再到"**持续管理**证据"。这意味着"更强的 VLM"本身不是主要瓶颈。
2. **显式检索与直接阅读是两条并行路径**，综述以前者为主线但不排除后者 —— 说明"是否需要检索"在长文档场景仍无定论。
3. **组件之间存在系统性耦合**：证据的组织方式直接约束生成器能学到什么，评测方式又反过来定义了"充分"的含义。
4. **未来方向指向可验证性**：evidence sufficiency + verifiable/correctable understanding 是两个相互支撑的方向 —— 只有能判定证据是否充分，才谈得上纠正理解。

## 局限性

- **综述本身**：无新实验、无新基准，结论的强度取决于被覆盖文献的完备性
- **聚焦 explicit retrieval** —— 直接阅读路线的覆盖被作者自述为"覆盖但非重点"，可能低估了长上下文模型直接读的现状
- 摘要**未列出所覆盖的具体数据集、模型、taxonomy 层级数**，正文 6 表才含这些细节
- **代码/资源未提供**
- 未见中文/非英语长文档 VQA 的系统讨论（摘要未提及）

## 实现建议

- **实现难度**: 低（阅读型工作）
- **适用场景**: 立项长文档 VQA / 文档理解项目时，用作**技术选型框架**而非算法参考
- **落地用法**:
  1. 用四组件分解**定位自己项目的瓶颈**（parsing / retrieval / generator / evaluation）—— 大多数团队其实卡在 ② 和 ④
  2. 未来方向中的 **evidence sufficiency** 最值得直接借用为**自检项**：答案生成前先判"证据够不够"
  3. **verifiable & correctable understanding** 与 2026-10-24 日报中的 SARL（自省）、RIPPLE（恢复内化）思路一致 —— 可组合成"证据充分性判据 + 恢复策略"
- **与其他笔记联动**: 与 [[2026-10-25-2610.31606-ground-truth-shapes-retrieval-scores]] 合看：后者提供了 ② evidence retrieval 的**评测口径陷阱**（标注覆盖影响分数），正好是本综述强调"充分性"却缺工具的缺口
