# MEMOIR: A Training-Free Memory Lifecycle for Long-Horizon LLM Agents

> **arXiv**: [2611.07631](https://arxiv.org/abs/2611.07631)
> **发表日期**: 2026-11-05
> **分类**: cs.IR
> **会议/期刊**: arXiv preprint

## 📋 摘要

长程（long-horizon）LLM agent 需要跨会话保存有用信息并在需要时取回的记忆系统。现有系统把"写入"与"取回"当作两个独立问题：记忆以**前瞻性**方式写入，带有**静态重要性分数**，使用后从不修订。这导致两个耦合的失效模式：**合并（consolidation）会静默销毁未来查询所需的证据**，同时**检索仍偏向陈旧记忆**。作者提出 MEMOIR（Memory Evidence via Merge-certified, Online Importance Revision），一个**免训练（training-free）**的记忆生命周期，统一了**judge-gated consolidation** 与**回溯式归因（retrospective attribution）**：压缩记忆前，筛选门（screening gates）检验答案相关证据是否被保留；每次查询后，归因（attribution）估计哪些被检索到的记忆支撑了答案，并更新其检索优先级；一个 **UCB 风格的探索奖励**额外鼓励取回"曝光不足"的记忆，降低高频记忆挤占少见但有用证据的风险。在 **1,905 条去重后的 LoCoMo QA 对**上，完整检索栈相对裸余弦把 evidence recall@5 提升 **11.92 个百分点**，其中 confidence-gated feedback 在无需参考答案、无需训练 reranker 的前提下再贡献 **1.50 个百分点**；一个部署时不可得的 oracle 再贡献 **1.84 个百分点**（多跳上 **8.05 个百分点**）。judge-gated merge 把文本证据召回率从 **58.82% 提升到 59.08%**，活跃存储减少 **1.42%**，在 100 次独立审计的合并中**观察到 0 次损失**（单侧 95% 损失率上界 **2.95%**）。作者据此勾勒出可部署路径：**在线写入路径不增加额外 LLM 调用**，合并筛选仅限周期性的离线整合。

## 🎯 核心贡献

1. **统一"写入"与"取回"的记忆生命周期**：提出 MEMOIR，把 judge-gated 合并与在线重要性修订合并为一套机制，破解现有系统"写入前瞻、评分静态"的根本缺陷。
2. **回溯式归因（retrospective attribution）**：查询后估计"哪些被检索的记忆真正支撑了答案"，据此在线更新检索优先级——用**实际使用效果**而非先验重要性来决定优先级。
3. **合并保真门（judge-gated merge / screening gates）**：压缩记忆前先检验"答案相关证据是否被保留"，从机制上防止合并静默销毁证据。
4. **UCB 式探索奖励**：显式抑制"高频记忆挤占少见但有用证据"的马太效应——这是纯基于使用频率的检索器系统性的失效点。
5. **可部署性证明**：在线写入路径零额外 LLM 调用（归因复用已有调用），合并筛选放到离线周期性整合，兼顾效果与成本。

## 🔧 方法/架构

- **免训练（training-free）**：无 reranker 训练、无参考答案依赖。
- **写入侧 — Judge-gated consolidation**：合并前由 screening gates 判断"是否保留了回答相关的证据"；判定通过才允许压缩。
- **读取侧 — Retrospective attribution**：每次查询后，对被检索到的记忆做归因，估计其对答案的贡献，并据此更新检索优先级（online importance revision）。
- **检索侧 — UCB-style exploration bonus**：对"曝光不足（under-exposed）"的记忆给予探索奖励，平衡利用与探索。
- **部署拓扑**：
  - 在线写入路径：**0 次额外 LLM 调用**；
  - 合并筛选：仅在**周期性离线整合**时执行。

## 📊 实验结果

- **LoCoMo（1,905 条去重 QA 对）**：
  - 完整检索栈 vs 裸余弦：evidence recall@5 **+11.92 个百分点**；
  - confidence-gated feedback：**+1.50 个百分点**（无需参考答案、无需 reranker 训练）；
  - 部署不可得的 oracle：**+1.84 个百分点**（overall），多跳上 **+8.05 个百分点**。
- **Judge-gated merge**：
  - 文本证据召回率 **58.82% → 59.08%**；
  - 活跃存储 **-1.42%**；
  - 100 次独立审计合并中**观察到 0 次损失**，单侧 95% 损失率上界 **2.95%**。
- 记忆生命周期覆盖：写入（合并）与读取（归因+探索）双侧。

## ⚠️ 局限性

- 评测仅覆盖 LoCoMo 一个对话记忆基准，跨领域（文档、代码库、工具轨迹）泛化未验证。
- Judge-gated merge 的"0 损失"基于 100 次审计样本，样本量偏小，仅给出 2.95% 的单侧上界——统计上仍允许约 3% 的合并损失率。
- 归因环节依赖 LLM 判断"哪条记忆支撑了答案"，在归因错误时优先级更新会放大偏差（错误归因 → 错误排序 → 错误归因的反馈回路）。
- UCB 探索奖励会主动检索"少见"记忆，可能引入额外延迟与噪声，尤其在记忆库极大时。
- "在线写入路径无额外 LLM 调用"的代价是归因质量受限于已有调用的信息量；摘要未澄清归因具体复用哪一步调用。
- 摘要未披露绝对数值（仅给出相对裸余弦的百分点提升）与总体成本/延迟开销。

## 💡 建议

- 是否推荐使用：**推荐**
- 适用场景：需要长期记忆的陪伴型/助理型 agent、多会话客服、跨天任务追踪；可直接作为现有 memory 层（MemGPT/Letta 类架构）的增强模块部署，尤其适合"记忆合并后证据丢失"与"高频记忆霸屏"两类线上问题。核心落地顺序建议：先上 attribution + exploration（收益大、风险低），再上 judge-gated merge（需配合离线审计）。
