## 核心贡献
1. **提出 MobileSpec 系统**，实现"generalist–specialist"部署范式：设备上只保留**一个 INT4 generalist**，每个任务只额外存一个 **1–5 MB** 的 specialist 文件；切换任务时 generalist 与 kernel 完全不变。
2. **提出核心算法 FuRA-S（Full-Rank Adaptation–Spectra）**：只用前向传播、只训练预训练权重的**块谱坐标**（block-spectral coordinates，即各列块在**未截断 SVD** 下的奇异值）。在 Qwen2.5-1.5B 上约占 **0.03%** 的参数（specialist 更新 **0.015–0.05%** 的参数）。
3. **理论 + 实证证明 FuRA-S 产生与 RLVR 同类的权重变化**：RLVR 大体保留预训练权重的奇异值而**旋转奇异向量**（spectral inheritance，Zhu et al., 2026a;b）。FuRA-S 独立重缩放各块的奇异值，从而改变各块对整体矩阵的相对贡献并**旋转奇异向量**而非改变奇异值。实证上：把训练得到的奇异向量与预训练奇异值组合，保留 **>95%** 的准确率增益。
4. **未截断分解带来的关键工程优势——不改权重即可适配 INT4 模型**：更新可被精确重写为**层输入的变换**（式 5）：
   $$y = \underbrace{W_q}_{\text{INT4, frozen}} \Big( x + \underbrace{R}_{\text{frozen}} \underbrace{\operatorname{diag}(\delta)}_{\text{trainable}} R^\top x \Big)$$
   这意味着 INT4 权重本身保持冻结、量化误差不累积、也不需要在每次迭代后重量化。
5. **步级 fitness 函数**：为长程 phone-use 任务设计，通过比较某个动作与其他扰动模型在**同一屏幕**上采取的动作来给单步打分。
6. **主要结果**：phone-use agent 成功率从 **6–23% 提升到 89–100%**；在 iPhone 16 Pro 上**过夜**训练出一个个性化 8B 模型。
7. **与现有方法的对比**：在 RLVR 基准上 FuRA-S **与全参数 ES 竞争**（competitive），**一致优于 ES over LoRA adapters（LoRA-ES）**，并在 INT4 模型上**超过量化 ES（QES）最多 16.25 点**。
8. **显存分析**：仅服务模型就占据 app 可用显存的大部分，BP 与全参数 ES 都会 OOM；FuRA-S 只增加 **1–5 MB** 可训练参数，在 Llama-3-8B 上训练（含 Adam moments）只比前向评估多约 **20 MB**。

## 问题背景

LLM 越来越多地作为自主 agent 部署在个人设备上（桌面环境到移动界面）。随着小语言模型进展与手机 NPU 推理加速器的普及，完全在端侧运行 agent 已成现实——这保持了用户数据本地化并支持离线工作。

但**移动设备的显存限制**把端侧模型限制在几十亿参数以内，其通用能力远低于前沿模型。而实践中用户很少需要这种广度：他们在设备上执行的任务高度特定。这催生了一个部署范式——**一个共享的 base model（generalist）在本地被适配为轻量 specialist**，每个 specialist 是为某个任务训练的一小组参数。

在端侧训练 specialist 面临标准后训练流水线不满足的约束：

1. **标注数据稀缺** → 模型应从使用中涌现的信号学习，包括任务结果的自动检查（RLVR）与用户在设备上积累的记录。
2. **移动 NPU 可能不支持反向传播**——它消耗数倍于推理的显存，且被端侧引擎的量化数据流 poorly supported。
3. **前向方法（ZO / ES）仍不够**：它们避免 BP 成本，但**仍扰动大量模型参数并维护一份全精度权重副本**，超出 app 可用显存，且使每个 specialist 与模型本身一样大。

于是核心问题成为：**手机能否仅用前向传播、从使用中涌现的信号训练出自己的 specialist？**

更深一层的方法论问题：**为什么前向更新必须是"块谱坐标"而非 LoRA？** 因为前向传播对任意参数化都能算出精确梯度，而前向优化把更新估计为**随机扰动的加权和**。因此学习效率**只在这些扰动与 RLVR 造成的权重变化相似时才有**。LoRA 的通用低秩扰动并非为产生这种旋转而设计。

## 方法

### 1. MobileSpec 系统流程

**Generalist** 由 INT4 权重与**冻结的块因子**组成；块因子在服务器上从权重计算一次并随模型分发。每个 specialist 是**块奇异值的相对变化的 1–5 MB 文件**。

**任务与 fitness**：每个任务需要一个设备能在无标签下计算的 fitness 函数。任务若以可验证状态结束（如回复帖子），扰动模型在**沙箱化的 app** 中尝试，检查器检视 app 最终状态并返回奖励。任务若由用户自己的记录定义（如给电影打标签），fitness 是扰动模型对这些记录的**似然**。

**训练**：手机空闲时（如过夜）用 FuRA-S 训练 specialist。每次迭代评估一批扰动模型（members），并把 specialist 朝 fitness 更高的成员移动；长程任务用 §3.4 的步级 fitness。这些前向评估**从 flash 流式读取 decoder 层**，因此设备从不在内存中持有整个模型。

**选择**：MobileSpec 周期性在任务的留出实例上评估 specialist（如用户后来的记录或新 episode），保留得分最好的 checkpoint，得分不再提升时停止训练。

**服务**：用户执行任务时，设备加载其 specialist，将其作为**每次 INT4 乘法之前对输入的变换**来施加。

### 2. 块式 SVD 重参数化

沿用 FuRA（Zhao et al., 2026），把 $W \in \mathbb{R}^{m \times n}$ 切成 $K$ 个宽度为 $b$ 的列块，$W = [W_1 | \cdots | W_K]$，每块用**未截断 SVD** 分解（式 1）：

$$W_k = L_k \operatorname{diag}(s_k) R_k^\top$$

其中 $L_k \in \mathbb{R}^{m \times b}$ 列正交归一，$R_k \in \mathbb{R}^{b \times b}$ 正交，$s_k \in \mathbb{R}^b$ 持块奇异值。**因为每块保留其全部奇异值，该分解精确重构 $W$**。乘积 $L_k \operatorname{diag}(s_k)$ 与 $W_k$ 同尺寸、占据其位置，故额外的存储与计算开销只来自 $K$ 个 $b \times b$ 的因子 $R_k$：每矩阵 $Kb^2 = nb$ 个值，即 $W$ 的 $b/m$ 比例。按 FuRA 的列划分方式，开销约 **3%**。

适配后的矩阵为（式 2）：$W' = [L_1 \operatorname{diag}(s'_1) R_1^\top | \cdots | L_K \operatorname{diag}(s'_K) R_K^\top]$。FuRA-S **冻结 $L_k$ 与 $R_k$**，把可训练参数集 $\theta$ 限制为块奇异值。

### 3. ES 更新规则

第 $t$ 轮评估 $N$ 个成员 $\theta_t + \mu z_j$（$z_j \sim \mathcal{N}(0, I_d)$），从前向传播得到 fitness $F_j$，更新 $\theta_{t+1} = \theta_t + \alpha N \sum_j F_j z_j$（步长 $\alpha$ 吸收 $1/\mu$）。

FuRA-S 的种群是 $N/2$ 对**反对称（antithetic）**扰动 $\theta_t \pm D z_j$，其中 $D = \operatorname{diag}(\mu_{\text{rel}}|\theta_0|)$，使**每个奇异值按自身大小成比例移动**。与 MeZO 相同，方向由随机种子重新生成、**从不存储**。成员评分后 fitness 被标准化为 $\tilde{F}_{\pm j} = (F_{\pm j} - \bar{F})/s_F$，块奇异值更新为（式 3）：

$$\theta_{t+1} = \theta_t + \frac{\alpha}{N} D \sum_{j=1}^{N/2} (\tilde{F}_{+j} - \tilde{F}_{-j}) z_j$$

每个方向按其**对的 fitness 差**加权，故更新朝 fitness 更高的扰动移动。对似然 fitness，FuRA-S 可改用 Adam 优化 MeZO 的两点梯度估计来更新块奇异值。由于两种更新都不存储激活或梯度，在 Llama-3-8B 上训练只比前向评估多约 **20 MB** 显存（含 Adam moments）。

### 4. 在 INT4 generalist 上服务

手机运行量化发布的模型，把每个权重矩阵存为 $W_q = (Q - Z) \odot \Gamma$（INT4 码 $Q$、零点 $Z$、缩放 $\Gamma$）。在量化权重旁存高精度块 SVD 因子会抵消量化省下的显存，而每次迭代后重量化 $W'$ 会累积量化误差。

MobileSpec 因而重写更新：把适配后的奇异值写为 $s'_k = s_k \odot (1 + \delta_k)$。由于 $R_k^\top R_k = I$，式 (1) 给出 $L_k \operatorname{diag}(s_k) = W_k R_k$，代入式 (2) 消去 $L_k$：

$$W' = W(I + E), \qquad E = R \operatorname{diag}(\delta) R^\top$$

其中 $R = \operatorname{blockdiag}_k(R_k)$，$\delta$ 拼接各 $\delta_k$。**这个重写不含任何近似**（因为没有块奇异值被截断）。对 INT4 generalist，$R$ 取自其**反量化权重**的块 SVD，每层计算：

$$y = W_q \Big( x + R \operatorname{diag}(\delta) R^\top x \Big)$$

即 $W_q$ 与 $R$ 冻结，只有 $\operatorname{diag}(\delta)$ 可训练。

### 5. 步级 fitness（长程 phone-use 任务）

对于长程任务，整集 reward 把所有步骤混在一起，credit assignment 很差。MobileSpec 设计步级 fitness：**把某个动作与其他扰动模型在同一屏幕上采取的动作相比较**来给单步打分。

## 实验结果

- **Dataset/Task**: phone-use 任务（agent 成功率）、个性化任务（iPhone 16 Pro 上训练 8B 模型）、reward-based（RLVR 基准）、supervised、agentic 任务。基线包括全参数 ES、LoRA-ES、量化 ES（QES）、LoRA/Zo/ES 系列方法。

- **Main results**:
  - **Phone-use agent 成功率**：从 **6–23%** 提升到 **89–100%**（specialist 仅 1–5 MB，更新 0.015–0.05% 参数）。
  - **端侧训练**：在 **iPhone 16 Pro 上过夜**训练出一个个性化 8B 模型。
  - **RLVR 基准**：FuRA-S **与全参数 ES 竞争**；**一致优于 LoRA-ES**；在 INT4 模型上**超过 QES 最多 16.25 点**。
  - **显存**：FuRA-S 只增加 1–5 MB 可训练参数（Qwen2.5-1.5B 上约占 0.03% 参数）；Llama-3-8B 上训练比前向评估多约 20 MB。BP 与全参数 ES 在手机上均 OOM。

- **Ablations**: (1) **谱继承的实证验证**：把 FuRA-S 学到的奇异向量与预训练奇异值组合，保留 >95% 的准确率增益——说明学到的东西几乎全部来自**旋转**而非奇异值变化。(2) 参数侧检查：知识 SFT 更多改变浅层到中层，judgment SFT 的改变集中在 FoK 信号强的晚期。(3) 与 LoRA-ES、QES 的对比。(4) 块宽度 $b$ / $K$ 与 $R$ 因子的 3% 存储开销核算。(5) 似然 fitness 下 Adam 版与 ES 版的对比。(6) INT4 上"不改权重"路径与"重量化"路径的对比（后者累积量化误差）。

## 关键洞察

1. **"前向优化高效"这一说法有前提条件，而本文给出了这个前提**：前向优化把更新估计为随机扰动的加权和，所以它的效率**只在扰动与真实梯度更新相似时才有**。这为"为什么 LoRA-ES 不行"提供了原则性答案，而不是经验性的调参问题。
2. **RLVR 的权重变化特征可以被"逆向设计"成搜索空间**：既然 RLVR 保留奇异值、旋转奇异向量，那么只需训练**块奇异值**就能间接实现奇异向量旋转——因为独立重缩放各块改变了它们对整体矩阵的相对贡献。这是一个很漂亮的"用便宜的量控制贵的量"的设计。
3. **"未截断"这个看似技术性的选择是全文工程可行性的支点**：不截断 ⇒ 分解精确 ⇒ $L_k$ 可消去 ⇒ 更新可精确写成层输入的变换 ⇒ **INT4 权重保持冻结**、不需重量化、不累积量化误差。若采用截断 SVD（更省存储但有近似），整个端侧 INT4 方案就不成立。
4. **singular value 的"相对缩放"（$\delta$ 而非绝对值）是多任务共享 generalist 的关键**：specialist 只存 1–5 MB 的相对变化，因此切换任务时 generalist 与 kernel 完全不动——这正是"generalist–specialist"范式在设备上可落地的形态。
5. **步级 fitness 的思路值得推广**：不按整集 reward 训练长程 agent，而是**用其他扰动模型在同一状态下的行为差异**来给单步打分——这是 ES 特有的一种 credit assignment 手段（因为多个扰动模型提供天然的多样轨迹），比 BP 时代需要 GiGPO 之类的分组技巧更直接。
6. **端侧训练的真正约束是"服务模型本身就吃掉了大部分显存"**，而不是优化算法本身。这个观察（Figure 1）重新定义了问题的难度：任何需要全精度权重副本的方法（ZO/ES）都注定 OOM，而**只训练 INT4 权重派生量的方法**才能存活。

## 局限性

- **论文未在摘要中给出具体的 RLVR 基准名称与逐基准数值**（仅给出"competitive with full-parameter ES""outperforms LoRA-ES""surpasses QES by up to 16.25 points"），细节需查正文表格。
- **iPhone 16 Pro 的"过夜训练"未给出确切时长、能耗与温度/降频信息**，实际可用性（用户是否愿意让手机整夜满载）未讨论。
- **依赖服务器端的预处理**：块因子 $R$ 需在服务器上从反量化权重算好并随模型分发。这意味着端侧方案需要模型提供方的配合，而非纯本地可完成。
- **$R$ 因子占 $W$ 的 $b/m$ 比例（约 3%）**——这个开销虽小，但它**必须在每个模型的每个权重矩阵上存储**，且必须以高精度（FP16/FP32）存储，抵消了一部分量化收益。
- **只测试了少数模型家族与规模**（Qwen2.5-1.5B、Llama-3-8B、8B 模型），未说明在更大模型上块奇异值的数量与显存开销如何增长。
- **沙箱化 app 中的自动检查器**是 fitness 的关键部件，其可靠性与实现难度未评估——真实设备上许多任务没有可自动检查的终态。
- **用户记录的似然作为 fitness**假设记录本身是高质量的；若用户历史包含噪声或已过时，fitness 会把 specialist 训练到拟合噪声。
- **未评估灾难性遗忘**：多个 specialist 共享同一个 generalist，切换任务时的相互干扰、以及 specialist 之间的组合使用均未测试。
- **ES 的固有低效**：即使搜索空间小，ES 仍需每步评估 $N$ 个成员，每个成员要在设备上跑完整的前向——手机上的总计算成本（论文聚焦显存而非算力/能耗）可能仍不可接受。
- **未与 INT4 上非 ES 的前向方法（如 QuZO 的低精度前向）做端到端对比**。
- **理论部分是一阶分析**（first-order analysis），证明的是"块奇异值重缩放会旋转奇异向量"这一机制，而非端到端收敛性或 RLVR 相似性的严格刻画。

## 适用场景

**适用**：
- 端侧/边缘设备上的个性化 agent（手机、可穿戴设备），需要在严格显存与无 BP 约束下训练任务专用 specialist。
- 追求**极小 per-task 存储**的多任务部署：一个共享 INT4 generalist + 每任务 1–5 MB。
- 有**可自动验证奖励**（RLVR）但无标注数据的任务：沙箱化环境 + 检查器。
- 需要"不改基础权重"地适配已量化发布模型的场景（FuRA-S 的输入变换重写）。
- 研究前向/零阶优化的理论动机："搜索空间必须匹配目标更新的谱结构"这一原则可直接用于设计新的 PEFT + ES 组合。

**不适用**：
- 端侧算力/能耗极其受限且任务需要大量前向评估的场景（ES 的采样成本高）。
- 没有可自动检查终态、也没有用户记录似然可用的任务（fitness 无从计算）。
- 需要一次训练、多次复用且不要求极小存储的场景（此时 LoRA + BP 更简单有效）。
- 服务于非量化模型（FuRA-S 的重写优势专为 INT4 设计；在 FP16 下必要性下降）。
