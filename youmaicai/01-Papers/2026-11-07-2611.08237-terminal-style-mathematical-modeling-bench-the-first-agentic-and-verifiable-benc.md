# Terminal-style Mathematical Modeling Bench: The First Agentic and Verifiable Benchmark for Mathematical Modeling

### 核心贡献
1. 提出 TB-MathModel：首个同时满足 agentic、verifiable、terminal 三个属性的完整数学建模基准，覆盖 2023–2025 年 18 道真实 CUMCM / MCM 赛题。
2. 设计「方向感知的单边打分」（direction-aware, one-sided scoring）：超过基准答案绝不会被扣分，只惩罚不足；同时用两层可行性验证（程序化不变式闸门 + 624 条 Lean 4 义务）配合硬闸门，对不可行答案直接归零。
3. 采用人类「杰出奖」论文面板作为多参考答案锚点，使模型必须接近多个被接受答案，从而把建模能力的数值内核变成可复现、机器可校验的信号，并可用于收集 agent 轨迹。

### 技术方案
**核心思想**: 把开放式建模问题封装成容器化终端任务，agent 只返回一个 JSON artifact，评测端用「可判定不变式的程序化校验 + 形式化义务」双层闸门把物理可行性变成硬约束，再用单边数值打分衡量与优秀答案的距离。

| 技术 | 说明 |
|------|------|
| 容器化 terminal 任务 | 每个任务在容器化 terminal 中提供逐字题面、官方附件与图表；agent 返回单个 JSON artifact |
| Direction-aware one-sided scoring | 只针对最终问题的数值内核打分，方向感知且单边：超越锚点不罚，落后才扣 |
| 双层可行性验证 | 第一层：针对六种可判定不变式形式的程序化闸门；第二层：624 条 Lean 4 形式化义务 |
| 硬闸门归零 | 任何不可行（physically infeasible）的答案经闸门判定后得分直接置零 |
| 多参考锚点面板 | 以一组人类杰出奖论文（而非单一论文）复现为参考锚点，输出 multi-reference O-Eval 指标 |

### 实验结果
- **数据集**: 18 道真实 CUMCM / MCM 赛题（2023–2025），附件与图表随题发布
- **基线**: 7 个多模态模型条目，每个 3 个随机种子；包含一个 2.54 美元的开源模型作为成本对照
- **结果**: 最强模型 multi-reference O-Eval 达 64.58%；2.54 美元的开源模型在 1/100 成本下取得 59.81%

### 局限性
- 仅 18 道题目，题目覆盖的建模类型有限，统计稳定性依赖面板设计
- 打分聚焦最终问题的数值内核，报告的论证质量未被评测（设计上是刻意为之）
- 依赖 Lean 4 等价性判定与程序化不变式，可形式化的建模约束覆盖面尚不完整
- 多模态条目各 3 个种子，seed 数量较少

### 关键洞见
> 「超越参考答案」在开放式建模中应当是合法甚至理想的结果，因此评分必须是非对称的；再叠加一个把不可行解直接归零的硬可行性闸门，就能在完全不依赖 LLM judge 的情况下得到一个机器可校验、与人类优秀答案对齐的建模能力信号——这是把长程建模能力变成可自动评测指标的关键一步。
