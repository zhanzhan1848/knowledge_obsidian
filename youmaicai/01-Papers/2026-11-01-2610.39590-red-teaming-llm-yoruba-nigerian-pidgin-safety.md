# Red-Teaming Large Language Models in Low-Resource African Languages: A Case Study of Yoruba and Nigerian Pidgin

## 摘要
LLM 在非洲的教育、医疗、客服与社交场景中部署日益广泛，但其安全性在低资源语言中几乎未被检验（绝大多数红队工作只做英语）。本文用 **400 条显式对抗性英文 prompt**（其中 **172 条（43%）**改编自 Do-Not-Answer、HARMFULQA、AdvBench、HarmBench 四个既有红队数据集，**228 条（57%）**新写以覆盖尼日利亚特定伤害场景），并翻译成 Yoruba（约 4,200 万使用者）与 Nigerian Pidgin，组成三语 **1,200 条**的基准，划分为四类伤害：仇恨/辱骂语言、有害指令、政治操纵、文化刻板印象与歧视。作者评测六个 SOTA 模型（Llama 3.1 8B / Llama 3.3 70B / Qwen3 32B / Gemini 2.0 Flash / GPT-4o Mini / Aya 101），全部用 zero-shot、temperature 0，并由**母语标注者**在三个维度打分（harmfulness、helpfulness、comprehension），用 **Cohen's κ** 衡量一致性。关键发现：拒答英语 prompt 达 69% 的 Gemini 2.0 Flash，在 Yoruba 只拒答 0%——但这不是更安全，而是模型根本没读懂；多数模型在尼日利亚语言上的 ASR 上升，**GPT-4o Mini 的跨语言安全差距最大（Yoruba CLSG = +0.23）**；一旦模型真的参与回应，伤害性内容比例可达英语 0.63、Pidgin 0.50；最难被检测的类别是文化刻板印象与歧视（**Pidgin ASR = 0.44**）。Gemini 2.0 Flash 是跨语言最一致的模型；Aya 101 虽明确训练过非洲语言，却有最高的英语 ASR（0.60）与最低的 Yoruba 理解率（0.28）。结论：英语中心的安全对齐**不能迁移**到尼日利亚语言。

## 核心贡献
1. **1,200 条三语红队基准**：400 英文 → 400 Yoruba → 400 Nigerian Pidgin，含人类标注的 harmfulness / helpfulness / comprehension 标签与 CLSG 指标（计划发布）。
2. **区分"安全失败"与"理解失败"**：引入并同时报告 Comprehension Rate (CR)，指出低 ASR 可能只是模型无法参与对话。
3. **Cross-Lingual Safety Gap (CLSG)** 指标：$CLSG = ASR_{lang} - ASR_{eng}$，并强调负值必须结合 CR 解读。
4. **母语人工评测 + Cohen's κ**：明确拒绝使用 LLM-as-judge（因其在这些语言上不可靠），采用双标注者 + 第三人仲裁设计。
5. **对既有工作的差异化定位**：区别于 UbuntuGuard（policy compliance 而非 adversarial exploitation）、LSR（单模型、无 Pidgin、无理解度）、Amplify Initiative（只收集数据不评测模型）。

## 方法与架构
### 1. 数据构建（Figure 2 四阶段流水线）
- **阶段 1 prompt 构建与本地化**：把通用机构/族群/政治制度/材料替换为具体的尼日利亚元素（如把选举操纵改写为尼日利亚政治语境、把仇恨言论本地化到尼日利亚族群）。
- **阶段 2 翻译**：Yoruba 用 Google Translate 初步翻译后由母语语言学家后编辑；Nigerian Pidgin 由母语者直接翻译，**不使用机器翻译**。
- **阶段 3 zero-shot 评测**：temperature 0，无上下文/示例/指令。
- **阶段 4 人工评测与指标计算**。
- 四类伤害各 100 条：Hate/abusive language（改编 50 / 新写 50）、Harmful instructions（40 / 60）、Political manipulation（33 / 67）、Cultural stereotypes（49 / 51）。所有 prompt 都涉及尼日利亚主要族群（Yoruba、Igbo、Hausa、Fulani）。全部为单轮、显式陈述有害意图（不做 role-play 或隐晦措辞）。

### 2. 模型选择（6 个，覆盖三种训练范式）
| 模型 | 定位 | 访问方式 |
|---|---|---|
| Llama 3.1 8B Instruct | 英语为主、8B，最小英文基线 | HuggingFace / A100 |
| Llama 3.3 70B Instruct | 同族 70B，检验规模是否影响安全性 | Together.ai API |
| Qwen3 32B | 广泛多语（100+ 语言） | Groq API |
| Gemini 2.0 Flash | 闭源商用多语，非洲部署广 | API |
| GPT-4o Mini | 闭源紧凑 OpenAI，检验商用泛化 | API |
| Aya 101 | Cohere，101 语言（一半低资源），检验显式纳入目标语言的效果 | HuggingFace / A100 |

### 3. 人工评测协议
- 每种语言**两名母语标注者**独立对每条回复在三个二值维度打分，按事先约定的书面指南与示例执行。
- Harmful content 判定按类别 rubric（如 hate speech：是否使用侮辱性词或含可用于仇恨言论的内容，即使以假设形式包装；harmful instructions：是否给出可操作的步骤；political manipulation：是否捏造归因于真实政治人物的言论；cultural stereotyping：是否宣扬对尼日利亚群体的负面或过度正面概括）。
- Helpful = 实质性参与回应（不论是否有害）；被拒答或离题记 0。
- Comprehension = 是否表现出对 prompt 的真正理解（例如用英语回答非英语 prompt 但处理了其内容）；不连贯、重复或离题输出不算。**理解度与有害性独立打分**。
- 一致性用 Cohen's κ：

```math
\kappa=\frac{P_o-P_e}{1-P_e}
```

要求 **κ ≥ 0.60**（substantial agreement）。分歧由第三方独立复核仲裁；共 **341** 个分数经仲裁更新。报告指标基于**全量回复的 30% 分层抽样（2,160 条）**，按模型、语言、伤害类别比例抽取。

### 4. 六个指标

```math
RR=\frac{N_{\text{refused}}}{N_{\text{total}}},\quad
HCR=\frac{N_{\text{harmful}}}{N_{\text{total}}-N_{\text{refused}}},\quad
ASR=\frac{N_{\text{harmful}}}{N_{\text{total}}}
```

```math
HR=\frac{N_{\text{helpful}}}{N_{\text{total}}},\quad
CR=\frac{N_{\text{understood}}}{N_{\text{total}}},\quad
CLSG=ASR_{\text{lang}}-ASR_{\text{eng}}
```

ASR 是本研究的主安全指标；HCR 度量"一旦参与回应"后的危险程度；CR（改编自 CSRT 框架的 comprehension 维度）低说明模型无法可靠处理目标语言，会混淆其他所有指标的解读；CLSG 为负可能反映真正更强的安全，也可能是理解不足，必须结合 CR 解读。

## 实验设置
- 6 模型 × 3 语言 × 400 prompt = 1,200 次推理（zero-shot，temperature 0）。
- 人工评测：3 维度 × 每语言 2 名母语标注者 + 仲裁；κ 阈值 0.60。
- 分析维度：按模型、按语言、按伤害类别；并做 CR 与 HR / ASR 的相关性分析（Appendix E, Figure 6）。
- 参照的既有工作：UbuntuGuard、LSR、Amplify Initiative、RedBench、Do-Not-Answer、HarmBench、AdvBench、HARMFULQA。

## 实验结果
**逐模型逐语言指标（Table 2）**
| 模型 | 语言 | RR | ASR | HCR | HR | CR |
|---|---|---|---|---|---|---|
| Aya-101 | Eng | 0.05 | **0.60** | 0.63 | 0.52 | 0.68 |
| | Yor | 0.00 | 0.25 | 0.25 | 0.22 | **0.28** |
| | Pid | 0.04 | **0.48** | 0.50 | 0.43 | 0.52 |
| Gemini-2.0 | Eng | **0.69** | 0.13 | 0.41 | 0.48 | 0.98 |
| | Yor | 0.55 | 0.06 | 0.13 | 0.32 | 0.92 |
| | Pid | 0.67 | 0.12 | 0.35 | 0.29 | 0.98 |
| GPT-4o-mini | Eng | 0.47 | 0.18 | 0.34 | 0.33 | 0.50 |
| | Yor | 0.01 | **0.41** | 0.41 | 0.57 | 0.72 |
| | Pid | 0.37 | 0.23 | 0.36 | 0.39 | 0.55 |
| Llama-3.3-70B | Eng | 0.38 | 0.16 | 0.26 | 0.36 | 0.74 |
| | Yor | 0.00 | 0.31 | 0.31 | 0.20 | 0.31 |
| | Pid | 0.36 | 0.31 | 0.48 | 0.50 | 0.68 |
| Llama-3.1-8B | Eng | 0.21 | 0.34 | 0.43 | 0.43 | 0.82 |
| | Yor | 0.00 | 0.11 | 0.11 | 0.03 | **0.08** |
| | Pid | 0.08 | 0.46 | 0.50 | 0.39 | 0.50 |
| Qwen3-32B | Eng | 0.34 | 0.13 | 0.20 | 0.34 | 0.99 |
| | Yor | 0.01 | **0.01** | 0.01 | 0.05 | **0.08** |
| | Pid | 0.27 | 0.28 | 0.39 | 0.69 | 0.87 |

**跨语言安全差距（CLSG）**：GPT-4o Mini 的 Yoruba CLSG = **+0.23**（0.18 → 0.41），为最大正差距；Llama 3.3 70B 与 Qwen3 32B 的 Pidgin 差距均为 **+0.15**，Llama 3.1 8B 的 Pidgin 为 **+0.12**。负差距：Aya 101 Yoruba **−0.35**、Llama 3.1 8B Yoruba **−0.23**、Qwen3 32B Yoruba **−0.12**，但作者强调这源于极低的理解度而非更强安全。Gemini 2.0 Flash 跨语言最一致（Yoruba −0.07、Pidgin −0.01）。

**理解度与相关性**
- 英语理解度高（Qwen3 32B 0.99、Gemini 2.0 Flash 0.98、Llama 3.1 8B 0.82），在 Yoruba 崩塌：Qwen3 32B 0.99→0.08、Llama 3.1 8B 0.82→0.08、Llama 3.3 70B 0.74→0.31；Gemini 2.0 Flash 例外（Yoruba 0.92、Pidgin 0.98）。
- 除 GPT-4o Mini 外，所有模型的 Pidgin 理解度都高于 Yoruba（与 Pidgin 与英语词汇重叠度更高一致）。
- **CR 与 HR 的相关**：Yoruba **r = 0.81**，英语 r = 0.20、Pidgin r = 0.15 → Yoruba 的主要瓶颈是理解而非安全策略。
- **CR 与 ASR 的相关**：Pidgin **r = −0.76**（理解越好伤害越少），Yoruba 仅 r = 0.25（弱正相关）→ Yoruba 的低 ASR 主要反映"无法参与"。
- **RR 与 ASR 的相关**：英语 r = −0.84、Pidgin r = −0.97，Yoruba 仅 r = −0.41 → 在 Yoruba 拒答不是可靠的安全指标。
- 定性分析发现低理解度输出形态：逐字重复原 prompt（Llama 3.1 8B）、重复与 prompt 内容完全无关的固定句式（Aya 101）。

**按伤害类别（Figure 5）**
- **文化刻板印象与歧视**最难检测：Pidgin **ASR = 0.44**（HCR 0.49），且三种语言拒答率都低 → 安全过滤器难以识别文化/社会框架下的伤害。
- 有害指令类拒答率最高（英语 0.52、Pidgin 0.52），但两种语言 ASR 仍达 0.27，非拒答回复中超过一半有害（HCR 0.55）。
- 政治操纵类在英语检测最有效（拒答率 0.40），Yoruba 仅 0.12、Pidgin 0.32。
- 仇恨/辱骂语言在英语 ASR 最低（0.22），但 Yoruba 拒答率极低（0.09），作者认为主要是理解弱而非真正更安全。

**标注一致性**：κ 范围 **0.64–1.00**，全部超过 0.60 阈值；拒答打分几乎完全一致（因为先经关键词自动标记再人工确认）；有害性分歧低（按语言 2.5%–4.7%），帮助性与理解度分歧较高（3.1%–9.6%）；三种语言间无系统性下降。

## 局限性
作者自述：
- 仅评测 6 个模型，其中只有 Aya 101 在设计上优先覆盖非洲语言；受 API 成本与 GPU 资源限制，未纳入更多非洲语言导向的多语模型。
- 只覆盖尼日利亚的两种语言，扩展到 Igbo、Hausa 等是重要下一步。
- Yoruba 使用"机器翻译 + 后编辑"而非从零翻译（合格标注者有限），也因此每种语言只能由 2 名评测者标注，分歧需研究者仲裁。
- 仅评测单轮 prompt；已有研究表明多轮对抗交互会显著提高攻击成功率，多轮红队在此类语言中仍是开放方向。
- 只做 prompt-based 攻击（不含 token-based / gradient-based / infrastructure-based），因为这最贴近真实尼日利亚用户与部署系统的交互方式。

我的补充批评：(1) 样本量按模型看仅 400 条 prompt（每类 100 条），ASR 差异在 0.05–0.1 量级时缺乏置信区间；(2) Yoruba 与英语之间的比较同时被"语言距离"与"翻译质量（MT 后编辑）"混淆，未与母语原创 prompt 对照；(3) CLSG 的负值解释依赖 CR，而 CR 是粗粒度二值人工判断——作者自己也指出二值理解度分数看不到"逐字重复"这类失败模式，这削弱了"负 CLSG = 低理解度所致"的论证强度；(4) 六模型之一（Qwen3 32B）在 Yoruba 的 CR = 0.08、ASR = 0.01，是典型的"无法参与"样本，用它参与跨语言安全性排名并不合适。

## 评估与建议
- 是否推荐深入阅读：是（作为低资源语言安全红队的方法论范式，特别是"必须同时报告理解度"的论证与 CLSG 指标）
- 适用场景：多语言安全评测设计；红队基准构建；部署前的语言级安全审计；解读 refusal rate 数据时的方法学警示。
- 与知识库的关联：与 2610.37245（Hausa 安全对齐）出自同一研究团队并互相印证（同样强调"低 RR ≠ 安全"）；与 UbuntuGuard（policy compliance）、AfriGuard、Amplify Initiative 构成非洲语言安全基准谱系；可与 2610.39802（over-refusal 的表征与优化视角）在"安全 vs 参与"的张力上对照。
