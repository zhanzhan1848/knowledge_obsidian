## 核心贡献

> 用 *低成本 outcome-aware likelihood* 评估 skill 效用，避免 rollout-based credit assignment 的不稳定，按需选择性注入 skill。

1. **Reusing outcome-verified trajectories**：复用已 RL 训练轨迹生成候选 skill
2. **Outcome-aware likelihood 比较** 估算 skill 效用，不做 candidate-specific 环境 rollout
3. **选择性注入**：当候选 skill 无助时保留 skill-free execution；否则注入最有用 skill
4. **Generator / Executor 联合训练**：Generator 生成与 Executor 当前能力匹配的 skill
5. **Scaffolded RL 鼓励 skill 内部化**：最终推理时可不依赖外部 skill

---

## 技术方案

### 核心思想

现有 skill-based RL 要么假设 skill 永远有用，要么用 rollout 估计 skill 效用——前者僵化、后者昂贵且不稳。SkillScaffold 关键洞察：skill 的价值依赖当前 policy 在该 query 上的能力，效用应该用 *outcome-aware likelihood*（即"加入 skill 后能否让该 query 看到正确 outcome 的可能性上升"）来低成本估算。

### 关键技术

| 技术 | 说明 |
|------|------|
| Candidate skill mining | 从 outcome-verified 训练轨迹里挖掘潜在 skill |
| Outcome-aware likelihood 效用估计 | 不 rollout，直接比 outcome likelihood |
| Selective injection | 没有 candidate 帮助就保留 skill-free |
| Generator-Executor 联合训练 | skill 与 policy 同步进化 |
| Skill internalization | 训练后期 skill 可被"内化"到 policy |

## 公式

对 query $q$ 与候选 skill $s$：

```math
U(q, s) = \log p_{\theta}(o^* \mid q, s) - \log p_{\theta}(o^* \mid q)
```

其中 $o^*$ 是已知的正确 outcome。注入规则：

```math
s^* = \begin{cases}
\arg\max_s U(q, s), & \text{if } \max_s U(q, s) > \tau \\
\text{none}, & \text{otherwise}
\end{cases}
```

## 实验结论

- **基准**：ALFWorld, WebShop, ScienceWorld, $\tau^2$-Bench
- **对比**：strong agentic-RL baseline + skill-based RL baseline
- **提升**：在 short / long-horizon tasks 上均超 baseline
- **消融**：utility-based 选择与 abstention 均关键
- **训练时效率**：避免 rollout-based utility 估计的 cost

---

## 局限性

- 依赖 outcome-verified 训练轨迹（前期需 RL 提供）
- $U(q, s)$ 仍是 likelihood-based 估计，可能 miss interaction-level benefit
- 跨任务 / 跨 domain 的 skill transfer 未深入
- 内部化机制主要是行为观察，未做 mechanistic 解释
