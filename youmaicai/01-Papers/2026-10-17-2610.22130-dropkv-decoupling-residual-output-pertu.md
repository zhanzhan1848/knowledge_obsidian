## 核心贡献

> KV cache 管理是 LLM 长上下文瓶颈。eviction 优化目标是"最小化输出扰动"，但**联合选择 evicted tokens 是 NP-hard 组合问题** → 现有方法要么数学次优，要么难 kernelize。

1. 提出 **DropKV**：基于 **Decoupled Residual-Output Perturbation** 的简单原理化 eviction framework。
2. **关键 trick**：将 joint eviction 决策**解耦为独立 per-token 评分** → 绕过组合难解。
3. 给出 **provable constant-factor approximation** 理论保证。
4. 工程上 **易 kernelize**（per-token score 可并行）。

---

## 技术方案

### 目标
```
min_{E ⊂ tokens}  ‖ output_with_E - output_no_evict ‖²
  subject to |E| ≤ budget
```
NP-hard → 必须解耦。

### DropKV 思路
- 将 joint optimization 解耦：每个 token 独立计算一个"**移除后扰动**"得分。
- 选分数最高的 budget 个 evict。
- 理论：给出常数因子近似保证（vs 全局最优）。

### Per-token Score
基于 residual contribution to next-layer residual stream：
```
score_i = ‖ residual_with_token_i  -  residual_without_token_i ‖²
  (相对于 attention output)
```

---

## 关键洞察

- **联合优化是 NP-hard** → 通过**解耦**绕开 → 失去全局最优但**易 kernelize + 有近似保证**。
- **Value representation** 比单纯 attention score 更能捕捉 eviction 影响（与已有 insight 一致）。

## 实现建议

- **实现难度**：中（per-token score 计算 + GPU kernel）
- **预期性能**：长上下文推理显著加速，质量损失小
- **适用场景**：128K+ 长上下文 LLM 服务部署、edge reasoning 后无法再上 KB-budget

---

## 局限性

- 解耦带来 sub-optimality，但有常数因子保证。
- 需要在 attention 内部算 residual → 与 FlashAttention 集成需定制。
