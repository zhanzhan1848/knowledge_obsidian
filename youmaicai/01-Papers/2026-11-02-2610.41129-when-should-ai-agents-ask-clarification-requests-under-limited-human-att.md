# AI Agent 何时该发问？有限人类注意力下的澄清请求

> **原题**: When Should AI Agents Ask? Clarification Requests Under Limited Human Attention

| **摘要** | AI agents increasingly carry out delegated tasks in parallel, with one person overseeing several of them at once. In practice, an agent often lacks information its task requires, such as an unstated preference, constraint, or specification. It can ask the human to clarify, or it can search for the information itself, for example in past records, which takes time and effort and may fail. In this paper, we study how to coordinate these decisions across several agents that share one human with limited attention. We build a stylized model in which each agent can search, ask, or continue the parts of its task that do not depend on the missing information, and we formulate the problem as a dynamic program. We first show that whether an agent should ask depends on more than its own uncertainty: an agent with other work to do can be better off asking earlier, and which question the human should answer first depends on all waiting questions, so no ranking computed agent by agent is optimal. We then propose the Pairwise Coordination Policy (PCP), which uses exact one- and two-task problems to estimate how pairs of tasks delay each other when they share the human. Theoretically, PCP is exactly optimal when at most two requirements remain unresolved and costs at most twice the optimum when every unresolved requirement must be resolved by the human. We evaluate PCP on 864 synthetic cases and in a case study with LLM agents. On the synthetic benchmark, PCP's mean gap to optimal cost is 0.07%, and it reduces cost by an average of 18-31% relative to three standard rules for when to ask. In the LLM case study, agents completed every task correctly, and PCP achieved the lowest mean cost in all tested settings. |

## 核心贡献

1. **场景**：AI agent 并行执行被委派的任务，**一个人同时监督多个 agent**。agent 常缺少任务所需信息（未言明的偏好、约束或规格）。
2. **两种选择**：**问人类**澄清，或**自己去查**（如历史记录，耗时耗力且可能失败）。
3. **模型**：构建风格化模型 —— 每个 agent 可**搜索**、**发问**，或**继续执行不依赖缺失信息的部分**；问题形式化为**动态规划**。
4. **关键反直觉结论**：
   - **agent 是否该发问，不仅取决于自身不确定性** —— 一个**手上还有其他工作**的 agent 可能**更早发问**反而更好
   - **人类该先回答哪个问题，取决于所有等待中的问题** —— 因此**任何逐个计算（agent by agent）得出的排序都不是最优的**
5. **提出 PCP（Pairwise Coordination Policy）**：用**精确的一任务与两任务子问题**来估计**任务对之间因共享人类而产生的互相延迟**。
6. **理论保证**：当**至多两个需求未决**时 PCP **精确最优**；当**每个未决需求都必须由人类解决**时，成本**至多为最优解的两倍**。
7. 在 **864 个合成场景**上评估。

### 关键发现

- **"手上还有别的活儿的 agent 反而更早发问更好"** 是本文最反直觉也最有实践价值的结论 —— 它意味着**"我够不够不确定才问"是个错误的决策依据**，正确的依据是"**我的排队位置与我的机会成本**"。
- **"逐个计算得出的优先级排序不是最优"** —— 这直接否定了当前 agent 框架里常见的"每个 agent 自己判断该不该问、然后统一排队"的做法。**必须全局协调**。
- **"至多两需求精确最优、全部需求至多 2× 最优"** 是漂亮的近似保证 —— 这类"配对子问题近似"在多 agent 协调里是标准手法。
- 与 [[2026-11-02-2610.41604-real-computation-or-merely-naming-a-pre-registered-mechanism-audit-of-25]]（agent 系统的机制审计）同属**把 agent 系统当作可分析的工程对象**而非黑盒，这条方法论路线今天出现了两次。
- 与 [[2026-11-02-2610.42004-tradewar-a-benchmark-for-execution-grounded-trade-negotiation-with-adapt]]（TACTIC 的跨 episode 经验）呼应：都在研究 agent 如何在**多轮、有延迟反馈**的环境里改进决策。

## 局限性

- 风格化模型假设较多（人类注意力、搜索成本、失败率），与真实场景有差距
- 仅合成场景评估，真实人类注意力研究不足
- "两倍最优"的界在需求数量大时可能不够紧
