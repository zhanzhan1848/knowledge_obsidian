## 核心贡献
1. **提出 HERIT**（Hanja-English RAG-based Intelligent Translation）：一套系统性的领域适配流水线，用 **RAG 生成高质量伪标注数据**来缓解历史档案翻译中的数据稀缺与**时间偏置（temporal bias）**两个核心障碍。
2. **量化了问题的严重程度**：朝鲜王朝《太宗实录》（AJD）的人工英译项目预计耗时 **22 年、预算约 2,000 万美元**；而《王氏朝鲜实录》（JRS）的体量是 AJD 的 **5 倍**，人工翻译的成本完全不可行。现有英译语料不仅稀缺，还**严重偏向特定朝代**（目前完成的是世宗时期，约占总量 2.5%）。
3. **构建了伪标注流水线**：以 Dtrain 为外部知识库，用**检索增强的 in-context learning** 从大量 Hanja-Korean 平行语料生成 Hanja-English 伪标注对。产出 **315K 伪标注样本**（$D_{aug}$，覆盖除世宗朝外的所有朝代），伪标注成本约 **$3,000**。
4. **用 Proposer–Fusor 双阶段架构（Fusion-of-N）提升伪标注质量**：Proposer 生成 5 个草稿（temperature 0.3），Fusor 结合原文与草稿融合出最终译文。最终伪标注配置达到 **BLEU 38.462**（对比仅用基础 prompt 的 Gemini-2.5-Flash 的 15.720）。
5. **最终模型是 Qwen3-32B 的两阶段微调**：第一阶段在 $D_{aug}$ 上学汉字语义与专有名词音韵规律，第二阶段在 $D_{train}$ 上对齐人类风格。**两阶段优于混合训练**（作者归因于 $D_{train}$ 与 $D_{aug}$ 的严重规模失衡）。训练用 8 张 H200，第一阶段 15.1 小时、第二阶段 1.2 小时。
6. **实际完成了剩余档案的翻译**：用 8 张 H200 在 **94.6 小时**内翻译了 **209 万份**此前未翻译的 AJD 与 JRS 文档，模型与语料均公开（github.com/dandamdandam/HERIT）。
7. **实验结论与直觉相反的发现**：模型规模（Qwen3 8B→32B）稳定提升质量，但**推理能力对机器翻译无显著贡献**——Gemini-2.5-Flash 加 reasoning 提升，Claude Sonnet-4.5 加 reasoning 反而下降（BLEU 18.131 → 17.342）。

## 问题背景
历史档案是跨学科研究的宝库：人文学科用它们分析政治动态与文化演变，自然科学用它们追踪日食、超新星、地震等自然现象。朝鲜王朝《太宗实录》与《王氏朝鲜实录》被公认为最杰出的历史档案之一，跨越 **500 多年**，涵盖天文观测、地震、饥荒、疫病等主题。NIKH 主导的 AJD 英译项目因需要同时精通汉字与英语的专家人工翻译，预计 **22 年、约 2,000 万美元**。

直接用中文-英文 LLM 处理这些语料会遇到四重障碍：
1. **根本的字体不匹配**：中文模型通常用简体，而韩国汉字保留繁体，导致字符不兼容。
2. **语义与句法差异**：即便字符相同，同形异义词在两种语言中已演化出不同含义。
3. **韩国特有的汉字用法**：反映本土语法结构，语序常偏离标准中文句法。
4. **专有名词音译错误**（最关键）：中文-英文模型按**中文发音**而非**韩语发音**转写人名与地名。这不仅降低翻译质量，还引入**事实错误**。

已有工作：Kang et al. (2021) 用 AJD+JRS 平行语料做了 Hanja→Korean 模型；Son et al. (2022) 基于部分 Hanja-English 语料提出了 Hanja-Korean-English 多语模型，但受限于人工翻译数据稀缺，从零训练的模型性能有限。

## 方法
### 1. 数据构建
- 从 NIKH 获取 AJD 文档，编译出 **350K Hanja-Korean 对**与 **17.7K Hanja-Korean-English 三元组**（因 AJD 文档原由汉字译为韩语，Hanja-English 数据自然形成三元组）。
- 从 Hanja-English 子集中各取 1,000 条做 $D_{valid}$ 与 $D_{test}$，剩余 **15.7K** 做 $D_{train}$。
- 为缓解时期偏置的评测偏差，额外构建 $D^{test}_{NT}$：从**未翻译**语料中按每位国王各 80 条采样，共 **2,080 条**。**$D^{test}_{NT}$ 被严格排除在伪标注过程与训练数据之外。**
- **去污染流水线**：汉字是表意文字、单字承载密集语义，因此**字符级**匹配特别有效。对每个测试实例用 BM25 从 $D_{train}$ 检索 top-10 候选，计算字符级归一化 Levenshtein 相似度，丢弃超过 **0.9** 阈值的候选。选 0.9 是因为历史档案常有形式化的行政模板，改动单个实体或动作就会极大改变翻译语义；阈值低于 0.9 会过度丢弃语义上确有区分的评测实例。该流水线从 $D_{test}$ 滤掉 83 条、从 $D^{test}_{NT}$ 滤掉 3 条、从 200 条人工评测子集滤掉 1 条。
- 过滤掉超过 800 字符的文档后，从除世宗朝外的未翻译语料构建 **$D_{aug}$：315K 条伪标注样本**（实际处理 317.4K 对）。
- **术语表（glossary）**：NIKH 提供含专有名词语义与英文发音的词库，编译出 **25K 条**术语表，在伪标注过程中使用。

### 2. 伪标注流水线（Proposer–Fusor）
整体框架为三阶段：**1) 伪标注数据增强 → 2) 微调 → 3) 翻译剩余语料**。

**输入增强**（三个来源）：
- **韩语译文**：把对应的韩语文本与汉字文本一起给模型，以弥补 LLM 对汉字理解能力的不足。
- **术语表**：源文本中出现精确匹配时，把术语（汉字源、韩语读音、英文译名）附到 prompt 中，例如 `{"hanja": "正朝使", "korean": "정조사", "term": "envoy for the New Year's greeting"}`、`{"hanja": "崔士儀", "term": "Choe Saui"}`。
- **RAG few-shot**：用基于 embedding 的检索器为输入汉字文档 $h$ 从 $D_{train}$ 检索 top-K 相似文档 $S(h)$，以 (Hanja, Korean, English) 三元组形式喂给 Proposer 与 Fusor。

**双阶段架构**：
- **Proposer**（1-1）：生成多个翻译草稿。检索器查询使用输入文档的**韩语部分**（因为 embedding 模型在韩语上训练得更多）。
- **Fusor**（1-2）：把草稿与原文一起融合出最终译文。检索器查询使用**输入汉字 + 英文草稿**。
- 后端：**Gemini-2.5-Flash**（Proposer 与 Fusor 均用），检索器用 **Gemini-Embedding**；Proposer 64 个 few-shot、Fusor 12 个；Fusor 从 5 个草稿（temperature 0.3）合成最终句。
- Fusor 通过对草稿的整体检视来**缓解误译并利用扩展信息提升质量**。

### 3. 模型训练
- 骨干：**Qwen3-32B**（也训练了 8B 版本）。
- **两阶段学习**：第一阶段用 $D_{aug}$ 学汉字语义与专有名词音韵模式；第二阶段用 $D_{train}$ 对齐人类级风格细节。
- 硬件：8 张 H200；第一阶段 15.1 小时，第二阶段 1.2 小时。
- 最终部署：8 张 H200，**94.6 小时**翻译 **2.09 百万份**剩余 AJD + JRS 文档。

- **Main results — 人工专家评测**（200 条跨国王均匀采样，$D^{test}_{NT}$，1–5 分 + 成对偏好）：
  - 平均分：HERIT **3.93** vs 基线（Qwen3-32B 仅训 $D_{train}$）**3.22**。
  - 成对偏好：HERIT **66.84%** vs 基线 33.16%。

- **Ablations / 其他**:
  - **数据规模效应**：伪标注数据量从 213K 增至 218K，BLEU 从 36.0 升到 38.5（Qwen3 8B 与 32B 两条曲线），性能随伪标注量持续上升。
  - **推理能力无益**：Gemini-2.5-Flash 加 reasoning 提升（15.720 → 17.183 BLEU），Sonnet-4.5 加 reasoning **下降**（18.131 → 17.342）。作者引用先前调查称 reasoning 对机器翻译无显著贡献。
  - **两阶段 > 混合训练**：36.849（混合）vs 38.432（两阶段），作者归因于 $D_{train}$（15.7K）与 $D_{aug}$（315K）的严重规模失衡使混合训练无法有效利用两者。
  - **直译 > pivot**：HERIT（38.432）显著优于 Pivot-MT（35.539），说明直接 Hanja→English 优于两级 pivot，以避免误差传播。
  - **RAG 可蒸馏进参数**：训练与推理都用 glossary & RAG 的 Qwen3-32B 得 38.117 BLEU，但需 8K+ 上下文（输入 prompt 长度增加 **13–14 倍**）、训练算力增加 **9 倍**；HERIT 则把外部知识蒸馏进参数，retrieval-free 且高效。
  - **时间偏置分析**：因人工语料集中在世宗朝，Qwen3 在世宗朝与 HERIT 表现相当；在**其他朝代 HERIT 持续更优**，验证伪标注缓解了时间过拟合。
  - **定性分析**：韩语发音转写正确（Hunyuan-MT-7B 错误地依赖中文音韵）；**语义分歧例**——`房子` 在标准中文意为"house"，但在朝鲜王朝语境中指"female palace servant"，Hunyuan-MT-7B 误译。
  - **去污染**：字符级归一化 Levenshtein 相似度 >0.9 过滤，从 $D_{test}$ 剔除 83 条、$D^{test}_{NT}$ 剔除 3 条、人工评测子集剔除 1 条。

## 关键洞察
1. **"外部知识蒸馏进参数"优于"推理时检索"**：RAG 版本 38.117 vs HERIT 38.432，但 RAG 需要 13–14 倍输入长度与 9 倍训练算力；HERIT 把 glossary 与检索到的参考**蒸馏进权重**，从而 retrieval-free。这对任何"要把领域知识塞进低资源领域模型"的场景都是可迁移的范式。
2. **术语表 + 同语言辅助文本是低成本的巨大增益**：基础 prompt 15.720 BLEU → 加 glossary 23.747 → 再加韩语译文 25.457。对 LLM 不熟悉的书写系统，**提供该系统的已翻译对应文本**是最有效的上下文增强之一（对照 2611.04349 中"翻译方向不对"的类似发现）。
3. **检索查询语言的选择影响显著且方向反直觉**：用**韩语**而非汉字作检索查询效果更好（36.430 vs 36.223），因为 embedding 模型在韩语语料上训练得更多——**检索查询语言应匹配 embedding 模型的强项，而非源文本的字面形式**。
4. **两阶段训练优于混合训练**，原因是规模失衡（15.7K vs 315K，20 倍差）。这是一个在数据增强类工作中常被忽略的工程要点：直接 concat 混合会让小数据集被淹没。
5. **模型选择中推理能力几乎无关**：Sonnet-4.5 加 reasoning 反而变差。这对成本敏感的大规模伪标注任务意味着——**选便宜的非推理模型**（Gemini-2.5-Flash，$0.42 vs Gemini-2.5-Pro 的 $18.17）即可，性能损失极小甚至更好。
6. **语言特有的音韵规则是可捕捉的、且必须显式指定**：汉字→英文的关键错误源是专有名词按中文发音转写。术语表（提供韩语读音 + 英文译名）与去污染流水线共同保证了专名正确性。
7. **伪标注同时解决"数据稀缺"与"时间偏置"两个问题**：$D_{aug}$ 覆盖除世宗朝外的**所有**朝代（315K vs 人工 15.7K），因此模型在未见朝代上仍优于只用人工语料训练的基线——这不是过拟合，而是真正的跨时期泛化。

## 局限性
- **BLEU 提升幅度需谨慎解读**：在 Dtest 上相对基线的绝对增益仅约 1.5 BLEU（38.432 vs 36.930），虽然方向一致且人工评测与跨朝代 LLM 评测都支持，但自动指标（BLEU/METEOR/chrF++）在历史汉语文本上的可靠性存疑；chrF++ 甚至在"仅 $D_{train}$ + glossary & RAG"（62.338）与 HERIT（62.525）之间只差 0.19。
- **强依赖配套资源**：术语表（NIKH 词库 25K 条）与 Dtrain 人工翻译语料都是本领域独有的。方法在缺乏此类资源的语言/领域是否成立未验证。
- **两阶段训练的顺序假设**：先大规模伪标注、后小规模人工的风格对齐，隐含假设是第一阶段学到的东西在第二阶段不会被冲掉。若人工语料更丰富或分布差异更大，顺序可能需调整。
- **Dtest 只有 1,000 条且集中在世宗朝**：主表（Table 4）的主要结论建立在这个单一朝代上；跨朝代结论依赖 LLM-as-judge（Sonnet-4.6）与 200 条人工评测，样本较小。
- **人工评测规模小**：200 条、1–5 分制 + 成对偏好；虽由汉文文献与韩国史领域专家完成，但样本量限制了统计把握度。
- **LLM 评测存在循环风险**：虽然用 Sonnet-4.6 避免与训练过程相关，但评测器仍是 LLM，其偏好可能与伪标注生成器的偏好同源。
- **训练成本未被充分报告**：8×H200、16.3 小时（仅训练）加上 94.6 小时推理翻译 209 万份文档，绝对成本可观（作者只给出了伪标注的 $3,000，未给出完整训练的美元成本）。
- **FusioN 的收益与成本权衡不清晰**：最终配置（D=5, K=64/12）成本 $7.059，而 K=64 的 RAG 单阶段只要 $5.646 却得 37.905 BLEU——FusioN 多花约 25% 成本只换来 0.56 BLEU，在 315K 样本规模下这笔账未必划算（作者未在伪标注全量成本上做此权衡）。
- **未与更新更强的翻译模型直接对比**：H2KE 的 BLEU 24.62 是引用原论文数字而非重跑，可能不可比。
- **"female palace servant"这类语境依赖语义**说明汉字→英文仍存在深层文化语义缺口，本文主要靠术语表覆盖，未系统性处理。

## 适用场景
- **低资源领域的领域适配**：人工标注稀缺但存在"源语言 A ↔ 目标语言 B 的平行语料 + 少量 B↔C 人工翻译"的场景——本文正是用 Hanja-Korean 大量平行语料 + 少量 Hanja-English 人工语料构造伪标注。
- **历史/法律/医疗等有配套术语表的垂直领域**：术语表把"专名音译错误"这一最大错误源降到最低。
- **需要跨越时间/世代泛化的模型**：当训练标签偏向某个子分布时，伪标注可覆盖全分布。
- **需在大规模语料上落地翻译/摘要的工程团队**：94.6 小时 / 209 万份的吞吐量与公开的模型与语料可直接复用。

**不适用于**：没有目标语言平行语料可用的场景（伪标注的原料缺失）；完全没有术语资源且领域依赖文化语义的场景；对零样本/少样本 API 直接翻译已足够的简单场景（本文的 8B 模型 + 两阶段微调路线可能过重）；以及期待人工级翻译质量的场景——专家评分仅 3.93/5。
