# IndicIPR-QA: A Benchmark for Extractive Question Answering on Indian IPR Laws

## 摘要
本文提出 **IndicIPR-QA**——首个覆盖印度全部七部知识产权法（IPR）的**抽取式问答**基准。数据集含 **4,462 个 QA 对**，来自 **1,116 个法条上下文**（statutory contexts），涵盖 Patents Act 1970、Trade Marks Act 1999、Copyright Act 1957、Designs Act 2000、GI Act 1999、Semiconductor IC Layout-Design Act 2000、Plant Varieties & Farmers' Rights Act 2001。问题与答案由 **GPT-4o** 生成，经**九道自动质量过滤**、**单模型与三模型 LLM 评测**以及**200 对人工审计**（两名法学毕业生）验证；按**法条（section）级划分**，train/valid/test = **3,710/408/344**，跨切分无源上下文重叠。基线结果：**BM25 检索 token-level F1 仅 20.21**，而微调的 **InLegalBERT 达 85.02**（差距 64.81 分），说明单纯词面匹配不足以回答法律问题；七部法案之间表现差异显著（Designs 100.00 → Plant Varieties 53.20）。

## 核心贡献
1. **基准构建**：五阶段流水线（语料抽取 → GPT-4o QA 生成 → 质量控制 → section 级划分 → 审计验证），算法 1 完整给出。
2. **九步质量控制 + 三层验证**：规则过滤（5,721 → 4,689）、context-balanced 选择（→ 4,462）、LLM-as-judge 单模型与三模型 ensemble、200 对人工审计。
3. **系统性基线**：4 个 BERT 系 encoder + 3 个开源 LLM（zero/few-shot）+ BM25（含 oracle window），并给出逐 Act 的误差分析。
4. **可泛化性分析**：train-test context Jaccard = 0.00，测试集中 **11.1%** 的答案 token 类型、**15.3%** 的问题 token、**13.7%** 的上下文 token 未在训练集出现。

## 方法与架构
**语料**：从 India Code 门户（indiacode.nic.in）收集七部法案 PDF，用 pdfplumber 抽取；去除目录页、编辑性修正标记（"Ins."、"Subs."、"w.e.f."）、规范化空白；按句安全分块（chunk size $\delta=1400$ 字符）得到 **1,173 个上下文**。

**QA 生成**：对每个上下文用 GPT-4o 生成至多 5 个 QA 对，要求结构化 JSON 输出、问题针对具体事实或法条、**答案必须逐字从上下文复制**；禁止改写答案、yes/no 或模糊问题、答案泄漏、近重复问题。共得 **5,721** 个候选。

**九步过滤**：F1 字段非空；F2 答案为上下文的精确 span；F3 答案长度 5–350 字符；F4 答案覆盖上下文 < 85%；F5 问题至少 5 词、以问号结尾、避免模糊的"章节概述"式提问；F6 移除含答案的问题；F7 移除截断上下文；F8 移除答案中的编辑性标记；F9 移除纯 1–4 位数字答案。共排除 **1,032** 对（F3 排除 595、F4 排除 417），剩 4,689。

**Context-balanced selection**：按问答长度排序候选，同时保持跨上下文覆盖，产出最终 4,462 对 / 1,116 上下文。

**划分**：按 section 分组得 **681 个唯一法条**，per-Act 分层划分（seed 42）→ 3,710/408/344。

**LLM-as-judge**：Gemma 3:12B 单 judge 与 Gemma 3:12B + Llama 3.1:8B + Mistral 7B 三模型 ensemble（至少两模型同分则采用），四项标准（Q_SPECIFIC、A_SUFFICIENT、A_MINIMAL、LEGAL_RELEVANT），1–3 分，任一项为 1 则 flagged。

**人工验证**：两名法学毕业生独立审计 200 个测试对（seed 42，跨七部法案：copyright 25、designs 24、GI 32、patents 29、plant varieties 28、semiconductor 30、trade marks 32），按 1–3 分评 question clarity、answer correctness、answer minimality，用 unweighted 与 quadratic-weighted Cohen's κ。

**模型配置**：4 个 BERT encoder（BERT-base uncased、LegalBERT-US、InCaseLawBERT、InLegalBERT）用 `BertForQuestionAnswering`（输入 `[CLS] question [SEP] context [SEP]`）微调；统一超参：AdamW，lr **3×10⁻⁵**，50 warm-up steps + 线性衰减，weight decay 0.01，effective batch size 32，max seq length **384**，document stride **128**，3 epochs，random seed 42，按 validation F1 选 checkpoint。推理时用 stride 128 的重叠滑窗切分长上下文，**constrained decoder** 跨窗口选最高分的合法 span 并返回原文。3 个开源 LLM（Llama 3.1:8B、Mistral 7B、Qwen2.5:7B）做 zero-shot 与 3-shot 评测。BM25 用标准参数 $k_1=1.5$、$b=0.75$：

```math
BM25(D,Q)=\sum_{q\in Q} IDF(q)\cdot\frac{f(q,D)(k_1+1)}{f(q,D)+k_1\left(1-b+b\frac{|D|}{\bar{|D|}}\right)}
```

## 实验设置
- **数据**：4,462 QA / 1,116 上下文 / 681 唯一法条 / 七部法案；上下文长 171.3 词、问题长 11.9 词、答案长 35.6 词。
- **评测指标**：EM、token-level F1、character-level F1（Char-F1）。
- **显著性**：paired bootstrap 检验，10,000 次重采样，Holm 校正。
- **消融**：逐过滤器 leave-one-out；模型级过滤器消融（用 InLegalBERT 在不同训练变体上训练，val/test 固定）；初始保留率 sweep。

## 实验结果
**基线（Table VII，测试集 344 对）**：

| 系统 | EM | F1 | Char-F1 |
|---|---|---|---|
| BM25 retrieval | 0.00 | **20.21** | 77.10 |
| BM25 oracle window | 14.24 | 51.30 | 85.23 |
| BERT-base | 63.66 | 83.33 | 86.38 |
| LegalBERT-US | 65.12 | 84.66 | 86.67 |
| InCaseLawBERT | 63.08 | 84.37 | 86.40 |
| **InLegalBERT** | 63.66 | **85.02** | 87.26 |
| Mistral 7B (ZS) | 18.31 | 67.11 | 75.07 |
| Mistral 7B (FS) | 24.71 | 68.83 | 76.01 |
| Llama 3.1:8B (ZS) | 33.43 | 74.78 | 79.61 |
| Llama 3.1:8B (FS) | 33.43 | **77.02** | 79.78 |
| Qwen2.5:7B (ZS) | 29.94 | **77.59** | 81.04 |
| Qwen2.5:7B (FS) | 34.30 | 76.39 | 78.60 |

最佳 prompted 结果比 InLegalBERT 低 **7.43 F1 分**。Encoder 之间差距很小：InLegalBERT vs BERT-base Δ = +1.70（adjusted p = 0.397）、vs LegalBERT-US +0.36（p = 1.000）、vs InCaseLawBERT +0.66（p = 1.000），**均无统计显著差异**——领域预训练单独带来的增益不成立。

**InLegalBERT 误差分析**：125 个非 EM 预测中 **100（80.0%）是 span 边界错误**，20（16.0%）重叠度低，2（1.6%）个别词不同，2（1.6%）部分重叠，1（0.8%）完全错误。典型案例：从 Section 14 正确子句开始却延续到下一个枚举子句。

**逐 Act 表现（Table VI，按 test F1 排序）**：

| Act | n_all | n_test | 平均答案词数 | Q-Ctx 重叠 | F1 |
|---|---|---|---|---|---|
| Designs | 173 | 24 | 43.4 | 0.320 | 100.00 |
| Patents | 1,143 | 69 | 35.8 | 0.429 | 98.40 |
| Semiconductor | 585 | 47 | 22.1 | 0.418 | 91.53 |
| Trade Marks | 1,106 | 88 | 31.9 | 0.416 | 83.83 |
| GI | 551 | 51 | 51.8 | 0.458 | 83.66 |
| Copyright | 349 | 25 | 62.3 | 0.447 | 79.41 |
| Plant Varieties | 555 | 40 | 21.9 | 0.636 | **53.20** |

七部法案上 question-context unigram 重叠与 F1 呈强负相关（r = **−0.928**，n = 7，仅作探索性解读）。Plant Varieties 重叠最高（0.636）但 F1 最低。Copyright 多子句答案占 **53.9%**（Patents 仅 13.7%），F1 也更低（79.41 vs 98.40）。

**答案结构分析**：主题分布——authority 29.4%、procedure 12.0%、rights 9.5%、conditions 7.9%、definitions 5.8%、duration 2.3%、penalties 1.7%、其他 31.4%；**19.9%** 的答案含分号，**5.9%** 含 "subject to"。按中位数 33 词分组，短答案 F1 **86.24** vs 长答案 **83.78**；多子句答案的 boundary-sensitive EM **56.10** vs 单子句 **66.03**；出现在上下文靠后位置的答案 F1 略低（84.21 vs 85.83）。

**质量验证（Table III）**：单 judge（Gemini 3:12B）——question specificity 2.92 / flagged 1.1%，answer sufficiency 2.92 / 2.8%，answer minimality 2.52 / 4.2%，legal relevance 2.97 / 0.7%，共 flagged 222 对（5.0%）；三模型 ensemble 对应 2.93 / 2.99 / 2.85 / 3.00，flagged 26 对（0.6%）。三个 judge 仅在 **8.0%** 的对上四标准全部同分。

**人工审计（Table IV，200 对）**：question clarity κ_UW = −0.008、κ_QW = 0.051、联合可接受 **99.0%**（天花板效应：198/200 双方都 ≥2）；answer correctness κ_UW = 0.117、κ_QW = 0.328、联合可接受 **95.0%**；answer minimality κ_UW = 0.312、κ_QW = 0.613、联合可接受 **75.5%**（至少一方接受 82.0%；36 对被双方判为非最小）。

**过滤器消融（Table I，leave-one-out）**：禁用 F3 多接纳 **368** 对（+7.8%），禁用 F4 多接纳 **417** 对（+8.9%）——span 长度是自动过滤的主要来源。模型级消融（Table II，InLegalBERT）：clean selected 84.11 F1；去掉 F3+F4 → 84.58（+0.47）；只去掉 F3 → 84.56（+0.45）；只去掉 F4 → 83.90（−0.21）；用未过滤 raw candidates → 83.44（−0.67）；用 heuristic all（不做 selection）→ 82.77（**−1.34**）。作者明确说明这些是单 seed 运行、无显著性检验，仅作诊断。

**泛化性**：train-test context Jaccard = 0.00，七个 Act 的 novel test-context rate 均为 **100%**；测试集 1,234 个唯一答案 token 类型中 **137（11.1%）** 未见于训练答案，15.3% 测试问题 token 与 13.7% 测试上下文 token 未见于训练。但 4,462 个问题小写归一化后只有 4,118 个唯一，常见开头为 "what does"（1,157）、"under section"（960）、"what is"（875）——GPT-4o 的问题模板模式会同时出现在 train 与 test。

## 局限性
- 作者自述：基准限于**英文、可回答、单上下文**问题，且问题由 GPT-4o 生成；结果衡量的是"在同一生成流程下、面对新法条上下文"的表现，不代表独立撰写的法律提问能力；人工审计因界面截断长上下文，只具诊断性；过滤器消融是单 seed、无显著性检验，仅作诊断而非证明每个过滤器都提升模型性能；领域预训练模型之间的差异不显著。
- 我的批判性意见：① **train/test 问题模板同源**是这一基准最大的方法学隐患——"what does / under section / what is" 三个开头覆盖了相当比例的问题，模型可以靠模式而非法条理解取得高分，作者自己也承认；② 人工标注的 inter-annotator agreement 极低（correctness κ_UW = 0.117），意味着"正确性"本身在法律专家之间都没有共识，用它作为质量基准的说服力有限；③ Designs 的 100.00 F1 来自仅 24 对测试样本，per-Act 排序因此极不稳定；④ 84–85 F1 的高分部分来自 "constrained decoder 从上下文中挑 span" 这一任务设定（答案必定是上下文子串），与真实法律咨询中"检索 + 综合 + 引用"的任务形态差距很大；⑤ 未提供无答案（unanswerable）样本，无法度量模型的拒答与幻觉率，而这恰是法律场景的核心风险。

## 评估与建议
- 是否推荐深入阅读：**是**（低资源语言法律 NLP 的基准构建与质量控制流程值得借鉴）
- 适用场景：法律 NLP 基准建设、低资源语言抽取式 QA、领域 BERT 微调、LLM 法律问答能力的对照评测
- 与知识库的关联：与 SQuAD/CUAD/JEC-QA 等抽取式 QA 基准、Indian 法律预训练模型（InLegalBERT、InCaseLawBERT）、以及"合成数据 + 多层质量控制"类数据集工作直接相关；可作为低资源 benchmark 方法论的模板
