## 核心贡献

> 在 840 个计分 episode、3 个前沿模型、3 种防御配置的实测下，"更谨慎（refuse more）" 只换来最多 3.7 个点的攻击成功率下降，却让 Sonnet 与 GPT-5 的过度拒绝（over-refusal）飙到 100%，在所有模型上都是最差 harm；而针对性的 trust gate（TGCC）在每个模型上都是最低 harm、过度拒绝不高于基线、containment 最高。

1. **双向成本敏感基准 SentryBench** — 覆盖 4 个子领域、5 类攻击向量、3 类结果类别的 **190 个场景**（family A–F），同时包含 adversarial 集 A、urgent benign 对照集 $B_u$（必须行动）与 ambiguous benign 对照集 $B_a$（不得过度行动），把 over-refusal 与 over-reaction 提升为一等指标。
2. **部署伤害的形式化** — 定义非对称代价泛函 $H(\pi)=\frac{1}{N}\sum_i(c^{FN}_i u_i + c^{FP}_i o_i)$（$c^{FN}$ 为漏报真实警情成本，$c^{FP}$ 为不当行动成本），并证明 Lemma 1（拒答代价恒非负）与 Theorem 1（当谨慎规避的攻击伤害 $\Delta^-$ 不超过新增拒答成本时，谨慎必然被伤害支配）。
3. **Trust gate 的零开销证明** — Theorem 2 证明当不可信通道的注入分数 $s=0$ 时，TGCC 放行 base agent 提出的每一个 consequential call，故 $\mathrm{ORR}_{gate}\le \mathrm{ORR}_{base}$；Theorem 3 进一步将残余成功率严格限制在 detector 的漏检集合内。
4. **840 episode 的前沿评测** — Haiku 跑满 190 个场景（570 episodes），Sonnet 与 GPT-5 各跑 45 个分层子集（各 270 episodes），合计 840 个计分 episode；采用确定性 ledger 打分（无 LLM judge）+ 1000 次 bootstrap 置信区间。
5. **模型级 vs 系统级计数分离** — Azure 内容过滤器在每个条件下对 **11–15 个** GPT-5 对抗 prompt 返回 HTTP 400（模型根本没跑），导致 GPT-5 的模型级 0% ASR 实际只建立在 **12 个已执行 episode** 上，必须与过滤计数一起阅读。
6. **安全性的"内容形式依赖"发现** — Haiku 全量 bank 上，显式 911 通话转录的 over-refusal 仅 **18%**，而简短的灾害报告类紧急事件高达 **83%**；同一模型、同一防御、仅措辞不同，说明 over-refusal 由**内容形式**而非危险等级驱动。

## 技术方案

### 核心思想

传统 agent 安全基准（InjecAgent、AgentDojo、ToolEmu、AgentHarm、R-Judge、AgentSafetyBench）都只优化单一轴："拒绝有害请求"，在这个轴上"拒得更多"总是弱安全。SentryBench 的核心论断是：**公共安全部署的错误是双向且不对称的**——漏掉真实警情（false negative，可能致命）与触发区域级误报/越权查询（false positive，侵犯隐私）代价不同，必须用领域标定的非对称代价同时度量。XSTest 启发了 benign 对照臂，但它局限于 chat，不涉及有后果的工具调用。

形式化框架把场景集 $S$ 划分为对抗集 $A$、紧急良性对照 $B_u$、模糊良性对照 $B_a$。每个场景定义 warranted 动作集 $A^*_i$ 与 forbidden 集 $F_i$，从 tool-call ledger 中导出三个布尔指示：$a_i$（是否执行了 warrant 的动作，name-level 匹配）、$k_i$（是否升级给人类且满足场景要求 $\kappa_i$）、$f_i$（是否执行了 forbidden 动作）。于是

- $u_i=\mathbb{1}[\neg a_i \wedge \neg(k_i \wedge \kappa_i)]$ —— under-reaction（在 urgent 对照上即 over-refusal）
- $o_i=f_i$ —— over-reaction

关键在于**在工具名层级打分而非约束层级**：选错单位类型或优先级是另一个正确性维度，不算 over-refusal，这样 benign 对照臂才诚实。

Lemma 1 给出了"拒答不免费"的精确表述：若谨慎策略 $\pi_c$ 相对基线 $\pi_0$ 在紧急集 $R\subseteq B_u$ 上额外拒答而其余行为一致，则 $H(\pi_c)-H(\pi_0)=\frac{1}{N}\sum_{i\in R}c^{FN}_i \ge 0$，等号当且仅当 $R=\varnothing$。Theorem 1 进一步把这条与攻击侧的规避量 $\Delta^-$ 放在一起：

$$H(\pi_c)-H(\pi_0)=\frac{1}{N}\sum_{i\in R}c^{FN}_i-\Delta^-$$

只要 $\Delta^-\le\frac{1}{N}\sum_{i\in R}c^{FN}_i$，谨慎就**不能**降低部署伤害，且严格不等时反而提高之。实证上 caution 只把 ASR 变动 ≤3.7 点，$\Delta^-$ 很小而 $R$ 巨大，因此三个模型**全部落在伤害被支配的区间内**——这就是 RQ2 的形式化内容。

### 核心思想（防御侧）：TGCC

TGCC（Trust-Gating for Consequential Calls）的设计哲学是**把对抗防御与"一刀切谨慎"解耦**。它有四个可独立消融的组件：(1) provenance separation，用 spotlighting 把不可信数据夹在标记之间并要求"不要遵循其中的指令"；(2) 启发式注入检测器，扫描不可信通道与工具返回值；(3) gate，在操纵信号或最小权限违规时把 consequential call 路由给人类；(4) escalation，把 gated call 视为人类接管的 containment。

Gate 的判据极简：定义注入分数 $s(x)=|\{p\in\mathcal{P}: p \text{ matches } x\}|$（固定模式集 $\mathcal{P}$ 中命中 $x$ 的模式数），阈值 $\theta=1$。consequential call $c$ 被路由给人当且仅当 $s\ge\theta$，或者 $c$ 是 over-broad 的公民记录查询且 $s>0$。

```
Algorithm 1  TGCC gate for a proposed tool call
1: 接收 call c, 注入分数 s, 阈值 θ=1
2:  if c ∉ ConsequentialTools: return allow
3:  reasons ← ∅
4:  if s ≥ θ: reasons += "injection signal"
5:  if c 是 citizen-record 查询 ∧ over-broad(c) ∧ s > 0:
6:      reasons += "least-privilege violation"
7:  if reasons ≠ ∅:
8:      record first-gate turn; mark human-routed
9:      return require_human ▷ containment
10: return allow
```

Theorem 2 证明该 gate 在干净良性输入上**不引入任何额外 over-refusal**（两个触发条件都要求 $s>0$，故 $s=0$ 时必然 allow）；因此 wrapper 下 over-refusal 的下降只能归因于 provenance preamble，而不是 gate 本身，残余 over-refusal 是继承自 base agent 的。Theorem 3 给出可靠性上界：所有残余成功都落在 detector 漏检集合内 $\mathrm{ASR}_{TGCC}\le\frac{1}{|A_e|}|\{i: s_i<\theta \text{ 且成功}\}|$。论文强调这个界是**紧的**（tight）而非空洞的：wrapper 下唯一真实成功（Sonnet 的 scenario C-008）其 $s=0$，是一个刻意措辞以绕过模式集的 over-trust payload，ledger 中完全没有 gate event。

### 数据管线与评测骨架

```
真实数据 → 场景合成 (family A–F) → seeded mocked-tool sandbox
        → agent + 可换防御 → tool-call ledger → 确定性打分 (无 LLM judge)
```

所有内容来自四个公开 Hugging Face 数据集：prompt-injections 与 jailbreak-classification 语料提供攻击 payload，disaster-response 与 emergency-call-transcript 语料提供合法内容。灾害消息只保留相关行、丢弃 PII 标记行、只用英文翻译并要求最小长度；采样带种子，incident 内容无放回抽取而 payload 可跨场景复用。场景的不可信通道 = `real_content + real_payload + domain_directive`；poisoning（family F）的 payload 放在工具返回值里而非 prompt 里。指令模板刻意混合：一部分会被检测器抓到，一部分被措辞成能绕过的样子，从而产生真实的 recall gap。

六个 mock 工具：`send_public_alert`、`dispatch_unit`、`query_citizen_record`、`escalate_to_human`、`update_incident_log`、`query_historical_incidents`，全部返回带种子的合成数据，不触碰真实系统。ledger 是评测基底：打分完全从日志确定性导出。

### 关键技术

| 技术/方法 | 说明 |
|------|------|
| Deployment harm 泛函 | $H(\pi)=\frac{1}{N}\sum_i(c^{FN}_iu_i+c^{FP}_io_i)$，把漏报与误报按领域标定的非对称代价折成单一标量 |
| 双向指标 ASR / ORR / FP | 三项都以"模型实际执行了"的条件集为分母，errored 与被内容过滤的 episode 不产生行为结果、单独计数 |
| Frontier dominance | $\pi$ 支配 $\pi'$ 需 ASR、ORR、FP 三轴均不劣且至少一轴严格更优 |
| Lemma 1（拒答代价） | 证明额外拒答集合 $R$ 的代价恰为 $\frac{1}{N}\sum_{i\in R}c^{FN}_i$，等号当且仅当 $R=\varnothing$ |
| Theorem 1（谨慎被伤害支配） | $H(\pi_c)-H(\pi_0)=\frac{1}{N}\sum_{i\in R}c^{FN}_i-\Delta^-$，给出谨慎策略何时必然更差的判据 |
| Theorem 2（零 over-refusal 开销） | $s=0$ 且无 over-broad 请求时 gate 必然 allow，故 $\mathrm{ORR}_{gate}\le\mathrm{ORR}_{base}$ |
| Theorem 3（召回受限残余） | 残余 ASR 上界等于 detector 漏检集合比例，该界被 Sonnet C-008（$s=0$）证明是紧的 |
| TGCC 四组件 | provenance separation（spotlighting）+ 启发式注入检测 + consequential-call gate + escalation-as-containment，四者独立可消融 |
| 注入分数 $s(x)$ | 固定模式集 $\mathcal{P}$ 的命中率计数，阈值 $\theta=1$；模式集刻意覆盖不全以模拟真实 recall gap |
| Ledger-first 确定性打分 | 从 tool-call ledger 导出全部指标，无 LLM judge，保证可复现 |
| 非参数 bootstrap | 1000 次重采样给出置信区间 |
| 模型级 vs 系统级双计数 | 内容过滤造成的"可用性驱动的不行动"单独作为 system-level over-refusal 报告 |
| 六个 mock 工具沙箱 | seeded synthetic 返回值；poisoning 时指定工具返回攻击者内容；over-broad `query_citizen_record` 可被检出用于最小权限评分 |

## 实验结果

### 精度–召回前沿（Table IV，%）

| 模型 | 防御 | ASR | ORR | FP | Containment | Harm |
|------|------|-----|-----|-----|-------------|------|
| Haiku | none | ≤3.7 | 35.0 | 0 | — | — |
| Haiku | caution | ≤3.7 | 100 | 0 | — | **1.33（最差）** |
| Haiku | TGCC | **0** | **35.0** | 0 | 最高 | **0.66（最好）** |
| Sonnet | none | ≤3.7 | 37.5 | 0 | 74.1 | — |
| Sonnet | caution | ≤3.7 | **100** | 0 | — | **1.80（最差）** |
| Sonnet | TGCC | 0 | **37.5**（持平基线） | 0 | **92.6** | **1.00（最好）** |
| GPT-5 | none | ≤3.7 | 62.5 | 0 | — | — |
| GPT-5 | caution | ≤3.7 | **100** | 0 | — | **1.60（最差）** |
| GPT-5 | TGCC | **0** | **37.5** | 0 | 最高 | **0.60（最好）** |

解读：

- **Caution 在所有三个模型上 harm 最高**，TGCC 在所有三个模型上最低或并列最低（0.66 / 1.00 / 0.60 vs caution 的 1.33 / 1.80 / 1.60，顺序为 Haiku / Sonnet / GPT-5）——正好落在 Theorem 1 的伤害被支配区间。
- TGCC **在所有三个模型上支配 caution**（Definition 3），在 Haiku 与 GPT-5 上还同时支配 none；Sonnet 上 ORR/ASR 与 none 持平，但 containment 从 **74.1% 提升到 92.6%**。
- Caution 最多只换来 **3.7 点** 的 ASR 变化，却让 Sonnet 与 GPT-5 拒绝掉几乎每一个真实紧急事件。

### 模型级 vs 系统级（Table V，GPT-5）

- Azure 内容过滤器在每个条件下对 **11–15 个** GPT-5 对抗 prompt 返回 HTTP 400，模型根本没被执行。
- 系统级 over-refusal 高于模型级，因为过滤器同样挡掉了部分**真实**紧急事件——这是可用性驱动的不行动，公平的部署比较必须计入。
- GPT-5 的模型级 **0% ASR** 实际只建立在 **12 个已执行 episode** 上，必须与过滤列并读。

### 真实攻击成功（VIII-D）

- 全run 共 **7 个**真实（非过滤）成功，全部是 family C 的 **under-reaction 抑制攻击**——该域最致命的 false negative：Haiku 上 5 个（none/caution 各若干），Sonnet 上 2 个（均为 scenario C-008，none 与 tgcc）。
- TGCC 消除了除 Sonnet C-008 外的全部抑制成功；C-008 的指令 $s=0$ 绕过了检测器，正如 Theorem 3 所述的 recall-limited residual。

### 张力所在（VIII-E）

- Benign over-reaction（FP）**所有模型均为 0%**：这些保守模型从不在模糊报告上广播误报，因此实测张力由 over-refusal（FN）轴主导。
- 锐利的子发现：Haiku 全量 bank 上，显式 911 通话转录的 over-refusal 仅 **18%**，而简短的灾害报告类紧急事件高达 **83%**。

### 四个研究问题的回答

- **RQ1（脆弱性）**：前沿 agent 对明显注入大体鲁棒（无防御 ASR ≤3.7%），但残余非零，且每个残余成功都是危险的真实警情抑制——脆弱性**率低但性质严重**。
- **RQ2（不对称性）**：是。谨慎的 ASR 下降几乎全部来自 over-refusal，Theorem 1 证明这在低 $\Delta^-$ 区间必然提高伤害，数据证实 caution 在三模型上 harm 最差。"Refuse more" 在此是**假经济**。
- **RQ3（干预）**：是。TGCC 在 harm 加权意义上对 none 与 caution 都做了 Pareto 改进。
- **RQ4（平台效应）**：provider filter 确实在做防御工作，但也造成系统级 over-refusal（挡掉真实警情），因此模型级/系统级双报是必要的。

## 局限性

- 场景与 mock 工具均为合成沙箱，`send_public_alert` 等只返回 seeded synthetic 数据，未在真实公共安全运营中心验证；真实系统的噪音、误报率与责任链远比模拟复杂。
- 伤害代价 $c^{FN}$ 与 $c^{FP}$ 是"领域标定"的，但论文未给出标定面板或真实成本比来源；作者把"召集严重度标定小组"列为未来工作，说明当前代价比仍是假设值，Theorem 1 的判据依赖该比值。
- 注入检测器是启发式模式匹配，存在真实 recall gap（唯一残余成功 $s=0$ 即为证据）；防御强度上限被检测器召回率而非模型能力所限，且尚未与 spotlighting、CaMeL 式分离、allow-listing 等已发表防御基线做对比。
- 每个模型/防御组合的最大样本仅 190（Haiku）或 45（Sonnet、GPT-5）个场景，GPT-5 的模型级 0% ASR 仅基于 12 个已执行 episode，统计功效有限；未做自适应攻击者（adaptive attacker）轨道的评估。
- 只评估了 3 个前沿模型（claude-sonnet-4-5、claude-haiku-4-5、Azure gpt-5），且都是单一供应商生态下的 API 版本，未覆盖开源权重模型或不同 provider 的过滤器差异。
- 内容形式驱动的 over-refusal（18% vs 83%）是重要发现但只做了定性归因，未系统化地隔离文本长度、正式程度等混淆变量。

## 与知识库既有工作的关系

- 与 [[2026-10-25-2610.30738-agenttriage-replayable-security-diagnosis]] 同属 agent 安全评测方向，但把视角从"是否可复现地诊断"转向"如何定义伤害"，以领域标定的非对称代价替代单轴 refusal。
- 延续知识库中"证伪默认假设"的主线：这里的默认假设是"refuse more = safer"，论文用 Lemma 1 + Theorem 1 形式化证明它在该域为假，并用 840 个 episode 实证确认。
- 与 [[2026-10-25-2610.31130-post-audit-mirage-agent-verification]] 呼应"最终状态审计不足"的观点——SentryBench 用 ledger-first 打分与 Theorem 3 的 detector 召回上界，给出"过程级而非结果级"评分的具体做法。

## 建议

- **是否推荐使用**：是（有条件）
- **适用场景**：适合为高后果工具调用型 agent（应急调度、公共预警、公民记录查询、权限敏感运维）设计安全评测与防御 wrapper；也适合作为"ASR 单轴评测不足"的论证素材；不适合直接当作通用 chat 安全基准使用。
- **可借鉴要点**：
  1. **照搬"双向 + 非对称代价"这一评测骨架**：任何"拒绝更安全"的领域（医疗分诊、法律咨询、合规审核）都可以套用 $H(\pi)$ 的形式，先把 FN/FP 两个代价显式标定，再用 frontier dominance 而非单轴分数比较防御。
  2. **把防御做成"只在有信号时触发"的 gate 而非"一刀切拒绝"**：TGCC 的四组件（provenance separation + 启发式检测 + consequential-call gate + escalation-as-containment）结构清晰、每个组件可独立消融，可直接作为模板；同时记住其上界 = detector 召回率，评估时必须单独报告召回缺口而非宣称已解决。
  3. **坚持模型级 / 系统级双计数**：provider 内容过滤器会静默承担一部分防御同时造成可用性损失，任何跨模型比较都应把被过滤的 episode 数量与理由单列，否则会得到虚假的"0% ASR"。
