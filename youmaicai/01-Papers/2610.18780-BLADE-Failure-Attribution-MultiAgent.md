## 核心贡献

> 把 multi-agent failure attribution 从"信息流向追踪"升级为"信息使用审计"——区分 *错误引入 / 传播 / 修复*，定位真正的责任代理。

1. **从 trace 到 audit**：现有方法追踪"信息从哪里来"，BLADE 审计"信息 *如何被使用*"是否合乎任务
2. **Jev probabilistic judgments** 给出结构化审计
3. **三大错误类型自动分类**：introduction / propagation / repair
4. **全局诊断**：综合所有 step 的审计，给出最终 blame
5. **8 个策略对比**：1,228 个失败 run，5 个 Who&When / Who&When Pro 评测集，**step accuracy SOTA / tie**，比 All-at-once 高 **2.2-11.1 pp**

---

## 技术方案

### 核心思想

Multi-agent 系统里，一个代理可能 *误读了* 别人给出的正确结果，把错误延续下去。仅靠信息流向追踪（dependency tracing）无法区分"传播错误"和"原始错误"。BLADE 在每个 source-decision handoff 上做 *use audit*：检查 receiving decision 是否 (1) 引用 source 忠实 + (2) 在任务需求范围内使用 → 然后用 dependency probabilities 选择关键 handoff 优先审计。

### 关键技术

| 技术 | 说明 |
|------|------|
| Dependency probability | 量化"接收方依赖源信息的程度"，用于挑选要审计的 handoff |
| Use-fidelity audit | 检查 receiving decision 是否 *忠实* 使用源 |
| In-task audit | 检查使用是否 *合乎任务需求* |
| Error classification | introduction / propagation / repair |
| Global diagnosis | 综合所有 step 的 audit 给出最终 blame |
| Training-free | 复用已训练的 Jev 作 probabilistic judgments |

---

## 公式

对 handoff $(d_s \rightarrow d_r)$：

```math
\text{audit}(d_s, d_r) = \underbrace{\mathbb{1}[\text{use\_fidelity}(d_r, d_s)]}_{\text{忠实使用}} \;\wedge\; \underbrace{\mathbb{1}[\text{in\_task\_req}(d_r)]}_{\text{符合任务}}
```

引入 audit 后，全局 blame score：

```math
\text{blame}(a_i) = \sum_{\text{step } t \,:\, a_t = a_i} w_t \cdot \text{audit\_severity}(t)
```

其中 $w_t$ 由 dependency probability 决定。

## 实验结论

- **数据集**：5 个 Who&When / Who&When Pro 子集（共 1,228 failed runs）
- **策略对比**：8 种 attribution 策略在同一 Jev 决策接口下
- **结果**：step accuracy 在所有数据集上 **SOTA 或 tied-SOTA**
- **vs All-at-once**：+2.2 到 +11.1 百分点
- **无需参考答案**：pure post-hoc diagnosis

---

## 局限性

- 依赖 Jev 做概率判断（Jev 自身的 bias 会传递）
- 多 agent 系统需要有效的 dependency 提取（依赖日志完整）
- 实时 attribution 性能未验证
- 对 repair 类型的判定可能与 introduction 混淆
