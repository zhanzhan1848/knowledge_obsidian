## 核心贡献
1. **提出训练无关的稀疏注意力方法，用"大粒度语义块"实现 per-query 选择的 prefill 加速**：把每个 prompt 的 key 聚类成大语义块（semantic blocks），块内 token 来自**非连续位置**但 key 相似。每个 query 通过给块质心打分选择块，然后在块内的**原始 key/value** 上做注意力。
2. **"大块 + 大预算"可同时更快且更准**：大块使质心打分与分组处理变便宜，从而每个 query 能在同样时间内关注更多 token，补偿了选择精度的下降。目标平均块大小 $u = 2{,}048$ token，预算 $K = L/16$。
3. **KV-outer 执行让 per-query 选择仍能跑出 prefill 加速**：选择同一块的 query 被**聚到一起**处理（与 MoBA、MSA 相同策略），GPU 可在片上内存中跨 query 复用 KV 数据，同时保留每个 query 自己的块选择。Qwen3.5-4B 在 512K 上 KV-outer 比"邻居 query 走所选块的并集"快 **2.6×**。
4. **端到端 wall-clock 加速（含建索引成本）**：Qwen3.5-4B 与 35B-A3B 在单张 H200 上，512K 时 prefill **2.3–2.4×**、decoding **1.7–2.0×**；1M 时 prefill **2.9–3.0×**、decoding **2.3–2.9×**。仅全注意力层本身加速 3.9–4.3×（prefill）。
5. **35B-A3B 在 1M 长度上保持接近 dense 的质量**：RULER 五任务 1M 处 73.9 vs dense 73.2；LongBench-v2 overall 63.3 vs 64.7；MRCR 256K 处 0.504 vs dense 0.655（此处掉点明显）。
6. **4B 模型在 multi-key retrieval 上掉点，但整体胜过同延迟的 dense Qwen3.5-2B**：RULER-5 1M 处 55.2 vs dense 4B 的 63.2 vs dense 2B 的 48.9；三个基准上均优于 2B。
7. **块有序 KV 缓存布局的必要性被量化**：若不把每个块的 KV 按原序列顺序连续存储，512K prefill 会慢约 **9%**。
8. **给出"位置块"受控基线**：用连续 $B$ 个 token 的位置块（mean key 表示）替换语义块，共享相同预算、$D_t$ 与 attention kernel，构成与位置块选择的受控对比。

## 问题背景

长上下文使注意力在 prefill 与 decoding 两端都很贵。稀疏注意力把每个 query 限制在 token 子集上，但**只有在"选 token 的成本 + 准备其 KV 的成本"低于所节省的注意力计算时才更快**。

带学习式索引器的方法（DSA、MSA、QSA）训练索引器与模型，使小 token 预算就够用。对于**训练无关**方法，逐 query 估计重要性代价高昂，且不规则选择难以在 GPU 上高效执行。现有训练无关方法的共同弱点是：(a) 只选**连续块**（Quest、MoBA），而连续块的 token 彼此常常毫无关系；(b) 在邻近 query 间**共享一次选择**（MInference、FlexPrefill、QuoKA、FlashPrefill）；(c) 一些方法在 dense prefill 期间聚类相似 key，但**只把索引用于 decoding**（ClusterKV、Tactic）。

还有一层被忽视的现实约束：**混合（hybrid）模型只在一部分层使用 full attention**（MiniMax-M1、Qwen3.5 中最多 1/4 的层用 full attention）。这些层是模型对远距离 token 的唯一精确访问通道，因此"全注意力模型能容忍多少稀疏度"的结论不适用；且注意力层只占模型总成本的一部分，仅报告注意力层加速无法说明整体收益。

本文的核心主张是：**在没有训练的情况下，每个 query 各自选块的 sparse prefill 仍可比 dense 快得多**——前提是用足够粗的块来让质心打分和分组执行足够便宜。

## 方法

### 1. 构建语义块

对每个 prompt、每个 layer、每个 KV head，在采样的归一化 key 上运行**球面 k-means**（spherical k-means）得到 $C$ 个单位范数质心 $\mu_1, \dots, \mu_C$。每个 key 分配到最近质心，定义其块（式 1）：

$$a_i = \arg\max_{c \in \{1,\dots,C\}} \tilde{k}_i^\top \mu_c, \qquad B_c = \{ i \in \{1,\dots,L\} : a_i = c \}$$

其中 $\tilde{k}_i$ 为 L2 归一化后的 key。目标平均块大小 $u$ 决定簇数约为 $C = L/u$。**每层与每个 KV head 有独立的划分**，块的成员一般散布在整个 prompt 中，因此需要把每个块的 key/value 连续存储（见 §3.4）。

论文的 Figure 3 展示了聚类的可解释性：上层例子里离质心最近的成员是来自遥远段落的关于环境/生态系统的词；下层例子是不同标识符的前导数字。块内可含大量不同 token——这正是"语义块"与"位置块"的区别。

### 2. 选择块与计算注意力

设 $L$ 为 prompt 长度，$d$ 为 head 维度，$k_i, v_i \in \mathbb{R}^d$，$q_{t,h} \in \mathbb{R}^d$ 为 GQA 组 $H$ 中 head $h$ 的 query。$D_t \subseteq \{1,\dots,t\}$ 表示位置 $t$ 的 query **不经选择**直接纳入的位置（近期 token）；其余可见位置在簇 $c$ 中为 $B'_{c,t} = (B_c \cap \{1,\dots,t\}) \setminus D_t$。

在每个 query head 内对质心算 softmax，再跨 GQA 组求和；并施加**尺寸惩罚**以考虑每簇检索到的 token 数（式 2）：

$$r_h(c) = \frac{\exp(\tilde{q}_{t,h}^\top \mu_c / \tau)}{\sum_{c'=1}^{C} \exp(\tilde{q}_{t,h}^\top \mu_{c'} / \tau)}, \qquad s(c) = \sum_{h \in H} r_h(c) (1 + |B'_{c,t}|)^\beta$$

用 $\tau = 0.1$、$\beta = 0.25$。按 $s(c)$ 降序选簇，在每簇取全部 token，直到总数达到或超过预算 $K$。选中的簇为 $J_t$，使用的位置为（式 3）：

$$S_t = D_t \cup \Big[ \bigcup_{c \in J_t} B'_{c,t}$$

选择**逐 query 位置计算**，并在其 GQA 组内的 query head 间共享。注意力在原 query/key/value 上按标准 softmax 计算（式 4），设 $S_t = \{1,\dots,t\}$ 即退回 dense attention。

对带 RoPE 或 partial RoPE 的模型，聚类与选择使用**旋转前**的 query/key；使用旋转后的结果精度相近（Appendix F.1）。

### 3. Prefill 与 Decoding

**Prefill**：每层先用 prompt key 建索引，再把 prompt query 分成连续 chunk 处理。每个 query 关注从更早 chunk 选中的块，以及自己 chunk 内全部因果可见 token。prompt 开头的 query 由于历史很短，改用 dense attention（设 $D_t = \{1,\dots,t\}$）以避免选择开销。

**Decoding**：每个 query 用同一索引选择 prompt 块；主实验中所有生成 token 都纳入 $D_t$ 不经选择。更长生成时，旧的生成 token 可加入索引，只留近期的在 $D_t$ 中。

**关于因果性的说明**：主实验在**整个 prompt** 的 key 采样上跑 k-means，因此 prompt query 的块选择可能依赖后面的 prompt key——但每个 query 仍只关注不晚于自己的位置。这在生成开始前整个 prompt 已给定的情况下是可行的，且每个生成 token 仍只依赖它之前的 token。其代价是 prefill 必须**逐层**跑完整个 prompt，而非普通 chunked prefill 那样把 chunk 穿过所有层。替代方案：只在前 64K key 上跑 k-means，后续 key 分配到最近质心，即可使用普通 chunked prefill，精度相近。

### 4. 高效执行

**KV-outer**：FlashAttention-3 等高效 dense kernel 会把邻近 query 一起处理以复用 KV tile。但在本文方法中邻近 query 可能选不同的块——若仍一起处理，某块会被未选它的 query 一并处理，稀疏收益被削弱。因此改为**收集选了同一块的 query**，把它们对该块的注意力一起计算。这与 MoBA 和 MSA 对连续块采用同样的执行策略。Attention kernel 在当前 chunk 内使用因果 FlashAttention-3；对每个 query，用其 softmax 归一化数合并各块的输出。

**块有序缓存**：尽管块的 token 散落各处，把它们的 KV 按原序列顺序连续存储。对每个 prefill chunk，可以直接从每个块的起始处读取更早 token 的 KV。这个**块有序 cache 每层构建一次**，prefill 与 decoding 共用。

**Decoding**：每步只读选中块的 prompt KV，把每步读取的 prompt token 数从 $L$ 降到约 $K$。每个 query 打分 $C$ 个质心而非 $L$ 个 key。vLLM 实现使用融合 kernel 降低打分与选择开销。

**成本会计**：$C$ 与 $K$ 都与 $L$ 成比例，因此 prefill 仍是 prompt 长度的二次函数，只是常数因子更小。

## 实验结果

- **Dataset/Task**: 模型 Qwen3.5-4B（32 层中 8 层 full attention）与 Qwen3.5-35B-A3B（40 层中 10 层 full attention），另在 NVIDIA Nemotron 3.5 Lightning 混合模型上验证（Appendix H.2）。权重全部固定。基准：RULER（5 个任务平均：multi-key retrieval MK-2/MK-3、multi-value retrieval、common-word extraction、HotpotQA）、MRCR（八针，OpenAI 2025）、LongBench-v2。硬件单张 H200，BF16，batch size 1，FlashAttention-3，decoding 用 full-step CUDA graph，取三次重复的中位数。prefill 延迟**包含**索引构建、KV 打包、选择、gather 与 merge。

- **Main results**（预算 $K = L/16$）：

|------|------|------|------|------|------|------|------|------|------|------|
| 35B-A3B dense | 85.7 | 84.4 | 73.2 | 0.846 | 0.655 | 0.564 | 64.4 | 66.2 | 64.7 | 173.5 |
| 35B-A3B ours | 84.5 | 84.2 | 73.9 | 0.844 | 0.668 | 0.504 | 63.1 | 64.7 | 63.3 | **57.4** |

  延迟加速（whole-model wall clock，vs dense）：Qwen3.5-4B prefill 512K **2.3×**、1M **2.9×**；decoding 512K **2.0×**、1M **2.9×**。Qwen3.5-35B-A3B prefill 512K **2.4×**、1M **3.0×**；decoding 512K **1.7×**、1M **2.3×**。仅注意力层：prefill 512K 加速 3.9×（4B）/ 4.1×（35B），1M 达 4.2×/4.3×；decoding 注意力层 GPU 时间加速 7.6×–10.2×（4B）、5.5×–7.3×（35B）。

- **Ablations**: (1) **prefill 时间分解**（Qwen3.5-4B @512K）：dense GPU 时间 31.4 s，注意力 kernel 从 40.3 s 降到 8.9 s（约 5×），而索引构建 + 选择 + gather + merge 合计约 **1.8 s**（其中拟合质心只占小部分），其余模型部分不变约占 sparse prefill 时间的一半。(2) **更早切换到稀疏无效**：在 prompt 更早位置切到稀疏 attention 反而**没有**加速——额外的选择、gather、merge 抵消了 dense 上省下的时间。(3) **块有序 KV 布局**：不采用该布局使 512K prefill 慢约 9%。(4) **KV-outer vs 并集执行**：4B @512K 上快 2.6×。(5) **块大小与预算的联合扫描**（Appendix F.3）：大块 + 大预算同时更快更准。(6) **RoPE 前后**：精度相近。(7) **64K-only k-means 变体**：支持普通 chunked prefill，精度相近。

## 关键洞察

1. **"块粒度"是训练无关稀疏注意力的真正控制变量，而非附属参数**。学习式索引器（DSA/MSA/QSA）通过训练让小块（2048 token 预算）就够用；本文证明在无训练条件下应当**反过来做**：用大块（$u=2048$）让选择本身变便宜，从而把省下的时间换成更大的预算（$K=L/16$）。选择精度与执行效率在这里是同一个旋钮的两端。
2. **语义块 vs 位置块是本质区别，不是启发式替换**。位置块（Quest、MoBA）内 token 无语义关系，因此块质心几乎不携带信息，选择也失去意义；语义块把"query 需要的 token"聚在一起。图 3 的例子（生态主题词聚在一起、UUID 前缀聚在一起）说明聚类确实捕获了真实的语义结构。
3. **KV-outer 执行是让 per-query 选择可行的关键工程机制**。没有它，"每个 query 自己选块"会退化为"邻居 query 走所选块并集"，稀疏收益被抹平——2.6× 的差距量化了这一点。
4. **只有一半层用 full attention 的混合架构里，注意力层加速不等于模型加速**。论文明确区分 whole-model wall clock（2.3–3.0×）与 attention-layer GPU time（3.9–4.3×），并解释差额来自未改变的其他层。这是本文在方法论上比多数稀疏注意力论文更扎实之处。
5. **prefill 时间分解揭示了这类方法的真实成本结构**：省下的注意力时间约 25 s，而索引 + 选择 + gather + merge 约 1.8 s——比例约为 14:1。这说明该方法的天花板不在"选择开销"而在"块内粒度"与"chunk 内仍用 dense attention"。
6. **"更早稀疏化"没有收益这一负面结果很有价值**：它说明 sparse prefill 的收益高度依赖"稀疏部分占总注意力的比例"，因此在短 prompt 上强行稀疏是负优化。

## 局限性

- **MRCR-8 在 512K 处掉点明显**：35B-A3B dense 0.564 → ours 0.504（-0.06），4B dense 0.412 → ours 0.399；MRCR 是多轮 needle 检索任务，对精确的长程依赖敏感，稀疏选择在 256K 以上开始丢失细粒度信息。
- **4B 模型在 RULER 1M 处显著掉点**（63.2 → 55.2，-8.0 点），主因是 multi-key retrieval；这限制了"训练无关稀疏"在较小模型上的可用性。
- **Prefill 仍是长度的二次函数**（$C \propto L$，$K \propto L$），只是常数因子更小；论文自己承认"prefill remains quadratic in prompt length"。
- **主实验的 k-means 依赖整个 prompt 的 key**，导致 prefill 必须逐层处理整个 prompt，破坏了普通 chunked prefill 的流水线；替代方案（64K 前缀拟合）精度相近但未作为主结果。
- **Chunk 内仍使用 dense attention**（且 prompt 开头也 dense），因此 $K=L/16$ 不带来 16× 的注意力加速。
- **未与学习式稀疏方法（DSA/MSA/QSA）直接对比质量**，因为那些方法需要训练并改变模型权重，与"权重全固定"的设定不可直接比较。
- **只在两个 Qwen3.5 变体加一个 Nemotron 混合模型上验证**，混合层比例是重要变量，其他架构比例（如更少 full attention 层）下的表现未知。
- **RULER 使用 greedy 无 thinking，MRCR/LongBench-v2 使用 thinking + 推荐采样设置**，两个基准的解码配置不一致，跨基准的精度数字不宜直接比较。
- **超出 256K 原生上下文时 dense 与 sparse 都用 factor-4 YaRN 插值**（不做 attention scaling），这是超出模型训练分布的外推，其绝对精度本身存在不确定性。
- **索引构建成本随层数与 KV head 数线性增长**，论文未讨论在更深的模型或更多 head 上的可扩展性。
- **仅在单张 H200、batch size 1 下测量**，高并发服务场景下的实际吞吐收益未评估。

## 适用场景

**适用**：
- 部署混合架构长上下文模型（Qwen3.5 系列、MiniMax-M1 式，full attention 层占少数）的推理服务，需要**免训练**降本增效的团队。
- 需要在保持权重完全不变的前提下压 prefill 延迟的场景（512K–1M prompt）。
- 长上下文 agent / RAG 系统，其中 prompt 很长但查询是少数位置。
- 想理解"块粒度—预算—执行策略"三者权衡的研究者，本文给出完整的成本会计与消融。

**不适用**：
- 自回归解码延迟极敏感、且上下文不长（<64K）的场景——建索引成本不划算。
- 需要在 512K 以上做多 key 精确检索（MRCR 类）且精度优先的场景。
- 全注意力（每层都是 softmax attention）模型——混合架构的实验结论不能直接迁移。
- 追求渐进式 KV 压缩（减少显存占用）的场景——本文方法不压缩 KV，块只是选择单元。
