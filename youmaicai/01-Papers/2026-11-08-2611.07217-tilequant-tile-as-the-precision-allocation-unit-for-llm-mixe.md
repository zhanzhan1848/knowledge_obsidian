# TileQuant: Tile as the Precision-Allocation Unit for LLM Mixed-Precision Post-Training Quantization

> **arXiv**: [2611.07217](https://arxiv.org/abs/2611.07217)
> **发表日期**: 2026-11-04
> **分类**: cs.LG (及交叉分类 cs.AI)
> **会议/期刊**: arXiv preprint

## 📋 摘要

Post-training quantization (PTQ) 降低 LLM 的部署成本，但要保住质量就必须处理权重敏感度不均的问题：uniform PTQ 用单一权重位宽；importance-aware PTQ 在同一位宽内调整 scale 或重构权重；column-wise mixed precision 则保留部分整列的高精度。但敏感度在**列内部**同样变化，因此整列保留会连带保护那些并不敏感的权重，而 runtime 的 outlier 检测又会带来解码开销。为此作者提出 TileQuant——一个 **training-free** 框架，将精度分配到与硬件对齐的 **2D 权重 tile** 上。离线校准提供两种打分：基于 forward statistics 的 input-activation-aware 打分（校准成本更低），以及基于 loss sensitivity 的 gradient-informed 打分（质量保持更强）。在每个 projection 的 retention budget 内，得分最高的 tile 保持 **16-bit**，其余使用 **8-bit**。由此得到的精度图指导权重重构写入紧凑的 weight buffer，kernel 复用该 buffer 进行原生整数与 16-bit 计算，并通过**局部累加（local accumulation）** 减少内存流量。实验显示 TileQuant 达到原模型生成吞吐的 **2.66x**；在语言建模、推理、长上下文检索与问答等任务上保持质量，并在多个任务上超过量化模型与原始模型。结果支持选择能刻画局部敏感度、同时利于硬件高效执行的精度分配单元。实现已开源。

## 🎯 核心贡献

1. **Tile 作为精度分配单元**：提出以硬件对齐的 2D 权重 tile（而非整列 / 整行 / 单权重）为混合精度粒度，同时解决"列内敏感度不均"与"runtime outlier 检测开销"两个既有方案的结构性缺陷。
2. **两种离线校准打分**：
   - **Input-activation-aware**：由前向统计量计算，成本更低
   - **Gradient-informed**：由 loss sensitivity 计算，质量保持更强
3. **Training-free**：完全无需再训练/微调，仅离线校准 + 权重重构。
4. **硬件协同设计**：精度图 → 紧凑 weight buffer → kernel 复用 buffer 做原生整数与 16-bit 计算 + **局部累加**减少内存流量，使混合精度真正获得推理加速（而非纸面省显存）。
5. **实测吞吐 2.66x**，且在多个任务上**超过量化模型与原始模型**（量化常被视为有损，这里出现反超）。

## 🔧 方法/架构

- **问题形式化**：给定权重矩阵 $W \in \mathbb{R}^{m \times n}$，将其划分为与硬件 tile 尺寸对齐的 2D 块 $\{T_i\}$；目标是在保留预算（retention budget）约束下，为每个 tile 分配位宽：

```math
\max_{\{b_i\}} \ \sum_i s_i \cdot \mathbb{1}[b_i = 16]
\quad \text{s.t.} \quad
\sum_i (b_i - 8)\cdot|T_i| \le B_{\text{retain}}
```

- **Tile 敏感度打分**：
  - Input-activation-aware（由前向统计）：用激活统计近似该 tile 的贡献，如激活幅值加权：

```math
s_i^{\text{act}} \propto \big\| X \odot \mathrm{grad}(W_{T_i}) \big\|_2
```

  - Gradient-informed（由 loss sensitivity）：以损失对权重的敏感度作为打分依据，质量保持更强
- **精度分配**：每个 projection 内，得分最高的若干 tile 保留 16-bit，其余为 8-bit。
- **权重重构与执行**：
  - 精度图指导重构，写入紧凑的 **weight buffer**
  - kernel 复用 buffer，执行**原生整数与 16-bit 混合计算**
  - 使用**局部累加（local accumulation）** 降低内存流量（避免逐元素回到高带宽 DRAM）
- **对比基线**：uniform PTQ、importance-aware PTQ（scale 调整 / 权重重构）、column-wise mixed precision、runtime outlier detection。

- **生成吞吐：2.66x 原始模型**（real-hardware 实测）
- 语言建模：质量保持
- 推理任务：质量保持
- 长上下文检索：质量保持
- 问答任务：质量保持

## ⚠️ 局限性

- Training-free 与 calibration-based 的打分对校准集敏感；校准数据的分布偏移可能使 tile 敏感度排序失真。
- 摘要未披露基线模型规模、硬件型号与 batch/序列长度设置，2.66x 吞吐的可迁移性需自行复现验证。
- 混合位宽需要定制 kernel，若硬件 tile 尺寸与实际加速器 tile 不匹配，收益可能大幅缩水。
- "超过原始模型"的表述在量化文献中反常，可能与具体评测噪声、量化引入的正则化效应或评测集规模有关，摘要未解释成因。
- 仅评测了权重量化路径；激活/KV cache 的量化与 tile 分配的协同未涉及。
- 检索与长上下文任务上的"质量保持"是否等价于无损，摘要未给出困惑度/准确率的绝对数值。

## 💡 建议

- 是否推荐使用：**是**（推理部署降本增效的直接可用方法，工程实现已开源）
