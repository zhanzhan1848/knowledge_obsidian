## 核心贡献

> 提出 **ValuSpec** —— 一个**即插即用**的候选估值模块，在昂贵的 target 侧验证**之前**过滤掉候选树中的低质量分支，且不改变输出分布。

1. **问题定位**：检索式（retrieval-based）树推测解码在真实 serving 场景下因相似请求反复产生**重叠的候选分支**，候选树变大时混入大量低质量分支，拖低验证效率、浪费 target 侧算力
2. **Transfer-based supervision**：用目标模型的行为来对齐"过滤"这一判据，而非训练独立的打分器
3. **免训练阈值估计**：过滤阈值由目标模型在 **calibration split** 上的 **greedy 轨迹**估计而来，**无需任何参数训练**
4. **输出等价保证**：过滤后的树在 **output-identical greedy rule** 下由 target 验证，接受的 token **保证与标准自回归解码完全一致**
5. **通用性与加速**：HumanEval、GSM8K、Dolly、SpecBench 上，检索式树场景取得**最高 2.38x** 端到端加速；接入 EAGLE-3 动态树框架**无需修改其建树策略**即可取得**最高 2.78x** 加速

## 技术方案

### 核心思想

树状推测解码通过并行验证多个候选分支来加速 LLM 推理。在线上服务中，相近请求会反复触发**重叠候选树**；而检索式方法通过复用历史 draft 来缓解这点，代价是候选树随规模增长不断塞入低质量分支。ValuSpec 的做法是在"验证之前"先做一次**候选估值过滤**，把明显无用的分支剪掉。

### 关键组件

| 组件 | 说明 |
|------|------|
| Candidate valuation | 对候选树分支打分排序，过滤低质量分支 |
| Transfer-based supervision | 以目标模型行为作为监督信号对齐过滤策略 |
| Calibration split | 用目标模型的 greedy 轨迹估计过滤阈值，无需参数训练 |
| Output-identical greedy rule | 保证接受 token 与标准自回归解码完全一致 |

### 关键公式

阈值由 calibration split 上目标模型的 greedy 轨迹统计得到：

```math
\tau = \mathrm{Quantile}_{\rho}\!\left(\{v(y^{(i)}_t)\}\right)
```

其中 $y^{(i)}$ 为 calibration 样本，$v(\cdot)$ 为分支估值，$\rho$ 为期望保留比例。

过滤后的候选集与验证规则：

```math
\mathcal{B}' = \{\, b \in \mathcal{B} \;:\; v(b) \ge \tau \,\},\qquad
\text{accepted} = \mathrm{TargetVerify}\big(\mathcal{B}'\big)
```

"output-identical greedy rule" 保证：

```math
\text{Output}_{\text{ValuSpec}} \equiv \text{Output}_{\text{autoregressive}}
```

即过滤只影响速度与算力，不影响生成质量。

## 局限性

- 依赖**历史 draft 的复用质量**：若检索到的历史候选本身与当前请求分布不匹配，过滤只能去掉低质量分支，无法补充缺失的优质分支
- 阈值来自 calibration split 的 greedy 轨迹，面对分布漂移（新的任务域、新的请求风格）可能需要重新标定
- 额外引入一次候选遍历的估值开销，在极短输出或极小候选树的场景中收益可能被抵消
- 只报告了最高加速比，摘要未给出**平均**加速与最坏情况退化的量化

## 实现建议

- **实现难度**: 中（在候选树送入 target 前插入一层过滤，不需要改训练管线）
- **适用场景**: 高并发 serving、请求高度重复/高度相似（客服、RAG 问答、模板化生成），此时检索式 draft 的候选树最容易膨胀
- **建议起点**: 先做无训练版本——用目标模型 greedy 轨迹统计分支估值分布取分位数作阈值；接入 EAGLE-3 验证能否在不改建树策略下拿到加速
- **价值点**: "output-identical" 是这类优化的关键卖点——可以在不重跑任何精度评测的前提下直接上线，只测速度
- **注意**: 若你的流量长尾、请求彼此差异大，检索式 draft 复用少，可优化空间也小
