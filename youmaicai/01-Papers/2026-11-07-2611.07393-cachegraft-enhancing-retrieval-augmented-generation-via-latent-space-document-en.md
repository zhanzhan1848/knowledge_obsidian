# CacheGraft: Enhancing Retrieval-Augmented Generation via Latent-Space Document Enrichment

### 核心贡献
1. 论证 **cache-to-cache（KV cache 直接在隐空间传递信息）** 这一技术除了原本的实时 agent 通信场景，还可以被复用于 **RAG**，把语料文档以「latent-space document enrichment」的形式注入小模型。
2. 提出 **CacheGraft**：基于 **Cache-to-Cache (C2C) fusion** 框架，把每条语料 passage **离线编码**成介于大 sharer model（实验中 **4B 参数**）与小 receiver model（**0.6B 参数**）之间的 **融合 KV cache**；查询时把该 cache 注入 receiver，**无需再运行大模型**。
3. 在 **5 个 QA benchmark × 2 个本地独立 judge** 上，相对纯文本的 receiver baseline，**30 次比较中有 29 次**答案质量提升，其中 **17/30** 具有统计显著性；且这些增益对 fuser 而言是 **zero-shot** 的（fuser 从未在检索数据上训练过）。

### 技术方案
**核心思想**: 传统 RAG 把文档以文本形式塞进小模型的 prompt；CacheGraft 换一条路——用大模型离线把文档「编译」成小模型可直接消费的 KV cache 片段，查询时把该 cache 拼接/注入小模型的上下文，等价于「文档在隐空间被预先增强过」。

| 技术 | 说明 |
|------|------|
| Cache-to-Cache (C2C) fusion | 基础框架：两个模型之间不通过文本、而通过 **KV cache 直接互传状态**；本文用它把「文档」而非「agent 状态」作为传递对象 |
| 离线 passage 编码 | 每条 corpus passage 在 **离线阶段** 被编码为融合 KV cache：sharer model（4B）先处理文档，再由 fusion 机制将表示对齐到 receiver model（0.6B）的 KV 空间 |
| Receiver 注入 | 查询时直接将该融合 cache 注入 receiver model（0.6B）的上下文，**推理阶段完全不需要 4B sharer model**——由此获得算力受限场景下「只部署小模型」的可能性 |
| 零样本 fuser | 融合器（fuser）**从未在检索数据上训练**，说明增益不是来自针对检索任务的过拟合 |

### 实验结果
- **数据集**: 5 个 QA benchmark（摘要未列出具体名称）
- **基线**: text-only receiver baseline（纯文本上下文的小模型 baseline）
- **结果**: 5 benchmarks × 2 个独立本地 judge = **30 组比较**，**29 组**优于 baseline，其中 **17 组**统计显著

### 局限性
- **Work in progress**（5 页 workshop 论文），完整数据集、可执行环境、统一评分协议与跨模型结果尚未完成
- 需要一个 **4B 的 sharer model** 做离线编码，离线阶段的算力/存储成本摘要未量化
- 融合 cache 与 receiver 的尺寸/架构绑定，跨模型迁移性摘要未说明
- 摘要未给出绝对分数，只给相对 baseline 的比较计数（29/30、17/30）

### 关键洞见
> RAG 的「文档增强」不必发生在 token 空间：既然两个模型能通过 KV cache 直接对话，就可以 **提前把文档编译成接收方的 cache 形态**。这等于用一次离线的大模型推理，换来了推理期「只跑 0.6B 小模型却拿到大模型级文档理解」的部署结构——是对「RAG 必然拖着大模型上线」这一假设的正面挑战。
