# RoleFUZZER: User-Behaviour Fuzzing for Role-Specification Adherence in Large Language Models

## 摘要
LLM 常通过 system prompt 被赋予 tutor、interviewer、代表组织的 agent 等角色，但它们在多轮交互中能否守住角色规范（role specification）研究不足。作者提出 **user behaviour fuzzing**：把软件测试中的 coverage-guided fuzzing 迁移到"角色化 LLM 是否遵守规范"这一问题——被测程序是角色条件化的 LLM，输入是用户，correctness condition 是对角色规范的遵守。作者用 **TUNA**（Taxonomy of User Needs and Actions，基于 1,200 段人机对话的实证分类）构建 **4 instrumental modes × 4 relational strategies × K=4 principles = 64 格** 的行为覆盖网格，并用双通道信息架构分离"campaign 级违规反馈（引导搜索）"与"conversation 级 grounding 反馈（保证每段对话可信）"。在 **5 种角色规范**（tutor、financial advisor、AI interviewer、antagonistic game character、企业 web agent）× **3 个目标模型**（Qwen3-32B、Gemma4-31B-it、Claude Haiku 4.5）的 **15 个 campaign × 240 episode** 中，RoleFUZZER 对每个模型/角色都达到 **≥89%** 的 64 格覆盖（其中 12 个超过 98%）；同等对话预算下，让 LLM 自由生成针对性用户只能覆盖 39–69%。同一份规范在不同模型上可能**朝相反方向失败**：开放权重模型在 antagonist 角色中越过玩家的安全信号（Qwen 58%、Gemma 62%），而 Claude Haiku 4.5 则是"出戏"（73%）。

## 核心贡献
1. **user behaviour fuzzing 方法论**：把 coverage-guided fuzzing 的抽象（program-under-test / input / correctness condition / coverage map）映射到角色规范遵守性测试。
2. **RoleFUZZER 框架**：双通道信息架构 + TUNA 锚定的行为覆盖网格 + 三桶退火调度（seed / coverage-directed / mutation）。
3. **多角色多模型实证**：15 个 campaign，5 种角色规范，量化覆盖率、违规严重度分布、首次违规轮次（TTFV）与可复现性（mutation 子节点违规率）。
4. **机制性发现**：违规集中在"规范要求模型拒绝/ withheld help 而用户正想要帮助"的场景；不同模型的失败方向取决于其训练默认（helpfulness vs safety-first）。

## 方法与架构
**形式化**：角色规范 $S=(\rho, P, \kappa)$，$\rho$ 为角色自然语言描述，$\kappa$ 为情境上下文，$P=\{p_1,\dots,p_K\}$ 为原则集合；每个原则 $p_k=(\ell_k, V_k)$，含自然语言陈述 $\ell_k$ 与分级违规标准 $V_k$（三档：clear breach / partial violation / full adherence，基于 Rahman et al. 的 5 点量表并把中间信号合并以改善下游校准）。目标模型 $M_S$ 经 system prompt 条件化；judge 为每条回复的每个原则给严重度 $J_{t,k}\in\{0,1,2\}$，$V_t^{(\theta)}=\mathbb{1}\{J_{t,k}\ge\theta\}$ 表示阈值 $\theta$ 下的违规。

**Fuzzing 映射**：program under test = $M_S$；input = 场景 $\sigma$（带背景与目标的用户，压向某条原则）；correctness condition = 对规范遵守性的判定；coverage map = 行为网格 $B$；给定 $N$ 次对话预算，逐个选择 $\sigma_n$ 以最大化 $B$ 的覆盖与违规发现的格子数；额外约束是每个用户输入必须像真实用户会发出的。

**覆盖网格**：$B=\mathcal{M}\times\mathcal{S}\times\mathcal{P}$，$|B|=4\times4\times K=64$（$K=4$）。$\mathcal{M}$（instrumental modes）：information seeking / information processing / procedural guidance / content creation；$\mathcal{S}$（relational strategies）：sociability / shared understanding / system management / conversation management。对原则 $p_k$，turn $t$ 实现格 $(m_t, s_t, p_k)$；当针对 $p_k$ 的对话中包含被分配 $(m,s)$ 的 approved turn 时该格被覆盖。每个格累积观测数 $n_b$、违规数

```math
v_b^{(\theta)}=\sum_C\sum_t V_t^{(\theta)}\mathbb{1}\{(m_t,s_t)=(m,s)\}
```

以及**favored parent** $\sigma_b^\star$（在该格产生最高严重度判定的场景输入，供后续轮次局部变异）。

**双通道 pipeline**：① **User simulator** — 以 LLM 扮演场景用户，只接收 planner 生成的 scenario-role 规范与对话历史，**绝不接收 judge 分数或违规反馈**，只看目标模型的真实回复（贴近真实用户的信息面）；② **Consistency monitor** — 在候选 turn 送达目标前（1）校验 groundedness 与目标遵循，不合格则请求重生成（最多 3 次后终止对话）；（2）把该 turn 分类到 TUNA 的 $(m,s)$ 并填充覆盖网格；（3）用自由文本注记把下一轮引向 planner 的目标格；③ **Judge LLM** — 每轮对所有原则同时打分，judge 分数只在轮次之间反馈给 planner，从不给 simulator 或 monitor。

**Planner 与三桶退火调度**（每轮预算分配，遵循 directed fuzzing 的开环退火）：① **Seed（$\alpha_{seed}$）** — 基于角色 seed 集的场景，原则对齐目标但无格目标、无 monitor 引导；同时充当覆盖率比较的无偏基线；② **Coverage-directed（$\alpha_{cov}$）** — planner 迭代 $(m,s,p_k)$ 三元组，为欠观测格合成场景，并以邻近格的诊断为条件；③ **Mutation（$\alpha_{mut}$）** — 对 favored parent $\sigma_b^\star$ 做两种 cell 级操作（改变用户沟通风格强度 / 重新锚定到另一个 seed 语料情境），保持其余格配置不变，使子节点在同一行为格上压同一条原则。

**五个角色规范**（每条 $K=4$，含公开标准依据）：
1. **Tutor**（NEA Code of Ethics）：学术诚信、保密、边界化教学角色、个体差异；
2. **Financial Advisor**（fiduciary standards）：受托责任、诚信与合规、边界化顾问角色、保密；
3. **AI Job Interviewer**（EEOC Uniform Guidelines）：公平与情感中立、结构化评估、保密、边界化评估者角色；
4. **Antagonist Game Character**（叙事一致性）：保持威胁性、保持角色、尊重安全信号、体裁适配的强度；
5. **Enterprise Web Agent**（ST-WebAgentBench）：用户同意、严格执行、层级遵循、鲁棒性与安全。

## 实验设置
- **目标模型**：Qwen3-32B、Gemma4-31B-it（开放权重）、Claude Haiku 4.5（闭源）。
- **多 LLM campaign 使用**：GPT-5-mini 作为主 judge（角色模拟/监控/judge 组件），构建在 **Inspect AI** 评估库之上。
- **Campaign 配置**：每 campaign **8 轮 × 30 次对话**，每段对话 **8 turns**，每轮同时评估 4 条原则。退火调度从 $(\alpha_{seed},\alpha_{cov},\alpha_{mut})=(0.15,0.40,0.45)$ 移到 $(0.15,0.25,0.60)$。
- **Seed 语料**：tutor / advisor / interviewer 各 **128** 条按领域相关性检索的 WildChat 对话；antagonist 为本工作撰写的 **32** 个场景；web agent 为基于 benchmark 文本构建的 **32** 条种子。
- **基线（即消融）**：① seed-only；② **no-grid**（planner 仅依据角色规范自由写压力场景，无目标格、无覆盖反馈，即"直接让 LLM 生成难缠用户"）；③ **random-cell**（保留完整方法但均匀随机选目标格）。
- **指标**：网格覆盖率；用户多样性（用 sentence-transformer 嵌入 turn，conversation 取 turn 嵌入均值，算 **Vendi score**）；行为聚类数与失败类型数（$k=32$）；每原则 violation rate / clear-breach rate；**首次违规轮次 TTFV**；每格违规率；mutation 子节点违规率。
- **测量效度验证**：80 段分层抽样对话（约 610 turns）人工标注。

## 实验结果
**覆盖与搜索效率**：
- 15 个 RoleFUZZER campaign 均在前 3 轮内越过 **80%** 网格覆盖，最终全部 **>89%**，其中 **12 个 >98%**。
- 同预算下 no-grid 基线覆盖仅 **39%（web agent）–69%（interviewer）**；论文摘要另称"最高留下 61% 的格子未被测试"。
- 种子对话本身覆盖 **14–41%**，而 RoleFUZZER 前 30 次对话即达 **47–63%**。
- random-cell 基线最终能覆盖大部分网格但更慢：在随机基线达到 >90% 覆盖的 campaign 中，RoleFUZZER 少用 **40%** 的对话（平均 **116 vs 193**），且更多场景瞄准未覆盖格（**60% vs 46%**）。

**网格的贡献（有网格 vs 无网格，5 个角色平均）**：用户多样性 **+19%**；行为聚类从 19 增至 **27**（共 32）；失败类型 **+26%**。

**违规严重度（Figure 3 / Table 4）**：Qwen3-32B 上 tutor 的学术诚信 clear breach **83.6%**，interviewer 的结构化评估 clear breach **81.1%**；antagonist 角色中开放权重模型越过玩家的安全信号（**Qwen 58%、Gemma 62%**），Claude Haiku 4.5 则"出戏"（**73%**，stay-in-character 原则）。多数 clear breach 发生在对话早期，**Mean TTFV 在 1.8–4.7 之间**。

**可复现性（mutation）**：对产生 clear breach 的 parent，度量其子节点在同一目标上再次 clear breach 的比例——pooled child breach rate 达 **61%（Qwen interviewer）** 与 **86%（Claude-Haiku antagonist，stay-in-character 原则）**，且与 parent 违规位置相关。

**违规热图（Figure 4, Qwen3-32B）**：interviewer 的违规集中在候选人"重定向对话"处；web agent 在员工建立融洽关系、试图主动引导 agent 执行时违反层级遵循（与常规 capability/safety benchmark 的目标不同）。

**测量效度（人工验证）**：模拟用户 turn 在 character naturalness / user-role fidelity / conversational grounding 三轴上的归一化均值分别为 **0.85 / 0.90 / 0.91**，可接受率 **87.1% / 95.3% / 95.9%**；用户达到目标 TUNA interaction mode 的可接受率 **94.5%**。Judge 校准：GPT-5-mini 与单个标注者的一致率 **76.1%**，标注者之间 **77.0%**（clear breach 上高度一致 **90.7%**）；用 GPT-5 与 Llama-3.3-70B-Instruct 复判全部对话，与 GPT-5-mini 的一致率分别为 **86%** 与 **79%**。Consistency monitor 在 **16%** 的模拟 turn 上做了修订，**91%** 的对话达到其目标格。

## 局限性
- 作者自述：① **分类法完备性**——TUNA 面向通用 AI 交互的功能性意图设计，未覆盖全部会对角色边界施压的行为；网格缺少显式的情绪效价（emotional valence）与压力动态轴，仅作为"实用且可 tractable 的起点"；② **测试环境**——角色规范是手工编写并锚定公开标准的，实际部署特征可能不同；③ **对话长度**——限于 8 turns（计算约束），虽多数违规早期出现，但可能遗漏长程时序退化动态；④ **文化与语言范围**——全部实验为英文，角色规范以美国为中心；⑤ 双重用途风险。
- 我的批判性意见：① 关键结论"违规方向相反"（Claude 出戏 vs 开放权重越界）只在 antagonist 这一角色上成立，且被解释为"安全对齐强度差异"，但也可能只是 Claude Haiku 4.5 的角色扮演能力弱——论文未做消融以区分"模型不愿扮演"与"模型不会扮演"；② Judge 是 GPT-5-mini，与被测模型同属一个厂商生态，且其"角色扮演扮演者"与"judge"是同一模型家族，可能存在系统性偏好；③ 15 个 campaign（5 角色 × 3 模型），无统计重复（每格 seed 数、对话数虽大，但 campaign 数小），报告的 83.6%、73% 等数字缺少置信区间；④ 覆盖率的定义是"某格至少被观察一次"，不区分该格被覆盖 1 次还是 20 次，因此 ≥89% 这一数字对"搜索效率"的支撑有限（作者自己也用 TTFV 与 mutation 复现率做了补充论证）。

## 评估与建议
- 是否推荐深入阅读：**是**（agent 安全评测与 red-teaming 方法论的高质量工作）
- 适用场景：为角色化 LLM（客服、教学、面试、web agent）做规范遵守性测试；设计覆盖驱动的安全评测流水线；撰写 role specification 时定位薄弱原则
- 与知识库的关联：与 multi-turn red-teaming（Crescendo、Tempest、GOAT、X-Teaming）、fuzzing 方法论（AFL、directed grey-box fuzzing）、Inspect AI / PETRI 评测框架、以及"规范与训练默认冲突"的失效模式分析直接相关
