# Minerva: Reinforcement Learning with Verifiable Rewards for Cyber Threat Intelligence LLMs

> **arXiv**: [2602.00513](https://arxiv.org/abs/2602.00513)
> **发表日期**: 2026-01-31
> **分类**: cs.LG
> **会议/期刊**: arXiv preprint

## 📋 摘要

网络威胁情报（CTI）分析师日常需要把噪声化、非结构化的安全工件转化为标准化、可自动化的表示。虽然 LLM 在这一任务上展现出潜力，但既有方法在产出**结构化 CTI 输出**时仍显脆弱，且主要依赖**监督微调（SFT）**。与之相对，CTI 社区标准与维护的资源定义了**规范化标识符（canonical identifiers）与 schema**，这使得模型输出可以被**确定性验证**。作者利用这一结构，研究 CTI 任务上的**可验证奖励强化学习（RLVR）**。他们提出 **Minerva**：一个统一的**数据集与训练管线**，覆盖多个 CTI 子任务，每个子任务配有**任务特定验证器（verifiers）**，用于给结构化输出与标识符预测打分。为解决 rollout 阶段的**奖励稀疏**问题，进一步提出 **MinervaRL**——一种**辅助自训练机制**，生成额外的已验证轨迹并蒸馏回模型。在**4 个骨干模型**与 **12 个 CTI 基准**上取平均，MinervaRL 相比对应 base 模型将平均分提升 **15.8 个百分点**，相比 **GRPO** 提升 **4.3 个百分点**。项目页见 https://maveryn.github.io/minerva-tmlr/ 。

## 🎯 核心贡献

1. **Minerva 统一数据集与管线**：跨多个 CTI 子任务统一数据格式与训练流程，每个子任务配套**任务特定验证器**——这是把 RLVR 从"数学/代码题"迁移到**安全领域结构化抽取**的关键。
2. **利用 CTI 标准的可验证性**：识别出 CTI 规范（canonical identifiers + schema）天然支持**确定性输出校验**，因此无需人工偏好标注即可提供可靠奖励信号。
3. **MinervaRL 自训练机制**：针对 rollout 中奖励稀疏问题，生成额外的**已验证轨迹**并**蒸馏回模型**——把"验证器发现的高质量样本"反向注入训练，显著提升信号密度。
4. **系统性实证**：在 4 个 backbone × 12 个 CTI benchmark 上给出平均分提升量化结果，验证方法的可迁移性。
5. **可复现资产**：提供统一数据集、管线与项目页，便于社区在 CTI 方向复现 RLVR。

## 🔧 方法/架构

- **数据层（Minerva）**：统一数据集，覆盖多个 CTI 子任务（结构化表示生成、标识符预测等），任务之间的输入/输出 schema 统一组织。
- **验证器层（Verifiers）**：每个子任务配一个**任务特定验证器**，对
  - **结构化输出**（是否符合 schema / 格式与字段是否合法）打分；
  - **标识符预测**（是否命中规范标识符）打分。
  验证是**确定性**的，因此可作为 RL 奖励，无需 RM（reward model）。
- **训练层（MinervaRL）**：
  - 主体为 RLVR 训练（类 GRPO 风格的策略优化）；
  - 额外引入**辅助自训练分支**：在 rollout 中收集通过验证器的轨迹 → 生成额外 verified trajectories → **蒸馏回模型**；
  - 目的：缓解 rollout 早期的**奖励稀疏**（多数采样不通过验证器，导致无梯度信号）。
- **推理/评测**：输出为符合 CTI 规范的结构化表示，可直接接入下游自动化（规则引擎/SIEM 解析）。

```math
r(x,y) = \mathbb{1}\!\left[\, \text{Verifier}_{\text{task}}(x, y) = \text{pass} \,\right]
\quad\text{(binary verifiable reward; passes are distilled back as self-training data)}
```

## 📊 实验结果

- **数据/基准**：**12 个 CTI 基准**（涵盖多个 CTI 子任务）；统一数据集 Minerva。
- **骨干模型**：**4 个 backbone**（摘要未逐一列出模型名）。
- **基线**：对应的 base models（未经训练）、**GRPO**、以及既有的 **SFT** 方法。
- **结果**（跨 4 backbone × 12 benchmark 取平均）：
  - 相比 base model：平均分 **+15.8 个百分点**；
  - 相比 **GRPO**：平均分 **+4.3 个百分点**。
- **项目页**：https://maveryn.github.io/minerva-tmlr/ （摘要未给出是否开源全部权重/数据）
- 摘要未给出逐基准的分数明细、具体 backbone 型号及绝对分数。

## ⚠️ 局限性

- **领域窄**：结论仅在 CTI 结构化抽取任务上验证，迁移到其他"有 schema 可验证"的领域（如法律/医疗文档结构化）需重新设计验证器与数据集。
- **验证器即天花板**：奖励完全由确定性验证器定义，验证器的 bug 或 schema 过窄会直接限制模型能力上限（"verifier hacking" 风险），摘要未讨论。
- **依赖社区标准**：CTI 规范化标识符与 schema 需持续维护；标准演进会使训练/评测失配。
- 摘要**未给出**绝对分数、逐基准明细、backbone 具体型号、训练成本与推理开销；也未提供与更强 RL 算法（如 RLOO / DAPO）的对比。
- **MinervaRL 的自蒸馏**可能放大验证器偏置；缺少对"错误但通过验证"样本的分析。

## 💡 建议

- 是否推荐使用：**是**（尤其对做安全情报解析、IOC 抽取、CTI 自动化流水线的团队）
- 适用场景：需要把杂乱安全日志/报告转为规范化结构化输出的场景，且团队已有或能构建**可靠的规则/模式验证器**。可复用其"统一数据集 + 任务验证器 + 自蒸馏缓解稀疏"的三件套范式到其他可确定性验证的抽取任务。
