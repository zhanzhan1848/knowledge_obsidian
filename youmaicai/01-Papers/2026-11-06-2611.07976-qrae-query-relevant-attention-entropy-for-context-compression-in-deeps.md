# QRAE: Query-Relevant Attention Entropy for Context Compression in DeepSearch Agents

## 摘要
DeepSearch LLM agent 会**反复搜索**并把检索到的来源带进后续推理步骤。这种**不断膨胀的上下文**推高 token 消耗与延迟，尽管**许多检索结果对后续推理毫无贡献**。本文提出 **QRAE（Query-Relevant Attention Entropy）** —— 一种**在线上下文压缩**方法，使用**稀疏证据评估头（sparse evidence-assessment heads）**决定哪些**完整的**检索块应跨推理步骤保留。它通过**配对前向（paired prefills）**对受限候选批次打分：一个**无查询的对照（query-free control）**抑制共享的注意力响应，而**归一化熵**度量每个块内正响应的**广度**。高分块进入**持久证据白名单**并被纳入推理上下文。不确定的块**留在推理上下文之外**，但被保留在**候选缓存**中，可供**后续重新评估**。QRAE **既不需要额外的生成式压缩 pass，也不修改注意力算子**。在多个 DeepSearch 基准与推理模型上，QRAE **平均提升任务成功率 2.35 个百分点**。

## 核心贡献
1. 提出 **QRAE** —— 基于**注意力熵**的在线上下文压缩，决定哪些检索块跨推理步骤**完整保留**
2. 核心机制：**稀疏证据评估头** + **配对前向**（无查询对照抑制共享注意力响应）+ **归一化熵**度量块内正响应广度
3. **双层保留策略**：高分块 → **持久证据白名单**（入推理上下文）；不确定块 → **留在推理上下文外但存入候选缓存**，可后续重评
4. **无需额外生成式压缩 pass，不修改注意力算子** —— 相比「再让模型压缩一遍」零额外生成成本
5. 多个 DeepSearch 基准与推理模型上**平均提升任务成功率 2.35 个百分点**

## 方法与架构
**打分机制**：
```
对每个检索块 b：
  prefill(查询 + b)      → 响应分布 R_q
  prefill(无查询对照)    → 抑制共享响应 R_0
  归一化熵 H(b) = 熵( R_q(b) 的正响应广度 | R_0 已抑制 )
```
「稀疏证据评估头」负责定位哪些头承载证据评估信号。

**保留策略**：
```
H(b) 高 → 持久证据白名单 → 进入推理上下文（跨步骤保留）
H(b) 低 → 不进入推理上下文，但存入候选缓存（可后续重新评估）
```

**约束**：无额外生成式压缩 pass；不修改注意力算子。

- **端到端 token/延迟下降**
- **零额外生成式压缩成本**，不修改注意力算子

## 局限性
- 依赖**稀疏证据评估头**的存在与可定位性，不同模型/架构上不一定成立；
- **2.35 pp 的提升**相对收益有限，需与压缩率一起看才完整；
- 候选缓存保留了被丢弃内容，**内存占用**的净节省需查正文；
- 注意力熵作为证据相关性的代理，其可靠性未做独立验证。

## 值得注意的点
「**不确定的块不丢弃，而是移出上下文但保留在候选缓存中，可后续重新评估**」是这个设计中最聪明的部分 —— 它避免了「压缩即丢失」的刚性。多数上下文压缩方法把「不确定」等同于「无用」，QRAE 把它当作「**暂时无用**」—— 这与今日多篇的思路一致：**把不确定性显式建模，而不是塞进二值判断**。
