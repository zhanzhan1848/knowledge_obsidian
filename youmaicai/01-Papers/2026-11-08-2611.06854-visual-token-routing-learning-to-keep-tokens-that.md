# Visual Token Routing: Learning to keep tokens that matter

> **arXiv**: [2611.06854](https://arxiv.org/abs/2611.06854)
> **发表日期**: 2026-11-04
> **分类**: cs.CV (及交叉分类 cs.LG)
> **会议/期刊**: arXiv preprint

## 📋 摘要

计算机使用 agent（CUA）近期在多个长程基准上取得超人表现，但其计算成本限制了它们在长程任务和实时领域（如电子游戏）中的使用。关键瓶颈在于：每张截图被表示为**数千个视觉 token**，随着 agent 在长交互历史中推理而不断累积进长上下文。作者观察到这些视觉 token 中的大多数要么与 agent 下一步动作**语义无关**，要么在多张截图之间**时间冗余**。基于此观察，作者提出 Visual Token Routing（VTR），一个**联合训练**框架，用于学习保留动作预测所需信息的稀疏视觉表示。在 VTR 中，作者同时训练视觉语言模型（VLM）与一个轻量的**时空路由器（spatio-temporal router）**，该路由器检视当前与前一帧截图的每个图像区域，决定其视觉 token 是否进入语言模型。路由器使用**自适应损失（adaptive loss）**优化：在最小化性能退化的同时把视觉 token 数量压到尽可能少。仅用 **2,000 个训练步**，VTR 在 **OSWorld、CUA-World** 以及**电子游戏动作预测**上匹配全分辨率模型的性能，同时使用 **2.5–5.8 倍更少**的视觉 token。这些节省把推理成本降低至多 **3.3 倍**、把 prefill 加速至多 **2.9 倍**。VTR 还优于"降低图像分辨率"及其他 token 丢弃基线，在 OSWorld 上最高领先 **12.8 分**。

## 🎯 核心贡献

1. **关键观察**：CUA 上下文中的大多数视觉 token 是**语义无关**（与下一步动作无关）或**时间冗余**（跨截图重复）——这是可被利用的压缩空间，而非必须全量保留。
2. **VTR 联合训练框架**：VLM 与轻量**时空路由器**联合训练；路由器逐区域（region-wise）检视当前帧与前帧，**逐 token 决定**是否送入语言模型——是学习式稀疏化，而非启发式裁剪。
3. **自适应损失（adaptive loss）**：在"最小化 token 数"与"最小化性能退化"之间取得平衡，避免简单地按重要性阈值硬截断。
4. **高效训练**：仅 **2,000 训练步**即可达到全分辨率模型水平，说明路由器的学习信号高效且易收敛。
5. **强基线优势**：相较"降低图像分辨率"和其他 token 丢弃方法，在 OSWorld 上最高领先 **12.8 分**——证明"选择性丢弃"优于"均匀降采样"。

## 🔧 方法/架构

- **组件**：
  - 视觉语言模型（VLM，主干）；
  - 轻量**时空路由器（spatio-temporal router）**。
- **路由器输入/决策**：检视**当前截图与前一帧截图**的每个图像区域，输出该区域的视觉 token **是否进入语言模型**的二值路由决策（spatio-temporal：空间 + 时间两维）。
- **训练方式**：**联合训练**（joint training），路由器的决策与 VLM 表现耦合。
- **损失**：adaptive loss——同时惩罚 token 数量与性能退化。
- **输入形态**：与直接"降低图像分辨率"不同，VTR **保留全分辨率**，只在 token 维度做选择性丢弃。

## 📊 实验结果

- **训练成本**：仅 **2,000 训练步**。
- **视觉 token 减少**：**2.5–5.8 倍**更少（相对全分辨率）。
- **性能**：在 **OSWorld**、**CUA-World**、**电子游戏动作预测** 上**匹配全分辨率模型**。
- **推理成本**：降低至多 **3.3 倍**；**prefill 加速至多 2.9 倍**。
- **基线对比**：优于降低图像分辨率及其他 token 丢弃基线，OSWorld 上最高 **+12.8 分**。

## ⚠️ 局限性

- 路由器为"时空"设计，依赖**前一帧**信息；在非连续、跳变式界面或需要严格状态核对的场景（如金融表单逐字段校验）中可能误删关键证据。
- 摘要未披露绝对性能数值（仅称"匹配全分辨率模型"）、模型基座规模、以及 token 减少倍数在不同任务上的分布。
- 需 2,000 步联合训练，意味着**并非即插即用**——需针对目标 agent 重新训练路由器，成本高于纯推理期优化（如降低分辨率）。
- "与下一步动作相关"的定义依赖动作预测监督信号，对需要**全局推理**（如需要读取整页表格再做决策）的任务可能不成立。
- 与 MEMOIR 等记忆侧压缩方法**叠加**后的边际收益未验证，二者可能存在冗余。
- 电子游戏动作预测的结论外推到真实桌面/移动端 agent 未验证。

## 💡 建议

- 是否推荐使用：**推荐（针对 CUA 场景）**
- 适用场景：已在 OSWorld / CUA-World 类基准上跑通但**推理成本或 prefill 延迟成为瓶颈**的计算机使用 agent，尤其适用于视频游戏、实时交互类场景。建议以 VTR 与"降低分辨率"作为并行基线对比，并重点验证在自身任务上的 token-丢弃误删率。
