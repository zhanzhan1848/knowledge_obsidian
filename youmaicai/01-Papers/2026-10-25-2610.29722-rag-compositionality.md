## 核心贡献

> 用开源框架 **LASAGNA** 预声明（pre-declare）三个假设、系统测试 **450 种 RAG 配置**，得出一个对整个 RAG 研究社区都重要但一直被忽视的结论：**单独测出的增益不能可靠预测组合后的表现**。

1. **预声明假设（pre-registered）**：论文明确**在实验前预声明三个假设** —— 这在 LLM 评测论文中极为罕见，意味着后续结论不是事后叙事（post-hoc storytelling）
2. **LASAGNA 开源框架**：受控的 RAG 评测框架，覆盖 embedding、chunking、retrieval、reranking、query augmentation、context compression、agentic verification 等 pipeline 各阶段
3. **规模**：**450 个配置** × **8 个 benchmark** × **语料从 5K 到 200K 文档**
4. **发现一 —— 增益不合成（gains do not compose）**：来自 pipeline 不同阶段的三个"单独强"检索技术**预测了 +47% 的组合提升，实际只交付了 +17%**
5. **发现二 —— 检索质量与答案忠实度（faithfulness）不共优化**：两者的组件增益**堆叠方式不同**，优化一个**会损害另一个**
6. **发现三 —— 最优组合随语料规模变化**：小语料上胜出的组合**在大规模上未必仍是最优**
7. **对研究共同体的明确呼吁**：**新的 RAG 技术应该在完整的周边 stack 中被测试**，并开源 LASAGNA 以简化这类实验

## 技术方案

### 核心思想

```
现代 RAG pipeline:
  embedding → chunking → retrieval → reranking → query augmentation
           → context compression → agentic verification

社区现状: 每个技术单独测 (isolated evaluation)
本文主张: 必须测组合 (compositional evaluation)

问题: 单点增益 → 组合增益 的传递关系未知
     小规模结论 → 大规模结论 的传递关系未知
```

### 关键技术

| 技术 | 说明 |
|------|------|
| **Pre-declared hypotheses** | 实验前写死三个假设，避免事后编故事 |
| **450 配置矩阵** | pipeline 各阶段技术的组合枚举 |
| **8 个 benchmark** | 跨任务覆盖 |
| **语料规模跨度 5K–200K 文档** | 用于检验"小规模结论能否外推" |
| **检索质量 vs 答案忠实度双轴** | 分别度量 retrieval quality 与 answer faithfulness，检验二者是否共优化 |
| **Stage-agnostic 组合分析** | 分析增益在 pipeline 各阶段的堆叠方式 |
| **LASAGNA 开源框架** | 使这类组合实验可复现、可扩展 |

### 评测的两个维度（论文明确区分）

| 维度 | 含义 |
|------|------|
| **Retrieval quality** | 检索是否取到了正确证据 |
| **Answer faithfulness** | 答案是否忠实于检索到的证据 |

## 关键实验结果

### 三条核心发现

| 编号 | 发现 | 关键数字 |
|------|------|------|
| **F1** | 来自 pipeline 不同阶段的**单独强**检索技术**不必然合成** | 预测 **+47%** 组合提升 → 实际只交付 **+17%** |
| **F2** | 组件增益在 **retrieval** 与 **faithfulness** 上**堆叠方式不同**，优化一个可能损害另一个 | （未给具体数值） |
| **F3** | **最优组合随语料增长而改变** | 小语料最优 ≠ 大规模最优 |

| 项 | 数量 |
|------|------|
| 测试配置 | **450** |
| Benchmark | **8** |
| 语料规模 | **5K – 200K 文档** |

### 差距的量级

**+47% → +17%** 是全文最有力的数字：预测增益与实际增益之间有 **30 个百分点的落差** —— 意味着**约 64% 的预期增益（30/47）在组合中蒸发**。

## 关键结论 / 局限性

### 关键结论

1. **单点 ablation 结论在组合场景不可靠** —— 这直接挑战了当前 RAG 论文几乎普遍采用的"单技术消融"评测范式
2. **"更多 pipeline 阶段"不等于更好**：阶段之间存在**负交互（negative interaction）** —— 增益在阶段内部叠加，但阶段之间互相抵消
3. **检索质量与忠实度需分开优化**：把二者混为一个"准确率"会掩盖权衡（trade-off）
4. **小规模实验的外推性有限**：语料从 5K 涨到 200K，最优组合就变了 —— **"在 NQ/SQuAD 小语料上验证"不足以支撑生产结论**
5. **可操作的社区规范**：任何新 RAG 技术都应在**完整 stack** 中报告增益

### 局限性

- **450 配置 × 8 benchmark** 仍是有限的组合空间，未覆盖全 pipeline 的笛卡尔积 —— 论文标题用了 "Compositionality" 但覆盖仍是选定组合
- **未覆盖多模态 RAG / agentic 长期记忆 RAG**（与 [[2026-10-25-2610.30989-colabench-memory-guided-knowledge-acquisition]] 形成对照）
- **模型侧固定**：摘要未披露使用了哪些 embedding / 生成模型 —— **不同 backbone 下交互项是否一致**未验证
- **"+47% 预测 vs +17% 实际"的计算方式未在摘要中说明**（是三技术独立增益的乘法/加法组合，还是别的定义）—— 需要查正文
- **faithfulness 的度量方式**（人工？LLM judge？）未在摘要中说明 —— 考虑到 [[2026-10-25-2610.31172-prompting-strategy-depends-on-judge]] 对 judge 可靠性的怀疑，这是一个**需要警惕的点**
- **未报告统计显著性**（摘要中无置信区间 / p 值）
- **仅 arXiv 预印本**，未见同行评审
- 代码与项目主页已开源（LASAGNA），复现成本低
