## 核心要点
1. **问题量化**：**DeepSeek-V4.1 的 203 GB Engram n-gram 表**目前放在主机 DRAM 中，占用 4-GPU serving 进程所用 **223 GiB 中的 190 GiB**。由于**行索引只依赖输入 token**，读取可在每一步开始时就启动并与更早的层重叠；但 **V4.1 的两个 Engram 层的窗口相差 30 倍（0.3 ms vs 9.3 ms）**。
2. **核心模型**：作者表明这个**逐层预取截止时间（per-layer prefetch deadline）**、加上**会话内复用**与**共享设备上的争用**，共同决定了每张表能用哪一档存储层级、哪些层需要缓存，并给出一个**由实测读取时间预测减速幅度**的模型。Agent 与 chat 流量在会话内会复用行，而**静态热点集迁移性差**。
3. **SlackTier 实现与结果**：为 SGLang 实现的表分层，**在 step 开始时发出全部查找**、**先读短窗口层**、并把**小型 GPU 行缓存跨层切分**；该路径**运行在 decode CUDA graph 内且与原 gather 位级一致（bit-exact）**。**第 14 层的表可放到 NVMe 且无需缓存**，解码开销无可测增长。两张表放四块 NVMe 磁盘时，agent 与 chat 回放的**每输出 token 平均时间相对未改动的 SGLang 最多上升 1.4%**，**主机内存从 212 GiB 降到 34 GiB**。两张表若通过 **RDMA** 从另一节点内存读取则**均无需缓存**，一份拷贝可服务两个实例；在 **KV 受限的 agent 负载**下，把释放出的内存用作**主机 KV cache** 可使**中位吞吐提升 36%**，**p50 首 token 时间中位数从 38 s 降到 24 s**。

## 摘要（原文）
DeepSeek-V4.1's 203 GB of Engram n-gram tables sit in host DRAM today, taking 190 of the 223 GiB a 4-GPU
serving process uses. Row indices depend only on input tokens, so reads can start with each step and overlap
earlier layers. V4.1's two Engram layers have windows that differ by 30x (0.3 vs. 9.3 ms). We show that this
deadline, together with session reuse and contention on a shared device, decides which tier each table can use
and which layers need cache, and we give a model that predicts the resulting slowdown from measured read times.
Agent and chat traffic reuse rows within sessions, and static hot sets transfer poorly. We build SlackTier, a
table tier for SGLang that issues all lookups at step start. It reads the short-window layer first and splits a
small GPU row cache across layers. The path runs inside the decode CUDA graph and is bit-exact with the
original gather. Layer 14's table can go to NVMe uncached with no measurable decode cost. With both tables on
four NVMe disks, mean time per output token on agent and chat replays rises at most 1.4% over unmodified
SGLang, and host memory falls from 212 to 34 GiB. Both tables need no cache when read over RDMA (remote
direct memory access) from another node's memory; one copy serves two instances. On a KV-constrained agent
workload, using the freed memory as host KV cache at the same memory budget raises median throughput by 36%
and cuts median p90 time to first token from 38 to 24 s.
