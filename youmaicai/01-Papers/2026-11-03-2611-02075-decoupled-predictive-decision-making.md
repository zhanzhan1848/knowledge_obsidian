## 核心贡献
1. **DPDM（Decoupled Predictive Decision Making）**：把**异构的 agent 决策**统一形式化为**条件预测（conditional prediction）**，配以一个**共享的预训练学习器（shared pretrained learner）**。
2. **双模型解耦架构**：**语言模型**提供当前与历史记录的**语义表示**；一个**通用条件预测器**从被表示的证据中预测**任务定义的目标**；二者通过 **evidence-and-query 接口**连接，预测结果由**决策规则（decision rule）**映射为选择。
3. **不更新任何神经参数**：预训练提供**可复用的推理能力**，部署证据**实例化**问题特定的预测——"从经验中学习"成为一项**可独立改进的基础模型能力**。
4. **统一覆盖五类任务**：工具判断（tool judgments）、候选偏好（candidate preferences）、推理评估（reasoning assessments）共享同一 evidence-and-query 接口。
5. **定量结果**：单一冻结的 **LimiX-2** 预测器服务全部 5 类任务；用 **Qwen3.5-27B** 作语义编码器，平均准确率从 few-shot 的 **78.80%** 提升到 **84.92%**（各自的历史预算下），在**相同历史与查询**下达到 **82.33%**；在 ToolPRMBench 的 **BFCL** 与 **ToolSandbox** 任务上绝对准确率分别提升 **34.26%** 与 **28.87%**；在相同的不平衡历史下，5 个推理步评估任务 × 4 个编码器的平均平衡准确率绝对提升 **14.51%**；准确率随历史增长而提升。

## 问题背景
Agent 的决策依赖于**部署观测（deployment observations）所揭示的经验关系**，而这些关系**仅靠任务描述可能无法解决**。换言之，一个 agent 常常需要"从自己过去的成功/失败中学习"才能做出更好的判断——例如判断一个工具调用是否可靠、偏好哪个候选方案、评估一条推理链是否正确。现有做法要么把这些能力分别塞进不同的专用模块（各自训练、各自维护），要么依赖 prompt 里的 few-shot 样例（无法吸收部署期新出现的经验）。本文提出把"**语义理解**"与"**从数据中做条件预测**"这两种能力**解耦**，用一个共享的预训练预测器承担后者，从而让不同任务共享部署证据的收益。

## 方法

### 架构：解耦的预测式决策
```
┌──────────────────────────────────────────────────┐
│  语言模型 (语义编码器)                              │
│  语义表示: 当前记录 + 历史记录                       │
│         ↓  evidence-and-query 接口                │
│  ┌──────────────────────────────────────────┐    │
│  │ 共享的条件预测器 (冻结, 预训练)              │    │
│  │ LimiX-2 (通用, 单一实例服务全部任务)          │    │
│  │ 输入: 语义证据 + 查询                        │    │
│  │ 输出: 任务定义的目标 (task-defined target)   │    │
│  └──────────────────────────────────────────┘    │
│         ↓                                        │
│  决策规则 (decision rule) → 选择 / 动作             │
└──────────────────────────────────────────────────┘
```

**关键点：两个模型的神经参数都不更新。**

### 1. 语义编码器（语言模型）
语言模型把**当前记录与历史记录**编码为**语义表示**。它承担的是"读懂证据"的能力，来自语言预训练。

### 2. 共享条件预测器
一个**通用**的（general-purpose）条件预测器，从被表示的证据中预测**任务定义的目标**。它的能力来自**结构化数据预训练（structured-data pretraining）**——摘要明确指出这是与"语言预训练"**互补的能力来源**。

关键设计：**单一冻结的 LimiX-2 预测器服务全部五类任务**。这意味着任务差异不通过换模型吸收，而通过**"任务定义的目标"**（即输出头的定义）与**决策规则**吸收。

### 3. evidence-and-query 接口
工具判断、候选偏好、推理评估三类决策共享同一个接口形状：把语义表示整理成"证据"，把任务诉求整理成"查询"，由同一预测器返回预测。

### 4. 决策规则映射
预测输出经**决策规则**映射为具体的选择。这把"打分"与"选哪个"解耦，使得同一个预测器可以在离散选择、排序、判定等不同输出形态间复用。

### 5. 不更新参数的学习范式
这是范式层面的主张：**预训练供给可复用推理能力，部署证据实例化问题特定的预测**。因此部署期的经验积累**不需要梯度更新**——新经验通过"证据"进入，而非通过"改权重"进入。

## 实验结果

### 主结果：跨 50 个基准的平均准确率
| 设置 | 平均准确率 |
|------|-----------|
| few-shot prompting（基线） | **78.80%** |
| DPDM（各自评测的历史预算下） | **84.92%** |
| DPDM（**相同历史与查询**条件下） | **82.33%** |

- 语义编码器：**Qwen3.5-27B**
- 条件预测器：**单个冻结的 LimiX-2**（服务全部五类任务）
- 覆盖：**50 个基准**、**5 类任务**

### ToolPRMBench 任务（绝对准确率增益）
| 任务 | 绝对准确率增益 |
|------|--------------|
| **BFCL** | **+34.26%** |
| **ToolSandbox** | **+28.87%** |

（均在各方法自身的评测历史预算下测得。）

### 推理步评估（不平衡历史 + 平衡准确率）
| 设置 | 结果 |
|------|------|
| 任务数 × 编码器数 | **5 个推理步评估任务 × 4 个编码器** |
| 相同的不平衡历史 | 平均平衡准确率**绝对提升 14.51%** |

用**平衡准确率**而非普通准确率，说明这一评估专门针对**类别不平衡**场景设计。

### 消融式趋势
| 观察 | 结果 |
|------|------|
| 历史长度 | **准确率随历史增长而提升** |
| 相同历史/查询的严格设定 | 仍有 82.33% vs 78.80% 的增益 |

摘要未给出：LimiX-2 的规模与架构、50 个基准的清单、Qwen3.5-27B 之外编码器的具体型号、五类任务的具体定义、以及历史预算的具体 token/条数。

## 关键洞察
1. **"从经验中学习"可以被重构成推理任务而非训练任务**：DPDM 的核心洞见是——部署证据揭示的经验关系，本质上是**条件预测**问题，交给一个在结构化数据上预训练的预测器即可，无需改动任何神经参数。这让"经验积累"变成一条**可独立改进的路线**（改进条件预测器），而不是每次都要微调 LLM。
2. **BFCL +34.26% / ToolSandbox +28.87% 的巨大增益说明了工具使用中"经验"的分量**：工具调用的可靠性高度依赖具体环境（某工具在此 API 版本下常失败等），这类知识**不可能在语言预训练里**，只能在部署中通过证据获得。这解释了为什么增益远大于总体基准的 6.12 个百分点（84.92% − 78.80%）。
3. **"相同历史与查询"下仍有 82.33% vs 78.80%**，是对 DPDM 有效性的一个稳健性检验：在最严格的可比设定下仍有约 3.5 个百分点的净增益，排除了"增益主要来自更多上下文"这一竞争解释。
4. **不平衡历史下平衡准确率提升 14.51%**，说明 DPDM 相比直接吃长历史的 few-shot 方式，在**类别不平衡**这一现实条件下的优势更大——因为 few-shot 会重复采样多数类，而条件预测器可以直接学习"在这样的不平衡经验分布下，什么条件下会失败"。
5. **单一冻结预测器服务 5 类任务**是架构优雅性与实用性的双重体现：它意味着 agent 的多类决策能力**共享同一份经验**，新的部署证据能同时惠及所有决策类型——这与"每类任务一个专用模型"的传统做法形成鲜明对照。

## 局限性
- **LimiX-2 预测器未公开描述**：其规模、架构、预训练数据与"通用条件预测"能力的边界均未在摘要中给出——这使得复现困难，也让"共享预测器"的泛化性主张难以评估。
- **依赖历史预算**：多个关键数字是在"各自评测的历史预算"下获得的，而严格的"相同历史"设定只有整体均值（82.33%）与一组平衡准确率（14.51%）——**跨设置的可比性有限**。
- **语义编码器仍是强依赖**：Qwen3.5-27B 提供的语义表示质量直接决定上限；用 4 个编码器做了推理评估的消融，但摘要未说明其余三个是什么、以及性能方差。
- **不更新参数的双刃剑**：优点是免训练、免灾难性遗忘；代价是**新经验无法改变语义表示**，若经验以语义之外的形式存在（如风格、领域术语的微妙含义），冻结编码器可能无法充分暴露它。
- **50 个基准的构成未披露**，因此 84.92% 的均值可能被少数高权重基准主导。
- **决策规则的映射能力未评估**：当预测目标是连续值或需要多选组合时，决策规则本身可能成为瓶颈。
- 未评估**多 agent 之间共享该预测器**的收益（这才是"共享"设计的最大潜力），也未讨论部署证据的存储、遗忘与隐私治理。
- 摘要未涉及成本（额外的预测器前向开销）与延迟影响。

## 适用场景
- **工具使用型 agent**：工具可靠性判断、API 选择——部署经验价值最高的场景。
- **多类决策共用同一 agent 平台**：如同时做工具调用、候选方案选择、推理链审核的产品，用一个共享预测器即可继承全部经验。
- **无法频繁微调 LLM 的合规/受控环境**：DPDM 全程冻结参数，满足"只推理不训练"的部署约束。
- **类别不平衡的经验数据场景**：如失败样本远少于成功样本的线上日志，用条件预测比 few-shot 重采样更稳。
