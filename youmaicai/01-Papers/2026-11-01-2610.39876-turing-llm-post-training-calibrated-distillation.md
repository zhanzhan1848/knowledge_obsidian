# Turing LLM Post-Training: Calibrated Distillation and Efficient Dynamic-MoE Execution

## 摘要
本文研究动态路由 mixture-of-experts（MoE）模型的后训练，聚焦于把独立优化的各领域专家整合进一个模型同时保持整合过程高效。方法结合**校准式多教师 on-policy 蒸馏**（C-MOPD）——在局部 Top-$K$ support 上匹配每个被选中的教师，并做 teacher-wise loss 归一化与 clipping——与一条执行路径，包含 post-capacity 有界宽度 dispatch（bounded-width dispatch）、final-route replay 以及异步 rollout–training overlap。在 Turing-20B-A2B 上，所选模型取得四领域归一化整合分数 **0.9988**，并在每个领域保留至少 **90.16%** 的实测专家增益。在匹配的 $K=32$ 下，完整校准目标得 0.9962，而不加校准为 0.9724、不加 clipping 为 0.9834。在匹配的 8K response cap 下，该模型在四个 reasoning-enabled 数学与代码 benchmark 上均超过 shared SFT 与 Qwen3-8B（非加权均值 **85.92**，对比 Qwen3-8B 的 80.33 与 SFT 的 74.21），并在更广评测的 12 项指标中的 10 项上优于 SFT。在 PPU-based profile 下，组合执行配置把 consolidation step time 从 **398.7 秒降到 139.3 秒**，相对串行执行观察到 **2.86×** 加速。作者同时强调，这些结果反映的是完整的训练与执行框架，而非任何单一组件。

## 核心贡献
1. **端到端 specialize-then-consolidate 流水线**：面向动态 MoE，把 shared SFT 初始化、四个 verifier-driven RL 专家与单一 C-MOPD 学生连成一体。
2. **C-MOPD**：teacher-local Top-$K$ reverse-KL 匹配 + teacher-wise loss-scale 归一化 + token-level clipping，教师权重固定。$K=32$ 的匹配消融：完整目标 0.9962 vs 去掉归一化与 clipping 的 0.9724、只去掉 clipping 的 0.9834。
3. **高效动态 MoE 执行**：capacity filtering 后的有界宽度 dispatch、final-route replay（R3 风格）、asynchronous rollout–actor overlap，保持跨引擎 route 一致性。
4. **开源性质的完整评测**：与 Qwen3-8B、SFT 在 12 项通用指标 + 4 项 reasoning 指标上逐项对比，并给出 output-cap hit rate 与硬件 profile。

## 方法与架构
**框架三阶段**（Fig. 1）：① **共享 SFT**：约 **5.28M** 样本，覆盖数学、代码、工具使用、指令跟随、长上下文与对话；采用 Qwen 约定的双响应模式——reasoning-enabled prompt 以开放的 `<think>` 标记结束 assistant 前缀（生成在 reasoning block 中进行直到 `</think>`），direct-response prompt 则插入空的 `<think></think>` 对后再输出答案。数据含 teacher correction、capability-boundary filtering 与 protocol-randomized MCQ 构造。
② **领域 RL 专家**：用 **GSPO**（每 prompt 16 个 rollout）训练四个专家——Math、Code、IF（instruction following）、Agent（agentic tool use）。奖励设计（Tab. 1）：Code 为抽取、签名有效性、编译与单测通过率（辅助项以可执行有效性为门槛）；Math 为最终答案正确性与正常完成（对截断与重复推理施加惩罚）；IF 为约束满足或选项正确性（偏好简洁有效输出）；Agent 为 tool-call 格式、参数正确性、任务完成度与来自 20B process reward model 的过程反馈。prompt 形式混合：Code/Math 为 Think 80% / Non-think 20%，IF 为 20%/80%，Agent 为 100% Think。
③ **C-MOPD 整合**：冻结四个专家作为教师。

**C-MOPD 细节**：
- 任务路由为每个 prompt 选一个冻结教师：$d_j = r(x_j)$。
- 在每个有效响应位置 $t$，在 student 自生成前缀 $(x_j, y_{j,<t})$ 上评估教师 $d_j$；记 $p_{\theta,j,t}$ 与 $q_{d_j,j,t}$ 为学生与教师的 next-token 分布。
- 教师局部 support：$S_{j,t} = \mathrm{TopK}(q_{d_j,j,t})$；在 support 内独立重归一化后计算 token 级 reverse KL：
```math
\bar p^S_{\theta,j,t}(v) = \frac{p_{\theta,j,t}(v)}{\sum_{u\in S_{j,t}} p_{\theta,j,t}(u)},\qquad
\bar q^S_{d_j,j,t}(v) = \frac{q_{d_j,j,t}(v)}{\sum_{u\in S_{j,t}} q_{d_j,j,t}(u)}
```
```math
\ell_{j,t} = D_{\mathrm{KL}}\!\left(\bar p^S_{\theta,j,t}\,\|\,\bar q^S_{d_j,j,t}\right)
```
该目标只匹配教师最可能的 $K$ 个 token 之间的相对概率，不直接约束 support 之外的概率质量。
- **teacher-wise loss-scale 校准**：对 microbatch $B_\mu$ 中每个教师 $d$ 计算其 token loss 的标准差（从计算图 detach）：
```math
\sigma^{(\mu)}_d = \mathrm{Std}\{\ell_{j,t} : j\in B_\mu,\ d_j=d,\ m_{j,t}=1\}
```
以 scale floor 0.1、clipping 上限 $c_{\max}$ 构造校准后 loss（不做 mean-centering，以保持非负）：
```math
\hat{\ell}_{j,t} = \min\!\left(c_{\max},\ \frac{\ell_{j,t}}{\max\left(\sigma^{(\mu)}_{d_j},\,0.1\right)}\right)
```
- **固定教师权重的 microbatch 目标**（token_mean 归约）：
```math
\mathcal{L}_\mu(\theta) = \frac{\sum_{j\in B_\mu}\sum_t m_{j,t} w_{d_j} \hat{\ell}_{j,t}}{\sum_{j\in B_\mu}\sum_t m_{j,t}}
```
固定权重 $(w_{\text{Math}}, w_{\text{Code}}, w_{\text{IF}}, w_{\text{Agent}}) = (1.0, 1.0, 0.3, 1.0)$；域采样概率 $(\rho_{\text{Math}},\rho_{\text{Code}},\rho_{\text{IF}},\rho_{\text{Agent}}) \approx (0.291, 0.194, 0.320, 0.194)$。教师保留输出与局部散度计算的开销为 $O(TK)$；学生前向仍计算全词表 logits。

**执行路径**：
- **Capacity-constrained Quantile Routing**（基础模型自带）：对路由窗口 $W$，per-expert capacity filtering 至多保留 $C(W)=\lceil \alpha |W| \bar{k}/E\rceil$ 个最高分配（$\alpha$ 为 capacity factor、$\bar{k}$ 为目标平均 expert 数、$E$ 为 expert 总数）。默认 rollout 表示每 token 保留 $E=256$ 个 expert slot；实测路由 profile 中 active expert 数的 **99 分位约为 19**，**0.21%** 的 token 路由超过 32 个 expert，故设 $W_{\text{route}}=32$：
```math
E^{\text{roll}}_t = \begin{cases} E^{\text{cap}}_t, & |E^{\text{cap}}_t| \le W_{\text{route}}\\
\mathrm{TopK}_{e\in E^{\text{cap}}_t}(s_{t,e}, W_{\text{route}}), & |E^{\text{cap}}_t| > W_{\text{route}}\end{cases}
```
这把依赖宽度的 route 表示缩到默认的 **1/8**。
- **Final-route replay（R3 风格）**：capacity filtering 依赖窗口内 token，rollout 与 actor 窗口不同会独立产生不同分配，故 replay capacity filtering 与宽度限制后的最终分配图 $A^{\text{roll}}$；actor 复用该离散分配并在当前参数下重算连续 routing 权重：
```math
A^{\text{actor}} = A^{\text{roll}},\qquad p^{\text{actor}}_{t,e} = A^{\text{roll}}_{t,e}\,\sigma(z^\theta_{t,e})\,\gamma
```
- **AsyncOverlap**：rollout 生成与 actor 更新并发，轨迹由前一代 student policy 生成、由当前 actor 在 replay 的 expert 分配下评估，引入**一步 policy lag**。

## 实验设置
- **模型**：Turing-20B-A2B（20B 总参数、每 token 约 2B 激活参数、原生 128K 上下文），post-training 保留其架构与动态 Quantile Routing。
- **训练预算（Tab. 10）**：SFT 10,000 步 / 512 packed rows / 5.27M 样本 / ~1 epoch；Code RL 240 步（128 prompts × 16 rollouts，16K prompts，~2 epoch）；IF RL 480 步（16.2K prompts，~4 epoch）；Math RL 550 步（35.5K prompts，~2 epoch）；Agent RL 512 步（64 prompts × 16 rollouts，8.5K prompts，~4 epoch）；C-MOPD 400 步（128 prompts × 1 rollout，51.5K prompts，~1 epoch，含 20 warmup 步）。
- **SFT 数据配比（Tab. 11）**：数学与代码蒸馏 2.69M（51.0%）、Agent 工具使用 1.51M（28.7%）、通用与指令跟随 0.67M（12.7%）、长上下文与对话 0.40M（7.6%）；全量约 53% reasoning-enabled / 47% direct-response。
- **数据构建（App. A）**：capability-boundary filtering——每个 prompt 采 $n\ge4$ 个温度 1.0 响应，经验通过率 $b_p(x)=\frac{1}{n}\sum r_i$，保留 $\frac{2}{n}\le b_p(x)\le n-\frac{2}{n}$ 的 prompt（即至少两个成功、至少两个失败）；MCQ 答案格式随机化含 29 个英文与 29 个中文格式变体，奖励 $r_{\text{mcq}}(y)=\mathbb{1}[E_f(y)\ne\perp]\mathbb{1}[E_f(y)=g_{f,\varpi}(\ell)]$。
- **评测**：OpenCompass 任务定义的统一生成式流水线，覆盖知识、推理、数学、代码、可验证指令跟随与 function calling；Qwen3-8B 参考分用相同流水线复现。
- **归一化整合分数**：对每个领域 $d$，$s_d$ 为该领域 benchmark 分的未加权均值；SFT 归一为 0、specialist 归一为 1；$e^s_d = \frac{s_d - s^{\text{SFT}}_d}{s^{\text{teacher}}_d - s^{\text{SFT}}_d}$，$\mathrm{Integration} = \frac{1}{n}\sum_{d=1}^{n} e^s_d$，$n=4$。Math 含 GSM8K+MATH（direct 模式）与 GSM8K+MATH-500（reasoning 模式）；Code 含 HumanEval、MBPP、MBPP+（两模式）；IF 用 IFEval；Agent 用 BFCL v4（reasoning 模式）。
- **输出长度上限**：direct 模式下 GSM8K 512、MATH 2,048、HumanEval/MBPP 8,192；reasoning 对比统一 8K cap，Qwen3 32K 作为更大预算参考。
- **硬件 profile**：PPU 硬件。

## 局限性
作者自述：结果反映的是**完整的训练与执行框架，而非任何单一组件**——即 C-MOPD 的贡献与执行路径的贡献在端到端数字上未被解耦；执行 profile 中"每个配置的 code benchmark 分数取自各自选定的 checkpoint，这些 checkpoint 位于不同训练步，因此只是描述性比较"。作者亦指出校准消融中完整目标在 **Math 域反而更低**（0.8298 vs no-calibration 的 0.8938）。

我的补充批判：① **归一化整合分数并非良态指标**——Code 与 Agent 的恢复率超过 1.0（1.0093、1.1435），意味着 consolidated student 在这两个领域**超过了各自 specialist**；这可能是专家蒸馏的正向泛化效应，也可能是 specialist 训练不足或 benchmark 噪声，但作者未做任何显著性检验，也没有多 seed 重复，400 步 consolidation 的 run-to-run 方差完全未知；② 与 Qwen3-8B 的对比虽复现了 pipeline，但 Turing-20B-A2B 有 20B 总参数/2B 激活，Qwen3-8B 是稠密 8B，容量与训练预算都不可比；③ GPQA Diamond 下降 5.05 点是显著退化，作者只列出未分析（可能与 specialization 后的通用推理能力回落有关）；④ 输出长度对比对 Qwen3-8B 不完全公平——32K 时 Qwen3-8B 的 MATH-500 达 95.00，高于 C-MOPD 8K 的 82.40，作者承认这一点但仅作为脚注；⑤ $w_{\text{IF}}=0.3$ 与四个域的采样比例是在 consolidation 前固定的超参，敏感性分析缺失；⑥ AsyncOverlap 引入的 one-step policy lag 对 on-policy distillation 的偏差影响未做量化。

## 评估与建议
- 是否推荐深入阅读：**是**（作为工业界 MoE 后训练与"specialize-then-consolidate"范式的参考实现与数据）。
- 适用场景：MoE 模型的 post-training 流水线设计；多领域专家整合为单一可部署模型；on-policy distillation 的损失校准与稳定化；大规模 RL 训练的执行效率优化（异步 overlap、route replay、有界宽度 dispatch）。
- 与知识库的关联：直接对应 MOPD（Ma et al. 2026，多教师 on-policy 蒸馏）、R3（Ma et al. 2025，MoE RL 的训练/推理 router 对齐）、GSPO（Zheng et al. 2025）、TuringLLM 基础模型报告、Qwen3 think/non-think 双模式约定；与 model merging、capability integration、SFT/RFT 阶段划分等主题相关。
