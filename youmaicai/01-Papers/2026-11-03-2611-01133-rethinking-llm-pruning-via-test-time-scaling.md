## 核心贡献
1. **重新定义剪枝的评估轴**：指出剪枝后 pass@1 的下降究竟反映**推理能力（reasoning capacity）受损**，还是仅反映**正确解更难被采样到（sampling difficulty）上升**——并给出可分离的诊断方法。
2. **pass@k 视角的覆盖率分析**：在**匹配的采样预算（matched sampling budgets）**下比较原始与剪枝模型；发现即使大幅剪枝，某些模型仍能**达到或超过原模型的推理覆盖率（reasoning coverage）**，尽管 pass@1 更低，并且能**解出原模型采样中未解出的题目**。
3. **覆盖率 ≠ 采样效率的分离**：保留广泛覆盖率并不意味着正确解依然容易获得；严重剪枝下**多样的 CoT 轨迹**会伴随**重复增加（increased repetition）**与**生成可靠性下降**。
4. **token 成本的反直觉结论**：随着正确答案越来越难采样，**额外尝试次数会急剧增加总 token 消耗**，即使单次响应变短。
5. **对专家选择方法（expert-selection）收益的重新解释**：pass@1 差异显著不同的方法，在大预算下能解出相同的问题集，但**达到同一覆盖率目标所需的尝试次数不同**。
6. **结论性主张**：剪枝应同时按"模型还能解出哪些问题的范围"与"获得正确解的采样成本"两个维度评估。

## 问题背景
结构化剪枝（structured pruning）可缩小 LLM 体积，但通常以准确率下降为代价。社区惯例是报告剪枝前后的 **pass@1**，并据此判断剪枝是否"损失了能力"。这一惯例混淆了两个不同的问题：模型是**真的不会了**（能力受损），还是**仍然会、但更難被采样命中**（采样变难）。二者的工程含义截然不同——前者需要重新训练，后者可以靠增加测试时采样预算补偿。该文在**专家剪枝、FFN 剪枝、层剪枝**三类操作、**四个数学与代码基准**上做 pass@k 分析，主张评测口径必须升级。

## 方法
**实验设计**

- **剪枝类型（三种）**：
  1. **Expert pruning**（专家剪枝）——针对 MoE 模型；
  2. **FFN pruning**（前馈网络剪枝）；
  3. **Layer pruning**（层剪枝）。
- **基准**：**四个数学与代码基准**（摘要未列出具体基准名称）。
- **核心度量**：
  - **pass@k**：在**匹配的采样预算（matched sampling budgets）**下比较原始模型与剪枝模型，即在同等采样次数/预算下比较覆盖率。
  - **reasoning coverage（推理覆盖率）**：模型在其采样集合中能解出的题目范围（对应 pass@k 所覆盖的问题集合）。
  - **采样效率 / token 成本**：达到某一覆盖率目标所需的**尝试次数**与**总 token 消耗**。
  - **pass@1**：单次采样准确率，作为对照。
- **多样性诊断**：统计生成 CoT 轨迹的**重复率（repetition）**与**生成可靠性**。

**诊断逻辑（据摘要重述）**
```
对每个 (剪枝配置, 基准):
  1. 在相同采样预算 N 下分别采样原模型与剪枝模型
  2. 计算 pass@1 与 pass@k（覆盖率）
  3. 对比：剪枝模型的解题范围是否 ⊇ / ⊇ 原始模型的范围
     → 若是，则 "能力未受损，只是更难采样"
  4. 记录达到同一覆盖率所需的尝试次数与累计 token
  5. 统计重复率与可靠性以刻画"多样但不可靠"的采样状态
```

**专家选择的解释**
- 两种 pass@1 差异明显的方法，在**大预算**下可以解出**相同的问题集合**；
- 但为达到**共同的覆盖率目标**，它们所需的**尝试次数不同**——即 pass@1 与"最终可达覆盖"之间没有单调对应关系。

## 实验结果
- **定性结论（摘要未给出具体数值，无 pass@k 表格数值、无剪枝比例、无基准名称）**：

| 观察 | 结论 |
|------|------|
| 大幅剪枝后的 pass@1 | 显著低于原模型 |
| 大幅剪枝后的 pass@k（匹配预算） | 某些模型**达到或超过**原模型的推理覆盖率 |
| 解题范围 | 剪枝模型可解出**原模型采样中未解出**的问题 |
| 生成质量 | 严重剪枝下 CoT 轨迹多样性增加，但**重复增加**、**可靠性下降** |
| token 成本 | 正确解越难采样，**额外尝试次数急剧推高总 token**，尽管单次响应变短 |
| 专家选择方法 | pass@1 差异大 ≠ 覆盖面差异大；达到同一覆盖率所需尝试次数不同 |

- 未披露：四个基准的名称、各剪枝配置的剪枝比例、pass@k 的 k 值与预算、重复率与可靠性的具体度量指标、数值型结果（摘要未给出具体数值）。

## 关键洞察
1. **pass@1 是"最易样本上的表现"，pass@k 是"能力上界"，二者可以反向**。剪枝模型在 pass@1 上更差却在 pass@k 上不差——这直接反驳了"剪枝掉的就是能力"的默认假设，并把问题重述为**采样效率问题**。
2. **"多样但不可靠"是一个陷阱**：剪枝后 CoT 更"发散"看起来像保留了多样性，实际上伴随重复与可靠性下降。pass@k 的上升部分来自**低质量轨迹的偶然命中**，这解释了为什么大预算下看似覆盖面广，但每次尝试的成本与不可控性剧增。
3. **剪枝的真实成本可能体现在推理账单而非准确率表上**：总 token 消耗的急剧上升是一个容易被 pass@1 掩盖的运营成本项。在按 token 计费的部署场景中，剪枝带来的体积节省可能被测试时采样的额外开销抵消甚至反超。
4. **对专家选择类方法的评价需要改口径**：pass@1 差距显著但大预算覆盖面相同 —— 这意味着只看 pass@1 会误判方法优劣，需要同时看达到目标覆盖率所需的尝试次数。

## 局限性
- **摘要完全未给出数值**：pass@k 曲线、剪枝比例、token 统计、重复率度量全部缺失，无法量化各项效应，也无法复现。
- 四个数学与代码基准**未被点名**，任务难度分布未知；pass@k 对任务难度分布高度敏感（难题需要更大 k），因此跨文献的 pass@k 数值本身也需谨慎解读。
- MoE 专家剪枝的结论与 dense 模型的 FFN/层剪枝可能不可互相推广，摘要未区分三者的效应量。
- 匹配采样预算下比较是正确的方法学，但 pass@k 随 k 增大而饱和的性质意味着"大预算下覆盖面相同"在足够大的 k 时是平凡成立的；论文的判断依赖于所选预算区间，这一点摘要未说明。
- 未涉及剪枝后的**再训练/恢复**方案，因此结论适用于"剪枝即部署"的场景；若常规做法是剪枝后继续训练，采样难度的结论需重新评估。
- 未考虑结构化剪枝对**推理延迟**、**显存占用**、**部署成本**的影响，仅从采样效率角度切入。

## 适用场景
- LLM 结构化剪枝方案的评测口径设计（MoE 专家剪枝、FFN/层剪枝）
- 推理服务的**成本核算**：在 pass@k 与 token 预算联合视角下评估"剪枝换体积"是否真的省钱
- 需要判断"剪枝模型是否能力受损"的技术尽调（用 pass@k 而非 pass@1 结论）
- 少样本 / 多采样解码策略的调参：为高难度数学代码任务选择合适的采样预算
- 专家选择（expert routing）方法的横向比较与选型
