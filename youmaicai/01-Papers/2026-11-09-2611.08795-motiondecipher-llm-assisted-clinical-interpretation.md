# MotionDecipher: LLM-Assisted Clinical Interpretation of Human Motion Signals for Efficient Gait Analysis

> **arXiv**: [2611.08795](https://arxiv.org/abs/2611.08795)
> **发表日期**: 2026-11-05
> **分类**: cs.HC (交叉分类 cs.AI)
> **会议/期刊**: IMWUT, Vol. 10, No. 4, Article 245, December 2026（33 pages, 19 figures, 2 tables）

## 📋 摘要

临床步态与运动分析被广泛用于指导神经疾病患者的针对性干预，其产出通常是一份描述关节运动与受力的**报告**。当前实践高度依赖专家手工劳动，**劳动密集且耗时**。LLM 的最新进展为解决该问题提供了机会，但"把人体运动翻译成临床步态描述"仍然困难——因为**上下文质量直接决定 LLM 对连续运动信号的推理能力**。为弥合这一鸿沟，本文提出 **MotionDecipher**：一个连接运动数据与临床解释的框架，包含三项关键设计：1）**Human Motion Tokenizer**，把运动信号转换为**领域专用 token**，支持同时考虑**时间域与频域**的步态解释；2）**Meta Feature Selector**，把这些 token 转换为**结构化表征（Structured Representations）**；3）**Hybrid Context Constructor**，为 in-context learning 确定**最优的示例式（demonstration-based）提示词**。作者在一家**认证步态实验室**采集的数据上评估 MotionDecipher，涵盖 **122 名患者**与 **46 名对照**。结果显示 MotionDecipher 达到 **0.91 的 BERTScore**（比 **GPT-5 高 13%**），而在**专家评估**中，MotionDecipher 在**正确性（Correctness）、完整性（Completeness）与简洁性（Conciseness）**三项上均**排名最高**，优于各基线，表明其在提升步态分析效率方面具有潜力。

## 🎯 核心贡献

1. **MotionDecipher 框架**：系统性地弥合"连续人体运动信号"与"临床步态文字描述"之间的语义鸿沟，把过去依赖专家手工的报告撰写转成可自动化的 LLM 辅助流程。
2. **Human Motion Tokenizer**：领域专用的运动 tokenization 机制，同时编码**时间域**（关节角度/受力的时序）与**频域**（步态周期、步频等频谱特征）信息——这是普通文本 tokenizer 缺失的部分。
3. **Meta Feature Selector**：把离散运动 token 聚合成**结构化表征**，降低噪声与维度，使后续 LLM 推理的上下文更紧凑、更有语义组织。
4. **Hybrid Context Constructor**：自动为 ICL 选择**最优示例式提示**（挑选哪些 demonstration、如何排布），把提示构造从人工经验变成可优化环节。
5. **临床级实证**：在真实认证步态实验室数据（122 患者 + 46 对照）上取得 0.91 BERTScore（超 GPT-5 13%），并在专家盲评的正确性/完整性/简洁性三项上均排名第一。

## 🔧 方法/架构

- **整体三段式流水线**：运动信号 → 领域 token → 结构化表征 → ICL 提示 → LLM 生成的临床报告。

```math
\text{Motion signals} \xrightarrow{\ \text{Human Motion Tokenizer}\ } \text{domain tokens}
\xrightarrow{\ \text{Meta Feature Selector}\ } \text{structured representation}
\xrightarrow{\ \text{Hybrid Context Constructor}\ } \text{ICL prompt} \xrightarrow{\ \text{LLM}\ } \text{clinical report}
```

- **Human Motion Tokenizer**：为**时域**（关节角度序列、力曲线）与**频域**（步态周期/步频/谐波成分）分别设计 token 表征，使 LLM 接收到的输入不再是裸数字序列，而是带有步态领域语义的 token。
- **Meta Feature Selector**：从 token 集合中筛选/聚合出关键结构化特征（对应临床报告要回答的关键问题，如关节活动受限、对称性异常、步态周期特征），降低上下文规模。
- **Hybrid Context Constructor**：混合式（hybrid）地组织 ICL 上下文——同时包含（a）精选的历史病例 demonstration，（b）当前待解释病例的结构化特征，从而在 few-shot 提示中最大化示例的诊断相关性。
- **输出**：结构化的临床步态描述文本（关节运动描述 + 力描述）。

## 📊 实验结果

- **数据集**：来自**认证步态实验室**的自采数据，**122 名患者 + 46 名对照**（共 168 人）。
- **基线**：**GPT-5**（通用最强模型直接处理运动上下文）及其他基线（摘要未逐一列出）。
- **结果**：
  - **BERTScore 0.91**，比 **GPT-5 高 13%**。
  - **专家评估**：MotionDecipher 在 **Correctness、Completeness、Conciseness** 三项上**均排名最高**（优于全部基线）。
- 摘要未给出各基线的逐项 BERTScore 分解、专家评估的评分量表/样本量与显著性检验数值（详见原文 2 张表格）。

## ⚠️ 局限性

- **单中心数据**：仅一家认证步态实验室的 168 人数据，**跨机构/跨设备（不同步态分析系统、传感器标定）的泛化性未验证**。
- **运动模态特殊性强**：Human Motion Tokenizer 针对步态运动信号定制，迁移到其他生理信号（心电、肌电）需重新设计 tokenizer。
- **专家评估细节缺失**：摘要未说明专家人数、盲评协议、评分量表与统计显著性，"三项均排名第一"缺少数值支撑。
- **BERTScore 的适用性**：BERTScore 度量的是与参考文本的**语义相似度**，而临床报告存在多种等价写法，该指标可能高估质量或对"正确但措辞不同"的报告惩罚不足。
- **依赖 LLM 生成最终报告**，幻觉风险未在摘要中量化；虽为 IMWUT 期刊论文，但摘要未提及事实性/安全性验证环节。
- 缺少与**传统自动化步态分析工具/报告模板系统**的对比，无法完全量化"相对专家手工"的效率增益幅度。

## 💡 建议

- 是否推荐使用：**是**（把"领域专用 tokenization + 结构化上下文 + ICL 提示构造"这套组合迁移到其他连续生理信号/工业信号解读任务的参考价值高）
- 适用场景：临床步态、运动损伤、康复评估的自动化报告生成；将专家的例行描述性报告工作转为人机协作；需要领域专用 tokenizer 的垂直信号-文本任务；作为"上下文化 ICL + 领域 token"的架构模板。
