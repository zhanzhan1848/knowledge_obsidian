# FlashOffloading: Low-Latency KV Cache Offloading for Long-Context LLM Serving

## 摘要
LLM 服务中 **KV cache 随序列长度与并发线性增长**，长上下文推理很容易撞上 **HBM 容量墙**，导致并发低下。把 KV cache **卸载到主机 DRAM** 可释放 HBM 空间、提升并发，但额外的**缓存管理**与**主机到设备（H2D）加载开销**会抬高推理延迟 —— **更高并发无法转化为有效吞吐**。本文提出 **FlashOffloading** —— 一个以**主机 DRAM 为中心**的推理架构，在 **prefill 与 decode 两个阶段都完全卸载 KV cache**。它构建 **rolling HBM cache** 用于 prefill、**hot cache** 用于 decode、一个**反向稀疏索引（reverse sparse index）**（零额外 miss-lookup 开销），以及一个**计算-加载重叠内核（compute-load overlapped kernel）**，在整个流水线中优化 KV 卸载延迟，并在 **TPOT（time-per-output-token）SLO** 下交付吞吐增益。实验在 **Ascend910C** PD 分离平台上部署 **GLM-5.2 + MTP3 推测解码**。

## 核心贡献
1. 指出 KV 卸载的核心悖论：**释放 HBM 提升并发，但缓存管理与 H2D 加载开销抬高延迟** → 高并发不转化为有效吞吐
2. 提出 **FlashOffloading** —— 主机 DRAM 中心架构，**prefill 与 decode 两阶段完全卸载**
3. 四件工程组件：**rolling HBM cache**（prefill）、**hot cache**（decode）、**反向稀疏索引**（零额外 miss-lookup 开销）、**计算-加载重叠内核**
4. 在 **TPOT SLO** 下交付吞吐增益（而非只报并发数）

## 方法与架构
**架构组件**：
1. **rolling HBM cache** —— prefill 阶段的滚动 HBM 缓存；
2. **hot cache** —— decode 阶段的热缓存；
3. **reverse sparse index** —— 反向稀疏索引，**零额外 miss-lookup 开销**；
4. **compute-load overlapped kernel** —— 计算与加载重叠内核。

**SLO 口径**：以 **TPOT（time-per-output-token）** 衡量，而非延迟或并发数。

**部署环境**：**Ascend910C** prefill-decode (PD) **分离**平台，**GLM-5.2** + **MTP3 推测解码**。

## 实验结果
- **FlashOffloading** 在 prefill + decode 全阶段完全卸载 KV cache
- 在 **TPOT SLO** 约束下获得吞吐增益（摘要截断具体数字）
- 实测平台：Ascend910C PD 分离 + GLM-5.2 + MTP3

## 局限性
- 依赖**主机 DRAM 容量与带宽**，DRAM 受限时收益递减；
- 未在 NVIDIA GPU 上验证（Ascend 平台特有），跨厂商可移植性未知；
- 「零额外 miss-lookup 开销」的代价体现在索引构建/维护开销上，摘要未细分。

## 值得注意的点
**用 TPOT SLO 而非并发数作为指标**是这个设计的正确之处 —— 也呼应昨日 MEMENTO 的「以 1/50 成本击败 GPT-5.5 agent」：**只有把成本约束写进指标，「更高并发」才不会变成自欺欺人的数字**。
