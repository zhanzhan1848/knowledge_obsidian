# ACSeL: Adaptive Configuration Search for Hardware-Constrained LLM Inference

## 摘要
在内存与延迟 SLO 约束下服务 LLM（含边缘设备），需要**联合选择模型规模、批大小、量化算法与混合精度配方** —— 这个组合空间大到穷举不可行。与数据中心服务（往往优先吞吐或生成速度）不同，**资源受限部署通常把内存与延迟设为约束，再在可行解中寻找生成质量最高者**。本文提出 **ACSeL**：一个识别「预测满足部署约束且预测生成质量高」之配置的框架。为高效估计质量，使用 **RMQD（Relative Model Quality Degradation）** —— 基于候选模型与参考模型在**小校准语料上的 next-token 分布差异**的代理指标。在被评测的各模型规模与精度上，**RMQD 评估廉价且与下游基准表现强相关**。ACSeL 结合 (i) 轻量的配置空间剪枝 与 (ii) 在可行配置中对质量做更精细的筛选。

## 核心贡献
1. 把边缘/资源受限 LLM 服务形式化为**约束满足 + 可行解中最大化质量**（区别于数据中心的吞吐优先）
2. 提出 **RMQD（Relative Model Quality Degradation）** —— 基于 next-token 分布差异的廉价质量代理，与下游基准**强相关**
3. 提出 **ACSeL** 框架：识别预测满足部署约束的配置，并在可行集中按预测质量排序
4. 组合 (i) 轻量配置空间剪枝 与 (ii) 质量导向的精细筛选，避免组合爆炸

## 方法与架构
**问题**：
```math
\max_{\text{config}} \ Q(\text{config})
\quad\text{s.t.}\quad
\text{Memory} \le M,\ \ \text{Latency} \le L
```
配置空间维度：模型规模 × 批大小 × 量化算法 × 混合精度配方。

**RMQD 代理**：
```math
\text{RMQD}(c, r) = \mathrm{div}\big( p_c(\cdot \mid x),\ p_r(\cdot \mid x) \big),
\quad x \sim \text{small calibration corpus}
```
即候选配置与参考模型的 next-token 分布散度。

**ACSeL 两阶段**：(i) 轻量剪枝配置空间 → (ii) 在可行配置中按预测质量精细筛选。

## 实验结果
- **RMQD 评估廉价，且与下游基准表现强相关**（在各模型规模与精度上验证）
- ACSeL 能识别满足内存/延迟约束且质量最高的配置

## 局限性
- 代理指标与下游基准的「强相关」是相关性而非等价，分布外模型可能失效；
- 依赖参考模型（reference model）的选择质量 —— 参考差则代理差；
- 校准语料的代表性决定泛化，上下文相关的质量漂移未讨论。

## 值得注意的点
**RMQD 的设计逻辑值得借鉴**：不跑下游 benchmark，而是**比较 next-token 分布** —— 这把「质量」从不可约的任务依赖量，转成了可复用的分布距离。对于需要频繁做模型/精度选型的团队，这个代理的性价比可能远高于反复跑全套评测。
