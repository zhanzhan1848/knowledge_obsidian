## 核心贡献
1. **给出核心判据**：一个 activation steering edit 应当依赖输入，**当且仅当目标点在"查询所请求的类"内部变化**（the destination varies *inside* the class a query requests）。这个条件**在任何规则被拟合或应用之前就可测量**。
2. **把 CAA、class-conditional CAA 与 per-query 检索统一为一个家族**（RGS，Retrieval-based Steering）：$k$ 控制编辑的局部性，从而控制检索到的目标点与理想 per-query 方向的接近程度。$k = |D^c|$（类大小）时，检索规则**恰好等于** class-conditional 差分均值；$k=1$ 时是移植单个存储状态。两个固定规则是该家族的两个端点。
3. **实验结论**：在两个模型、六个替换语料库的**每一层**上，**per-query 检索都优于固定方向 steering**（当目标点在类内变化时）。所需输入依赖程度反过来决定了怎么用：**词级编辑应在网络前 1/10 深处、从少数邻居检索；子句级编辑可在任意深度、从类均值施加**。
4. **"类已决定答案"的情形**：类均值已足够，检索只能与之持平，而**固定方向在那种情形下仍然失败**——即固定方向在两种情形下都不占优。
5. **提出四个仅从状态计算的诊断量**，用于识别编辑应当施加的"regime"：标准化位移 $D$、全局共享比例 $g$、残差 $R$、检索对齐度 $A$（以 $1-A$ 报告以与 $E$ 同单位）。
6. **用构造性的二维几何数据集给出"正确答案先验已知"的失败演示**：THREE-MODE（类间偏移旋转，CAA 向量按构造为零，而类内差分均值精确）、CONCENTRIC（各 query 沿各自角度向外，类内位移也相消，固定规则无可估计量）、HIERARCHICAL（类嵌套于簇中，所需位移依赖 query 所在簇：所需映射的线性部分跨簇共享但截距不共享）。另有 SHARED-OFFSET 对照只变 globality。

## 问题背景

Activation steering 用一个选定的向量扰动 hidden state 以诱导某种行为。**CAA（Contrastive Activation Addition）** 收集表现出该行为的 prompt 与不表现出该行为的 prompt 的状态，把它们的均值差加到**每一个**输入上。这隐含假设：**一个位移描述了所有输入的编辑**。该假设在所需编辑依赖输入内容时失效：把一个句子 steer 向"下一个星期几"对 Monday 与 Thursday 提出的要求不同；而把 king→queen 的概念从男性改为女性则不需要。

有两种修复方案，而它们其实是同一规则在不同设置下的表现：**条件化于目标类**的差分均值给出每类一个向量（而非全语料一个）；**检索**则给出每 query 一个目标点——在一批已表现出目标行为的状态中搜索，steer 向 $k$ 个最近者的均值。

这一权衡是任务依赖的，而且**可以在任何规则被拟合之前被定量刻画**。每条规则形式相同（每 query 一个方向乘一个在留出数据上选定的标量），因此可以**提前**用"其方向与任务所需编辑的一致程度"来打分。

## 方法

### 1. Steering 规则的形式化

设 $D$ 为目标状态库（datastore），$S$ 为源状态集合。每条规则表现为它所添加的位移：

$$\delta_{\text{CAA}}(h) = \alpha\big(\text{mean}(D) - \text{mean}(S)\big), \qquad \delta_{\text{RGS}}(h) = \alpha\big(\mu_k(h) - h\big), \qquad \mu_k(h) = \frac{1}{k} \sum_{x \in N_k(h)} x$$

其中 $N_k(h)$ 是 $D$ 中按欧氏距离最近的 $k$ 个元素。搜索**仅限于目标状态**，条目不与任何源状态链接。$\alpha$ 为权重位移的标量。$\alpha$ 与 $k$ 在验证集上选定，测试时原样使用。

**class-conditional CAA** 是式 (1) 的差分均值取在类内部：$\alpha(\text{mean}(D^c) - \text{mean}(S^{c'}))$，给出每类一个向量而非全语料一个。

**关键等价（§3.1.1）**：把搜索限制在类 $c$ 并取 $k = |D^c|$，则 $\mu_k(h) = \text{mean}(D^c)$，于是

$$\delta_{\text{RGS}}(h)\big|_{k=|D^c|} = \alpha\big(\text{mean}(D^c) - h\big), \qquad \delta_{\text{class-conditional CAA}}(h) = \alpha\big(\text{mean}(D^c) - \text{mean}(S^{c'})\big)$$

由于 $\mathbb{E}[h] = \text{mean}(S^{c'})$，**两者在期望上一致**：class-conditional CAA 从源类质心瞄准目标类质心，RGS 从 query 瞄准。因此"所选的 $k$ 本身就报告了哪条规则胜出"。

论文另考虑一个**拟合的仿射映射**（需要对齐的配对数据），作为比较的天花板报告——固定规则得不到这种配对信息。

### 2. 语料库家族（五族）

**(a) 六个替换语料库**（每个只变一个属性，其余固定）：每个语料在每个类中把源 span 与目标 span 配对，在同一句框架中渲染两者并读最后一个 token 的状态，因此源与参考仅差一个属性。四个**词级**：LEXICON（英语名词→法语/德语/西语等价词，源与目标词表**不相交**）、TENSE（不规则动词→过去式/进行式/第三人称）、REGISTER（中性词→正式或随意同义词）、CASING（大小写变换，**理论对照**：每个 query 需要相同编辑）。两个**子句级**：SENTIMENT（中性子句→正面或负面；**唯一**源与参考是两个不同子句而非同句改 span 的语料）、CERTAINTY（断言或模糊化一个命题，两种渲染以同一词结尾）。

**(b) 两个 token 语料库**：**Weekday advancement**（把句子中的某天 steer 向"下一天"，1,200 模板 × 7 天）。源与目标集是**同一批状态的置换**，故 $\text{mean}(D) = \text{mean}(S)$，CAA 的向量**按恒等式为零**而非估计误差——各天质心近乎等距而非成环，故每天需要不同的步长。**Country-to-capital**（steer 向首都，20 个国家/首都对 × 40 框架 × 12 主语）。

**(c) 两个 A/B 行为基准**：Perez et al. (2022) 的 sycophancy 与 corrigibility，每个 item 给一个问题与两个答案，其中一个表现出该行为。**不提供 per-query 参考**（两状态主要差在选了哪个答案），故 reference error 与 identity 未定义，用 forced choice 评分。

**(d) 外部基准 COUNTERFACT**（Meng et al., 2022）：按其自身文献的方式打分——要求 subject-relation prompt 以新 object 结尾；状态库是基准自带的属性 prompts 与已带该 object 的其他 subject 的状态；分数是其 efficacy measure（编辑后模型偏好新 object 而非真实 object 的案例比例）。

**(e) 生成的构造数据集**：四个二维数据集，各自构造以演示固定规则的失败，因此**每条规则的正确分数在它运行前就已知**。CAA 把类均值差加到每个 query，故它能提供的只有每个 query 共享的部分（其向量是 $\mathbb{E}[d]$，必然留下的是 $d$ 关于均值的散布）。THREE-MODE 旋转三个簇的偏移，使所需位移跨类相消，CAA 留下零向量，而同样在类内取的差分均值是精确的；SHARED-OFFSET 对照只变 globality，使任务对 CAA 可解。CONCENTRIC 把类放在环上、各 query 沿自己的角度向外，径向向量在环上平均为零，故位移**类内也相消**，class-conditional CAA 也无可估计量，且两个环比例无法由一个线性映射服务。HIERARCHICAL 把每个类放在每个簇内并给每个簇自己的旋转，使一个类所需的位移依赖 query 所在簇。

### 3. 语料切分与交叉验证

除 A/B 基准外，所有语料提供 **per-query 参考**（若正确编辑已做出，模型本应产生的状态），这使 reference error 与 per-item identity 可计算。语料**按 frame 切分**，保证没有 frame 同时出现在拟合规则的训练对与评估 query 中，steering 结果做**四折交叉验证**。参考误差按**整个语料的所需步长**归一化（而非每折的），因此未 steer 的分数读作 1.000 ± 0.073 而非恰好 1。

### 4. 四个诊断量

在运行任何规则之前计算：

- **标准化位移** $D = \sqrt{\mathbb{E}\|d\|^2 / \mathbb{E}\|x - \bar{x}\|^2}$：状态必须移动多远（以状态自身离散度为单位）
- **全局共享比例** $g = \|\mathbb{E}[d]\| / \mathbb{E}\|d\|$：per-sample 位移 $d_i = r_i - h_i$ 是否同向
- **残差** $R = \sqrt{\mathbb{E}\|d - \bar{d}\|^2 / \mathbb{E}\|x - \bar{x}\|^2}$：任何单一向量都提供不了的编辑部分
- **检索对齐度** $A$：最优检索位移与真实位移的一致程度，以 $1-A$ 报告以与 $E$ 同单位

$D$、$g$、$R$ 只需要配对；$A$ 还需要类标签与状态库——因此**每一个都比它所筛查的规则需要更多监督**（$R$ 需 6 对，$g$ 需数千，$A$ 需数百）。

## 实验结果

- **Dataset/Task**: 五族语料——6 个替换语料库（LEXICON / TENSE / REGISTER / CASING / SENTIMENT / CERTAINTY）、2 个 token 语料库（Weekday advancement 1200 模板 × 7 天；Country-to-capital 20 对 × 40 框架 × 12 主语）、2 个 A/B 行为基准（sycophancy、corrigibility）、4 个生成构造数据集（THREE-MODE / CONCENTRIC / HIERARCHICAL / SHARED-OFFSET）、1 个外部基准（COUNTERFACT）。两个模型。四折交叉验证。

- **Main results**:
  - **构造数据集（正确答案已知）**：THREE-MODE 上 CAA 的 $E = 1.00$（= 不动输入的分数，即完全失败），class-conditional CAA 的 $E = 0.00$（精确），RGS 的 $E = 0.20$。CONCENTRIC 上 CAA $E = 1.00$（失败）、class-conditional CAA $E = 1.01$（失败，甚至略差）、RGS $E = 0.09$。**只有 per-query 的目标点在两种构造下都存活。**
  - **主结论**：**在两个模型、六个替换语料库的每一层上，检索都优于固定方向 steering**（当目标点在类内变化时）。
  - **概念层级决定施加方式**：**词级编辑**（LEXICON / TENSE / REGISTER / CASING）最好在**网络前 1/10 深处**、从**少数邻居**（小 $k$）检索；**子句级编辑**（SENTIMENT / CERTAINTY）可在**任意深度**、从**类均值**（大 $k$）施加。
  - **类已决定答案的情形**：类均值足够，检索只能与之持平（而非超越），但**固定方向在那种情形下仍然失败**。
  - **诊断量**：四个量（$D$, $g$, $R$, $1-A$）与规则后续的得分做相关，据此给出"该在哪个 regime 施加编辑"的判定。

- **Ablations**: (1) $k$ 的扫描（局部性 ↔ 检索目标接近理想 per-query 方向的程度）；(2) 施加深度的扫描（层位置 × 概念层级）；(3) 状态库覆盖率（bank coverage）；(4) 四类规则的对比：CAA、class-conditional CAA、RGS、拟合仿射映射（天花板）；(5) 诊断量与规则得分的一致性检验。

## 关键洞察

1. **"编辑应当依赖输入"的判据是"目标点是否在类内变化"，而不是"任务是否多义"**。这比"任务看起来复杂"精细得多：CERTAINTY（断言 vs 模糊）虽然是子句级，但若在类内变化小则类均值足够；而 CASING 是理论对照（每个 query 需同一编辑），按判据应当用固定方向——而固定方向恰好在那儿能work。判据的可测量性（只需状态，无需拟合）是本文最大的实用价值。
2. **概念层级（词 vs 子句）不是任务的表层属性，而是"所需的编辑在表示空间中如何局部化"的代理**：词级编辑在浅层就完成、且只依赖少数邻居（说明词级语义在浅层已线性可分）；子句级编辑需要更深的表示，但一旦到达那里类均值就够用。这为"steering 施加在哪些层"提供了基于任务结构的先验，而非纯网格搜索。
3. **THE MODE / CONCENTRIC 构造揭示了固定方向方法的一个共同盲点**：CAA 的向量是 $\mathbb{E}[d]$，它只能表达每个 query 共享的那部分编辑——**类间相消**（THREE-MODE）与**类内相消**（CONCENTRIC）两种情形下它都归零。而这**不是估计误差**，是构造使然。这个区分很重要：换更多数据、更多采样都不会修复它。
4. **固定方向在两种 regime 下都不占优**：目标在类内变化时它错（CONCENTRIC），类已决定答案时它也错（论文明确指出 fixed direction 仍然失败，而类均值可用）。这意味着 CAA 类方法的适用范围比通常假设的窄得多。
5. **"检索 vs 类均值"是关于监督预算的连续权衡**：$k$ 从 1（移植单个状态）到 $|D^c|$（类均值）连续过渡，而 $k$ 的选择由任务的概念层级决定，且这个选择规则在**两个模型、全部六个语料库、每一层**上都成立——跨模型、跨层的稳定性是很少见的强证据。
6. **诊断量的"监督阶梯"是一个反直觉但重要的事实**：用来筛查规则的量（D、g、R、1-A）本身需要**比规则更多**的监督（配对、类标签、大量状态）。因此它们**不是实用的在线工具**，而是在决定是否值得投入采集这些监督前的离线筛查器。

## 局限性

- **诊断量需要比被筛查规则更多的监督**，因此其实用性受限——作者的定位是"离线筛查"，但离线筛查也需先付出监督成本。
- **状态库（datastore）的覆盖度**被列为影响规则选择的因素之一，但摘要与主体未给出定量的覆盖度—性能曲线。
- **仅两个模型**，且论文未在摘要中指明是哪些模型；跨模型泛化虽被声称但证据来自两个点。
- **"first tenth of the network"是一个粗粒度结论**（层的划分为前 10%），没有给出更精细的层级定位方法。
- **A/B 行为基准（sycophancy、corrigibility）没有 per-query 参考**，因此只能 forced choice 评分，与其他语料的 reference error 不可直接比较——跨基准的结论统一性受限。
- **COUNTERFACT 只按其自身协议打分**，protocol 与其他语料不同（efficacy measure 而非 reference error），结果不严格可比。
- **生成构造数据集是二维且答案已知的合成数据**，虽然便于归因，但与真实高维表示空间的经验性质可能相差甚远。
- **未评估 steering 之后的副作用**：更激进的 per-query 编辑（更大 $k$ 变化或更深层施加）是否损害无关能力，本文只报告目标任务得分，未做能力保持评测。
- **"类已决定答案"的情形下检索"只能与之持平"**说明该情形下 per-query 检索无额外收益——但论文未给出可在实践中识别该情形的判据（除了那四个需要额外监督的诊断量）。
- **未与依赖感知的 steering（如基于 attention 的方向选择）比较**，所有固定规则的比较都在 CAA 家族内部。

## 适用场景

**适用**：
- 需要判断"我的 steering 任务该不该做 input-dependent 编辑"的研究者与工程师：判据与四个诊断量直接可用。
- 词级与子句级编辑的层级选择：词级 → 浅层 + 小 $k$；子句级 → 任意深度 + 类均值。
- 寻求 CAA 之外的 steering 规则的实践者：RGS 是一个即插即用的替代，只需一个目标状态库。
- 构造并证伪"某个 steering 假设"的实验设计：THREE-MODE / CONCENTRIC / HIERARCHICAL 是现成的、正确答案先验已知的诊断构造。

**不适用**：
- 需要诊断量而无法提供配对/类标签/大状态库的实践场景（诊断量在此不可用）。
- 大规模模型部署的 steering（论文只测两个模型，状态库规模与检索开销未评估）。
- 涉及能力保持要求的生产场景（未做副作用评估）。
- 闭源 API 模型（需要访问 hidden states）。
