## 核心贡献

> Bank-World 揭示 agent 的「决策-执行断层」：正确决策常常无法转化为完成的工作。

1. 提出 Bank-World：覆盖两家模拟机构的 50 个银行任务基准，把「正确决策」与「完成工作」区分开 —— 真正的考验是对账、取得授权、执行交易，并在情况变化时保持指令与状态报告一致。
2. 支持单轮任务与多轮交互（含模拟员工提供信息、批准动作、修改指令），评分结合对已记录动作与状态的**可执行检查**与对任务要求的模型判定。
3. 在 4 个模型 1,600 次尝试中发现核心现象：**正确的决策常常无法转化为完成的工作** —— 重复收取费用、把正确总额错误分配给多个收款人、在审批未通过时执行支付。

## 技术方案

### 核心思想

现有 agent 基准大多在「给出正确答案」的维度上评测。但真实业务工作的完成标准远不止于此：银行任务要求 agent 对账、获得许可、执行交易，并在条件变化时让指令与状态报告保持一致。

Bank-World 的评测哲学因此是**双轨的**：一部分是可直接执行验证的动作与状态检查（executable checks），另一部分是对「是否满足任务要求」的模型判定，并且明确允许有效的替代解法被判为通过。这个组合在设计上很谨慎 —— 纯模型判定会惩罚多样化的正确路径，纯规则检查又覆盖不了软性要求。

论文最核心的发现是一个**决策-执行断层**：correct decisions often fail to become completed work。具体表现为三类：重复收取费用（charge fees twice）、把正确总额以错误的金额分配给多个收款人、以及**在审批仍处于 pending 状态时就执行支付**。第三类尤其值得注意 —— 它是一个纯粹的流程违规，而模型的「决策」看起来是对的。

不同模型的能力画像也不同：Sol 在单轮完成度上领先，Opus 的多轮完成率最高，而 Grok 能在更多多轮任务上取得成功但稳定性较差。论文保留了任务环境，并提供任务 ID 映射、奖励规格与单轮检查-授权映射等辅助文件。

### 关键技术

| 技术 | 说明 |
|------|------|
| 双轨评分 | 可执行的动作/状态检查 + 对任务要求的模型判定，并显式支持有效替代解 |
| 两机构模拟环境 | 50 个任务覆盖两家模拟银行，含状态化流程与权限系统 |
| 多轮模拟员工 | 模拟员工提供信息、批准动作、修改指令，制造真实的状态转移 |
| 决策-执行断层诊断 | 区分「决策正确」与「工作完成」，并对失败类型做结构化归类 |
| 任务级可检查性 | 提供任务 ID 映射、奖励规格、check-authority 映射，使失败可复现分析 |

## 实验结论

- **数据集**: Bank-World：2 家模拟机构、50 个银行任务
- **基线**: 4 个前沿模型的 agent 尝试，1,600 次尝试
- **结果**: 正确决策常无法转化为完成工作。典型失败：重复收费、把正确总额以错误金额分配给多收款人、在审批未通过时执行支付。单轮完成度以 Sol 领先，多轮完成率以 Opus 最高，Grok 覆盖更多多轮任务但一致性较差。

- **决策 ≠ 完成** 是本文最可迁移的评测理念 —— 很多 agent 榜单衡量的其实是前者。
- 「审批 pending 时执行支付」是一类纯粹的流程违规，与决策正确性无关，必须靠状态检查而非模型判定来捕获。
- 评分同时支持有效替代解，说明作者意识到过度刚性的评测会惩罚多样化的正确解法。
- 1,600 次尝试 × 4 模型的规模，配合任务级结果与 worked example，使结论可检查。
- 模型的强项分化明显（Sol 单轮 / Opus 多轮 / Grok 广度）—— 单看总分会掩盖这些差异。

## 局限性

['模拟银行环境与真实金融系统的差距（合规、异常处理、系统集成）较大。', '评分仍包含模型判定成分，其可靠性受 judge 质量制约。', '仅 50 个任务，任务选择的代表性可能不足。', '论文未给出针对这些失败模式的修复方案。']

## 实现建议

- **实现难度**: 中（需搭建状态化的银行模拟环境与权限/状态检查器）
- **适用场景**: Agent 评测基准设计、业务流程 agent 的上线前验证、工具调用正确性评估
- **建议**: **评测 agent 时一定要把「决策正确」与「任务完成」分成两个指标** —— 这篇论文显示二者的差距足以掩盖严重的流程违规（尤其在有审批门禁的场景）。评分器里必须包含对状态的检查，不能只有模型判定。

## 原始摘要

```
Bank-World is a benchmark of 50 banking tasks across two simulated institutions. Completing banking work requires more than producing the right calculation: agents must reconcile records, obtain permission, execute transactions, and keep instructions and status reports consistent as circumstances change. Bank-World tests these requirements through single-turn assignments and multi-turn interactions with simulated employees who supply information, approve actions, and revise instructions. Grading combines executable checks of recorded actions and state with model judgments of task requirements, including whether valid alternative solutions satisfy them. Across 1,600 attempts by four models, we find that correct decisions often fail to become completed work. Agents charge fees twice, distribute the correct total in incorrect amounts among the recipients, and execute payments while approval is pending. Their strengths also differ: Sol leads single-turn completion, Opus has the highest observed multi-turn completion rate, and Grok succeeds across more multi-turn tasks but less consistently. Bank-World makes these differences inspectable through task-level results and worked examples connecting source evidence, agent decisions, and simulated consequences. We retain the task environments, executable graders, and full trajectories privately to reduce contamination and preserve the benchmark for future evaluations.
```
