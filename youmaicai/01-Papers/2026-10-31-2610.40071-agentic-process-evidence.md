## 技术方案

### 核心思想

The way software gets built is changing dramatically. AI agents now create pull requests, select
dependencies, refactor codebases, interpret test failures, and execute infrastructure changes across
the entire Software Development Life Cycle (SDLC). AI agents are autonomous team members, but unlike
human engineers, they are ephemeral - their reasoning, decisions, and tool calls vanish the moment
the session ends. Modern Security incidents involving intent mismatch or injection are becoming
increasingly common - forcing us to address AI Agents as an insider threat. No widely adopted
standard yet enables agentic provenance and governance and its obvious that you can't hold an
ephemeral process accountable. The git log was designed for human commits. It shows what changed. It
does not show what an AI agent did, which model it used, which tools it called, or whether anyone
was accountable for the outcome. Every governance framework, every audit trail, every compliance
control in the SDLC was built around one assumption: a human made the decision. That assumption no
longer holds. This shift introduces 3 main procedural problems (not addressing scale) - Supply-chain
vector - The agentic coder is software, so it is a supply-chain security risk. Policy guardrails -
How to ensure the agentic coder is compliant with the policies of the organization. Task-alignment -
How to align the agentic coder on its tasks and goals. We introduce Agentic Process Evidence (APE),
a signed, tamper-evident, machine-readable attestation of agentic processes, linking the sessions to
their outcome (process-aware logging). APE enables Policy-as-Code control over the agentic
processes, allowing for human in the loop only when it's needed. We support the in-toto style
attestation framework, and the protocol is aligned with the relevant regulations
