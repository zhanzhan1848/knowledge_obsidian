# SecureGARD: Dynamic Ontology-Guided Governance for Secure Tool-Using LLM Agents

> **arXiv**: [2611.06682](https://arxiv.org/abs/2611.06682)
> **发表日期**: 2026-11-04
> **分类**: cs.LG
> **会议/期刊**: arXiv preprint

## 📋 摘要

使用工具的 LLM agent 会把模型输出转化为有实际后果的行动，从而使间接 prompt injection 演变为一个执行层（execution-security）问题。现有防御手段主要约束工具调用、轨迹或信息流，但往往把动作语义、状态依赖与证据关系留作隐式表达，限制了跨异构工具的泛化能力，也让安全更新变得复杂。本文提出 SecureGARD：一个动态本体引导的治理框架，把异构调用锚定到共享的语义表示上，并将可执行本体（executable ontology）与 episode 级别的任务状态结合，推导出确定性的 ready / waiting / forbidden 三类决策。其中 waiting 决策标识出"尚未满足但可恢复"的义务，从而在不扩大 agent 授权边界的前提下支持有界重规划（bounded replanning）。SecureGARD 的本体在离线阶段从已验证的训练执行轨迹中演化而来：离线 LLM 提出与具体实例无关的 action–state 公理，这些公理只有在能回应训练失败暴露出的本体错误、保持逻辑一致性与受保护的蕴含关系、并通过留出集验证后才会被接受，随后本体被冻结。实验在 AgentDojo、ASB、AgentDyn 三个基准的良性设定与间接 prompt injection 设定下进行。

## 🎯 核心贡献

1. 提出 **SecureGARD** 动态本体治理框架：首次将异构工具调用统一锚定在共享语义表示上，用"可执行本体 + episode 级任务状态"做确定性授权判定，而非仅做调用/轨迹/信息流的粗粒度拦截。
2. 引入 **三态决策语义**（ready / waiting / forbidden）：waiting 表示"义务未满足但可恢复"，使得 agent 可以在不扩大授权边界的前提下进行有界重规划，兼顾安全与效用。
3. 提出 **本体离线演化机制**：离线 LLM 生成与实例无关的 action–state 公理，但必须同时满足"修复训练失败暴露的本体错误""保持逻辑一致性与受保护蕴含""通过留出集验证"三道门槛才被冻结，形成可控的安全更新路径。
4. 在 AgentDojo / ASB / AgentDyn 三个基准上同时验证攻击抑制与良性效用保持，取得 0% ASR。

## 🔧 方法/架构

整体为"语义层治理 + 状态层守卫 + 离线本体演化"三段式：

- **共享语义表示（grounding）**：将异构工具调用映射到统一的动作/状态本体空间，使跨工具的语义可比。
- **可执行本体（executable ontology）**：以 action–state 公理形式显式表达动作语义、状态依赖与证据关系，取代隐式约束。
- **episode 级任务状态**：记录当前 episode 的义务履行情况，用于与本体联合推理。
- **确定性决策器**：由本体与任务状态联合推导 `ready` / `waiting` / `forbidden`：

```math
D(a, s) \in \{\texttt{ready},\ \texttt{waiting},\ \texttt{forbidden}\}
```

  - `ready`：允许执行；
  - `waiting`：义务未满足但可通过重规划恢复 → 触发 bounded replanning，授权边界不扩张；
  - `forbidden`：违反本体/受保护蕴含 → 硬阻断。
- **离线本体演化（governance update）**：离线 LLM 提出 action–state 公理 $\mathcal{A}$，接受条件为：

```math
\text{accept}(a) \iff \text{fixes\_ontology\_error}(a) \wedge \text{logically\_consistent}(a) \wedge \text{preserves\_entailments}(a) \wedge \text{passes\_holdout}(a)
```

  通过后本体冻结（freeze），运行期不再在线改动治理规则。

## 📊 实验结果

- **攻击成功率（ASR）**：在 AgentDojo、ASB、AgentDyn 三个基准的间接 prompt injection 设定下，**ASR = 0%**。
- **任务效用（Task Utility under attack）**：相较现有基线（既有 defenses）在受攻击条件下**有提升**。
- 摘要未披露具体效用数值（详见原文实验章节）；涉及基准为 AgentDojo、ASB、AgentDyn（各含良性设定与间接 prompt injection 设定）。

## ⚠️ 局限性

- 本体演化依赖"已验证的训练执行轨迹"，对冷启动工具集与长尾工具的覆盖可能不足；跨领域迁移性未在摘要中给出证据。
- 0% ASR 仅在三个既有基准（AgentDojo / ASB / AgentDyn）与间接注入威胁模型下成立，对直接注入、跨会话/跨 episode 攻击、以及非工具型 agent 的外推性存疑。
- "waiting" 边界依赖义务可恢复性的判定，该判定在开放式任务中可能过于保守或过于宽松。
- 需要额外的 ontology 构建与验证流水线，带来部署与维护开销。
