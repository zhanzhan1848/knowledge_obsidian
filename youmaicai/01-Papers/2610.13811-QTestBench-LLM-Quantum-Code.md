## 核心贡献

> 提出 **QTestBench**：评估 LLM 生成的量子代码**测试套件**（而非解本身）的可信度框架，跨 PennyLane/Qiskit 双框架。

1. **评测对象**: LLM 生成 unit tests 而非 quantum solution
2. **3 cohort validation**: 每个 task 测 syntactic / semantic / behavioral tests 与独立 benchmark checker 的对齐度
3. **关键发现**: 生成测试几乎都能执行，但**区分正确与错误实现**的能力滞后；最佳 generator 在 QHack 上 quality **0.71**

---

## 技术方案

### 核心思想

现有 quantum benchmark 只测"模型能否解出"，不测"模型能否写测试区分对错"。本文引入跨框架 test-benchmark 比较，并用 oracle-verified synthetic mutants 稳定 bug-detection 估计。

### 关键技术

| 技术 | 说明 |
|------|------|
| Syntactic / semantic / behavioral tests | 三类测试分别评估 |
| Independent benchmark checker | 不以 LLM 测试作 ground truth |
| Oracle-verified synthetic mutants | 注入合成错误以稳定估计 |
| 3 cohort validation | 三个 validation cohort 回答不同诊断问题 |

---

## 实验结论

- **数据集**: 8 PennyLane QHack challenges + 10 Qiskit HumanEval tasks
- **模型**: 5 个 LLM
- **结果**:
  - 最佳 generator test quality: **0.71 (QHack)** / **0.34 (Qiskit HumanEval)**
  - Executability 几乎 100%，但 discrimination 远低
  - Synthetic mutants 在 3/10 Qiskit 任务上稳定 bug-detection 估计（自然错误稀缺）

---

## 局限性

- 仅 5 个 LLM，覆盖面有限
- Quantum 测试领域狭窄，迁移性未验证
- Synthetic mutants 与真实 bug 分布的差异未量化

---

## 实现建议

- **实现难度**: 中（需 quantum 模拟器 + benchmark checker）
- **预期性能**: 区分 LLM 的测试生成能力而非解生成能力
- **适用场景**: LLM code generation 评估、quantum software engineering
