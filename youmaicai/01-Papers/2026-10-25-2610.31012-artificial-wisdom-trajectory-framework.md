## 核心贡献

> 提出一个**以轨迹为基础**的"人工智慧（Artificial Wisdom）"测量框架与**前瞻性验证协议**：智慧在行为上被定义为**情境敏感的判断调节**（context-sensitive regulation of judgment），而不是"会做什么"。

1. **行为化的智慧定义**：AW = 情境敏感地调节判断；**能力基准测不了**"当决策条件变化时建议是否仍然恰当"
2. **版本化参考规范（versioned reference specifications）**：在评测**之前**就确定"可接受的回答"与"哪些转变是实质性的"
3. **九分量剖面**：**7 个阶段级准则**（在当前条件下的判断）+ **2 个转变分量**（实质更新充分性 + 承诺保持稳定性）
4. **稳定性以先行充分性为前提**：在已登记的承诺类别内允许切换；**持续犯错不得稳定性分**
5. **瓶颈评分 + 关键失败单列**：九分量剖面为主指标，另有次级 bottleneck score 与独立的 critical-failure 报告
6. **三个简化模拟**检验框架自身性质：精度、瓶颈估计、对模型家族数量的敏感性

## 技术方案

### 核心概念框架

| 概念 | 定义 |
|------|------|
| Artificial Wisdom (AW) | 行为上定义为 **context-sensitive regulation of judgment** —— 判断随条件变化而恰当调整 |
| Versioned reference specification | 版本化的参考规范；确定 admissible responses 与 **transition materiality**（哪些条件变化算实质变化） |
| Commitment class | 已登记的承诺类别；在其中切换**被允许**（不算不稳定） |
| Critical failure | 单列报告的关键失败，不被其他分数稀释 |
| Bottleneck score | 次级指标；识别限制整体表现的**最弱环节** |

### 九分量剖面

| 组 | 组成 | 说明 |
|------|------|------|
| **阶段级准则（7 个）** | current-conditions judgment | 评估模型在**当前**条件下给出的判断是否恰当 |
| **转变分量（2 个）** | ① material-update adequacy | 条件实质变化后，判断更新是否**充分** |
| | ② commitment-preserving stability | 是否在应保持承诺时保持稳定 |

### 关键约束

- **稳定性要求先行充分性**：若当前判断本就不充分，则谈不上"稳定地保持一个坏判断" —— 这排除了"固执地错"被计入稳定性的可能
- **持续错误不获稳定性分**：persistent error earns no stability credit
- **已登记承诺类别内切换允许**：避免把"合理的重新判断"误判为不稳定

### 关键技术

| 技术 | 说明 |
|------|------|
| Trajectory-based measurement | 以**决策轨迹**（而非单点问答）为测量单位 |
| Prospective validation protocol | **前瞻性**验证：先定规范、再评测，而不是事后解释 |
| Versioned reference specifications | 规范本身有版本，保证跨时间/跨运行的判定可审计 |
| Single-criterion precision simulation | 单准则模拟，检验"每领域所需场景数"的精度条件 |
| Incremental-prediction simulation | 检验剖面能否**增量预测**独立决策结果 |
| Predecessor-rubric exploratory study | 前身量表的前瞻性研究（**仅示例聚合敏感性**） |

## 关键实验结果

| 实验 | 结果 |
|------|------|
| 单准则模拟（精度） | 在**每领域 24 个场景**时满足精度条件 |
| 瓶颈估计偏差 | 在瓶颈**接近持平**（tie）时，该规模下估计的最小值有 **0.55 点**的**向下偏差**（downward bias） |
| 增量预测模拟（简化） | 检出 Brier 改进 **0.027**，对应概率 **.508**（**8 个模型家族**）与 **.742**（**12 个模型家族**） |
| 该模拟的效力 | **未确立**其在操作协议上的统计效力（does not establish power for the operational protocol） |
| 前身量表探索性研究 | **71 条评测记录**；仅说明**聚合敏感性**，**未验证**本量表 |
| 家族数量目标 | **12 个家族**的目标**仍是暂定值**（provisional），待可行性评估与完整分析的校准 |
| 开放问题 | 剖面是否能预测**超出能力之外的**独立决策结果，仍是开放的经验问题 |

## 关键结论

1. **能力 ≠ 智慧**。AW 框架测的是"建议在条件变化时是否仍然恰当"，这是能力基准结构上无法覆盖的维度。
2. **稳定性必须以充分性为前提**。这个设计约束避免了最常见的评测陷阱：把"固执地错"当成"有原则的稳定"。
3. **框架本身仍处在早期**：12 家族目标暂定、增量预测模拟未确立效力、前身研究只有 71 条记录。
4. **瓶颈估计在 tie 附近有可量化偏差**（0.55 点向下）—— 使用 bottleneck score 时应注意 tie 区域的不确定性。

## 局限性

- **方法论自述的谨慎程度很高**：作者明确使用了 preliminary / provisional / simplified / exploratory / does not establish / remains an open empirical question 等限定词
- **三个模拟都是"简化"的**：不是真实部署场景的验证
- **未见真实 LLM 评测结果**：摘要只报告模拟与前身研究，**没有**在真实模型上跑九分量剖面的结果
- **增量预测模拟的效力未确立**：Brier 改进 0.027 对应的概率 .508/.742 在 8/12 家族下只接近随机，12 家族下才明显
- **单作者**工作，缺乏独立复现
- **代码/数据未提供**

## 实现建议

- **实现难度**: 中（框架本身是规范性的，但落地需要自建版本化参考规范）
- **适用场景**: 需要评估模型**"结论随情境变化是否仍然恰当"**的团队 —— 例如长期助理的建议更新、决策支持系统
- **适用场景（谨慎）**: **不适合**作为模型选型的当前主指标；更适合作为**研究性诊断维度**
- **落地步骤**:
  1. 先建**版本化参考规范**：明确 admissible responses、commitment classes、什么算 material transition
  2. 设计**轨迹式任务**：同一情境多次评估，中间注入条件变化
  3. 打分时严格区分 **stability（需先行充分性）** 与 **persistent error**
  4. 单独报告 critical failures，不要只看加权总分
- **价值点**: 这是把"上下文敏感性"从零散观测提升为**可版本化、可审计的测量协议**的尝试，与 2026-10-24 日报中"上下文敏感度"主题（Prompt Sensitivity、Invisibilization）形成方法论补充
