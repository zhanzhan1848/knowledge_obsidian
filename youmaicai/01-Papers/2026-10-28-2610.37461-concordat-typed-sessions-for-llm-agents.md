## 核心贡献

> **把「代理必须遵守的规则」从提示词里的软约束，变成运行时强制执行的类型化协议** —— 用 typestate / session types 的思想，让违规调用**在产生副作用之前**就被拒绝。

1. **问题定位**：LLM Agent 越来越多地执行**有后果的动作**（取消预订、退款、改账户），而约束这些动作的规则（如「改动前必须取得客户明确确认」）通常只写在 prompt 里 —— **模型的遵守程度完全取决于模型自己选择遵守**。
2. **提出 Concordat**（Python 库）：
   - 把 Agent 视为**接口即有限状态协议（finite-state protocol）**的对象
   - **每一轮只向模型提供当前协议状态下合法的工具**
   - 协议外的调用**在产生副作用之前被拒绝**
   - 保留给人类决策的环节**只能被「请求」，不能被代替**
   - token 与工具调用预算**线性分摊**到各次交接
3. **协议在定义时即被检查**；Agent 的子类若**可能绕过父类协议**会被拒绝 —— 这是**行为版本的 Liskov 替换原则**。
4. **实证结果（关键）**：
   - 标准 Agent 在 50 个航空任务中，有 **13/50 次在未取得所需「yes」的情况下做出改动**（gpt-4.1）；Claude Haiku 5.5 则是 **29/128 次任务运行**
   - **Concordat Agent：0 次违规**，且**任务成功率无显著差异**
   - **tau-bench 自带的 reward 未能检测出大多数这类违规**

## 技术方案

### 核心思想

「模型是否遵守规则」本质上是个**不可靠的运行时属性**。Concordat 的立场是：**不要问模型，要用类型系统来约束它**。既然规则有状态依赖性（只有在「已确认」之后才能执行「改动」），那就把它建模成状态机，并让「可用工具集合」成为状态的函数。

```text
❌ 依赖提示词:
   prompt: "改动前必须先取得客户明确确认"
   → 模型自行决定是否遵守 → 13/50 次违反

✅ Concordat (类型化协议):
   state: AWAITING_CONFIRM ──confirm()──▶ CONFIRMED ──▶ may_expose({refund, cancel})
          │                                              ✗ 非法调用被拒绝
          └─(无 confirm)──▶ 非法调用 refund ──▶ REJECTED (无副作用)
```

### 关键技术

| 技术 | 说明 |
|------|------|
| **Typestate / Session Types** | Agent 接口 = 有限状态协议，类型携带状态 |
| **状态相关工具暴露** | 每轮仅暴露当前状态下合法的工具，模型物理上无法选到非法工具 |
| **前置拒绝（pre-effect rejection）** | 协议外调用在产生副作用**之前**被拦截 |
| **人类决策保留** | 保留给人的决策只能「请求」，不可被 Agent 代替 |
| **预算线性分摊** | token / tool-call 预算跨交接线性分配 |
| **定义时协议检查** | 协议定义阶段即校验，不合法直接拒绝 |
| **行为型 Liskov** | 子类若可绕过父类协议则被拒 —— 防止「继承即失效安全保证」 |

## 公式

```math
\text{合法工具集}:\quad
\mathcal{T}(\sigma) \;=\; \{\, t \in \mathcal{T}_{\text{all}} \;\mid\; \delta(\sigma, t) \text{ 有定义} \,\}
```

其中 $\sigma$ 为当前协议状态，$\delta$ 为状态转移函数。模型在状态 $\sigma$ 下**只能**看到 $\mathcal{T}(\sigma)$。

```math
\text{调用准入}:\quad
\text{execute}(t) \;\text{合法} \iff \; t \in \mathcal{T}(\sigma)
\quad\land\quad \neg \exists\, \sigma' \text{ 使 } \delta(\sigma, t) = \text{undefined}
```

```math
\text{预算分摊}:\quad
\sum_{i=1}^{n} b_i \;=\; B, \qquad b_i \ge 0
```

## 代码片段

```python
# 概念性示例：Concordat 风格的类型化 Agent
from concordat import Agent, Protocol, state, confirm, tool

class Booking(Protocol):
    # 订票协议：未确认前不可执行任何变更

    @state(initial=True)
    def awaiting_confirm(self):
        # 此状态下只有「询问 / 记录确认」类工具合法
        return [ask_customer, record_confirmation]

    @state(after=record_confirmation)
    def confirmed(self):
        # 只有拿到确认后，变更类工具才被暴露
        return [change_booking, issue_refund]

    @tool
    def change_booking(self, booking_id):
        # 只有在 confirmed 状态下才可达；否则调用被前置拒绝
        ...

class BookingAgent(Agent, protocol=Booking):
    ...
```

```python
# 子类安全检查：子类若可绕过父类协议 -> 拒绝
class UnsafeSubclass(BookingAgent):
    def change_booking(self, booking_id):
        return api.cancel(booking_id)   # 绕过 confirmed 状态
        # -> Concordat 拒绝实例化（行为型 Liskov 违规）
```

## 实验结论

- **基准**: tau-bench 航空域 50 个任务
- **模型**: gpt-4.1, Claude Haiku 5.5
- **额外设置**: 加入**模拟客户**施压要求代理跳过确认环节
- **结果**:

| 配置 | 未取得所需确认即执行改动 |
|------|------|
| 标准 Agent (gpt-4.1) | **13 / 50** 任务 |
| 标准 Agent (Claude Haiku 5.5) | **29 / 128** 任务运行 |
| **Concordat Agent** | **0** |

- 任务成功率**无显著差异**（安全性提升不以能力为代价）
- **tau-bench 自带 reward 未能检测出大多数此类违规** ← 这是一个对 benchmark 设计的批评

---

## 局限性

1. **单领域、单任务集** —— 仅 tau-bench 航空域 50 任务，无跨领域验证
2. **协议需人工编写** —— 状态机建模的成本随规则复杂度上升；规则表达力受 FSM 限制（无循环、无守卫条件的高级逻辑）
3. **数值样本量小** —— 13/50、29/128 的绝对数不多，统计检验细节未在摘要说明
4. **「只能请求人类决策」的实现边界不明** —— 摘要未说明人工交接的延迟与可用性假设
5. **模型侧无法绕过假设** —— 若模型通过非工具通道（如直接构造 API 请求）发起动作，防护有效性未知
6. **与通用 agent 框架的兼容性**未讨论（LangChain / MCP 等生态集成成本）
7. 单作者作品，工程成熟度与生产可用性需自行评估

## 实现建议

- **实现难度**: 中（核心是状态机 + 工具暴露过滤器 + 类型检查）
- **预期性能**: 安全性**确定性强提升**（0 违规），能力**基本无损**
- **适用场景**: **有合规/退款/账户变更等强流程约束的 Agent** —— 客服、订票、金融操作后台
- **落地注意**:
  1. **先盘点现有规则**：把散落在 prompt 里的约束整理成状态机，是这项技术的前置工作量，也是主要成本
  2. **继承体系要小心**：Python 子类可覆盖方法绕过协议，Concordat 用行为型 Liskov 拦截 —— 接入现有代码库时要检查是否所有 override 都走检查
  3. **与 LLM-judge 式安全护栏互补**：Concordat 管「流程合法性」，judge 管「语义适当性」，两者不互相替代
  4. **可以先只做一层**：把最高风险的 2-3 个动作（如退款）纳入协议，其余仍走 prompt，成本可控

## 我的评注

> 这篇的核心洞察只有一句：**别把合规问题交给模型判断。** 这是把类型系统的「编译期保证」搬到了运行时 —— 而且是**类型系统能覆盖的那部分**（状态依赖的流程约束），不是让类型系统去判断语义。
>
> 最值得注意的其实不是 Concordat Agent 做到了 0 违规，而是**「tau-bench 自带的 reward 未能检测出大多数这些违规」**这一句。它意味着：现存大量 agent 评测里，我们看到的「高成功率」里藏着一堆**根本没合规的轨迹**。这是对整个 agent benchmark 生态的实质性批评 —— 分数不等于合规。
>
> 方法论上，「行为型 Liskov」是很聪明的设计：与其要求子类「记得」调用 super（Python 里太容易被忘），不如在**运行时**验证子类的行为仍在父类协议的可达状态集合内。这比静态检查更 robust。
>
> 保留意见：FSM 的表达力天花板是真实存在的 —— 「除非金额超过 1000 且客户是 VIP 否则需二级审批」这类带守卫的规则要么拆成多个状态，要么把判断交给模型（那又回到了软约束）。所以 Concordat 更像**给最重要的几条硬规则上一道保险**，而不是完整替代 guardrail 体系。
>
> 单作者 + 开源库 + 强实证，实用性评分应该不低。这是我今天最想实际试一下的一篇。
