## 核心贡献

> 提出 **Epistemic Humility (EH)** 评测框架，用 ISE（Identify-Solve-Escalate）三个轨迹级维度刻画 agent 在知识冲突下"识别、修正、表达不确定性"的能力；揭示"任务精度高≠EH 高"，且 model-level 干预提升 EH 通常会牺牲任务精度。

1. 提出 **ISE 框架**：在 trajectory 层面度量 agent 的 epistemic humility，包含 Identify / Solve / Escalate 三个行为维度。
2. 设计**两类知识冲突**：controlled conflict（参数化记忆 vs 检索证据）与 naturally occurring conflict（多步执行中上下文源互斥）。
3. 实证发现：4 个被评测 agent 中，**task accuracy 与 EH 不正相关**；trajectory-level 分析显示冲突识别往往在早期步骤被检测但未在后续步骤维持。

---

## 技术方案

### 核心思想

传统 agent 评测只关心"最终答案对不对"，忽略了 agent 过程中如何处理不确定性。本工作把不确定性处理拆为三个可观测行为：是否察觉到冲突、是否在推理中修正、是否在最终输出中显式 escalate。

### 关键技术

| 技术 | 说明 |
|------|------|
| ISE dimensions | Identify（检测冲突）/ Solve（推理时修正）/ Escalate（在答案中表达不确定性） |
| Matched no-conflict controls | 每个冲突场景都配有相同任务的非冲突对照，用差异度量 EH 行为 |
| Trajectory-level analysis | 在 step-level 跟踪 EH 行为是否跨步骤保持 |
| Model-level interventions | 通过 system prompt 强制表达不确定性，评估其 trade-off |

---

## 公式

EH 得分定义为 ISE 三个维度的加权组合：

```math
\text{EH} = w_1 \cdot \mathbb{1}[\text{Identify}] \cdot \mathbb{1}[\text{Solve}] + w_2 \cdot \mathbb{1}[\text{Escalate}]
```

实际实现中各维度为 0/1 标注，所有评估在 paired conflict/no-conflict trajectories 上做对比。

---

## 实验结论

- **数据集**: 自构的多 agent 执行轨迹数据集，包含 controlled + naturally occurring 冲突
- **基线**: 4 个主流 agent harness
- **结果**:
  - 高 task accuracy 不等于高 EH
  - Conflict detection 多在早期 step 完成，但**未在后续 step 维持**
  - System prompt 强制表达不确定性会**显著降低** task accuracy

---

## 局限性

- 仅评测 4 个 agent，覆盖度有限。
- ISE 标注依赖人工或强 LLM judge，存在 judge bias。
- 尚未研究 EH 与 long-horizon task 表现的关系。
