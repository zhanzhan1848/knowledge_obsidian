# 标准评测藏住了什么：LLM Agent 被劫持检测器的真实水平

| **摘要** | Detectors can flag hijacked large language model (LLM) agents from the traces of the tools they call. In the eleven evaluations we audited, attacks or anomalies make up 16% to 86% of the test samples, no evaluation varies that share, and six report no test on data from a second benchmark or source. We ask what such evaluations hide. On the AgentDrift and AgentDojo benchmarks we test trained detectors that read tool identities, behavior, call sequences, step embeddings or text, and a released LLM action monitor, AlignmentCheck, with thresholds fixed on training data or set by the monitor's released decision rule. First, at a 2% attack rate a detector with an area under the receiver operating characteristic curve (AUROC) of 0.879 reaches a precision of 0.076, and the mix of negatives alone moves that precision between 0.039 and 0.117. Second, as tool coverage, the share of test tool calls whose tool was seen in training, falls, detector rankings cross near 50% coverage and reverse below it, because unseen tools map to inputs that training never reached. Dropout on tool inputs largely removes the reversal. Third, no detector trained on AgentDrift ranks AgentDojo traces better than chance (AUROC 0.47 to 0.52), including one that reaches 0.996 within AgentDojo. The monitor, trained on neither, reaches 0.930, but with its open backbone its released decision rule would still mostly raise false alerts at a 2% attack rate (precision 0.096). We turn these findings into a checklist for evaluating trace detectors. |

## 核心贡献

1. **审计了 11 个已发表的 Agent 劫持检测器评测**，发现攻击/异常样本占比在 **16%–86%** 之间浮动 —— 没有一个评测公开说明了自己用了多少攻击样本，这个比例会直接决定检测器的实际可用性。
2. **低攻击率下的精确率崩塌**：在 2% 攻击率下，一个 AUROC 高达 **0.879** 的检测器精确率只有 **0.076**；仅仅改变负样本构成就能让精确率在 **0.039–0.117** 之间浮动。
3. **工具覆盖率的临界点效应**：当测试工具调用中"训练时见过该工具"的比例（tool coverage）下降时，检测器排名在 **50% 覆盖率附近发生交叉**，低于此点即**完全反转** —— 未见过的工具被映射到训练从未触及的输入分布。
4. **跨基准迁移基本失效**：在 AgentDrift 上训练的检测器，在 AgentDojo 上 AUROC 仅 **0.47–0.52**（等于随机），其中包括一个在 AgentDojo 内部达到 **0.996** 的检测器。
5. **Dropout 是关键对照**：对工具输入施加 dropout 可基本消除排名反转，说明问题出在工具身份特征而非其他信号。
6. **公开监控器 AlignmentCheck** 在两个基准都没训过的情况下达到 0.930，但按其发布的决策规则在 2% 攻击率下**仍以 0.096 的精确率**大量误报。

## 技术方案

### 关键技术

| 技术 | 说明 |
|------|------|
| 技术 | 说明 |
|------|------|
| 轨迹检测器 | 从工具调用轨迹中检测被劫持的 LLM Agent |
| 工具身份 vs 行为 vs 调用序列 | 三类特征通道对比 |
| 步嵌入 / 文本通道 | Embedding-based 与文本-based 监控 |
| Tool coverage | 测试工具调用中"训练时见过"的比例 |
| AUROC / Precision@低攻击率 | 评测指标组合 |
| Dropout 对照 | 隔离工具身份特征的因果检验 |

### 关键发现

- **攻击样本比例是评测的一级元参数，却几乎无人报告**。这与 "ICLR 2026 Detectors Hide in the Open" 指出的问题同源，但本文给出了量化区间。
- **工具覆盖率的非单调效应**：不是"覆盖率越低越差"的线性退化，而是在 ~50% 处发生**排名反转**（模型间的优劣关系被翻转，而非仅仅一起变差）。
- **"基准内高分"完全不代表泛化能力**：AgentDojo 内 0.996 的检测器跨基准只有 0.47–0.52。
- **开源监控器不豁免**：AlignmentCheck 的问题不是架构而是**默认决策阈值**没有按攻击率校准。
- 论文最终把发现转化为一份**评测清单（checklist）**。

## 实验结果

| 配置 | 结果 |
|------|------|
| 2% 攻击率，AUROC 0.879 检测器 | 精确率 **0.076**（负样本构成改变则 0.039–0.117） |
| AgentDrift → AgentDojo 迁移 | AUROC **0.47–0.52**（随机水平） |
| AgentDojo 内部检测器 | AUROC **0.996**（但零跨基准能力） |
| AlignmentCheck（零训练迁移） | AUROC **0.930**，但发布决策规则下精确率仅 **0.096** |
| 施加工具输入 dropout 后 | 排名反转基本消除 |

---

## 局限性

- 审计覆盖 11 个评测，但均为论文报告的设定，攻击样本的"真实"分布无法确证。
- 只考察 trace-based 检测器，不覆盖在模型输出层面做检测的方法。
- 结论依赖 AgentDrift / AgentDojo 两个基准的特定构造，普适性待验证。
