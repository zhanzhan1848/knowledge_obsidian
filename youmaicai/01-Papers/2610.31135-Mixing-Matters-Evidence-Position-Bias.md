## 核心贡献

> 跨 **Transformer / state-space / hybrid Mamba** 三类架构比较 long-context QA 中的**证据位置偏置**，给出**谨慎、可证伪**的结论：**序列混合器不是唯一成因**。

1. **方法**：把**一份 gold document** 在固定 9 个 distractor 中移动，追踪准确率随证据位置的**响应曲线**。
2. **关键发现**：
   - **Transformer 有 beginning advantage（开头优势）**；**state-space 模型没有**；
   - 但**两个族都偏好靠近末尾的证据**；
   - **matched pure-vs-hybrid Mamba** 比较指向同方向，但**统计上不确定**；
   - 族间差异只出现在**能完成任务的模型**中；
   - 在**合成检索**任务上 Transformer 优势重现，但 state-space 存在**能力天花板**，无法做公平的族间比较；
   - 在**同一 state-space 架构内**做 corpus swap → 总准确率改变，但**曲线形状无可检测变化**；
   - **Prompt 改动可制造或几乎消除开头优势**；
   - 位置在跨架构间**仍可解码**，即使响应曲线不同；Transformer 族中**初始 token 附近的注意力集中度**与开头敏感度**协变**。

---

## 技术方案

| 实验 | 目的 |
|------|------|
| Gold doc 位置扫描（9 distractors） | 刻画位置响应曲线 |
| Transformer vs SSM vs hybrid | 族间比较 |
| Pure vs hybrid Mamba matched | 隔离混合器本身 |
| 合成检索 | 突破 state-space 能力天花板 |
| Corpus swap（同架构内） | 区分"数据"与"架构"效应 |
| Prompt 变化 | 分离 prompt 混杂 |
| 注意力集中度相关性 | 机制侧证据 |

### 关键洞见

- 论文措辞非常克制：**"未隔离出序列混合器是唯一成因"**。开头优势既可能来自架构，也可能来自 prompt 语序、注意力分布等。
- "能回答任务的模型才有族间差异" → 能力与位置偏置**耦合**，评估 position bias 时必须先控制能力。

---

## 实验结论

- 探索性结论：有效上下文使用**取决于架构族、能力、任务与 prompt**，而非单一混合器。

---

## 局限性

- 论文自称 **exploratory results**；
- 纯 vs hybrid Mamba 比较**统计不确定**；
- state-space 能力天花板使部分比较不可行；
- 未覆盖长文档推理、代码等非 QA 场景。
