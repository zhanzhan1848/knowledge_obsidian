## 核心贡献

> 用 streaming structure-aware optimal transport 在**毫秒/步**尺度对比 agent 当前轨迹与历史成功 run 的 dependency 结构，提前检测失败、节省 18% 计算（83% 中断正确）。

1. 提出 **OnTrack**：streaming 监控机制，每步仅 ~1ms 即可比较 agent 当前轨迹与历史成功 run 的步骤 + 依赖结构。
2. 三档数据访问模式（full / intermediate / no prior）下能力平滑退化，从"plan violation detection"逐步降级为"loops / stalls / repeated tool calls"。
3. SWE-bench 上用前 8 步轨迹做 OT，**AUROC 比内容相似度方法高 +0.057**。
5. 中断策略下，节省约 **18% 失败 run 的计算**，其中 **83% (5/6) 中断实际正确**。

---

## 技术方案

### 核心思想

传统方案：每步调 safeguard agent 监控（高延迟 / 高 cost），或事后审计（已造成损失）。OnTrack 用**结构感知的 OT 距离**在 step-level 实时比对，**比 safeguard agent 快 ~1000 倍**，比事后审计早发现失败。

### 关键技术

| 技术 | 说明 |
|------|------|
| Streaming OT | 每步追加一次 OT 距离计算，无批处理约束 |
| Dependency-aware 比对 | 不只看 step 内容，更看工具调用依赖图结构 |
| Plan violation detection | full reference access 下：检测是否偏离已知成功 plan |
| Degraded modes | 仅 tool schema → 检测 loops / stalls；仅 step logs → 检测 repeated calls |
| Abort policy | 当累计异常分数超阈值则提前终止 run |

### 三档数据访问模式

| Mode | 数据 | 可检测 |
|------|------|--------|
| Full | 历史 run + tool schema | Plan violation |
| Intermediate | 仅 tool schema | Loops / stalls / repeated calls |
| No prior | 仅当前 step log | Repeated tool calls / structural anomalies |

---

## 实验结果

- **SWE-bench trajectories**：基于前 8 步 OT，AUROC 比内容相似度高 **+0.057**
- **Abort policy**：节省 **18% compute 用于失败 run**
- **Correct aborts**：83% (5/6 中断实际真会失败)
- 单步监控耗时 ~1ms，对正常推理几乎无开销

---

## 关键 takeaway

- **结构信息 > 内容信息**：dependency graph 的 OT 距离比 token 级相似度更有判别力。
- 实时监控成本可以做到极低，关键是**流式 OT** 而非"逐 token LLM 评判"。
- 数据访问模式决定能力上限，但**即使无 prior 知识**仍有可用信号（loops / stalls）。

---

## 局限性

- 仅在 SWE-bench 验证，其他 agent 任务（IT triage / stock trading / trip planning）需进一步测试
- OT 距离的解释性不足，难作为根因分析工具
- 仅支持依赖图结构特征，遗漏内容级异常（错误但语法正常）
