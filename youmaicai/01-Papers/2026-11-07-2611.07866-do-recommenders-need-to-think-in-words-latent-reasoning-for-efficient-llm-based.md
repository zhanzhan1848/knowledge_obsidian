# Do Recommenders Need to Think in Words? Latent Reasoning for Efficient LLM-Based Recommendation

### 核心贡献
1. 提出 **LatentRec**：把 LLM 推荐中「推理时推理产物」（文本 CoT 或 latent reasoning）整体替换为 **训练时逐步监督**，从而在推理阶段完全省掉推理开销且不损精度。
2. 框架由三部分组成：2.5M 参数的 **Continuous Thought Module**、**Soft Token Selection**（桥接 hidden state 与 input embedding 之间约 **14× 的范数差**）、以及 **Per-step Reasoning Loss (PRL)**。
3. 训练后的 LLM 在推理时 **不再需要该 module（可直接丢弃）**，仍保留同等精度；在 3 个 Amazon benchmark 上相对 CoT-distilled 基线 **HR@10 提升 4.0–5.0%（相对）**，同时 **延迟降低 18.3×**（batch=1）。

### 技术方案
**核心思想**: 推理时生成 CoT 文本每条推荐要多花数十到数百 token；改为在训练阶段对 LLM 的 **每一个中间 hidden state** 直接用预测头做监督（对齐目标 Semantic ID 的第一个 token），把「思考过程」内化进权重。训练时需要一个轻量 latent 模块来提供中间步骤载体，部署时该模块被丢掉。

| 技术 | 说明 |
|------|------|
| Continuous Thought Module | 仅 **2.5M 参数**的轻量模块，在训练阶段基于 LLM 的 hidden state 迭代 **K 步 latent reasoning**，输出连续的隐式思考步骤；推理时整个模块被丢弃 |
| Soft Token Selection | 解决 hidden state 与 input embedding 之间约 **14×** 的范数（norm）gap——直接把 hidden state 当 token 喂回模型会尺度失衡，因此引入可学习的软选择/映射来对齐尺度 |
| Per-step Reasoning Loss (PRL) | 监督 **每一个中间推理状态**：把该中间状态送入 LLM 的预测头，与目标 Semantic ID 的 **第一个 token** 做对齐损失，从而对全推理链逐步注入监督 |
| 训练/部署解耦 | 「思考」只付一次训练成本，而非每条推荐都付推理成本；部署时 module 可丢弃，延迟回到单次前向水平 |

### 实验结果
- **数据集**: 3 个 Amazon benchmark（具体名称摘要未说明）
- **基线**: CoT-distilled baseline（蒸馏链式思考的 LLM 推荐基线）
- **结果**: HR@10 相对提升 **4.0–5.0%**；延迟降低 **18.3×**（batch=1）；per-step 训练监督在 3 个数据集上均一致带来精度提升

### 局限性
- 训练阶段需要额外的 Continuous Thought Module 与 K 步前向，训练成本上升（摘要未给出具体训练开销数字）
- 监督目标只用 Semantic ID 的 **第一个 token**，多 token/序列级目标的适用性摘要未说明
- 依赖 Semantic ID 这一生成式推荐的 token 化方案，迁移到非 Semantic ID 范式（如直接打分/embedding 推荐）摘要未说明
- 摘要未说明具体模型 backbone、参数量与更多 baseline 对比

### 关键洞见
> 推理时的 CoT 文本其实是「把思考外包给 token」；LatentRec 证明思考可以完全内化进参数——只需在训练期对每个中间隐状态施加监督，推理期即可彻底删除思考模块。精度用训练期一次性成本换来了 18.3× 的推理延迟下降，这是把 **推理期成本迁移到训练期** 的一个干净范式。
