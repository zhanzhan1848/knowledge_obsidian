# Same Request, Different Answer: Quantization Amplifies Cache-Induced Divergence in LLM Serving

> **arXiv**: [2609.04748](https://arxiv.org/abs/2609.04748)
> **发表日期**: 2026-09-04
> **分类**: cs.SE (及交叉分类 cs.DC, cs.LG)
> **会议/期刊**: IEEE Access, 2026, Early Access（DOI 10.1109/ACCESS.2026.3749922；20 pages, 3 figures, 7 tables）

## 📋 摘要

主流开源推理栈默认复用共享前缀的 key-value 张量。本文量化了这种前缀复用对"可复现性"的代价：在模型、解码参数、随机种子与请求顺序全部固定、batch size 为 1 的条件下，作者在一个 80 回合的多轮 agentic tool-use 工作负载上，对两个引擎、四种权重格式分别开启与关闭前缀复用作对比。关闭前缀复用时，十种配置下重复运行都能复现每一个 token 与 log-probability；开启后，两个引擎上 cache-hit 路径与 recompute 路径都出现分歧。在 llama.cpp + GGUF 权重上，分歧随量化程度上升：Qwen2.5-7B 在十段独立服务端历史中，16-bit 时有 37.4% 的 episode 出现分歧，4-bit 时升至 82.5%。近似平局的决策占比仅从约 1.2 倍上升，而 cache 路径在 top-two margin 上的变化从 16-bit 到 3-bit 增长了 4.9 倍。4-bit 权重走 16-bit kernel 时，分歧与 16-bit 无可检测差异，说明放大效应主要来自量化执行路径本身。在 Q4_K_M 下，运行间分歧主要来自 llama.cpp 的服务端 prompt cache：在规范 episode 顺序下它移动分歧 37.5 个百分点，在默认设置下五种随机顺序使分歧跨 20.0%–28.7%。恢复 cache 状态后，每条路径各自精确复现，但两条路径仍然不同。作者结论是：在被测推理栈中，缓存式服务不可复现，根因是 cache 状态不在请求中、也不被默认重置。一个单轮桥接实验显示路径分歧能传导到任务结果，但未检出净准确率变化。作者开源了 harness、日志与分析流水线。

## 🎯 核心贡献

1. **把"缓存可复现性"量化成一个可测量的工程问题**：在模型/解码/种子/请求顺序完全受控的条件下，测出启用 KV 前缀复用后 token 级与 log-prob 级的不一致。
2. **发现量化会放大缓存路径分歧**：Qwen2.5-7B 在 llama.cpp + GGUF 下，16-bit 时 37.4% episode 分歧，4-bit 时 82.5%。
3. **定位放大机制**：4-bit 权重经 16-bit kernel 服务时分歧与纯 16-bit 无可检测差异 → 放大主要发生在量化执行路径，而非量化权重本身。
4. **定位主要来源**：Q4_K_M 下的运行间分歧主要来自 llama.cpp 的服务端 prompt cache（规范顺序下移动分歧 37.5 个百分点）。
5. **给出根因结论并开源复现材料**：cache 状态既不在请求内也不被默认重置；提供 harness、日志与分析流水线。

## 🔧 方法/架构

- **受控实验设计**：固定模型、解码配置、随机种子、请求顺序，batch size = 1；自变量为"前缀复用开/关"，在 **2 个引擎 × 4 种权重格式 = 10 种配置**上跑 80 回合多轮 agentic tool-use 工作负载。
- **分歧度量**：逐 episode 比较 cache-hit 路径与 recompute 路径在 token 序列与 log-probability 上的差异；并统计近似平局决策占比、top-two margin 的变化幅度。
- **分解归因**：把"权重量化"与"kernel 精度"分离（4-bit 权重 + 16-bit kernel），把"服务端 prompt cache 状态"与"路径差异"分离（恢复 cache 状态后重测）。
- **顺序敏感性**：在 Q4_K_M 下比较规范 episode 顺序与五种随机顺序下的分歧分布。
- **端到端传导验证**：单轮桥接实验检查路径分歧是否影响任务结果，同时监测净准确率变化。

$$

## 📊 实验结果

- **无前缀复用**：10/10 配置下重复运行**精确复现**每一个 token 与 log-probability。
- **Qwen2.5-7B @ llama.cpp + GGUF**：16-bit → **37.4%** episode 分歧；4-bit → **82.5%**（基于 10 段独立服务端历史）。
- **近似平局决策占比**：仅升至约 **1.2 倍**（即敏感决策并未显著增多）。
- **top-two margin 变化**：从 16-bit 到 3-bit **增长 4.9 倍**。
- **4-bit 权重 + 16-bit kernel**：分歧与 16-bit **无可检测差异**。
- **Q4_K_M 服务端 prompt cache**：规范 episode 顺序下移动分歧 **37.5 个百分点**；默认设置下五种随机顺序分歧跨 **20.0%–28.7%**。
- **恢复 cache 状态后**：每条路径各自精确复现，但两条路径彼此仍不同。
- **端到端**：路径分歧可传导至任务结果，但**未检出净准确率变化**。
- **工作负载**：80 回合多轮 agentic tool-use。

## ⚠️ 局限性

- **引擎覆盖面窄**：仅覆盖两个引擎（其中 llama.cpp + GGUF 为重点），vLLM/SGLang 等主流栈是否表现一致未覆盖。
- **单一模型族（Qwen2.5-7B）**：量化放大的结论是否跨模型族成立需要更多验证。
- **工作负载单一**：结论建立在 agentic tool-use 工作负载之上，通用 QA / 长上下文场景未系统评估。
- **精度评估的分辨率**：以 token 与 log-prob 层面的分歧为主，"任务结果受影响但净准确率不变"的结论意味着影响尚未被常规指标捕获。
- **工程结论依赖具体实现细节**（llama.cpp 的服务端 prompt cache 行为），上游版本更新可能改变结论。

## 💡 建议

- 是否推荐使用：**是**（工程实践价值高）
- 适用场景：需要**可复现、可审计**的 LLM 部署（金融、合规、安全评测、回归测试）；生产环境中的低比特量化服务；agentic 多轮系统的调试与一致性排障。
- 落地建议：把 cache 状态纳入请求显式传递或默认重置；在评测流水线中区分"同路径复现"与"跨路径一致性"两个不同层次的指标。
