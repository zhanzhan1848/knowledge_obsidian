## 核心贡献

> **agent 的最终回复不解释它造成的安全事件**，而异构运行时把关键证据暴露在不兼容的接口里。AgentTriage 给出一个**可执行契约（executable contract）**：结论必须引用规范化的运行时事件，强制证据缺失时**弃权（abstain）**，并保证诊断**可在无 LLM 介入的情况下重算与复核**。

1. **提出可执行契约（executable contract）**：跨异构运行时的可重放安全诊断
2. **强制引用与弃权**：结论中的每条 claim 都必须**引用 canonical runtime events**；**强制证据缺失时必须弃权**
3. **Runtime overlays 归一化**：把各运行时的原生观测**规范化**为统一格式
4. **确定性管线（deterministic pipeline）**：连接 invocation 与 result 生命周期 → 构建**带类型的 provenance graph（溯源图）** → 选出 **policy-decisive slice（策略决定性切片）** → 把 claims 绑定到已记录的证据
5. **可重放性保证**：给定**相同的归一化 trace、overlay 版本、运行前策略 oracle**，诊断可被**重新计算**、claims 可被**重新检查**，**全程不需要语言模型判断**
6. **实证效果**：5 个运行时、一个契约覆盖**全部 159 个适用执行**；**120 个已裁决案例**上达到 **0.858 grounded joint diagnosis**、**0.966 required-evidence coverage**、**0.036 unsupported-claim rate**；联合诊断比**最强同 schema 基线高 0.175**（**95% CI [0.092, 0.258]**）

## 技术方案

### 核心思想

```
异构运行时 (5 种) 的原生日志
      ↓ runtime overlays（逐运行时适配层）
归一化事件 (canonical runtime events)
      ↓ 确定性管线（无 LLM）
① 连接 invocation ↔ result 生命周期
② 构建带类型的 provenance graph
③ 选出 policy-decisive slice
④ 把 claims 绑定到已记录证据
      ↓
   诊断结论 + 证据引用 + （必要时）弃权
```

### 关键技术

| 技术 | 说明 |
|------|------|
| Executable contract | 契约同时规定"结论形式"与"证据义务"，可被机器检查 |
| Canonical runtime events | 跨运行时的规范化事件表示，构成证据的公共语言 |
| Runtime overlays | 每个运行时一个适配层，把原生观测映射到 canonical events |
| Typed provenance graph | **带类型**的溯源图，节点/边类型编码"谁调用了什么、产生了什么" |
| Policy-decisive slice | 从图中裁出**真正决定策略判定**的子图 —— 避免"把整条日志扔给 LLM" |
| Claim–evidence binding | 每条 claim 绑定到具体记录证据，可机械复核 |
| Deterministic recomputation | 同输入 → 同诊断；**无 LLM 判断** ⇒ 无幻觉、可审计 |
| Abstention on missing mandatory evidence | 强制证据缺失 ⇒ 弃权，而非猜测 |
| Native + synthesized identifier audit | 审计原生与合成标识符的覆盖情况 |

### 评测指标

| 指标 | 含义 |
|------|------|
| Grounded joint diagnosis | 联合诊断（诊断 + 证据）都正确且有据可依的比例 |
| Required-evidence coverage | 强制证据被覆盖的比例 |
| Unsupported-claim rate | 无支撑声明的比例（越低越好） |

## 关键结论

1. **"最终回复解释不了安全事件"是 agent 审计的根本障碍**。AgentTriage 的贡献不是又一个检测器，而是**一条从运行时日志到可审计结论的确定性通路**。
2. **确定性管线带来三个同时成立的性质**：无幻觉（结论由图计算得出）、可重放（同输入同输出）、可离线复核（claims 可机械核对）。这三者一起构成合规场景的硬需求。
3. **弃权是设计的一部分**，不是失败。**0.036 unsupported-claim rate** 与 **0.966 required-evidence coverage** 说明：既能保证覆盖率，又能把无支撑声明压到 3.6%。
4. **一个契约覆盖 5 个运行时、159 个执行**，说明"异构"这一障碍在契约层面是**可解的** —— 差异被 runtime overlay 吸收掉了。
5. **相对基线的 +0.175（CI 不含 0）是本文最有说服力的数字** —— 提升幅度大且统计显著，说明"确定性溯源图 + 决定性切片"确实比同 schema 基线（大概率为 LLM-based 或纯日志分析）更有效。

---

## 局限性

- **unsupported-claim rate 0.036 意味着约 3.6% 的声明仍无支撑** —— 在安全审计中这个残留不可忽略
- **grounded joint diagnosis 0.858 仍有 14.2% 的缺口**，摘要未说明失败案例的分布（是某类运行时更难？还是某类策略？）
- **159 个执行、120 个裁决案例**规模偏小；5 个运行时的选择可能偏向常见框架（未列出具体是哪些）
- **仅 120 个 adjudicated cases**，裁决本身的人工标准与一致性（inter-annotator agreement）未报告 —— 评测的 ground truth 质量因此无法评估
- **依赖 runtime overlay 的人工适配**：每新增一种运行时都需要写 overlay，"契约通用"不等于"零成本接入"
- **policy-decisive slice 的选取算法**是系统精度的关键，但摘要未描述其原理
- 摘要**未给出"证据缺失时的弃权率"** —— 这是弃权机制的核心指标，缺失

## 实现建议

- **实现难度**: 高（需要为每个运行时写 overlay + 溯源图 schema + 策略 oracle + 确定性管线）
- **适用场景**: 受监管行业中的 tool-use agent（金融、政务、医疗）—— 需要事后追责与可复核结论
- **落地步骤**:
  1. 先定义 **canonical event schema**（比 overlay 更重要 —— schema 错了后面全错）
  2. 为自己的运行时写 **overlay**，把原生事件映射到 canonical 形式
  3. 构建**带类型的 provenance graph**，先用最简的 invocation/result 二部图
  4. 实现 **policy-decisive slice** 选取：先用"与策略谓词相关的节点"做粗筛
  5. 引入**强制证据缺失即弃权**的规则 —— 这是可信度的来源
  6. 度量 **unsupported-claim rate** 与**弃权率**两项，不要只看联合诊断准确率
- **与相关工作互补**: 与 [[2026-10-25-2610.31130-post-audit-mirage-agent-verification]] 是**互补的一对**：
  - AgentTriage 回答"**证据足够时**，如何给出可重放、可复核的诊断"
  - Post-Audit Mirage 回答"**证据不足时**，如何诚实地弃权并说明边界"
  - 合起来构成 agent 安全评测的完整链条；且 Post-Audit Mirage 提出的"fresh group-labelled harm outcomes"恰好可以作为 AgentTriage 之后的**部署期监控补充**
- **价值点**: 把"让 LLM 解释自己干了什么"换成"**让确定性管线从日志算出它干了什么**"—— 这是 agent 审计从 demo 走向生产的关键一步
