### 核心贡献
1. 定义 **personal external service agent**：由某个具体个人 **授权并持续管理**、用于承接外部客户请求、交付工作并提供持续支持的 agent，其能力来源于该个人的知识、经验、专业方法与服务边界。
2. 提出 **DelegateEval**：一个 **平台级（platform-level）** 的 agent 系统评测框架，适用于结合 LLM、可复用 skills、**MCP 等协议**与可执行工具环境的系统。
3. 框架覆盖 **8 个维度**：易创建性、服务发现与匹配、交付质量、专业能力继承、服务连续性、学习与改进、可靠性与治理、效率与价值；并给出 **实验设计**（framework + experimental design）。

### 技术方案
**核心思想**: 评测的标的不是「模型强不强」，而是「平台是否让不同背景的人把自己的专业知识变成可持续、可验证、经济上可行的对外服务」——因此评测对象是平台生态（模型 + skills + 协议 + 工具环境），而非单一 agent。

| 技术 | 说明 |
|------|------|
| Personal external service agent 定义 | 强调三重属性：**个人授权**、**持续管理**、以「委托」而非「雇佣」关系对外服务，交付物需可验证 |
| 8 维度评测框架 | ① ease of creation（易创建性）② service discovery and matching（服务发现与匹配）③ delivery quality（交付质量）④ expertise inheritance（专业能力继承）⑤ service continuity（服务连续性）⑥ learning and improvement（学习与改进）⑦ reliability and governance（可靠性与治理）⑧ efficiency and value（效率与价值） |
| 平台级评测对象 | 明确涵盖 **LLM + reusable skills + 协议（如 MCP）+ 可执行工具环境** 的组合，而非孤立的模型或 agent |
| 评测准则 | 考察平台能否让「不同背景的人」把专业知识转化为可持续服务：交付可验证的工作、通过经验积累能力、且经济上可行 |
| 实验设计 | 给出完整数据集、可执行环境、统一评分协议与跨模型结果的 **待办计划**（当前尚未完成） |

### 局限性
- 论文为 **框架/立场性工作（framework + experimental design）**，缺少实证验证，所有维度尚无量化打分结果
- 评测对象覆盖 LLM、skills、MCP 协议、可执行工具环境，范围极大，工程实现难度高
- 依赖「服务发现与匹配」「经济可行性」等需要真实多主体生态才能验证的维度，当前只能用模拟环境近似
- 摘要未给出与既有 agent benchmark（如 WebArena 类工具使用基准）的具体关系

### 关键洞见
> 「个人 agent」不只是帮自己干活，还能变成 **以个人为背书的对外服务基础设施**——这带来一种新的价值形态：把个人经验打包成可持续交付、可验证、经济上可行的服务。要评估这类系统，评测的层级必须上升到「平台是否支持个人把专业知识产品化」，而不是单看模型分数。
