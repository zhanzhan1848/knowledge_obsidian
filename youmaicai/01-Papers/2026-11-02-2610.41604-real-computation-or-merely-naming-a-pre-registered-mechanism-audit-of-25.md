# 真实计算还是仅仅命名？LLM Agent 系统 25 个认知架构模块的预注册机制审计

> **原题**: Real Computation or Merely Naming? A Pre-Registered Mechanism Audit of 25 Cognitive-Architecture Modules in an LLM-Based Agent System

| **摘要** | Agent systems built on local large language models are increasingly marketed through the vocabulary of cognitive architecture: modules named global workspace, theory of mind, causal reasoning, or active inference are listed as features, and the presence of the name is taken as the presence of the mechanism. We ask the prior question -- does the named computation actually happen -- and contribute a transferable verification method for the claim-implementation gap: a four-question static audit protocol with line-number evidence and call-chain tracing, demonstrated on two systems. We audit a system claiming 25 cognitive mechanisms, pre-register falsifiable predictions for 11 modules and execute the interventions, replicate the protocol on the IIT-phi core of a second, independent system with its own pre-committed falsification criteria, and run two repair experiments as positive controls. In 18 of 25 modules the computed value never reaches any production output; three idle-wiring shapes new to the dead-code and code-smell literatures emerge (connected-but-never-called, called-but-inert, called-but-content-blind). Of 61 frozen criteria across 12 interventions, 53 were confirmed, two partially adjudicated, five falsified, one adjudication-ambiguous. Repairs raised planner task success from 0.028 to 1.000 and cut state-controller error by 52%. Module names and module computations must be audited as independent claims; the protocol and the five-class failure taxonomy are reusable for the claim-implementation gap at two-system, case-level depth. |

## 核心贡献

1. **问题**：基于本地 LLM 的 agent 系统越来越多地用**认知架构词汇**做营销：模块名叫 global workspace、theory of mind、causal reasoning、active inference，**而"名字的存在"就被当作"机制的存在"**。
2. **核心追问**：被命名的计算**真的发生了吗**？本文提出可迁移的**验证方法**来应对"声称-实现落差"：一个**四问静态审计协议**，配合**行号级证据**与**调用链追踪**，并在两个系统上演示。
3. **审计结果（最刺眼的数据）**：一个声称有 **25 个认知机制**的系统中，**18 个模块的计算值从未到达任何生产输出**。
4. **三种"闲置接线"（idle-wiring）形态**（论文称其对死代码与代码坏味道文献有新意）：
   - **已连接但从未被调用**（connected-but-never-called）
   - **被调用但无效果**（called-but-inert）
   - **被调用但对内容不敏感**（called-but-content-blind）
5. **预注册干预**：为 11 个模块**预注册可证伪预测**并执行干预；**61 条冻结标准**跨 12 项干预：**53 条确认**、2 条部分裁定、**5 条证伪**、1 条裁定模糊。
6. **两个修复实验作为阳性对照**：修复后**规划器任务成功率从 0.028 → 1.000**，**状态控制器错误率下降 52%**。
7. **结论**：**模块名与模块计算不是一回事**。

### 关键发现

- **"25 个模块中 18 个的计算值从未到达任何生产输出"** —— 也就是说 **72% 的"认知架构"模块是装饰性的**。这是今日最尖锐的一组数字。
- **"已调用但对内容不敏感"（called-but-content-blind）** 是三种形态中最精妙的一种：模块确实被调用了，但它**接收参数却不使用** —— 这类问题传统代码审查很难发现，因为它"看起来在工作"。
- **"预注册 + 冻结标准 + 阳性对照"** 是本文方法论的骨架。这与 [[2026-11-02-2610.40893-qistas-a-pre-registered-portable-protocol-for-fairness-evaluation-of-lar]]（Qistas 的预注册协议）属于**同一社区规范的形成**：预注册正在成为 LLM 评测与审计的标准动作。
- **0.028 → 1.000 的修复效果** 极为惊人 —— 它同时证明了两件事：审计**找对了问题**，且这些"认知模块"**一旦真正接线就真的有用**。所以问题不是"这些机制没用"，而是"**它们没被接上**"。
- 与 [[2026-11-02-2610.42004-tradewar-a-benchmark-for-execution-grounded-trade-negotiation-with-adapt]]（TradeWar）对照：那篇说"达成率不等于价值"，这篇说"**模块名不等于机制**"。**指标与机制的双重落差**。
- 与 [[daily-2026-11-01]] 那批"表面成功 vs 真实机制"的主线**完全一致**，但这次把方法从实验室搬到了**工程代码审计**。

## 局限性

- 静态审计只能发现**结构性**闲置（有调用链证据的），**无法判断计算本身是否正确**
- 两个系统都是本地 LLM agent，结论对闭源 API agent 的适用性未验证
- 修复实验同时改变了多个组件，难以完全归因到某个模块
- 审计协议的"四问"依赖人工判定，存在主观性（论文用冻结标准缓解但未消除）
