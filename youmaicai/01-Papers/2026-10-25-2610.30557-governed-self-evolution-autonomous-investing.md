## 核心贡献

> 提出 **Steward** —— 一个多 agent LLM 投资系统，其核心设计是**用类型系统划定"自我进化"的边界**：自我演化只能发生在**外层**（记忆、反思、prompt 学习），而**不变核心（invariant core）—— 订单算术、风控规则与纪律 agent prompt —— 任何自编辑都无法触及**。

1. **明确的边界划定方式**：不是靠 prompt 约束"别乱改"，而是**在类型系统层面**定义哪些状态可被自修改 —— 这比"靠 instructions 守住底线"的结构性强得多
2. **九个角色专职 agent 联合决策**：**4 个 analyst** 分别读取 **news feeds、SEC filings、宏观经济序列、市场数据**，输出**带类型的报告（typed reports）**；由此 **Portfolio Manager** 设定目标仓位；**受保护的 Risk Manager** 负责审计
3. **七层共享记忆**：**由代码从系统自身记录装配而成**，为每个决策提供**持仓上下文、市场叙事（market narrative）、校准（calibration）与该 agent 过去的决策**
4. **通过评审实现自我改进**：
   - **code 每晚为每笔交易与预测打分**，并把分数**写入记忆**
   - **每季度由 reflector 提出 prompt 学习（prompt learnings）**
   - **确定性门（deterministic gate）可逆地应用**这些学习
   - **重放（replay）记录的输入**进行验证
5. **不变核心**：**订单算术（order arithmetic）、风控规则、纪律 agent prompts** —— **没有任何自编辑能触及**
6. **五个月真实部署的实证**（见下）
7. **开源**：代码在 GitHub

## 技术方案

### 核心思想

```
         ┌──────────────── 可自演化外层 ────────────────┐
         │  七层共享记忆（代码装配）                      │
         │  ← 每晚 code 打分写入（夜间评审）              │
         │  ← 每季 reflector 提 prompt 学习             │
         │     → deterministic gate 可逆应用 → replay 验证 │
         └──────────────────────────────────────────────┘
                            ↓ 只读/受限接口
         ┌──────────────── 不变核心（inviolable）─────────┐
         │  订单算术 · 风控规则 · 纪律 agent prompts     │
         └──────────────────────────────────────────────┘
```

关键洞见：**自进化的"权限边界"应由系统结构（类型系统 + 核心代码）保证，而不是由 LLM 的自我约束保证。**

### 关键技术

| 技术 | 说明 |
|------|------|
| **Type-system boundary** | 类型系统划定自演化边界；核心状态不在可编辑类型中 |
| **Nine role-specialised agents** | 4 analysts + Portfolio Manager + protected Risk Manager（共 9） |
| **Typed reports** | analyst 输出**带类型**的报告，而非自由文本 —— 使下游可静态检查 |
| **Protected Risk Manager** | 风控 agent **受保护**，其审计权不可被自修改削弱 |
| **Seven-layer shared memory** | **由代码从系统自身记录装配**（非 agent 自由写入） |
| **Nightly code grading** | **code（不是 LLM）**给每笔交易与预测打分并写入记忆 —— 评分器不是可自改的 |
| **Quarterly reflector** | reflector **提出**学习（不是直接应用） |
| **Deterministic gate** | 确定性门**可逆地**应用 prompt 学习 —— 可回滚 |
| **Replay verification** | 用记录的输入重放验证学习是否有效 |
| **Invariant core** | 订单算术、风控规则、纪律 prompts —— **任何自编辑都到不了** |
| **Untrusted Web content** | 显式把 web 内容视为**不可信输入**（在金融场景尤其关键） |

### 三层分工

| 层 | 职责 | 可否自改 |
|------|------|------|
| 核心层 | 订单算术、风控规则、纪律 prompts | **否** |
| 记忆层 | 七层共享记忆（代码装配） | 是（受控写入） |
| 改进层 | 季度 prompt 学习 | 是（经 gate + replay） |

## 关键实验结果

### 真实部署（five-month live deployment）

| 指标 | 结果 |
|------|------|
| 部署时长 | **五个月** |
| 交易天数 | **102 trading days** |
| LLM 调用总数 | **1,632 LLM calls** |
| 板块回撤 | **24.6% 的 sector drawdown 被控制在 0.3% 的损失** |

### 对照实验（replay of recorded inputs）

| 对照 | 结果 |
|------|------|
| 对照组 | **单一模型**给定**相同原始数据** → **交易更多**，且**五天内相对市场亏损 1.35 点** |
| 联合设计组 | 五天内**无显著亏损（no significant loss）** |
| 注入攻击 | **无任何注入指令被遵从（no injected instruction was followed）** |

### 回测（2015–2026 backtest）

| 设定 | 结果 |
|------|------|
| 时间跨度 | **2015–2026** |
| 随机入场策略数 | **50 种随机 entry policies** |
| 结果 | **核心层（core alone）在全部 50 种策略下都降低了最大回撤（lowering the maximum drawdown under all 50 random entry policies）** |

### 自我改进链条的验证

| 环节 | 结果 |
|------|------|
| Reflector | **追溯主导失败到其根因**（traced the dominant failure to its root cause） |
| Gate 应用的 learning | 该学习**在 trigger evenings 被采纳（on trigger evenings）**，且**在 no control evening 未被采纳** —— 呈现清晰的触发条件性 |

## 关键结论 / 局限性

### 关键结论

1. **"自进化"必须被结构性地关起来**：Steward 的做法是**把自进化的作用域限制在记忆与 prompt 层**，核心逻辑用代码与类型锁死 —— 这比"给 agent 一句别乱改的 instruction"可靠得多
2. **评分器必须不可自改**：夜间打分的执行者是 **code**，不是 LLM —— 否则"自己给自己打分、自己改自己"会形成闭环失效
3. **确定性门 + replay 使自进化可审计、可回滚**：季度学习经门控应用、经重放验证、**可逆**
4. **联合多 agent 结构优于单模型强模型**（至少在此设定下）：同样原始数据，单模型交易更多、亏损更多 —— 提示**角色分工 + 风控独立于分析**本身带来价值

### 局限性

- **金融场景的可外推性有限**：金融有天然的风控规范与低风险偏好，其它领域（研发、内容生成）的"不变核心"如何界定并不显然
- **102 天样本短**：五个月真实部署**不足以覆盖完整市场周期**；单一 regime 下的表现不能外推到高波动期
- **基准与对照规模小**：仅 1 个对照（单模型）、1 个回测（2015–2026）、50 种随机入场策略 —— 统计显著性只在"no significant loss"处出现，其余数字无置信区间
- **风险指标单一**：只报了 drawdown（24.6% → 0.3%）与相对市场的 1.35 点，**未报收益、夏普、换手、交易成本** —— 无法判断这是"更安全"还是"更保守"（可能只是交易更少）
- **"不受遵从注入指令"仅在测试注入下成立**，不构成对 prompt injection 的完整防御论证
- **Reflector 的 root-cause 追溯可能被误判**：论文只给出一个案例，未做反思质量的系统评估
- **未与其他多 agent 金融系统对比**：无外部 baseline
- 无关于成本（LLM 调用成本、延迟）的报告，1,632 次调用的开销未披露
