## 核心贡献

> 提出 **Adaptive Skill Granularity** —— 把"技能粒度"当作一个**由运行时状态决定的动作抽象策略**，而不是执行前固定的资源选择。

1. **现有研究的盲区**：先前工作主要研究 agent 如何**检索、组合、合成**技能（都在执行之前）
2. **新识别的控制问题**：在 coding agent 中，**执行期**还有一个额外问题 —— 同一任务可以通过**原始工具调用、宏技能、或混合执行**（先宏后微降级）来完成
3. **框架设计**：
   - **feature-based granularity controller** —— 基于任务结构、执行状态、宏技能失败信号的粒度控制器
   - **finite-state recovery executor** —— 有限状态恢复执行器
4. **核心结论**：固定粒度执行在匹配任务上**高效但脆弱**；运行时路由 + 显式 macro-to-micro 恢复**提升了鲁棒性**，并能救回固定粒度执行无法解决的受控宏失败

## 技术方案

### 三种执行模式

| 模式 | 说明 |
|------|------|
| Primitive tool calls | 原始粒度，逐步调用工具 |
| Macro skills | 宏粒度，一次性执行封装流程 |
| Hybrid (macro → micro) | 先走宏，失败后降级到微粒度恢复 |

### 控制器设计

```
任务结构 + 执行状态 + 宏技能失败信号
            ↓
   granularity controller（基于特征）
            ↓
   路由决策: primitive / macro / hybrid
            ↓
   finite-state recovery executor（宏失败 → 微降级）
```

### 评测维度

| 指标 | 说明 |
|------|------|
| Success | 由 verifier 定义的确定性成功 |
| Total cost | 总成本 |
| Macro adoption | 宏技能采用率 |
| Failure recovery | 失败恢复率 |
| Route match | 路由与理想路由的匹配度 |
| Transition correctness | 状态转移正确性 |

---

## 实验结论

| 发现 | 细节 |
|------|------|
| 固定宏执行 | 适用时**高效**，但**不匹配时脆弱** |
| 运行时路由 | **更鲁棒** |
| 显式 macro-to-micro 恢复 | 能恢复**受控的宏失败** —— 这正是固定粒度执行留下的未解问题 |
| 综合结论 | 路由 + 恢复优于任何单一固定粒度 |

---

## 局限性

- 采用**确定性 coding-agent 协议**评测，与真实开放式开发环境有差距
- 未给出在真实仓库规模任务上的验证
- feature-based controller 的特征设计与泛化能力未深入分析
- 状态空间为有限状态机，复杂长程场景的覆盖有限

## 实现建议

- **实现难度**: 中（需要定义粒度特征 + 状态机）
- **适用场景**: 已有 skill 库、但经常遇到"宏技能不适用"退回全手工的 coding agent
- **建议起点**: 先加日志统计 —— 你的 agent 里有多少比例的任务启动了宏技能后又回退到逐工具调用
- **价值点**: 把 skill 从"静态资源"重新定义为"可控、可验证、可恢复的执行抽象"，这个视角转换比方法本身更有启发
