# The Intrusion Pathway: How Non-Evidential Context Degrades Language Model Performance

### 核心贡献
1. 首次为「非证据性上下文（non-evidential context）」导致的性能退化给出机制性解释，并将其追踪到一条称为 Intrusion Pathway 的具体计算通路。
2. 定位出稀疏的一组注意力头——intrusion heads——它们是干扰的主要载体，可跨任务、跨干扰类型迁移，并可做类别条件干预。
3. 提出可部署的修复手段：屏蔽约十个 head（约占注意力头的 1%），即可在有限代价下恢复 57% 的性能损失。

### 技术方案
**核心思想**: 非证据上下文（无关领域的陈述或离分布随机 token）没有竞争答案、无语义重叠，却仍能削弱模型表现；其机制被定位到少数 attention head 对 prefix 内容的「错误写入」。

| 技术 | 说明 |
|------|------|
| 通路分解 | MLPs 同时丰富 query-subject 与无关 token 表示；parroting heads 把 prefix token 内容搬运到预测位置；relational readers 大体回避无关来源 |
| 关键反直觉 | 保留了 subject enrichment、selective reading 并不足以阻止 intrusion，干扰发生在更广义的计算中 |
| Intrusion heads | 稀疏注意力头集合：其 prefix-derived writes  promotes 干扰相关内容；正确答案支持度下降主要源于更弱的 non-prefix 贡献，而非 prefix 的直接压制 |
| 可迁移性 | 同一批 head 跨任务、跨 distractor 类型迁移，且与「整合相关上下文证据」的 head 几乎权重不相交（weight-disjoint） |
| Oracle 探针 | 用 clean counterpart 替换被污染的 last-token residual（需配对 clean forward pass），在四个下游任务上平均恢复干扰所致损失的 97.6% |
| 可部署干预 | mask level knockout 约十个 head（约 1% 注意力头），恢复 57%，对有用上下文代价有限 |

### 实验结果
- **数据集**: 四个下游任务（摘要未列出具体任务名），干扰类型涵盖无关领域陈述与离分布随机 token
- **基线**: 未干扰的 clean 模型前向；以及相关性证据整合 head 的对照
- **结果**: Oracle residual 替换平均恢复 97.6% 的干扰损失；可部署的 ~10 头（≈1% 注意力头）屏蔽恢复 57%，对有用上下文影响有界

### 局限性
- Oracle 探针需要一次配对的 clean forward pass，实际部署不可行；真实可部署方案仅恢复 57%
- 论文体量极大（32 页、25 图、29 表），摘要未说明所用模型规模、任务清单与各 head 干预的逐任务数字
- 权重不相交性结论可能依赖具体模型与干扰构造方式，跨模型泛化性未说明

### 关键洞见
> 干扰并非来自「模型读错了无关内容」，而是来自一组 intrusion heads 用 prefix 写入挤占了本该由 non-prefix 证据贡献的信号——所以正确答案支持度的下降主要源于「非前缀贡献变弱」而非前缀的直接压制；这既解释了为何单纯的注意力读取分析会低估风险，也直接给出了只需动 ~1% 注意力头的低成本修复路径。
