# Category-Anchored Large Language Models for Next POI Recommendation

## 摘要
Next POI 推荐试图从时空签到数据预测用户下一个目的地。近年工作把 LLM 引入该任务，方式是把轨迹文本化以利用其语义推理能力，但**直接生成 POI 标识符不可靠**：POI 是稀疏、本地化、长尾且自然语言语义弱的实体，造成高层移动意图与具体 POI 预测之间的 **semantic-to-entity gap（语义—实体鸿沟）**。作者提出 **ANCHOR**：category-anchored 框架。① **Semantic Intent Pre-estimation**：让 LLM 在紧凑稳定的**类别空间**中估计移动意图（而非生成 POI ID）；② **Multi-Source Candidate Grounding**：结合三类移动证据——category anchors、history POI memory、user preferences——把意图落到具体候选集，并施加来源配额防止单一来源主导；③ **History-Aware Reranking**：让每个候选 POI 用 target-attention 式的候选—历史交互，选出与用户历史移动模式匹配的最终 POI。在 **Foursquare-NYC / TKY / Gowalla-CA** 三个真实签到数据集上，ANCHOR 在 Acc@1/5/10 与 MRR 上全面优于传统、图结构增强与 LLM 基线（如 NYC Acc@1 0.4138，MRR 0.5335），且 prompt token 开销更低。

## 核心贡献
1. **识别并命名 semantic-to-entity gap**，提出 reason–ground–discriminate 分解（意图推理 → 候选落地 → 候选判别）。
2. **类别锚定的语义意图预估计**：把 LLM 输出限制在预定义类别空间的分类任务上（LoRA 微调 + 序列分类头），彻底避免实体幻觉。
3. **多源候选 grounding + 配额控制**：LLM 类别 POI / 历史 POI 记忆 / 用户偏好扩展三源召回，配额分别为 800/100/200（池大小 2000），防止大源淹没小源。
4. **History-aware reranker**：候选—历史 cross-attention（target attention 思想）+ 三类上下文 query 自适应聚合。
5. **消融与参数敏感性分析**：验证 LightGCN 初始化、LLM 锚点、多源 grounding、reranker 四者各自必要；揭示 coverage 与 ranking quality 的非单调权衡。

## 方法与架构
**任务定义**：check-in $q=(u,p,c,t,g)$，$c$ 为 POI 类别，$g=(lat,lon)$；轨迹 $T_u=\langle q_1,\dots,q_n\rangle$，$t_i<t_{i+1}$。模型输出排序列表：

```math
\hat Y_u = \mathrm{TopK}_{p\in P}s(p\mid T_u, t_{n+1})
```

**模块 1：Semantic Intent Pre-estimation via LLM**

*Trajectory prompting*——紧凑字段化序列化（而非逐条句子展开，以避免 prompt 长度随历史膨胀）：

```math
X_u = \mathrm{Prompt}(T_u, u, t)
```
prompt 分四块：Instruction（"predict the POI category of the target check-in"）、History（格式 `trajectory id | time | day of week | norm in day time | poi category`）、Current（目标 trajectory id + 时间上下文，**类别被 mask**）、Output（"Return the target POI category only."）。

*LLM Category Classifier*——在 base LLM 上挂序列分类头，输出维度为类别数 $|C|$：

```math
P_\theta(c\mid X_u)=\mathrm{softmax}\!\left(f^{\mathrm{cls}}_\theta(X_u)\right)_c,\quad c\in\mathcal C
```

*LoRA 微调*——注入到 attention 的 q/k/v/o 投影与 FFN 投影，backbone 冻结：

```math
W'=W+\Delta W,\qquad \Delta W=\frac{\alpha}{r}BA
```
分类头用交叉熵：

```math
\mathcal L_{\text{cat}}=-\frac{1}{|D_{\text{cat}}|}\sum_{(X_u,c^*_u)\in D_{\text{cat}}}\log P(c^*_u\mid X_u)
```

**模块 2：Multi-Source Candidate Grounding**

*候选来源*：LLM-category POIs（top-$K_c$ 类别下的 POI，语义 grounding）、History POI memory（重复与近期 POI，捕捉 revisit 行为）、User-preferred category expansion（长期/近期/目标时刻偏好，个性化扩展）。

*Grounding prior*：

```math
r(p)=r_{\text{llm}}(p)+r_{\text{pref}}(p)+r_{\text{hist}}(p)
```
```math
r_{\text{llm}}(p)=w_{\text{llm}}\cdot\frac{1}{\log(\mathrm{rank}(c_p)+1)}
```
```math
r_{\text{hist}}(p)=w_{\text{rep}}\log(1+n_u(p))+w_{\text{rec}}\sum_{i:p_i=p}\frac{1}{\log(\Delta_i+1)}
```
```math
r_{\text{pref}}(p)=w_{\text{long}}\phi_{\text{long}}(c_p)+w_{\text{recent}}\phi_{\text{recent}}(c_p)+w_{\text{time}}\phi_{\text{time}}(c_p)
```
其中 $n_u(p)$ 为访问次数、$\Delta_i$ 为第 $i$ 次访问到目标时刻的位置距离。

*配额控制选择*：先在每个来源内部按 grounding prior 排序并按配额取 top（history 100 / LLM anchor 800 / preference 200），合并去重得初始池；不足 $N$ 时用未选中的最高分候选补齐，避免 LLM-category 这一大源独占。

**模块 3：History-Aware Reranking**

*表征*：历史 check-in 融合 POI、类别、时间、轨迹位置嵌入后线性投影：

```math
h_i=\mathrm{Proj}_h\!\left([e^{poi}_i; e^{cat}_i; e^{time}_i; e^{pos}_i]\right),\qquad H_u=[h_1,\dots,h_n]
```
POI 嵌入用 **LightGCN** 在 POI 转移图上预训练初始化；候选侧：

```math
v_p=\mathrm{Proj}_c\!\left([e^{poi}_p; e^{cat}_p; e^{reg}_p; x_p]\right)
```

*当前上下文 query*——三类 query 并自适应聚合：

```math
s_u=\sum_{i=1}^{n}\beta_i h_i
```
```math
q_t=\mathrm{Proj}_t([e^{dow}_{t^*}; e^{bin}_{t^*}; e^{\Delta}_{t^*}]),\quad
q_{tr}=\mathrm{Proj}_{tr}([e^{poi}_{prev}; e^{cat}_{prev}; e^{\Delta}_{t^*}]),\quad
q_s=\mathrm{Proj}_s([h_n; s_u])
```
```math
[\hat q_t;\hat q_{tr};\hat q_s]=\mathrm{SelfAttn}([q_t;q_{tr};q_s]),\qquad
q=\mathrm{AttnPool}(q_s,[\hat q_t;\hat q_{tr};\hat q_s])
```
（用 $q_s$ 作 pooling query，因为近期历史状态是天然锚点。）

*候选—历史注意力*：

```math
\alpha_{p,i}=\mathrm{softmax}_i\!\left(\frac{v_p^\top h_i}{\sqrt d}\right),\qquad
c_p=\sum_{i=1}^{n}\alpha_{p,i}h_i
```
```math
\tilde v_p=\mathrm{LN}\big(v_p+\mathrm{MLP}([v_p;c_p;v_p\odot c_p])\big)
```
*上下文感知打分*：

```math
z_p=[\tilde v_p\odot q;\ \tilde v_p\odot q_t;\ \tilde v_p\odot q_{tr};\ \tilde v_p],\qquad s(p)=\mathrm{MLP}_s(z_p)
```
训练损失：

```math
\mathcal L_{\text{rank}}=-\log\frac{\exp(s(p^*))}{\sum_{p'\in P_{\text{cand}}}\exp(s(p'))}
```

**评测指标**：

```math
Acc@K=\frac{1}{|D_{\text{test}}|}\sum_{q\in D_{\text{test}}}\mathbb{1}(r_q\le K),\qquad
MRR=\frac{1}{|D_{\text{test}}|}\sum_{q\in D_{\text{test}}}\frac{1}{r_q}
```

## 实验设置
- **数据集**：Foursquare-NYC（1,075 用户 / 5,099 POI / 318 类 / 104,074 签到 / 14,160 轨迹，2012-04 至 2013-02）、Foursquare-TKY（2,281 / 7,844 / 291 / 361,430 / 44,692，同期）、Gowalla-CA（4,318 / 9,923 / 301 / 250,780 / 32,920，2009-02 至 2010-10）。预处理：去除签到数 < 10 的 POI 与用户；按时间顺序以 **80%/10%/10%** 在**轨迹级**划分（轨迹为不可分割单元）。
- **模型配置**：base LLM **Qwen2.5-7B-Instruct** + LoRA（rank $r=16$，dropout 0.05）；最大历史长度 50 条签到；最大序列长度 2560 token；分类器训练 5 epochs，lr **5×10⁻⁵**，batch size 4，gradient accumulation 4。Grounding：top-**10** 类别，候选池 **2000**，配额 history/LLM/preference = **100/800/200**。Reranker：LightGCN 初始化 POI 嵌入 + 两层 Transformer（hidden 256），AdamW，lr **1×10⁻⁵**，weight decay 0.02，early stopping patience 10。硬件：**4 × NVIDIA GeForce RTX 4090**。
- **基线**：PRME、LSTM、PLSPL、STAN、GETNext、STHGCN、ROTAN（传统/时空/结构增强）+ LLM4POI、GNPR、GA-LLM、Think2Go（LLM 类）。

| 变体 | NYC | TKY | CA |
|---|---|---|---|

| w/o LightGCN | 0.3875 (−6.33%) | 0.3341 (−7.25%) | 0.2581 (−1.97%) |

**语义意图预估计有效性**：Category Acc@10 在 NYC/TKY/CA 分别为 **0.8267 / 0.8967 / 0.6105**，$K=50$ 时升至 **0.9422 / 0.9806 / 0.8324**。用 MLP 或 Transformer 替代微调 LLM 作类别预测器（ANCHOR-MLP / ANCHOR-Trans）在类别级与最终 POI 级 Acc@1 上均劣于 ANCHOR。

**冷启动分析（Table VI，Acc@1 vs GA-LLM）**：Inactive 组——NYC 0.3270 vs 0.3365（**输**）、TKY 0.2879 vs 0.3276（**输**）、CA 0.2872 vs 0.2655（赢）；Normal 组——NYC 0.4750 vs 0.4416、TKY 0.3607 vs 0.3513、CA 0.2573 vs 0.2498（**全赢**）；Very active 组——NYC 0.4263 vs 0.4129、TKY 0.4089 vs 0.3483、CA 0.2592 vs 0.2437（**全赢**）。

**参数敏感性**：类别数 $K_c$ 增大时 LLM Category Hit 与 Candidate Hit 单调上升，但 **Acc@1/MRR 非单调**——$K_c$ 过大引入噪声候选、削弱语义选择性。候选池 $N$ 从 100 → 3000 时 Candidate Hit 单调上升，但 NYC 的 Acc@1 在 **N = 1500** 达峰后回落；评测速度随 $N$ 增大明显下降（图中 eval samples/s 从 50+ 降至约 10 量级）。

**效率（Fig. 5，NYC）**：ANCHOR 位于 token 消耗–准确率平面的左上角（Acc@1 最高、prompt token 较少），优于 LLM4POI、GNPR、GA-LLM、Think2Go。

## 局限性
- 作者自述（体现在分析中而非独立 Limitations 节）：① 极端冷启动（Inactive 用户）下 ANCHOR 在 NYC/TKY 反而不如 GA-LLM——历史信息不足时 history-aware reranker 优势受限；② $K_c$ 与 $N$ 都存在覆盖-排序-效率的非单调权衡，说明"更多候选"并不等于更好结果；③ LLM Category Acc@10 在 CA 仅 0.6105，语义锚点在长尾数据集上质量下降明显。
- 我的批判性意见：① 全部结论基于 2012–2013 年的 NYC/东京与 2009–2010 年的 Gowalla 数据（**最老近 15 年**），与当代 POI 分布和签到行为差异巨大；② 基线中 LLM4POI、GNPR、GA-LLM 只报告 Acc@1，无 Acc@5/10/MRR，**无法与 ANCHOR 做完整对照**，而 Think2Go 是唯一提供完整指标的 LLM 基线——"全面超越 LLM 基线"的表述因此被高估；③ 候选池大小 2000、top-10 类别这些超参在 NYC 上调优，未验证跨数据集稳健性；④ 无消融显示 grounding prior 的六项权重（$w_{\text{llm}}, w_{\text{rep}}, w_{\text{rec}}, w_{\text{long}}, w_{\text{recent}}, w_{\text{time}}$）的影响，也没有与端到端训练分类器的对比——"用 LLM 而非 MLP/Transformer"的增益可能主要来自参数量而非"语义锚定"机制本身；⑤ 未报告推理延迟的绝对数值与 GPU 显存占用，"效率优势"仅以 token 数量间接论证。

## 评估与建议
- 是否推荐深入阅读：**是**（"不让 LLM 直接预测稀疏实体，先做语义锚定再落地"的思路可迁移）
- 适用场景：推荐系统中 LLM 与结构化/图模型结合的架构设计；实体空间稀疏长尾的生成式推荐；grounding 候选生成与 rerank 的两阶段范式
- 与知识库的关联：与 LLM4Rec / GraphGPT / CoLLM / CORAL 等 LLM×推荐工作、LightGCN 图嵌入、target attention 直接相关；也适合与"检索-重排"类 RAG 架构对照阅读
