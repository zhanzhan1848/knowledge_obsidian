# On Turn-Level Best-of-N Sampling for Scaling LLM Agents

> **arXiv**: [2611.06868](https://arxiv.org/abs/2611.06868)
> **发表日期**: 2026-11-04
> **分类**: cs.AI
> **会议/期刊**: arXiv preprint

## 📋 摘要

本文评估一种简单的**推理期扩展（inference-time scaling）**方法——**turn-level best-of-N sampling**——用于在复杂、长程（long-horizon）任务上扩展 LLM agent。作者用 **generator-selector** 框架实例化该方法，包含两个 LLM：在每一轮（turn），**generator** 模型生成 $N$ 个候选动作，**selector** 模型从中选出其一并在环境中执行。本文与使用 critic 模型做推理期引导搜索的工作（Zainullina et al., 2025, guided search）密切相关，但不同之处在于，作者评估的是**现成的、开放权重的 LLM 是否能够直接比较不同候选动作**。在长程 terminal 任务上的实验表明，该方法能带来显著性能提升，在**准确率（5–10%）**与**多次重复尝试之间的一致性**两方面均有改善。对 agent 轨迹的分析揭示了行为向更可取模式的转变，例如**完成任务所需尝试次数减少**、任务指令遵循改进，以及更好的调试与测试行为。

## 🎯 核心贡献

1. **提出并评估 turn-level best-of-N sampling**：把 best-of-N 的粒度下放到"每一轮 agent 动作"而非整条轨迹，属简单但有效的推理期扩展策略。
2. **generator-selector 双模型框架**：generator 产生 $N$ 个候选动作，selector 选一个执行；关键问题是 **现成的开放权重 LLM 能否直接胜任候选动作比较**（而非训练专用 critic）。
3. **显著提升准确率与一致性**：准确率提升 **5–10%**，且多次重复尝试之间的表现一致性明显改善（consistency across repeated attempts）。
4. **行为层面的定性证据**：轨迹分析显示 agent 行为转向更优模式——完成任务的尝试次数减少、指令遵循更好、调试与测试更充分。

## 🔧 方法/架构

**Turn-level best-of-N 采样（generator-selector）**

在第 $t$ 轮交互：

1. **Generator** 依据当前历史 $h_t$ 生成 $N$ 个候选动作：
$$
\mathcal{A}_t = \{a^{(1)}_t,\dots,a^{(N)}_t\},\qquad a^{(n)}_t \sim \pi_{\text{gen}}(\cdot \mid h_t)
$$
2. **Selector**（可以是与 generator 同构或不同构的开放权重 LLM）在候选中做比较与选择：
$$
a_t = \arg\max_{a \in \mathcal{A}_t} s_{\text{sel}}(a \mid h_t, \mathcal{A}_t)
$$
3. 选中的 $a_t$ 被送入环境执行，环境反馈写入历史，进入下一轮。

与整条轨迹级别的 best-of-N 相比，turn-level 的优势是**反馈更密**：每一步都有一次"选择"，因此错误在早期就被纠正，不必等整条轨迹跑完；同时比 guided search（critic 参与搜索）更简单，只需一次比较。

**与相关工作的差别**
- *Guided search（Zainullina et al., 2025）*：用 critic 模型在推理期做引导式搜索；
- *本文*：不训练 critic，直接检验**现成开放权重 LLM 能否直接比较候选动作**。

## 📊 实验结果

- **准确率提升：5–10%**（在长程 terminal 任务上）。
- **重复尝试一致性**：across repeated attempts 的一致性显著改善。
- **行为分析**：完成任务所需尝试次数减少；任务指令遵循改进；debugging 与 testing 行为更充分。
- 摘要未披露具体基准名称与逐任务分数（详见原文实验章节）；涉及模型为 off-the-shelf open-weight LLM。

## ⚠️ 局限性

- **推理成本成倍增长**：每轮需 generator 生成 $N$ 个候选 + selector 比较，长程任务下延迟与 token 消耗显著增加（摘要未给出成本量化）。
- selector 的比较质量直接决定收益；selector 若本身偏弱，可能选出更差的候选。
- 实验仅覆盖 **terminal 类长程任务**，未验证 web/软件工程等长程 agent 场景。
- 摘要未披露具体基准、模型规模与统计显著性，也未给出 N 的敏感性分析。
- 与 guided search 的正面 head-to-head 对比缺失。

## 💡 建议

- 是否推荐使用：是（作为低成本推理期增强的参考实现）
- 适用场景：已有可用 generator 且愿意增加一轮 selector 调用的长程 agent（终端任务、代码 agent、运维 agent）；希望在**不训练任何专用 critic** 的前提下拿到 5–10% 准确率提升的团队；关注多次运行稳定性（consistency）而非仅单次峰值的场景。
