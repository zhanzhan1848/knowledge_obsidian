## 核心贡献

> 提出 **TeCoP** —— **免训练**（training-free）dLLM 解码器。核心洞察：dLLM 效率低是因为把「某个预测**是否可被不可逆提交**」与「它**作为上下文有多大用**」这两件事**耦合**了。TeCoP 用错开的块并行流水 + draft-and-verify 把两者解耦。

1. **角色解耦**：committed token（已提交）vs provisional cross-block context（暂定跨块上下文）
2. **机制**：复用稳定但未提交的预测作为**临时上下文**；提交由**置信度 + 稳定性检查**把关
3. **免训练**：无需额外训练或微调
4. **大幅提速**：前向评估次数减少 **87%**；无 KV cache **7.50x** 吞吐、有 cache **11.77x**

---

## 技术方案

### 问题诊断

块式（block-wise）解码器**串行化生成**，反复重算稳定的预测。根因是耦合：

```math
\underbrace{\text{readiness for irreversible commitment}}_{\text{何时定稿}}
\ \text{coupled with} \
\underbrace{\text{utility as context}}_{\text{作上下文的作用}}
```

### TeCoP 解耦

| 角色 | 处理方式 |
|------|---------|
| **暂定上下文** | 稳定但未提交的预测**复用**为临时跨块上下文 |
| **提交** | 由**置信度 + 稳定性检查**双重把关 |

通过**错开的块并行流水（staggered block-parallel pipelining）** + **draft-and-verify** 实现。

```math
\text{commit}(x_i) = \mathbb{1}\big[\text{conf}(x_i) > \tau_1 \;\wedge\; \text{stable}(x_i)\big]
```

### 支持模式

- 无 KV caching
- 有 KV caching

## 实验结论

| 指标 | 结果 |
|------|------|
| 前向评估次数减少 | **最高 87%** |
| 吞吐提升（无 cache） | **最高 7.50x** |
| 吞吐提升（有 cache） | **最高 11.77x** |
| 覆盖 | 4 个 LLaDA / Dream dLLM × 3 基准（GSM8K, Minerva MATH, MBPP）= **12 组设置** |
| 对比 | **全部 12 组**吞吐优于 Fast-dLLM 与 DSB（有/无 cache 均是） |
| 精度 | 有 cache 平均精度**在原解码器 1 pp 以内** |

---

## 局限性

- 仅在 LLaDA / Dream 两类 dLLM 上验证
- 置信度 + 稳定性阈值需调参，跨域迁移性未验证
- 错开流水对硬件调度有要求，吞吐数字与 kernel 优化程度耦合
- 精度 1pp 内的说法基于**平均**，个别设置可能有更大波动
