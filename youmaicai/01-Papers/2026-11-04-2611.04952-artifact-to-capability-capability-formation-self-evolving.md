## 核心贡献
1. **提出并定义"能力形成"（capability formation）的五个顺序依赖属性**，构成从 artifact 到 capability 的诊断框架：
   1. **Artifact formation**：持久结构已形成并连接到后续决策；
   2. **Behavioral activation**：同状态同接口下，有无 artifact 的动作差异超过采样噪声；
   3. **Task-relation realization**：artifact 产生**正向效果**——所得动作整体上更好地满足相关任务关系，而不只是与原动作不同；
   4. **Boundary-safe reuse**：artifact **不破坏已建立的效果**——在实际决策中，已建立的正向关系没有被系统的另一部分推翻；
   5. **Capability extension**：后续版本**新增正向效果的同时保留既有效果**。

   依赖结构为 $1\to 2\to (3 \text{ and } 4)\to 5$，称为**能力链（capability chain）**；属性 3 与 4 共同构成**能力形成的检查点（checkpoint）**。诊断按此顺序进行：**第一个失败的属性就是"断点"（the break）**，依赖它的属性不再判定。
2. **提出"三尺度诊断"（three-scale diagnosis）**：状态级（state-level，配对比较同状态上有/无 artifact 的走子）、博弈级（game-level，在完整对局中看已建立效果是否被推翻）、谱系级（lineage-level，沿版本谱系统计新通过与丢失的状态）。
3. **引入"系统级"分析单元**：判定对象是**冻结的系统整体**（所有实际参与决策的 artifact），而非单个组件——因为单个组件可能自身正确，却在组合后效果被另一组件推翻。以组件为单元会把失败归咎于"某个写得差的 skill"，而无法判断系统整体是否形成了能力。
4. **关键概念区分：任务关系 vs 环境规则**。任务关系由任务目标定义（如走出自己的立即胜点、封堵对手的、形成活四）；**环境规则（如不落在已有子的交叉点）不是任务关系**——每个合法动作都满足它们，但它们不推进任何目标。因此属性 3 **只比较合法动作**，减少规则违规本身不算正向效果。
5. **三个反例，各自断在不同的属性上**（同一基座模型 DeepSeek-V4-Flash、同一环境、同一对手）：
   - **Reflexion：legalization gain（合法化增益）**。记忆使走子改变率超过噪声（59.8%–78.2% vs 噪声基线 46.7%），总体 pass rate 上升（B 集 8.0% → 9.2%–10.3%；A 集 21.7% → 22.5%–27.5%）。但由恒等式 $\text{P(pass)}=\text{P(legal)}\times\text{P(pass|legal)}$，**总体 pass rate 的上升完全来自合法性率上升**——六个记忆在 12 个组合中**没有一个改善合法 pass rate**，在更大、噪声更低的 B 集反而下降 1.6–4.4 个百分点。**记忆抑制了规则违规，却没有产生选择增益。断点在属性 3。**
   - **Voyager：compositional override（组合覆盖）**。组件消融使走子在 89–808 个 B 状态上改变；从 round1 到 full 有 459 个新通过、73 个丢失，**属性 3 成立**；对局中的活四从 0/20 升到 20/20。但博弈级诊断中，Voyager **在全部 20 局都到达立即胜点状态，却一局也没能在其上连成五子（0/20）**——反而封堵了对手的立即胜点并输掉全部 20 局。全部 20 局都是冲突状态。调用追踪定位到机制：`auto_player` 的 defense-first 早返回在冲突状态下**先于**自身的立即胜点检查触发，于是 `evaluate_threats` 的 "win if possible" 逻辑与自身的立即胜点检查都从未被触及。**每个组件单独看都正确，组合起来却推翻了已建立的效果。断点在属性 4。**
   - **DGM：loss-only drift（只丢不增的漂移）**。OB-3 通过检查点（相对 P0 有 522 个新通过、139 个丢失，净 +383；20 局中在全部 19 个立即胜点状态连成五子，19/19；赢 19 局）。但后续版本 OB-5 与 OB-6 **没有任何新通过状态，只有丢失**（0/−103、0/−29），胜场跌到 0；OB-7 与 OB-6 在 7,234 个状态的差异池中**只差 1 个状态**，其修改几乎未进入实际决策。**与此同时 evolutionary score 仍从 OB-3 升到 OB-5。断点在属性 5。**
6. **核心结论：信号式评估无法判定能力是否形成**。三个反例都同时呈现了三个代理信号（artifact 累积、行为改变、指标上升），却各自在不同的属性上断裂——**三个断点落在不同属性上也说明没有任何一个属性可以替代另一个**。
7. **给出 GUI agent 的迁移猜想**（明确标注为**未经测试的猜想**）：Skill A 移动光标并点击（可达目标、落在非交互区、或打开无关页面）；只修复畸形坐标的版本将产生 legalization gain；Skill B 先点掉弹窗再移动到自己目标，单独可达，但当 B 在 A 之后运行时，**它的第一次点击会命中 A 刚到达的页面中光标下的任何东西并导航离开**——构成对 A 已建立效果的 compositional override。

## 问题背景
自我进化 agent 通过与环境交互生成 artifact（文本反思、可执行技能、代码），并将其注入 harness 以便在后续任务中复用。领域内通常用三个信号论证方法有效：**artifact 累积、加载后行为改变、准确率/pass rate/进化分上升**。作者称之为**信号式评估（signal-based evaluation）**。

作者指出三个信号**都是能力的代理**，没有一个直接检验：改变后的行为是否推进了任务？已建立的效果是否被系统的另一部分推翻？后续进化是否建立在已获得之上？更根本地，"有效"应指什么从未被定义。

已有工作多以 episode、版本或工具为分析对象（过程导向评估、outcome analysis）。要回答本文的问题，必须**把"从 artifact 到 capability 的转变本身"作为对象**：观察单个动作如何改变、该改变是否在实际决策中存活、以及它是否跨版本迁移。

这类观察在开放式任务中难以进行：状态无法精确重放、动作正确性缺乏独立判据、环境噪声与无结构状态混淆归因。因此作者转向**受控环境**——受 Li et al. (2023)（用受控棋局序列研究世界模型表示）启发，选择**自由五子棋（freestyle Gomoku，无禁手规则）**作为自我进化机制的"显微镜"。

## 方法

### 1. 五个诊断属性

1. **Artifact formation**：持久结构已形成且连接到后续决策；
2. **Behavioral activation**：在相同状态与接口条件下，有/无 artifact 的动作差异超过采样噪声；
3. **Task-relation realization**：artifact 产生正向效果——结果动作整体上更好地满足相关任务关系；
4. **Boundary-safe reuse**：artifact 不破坏已建立的效果——在实际决策中，已建立的正向关系不被系统的另一部分推翻；
5. **Capability extension**：后续版本新增正向效果同时保留既有效果。

属性 4 只关注**在实际决策中被推翻的**已建立正向关系；固定状态上的得失已计入属性 3。属性 5 只对通过检查点的版本有意义。

### 2. 三尺度诊断（Table 1）

| 尺度 | 判定的属性与判据 | 为何可行 |
|---|---|---|
| **状态级** | 在相同状态上比较有/无被测 artifact 的走子。属性 2：走子改变超过采样噪声。属性 3：合法走子中的 pass rate 上升 | 状态完全相同、被测 artifact 是唯一差异，故任何走子变化只能来自它。规则程序独立指定可接受走子，从而区分"变好了"与"只是变了" |
| **博弈级** | 冻结系统与程序化对手下完整对弈。属性 4：在每个立即胜点状态完成五连 | 在立即胜点状态，"一手获胜"已确立且规则指定唯一正确走子。未能连成五说明系统的另一部分推翻了该效果，**故不需要对照组** |
| **谱系级** | 在相同状态上逐状态比较相邻版本，并比较胜场。属性 5：后续版本保留既有效果同时新增；只丢不增、或行为几乎不变则失败 | 配对的状态级比较精确显示每个版本新增或丢失了什么，以及其修改是否仍能到达行为 |

### 3. 环境：自由五子棋

三个性质使三尺度诊断成为可能：**可重放状态**（任意棋盘可精确恢复，故状态级诊断可在同状态上比较有无 artifact 的走子，集合 A 还可通过旋转与反射扩充）、**规则判定的任务效果**（一个规则程序独立于被诊断系统和其他模型枚举每个状态的可接受走子）、**完整记录的对局与版本**（每步走子、调用路径、版本全部归档）。

棋盘 15×15；双方轮流在空交叉点落子；落在已有子的点或盘外为非法；横/竖/斜连成五子获胜；局长按步数计。**立即胜点**（immediate winning point）：一步能连成五的点。**立即胜点状态**：轮到 agent 且 agent 有立即胜点；若对手也有则为**冲突状态**。**活四**（open four）：四子连且两端皆空；**活三**：三子连且两端皆空。规则程序给出每个状态的**可接受集 $G(s)$**；$G(s)$ 中的走子称为 pass，集合中通过状态的比例即 **pass rate**。三个对手均为程序化（rule-based、threat-aware、search_2；最强的 search_2 前瞻两步）。

**任务关系 vs 环境规则**：任务关系由任务目标定义（走出自己的立即胜点、封堵对手的、形成活四）；环境规则（如不落在已有子的交叉点）不是任务关系——每个合法动作都满足它们，却不推进任何目标。

### 4. 实验设计

三个机制用**同一基座模型（DeepSeek-V4-Flash）、同一环境、同一对手**自主进化，之后冻结并接受三尺度诊断。**所有判断只依赖实验数据与规则。**

**状态集**：共 **1,876 个固定状态**——集合 A 含 120 个由人工构造的战术状态经旋转与反射得到的状态；集合 B 含 1,756 个从 DGM 进化过程中的真实对局中抽取的状态。

**对照组（移除被测 artifact）**：Reflexion → 空记忆；Voyager → round1（只保留第一轮的战术技能，calling script 不变）；DGM → 初始策略 P0。对 Voyager 与 DGM，这样测的是"**进化所新增的东西**"的效果。因 Reflexion 对走子有采样，用**两次空记忆运行之差**作为噪声基线。

**博弈级诊断**：冻结系统对 search_2 下 20 局（每局不同随机种子）。每步后重建棋盘，识别全部立即胜点状态，记录系统是否连成五；对未连成的局保留逐步调用追踪用于解释。

**谱系级诊断**：只适用于有版本谱系的机制（DGM）。在 OB-3（对 search_2 胜场最多的进化版本）上判定属性 1–4，再用谱系级诊断检验后续版本是否保留并扩展其效果。沿主谱系逐状态比较相邻版本（集合 B），统计新通过与丢失状态，并比较胜场。另建 7,234 个状态的差异池（来自归档的进化对局），比较最后两版 OB-6 与 OB-7 在每个状态上的走子。

### 5. 三个机制的 artifact 形态

- **Reflexion**：把对局反馈写入文本记忆，按对手与反馈类型切分为六格、每格七条，全部被测。反馈类型分 `outcome`（只给结果）与 `trace`（给完整走子序列）。模型直接选走子。
- **Voyager**：把经验写成可执行技能，只负责检测棋盘特征或提出候选（如 `detect_immediate_wins` 找立即胜点，`create_open_three` 提出形成活三的攻击走子）。最终走子由 agent **自己写的** calling script `auto_player` 决定——按固定顺序查询技能，一旦某个命中就返回。
- **DGM**：直接修改策略代码，产生谱系 P0 → OB-1 → OB-2 → OB-3 → OB-5 → OB-6 → OB-7（OB-4 是旁支）。

## 实验结果

- **Dataset/Task**：自由五子棋（15×15），三个程序化对手；1,876 个固定状态（集合 A 120 / 集合 B 1,756）+ 7,234 状态的差异池；20 局对 search_2 的博弈级诊断。

- **Main results（Table 2，三个机制的信号与三尺度诊断结果）**：

| 机制 | 三个信号 | 状态级：属性 3 | 博弈级：属性 4 | 谱系级：属性 5 | 断点 |
|---|---|---|---|---|---|
| **Reflexion** | 六格、每格七条记忆；走子在 **59.8%–78.2%** 的 B 状态上改变（噪声 46.7%）；总体 pass rate 在 B 上从 **8.0%** 升到 **9.2%–10.3%**，在 A 上从 **21.7%** 升到 **22.5%–27.5%** | **合法 pass rate 在 12 个组合中无一改善；失败** | 不判定 | 不判定 | **属性 3** |
| **Voyager** | 七个技能 + calling script；消融组件使走子在 **89–808** 个 B 状态上改变；活四从 **0/20 升到 20/20** | round1→full：**459 个新通过、73 个丢失**（成立） | **在 0/20 个立即胜点状态上连成五；失败** | 不判定 | **属性 4** |

（OB-7 与 OB-6 在 7,234 个状态的差异池中只差 **1 个状态**。）

- **Ablations / 关键分解**：
  - **Reflexion 的分解**：$\text{P(pass)}=\text{P(legal)}\times\text{P(pass|legal)}$；六个记忆在 12 个组合中**全部提高总体 pass rate 与合法率，却全部降低合法 pass rate**（Figure 5）；空记忆重跑本身把三个率改变 +2.5%、+2.4%、+0.6%。在双方都产出合法走子的状态上净变化为负。
  - **Voyager 的机制解释**：20 局独立对局收敛到 4 条走子序列（G1–G4）；每条序列中 Voyager 走出活四且其两个立即胜点（蓝星）保持为空。第 19 步的冲突状态下，`auto_player` 在 defense 分支早返回，**反而封堵了 search_2 的一个立即胜点**（橙圈），search_2 在第 20 步于另一侧连成五（橙线）。
  - **DGM 的"进化分仍上升"**：OB-3 到 OB-5 的 evolutionary score 仍上升（Appendix D.1），但实质能力在流失——**指标信号与能力断裂脱钩的直接证据**。
  - 属性 1 对三个机制均成立，并直接从调用记录确认（Reflexion 的记忆进入每次走子 prompt；Voyager 的技能库与 auto_player 每步都被调用；每个 DGM 版本都提供 evaluator 调用的 `select_move` 函数）。

## 关键洞察
1. **"信号式评估"这一命名本身就是本文最有价值的贡献**。绝大多数自进化论文用三个代理信号论证有效性，却从未定义"有效"指什么。本文不做改进，而是**先定义再判定**——把讨论从"哪个方法分数高"提升到"分数是否对应能力"。
2. **属性 3 的关键设计是"只比较合法动作"**。这一条把"减少规则违规"从"能力"中彻底剥离。Reflexion 的例子说明这个区分是决定性的：它的 pass rate 上升 1.2–2.3 点，全部来自合法化，而在合法走子中的选择质量**在 12 个组合中无一改善**，在噪声更低的 B 集上还掉了 1.6–4.4 点。**没有这条区分，"反思提升了棋力"就是成立的错误结论。**
3. **"系统级"分析单元的选择避免了归因谬误**。Voyager 的失败若按组件归因，会得到"evaluate_threats 写错了"或"auto_player 逻辑有 bug"——但实际上**每个组件单独看都正确**（`evaluate_threats` 的 "win if possible" 正确、auto_player 的 defense-first 规则在只有对手有立即胜点时合理、create_open_three 正确地驱动形成活四的攻击），错的是**组合**：频繁的冲突状态让 defense-first 早返回永远先于自身的立即胜点检查触发。作者的表述"每个组件单独看都正确，组合起来却推翻了已建立的效果"精确命名了这类失效。
4. **博弈级诊断用"立即胜点状态"实现了无需对照组的因果判断**——因为规则指定了唯一正确走子，"未能连成五"本身就证明了有别的东西推翻了它。这是一个干净的设计，比"移除 artifact 再比"更强。
5. **"只丢不增的漂移"是一个此前被忽视的失效模式**。DGM 的 OB-3 确实形成了能力（19/19 立即胜点、净 +383 状态），但后续版本只丢不增，胜场跌到 0，而 **evolutional score 仍在上升**。这说明**常用的进化指标（fitness）与能力延续可以完全脱钩**——这对所有用 fitness 选代的自进化系统是个警告。
6. **"能力链"是顺序依赖的，因此诊断必须按序停止**。第一个失败的属性即断点，依赖它的属性不再判定。这使得"某个系统形成了能力"成为一个有明确判据的、可否证命题。
7. **三个断点落在三个不同属性上，本身就是一项论证**：**没有任何一个属性可以替代另一个**（例如不能用"行为改变"代替"任务关系实现"）。这是对任何想用单一指标做能力判定的研究的直接反驳。
8. **自由五子棋作为"显微镜"的选择有具体理由**：规则简单不等于任务简单——agent 只以坐标序列读棋盘，**必须自行重建行列与对角线上的空间关系**；没有记忆时约一半的走子落在已有子的点上，因此**进化有真实的改进空间**。
9. **GUI agent 的迁移猜想（未测试）给出了一条可检验的假设**：Skill B 在 Skill A 之后运行时，第一次点击会命中 A 刚到达页面中光标下的任何东西并导航离开——这是 compositional override 在真实 agent 中的具体机制。

## 局限性
- **单一环境**：全部结论建立在自由五子棋上。作者明确表示"虽然属性源自五子棋，但它们关涉任务关系而非游戏本身；我们**猜想**（未经测试）只要 artifact 通过固定接口被复用，同样的断裂就会出现。"——**猜想，非证明**。
- **单一基座模型**（DeepSeek-Vlash-4-Flash）：三个机制用同一模型是为了控制变量，但也意味着结论未在多模型上验证。
- **程序化对手**（rule-based、threat-aware、search_2 前瞻两步）：对手强度有限（仅 search_2 前瞻两步），博弈级诊断的结论受此约束。
- **属性 3 的"task relation"由规则程序定义**，即"可接受走子集 $G(s)$"。这要求任务有可枚举、可独立判定的正确走子集——**在开放式任务中不存在**，这也是为什么本文必须选受控环境；而该可判定性恰恰是框架无法推广到真实场景的核心限制。
- **只判定第一个失败的属性**，因此对后续属性一无所知。Voyager 的谱系级、DGM 的博弈级空白不是因为表现好，而是因为按规则不再判定——**报告的"通过"有结构性缺口**。
- **Reflexion 的噪声基线来自两次空记忆重跑**，这是一个较弱的噪声估计（2 次 vs 需要的多次采样），作者也承认 B 集是"更大、噪声更低"的集合。
- **状态集 B 来自 DGM 进化过程中的真实对局**，因此对 Voyager 与 Reflexion 的泛化性存在选择偏差（虽按对局抽取）。
- **DGM 的 OB-4 是旁支**，主谱系被跳过；判定 OB-3 为"对 search_2 胜场最多的进化版本"本身是一个基于 outcome 的选择。
- **Voyager 的 20 局收敛到 4 条走子序列**，说明样本多样性有限；虽然作者将其作为机制证据（而非统计推断），但 20 局的统计效力有限。
- **没有给出"修复方案"**：论文诊断了断裂，但未提出如何在一般设定下修复 legalization gain / compositional override / loss-only drift（迁移到 GUI agent 的测试也被明确列为需要 replayable screen 与规则化 checker）。
- **"能力"的定义是相对于给定 task relation 的**，因此框架不能回答"该追求哪些 task relation"这一上游问题。

## 适用场景
- **评估自进化 agent 方法时**：把三个信号换成五属性 + 三尺度诊断，能立刻区分"真的提升了能力"与"只是更少犯规/分数更好看"。
- **设计自进化系统的 artifact 与 harness**：Voyager 的 compositional override 对"多技能 + calling script"的架构有直接的设计启示（技能间的交互顺序本身可能就是 bug 来源）。
- **用 fitness/进化分选代的自进化流水线**：DGM 的 loss-only drift 提示 fitness 与能力延续可能脱钩，选代逻辑需额外检验。
- **任何有可判定正确动作集合的任务**（棋类、规划、代码补全的部分场景、工具调用）：可用状态级配对比较 + 规则判定来做同构诊断。
- **不适合**：开放式生成任务（无独立判据）；需要端到端 capability 度量的真实部署场景；多模型/多任务的广谱结论（本文均为单点反例）。
