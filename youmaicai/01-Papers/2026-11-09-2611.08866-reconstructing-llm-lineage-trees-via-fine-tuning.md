# Reconstructing LLM Lineage Trees via Fine-Tuning Path Inference

> **arXiv**: [2611.08866](https://arxiv.org/abs/2611.08866)
> **发表日期**: 2026-11-06
> **分类**: cs.LG
> **会议/期刊**: arXiv preprint（Under review at ICLR 2027）

## 📋 摘要

大语言模型的微调（FT）衍生模型如今被大量发布，但其来源（provenance）依赖自述、无法验证。血缘误标会使验证者无法审计外包的微调、确认衍生模型的许可证合规性，也无法追溯父模型传给子模型的漏洞。这三件事都需要的是"派生的方向"，而不仅仅是"是否存在派生关系"。现有仅依赖输出的方法受限于成对派生测试或无向血缘估计，而要恢复一棵有向树则需要白盒访问模型权重。本文在**灰盒访问**下形式化了"重建有向模型树（含内部节点）"的问题：只观测 teacher-forced 的对数似然，永不检视权重。作者利用"微调会提升训练数据的对数似然、且子模型从父模型继承这一提升"这一性质，定义任意两个模型之间的**非对称逐任务对数似然偏移**作为微调历史的痕迹，并由此导出每个有序模型对的边权。最后提出 **TRACE-Edge**，在这些边权下精确求解最大生成有向树（maximum spanning directed tree），既无需超参数也不施加树结构约束。评测覆盖 5 种配置、共 25 棵由 3 个基座模型与 7 个任务构成的模型树。用微调样本本身做探测时，TRACE-Edge 的父节点匹配准确率达 **0.74**；即使改用与训练数据同分布的留出探测样本，平均表现仍优于 output-similarity 基线。

## 🎯 核心贡献

1. **形式化"灰盒下重建有向模型树"问题**：在只观测 teacher-forced 对数似然、不访问权重的条件下，恢复包含内部节点的有向血缘树。
2. **发现核心可利用性质**：微调提升训练数据的对数似然，且子模型从父模型继承这一提升——这是把"成对派生测试"升级为"树恢复"的杠杆。
3. **提出非对称逐任务对数似然偏移（asymmetric per-task log-likelihood deviation）** 作为微调历史痕迹，并据此构造有序模型对的边权。
4. **提出 TRACE-Edge**：在给定边权下精确求解最大生成有向树，**无超参数、无树结构先验**。
5. **实证有效**：5 种配置、25 棵模型树；父节点匹配准确率 **0.74**；在同分布留出探测下仍优于 output-similarity 基线。

## 🔧 方法/架构

- **访问级别（gray-box）**：只能查询任意模型在给定文本上的 teacher-forced 对数似然 $\log p_{\theta}(x \mid x_{<t})$，不下载、不检视权重。
- **核心统计量**：对任务 $T$ 与模型对 $(M_i, M_j)$，定义**非对称**偏移——即 $M_i$ 相对 $M_j$ 在任务 $T$ 上的对数似然偏差，且该偏差关于有序对不对称：

$$
\Delta_{ij}^{(T)} = \log p_{M_i}(x \mid x_{<t}) - \log p_{M_j}(x \mid x_{<t}), \qquad x \sim \mathcal{D}_T
$$

- **边权构造**：由上述偏移（跨任务聚合）导出每个有序对 $(M_i \to M_j)$ 的边权，刻画"子继承父的对数似然提升"这一信号。
- **树求解**：在有向边权上求**最大生成有向树（maximum spanning directed tree）**，得到包含内部节点的血缘树；不需要超参数，也不需要树形约束（不预设根节点数、层数等）。
- **评测设置**：5 种配置、合计 25 棵模型树，由 3 个 base model 在 7 个任务上微调派生而成；对比 output-similarity 基线；探测数据分两种：微调样本本身，以及与训练数据同分布的留出样本。

$$
\log p_{M_{\text{child}}}(x) \gtrsim \log p_{M_{\text{parent}}}(x), \qquad x \in \mathcal{D}_{\text{FT}}
$$

（以上为本笔记对该文核心性质的形式化表述，摘要中未给出具体公式。）

## 📊 实验结果

- **父节点匹配准确率（parent-match accuracy）**：**0.74**（以微调样本作为探测数据时）。
- **实验规模**：5 种配置、共 **25** 棵模型树；**3** 个 base model、**7** 个任务。
- **对比基线**：output-similarity 基线；TRACE-Edge 在平均意义上**优于**该基线。
- **探测稳健性**：即使改用与训练数据同分布的**留出探测样本**，TRACE-Edge 平均表现仍优于基线。
- **具体逐树/逐任务数值**：摘要未给出（详见原文表格）。

## ⚠️ 局限性

- **仅用对数似然这一单一信号**：对数似然提升可能来自数据污染、任务相似性、相同教师模型等混杂因素，未必唯一指示血缘。
- **需要可查询 log-likelihood**：对只提供生成 API（不暴露 logprobs）或只提供黑盒采样接口的模型不可用；实际"衍生模型"发布方也未必配合。
- **父节点准确率 0.74 仍有较大误差空间**：25 棵树规模不大，跨更多 base model 家族（不同 tokenizer、不同语料）时的稳健性未验证。
- **树结构假设**：最大生成有向树隐含"单一父节点、无环"的假设；对多父混合（merge）模型不成立。
- **任务需可采样**：要求每个任务有可查询样本分布，真实微调数据集常不公开。

## 💡 建议

- 是否推荐使用：**是**（供应链审计场景有实用价值）
- 适用场景：开源模型生态的**许可证合规审计**与血缘追溯；检测误标/冒充的微调衍生模型；追踪父模型向子模型传递的漏洞与后门；模型资产盘点与归属核查。
- 落地建议：把 TRACE-Edge 作为"筛查式"工具优先用于大规模候选模型间的粗排，再结合人工或白盒手段确认。
