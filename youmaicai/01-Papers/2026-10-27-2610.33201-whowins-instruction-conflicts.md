## 核心贡献

> **拆解「指令来源」这个混淆变量**：既有指令层级基准把「位置、角色、标签」三者捆在一起，导致无法判断到底是哪个因素在起作用。

1. **指出既有基准的方法论缺陷**：指令层级基准问「更高层级的来源是否胜出」，但**一个来源同时设置了位置（position）、角色（role）和标签（label）** —— 三者被混淆，归因不可能。
2. **构建 WhoWins 基准**：**1,080 个代码评分的场景**，覆盖 **5 种任务类型**，每个场景最多含 **5 条互斥指令**。
3. **7 组受控实验**：只改变指令的**投递方式**，其余全部固定。
4. **规模化评测**：**14 个开放权重模型**（0.6B–122B，thinking 开与关），**1,887,356 条评分回复**，并在**留出场景**上复核主要结论。

### 核心发现

| 发现 | 数值 |
|------|------|
| **同一消息内**，两条冲突指令中「先出现者」胜出 | **72.42% – 94.66%** |
| **跨消息**，「先出现者」胜出 | **22.95% – 62.65%**（大幅下降） |
| **Qwen 系模型**：system/developer 消息中先发的策略，在与后续行的冲突中**输掉大部分** | — |
| **gpt-oss**：该策略**生效时反而赢得多数** | — |
| **工具/文件写入任务**：同样的文本作为「带标签的用户消息」先发时胜率**更高** | **每个模型-模式组合均如此** |
| 知道「任务行在哪」后，**冲突预测在所有模型-模式下都改善** | — |
| 最多仅 **2.92%** 的已裁决配对回复会**标记或回避**冲突 | — |

## 技术方案

### 核心思想

方法学贡献是全文骨架：**把混淆变量拆开**。

```text
一个「来源」同时设置了三件事:
  ├── 位置 (position)  ── 在消息序列中的先后
  ├── 角色 (role)      ── system / developer / user / tool
  └── 标签 (label)    ── 文本中的显式标签，如 "IMPORTANT:"
        ↓
  既有基准无法归因: 到底哪个在起作用?
        ↓
  WhoWins: 7 组受控实验, 每次只变投递方式
```

### 实验设计

- **WhoWins**: 1,080 场景 / 5 任务类型 / 最多 5 条互斥指令 / **代码评分**（可复现、无 LLM-as-judge 偏差）
- **7 组受控实验**: 改变「指令如何被投递」—— 位置、角色、标签各自独立操纵
- **评测规模**: 14 模型 × thinking 开/关 × 1,887,356 条评分回复
- **留出验证**: 主要结论在 held-out 场景上复核

---

## 实验结论

- **数据集**: WhoWins 自建基准（代码评分）
- **模型**: 14 个开放权重模型，0.6B–122B，thinking 开/关
- **结果**: 见上表；**规模之大使结论具有统计意义**

**最具实践价值的发现**：在工具调用与文件写入任务中，把策略文本作为**带标签的用户消息**先发，比作为 system 消息先发**胜率更高** —— 而这在所有模型-模式组合上都成立。这是一个**可立即采纳的提示工程结论**。

---

## 局限性

1. **代码评分**虽避免 judge 偏差，但仅覆盖**可编程判定**的任务类型，结论外推到开放式任务需谨慎
2. **结论随模型族分化明显**（Qwen 与 gpt-oss 行为相反）—— **不存在统一的「最佳投递方式」**，需按模型族调优
3. **跨消息胜率区间很宽**（22.95%–62.65%）—— 均值参考价值有限
4. 只测**开放权重模型**；闭源前沿模型（且可能经过指令层级训练）行为未知

## 实现建议

- **实现难度**: 中（基准已开源，`pip install whowins`）
- **预期性能**: 立即可用的结论 —— **工具/文件写入任务中，把高优先级策略作为带标签的用户消息前置**
- **适用场景**: 多来源指令的 agent（operator / repo config / user / tool results / memory 冲突）
- **落地注意**:
  1. **按模型族分别调优** —— Qwen 与 gpt-oss 行为相反
  2. 保持**位置**优先：同一消息内「先出现者」胜率高达 72–95%，这是最强的单一线索

## 我的评注

> 这是今日批次里**方法论最扎实**的一篇：1,080 场景 × 14 模型 × 187 万条评分回复 × 7 组受控实验。这个规模让「位置效应」这个结论变得可靠。
>
> 最实用的收获是那条可立即执行的结论：**工具/文件写入任务里，把策略文本作为带标签的用户消息前置，比放在 system 消息里更有效** —— 且在所有模型-模式下都成立。这与「system prompt 权重最高」的直觉相反，值得在自己的 agent 里验证。
>
> 「先出现者胜出 72–95%，但只有 2.92% 的回复会标记冲突」这个组合很说明问题：模型**默默地**按位置而非标签做仲裁 —— 它们没有在「处理冲突」，只是在「服从先到的」。这暗示**层级提示词在实践中可能比想象的有效得多**，因为模型可能压根没在做层级判断。
>
> 与 [[Propensities Please]] 一起看：两篇都是**受控实验 + 行为观测**范式，都在绕开「读模型内部」的不可靠路线。这可能是 LLM 评估方法论的一个转折点。
