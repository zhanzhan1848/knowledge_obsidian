## 核心贡献

> **一个冻结的稀疏 MoE 模型，单靠「给不同轨迹挂不同的专家资格掩码」，就能产生真正不同的推理路径** —— 不需要分配角色、不需要规定方法、不需要微调、不需要模型副本。

1. **问题**：生成多个解本应能暴露不同解法，但**额外轨迹常常只是同一种主导方法的改写（paraphrase）**。
2. **提出 ACR（Agent-Conditioned Routing）**：
   - 给 $m$ 条并行轨迹分配**持久的、未训练的共享/私有专家资格掩码（shared/private expert-eligibility masks）**
   - **保留原有的、依赖输入的 token router**（不做替换）
3. **核心结果**（在**匹配输出预算**下）：
   - GLM 5.3 上，多方法问题数 **37.3 vs 18.7**（最强温度设置）→ **约 2 倍**
   - GPT-5.6 Sol 上 **45.00 vs 27.00** → **1.67 倍**
4. **盲审验证**：30 题分层抽样上的四专家盲审，两个骨干模型上 ACR 都得到更多多方法解，**但正确性更低**。
5. **消融**：匹配资格的消融显示 ACR 在多方法计数上仅**温和优势**；而**token 重采样掩码**获得**更高正确性**。
6. **成本**：ACR 增加约 **160 KiB 掩码状态**；三题微型基准、1,024 token 上限下，**延迟与峰值显存均在批量温度采样的 3% 以内**。

## 技术方案

### 核心思想

稀疏 MoE 模型内部本来就有「多个专家」这一结构资源。常规做法是让 router 按 token 决定专家 —— 但同一个 prompt 重复采样，router 会倾向选同一批专家，于是多条轨迹同质。

ACR 的做法：**不动 router，只在「哪些专家有资格被选中」这一层加一个持久掩码**。不同轨迹用不同掩码 → router 的候选集不同 → 轨迹自然分叉。

```text
冻结 MoE 模型 (router 不变)
   ┌─────────────────────────────────────┐
   │ 轨迹 1: mask₁ = {E1,E3,E7,...}        │  → router 在该候选集内选
   │ 轨迹 2: mask₂ = {E2,E4,E7,...}        │  → router 在该候选集内选
   │ 轨迹 3: mask₃ = {E1,E5,E9,...}        │  → router 在该候选集内选
   └─────────────────────────────────────┘
   输出预算不变，但三条路径走的是不同专家子集
```

### 关键技术

| 技术 | 说明 |
|------|------|
| **专家资格掩码** | 每个 (专家, 轨迹) 的二元资格标记，持久生效 |
| **共享/私有掩码划分** | 部分专家在多轨迹共享（保底），部分为轨迹私有（保分叉） |
| **保留输入依赖 router** | 不替换 router，只约束其候选集 |
| **未训练** | 掩码随机初始化即可生效，无需微调 |
| **盲审审计** | 用模型裁判读**完整推导过程**判定方法数 |
| **token 重采样掩码** | 消融中的变体：掩码随 token 重采样，正确性更高但多样性弱 |

## 公式

```math
\text{专家资格掩码}:\quad
M \in \{0,1\}^{m \times E}
\qquad (m = \text{轨迹数},\; E = \text{专家数})
```

```math
\text{受约束的路由}:\quad
g^{\text{acr}}_{m}(x) \;=\; \text{Softmax}\!\Big(
\frac{Q(x)K(x)^{\top}}{\sqrt{d}}
\;\odot\; M_{m} \Big)
```

```math
\text{多方法问题比例}:\quad
\text{Diversity} \;=\; \frac{\#\{\text{至少两种不同主方法的问题}\}}{\#\{\text{筛出的问题}\}}
```

```math
\text{掩码开销}:\quad
\text{state} \;=\; m \times E \times 1 \text{ byte} \approx 160\ \text{KiB}
```

## 代码片段

```python
# 概念性伪代码：ACR 的专家资格掩码路由
import torch

class ACRRouter:
    # 在冻结 MoE 模型上，用持久掩码约束 router 的候选专家集合。

    def __init__(self, model, n_traj, seed=0):
        self.model = model
        self.n_traj = n_traj
        g = torch.Generator().manual_seed(seed)

        # 共享专家：所有轨迹都能用（保证不塌陷）
        shared = torch.randperm(model.n_experts)[: model.n_experts // 4]
        mask = torch.zeros(n_traj, model.n_experts)
        mask[:, shared] = 1.0

        # 私有专家：每条轨迹独有（制造分叉）
        for m in range(n_traj):
            pool = [e for e in torch.randperm(model.n_experts) if e not in shared]
            mask[m, pool[: model.n_experts // 4]] = 1.0

        self.mask = mask.bool()

    @torch.no_grad()
    def generate_parallel(self, prompt, max_new_tokens=1024):
        # n_traj 条轨迹并行生成，共享同一 prompt、同一输出预算。
        outs = []
        for m in range(self.n_traj):
            # 把当前轨迹的资格掩码注入 router 的 logits
            out = self.model.generate(
                prompt,
                max_new_tokens=max_new_tokens,
                expert_mask=self.mask[m],       # 屏蔽非资格专家
                temperature=1.0,
            )
            outs.append(out)
        return outs
```

## 实验结论

- **模型**: GLM 5.3, GPT-5.6 Sol
- **基准**: 126 题多模式数学 + 物理（先筛选 soft-correct 的解答）
- **判定方式**: 模型裁判**阅读完整推导**，统计「至少两种不同主方法」的问题数
- **结果**:

| 模型 | ACR | 最强温度设置 | 倍数 |
|------|-----|--------------|------|
| GLM 5.3 | **37.3** | 18.7 | ~2.0× |
| GPT-5.6 Sol | **45.00** | 27.00 | 1.67× |

- **盲审**（30 题分层抽样，四专家盲审）：两个骨干上 ACR 多方法解更多，**正确性更低**
- **消融**：
  - 匹配资格（matched-eligibility）消融 → ACR 多方法计数**仅温和优势**
  - **token 重采样掩码** → **正确性更高**
- **开销**：+160 KiB 掩码状态；1,024 token 上限下延迟/峰值显存**均在批量温度采样的 3% 内**

---

## 局限性

1. **多样性 ↔ 正确性的权衡未解决** —— 盲审明确指出 ACR 解法**正确性更低**；token 重采样掩码则正确性高但回到同质化。这条主线没有解
2. **消融削弱主结论** —— matched-eligibility 消融显示 ACR 的优势「modest」，说明多方法计数增益有多少来自「资格掩码」本身、多少来自采样差异，需要正文澄清
3. **强依赖 MoE 架构** —— 稠密模型无从谈起，适用面窄
4. **基准规模小**（126 题、微基准 3 题 1,024 token），统计效力有限
5. **裁判依赖模型评判** —— 「方法数」的判定由模型裁判完成，有偏风险
6. **「有信息量的顺序提示」更强** —— 摘要提到 informed sequential prompt 诱导的多样性**比 ACR 更多**，即 ACR 可能不是最优解
7. 具体实现（如何把掩码注入到实际 MoE 实现）细节未给

## 实现建议

- **实现难度**: 中（需要能注入 router 候选集的 MoE 实现）
- **预期性能**: 多样性显著提升（2×），正确性可能下降 5-10 个点量级（需实测）
- **适用场景**:
  - **需要「多个不同思路」而非「多个类似答案」的场景**：数学/物理竞赛式推理、需要多假设探索的科学问题
  - **不适合**：单纯追求答案准确率、且已有验证器可筛选的任务（正确性下降是净损）
- **落地注意**:
  1. **先确认你的模型是不是 MoE** —— 稠密模型这条路子直接不成立
  2. **配套验证器**：既然多样性上来了，收益必须靠「多个候选里挑对的」兑现，没有验证器就没有价值
  3. **值得同时试 informed sequential prompt** —— 摘要暗示它更强，且零架构改动，可能直接取代 ACR
  4. 成本优势明显（3% 以内开销），**风险主要是质量而非性能**

## 我的评注

> 想法很巧：既然 MoE 模型内部已经存在「多个专家」这个天然的多样性资源，为什么不用它来产出多样化的推理路径？做法又极轻 —— 只是加掩码，160 KiB，3% 以内的开销。
>
> 但我读完摘要后的第一反应是：**消融把主结论削掉了**。matched-eligibility 消融只显示「modest」优势，意味着多方法计数的增益里有相当部分可能来自「不同掩码导致采样分布整体变化」，而非 ACR 机制本身。再叠加上「盲审显示正确性更低」，这更像是一个**用正确性换取多样性的交易**，而不是纯粹的能力提升。
>
> 更关键的是摘要自己承认：**informed sequential prompt 诱导的多样性比 ACR 更多**。如果一个零架构改动的顺序提示方法效果更好，那 ACR 的定位就变成「便宜且并行的替代品」—— 有价值，但说服力大幅削弱。这篇读起来像是诚实报告了「我们尝试了一个方案，但它被更简单的方案超过了」。
>
> 我认同它的**问题设定**（多轨迹 ≠ 多样化，这是真问题），但对**解法**保留意见。多样性的真正瓶颈可能在训练分布（模型只会一种解法），而不在推理时的路由。
>
> 值得一读的是它的**测量方法**：让裁判读完整推导来判定「方法数」，比只看最终答案的方法计数靠谱得多。这套评测思路可以借用。
