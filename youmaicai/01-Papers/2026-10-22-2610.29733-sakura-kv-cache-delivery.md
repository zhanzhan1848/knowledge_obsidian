## 核心贡献
1. 提出 **SAKURA**，一套 cloud-edge 架构，在**带宽预算约束下**把可复用的 attention KV state 投送到手机端，用于隐私图像编辑。
2. 设计 **fine-grained token-importance-aware 压缩方法**，在有限传输预算下保持图像质量。
3. 在运行时**按网络带宽为每个即将到来的 shard 自适应选择 cache 表示**（rate adaptation）。
4. 实现**流水线化 runtime**，把 cache 传输与重建同端上执行重叠（overlap）起来。
5. 相对基线显著降低延迟并压缩存储量，同时保持图像质量。

## 问题动机
Diffusion transformer 已被广泛用于图像编辑服务。为兼顾效率与隐私，现有系统普遍采用**云端-设备协同**：把 request-specific 推理保留在设备端，从而避免把个人图像和 prompt 上传到云。但这类负载（如**换脸 face swapping** 与**虚拟试穿 virtual try-on**）往往复用**公共模板**，这意味着 KV state 可以**预计算并跨请求复用**。问题在于：这份可复用状态体积大，且随模板数量增长，全存到手机上不现实；存云端则解决容量，但**cache 传输被放到了推理关键路径上**，在波动 mobile 网络下甚至可能比端上直接算还慢。这构成一个存储/带宽/隐私的三方张力。

## 方法
- **压缩**：fine-grained **token-importance-aware** compression，在有限传输预算内保留关键 token 的 KV，抑制图像质量损失。
- **多档表示**：由于不同带宽下可接受的压缩率不同，SAKURA 维护多个 cache representation（对应不同 token 重要性取舍）。
- **运行时自适应**：根据**当前网络带宽**，为**每个即将处理的 shard** 动态选择 cache 表示（rate adaptation）。
- **流水线 runtime**：让 cache 的传输（transfer）与重建（reconstruction）同设备端推理**重叠执行**，把传输延迟从关键路径上隐藏掉。

## 实验设置与结果
- 数据/基准: **三个图像编辑任务**（摘要未逐一列名，推测包含换脸与虚拟试穿等模板类任务）与**两个 diffusion 模型**；硬件为 **Snapdragon 8 Elite Gen 5** 手机真机。
- 对比方法: (a) **CacheGen adapted to DiT**；(b) **on-device generation**（端上全量生成）；存储对比为 **uncompressed cache**。
- 主要结果:
  - 相比 **CacheGen (adapted to DiT)**，延迟降低 **1.82×**。
  - 相比 **on-device generation**，延迟降低 **3.27×**。
  - 相比 **uncompressed cache**，cache 存储减少 **3.06×**。
  - 在上述压缩与加速下**保持图像质量**（摘要未给出具体质量指标数值）。

## 关键技术细节
- 部署目标明确为真实商用 SoC（Snapdragon 8 Elite Gen 5），而非模拟环境，因此延迟数字的工程可信度较高。
- 三层机制叠加：压缩降低载荷量 → 带宽自适应选择表示 → 流水线隐藏传输延迟，三者共同作用于不同瓶颈。
- 关键 trade-off 是"bandwidth budget ↔ image quality"，由 token importance 做细粒度分配而非均匀量化。
- 隐私模型：仅 KV state（模板侧的注意力状态）过网络，用户图像与 prompt 始终不出设备。
