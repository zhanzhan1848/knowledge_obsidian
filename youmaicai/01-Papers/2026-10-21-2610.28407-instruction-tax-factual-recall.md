## 核心贡献

> 提出并实证 **instruction tax（指令税）**：**指令微调会降低事实召回能力**。在 AKBC LM-KBC 2026 Shared Task（32B 参数以内、无检索、无微调）上，base model 0.6836 vs instruction-tuned 0.5681 —— **权重导致，不是提示方法导致**。

1. **成绩**：官方榜 **0.6836**，是基线 0.2964 的两倍多
2. **核心论断**：instruction tax 由**模型权重**造成，而非提示方式 —— 即使用 base model 该效应依然存在
3. **简单有效的方案**：给 base model 若干训练样例做上下文 → 生成 64–256 个输出 → **只保留重复出现的**
4. **两个关系专用方法**：一个提升大答案集的召回；一个在预测人物死亡地点前**验证其是否在世**

---

## 技术方案

### 任务设定

为「主语-关系」对生成**所有可能的对象**（知识库补全）。约束：≤32B 参数、**无检索、无微调**。

### Self-consistency 过滤（核心技巧）

```math
y^\ast = \arg\max_y \big| \{ i : y_i = y \} \big|,\quad y_i \sim \pi(\cdot \mid \text{few-shot prompt})
```

采样 64–256 次，保留**重复出现**的答案 —— 频率即置信度。

### 两个关系专用后处理

| 方法 | 用途 |
|------|------|
| 大答案集召回增强 | 关系（如职业、居住地）候选极多时提升 recall |
| **在世验证（vitality check）** | 预测人物死亡地点前先确认其**尚未去世** —— 训练数据的时间滞后是事实性错误的典型来源 |

---

## 实验结论

| 对比 | 分数 | 结论 |
|------|------|------|
| base + text completion | **0.6836** | 最优 |
| IT 版 + chat 接口 | 0.5681 | **-11.6 pp** |
| 官方 baseline | 0.2964 | base 是其 **2.3x** |

**提示方法与模型架构同等重要** —— 但 base 更优说明根因在权重侧。

---

## 局限性

- 结论绑定**单一任务**（知识库补全）与**单一模型族**，跨任务泛化未验证
- "instruction tax"这一命名可能过强 —— 指令微调的收益（可遵循性）在该任务中不参与评分
- 无检索、无微调的约束是任务设定所限，不代表真实部署
- 未做因果机制分析，仅观察到相关

## 实现建议

- **实践含义**: **事实密集型任务不要默认用 chat 模型** —— 应 A/B 测试 base 模型配文本补全提示
- **适用场景**: 知识库补全、实体属性枚举、罕见事实召回
- **建议起点**: 成本极低 —— 拿同一权重的 base 与 IT checkpoint 跑一遍 few-shot 补全 + 重复过滤，半天可验证；再加针对时间敏感关系（在世验证）的后处理
