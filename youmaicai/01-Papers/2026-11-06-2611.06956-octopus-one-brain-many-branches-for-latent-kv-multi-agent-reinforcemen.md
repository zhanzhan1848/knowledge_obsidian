# Octopus: One Brain, Many Branches for Latent-KV Multi-Agent Reinforcement Learning

## 摘要
多 agent LLM 系统通过**派生带隔离上下文的子 agent** 并行探索，而单 agent 系统则把每个搜索与验证步骤**追加进一条不断增长的轨迹**。然而，既有**多 agent 框架在分支间重复复制前缀 KV cache**、通过**重新预填充文本摘要**交换发现，并在 RL 过程中**扁平化或丢弃跨分支依赖**。本文提出 **Octopus** —— 一个**单模型多 agent RL 框架**，其中所有线程**共享一个骨干**，通过**五个原语**在 GPU 驻留的 KV 状态**有向无环图（DAG）**上协调：**fork、read_thread、wait_threads、rewind、commit**。三个协同设计的机制：(1) **Zero-Copy Radix Forking** —— 把分支生成作为共享物理 KV 页上的 **O(1) 游标视图**；(2) **Attention-Only KV Mounting** —— 把兄弟线程的终态 KV 块**直接挂载**进全注意力层，同时**绕过线性循环状态**（Gated DeltaNet / Mamba-2），把**离任务劫持（off-task hijacking）削减 21×（57.9% → 2.7%）**，同时在**零额外开销**下保留 **92.2%** 的全文本互信息。

## 核心贡献
1. 诊断既有多 agent 框架的**三重浪费**：分支间**重复复制前缀 KV cache**、用**重预填充文本摘要**交换发现、RL 中**扁平化/丢弃跨分支依赖**
2. 提出 **Octopus** —— 单模型多 agent RL，全部线程**共享一个骨干**，在 GPU 驻留的 **KV 状态 DAG** 上协调
3. 定义**五个协调原语**：**fork / read_thread / wait_threads / rewind / commit**
4. **Zero-Copy Radix Forking** —— 分支作为共享物理 KV 页上的 **O(1) 游标视图**（零拷贝）
5. **Attention-Only KV Mounting** —— 把兄弟线程终态 KV 块直接挂载进全注意力层，同时**绕过线性循环状态**（Gated DeltaNet / Mamba-2）：**离任务劫持 21× 削减（57.9% → 2.7%）**，且在**零额外开销**下保留 **92.2%** 的全文本互信息

## 方法与架构
**KV 状态 DAG + 五原语**：
```
fork           —— 从当前状态派生分支（O(1) 游标视图，零拷贝）
read_thread   —— 读取另一线程的终态
wait_threads  —— 等待若干线程
rewind        —— 回退到某状态
commit        —— 提交线程结果回主干
```

**三机制**：
1. **Zero-Copy Radix Forking** —— 分支 = 共享物理 KV 页上的 O(1) 游标视图；
2. **Attention-Only KV Mounting** —— 兄弟线程终态 KV 块直接挂载进全注意力层，**绕过线性循环状态**（Gated DeltaNet / Mamba-2）；
3. 摘要截断的第三机制。

**关键设计理由**：线性循环状态**不可挂载**（状态是递归的），故只挂载注意力部分 —— 这同时解释了为什么混排线性注意力的模型特别容易发生**离任务劫持**。

## 局限性
- **共享单骨干**限制了线程间的模型多样性（相比真正的多模型多 agent）；
- 需要模型支持**注意力与线性循环状态分离**（如混合线性注意力架构）—— 纯全注意力模型上无劫持问题，也无该机制的意义；
- 摘要截断，第三机制与主结果数字需查正文；
- 21× 与 92.2% 是在特定架构与任务上的数字，跨架构泛化未验证。

## 值得注意的点
**「Attention-Only KV Mounting」的诊断极精彩**：离任务劫持（57.9%）之所以严重，是因为**线性循环状态（Gated DeltaNet / Mamba-2）的状态无法挂载** —— 你能借别人的注意力输出，却借不了别人的递归状态，于是两个世界的语义在中途分叉。绕过线性循环状态后，劫持率降到 2.7%，且保留 92.2% 互信息、零额外开销。

这是今日**最硬核的机制性解释**：一个具体的失效现象，追溯到了架构层面的一个「不可移植性」约束。
