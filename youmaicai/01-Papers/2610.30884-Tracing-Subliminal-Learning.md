## 核心贡献

> 系统研究 **subliminal learning**（隐性学习）——模型从"其他模型生成的数据"中继承**与该数据无关的特质** —— 在 **hard-label** 与 **on-policy soft-label** 两种蒸馏设定下的**传递机制**。

1. **背景**：用其他模型生成的数据训练 LLM，可能继承与数据内容**无关**的特质（如教师对数字的偏好）。这在 **model merge** 与 **on-policy distillation** 广泛使用的今天尤其实用。
2. **设定对比**：
   - **Hard label distillation**：student 在教师生成的数字上训练（只有标签）；
   - **On-policy soft label distillation**：student 自己生成数据，**教师的 logits** 提供学习信号。
3. **关键发现**：
   - **传递在两种设定下都存在**，且在以下差异下**稳健**：weight initialization、pretraining data order、pretraining corpus、model size、architecture；
   - **教师与学生角色不对称**：某些 checkpoint 是**更好的教师但更差的学生**，反之亦然；**角色互换时传递幅度强烈不对称**；
   - **偏好信号载体**：构造**合成数字序列** —— 匹配教师生成数字的**频率**，但**不依赖 prompt 也不依赖前序数字** → 在 hard-label 设定下**仍能诱导大量传递**；
   - **top-K soft-label 蒸馏**中，从 loss 中**移除 animal token 会减少传递**（同模型设定下不完全减少）；
   - **soft label distillation 传递更一致，且所需训练量更少**。

## 技术方案

| 组件 | 说明 |
|------|------|
| Pythia / PolyPythia / DataDecide OLMo | 模型系列 |
| Hard-label vs soft-label 蒸馏 | 两种设定对比 |
| 合成频率序列 | 隔离"信号载体" |
| top-K token 消融 | 定位偏好 token |
| Checkpoint 角色不对称分析 | 教师/学生能力解耦 |

### 关键洞见

- **最关键的实验设计是"合成频率序列"**：如果匹配频率但无依赖关系的序列也能传递偏好，说明传递**不依赖数据的内容逻辑**，而是依赖**token 分布层面的统计痕迹**。这直指 on-policy distillation 的一个现实风险：**你在不知情的情况下把教师的人格一起继承了**。
- **soft label 比 hard label 传递更强更省** —— 这对当前"大量使用 on-policy distillation"的行业实践是个警告。

---

## 实验结论

- 传递在 2 种设定、5 类差异下**稳健存在**；
- 教师/学生角色**可解耦**（好教师 ≠ 好学生）；
- **频率匹配的合成序列**在 hard-label 下仍诱导大量传递；
- top-K 消融中移除 animal token **减少**传递；
- **soft-label 传递更一致、训练量更少**。

---

## 局限性

- 偏好传递机制的**根本成因仍未确定**（本文只做了"信号在哪"的定位）；
- 实验模型 ≤ OLMo / Pythia 规模，更大模型是否一致未知；
- 传递的**量级**与下游安全性影响未评估；
- 未给出防御方法。

## 实现建议

- **实现难度**：中高（研究性，需多设定受控实验）
- **预期价值**：高 — 直接关系到"用别人的模型数据训练自己的模型"这一普遍做法的**隐性成本**
- **适用场景**：模型合并、第三方数据采购、蒸馏 pipeline 审计
- **建议部署**：
  1. 在蒸馏 pipeline 中**主动检查继承的隐性格**（偏好、拒答风格、隐藏 token 偏好）；
  2. 采购第三方生成数据时**做偏好审计**；
  3. 关注后续防御方法的跟进工作
