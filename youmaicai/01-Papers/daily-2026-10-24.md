## 重点论文（28 篇详细精读）

### 1. **SCOPE: Compiling Natural-Language Policies into Neurosymbolic Predicate Programs** (2610.31062)
- **核心**：把自然语言策略**编译成可执行的神经谓词程序**（小模型判定 + 确定性抽取器 + 组合代码），应对多轮 transcript + tool-call 轨迹上的复合策略判定。
- **痛点**：微调 guardrail 在复合策略上退化；LLM-as-a-judge 精度高但成本高、预测不稳定。
- **方案**：程序与训练数据**联合优化**，用**对抗生成反例**针对"程序偏离策略"之处。
- **结果**：各任务与模型上**平均准确率最高**；**用最弱 executor 优化的程序可零成本迁移**到其他模型；可在廉价模型上部署至前沿推理模型的精度；预测**显著更稳定**且每个 verdict 可回溯到 predicate 输出。
- 详见 [[2026-10-24-2610.31062-scope-neurosymbolic-policy-compilation]]

### 2. **Self-Assessment Reinforcement Learning for Search-State Awareness** (2610.30435)
- **核心**：search agent 缺乏 **search-state awareness**（知道自己已搜到什么、还缺什么）→ 幻觉式推理 + 过早终止检索。
- **方案**：SARL 用**双奖励**（奖励"自评带来的纠正效果" + 惩罚"对自评的过度依赖"），把自省能力**内化进策略**，推理期零额外 scaffolding。
- **结果**：相对最强基线 **+24.3%**；multi-hop 推理平均 **+35.9%**，deep research 平均 **+27.9%**；超越依赖辅助监督与多智能体协作的方法；**长搜索视野下保持训练稳定**（现有方法在此区间一致退化）。
- 详见 [[2026-10-24-2610.30435-sarl-self-assessment-rl-search-state]]

### 3. **RIPPLE: Recovery Internalization through Process-Level Policy Learning** (2610.31276)
- **核心**：长时程 coding agent 能"看见失败并生成合理批评"，却**继续沿着同一条错误轨迹走** —— 作者命名为 **Critique-to-Action Handoff Gap**。
- **方案**：**prefix-only teacher** 提供证据接地的恢复监督（无未来动作、无终局结果访问）→ 轻量蒸馏 → RL 对**反思触发 / 诊断 / 纠正动作**三阶段分配**阶段化 credit**；**局部有效性信号门控 trajectory advantage**，避免中间恢复决策无差别继承终局结果。
- **结果**：四个仓库级 SWE benchmark 上**算术平均 +4.8 分**，部署时**无辅助 critic**；消融隔离出"局部 + 阶段对齐 credit"的贡献；matched-prefix 干预显示**批评语义确实影响后续纠正**。恢复增益集中在"prefix 含足够诊断证据且仓库状态在剩余预算内可逆"处。
- 详见 [[2026-10-24-2610.31276-ripple-recovery-internalization-coding]]

### 4. **Simulated Control Evals** (2610.31593)
- **核心**：控制评估通常在 purpose-built control setting 中执行再外推到部署，但部署中 safeguard 有效性依赖 control setting 未能代表的环境/任务特征。
- **方案**：**SCEs** —— 用语言模型**模拟工具响应**替代真实环境，把评估搬到**部署任务集本身**。
- **结果**：安全预测 **RMSE 3.6 pp** vs BashArena **10.1 pp**（5% audit budget，五个 monitor）；与真实执行的 **KL 散度低 10 倍以上**；**解释 78–85%** 的环境间方差；**样本效率** —— 用不到部署任务集 **5%** 的抽样即超越 BashArena；仿真发现的攻击策略能提升 monitor 在 held-out 真实攻击上的表现。
- 详见 [[2026-10-24-2610.31593-simulated-control-evals]]

### 5. **EpiSEM-Bench: Safety and Evidence Recovery under Missing Evidence** (2610.31650)
- **核心**：工具响应**遗漏安全相关事实**时，agent 可能执行本应禁止的动作 —— 尽管用户请求无害、所有返回陈述都是真的。
- **方案**：**300 组匹配的安全/不安全任务对**、六领域；系统性压制关键事实；独立审计工具检查 agent 是否**主动寻求**缺失事实并同时拒绝禁止动作、完成许可任务。
- **关键结论**：**"抵抗缺失证据"≠"有效恢复"**。恢复通路对全部十个模型都降低不安全执行，但模型在"是否主动获取缺失事实"上差异明显，且获取后能否在两个世界中都恰当行动不一致。
- 详见 [[2026-10-24-2610.31650-episem-bench-missing-evidence]]

### 6. **Why Bother Me Again? Benchmarking Personal Agent Memory** (2610.30485)
- **核心**：现有 memory benchmark 聚焦**事实召回**，几乎不测 agent 如何**学习并执行交互偏好**。
- **方案**：MemPABench —— 交互式环境，4 个 grounded simulated users、**14 条偏好**、**99 个 session 跨 4 个月**、每用户 **5 次事件驱动变更**；评测 preference selection / delivered behavior / 上下文与变更敏感度。
- **关键结论**：**检索式记忆（Mem0、MemOS、simple RAG）不优于 No Memory**；文件式记忆提升准确率但**在无关上下文中套用偏好**；三重根因 —— 检索不到交互偏好、无法适配偏好变更、**即使偏好可用也难以覆盖 agent 默认交互习惯**。
- 详见 [[2026-10-24-2610.30485-mempabench-personal-agent-memory]]

### 7. **Prompt Sensitivity in Tool-Augmented Model Comparisons** (2610.31148)
- **核心**：改写问题措辞就可能翻转两个模型的排名，而**加工具反而放大**这种敏感性 —— 因为工具同时改变了问题到答案之间的多个环节。
- **方案**：**匹配协议**把过程拆解为五个可分离环节：答案读出、推理、调用决策、工具答案、无调用时的报告。
- **结果**：6 个 open 模型 × 5 领域 × 5 措辞；工具在**有程序可解**处提升准确率，却**加宽**许多两两比较的敏感区间；加宽**跟随调用频率**，而调用频率是否随措辞变因模型而异；native tool-calling 接口 + 第二份工具描述下 molecules 领域未检测到加宽。
- **建议**：报告准确率之外，**同时报告调用频率与多措辞下的比较稳定性**。
- 详见 [[2026-10-24-2610.31148-prompt-sensitivity-tool-augmented]]

### 8. **Low-Bit N-Gram Embeddings for Language Models** (2610.31646)
- **核心**：n-gram embedding 表占用巨大 —— DeepSeek-V4.1-Flash 的 **Engram n-gram memory 分配了 1960 亿参数**。
- **方案**：系统性研究**量化方法与跨表 bit 分配**。
- **结果**：nanochat / Llama / GPT-2 系从头训练模型中，**4-bit 表节省约 75% 表内存**，同时保留加入该表带来的 **>99% 验证损失改善**；更低位宽性能下降更大，但**短程微调可恢复大部分损失**；把省下的内存**再投入更大的表**，性能可**超越原全精度表**且总内存更少。大型现有模型上（DeepSeek-V4.1-Flash、Qwen3.8-Flash-Next）节省 **47–55%** 表内存，**困惑度增幅 <1.2%**。
- 详见 [[2026-10-24-2610.31646-low-bit-ngram-embeddings]]

### 9. **MOER: Mix-Policy Optimization under Expert Prefix Guidance** (2610.30873)
- **核心**：off-policy 专家数据能突破 on-policy RL 的能力边界，但已有方法要么**静态全轨迹引导（抑制自我探索）**，要么**专家前缀引导无正确性保证**（可能导致训练崩溃）。
- **方案**：注入**衰减的专家 CoT 前缀**（前缀长度逐步退火以鼓励自我探索）+ **selective rollback**（失败补全替换为完整专家轨迹，保证每条 off-policy 轨迹的正确性）+ **协调的 mix-policy 目标**（on-policy token 用 GRPO loss，专家前缀与补全 token 用 **trust-region SFT loss** 监督）。
- **结果**：数学与通用领域推理任务上**平均分最高**，超越所有基础与 mix-policy 基线；在多样任务、模型规模与基座类别上**一致泛化**。
- 详见 [[2026-10-24-2610.30873-moer-mix-policy-expert-prefix]]

### 10. **Drift Says When, Budget Says How Much: Rate-Controlled KV Re-selection** (2610.31433)
- **核心诊断**：现有 KV 压缩在 prefill 选一次视觉 token 并全程复用；即使是 **oracle**（用未压缩答案的 attention 选）也只有 **0.44–0.52 ROUGE-L 一致度** —— 模型"读证据的位置"会随描述推进而移动。
- **第二诊断**：固定漂移阈值**系统性失效** —— drift 幅度**跨样本不可比**，低 drift 样本几乎从不被刷新，**而它们恰恰最受益**。
- **方案 RCR**：drift 决定**何时/何处**重选，per-sample 控制器调节**刷新频率**；low-rank drift detector + candidate-restricted re-selection + **GPU 常驻判定**。
- **结果**：一套配置通吃；**6 个 model-task 设置中 5 个超 InfiniGen 1.6–3.8 ROUGE-L**，第 6 个无显著差异；距精确 per-step 重选**仅 1.7 点以内**；检测器**小 4 倍**。DetailCaps 上 drift-chosen timing 优于 random（相同速率）与 periodic（更高速率）**2.0–5.0 点**。
- 详见 [[2026-10-24-2610.31433-rcr-kv-reselection-multimodal]]

### 11. **ValuSpec: Candidate Valuation before Target Verification** (2610.31338)
- **核心**：实际 serving 中相似请求**反复产生重叠候选分支**，检索复用让候选树充满低质量分支，浪费 target 侧算力。
- **方案**：在**验证前**过滤低质量分支；**transfer-based supervision** 对齐 target 模型行为；过滤阈值由 calibration split 上 target 模型的 greedy 轨迹估计，**零参数训练**；target 按 **output-identical greedy rule** 验证。
- **结果**：HumanEval / GSM8K / Dolly / SpecBench 上，retrieval-based tree 设定**最高 2.38x 端到端加速**；接入 **EAGLE-3 动态树**框架（不改其建树策略）**最高 2.78x**。接受 token **保证与标准自回归解码逐 token 相同**。
- 详见 [[2026-10-24-2610.31338-valuspec-speculative-decoding]]

### 12. **Invisibilization as a Source of Probability Bias in Language Models** (2610.30785)
- **核心**：模型被对齐为不使用受保护属性 → 当属性出现在 prompt 中时**拒绝或回避**。但若系统需要判断"该从说话人那里学到多少"，**因来源而拒绝有价值的信息代价高昂**。
- **方法**：双 urn 游戏 + 精确贝叶斯答案；把报告者描述在 10 种配置中随机化，**6,600 个 session**。
- **关键发现**：模型常**拒绝评估报告者**（按描述而非按证据把信息当作无价值）；最极端时，**Black 描述报告者被拒 46%，white 描述仅 9%**；但被评估时 Black 描述者获得**略多**信任。该偏差**对只比较平均信任或只看已评估案例的审计不可见**；**随推理 effort 增长**；**跟随词汇而非类别**（模型对 "Black" 触发种族推理，对西班牙语 "negro" 不触发，对 "Indigenous" 从不触发）；**在实践者最先尝试的警告指令下反而恶化**。
- **缓解**：当模型信任按多轮揭示的真值打分时，五个配置中有四个在最后几轮把 racial gap 压到 **<0.02**。
- 详见 [[2026-10-24-2610.30785-invisibilization-probability-bias]]

### 13. **Cross-Identifier Binding Failures in LLMs** (2610.30903)
- **核心**：默认假设"同一分子的多种标识符（俗名/IUPAC/SMILES）提供可互换的知识访问"—— **不成立**。
- **发现**：**7B–72B** 模型（含化学专门模型）持续暴露不一致的知识子集；即使模型**能从 SMILES 识别分子**、**通过名称检索到事实**，同一事实**从 SMILES 仍不可得**。
- **因果诊断**：行为 / 表征 / 参数编辑三层分析一致表明 —— **更强的化学表征能力**与**修改单个事实**都**不足以**建立可靠的跨标识符访问；**根源在"标识符 ↔ 已有知识"的绑定**。
- **缓解**：**Binding Self-Distillation** —— 利用词法同一性把已有的知识访问迁移到结构化路径，推理时**无需名称查找、无需从头训练**。
- 详见 [[2026-10-24-2610.30903-cross-identifier-binding-failures]]

### 14. **Spectral Smoothing and Spiking Perturbations** (2610.30676)
- **核心**：FFN 投影的奇异值谱编码重要结构，但其对下游行为的**因果作用**欠缺探索。
- **方法**：对 `up_proj` / `down_proj` 做后处理谱扰动 —— **spiking**（放大对几何均值的偏离）与 **smoothing**（压缩偏离），两者都**保持奇异向量不变、保持奇异值几何均值不变**。
- **结果**：5 个 open Llama / Qwen instruction 模型上，大幅正扰动更可靠地**抑制语言与演绎推理**；中等负扰动**有时提升**事实性或任务局部表现；敏感性**强烈依赖模型家族、基准模块与底层 layerwise 谱不等式**；变化呈**结构化**而非随机。
- **方法论价值**：一种**零训练**的白盒能力探针。
- 详见 [[2026-10-24-2610.30676-spectral-smoothing-capability-profiles]]

### 15. **Adaptive Skill Granularity for Coding Agents** (2610.31461)
- **核心**：先前工作研究 agent 如何在**执行前**检索/组合/合成技能；但 coding agent 还有**执行期**的控制问题 —— 同一任务可走原始工具调用、宏技能或**混合执行**（先宏后微降级）。
- **方案**：**feature-based granularity controller**（条件于任务结构、执行状态、宏技能失败）+ **finite-state recovery executor**。
- **结果**：固定宏执行**适用时高效、不匹配时脆弱**；运行时路由与显式 macro-to-micro 恢复**提升鲁棒性**并救回固定粒度执行留下的受控宏失败。
- **核心观点**：skill 库应被视为**可控、可验证、可恢复的执行抽象**，不只是可检索资源。
- 详见 [[2026-10-24-2610.31461-adaptive-skill-granularity]]

### 16. **Towards User Simulators That Stay On Task And Still Sound Natural** (2610.31512)
- **核心**：prompted assistant 忠实意图但**缺行为保真**；专用模拟器**像真人但难以忠实复杂意图** —— 既有方法存在 trade-off。
- **方案**：RL recipe **同时奖励意图忠实度与行为自然度**；用**轻量判别器**操作化自然度，与用户模拟器在**交替对抗循环**中训练。
- **结果**：**UserLM-2.0** 有效模拟对话比例 **46.2%**，超过此前最强模拟器（14.1%）**三倍以上**。
- 详见 [[2026-10-24-2610.31512-user-simulators-task-naturalness]]

### 17. **Federated GraphRAG (FedGRAG)** (2610.30728)
- **核心**：GraphRAG 依赖中心化 KG，但真实知识**天然分布式**，且隐私约束**禁止共享完整本地图**。
- **方案**：**Federated Knowledge Routing** —— 用**轻量知识索引**定位相关客户端，**不暴露本地图结构**；**controlled-disclosure evidence construction** —— 抽取证据子图并转为 **evidence abstract**，支持服务器端转换与重建。
- **结果**：检索与下游生成任务上**一致优于现有基线**。
- 详见 [[2026-10-24-2610.30728-fedgrag-federated-graph-rag]]

### 18. **PointerBench: A Diagnostic Benchmark for Fine-Grained GUI Grounding** (2610.31274)
- **贡献**：**1,500 组截图-指令对**，三组子基准 —— **Sheets**（细粒度子元素 + 几何 grounding）、**Text**（**字符级 grounding**）、**Pro**（跨 **100 个专业应用**）；每任务**像素级精确**目标几何；评测通用多模态模型 + **39 个专用配置**。

### 1. 记忆系统的"祛魅"是最强信号

### 2. 评测方法论本身正在成为被批判的对象
Prompt Sensitivity（加工具放大敏感性）、Reward Scores across Prompts（pairwise 掩盖跨 prompt 漂移）、Simulated Control Evals（control setting 不代表部署环境）—— 三篇从不同角度指向同一件事：**当前的标准评测流程可能在系统性地产生不可靠结论**。这是比任何单项方法改进都更值得关注的信号。

### 3. "拒绝"与"不作为"正在被识别为独立风险类别
EpiSEM-Bench（拒绝获取缺失证据 ≠ 安全）、Invisibilization（因报告者身份而拒绝信息是**概率偏差**而非中性行为）、Prompt Sensitivity（不调用工具的报告**不保证**比较稳定）—— "模型没做什么"正在成为独立于"模型做错什么"的评测维度。

### 4. 效率优化进入"精细化"阶段
不再是大粒度的剪枝/量化，而是**时机的把控**（drift 决定何时）、**分支的预筛**（验证前估值）、**bit 的重新分配**（4-bit n-gram + 省下内存再投入更大的表）。共同特征：**保效用前提下省算力**，且多数声称**输出完全等价或可对齐**。
