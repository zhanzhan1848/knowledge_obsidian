## 核心贡献

> 提出 **Rate-Controlled Refresh (RCR)** —— 让**漂移（drift）决定何时、何处重新选择**，让**逐样本控制器决定重新选择的频率**，二者解耦，从而在长文本多模态生成中高效刷新 KV cache 的视觉 token 保留集合。

1. **揭示一次性选择的致命缺陷**：现有 KV 压缩在 prefill 时选一次视觉 token 就全程复用；在详细图像描述上，**即使用未压缩答案的 attention 做 oracle 选择**，与未压缩输出也只有 **0.44–0.52 ROUGE-L 一致度** —— 因为模型"读"的证据会随描述展开而移动
2. **诊断固定阈值必然失败**：漂移幅度**跨样本不可比**，低漂移样本几乎从不被刷新，**而它们恰恰最受益**
3. **RCR 机制**：漂移负责"when & where"，逐样本控制器负责"how much"，配合低秩漂移检测器、候选受限的重新选择、以及留在 GPU 上的判决
4. **统一配置泛化**：一套设定通用于所有模型与任务，5/6 个 model-task 设置上超过逐步检索方法 InfiniGen **1.6–3.8 ROUGE-L**，第 6 个无显著差异
5. **成本可控**：与精确的逐步重选差距在 **1.7 分**以内，每步数据搬移量相当，检测器 GPU 占用**小 4 倍**

## 技术方案

### 问题定位

多模态 LLM 的 KV cache 压缩通常在 prefill 时一次性选定要保留的视觉 token，之后整个生成过程复用该选择。长文生成中"证据在动"，一次性选择严重受限。

### 关键组件

| 组件 | 说明 |
|------|------|
| Drift detector (low-rank) | 低秩漂移检测器，判定保留集合外的 attention 漂移；驻留 GPU，体积为对比方案的 1/4 |
| Per-sample rate controller | 逐样本控制器：决定"多频繁"刷新，把漂移幅度的不可比性吸收掉 |
| Candidate-restricted re-selection | 重新选择限定在候选集内，避免全量重选 |
| GPU-resident decision | 判决逻辑保持在 GPU 上，避免频繁 host-device 往返 |

### 关键设计原则

```
漂移 (drift)  ──→  决定 when & where  (何时、何处重选)
速率控制器     ──→  决定 how much      (多频繁重选)
```

### 关键公式（速率控制角度）

把"预算"与"漂移"解耦，可写为逐样本的刷新预算调度：

```math
r_t = C(\sigma_t),\qquad \sigma_t = \mathrm{drift}(A_t, S_t)
```

```math
\text{refresh}(t) = \mathbb{1}\big[\sigma_t > \tau \;\wedge\; t \ge t_{\text{last}} + 1/r_t\big]
```

其中 $\sigma_t$ 为第 $t$ 步相对保留集合 $S_t$ 的漂移量，$C(\cdot)$ 为逐样本控制器给出的刷新速率，$\tau$ 为漂移侧的触发条件——漂移负责"where"，速率负责"how much"。

## 实验结论

### 主结果（与 InfiniGen 对比）

| 指标 | 结果 |
|------|------|
| ROUGE-L 提升（5/6 个 model-task 设置） | **+1.6 ~ +3.8 分** |
| 第 6 个设置 | 无显著差异 |
| 与精确逐步重选的差距 | **≤ 1.7 分** |
| 每步估计数据搬移量 | 与 InfiniGen 相当 |
| GPU 常驻检测器体积 | **小 4 倍** |
| Oracle 上界（未压缩答案 attention 选择 vs. 未压缩输出） | 仅 **0.44–0.52 ROUGE-L** |

### DetailCaps 消融：时机的价值

| 对比 | 结果 |
|------|------|
| RCR 的漂移时机 vs. 同刷新率下的随机时机 | **+2.0 ~ +5.0 分** |
| RCR 的漂移时机 vs. **更高**刷新率下的周期性时机 | **+2.0 ~ +5.0 分** |

### 预注册视频描述（漂移同质场景）

| 设置 | 结果 |
|------|------|
| Qwen2-VL | 与 InfiniGen 持平 |
| Qwen3-VL | 超过 InfiniGen |
| vs. 最近测试的固定阈值 | **不再领先**（与前述诊断一致） |
| 对象级评测（object-level F1，对比未压缩输出） | 3 个模型中 2 个高于 InfiniGen |

## 局限性

- 收益高度依赖**漂移的样本间异质性**：在漂移同质的视频描述场景下，RCR 相对固定阈值的优势消失
- 仍是**近似**方法：与精确逐步重选存在 1.7 分差距，且刷新决策本质是启发式
- 依赖低秩漂移检测器的质量，对比未压缩输出的 object-level F1 仅在 3 个模型中的 2 个占优，未全面领先
- 需要维护候选受限的 re-selection 集合与 GPU 上的判决逻辑，显存与实现复杂度高于简单的一次性压缩

## 实现建议

- **实现难度**: 中高（需要 per-sample 速率控制器 + 低秩漂移检测器的 GPU 常驻实现）
- **适用场景**: 详细图像描述、长视频描述等"证据随生成推移"的多模态长文生成场景
- **建议起点**: 先在 DetailCaps 上复现"漂移时机 vs. 随机时机 vs. 周期性时机"的对照，验证漂移信号在你的任务上是否真的可区分；再调控制器
- **价值点**: 核心洞见是"漂移定时机、预算定频率"这一解耦 —— 直接用固定阈值（多数实现的做法）在低漂移样本上会系统性失效
- **注意**: 若你的任务漂移同质（如均匀分布的视频描述），固定阈值可能反而更省算力
