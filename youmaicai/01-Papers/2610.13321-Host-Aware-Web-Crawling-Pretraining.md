## 核心贡献

> 系统研究 LLM 预训练 web crawl budget 应如何分配：跨 host（centrality vs random）与 host 内（先采样再决定 depth），发现 few-pages-as-probe 策略比 uniform / graph-centrality 更高效。

1. **跨 host 变异**: ~50% quality classifier 变异来源于 host 之间
2. **Probe-and-extend**: 先采少量页 → 高分 host 多抓 → 高质量页/fetch 提升数倍
3. **重新评估 Centrality**: Common Crawl 的 harmonic centrality 在他们模拟下增益有限（甚至更差）

---

## 技术方案

### 核心思想

数据选择 pipeline 大多只看单页 quality signal，忽略 host-level 结构。本文显式分析：何时跨 host 选、何时 host 内深挖。

### 关键技术

| 技术 | 说明 |
|------|------|
| Document-level quality classifier | 单页质量打分 |
| Web-graph centrality (harmonic) | Common Crawl 现用 host 选择信号 |
| Common Crawl per-host coverage | 实证观察 vs quality signal 相关性 |
| Few-pages-as-probe allocation | 采样 5-N 页估算 host 质量，再扩展 |

### 关键发现

- 跨 host 变异 ≈ 总变异 **50%**（between-host）
- Few-page probe → 高质量页/fetch 比 uniform depth 或 centrality 高**数倍**
- Common Crawl 实际 per-host coverage 与 quality signal **相关性弱**
- Centrality-driven crawl 在某些 classifier 上甚至**不如 random**

---

## 实验结论

- **数据集**: Common Crawl 多 snapshot
- **方法**: simulation + 分析
- **结果**:
  - 随机 order 经常匹敌 centrality（部分 classifier 反而更差）
  - Probe-and-extend 高质量页/fetch **数倍** 提升
  - 调整 crawl policy 直接影响 LLM 预训练数据 mix

---

## 局限性

- 仅在 Common Crawl snapshot 上做 simulation，未在真实 pretraining run 上验证下游 loss
- Quality classifier 本身是研究目标（不同 classifier 结论不同）
- "Probe size" 最优值未严格给出

---

## 实现建议

- **实现难度**: 低（crawl policy 改动，无需模型改动）
- **预期性能**: 高质量 token / fetch 提升数倍，潜在 pretraining loss 改善
- **适用场景**: 任何自建 pretraining corpus pipeline（替代 Common Crawl default centrality）
