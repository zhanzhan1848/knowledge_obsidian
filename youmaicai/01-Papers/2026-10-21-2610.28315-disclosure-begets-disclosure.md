## 核心贡献

> 发现**普通（非对抗性）助理助手中的隐私自强化循环**：agent 引用记忆中的属性 → 用户默认确认或不予纠正 → 该线索与 agent 自己的猜测被记录为确定值 → 循环自我强化。用户**无法自行打破**（纠正=披露、拒谈=推向敏感值、错误值固化）。

1. **多会话模拟**：模拟用户含 24 项个人属性，与「用/不用记忆」的客服 agent 对话
2. **跨 4 个客服模型一致成立**：记忆提升响应质量，**同时**提升经验泄漏率，且差距随会话数**扩大**
3. **量化机制**：移除 agent 对某属性的提及，可使其后续披露降低约**单轮效应的两倍**
4. **有效干预点**：唯一有效的缓解在 **agent 侧响应** —— 指示 agent 不陈述/不预设属性，泄漏降至无记忆水平且保住大部分质量收益

---

## 技术方案

### 自强化循环机制

```math
\underbrace{\text{agent 预设属性值}}_{\text{响应}}
\to \underbrace{\text{用户确认或沉默}}_{\text{对话}}
\to \underbrace{\text{线索 + agent 猜测被记为确定值}}_{\text{记忆写入}}
\to \underbrace{\text{下一轮更高置信度的预设}}_{\text{下一轮响应}}
```

| 用户的三个选项 | 为何无效 |
|--------------|---------|
| 纠正数值 | **披露了该属性存在** |
| 拒绝讨论 | 后续预测**转向敏感值** |
| 放任错误值 | 错误值**固化** |

### 泄漏与质量的两难

| 干预侧 | 泄漏 | 质量 |
|--------|------|------|
| 不记记忆 | 无泄漏 | 无质量收益 |
| 过滤/匿名用户输入 | 部分降低 | **损失大部分质量收益** |
| 过滤/匿名存储内容 | 部分降低 | **损失大部分质量收益** |
| **agent 不陈述/不预设属性** | **≈ 无记忆水平** | **保留大部分收益** |

---

## 实验结论

- 4 个客服模型上，记忆使经验泄漏率（从完整累积记录中正确推断出的属性值占比）上升，**margin 随会话扩大**
- 移除 agent 对某属性的提及 → 后续披露下降 **~2x 单轮效应**
- Agent 侧「不陈述/不预设」指令：泄漏 ≈ 无记忆水平，质量收益大部分保留

---

## 局限性

- 结论基于**模拟用户**，真实用户行为可能不同
- 属性集合为客服场景设计（24 项），跨领域泛化待验证
- "不陈述属性"指令可能损害某些确实需要个性化的高价值场景
- 论文强调循环发生于**非对抗性**常规使用，攻击者视角未覆盖

## 实现建议

- **实现难度**: 低（改 agent system prompt 即可尝试）
- **适用场景**: 任何带跨会话记忆的客服/助理类 agent
- **实践建议**: 记忆存储应区分「用户明确陈述」与「agent 推测/预设」两类，**在响应层禁止 agent 陈述未确认属性**；这比事后过滤/匿名存储性价比高得多
