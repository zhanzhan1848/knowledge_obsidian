# Don't Lose the Thread: Empowering Long-Horizon LLM Agents with Cognitive Resource Self-Allocation

## 摘要
长程（long-horizon）任务上，LLM agent 的工作记忆会被不断膨胀的环境反馈与失败尝试历史填满，造成"认知过载"（cognitive overload），稀释注意力并损害规划与推理能力。现有上下文优化方案多由固定间隔或上下文接近饱和的规则触发，属于外部控制器；本文提出 **CORAL（COgnitive Resource Self-ALlocation）**，把它做成 agent 可自主调用的工作记忆管理工具集：**Memory Management (MM)** 工具记录任务进度与已核实事实，**Context Optimization (CO)** 工具在 agent 判断上下文过长或杂乱时硬重置上下文、只保留 checkpoint 内容，使 agent 从干净状态继续推理。训练分两阶段：先用 SFT 注入 checkpoint 能力，再用新提出的 **Multi-episode ARPO**（把轨迹级奖励跨 episode 边界传播、从而优化 checkpoint 策略）强化。GAIA 上 8B 模型达 **42.8%** 平均准确率，在最难的 Level 2/Level 3 上优势显著；更关键的是**输入 token 比 ReAct agent 少 6–7×**（136K vs 1,078K per trajectory，LLM 调用 15.2 vs 45.3），并在多跳 Knowledge QA 与更难的 BrowseComp 上泛化（BrowseComp 上把一个强商用 agent 提升 **8.0 点**）。论文被 COLM 2026 接收，代码见 github.com/JIA-Lab-research/CORAL。

## 核心贡献
1. **CORAL 框架**：把认知卸载（cognitive offloading）引入 LLM agent，MM + CO 两个自主调用工具，构成多 episode 轨迹范式。
2. **Multi-episode ARPO**：把 DAPO 扩展到多 episode 轨迹——奖励从最终 episode 计算并回传给所有前置 episode，实现跨 episode 边界的 credit assignment，使"何时 checkpoint、何时重置"成为可学习策略。
3. **训练范式**：SFT（按 episode 切分轨迹、mask 观测 token）→ Multi-episode ARPO；Qwen3-8B 上 20.4% → 41.6% → 42.8%。
4. **效率论证**：CORAL RL 比 ReAct 少用 **87.4%** 输入 token，准确率却是 ReAct 的两倍多——"管理注意力"不是精度的成本而是精度的来源。
5. **系统性的数据消融**：证明"错误轨迹"对 behavior cloning 仍有价值（监督的是过程而非结论），并给出体积匹配的随机子采样对照。

## 方法与架构
### 1. 问题形式化
沿 ReAct 的 Thought-Action-Observation 循环，agent $\pi_\theta$ 在 step $t$ 生成 $r_t\sim\pi_\theta(\cdot|c_t)$ 与 $a_t\sim\pi_\theta(\cdot|c_t,r_t)$，上下文 $c_t=(s,q,r_1,a_1,o_1,\ldots)$，环境返回 $o_t$。单 episode 终止/完成定义：

```math
e_{\text{terminated}}=(s,q,r_1,a_1,o_1,\ldots,r_M,a_M,o_M),\quad
e_{\text{completed}}=(s,q,r_1,a_1,o_1,\ldots,r_M)
```

### 2. 两个 agent 可调用工具
- **Memory Management (MM)**：维护两类持久信息——**Task progress**（高层计划与各 sub-goal 完成情况）与 **verified facts**（推理中确认过的关键信息/中间结果/发现的实体）；可增删改条目，checkpoint 在上下文重置后存活。典型调用时机：任务开始记录计划、发现关键信息时存为已核实事实、完成子任务后更新进度。
- **Context Optimization (CO)**：当 $a_t = a_{CO}$ 时硬重置——清空对话历史，把当前 memory 状态作为 observation $o_t$ 返回，下一 episode 的初始上下文为 $(s,q,o_t)$。

### 3. 多 episode 轨迹
第 $i$ 个 episode（含 $M_i$ 次迭代）：

```math
e_i=\begin{cases}(c_i,r_{i,1},a_{i,1},o_{i,1},\ldots,r_{i,M_i},a_{i,M_i},o_{i,M_i}), & i<N\\
(c_i,r_{i,1},a_{i,1},o_{i,1},\ldots,r_{i,M_i}), & i=N
\end{cases}
```

```math
c_i=\begin{cases}(s,q), & i=1\\ (s,q,o_{i-1,M_{i-1}}), & i>1\end{cases},\qquad T=(e_1,e_2,\ldots,e_N)
```

### 4. 阶段一：Behavior Cloning（SFT）
按 episode 切分轨迹后用 episode 批次训练。切分的必要性在于各 episode 的初始上下文不同（第一个从 $(s,q)$ 开始，后续从 $(s,q,o_{i-1,M_{i-1}})$ 开始），若拼成扁平对话会歪曲推理时的实际所见。损失：

```math
\mathcal{L}=-\frac{1}{\sum_{i=1}^{|e|}\mathbb{I}(x_i\neq o)}{|e|}\sum_{i=1}^{|e|}\mathbb{I}(x_i\neq o)\cdot\log\pi_\theta(x_i\mid x_{<i})
```

$\mathbb{I}(x_i\neq o)$ 屏蔽 observation token，只监督模型自身的 thought 与 function call。作者指出 episode 位置决定所监督的技能：非末 episode 教模型"推进任务并维护工作记忆、识别何时子任务已完成可以丢弃上下文"，因此 CO 调用是一个**被监督的决策**而非外部规则触发；靠后的 episode 教模型"从 checkpoint 恢复"——拿到紧凑的进度+事实状态而非历史，必须定位下一个 sub-task 而不重做已完成工作。这两类技能在扁平轨迹训练的 ReAct agent 中都不会出现。

### 5. 阶段二：Multi-episode ARPO
对问题 $q$ 采样 $G$ 条多 episode 轨迹 $T_i=(e_i^1,\ldots,e_i^{N_i})$。奖励从最终 episode $e_i^{N_i}$（含答案）计算并**向前回传**给所有 episode：

```math
R_i^j=R_i,\quad \forall j\in\{1,\ldots,N_i\}
```

设所有 episode 集合 $E=\{e_i^j\mid i\in[1,G],j\in[1,N_i]\}$，目标：

```math
J_{\text{ME-ARPO}}(\theta)=\mathbb{E}_{q\sim\mathcal{D},\{T_i\}\sim\pi_{\theta_{old}}}\left[\frac{1}{\sum_{e\in E}|e|}\sum_{e_i^j\in E}\frac{|e_i^j|}{\sum_{t=1}^{|e_i^j|}\min\left(r_{i,j,t}(\theta)\hat A_i^j,\ \mathrm{clip}\left(r_{i,j,t}(\theta),1-\epsilon_{low},1+\epsilon_{high}\right)\hat A_i^j\right)\right]
```

```math
r_{i,j,t}(\theta)=\frac{\pi_\theta(e_{i,j,t}\mid c_i^j,e_{i,<t}^j)}{\pi_{\theta_{old}}(e_{i,j,t}\mid c_i^j,e_{i,<t}^j)},\qquad
\hat A_i^j=\frac{R_i-\mathrm{mean}(R)}{\mathrm{std}(R)}
```

$R=\{R_{i,j}\mid i\in[1,G],j\in[1,N_i]\}$ 收集同一问题下所有 episode 的（继承自父轨迹的）奖励，优势按问题在所有 episode 上归一化。**奖励函数**：

```math
R_i=R_i^{\text{format}}\times R_i^{\text{answer}}
$$

format 奖励检查整条轨迹是否符合预定义格式且所有 JSON 格式的 tool call 有效；answer 奖励用 LLM-as-judge 判断最终答案是否正确。

### 6. 认知心理学动机
Kahneman (1973) 把注意力建模为有限容量资源；Baddeley & Hitch (1974) 把工作记忆视为支持进行中推理的小型主动维持存储；认知负荷理论（Sweller, 1988）说明超载为何有害。人类的标准对策是**认知卸载**（Risko & Gilbert, 2016）——把中间状态外化（如写下来），让内部容量专注于当前子问题。CORAL 是其 agent 版类比。

## 实验设置
- **Agent 设置**：ReAct 风格循环 + 两个环境工具（Web Search、Web Browse）+ 两个 CORAL 工具（MM、CO）。
- **CORAL 变体**：Prompting（仅提示）、SFT、RL（Multi-episode ARPO）。
- **基线**：(1) Direct Inference——GPT-4o、DeepSeek-R1、Claude Sonnet 4；(2) Agentic Inference——R1-Searcher、WebDancer、WebThinker、Cognitive Kernel-Pro、WebSailor、WebShaper、OpenAI Deep Research；(3) ReAct（经典范式）。作者强调 agentic 基线本身是同等复杂度的**已训练**系统（多阶段 RL、SFT+iterative DPO、SFT+RL），因此 Table 1 是"已训练 agent 与已训练 agent"的比较。
- **基准**：(1) GAIA 标准 103 样本纯文本验证集（39 个 Level 1、52 个 Level 2、12 个 Level 3）；(2) Knowledge QA 套件：Natural Questions、HotpotQA、2WikiMultiHopQA、Musique、Bamboogle；(3) BrowseComp（需多跳网页探索，最考验上下文管理）。
- **训练数据**：沿用 WebShaper 的 formalization-driven 题目构造（Knowledge Projections、逐层展开 seed question 的叶子常量并对每步展开做证据校验）；由 Claude Sonnet 4 配 CORAL 工具集合成 **2,932** 条 web agent 轨迹，其中 **1,642（56%）**答对、**1,290（44%）**答错（两者都保留，答错者不是"near-miss"而是普通失败，仅按格式良好性过滤）；另加 **241** 条来自 NuminaMath 与 OpenMathReasoning 的数学推理轨迹以强化计算。合计 **3,173** 条原始轨迹，按 episode 切分后展开为 **3,682** 条 SFT 对话（每次 CO 调用多产生一条）。RL 阶段只用 web 任务，所有训练题独立于所有测试集合成。
- **评测协议**：每题采样 8 条独立轨迹，temperature **0.7**、top-p **0.8**；默认报告 Pass@1 (Avg@8)。

| CK-Pro-8B | **56.4** | 42.3 | 8.3 | **43.7** |
| WebDancer-32B | 46.1 | 44.2 | 8.3 | 40.7 |
| WebThinker-32B-RL | 56.4 | 50.0 | 16.7 | 48.5 |
| WebSailor-72B | – | – | – | 55.4 |

| OpenAI DR | 74.3 | 69.1 | 47.6 | 67.4 |

要点：8B 规模下 CK-Pro-8B 平均最高（43.7% vs CORAL RL 42.8%），但优势全在 Level 1（56.4% vs 46.2%），而 CORAL+RL 在 Level 2（45.7% vs 42.3%）与 Level 3（19.8% vs 8.3%）领先——维护工作记忆在"短到不会产生杂乱"的题上有开销，单一平均分会低估该方法。RL 相对 SFT 的 1.2 分平均增益被低估：Level 2 +2.2、Level 3 +4.2（Level 1 略降），且 RL 稳定了 agent，把运行间标准差从 **3.5% 降到 1.9%**、8 次运行中最差从 36.9% 提升到 39.8%。

**推理成本与工具使用（Table 2，GAIA，Qwen3-8B，全部 824 条评测轨迹 = 103 题 × 8 样本）**
| 方法 | 输入 token/轨迹 | LLM 调用 | 峰值上下文 | MM 调用 | CO 调用 | GAIA |
|---|---|---|---|---|---|---|
| ReAct | 1,078K | 45.3 | 30.6K | – | – | 19.4 |
| CORAL Prompting | 314K | 21.8 | 14.3K | 20.6 | 4.3 | 20.4 |
| CORAL SFT | 153K | 15.9 | 13.9K | 3.9 | 0.21 | 41.6 |
| **CORAL RL** | **136K** | **15.2** | **12.7K** | 4.1 | 0.21 | **42.8** |

CORAL RL 比 ReAct 少用 **87.4%** 输入 token。机制：CO 重置限制了上下文长度（峰值 12.7K vs 30.6K），而 ReAct 每轮重读全部历史、代价随轮数平方增长；写下计划与事实后 agent 不再重复搜索，轮数降到三分之一。工具用量有个有趣现象：训练后的 agent 只调用 CO **0.21** 次/轨迹（prompting 版为 4.3），说明训练教会模型"少重置、但更好地 checkpoint"；且重置会丢弃让 agent 修复早期错误的历史，因此 MM 保留历史、宜频繁使用。

**BrowseComp**：报告前 **150** 题，Claude Sonnet 4，CORAL **30.7%** vs 同工具的 ReAct **22.7%**，**+8.0 分**，为所有基准中最大增益，且完全无训练。附录案例（BrowseComp #6）：CORAL 36 轮（17 次 search、11 次 browse、7 次 MM）得正确答案，而 ReAct 47 轮（42 次 search、4 次 browse）后放弃——ReAct 用搜索量替代结构，其多数搜索在探查一个从未回头复查的错误前提。

## 局限性
作者自述（附录 E）：
- **跨 episode 的 credit assignment**：Multi-episode ARPO 把轨迹奖励**等同广播**给每个 episode，作者承认这与框架初衷存在张力——若一条轨迹混合了有成效的铺垫与失败绕路，等同奖励恰好抹掉了框架所依赖的区分。作者选择最简方案是为了先回答"专门训练能否改进 CORAL"这一问题；同时指出"对早期 episode 折扣"这一常规做法在此**可能反而有害**，因为 episode 边界不是任意时间点，而是 agent 主动做出的、被学习的整合决策，惩罚早期 episode 会抑制 CORAL 恰恰想安装的行为。改进方向：episode 级 reward model、基于"该 episode 的 checkpoint 事实被后续使用程度"的贡献加权方案。
- **对 memory store 的信任**：CORAL 的工作记忆在构造上是权威的——框架中没有任何机制允许 agent 怀疑已 checkpoint 的事实。附录 D.2 显示这是真实失效模式且边界清晰：**对话历史仍在**时被污染的事实常被发现；**CO 重置之后**被污染的事实则永不被发现。对话历史因此充当交叉验证通道，而 CO 会永久关闭该通道。作者提出 **provenance-aware memory**（每条 verified fact 携带指向其证据的指针，重置后可重新获取并复核）作为下一步。
- **评测规模**：GAIA 纯文本验证集只有 12 个 Level 3 题，单题变化即影响 8.3 分，标准差 9–10%，因此 Level 3 数字只能作方向性证据；缓解手段是每题 8 次采样平均、报告完整分布（含最差运行）、并在 5 个 Knowledge QA 基准与 BrowseComp 上交叉验证。
- **范围限制**：BrowseComp 只评测前 150 题、使用单一商用骨干（出于成本）；框架未处理"任务本身可被并行分解"或"存在并行子任务"的场景。

我的补充批评：(1) CO 调用在训练后降到 0.21 次/轨迹，与论文提出的"CO 是核心机制"存在张力——若模型几乎不重置上下文，那么"6–7× 更省 token"主要来自"不再重复搜索"而非上下文重置，论文的机制归因（"CO 重置限制上下文长度"）因此被自身数据削弱；(2) Multi-episode ARPO 把 DAPO 的 clip-higher 等稳定性技巧与跨 episode 广播结合，但没有与"仅在单 episode 上做 DAPO + 同样的 SFT 数据"的对照，无法区分增益来自多 episode 训练还是仅仅来自更多训练信号；(3) GAIA Level 3 只有 12 题且 Claude Sonnet 4 上的 CORAL prompting 反而低于其 ReAct 基线（19.4 → 20.4 中 ReAct 33.3 vs prompting 28.2），说明 prompting-only 在强模型上可能因工具调用格式而受损，这一负结果值得更多讨论。

## 评估与建议
- 是否推荐深入阅读：是（作为"context 膨胀导致长程 agent 失败"这一问题的系统方案，尤其多 episode RL 的形式化与效率论证）
- 适用场景：深度研究/网页 agent 的长程任务；上下文工程与压缩策略设计；需要自管理状态的 agent 训练（把"何时压缩"变成可学习决策）；agentic RL 中处理上下文重置这类"轨迹内事件"的 credit assignment。
- 与知识库的关联：与 context engineering / memory 管理类笔记（Mem1、MemAgent、Subconscious Threads）直接对照；与 agentic RL（DAPO/GRPO/Search-R1/WebThinker）笔记互补；与 2610.39182（RL 是否真的带来推理）共享"训练带来的收益究竟来自何处"的问题意识。
