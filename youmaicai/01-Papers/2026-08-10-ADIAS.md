## 核心贡献
1. **Issue-centric Agent Optimization**：提出问题中心的 Agent 优化范式（替代传统的 candidate-centric）
2. **Persistent Issue State**：维护显式持久化问题状态（包含 issue 身份、生命周期、支撑证据、干预-结果历史）
3. **Issue-guided Optimization**：使用问题状态联合提议修复目标和修订方向，实现聚焦的全代码修改

## 问题背景

### Candidate-centric 的局限
现有自动化 Agent 设计方法以候选 Agent 为中心：
- 跨轮经验围绕候选 Agent 组织
- 修复进度是隐式的
- 导致：修复目标不高效、进度累积缓慢、无效干预跨轮传播

### Issue-centric 的核心思想
跨轮经验围绕**问题**组织：
- 修复进度作为显式的持久化问题状态携带
- 每轮不再重新从候选历史推导，而是直接利用已有问题状态

## ADIAS 两个机制

### 1. Persistent Issue State
- **Issue Identity**：稳定的 issue 标识
- **Lifecycle Status**：issue 生命周期状态
- **Supporting Evidence**：支撑证据
- **Intervention-Outcome History**：干预-结果历史

### 2. Issue-guided Optimization
- 使用问题状态联合提议：
  - **修复目标**（哪个 issue）
  - **修订方向**（如何修复）
- 然后执行聚焦的全代码修改

## 实验结果
- **5 个交互式基准**
- 相比最强基线平均提升 **25.2%**
- **4 个 backbone 模型**均有一致提升

### 消融实验
- 移除 persistent issue state → 性能下降 **40.7%**
- 替换为 candidate-centric 策略 → 性能下降显著

## 局限性
- 主要在代码生成类 agent 上验证
- issue state 的维护有额外存储开销

## 建议
- **是否推荐**：✅ 是（Agent 系统设计的突破性进展）
- **适用场景**：Agent 代码自动化、复杂任务规划、AI Agent 迭代优化
- **相关方向**：Agent Design、AutoML、LLM Agent、Iterative Refinement
