## 核心贡献

> CLIP 可以承受大量 transformer block 的循环复用：在保持计算深度不变（$N\cdot M = 12$）的条件下，单 block 的 rCLIP 蒸馏后 ImageNet zero-shot 达 56.7%、6 block 达 68.8%（teacher 72.5%），而 r²CLIP 1b12i 只需 36.97M 参数即可工作（参考 CLIP 149.62M）。

1. **系统性递归 CLIP 架构研究** — 在固定计算深度下，把编码器的 $L=12$ 个独立参数 block 换成 $N$ 个不同 block 循环执行 $M$ 次，考察 $(N,M)\in\{(1,12),(2,6),(3,4),(4,3),(6,2)\}$ 五种配置；所有配置 FLOP-matched 于非递归 ViT-B，但需存储的 distinct transformer 参数显著减少。
2. **两个模型家族** — **rCLIP**（仅视觉编码器递归）与 **r²CLIP**（视觉与文本编码器同时递归）。参数量从 Ref. CLIP 的 **149.62M** 降到 r²CLIP 1b12i 的 **36.97M**（-75%），rCLIP 1b12i 为 **71.65M**（-52%），两者算力完全相同（17.57 visual GMACs + 2.98 text GMACs）。
3. **蒸馏目标选择的反直觉结论** — Feature Distillation (FD) 是最强的单一蒸馏信号（Ref. CLIP 达 37.0% ImageNet，逼近 CRD+ICL+FD 全组合的 37.3%）；而 **Activation Matching (AM) 在递归学生上崩溃**（rCLIP 1b12i 仅 15.5% vs 非递归 31.0%，保留率骤降至 **50%**，远低于输出级目标的 76–95%），故被排除；最终权重定为 $\lambda_{CRD}=1$、$\lambda_{ICL}=0$、$\lambda_{FD}=10^4$。
4. **文本塔可承受极端权重共享** — CLIP-only 直接训练下，r²CLIP 1b12i（56.34%）甚至略优于 rCLIP 1b12i（56.34% 对比更高基线）；从 2 block 起两者几乎相同；蒸馏后差距从 1 block 的 **4.7 点**收窄到 6 block 的 **1.1 点**。
5. **下游任务对递归的敏感度差异巨大** — Visual grounding 对递归几乎免疫（rCLIP 6b2i 在 RefCOCO testB 达 78.73 vs 蒸馏 ViT-B 的 78.85，ReferItGame 上 69.41 反而超过三个 ViT-B 参考的 68.26–68.98）；fine-grained 分类受影响最大（rCLIP 6b2i 在 Aircraft 仅保留参考模型的 78%）；16-shot LoRA 适配后差距大幅收窄（rCLIP 6b2i ImageNet 72.13 vs Ref. 75.18）。
6. **遗忘（unlearning）中的敏感差异** — DIET 后所有 backbone 的平均 forget-set 精度都降到 **5.1–15.2%**（递归）与 **6.4–7.3%**（非递归），但保留精度 $D_t$ 差异大：递归家族中 block 越多保留越好（rCLIP 1b12i Pets 从 87.2 掉到 45.6，rCLIP 6b2i 从 90.7 掉到 67.7，Ref. CLIP 从 92.2 掉到 69.1）。

## 技术方案

### 核心思想

CLIP 的可迁移能力通常被认为来自"每一层都有独立参数"，本文追问：**depth-wise 的参数独立到底有多必要？** 为了可控地研究这一点，作者采用一个干净的实验设计——保持**计算深度不变**，只改变**参数共享程度**。

具体地，把编码器原本的 $L$ 个独立参数 block 替换为 $N$ 个 distinct block 循环执行 $M$ 次，满足 $N\cdot M = L$：

$$F = B_N \circ B_{N-1} \circ \cdots \circ B_1, \qquad A^0 = \mathcal{T}(x), \qquad A^m = F(A^{m-1}),\ m = 1,\dots,M$$

最终表示 $z = \mathcal{P}(A^M)$。输入 tokenization 与输出层与标准 CLIP 完全一致。

与前人工作的关键区别有三点。第一，**不限于 $N=1$**：既有工作（SReT、MiniViT、bViT）要么用额外的 layer-specific 变换（SReT 的 sliced group self-attention、MiniViT 的轻量层特定变换），要么只研究单 block 递归（bViT）；本文允许 $N>1$，从而能扫出"性能 vs 模型存储占用"的连续权衡曲线。第二，**不引入 iteration-specific embedding**：相邻两次应用 $F$ 仅通过输入激活而不同，不靠位置编码区分迭代。第三，**把递归直接引入 CLIP 编码器本体**，而不是像 R-MMA 那样只在冻结 CLIP 上共享 recurrent adapter。

这一设计的直接后果是**参数效率与适配效率自然涌现**：模型只需存储 $N$ 个 block 而非 $L$ 个；下游 LoRA adapter 挂在 distinct block 上、随迭代复用，因此所需 adapter 数量也从 $L$ 降到 $N$。这对内存受限的边缘设备部署有实际意义。

### 蒸馏框架与 AM 的失效

作者把 CLIP-KD 框架适配到递归学生：teacher 是 DFN-2B 预训练的 CLIP ViT-B/16（强 teacher），student 在 **CC3M + CC12M**（共 **13,874,493** 图文对）上训练，远小于 teacher 的 DFN-2B。总目标：

$$\mathcal{L} = \mathcal{L}_{\mathrm{CLIP}} + \lambda_{\mathrm{CRD}}\mathcal{L}_{\mathrm{CRD}} + \lambda_{\mathrm{ICL}}\mathcal{L}_{\mathrm{ICL}} + \lambda_{\mathrm{FD}}\mathcal{L}_{\mathrm{FD}} + \alpha\mathcal{L}_{\mathrm{AM}}$$

其中 FD 直接匹配 teacher/student 的最终图文 embedding；CRD 匹配 mini-batch 上的跨模态相似度分布；ICL 让 student 图像特征对抗 teacher 文本特征（及对称方向）；AM 对齐中间层视觉表示。

AM 的关键问题是**索引对应关系**：递归 block $B_i$ 在第 $m$ 次迭代中被匹配到多个 teacher 层 $\{i, N+i, \dots, (M-1)N+i\}$。这隐含了一个假设——**共享 block 的连续应用会沿着 teacher 的逐层轨迹前进**。实验证伪了这个假设：rCLIP 1b12i 的单个 block 被要求匹配 12 个不同 teacher 层，而其递归轨迹根本不重现 12 个独立参数 block 产生的表示序列，逐点匹配因而成为过度约束的枷锁（保留率仅 50%）。这个发现是本文最有迁移价值的部分之一：**为非递归学生设计的层间对应式蒸馏目标，在强参数共享下会失效**，必须改用输出级（output-level）信号。

### 下游适配的三种协议

下游适配协议全部**沿用为非递归模型设计的方法**，并把"层"的概念重新映射到"执行步 / distinct block"：

- **Few-shot classification**：CLIP-LoRA，16 shots/class，10 个数据集，adapter 挂在递归核的每个 distinct block 上并随迭代共享。
- **Visual grounding**：HiVG，5 个数据集（RefCOCO/+/g、ReferItGame、Flickr30k Entities），报告 IoU ≥ 0.5 的 top-1 准确率；HiVG 的 cross-modal bridge 与 LoRA curriculum 原本绑定 distinct transformer 层，作者改绑到执行步与 $N$ 个 distinct block。
- **Unlearning**：DIET（retain-data-free 方法），通过挂在视觉编码器上的 LoRA adapter 移除一个类，报告 forget-set 精度 $D_f$ 与全测试集精度 $D_t$，5 个种子各随机抽一个待遗忘类。

### 关键技术

| 技术/方法 | 说明 |
|------|------|
| 递归 transformer 核 | $N$ 个 distinct block 循环 $M$ 次，$N\cdot M = L = 12$，FLOP-matched 于非递归 ViT-B |
| rCLIP | 仅视觉编码器递归，文本编码器保持标准 12 block |
| r²CLIP | 视觉与文本编码器同时递归（cross-encoder joint recurrence） |
| 配置命名 | `NbMi`，如 `1b12i`（1 block × 12 次）、`6b2i`（6 blocks × 2 次） |
| Feature Distillation (FD) | 匹配 teacher/student 最终图文 embedding；最强的单一蒸馏信号 |
| Contrastive Relational Distillation (CRD) | 匹配 mini-batch 上的跨模态相似度分布 |
| Interactive Contrastive Learning (ICL) | student 图像特征 vs teacher 文本特征，双向 |
| Activation Matching (AM) | 对齐中间层视觉表示；**在递归学生上失效**（保留率 50%） |
| 全局执行索引 | $\ell = (m-1)N + i$，给 student 的 $L$ 次执行与 teacher 的 $L$ 层建立索引保持的对应 |
| 迭代无 embedding | 不用 iteration-specific embedding，相邻迭代仅靠输入激活区分 |
| CLIP-LoRA | 16-shot 适配，adapter 挂在 distinct block 上并跨迭代复用 |
| HiVG | grounding 适配，bridge/curriculum 重绑到执行步与 distinct block |
| DIET | retain-data-free 概念遗忘，每 distinct block 一个 LoRA adapter |
| 训练配置 | AdamW，峰值 lr $10^{-3}$，10k warmup + cosine decay，effective batch 1024，32 epochs |

### 实验设置

| 维度 | 规模 |
|------|------|
| Teacher | CLIP ViT-B/16 预训练于 DFN-2B（冻结） |
| Student 训练数据 | CC3M + CC12M = **13,874,493** 图文对 |
| 递归配置 | $(N,M)\in\{(1,12),(2,6),(3,4),(4,3),(6,2)\}$，$N\cdot M=12$ |
| 模型族 | rCLIP、r²CLIP；参考模型 Ref. CLIP（非递归，同配方蒸馏）+ OAI ViT-B/16 checkpoint + Teacher |
| 零样本分类 | ImageNet-1k + V2 / Rendition / Sketch 变体，80-prompt template ensemble |
| 跨模态检索 | Flickr30k、MSCOCO，Recall@1（t2i / i2t） |
| Few-shot | 10 个分类数据集，CLIP-LoRA，16 shots/class |
| Grounding | RefCOCO / RefCOCO+ / RefCOCOg / ReferItGame / Flickr30k Entities，IoU ≥ 0.5 |
| Unlearning | DIET，Flowers102 / Pets / Food101，5 seeds，每 seed 随机抽一个遗忘类 |
| 算力 | 每个模型 17.57 visual GMACs + 2.98 text GMACs（224×224，77-token context） |

### CLIP-only 直接训练（Section 4.1）

- rCLIP ImageNet 从 1 block 的 **32.8%** 升到 6 block 的 **36.5%**，最大增益出现在 1→2 block 之间，之后饱和。
- r²CLIP 1b12i 甚至**略优于** rCLIP 1b12i；2 block 起两者几乎相同——说明文本塔能承受极大权重共享。

### 蒸馏后结果（Section 4.3）

| 模型 | ImageNet zero-shot |
|------|------|
| Teacher (DFN-2B ViT-B/16) | 72.5 |
| Ref. CLIP（蒸馏） | 71.86（≤ teacher 4 点） |
| rCLIP 1b12i | 56.7 |
| r²CLIP 1b12i | 52.0 |
| rCLIP 6b2i | **68.8** |

- rCLIP 与 r²CLIP 的差距从 1 block 的 **4.7 点**收窄到 6 block 的 **1.1 点**；在 shift 数据集上差距更小，6 block 时 r²CLIP 在 ImageNet-R 上略超 rCLIP。
- 检索任务上差距更大：Flickr I2T rCLIP **85.4** vs r²CLIP **83.7**——激进共享文本塔对跨模态匹配影响更强。
- 非递归 Ref. CLIP 在 zero-shot 分类上最多落后 teacher **4 个点**（尽管训练数据少得多），却在跨模态检索上**略微超过** teacher。

|------|------|------|------|------|
| OAI ViT-B/16 | 6.36 | **67.73** | 4.36 | 56.60 |
| Teacher | 7.32 | **70.19** | 3.87 | 74.24 |
| Ref. CLIP | 6.57 | 57.55 | 2.60 | 56.45 |
| rCLIP 1b12i | 8.73 | 38.85 | 4.29 | 33.48 |
| rCLIP 3b4i | 15.15 | 52.22 | 7.20 | 51.92 |
| rCLIP 6b2i | **5.14** | 54.51 | **1.84** | 44.67 |
| r²CLIP 1b12i | 8.26 | 38.71 | 5.67 | 27.73 |
| r²CLIP 6b2i | 5.55 | 54.95 | 0.82 | 44.30 |

- 遗忘本身都很有效：递归配置平均 forget-set 精度降到 **5.1–15.2%**，非递归参考为 **6.4–7.3%**。
- 差异主要在**保留**：蒸馏 ViT-B 平均 $D_t$ 掉 **22.2 点**，OAI checkpoint 掉 **14.1 点**（Food101 上 80.2→47.1 vs 85.9→72.8）——但这一行为在非递归学生上同样存在，**并非递归导致**；teacher 也掉 **17.0 点**，提示预训练语料与共享学习率协议可能也有份。
- 递归家族内部：block 越多保留越好（如 Pets：rCLIP 1b12i 87.2→45.6，rCLIP 6b2i 90.7→67.7，Ref. CLIP 92.2→69.1）。
- rCLIP 与 r²CLIP 在相同配置下差异很小，所有 block 数上平均 post-DIET $D_t$ 差异都在 **0.6 点**内——文本塔递归对遗忘行为影响甚微。

## 局限性

- **单次训练运行**：多数实验只用单次 run，作者自己提示"小幅性能差异应谨慎解读"；蒸馏目标选择阶段的消融更是只用 CC3M + 单种子。
- **未探索的递归变体**：没有评估 block-specific iteration counts（每层不同迭代次数）、loop-specific LoRA（Relaxed Recursive Transformers 路线）等更细粒度的共享方案。
- **适配协议是为非递归模型设计的**：下游适配协议直接沿用 CLIP-LoRA / HiVG / DIET 的原始配方，作者承认其表现可能对超参敏感，针对递归模型专门调优可能带来提升。
- **规模受限**：所有实验在 ViT-B/16 尺度上进行（$L=12$），结论能否外推到更大深度的模型（如 ViT-L 的 24 block）未验证；$N\cdot M = L$ 的约束也限制了更激进的共享比例。
- **数据规模差距**：teacher 用 DFN-2B、student 只有 CC3M+CC12M（13.87M 对比 DFN-2B 的 2B 量级），递归与非递归学生的绝对精度都被数据量压制，"递归几乎无损"的结论可能低估了递归的上限。
- **AM 失效的机制未解释**：作者明确说"详细解释留待未来研究"，只给出"递归轨迹不复现 teacher 逐层轨迹"这一现象描述，未做进一步诊断实验。
- **遗忘实验的混淆**：保留精度的下降部分源于蒸馏与较小训练集，而非递归本身，因此"递归对遗忘更敏感"这一说法在家族内部成立但跨家族比较需谨慎。

## 与知识库既有工作的关系

- 与 [[2026-03-13-Algorithmic-Capture-Infinite-Transformers]] 同属"递归/共享 transformer 的表达能力边界"方向，但本文把问题移到**视觉-语言对比模型**上，并系统研究了蒸馏目标在共享条件下的适配性。
- 与知识库中既有 CLIP 压缩类工作（TinyCLIP / CLIP-KD 谱系）形成对照：那些方法靠**减少层数或剪枝**降参数，本文靠**参数共享**在保持计算深度的同时降参数，并给出了完整的下游适配（few-shot / grounding / unlearning）评估。
- 延续"参数效率的来源不止一种"的主线：本文的 AM 失效发现与知识库中关于"为特定架构设计的训练目标不能直接迁移"的教训一致（例如 [[2026-03-12-SNA-Separable-Neural-Architectures]] 中结构约束与训练目标需协同设计）。

## 建议

- **是否推荐使用**：是（有条件）
- **适用场景**：适合在边缘/内存受限设备上部署 VLM 时的架构选型参考；适合做 CLIP 蒸馏与参数高效适配的研究者；不适合作为"CLIP 可以无损压缩"的一般性结论依据（本文只覆盖 ViT-B 尺度与特定数据规模）。
- **可借鉴要点**：
  1. **AM/层间对应式蒸馏目标在强参数共享下会失效**——若把模型改造成循环结构，必须改用输出级蒸馏信号（FD 最强），并检查旧的层对齐 loss 是否还成立；这是本文最可直接迁移的负面结论。
  2. **"共享程度 × 下游任务"的二维地图**可直接复用：grounding / 跨模态检索 / fine-grained 分类 / 遗忘对参数共享的敏感度差异巨大，评估一个共享结构时不要只看零样本分类这一个数。
  3. **"计算深度固定、只改参数共享"是研究共享程度的干净实验设计**，比"顺带减层"更能分离出共享本身的影响，值得作为架构消融的模板。
