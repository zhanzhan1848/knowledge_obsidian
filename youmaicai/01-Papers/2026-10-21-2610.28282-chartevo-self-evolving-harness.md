## 核心贡献

> 提出 **ChartEvo** —— 递归自我改进框架：让 chart agent 通过**经验驱动的 harness 级自我改进**适应表现不佳的图表类型，同时联合演化可复用的 **Skills** 与可执行的 **Tools**。

1. **问题**：MLLM 在常见图表上表现好，但在**长尾图表**（多样视觉结构 + 各异推理需求）上准确率急剧下降
2. **递归自我改进**：以 harness（而非模型权重）为改进对象
3. **联合演化两层能力**：可复用 chart-specific **Skills** + 可执行 **Tools**
4. **推理开销控制**：学习**可复用的局部工具调用链**来组合已演化能力
5. **效果**：相对基座 Qwen3.7-Plus，在 ChartBench 长尾图表上 **+45.6%**、ChartX 上 **+32.5%**

---

## 技术方案

### 为什么改进 harness 而非模型

| 路径 | 瓶颈 |
|------|------|
| 微调 MLLM | 覆盖不断变化的长尾类型成本高、不可扩展 |
| 手工工程策略与工具 | 长尾异构且持续演化，**难以规模化** |
| **递归 harness 自我改进** | 可扩展 ✅ |

### 三层机制

```math
\text{failure on chart type} \to \text{evolve Skill} + \text{evolve Tool} \to \text{compose via learned call chains}
```

| 组件 | 作用 |
|------|------|
| **Skills** | 可复用的图表类型特定技能 |
| **Tools** | 可执行的视觉能力工具 |
| **局部工具调用链** | 组合已演化能力，**控制工具增强推理的开销** |

递归性：改进后的 harness 本身成为下一轮的经验来源。

---

## 局限性

- 改进过程需**失败驱动的交互**，推理成本高于单次前向
- 仅图表领域 —— 递归 harness 改进能否迁移到其他多模态任务未验证
- 递归自我改进存在**误差累积 / 漂移**风险，稳定性分析未见
- Skills/Tools 演化后是否可解释、可审计未说明

## 实现建议

- **适用场景**: 多模态任务中的长尾分布（图表、文档、工业质检）—— 领域会持续演化、长尾无法穷举工程化
- **实践建议**: 优先投入「**可复用的工具 + 调用链**」而非「更多专用工具」；调用链学习是控制开销的关键
- **⚠️ 建议**: 需要配套的 harness 版本管理与回滚 —— 递归改进的漂移风险应纳入上线流程
