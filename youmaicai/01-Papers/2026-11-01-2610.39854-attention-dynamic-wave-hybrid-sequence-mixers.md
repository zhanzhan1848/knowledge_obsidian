# Attention, Dynamic Wave and Hybrid Sequence Mixers in Language Models

## 摘要
本文形式化了一种基于输入依赖的指数阻尼（exponential damping）与余弦相位调制（cosine phase modulation）的 Dynamic Wave 循环层，并在 TinyStories 上评测三种 10.94M 参数配置：Pure Transformer、Pure Wave 与 Hybrid Wave-Attention，考察 perplexity、latency、throughput 与 peak VRAM（最长 4096 token）。Hybrid 取得最佳 perplexity——完整 held-out split 上 5.95，优于 Transformer 的 6.93 与 Pure Wave 的 7.26。但效率结论由实现而非架构决定：相对 unfused attention 基线，Pure Wave 在 4096 token 上少用 78.7% peak VRAM（1404.3 MB vs 6601.6 MB）；相对 fused scaled-dot-product attention kernel，同样的比较则毫无优势（1404.3 MB vs 1403.6 MB）；训练模式下 Pure Wave 反而比 Transformer 贵 8.3%。把 elementwise 项提出循环外可使该层加速 2.53 倍（无需自定义 kernel），把相对 attention 的延迟差距从 2.48 倍缩到 1.12 倍。Hybrid stack 的 peak VRAM 与 Pure Transformer 匹配到 0.1% 以内——它继承的是更贵那个 mixer 的成本而非更便宜那个的优势。论文给出闭式显存模型，重现了实测值并预测出 attention 超过 vocabulary projection 的上下文长度。核心结论是：循环式 attention 替代方案的效率收益必须相对于具名的 attention backend 与具名的实现来陈述，而 hybrid 化最好以质量为理由。

## 核心贡献
1. **Dynamic Wave 层的数学形式化**：实值阻尼振荡递推，与复值对角 state space（S4D、Linear Recurrent Unit）的关系被明确指出。
2. **证明该递推是 associative scan**，因而不存在原理上的并行化障碍，可获得与 SSM 层相同的 $O(\log T)$ 深度并行化。
3. **参数严格对齐的三配置对比**：Pure Transformer / Pure Wave / Hybrid Wave-Attention，均为 10.94M 参数。
4. **测量协议**：分离 mixer 显存与输出层显存，控制 attention backend、编译设置与 allocator 状态；作者证明省略这些控制会得到"定性错误"的结论。
5. **实现级消融**：量化循环层 latency 惩罚中"架构性"与"未优化循环"各占多少。
6. **闭式 peak activation memory 模型**：与实测吻合，并预测 crossover 上下文长度。
7. **硬件感知的策略选择模型**：在明确运营约束下指导架构选型。

## 方法与架构
**Dynamic Wave 层**：设层归一化输入 $X=(x_1,\dots,x_T)$，$x_t\in\mathbb{R}^d$。三个独立线性投影产生输入依赖的门控参数：
```math
\alpha_t = \mathrm{softplus}(x_t W_\alpha + b_\alpha),\quad \omega_t = x_t W_\omega + b_\omega,\quad \phi_t = x_t W_\phi + b_\phi
```
隐藏状态按逐通道递推更新（$h_0=0$）：
```math
h_t = \exp(-\alpha_t) \odot h_{t-1} + \cos(\omega_t + \phi_t) \odot x_t
```
输出映射：
```math
y_t = W_o h_t + b_o
```
其中 $\alpha_t>0$ 是通道级遗忘率，$\omega_t$ 是瞬时角频率，$\phi_t$ 是相位偏移。展开后，早期 token $x_k$ 对时刻 $t$ 状态的贡献被所有中间阻尼因子之积以及 $\cos(\omega_k+\phi_k)$ 缩放——这构成一个"指数衰减 + 相位调制"的记忆核，取代纯衰减核，从而允许非相邻 token 之间的建设性/破坏性干涉（对比 RetNet、Mamba 的单调衰减核只能表达 recency bias）。

**并行形式（associative scan）**：因 $\alpha_t,\omega_t,\phi_t$ 只依赖 $x_t$ 而非 $h_{t-1}$，令 $a_t=\exp(-\alpha_t)$、$b_t=\cos(\omega_t+\phi_t)\odot x_t$ 可一次性批量算出，递推写成 $h_t = a_t\odot h_{t-1}+b_t$。定义结合算子：
```math
(a_i,b_i)\bullet(a_j,b_j) = (a_i\odot a_j,\ a_j\odot b_i + b_j)
```
该算子满足结合律（任一括号化均化为 $(a_1a_2a_3,\ a_3(b_2+b_1)+b_3)$），单位元为 $(1,0)$。因此
```math
h_t = \pi_2\big[(a_1,b_1)\bullet(a_2,b_2)\bullet\cdots\bullet(a_t,b_t)\big]
```
整个状态序列是 $\{(a_t,b_t)\}$ 的 prefix scan，可用 work-efficient parallel scan 以 $O(\log T)$ 顺序深度、$O(T\cdot d)$ 工作量求值。作者强调：**因为 $a_t,b_t$ 可预计算，即便不实现 scan，也可把它们提出顺序循环，循环内每步只剩一次 multiply-add**——这不改变数学与参数量，实测带来 2.53 倍加速。

**Transformer block 集成（pre-norm）**：
```math
u^{(l)} = x^{(l)} + \mathrm{Mixer}_l(\mathrm{LN}_1(x^{(l)})),\qquad x^{(l+1)} = u^{(l)} + \mathrm{FFN}(\mathrm{LN}_2(u^{(l)}))
```
其中 $\mathrm{FFN}(x)=W_2\,\mathrm{GELU}(W_1x)$。两种 mixer 都恰好带 $3d^2+3d$ 投影参数加 $d^2+d$ 输出映射，故三配置天然参数对齐。embedding 与 LM head 权重绑定。

**复杂度（Tab. I）**：

| Mixer | 训练时间 | 训练显存 | 生成显存（理想，每步） |
|---|---|---|---|
| MHA unfused | $O(T^2 d)$ | $O(T^2+T d)$ | $O(T d)$（KV cache） |
| MHA fused | $O(T^2 d)$ | $O(T d)$ | $O(T d)$（KV cache） |
| Dynamic Wave | $O(T d)$ | $O(T d)$ | $O(d)$（固定状态），未实现 |

**闭式显存模型（FP32）**：三类张量族几乎覆盖全部 activation memory：
```math
A_{\text{logit}} = 4BTV,\qquad A_{\text{attn}} = 8BHT^2,\qquad A_{\text{lin}} = 4cBTd
```
（$A_{\text{attn}}$ 的系数为 8 而非 4，因为 unfused 路径同时持有原始 score 矩阵与 softmax 输出；fused kernel 完全不贡献 $T^2$ 项。）拟合得 Wave stack 的 $c\approx 10$、attention stack 的 $c\approx 11$。峰值由前向传播中两个"时刻"的较大者决定：
```math
A_{\text{peak}} \approx \max\big(A_{\text{attn}} + A_{\text{lin}},\ A_{\text{logit}} + 4BTd\big)
```
令 $A_{\text{attn}} > A_{\text{logit}}$ 得 crossover 上下文长度：
```math
T^{*} > \frac{V}{2H},\quad T^{*}\approx \frac{10000}{12}\approx 833\ \text{tokens}
\]
这解释了 fused 列：fused kernel 移除 $A_{\text{attn}}$，logit 分支在所有测试长度上主导，而该分支三配置完全相同，故三者必然重合（实测吻合到 0.1% 以内）。

## 实验设置
- **数据集**：TinyStories 50 万故事子集；从零训练 10,000 token 词表 BPE（whitespace 预分词）；拼接后切为 512-token 固定块，得 **207,113** 个训练 chunk，最后 **2000** 个 chunk 留作 held-out（63 个 eval batch）。
- **共享超参**：$d=384$、FFN 维度 1536、6 个 attention head、4 个 transformer block、10,000 词表、**10.94M** 可训练参数。
- **三种配置**：Pure Transformer（4×Attention，唯一使用 torch.compile 编译）；Pure Wave（4×Wave）；Hybrid Wave-Attention（block 1-2 为 Wave，block 3-4 为 Attention，遵循 Griffin/Jamba 的"先便宜压缩后全局精炼"放置原则）。
- **训练**：1 epoch（6472 步，batch 32 chunks）；AdamW（weight decay 0.01）、OneCycle LR + cosine annealing、peak LR $5\times10^{-4}$、500 步 warmup、mixed-precision autocast + gradient scaling、grad-norm clip 1.0。Pure Wave 与 Hybrid 用 eager 模式（torch.compile 尚不能处理显式逐时间步 Python 循环）。
- **硬件**：单张 NVIDIA Tesla T4（16 GB GDDR6，Turing，cc 7.5），Kaggle notebook，Python 3.12.12、PyTorch 2.10.0、CUDA 12.8；T4 不支持 BF16，训练用 FP16 autocast，全部 profiling 用 FP32。
- **显存测量的四项控制**：① Isolation（每个配置独立构造/测量/销毁，显式 gc + cache 释放）；② Activation memory = peak − steady state（去掉常量权重）；③ Output-layer separation（每次 sweep 跑两遍：含/不含 tied LM head）；④ Named attention backend（所有 attention 数字同时报告 unfused 与 fused scaled-dot-product）。
- **sweep**：短上下文 128/256/512 token、batch 16、warmup 后 30 次计时平均；极端上下文 1024/2048/4096 token、batch 8；训练模式（前向+反向）512 token、batch 8。
- **吞吐**：bounded-window（生成 100 token，每步上下文截断到 512）与 unbounded growing-context（生成 1500 token，每步喂全量增长上下文）两种 regime，greedy 解码。

## 实验结果
**质量（Tab. III / IV）**：

| Model | PPL (quick, 50 batch) | PPL (full, 63 batch) | Avg CE Loss |
|---|---|---|---|
| Pure Transformer | 6.75 | 6.93 | 1.9357 |
| Pure Wave | 7.05 | 7.26 | 1.9818 |
| **Hybrid Wave-Attention** | **5.79** | **5.95** | 1.7831 |

Hybrid 相对 baseline 降低 perplexity **14.1%**，相对 Pure Wave 降低 **18.0%**。

**前向延迟与短上下文显存（Tab. III，batch 16）**：

| Model | Lat@128 (ref) | Lat@256 | Lat@512 (ref) | Lat@512 (opt) | Act mem @512 (full) | Act mem @512 (mixer only) |
|---|---|---|---|---|---|---|
| Pure Transformer | 15.8 | 32.8 | 72.6 | 63.3 | 324.5 | 265.0 |
| Pure Wave | 46.1 | 89.2 | 180.2 | 71.2 | 324.5 | 120.0 |
| Hybrid | 24.1 | 50.0 | 114.2 | 67.3 | 324.5 | 265.0 |

三配置 full model 的 activation memory 在每个长度上完全相同（128/256/512 分别为 81.1/162.2/324.5 MB），因为峰值由 tied LM head 的 $[B,T,V]$ logit 张量决定——$T=512$、batch 16、FP32 下占 312.5 MiB，即实测 activation 的 **96%**。去掉 head 后 mixer 才分离：unfused attention 265.0 MB vs Wave 120.0 MB（**2.2 倍**）。把 elementwise 项提出循环外使 Pure Wave 从 180.2 ms 降到 71.2 ms（**2.53 倍**），相对 fused attention（63.3 ms）仅慢 **1.12 倍**。

**Peak VRAM（Tab. V，batch 8，含 LM head，MB）**：

| Model | Unfused 1024 | Unfused 2048 | Unfused 4096 | Fused 1024 | Fused 2048 | Fused 4096 |
|---|---|---|---|---|---|---|
| Pure Transformer | 565.4 | 1801.5 | 6601.6 | 429.9 | 755.5 | 1403.6 |
| Pure Wave | 430.6 | 756.2 | **1404.3** | 430.6 | 756.2 | **1404.3** |
| Hybrid Wave-Attention | 566.3 | 1802.3 | 6602.5 | 430.8 | 756.3 | 1404.5 |

4096 token 处 Pure Wave 相对 unfused 少 **78.7%**（mixer-only 口径 480.0 vs 6496.0 MB，减少 **92.6%**）；相对 fused 则是 1404.3 vs 1403.6 MB，差 0.05%，**毫无优势**。Hybrid 在两种 backend 下都与 Pure Transformer 匹配到 0.1% 以内。

**训练显存（Tab. VII，512 token，batch 8，前向+反向，MB）**：

| Model | Unfused | Fused |
|---|---|---|
| Pure Transformer | 789.2 | 573.6 |
| Pure Wave | 621.2 | 621.2 |
| Hybrid | 705.2 | 597.4 |

排名反转：相对 unfused，Pure Wave 省 21.3%；相对 fused，Pure Wave 反而**贵 8.3%**——原因是 Wave 递推必须为反向传播保留所有中间状态 $h_t$（$O(T\cdot d)$ autograd tape，含 $T$ 个节点），而 fused attention kernel 重算中间量、存储很少。

**显存模型验证（Tab. VI）**：Wave/with head 在 B=16,T=512 预测 324.5 vs 实测 324.5（0.0%）；B=8,T=2048 预测 649.0 vs 650.0（−0.2%）；T=4096 预测 1298.0 vs 1298.0（0.0%）；unfused attn/with head 在 T=2048 预测 1776.0 vs 1696.0（+4.7%）、T=4096 预测 6624.0 vs 6496.0（+2.0%）。

**生成吞吐（Tab. VIII，reference implementation）**：

| Model | Bounded window (100 tok, tok/s) | Unbounded (1500 tok, tok/s) | Slowdown |
|---|---|---|---|
| Pure Transformer | 526.22 | 102.31 | 5.1× |
| Pure Wave | 49.55 | **3.96** | 12.5× |
| Hybrid | 80.25 | 7.75 | 10.3× |

unbounded regime 的崩塌原因不同：实现未做增量 state caching，每个解码步都从第一个 token 重算整个递推，把构造上 $O(T)$ 每步的机制实际执行成 $O(T^2)$ 总量；这一路径未实现，因此结果只反映当前参考实现而非递推的上限。

**训练墙钟（Tab. IX，1 epoch / 6472 步）**：Pure Transformer **18.36 min**（torch.compile：是）；Pure Wave **328.27 min**（否）；Hybrid **174.99 min**（否）。作者明确指出此比较混淆了架构成本与工程成本。

**隔离性控制的重要性**：当三配置同驻设备按固定顺序测量时，Hybrid 显得最耗内存（8021.9 MB vs Transformer 4373.9 MB）；隔离测量后差异消失，且结果不依赖测量顺序。

**可解释性**：Hybrid 中 block 3 的注意力权重显示 "climb" 与 "it" 的最大权重落在 "tree"（0.44 与 0.25），句末句号落在主语 "Tom"（0.29）；block 1 的 $\alpha_t$ 通道均值在 token 间在 0.53–1.49 间变化，在句末句号达到最大 2.19（状态被最强冲刷），呈内容依赖的选择性遗忘。

## 关键公式与代码
核心公式（Dynamic Wave 递推、associative scan 算子、显存模型与 crossover 条件）已在"方法与架构"给出。论文无代码块，但给出关键实现细节：`exp(-αt)` 与 `cos(ωt+φt)` 应在循环外批量预计算；fused vs unfused attention 分别对应 `nn.MultiheadAttention` + 显式 float mask 与 fused scaled-dot-product kernel；纯 Wave 与 Hybrid 因 torch.compile 不支持显式逐时间步 Python 循环而用 eager 模式。

## 局限性
作者在 Sec. VIII-E 自述六点：①所有模型只训练 1 个 epoch、单一规模（10.94M）、单一数据集（TinyStories），perplexity 排序在更大规模、多 seed、更复杂长文档语料（如 The Pile）上是否成立尚未证实；②训练墙钟与生成吞吐的比较仍被 torch.compile 不对称污染，只有显存与前向延迟基准是三者都不编译的；③未实现增量 state-caching 解码路径，吞吐结果只反映当前参考实现；④可解释性分析只用单个例句，属示例而非系统性研究（作者建议 HELM 之类的协议）；⑤**未纳入任何已有的 sub-quadratic 基线**，在匹配参数预算下与 Mamba、RWKV、linear attention 的对比缺失，也缺少 Zoology 式的针对性 associative-recall 基准；⑥全部 profiling 在 FP32、单 GPU 架构上完成，混合精度与多设备行为可能不同（attention backend 相对成本强烈依赖 kernel 可用性）。

我的补充批判：TinyStories 是句法简单、词汇受限的儿童故事，10.94M 模型 + 512 训练长度下"Hybrid 优于纯 Transformer"极可能是容量/任务特性的产物而非架构结论；作者提出的 $T^{*}=V/2H\approx833$ 结论建立在 $V=10000$ 的小词表上，对现代 10^5 级词表模型意味着 crossover 极晚出现（即 logit 张量主导一切），这实际上削弱了 sub-quadratic mixer 的实用价值；论文全部数字来自单卡 T4，与真实部署的 A100/H100 上 fused kernel 表现差异很大。

## 评估与建议
- 是否推荐深入阅读：**是**（作为方法论参考），**但对架构贡献本身建议谨慎**。其真正价值在于"效率声明必须具名 backend 与实现"这一测量协议与闭式显存模型。
- 适用场景：自建 sequence-mixing 层或做长上下文推理的工程团队，用作对照基线与评测协议模板；论文评审中审查"显存/延迟优势"声明时的检查清单；hybrid 架构放置策略（Griffin/Jamba 风格）的小规模复现。
- 与知识库的关联：与 Mamba/S4/RWKV/RetNet、linear attention、FlashAttention 系列、structured state space duality、associative scan 理论直接相关；与"benchmark 协议与可复现性"主题高度契合；与 LLM 长上下文 memory wall、KV cache 优化等工程主题互补。
