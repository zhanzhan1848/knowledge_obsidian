## 核心贡献

> 系统化梳理 LLM 集成应用的 7 种架构形式（LLM chats、custom agents、RAG、AI workflows、copilots、coding agents、agentic RAG），用 4 个结构维度统一刻画。

1. 系统化分类 LLM-integrated applications
2. 提出 4 个结构维度（架构 pattern、用户介入点、单任务 agent 调用次数、tool use）
3. 22 个系统实例贯穿全篇（研究 + 厂商文档）

---

## 技术方案

### 核心思想

LLM 被嵌入为软件组件后，市场上出现 chatbot、copilot、RAG、workflow、coding agent、AI agent 等标签。这些标签是否对应真实架构差异？本文通过 22 个系统调研，区分真·假到形。

### 七大架构形式

| 形式 | 描述 |
|------|------|
| LLM chats | 单轮或多轮对话，LLM 直接生成 |
| Custom agents | 用户定制 prompt + tool 的专用 LLM |
| RAG | 检索增强生成，外部知识库注入 |
| AI-enhanced workflows | LLM 嵌入业务流程，每步可介入 |
| Copilots | router-worker 架构，用户逐步确认 |
| Coding agents | reason-and-act loop，委托子 agent |
| Agentic RAG | RAG + agentic 迭代搜索 |

### 四个结构维度

1. **Architectural pattern**: 架构模式
2. **Control of execution & point of user intervention**: 用户介入点
3. **Number of agent calls per task**: 单任务 agent 调用次数
4. **Tool use**: 工具使用程度

### 关键洞察

- 标签确实携带架构内容（不纯粹是营销）
- "copilot" = router-worker + 逐步用户确认
- "agent" = AI-planned multi-step execution + 用户只看结果
- 四大 coding agent 厂商共享同一架构：reason-and-act loop delegating to subagents

---

## 实验结论

- **对象**: 22 个系统（研究 + 厂商）
- **结论**: 
  - 标签有架构内容
  - 4 维度能区分形式
  - 形式之间存在连续谱

---

## 局限性

- 主要分析 LLM 集成应用，不深入 LLM 本身架构
- 系统选样可能存在覆盖偏差
