## 核心贡献

> 提出 **AutoSFT** —— **多 agent 系统**自动化 SFT 数据工程。设计**完整 data action space**（select / prune / repair / replace / synthesize），single agent 只到 adjust proportions，**多 agent** 才有完整能力。**每轮 retrain from base** → 每个组件的贡献**独立可测**。IFEval / IFBench / MBPP+ 多项提升。

1. **Data action space**：完整人类数据工程师能做的动作（proportions / prune / repair / replace / synthesize）。
2. **失败模式**：single agent 只能到 adjust proportions，context 在 search 中被丢。
3. **多 agent 架构**：
   - **Meta agent**：分离 execution 与 analysis
   - **Analysis sub-agents**：多独立角度 proposal
   - **Synthesis sub-agent**：补 pool 没有的能力
4. **方法论**：每轮 retrain from base model → 组件效果独立测量。

## 技术方案

### Background

- LM agent 越来越多自动化 post-training。
- 当给完整 training stack 时 → **收敛到 SFT**，spent most effort **改 training data**。
- 现有系统 agent 仅有**一种** control（row selection 或 generator 调用）。
- 人类数据工程师动作：**adjust proportions / prune / repair / replace / synthesize**。

### Question

- **能否自动化系统的全谱 data action**？
- 需要什么结构？

### 发现 1：Single Agent 不足

- 单 agent 跑这一 loop → 只能到 **adjust category proportions**
- context 充满 execution output，**search 中被丢弃**
- → 需要 multi-agent 分离 concerns

### AutoSFT 架构

```
                  Meta Agent
                  /         \
           Executor       Analysis Sub-agents
              ↓               ↓
           Train       (multiple proposals)
              ↓               ↓
              └─── Synthesis Sub-agent ───┘
                       (for missing capabilities)
```

| Agent | 作用 |
|-------|------|
| **Meta** | 分离 execution 与 analysis；gather proposals；调 synthesis |
| **Executor** | 执行 training run（context 不丢失） |
| **Analysis sub-agents** | 独立角度 proposal（每 agent 一视角） |
| **Synthesis sub-agent** | 补 pool 缺失能力（如新 data source / 新 augmentation） |

### 评估方法学

- **每轮 retrain from base model** → 不继承前轮 policy
- **Model / trainer / budget 在比较中固定** → 组件效果独立可测

## 实验结果

### 组件贡献（顺序添加）

| Component | IFEval Gain | IFBench Gain | MBPP+ Gain |
|-----------|------------|--------------|-----------|
| Executor（context 不丢） | 减半 context loss | — | — |
| Analysis sub-agents | **+6.5** | — | **+3.7** |
| Synthesis sub-agent | +3.4 IFEval | **+2.9** | — |
| Code transfer loop | — | — | +3.7 (单 agent 不 improvement) |

### 关键数据

- **IFEval**：+6.5 (analysis) + +3.4 (synthesis)
- **IFBench**：+2.9 (synthesis)
- **MBPP+ (code)**：+3.7 (analysis) — 单 agent 不 improvement → 转移 loop 必要

---

## 局限与展望

- Action space 仍有局限（可能缺高级动作如 curriculum design）。
- Multi-agent 协调 overhead → 大规模训练 cost 上升。
- 跨 domain transfer 是否仍 gain（当前仅指令跟随 + 代码）。
- "Synthesis sub-agent" 边界模糊（什么能力是"pool 没有"的？）。
- 每轮 retrain from base **很贵** → 是否可缓存 transfer learning 加速。

## 实现建议

- **实现难度**: 中-高（multi-agent + 每轮 retrain from base 评估方法）
- **预期性能**: IFEval / IFBench / MBPP+ 各 +3–7 pp 提升
- **适用场景**:
  - **企业内部 SFT 数据 pipeline**（持续优化 data quality）
  - **多 domain 通用模型**训练（指令跟随 + 代码 + reasoning）
  - Research SFT recipe 研究
- **不适用**: 一次性 SFT（overhead 不可摊销）；极小模型（per-round cost 过高）
- **工程提示**:
  - Executor 应**支持 resume**（避免每次 context loss）
  - Analysis sub-agents 应**并行执行**（节省 wall-clock）
  - 每轮 retrain 评估方法 → 需 **固定 compute budget**（避免 cost 漂移）

---

## 一句话总结

AutoSFT 把 SFT 数据工程自动化从"single-agent 只调 proportions"升级到"multi-agent 完整 data action spectrum"（select/prune/repair/replace/synthesize），每轮 retrain from base 确保组件贡献可独立验证，IFEval/IFBench/MBPP+ 显著提升。
