## 核心贡献

> 把 LLM 从"规划者"降级为"语言—符号桥接器"，用**带记忆条件的 PDDL 规划**取代 LLM 直接出动作：PDDL domain 保持不变，每一步从观测、候选假设与交互记忆**重建 PDDL problem**。

1. **记忆条件化的问题重建**：每步根据解析出的观测 + 候选假设 + 交互记忆重新构造 PDDL problem，而不是一次性生成完整计划
2. **正图记忆（Positive graph memory）**：给候选假设（缺失的物体、位置、条件）分配**基于相关性的动作代价**，把规划器导向更可能应检查的假设
3. **负记忆（Negative memory）**：记录被执行反馈**证伪**的假设，编译成**排除约束**，防止重复尝试已被反驳的候选
4. **统一 schema 条件化语言—符号接口**：离线 SFT 训练，负责 observation→fact 解析与 symbolic-action→command 落地，把文本环境接进规划回路
5. **跨任务类型零额外微调**：同一套 fine-tuned 接口在不同 TextWorld 任务类型上复用，**无需 task-specific fine-tuning**

## 技术方案

### 问题定位

| 方案 | 问题 |
|------|------|
| LLM 作为长时程规划器 | 成本高，且容易产生**幻觉动作**或非法动作 |
| 纯 PDDL 规划 | 需要已知完整状态，在**部分可观测**文本环境下不可得 |
| 纯语言/反应式 agent（ReAct 等） | 步数多、token 成本高，会重复尝试已被否证的假设 |

MemPlan 的定位：**约束 LLM 在语言与符号规划之间做桥接**，而不是让 LLM 做规划决策本身。

### 核心思想

```
观测文本 ──► 统一接口（offline SFT）──► 事实 + 候选假设
                                        │
                          交互记忆（正图记忆 / 负记忆）
                                        │
                                   重建 PDDL problem
                                        │
                                  PDDL 求解器（domain 固定）
                                        │
                          symbolic action ──► 统一接口 ──► 环境命令
```

关键在于**每步重建 problem**：domain 固定，problem 随观测与记忆变化，这使部分可观测问题可以交给经典规划器求解。

### 关键技术

| 技术 | 说明 |
|------|------|
| Positive graph memory | 依据相关性为"缺失物体 / 位置 / 条件"的候选假设赋予动作代价，引导规划器优先检查更可信的假设 |
| Negative memory | 记录被执行结果**证伪**的假设，编译为 exclusion constraints，阻止重复尝试 |
| Schema-conditioned language–symbol interface | 统一处理 observation→fact 解析 与 symbolic-action→command 落地两种方向的任务 |
| Offline supervised fine-tuning | 接口在离线阶段用 SFT 训练，不依赖在线 LLM 规划调用 |
| PDDL problem reconstruction | domain 固定，仅 problem 随步变化；使部分可观测状态可在每步被显式化 |
| Reuse across task types | 同一微调接口在不同 TextWorld 任务类型上直接复用，无需 per-task 微调 |

### 接口的双向职责

| 方向 | 职责 |
|------|------|
| Observation → Fact | 从环境返回的自然语言反馈中解析出 PDDL 事实与候选假设 |
| Symbolic Action → Command | 把规划器输出的符号动作落地为环境可执行命令 |

## 实验结论

| 维度 | 结果 |
|------|------|
| 环境 | **TextWorld**、**ALFWorld**、**Robotouille** |
| 对比基线 | language-only 基线、PDDL-aware 基线、LLM-planning 基线（**ReAct**） |
| 任务完成率 | 优于 language-only 与 PDDL-aware 基线 |
| 步效率 | 优于上述基线（step efficiency 提升） |
| Token 成本 | 相比 ReAct 等 LLM-planning 基线**大幅降低**（substantially reducing online token cost） |
| 跨任务泛化 | 同一微调接口在 TextWorld 不同任务类型上复用，**无需任务特定微调** |

> 注意：摘要中**未给出具体数值**（百分比、点数、token 降幅）。需查阅正文表格获取精确数字。

## 局限性

- **数值未在摘要披露**：所有对比均为定性描述（"improves"、"substantially reducing"），缺少数值级证据
- 依赖**人工编写 PDDL domain**：domain 固定意味着每个环境需要专家写出 domain 定义，迁移到新环境的成本未被量化
- 依赖**离线 SFT 接口**：对未见过的新环境/新观测措辞的鲁棒性未说明
- 部分可观测假设的**候选假设生成质量**是上游瓶颈，但摘要未拆分其贡献
- 负记忆编译为 exclusion constraints 假设是**可靠的证伪**——若观测解析错误会产生错误排除

## 实现建议

- **实现难度**: 中高（需要 PDDL domain 编写 + 离线 SFT 数据构造 + 双向接口）
- **适用场景**: 文本具身/家庭环境中的长时程任务，对**步数与 token 成本敏感**且状态可被 PDDL 建模的场景
- **预期性能**: 任务成功率与步效率提升，成本显著低于 LLM 直出规划
- **落地顺序建议**:
  1. 先在一个 PDDL 可完整描述的环境（如 ALFWorld 类）上验证接口的解析准确率
  2. 再引入正/负记忆，单独测其对"重复尝试率"的贡献
  3. 最后测跨任务类型零微调复用是否成立
- **与相关工作互补**: 可与 [[2026-10-25-2610.30738-agenttriage-replayable-security-diagnosis]] 的"可重放诊断"结合，把执行轨迹转成可审计的规划证据
