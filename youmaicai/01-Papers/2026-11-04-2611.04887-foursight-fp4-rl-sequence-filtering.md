## 核心贡献
1. 揭示 NVFP4 RL 的失败是**集中的（concentrated）而非均匀的**，并给出两条关键诊断：
   - **跨引擎 TIM 集中在少数"离群轨迹"**：严重不匹配的 tail token 在崩塌前只占 batch 的 **0.2%**，在崩塌谷底集中到 **361/1024** 条轨迹，在部分反弹后**近 89%** 的轨迹恢复而其余几乎完全被 tail token 饱和。
   - **rollout 质量退化源于量化敏感性而非权重损坏**：把崩塌后的 FP4 checkpoint 的 **rollout 精度从 W4A4 切回 BF16**，GSM8K 测试准确率**立即恢复 20 个百分点**；训练全程权重漂移**至多 0.11%**，而相对策略量化误差**增长近 8 倍**。
2. 提出 **FourSight**（算法-系统协同设计），包含两个互补组件：
   - **TIM-aware 序列过滤（SF）**：在**序列级**屏蔽漂移轨迹的 advantage，而非 token 级裁剪。**双门机制**：G1 累计 tail token 数超阈值即丢弃（ widespread numerical drift）；G2 连续 tail token 段长超阈值即丢弃（自回归模式崩塌）。同时容忍健康 rollout 中偶发的孤立 tail token。
   - **稀疏精度补偿（PC）**：每个投影中仅保留**方差最高的 top-64 通道**（共 4096 通道）在 BF16 计算，其余保持原生 NVFP4。
3. 设计**融合算子 SpliceGEMM**：把 BF16 修正**折叠进 NVFP4 GEMM**（而非走独立残差路径），并针对大 batch 的 **prefill/训练** 与小 batch 的 **decode** 两种场景提供**专用数据通路**。
4. **训练质量**：Qwen3-8B + DAPO 上在 vLLM+Megatron 与 vLLM+FSDP **两种引擎组合**下均保持接近 BF16 的验证准确率；最终 FP4 推理准确率在 Megatron 上 5 个基准中 4 个第一、FSDP 上 5 个全部第一（AIME24 **26.3%** vs 最强基线 QaRL 23.1%；AMC23 **73.3%** vs QUADS 70.6%）。
5. **学习效率**：达到 20% AIME24 验证准确率只需 **150 步**（Megatron）/ **250 步**（FSDP），相对 QaRL 提升 **2.60× / 1.76×**（相对 QUADS 为 2.33× / 1.52×）。
6. **跨引擎、跨模型、跨算法的稳健性**：Qwen3-1.7B + GRPO 上稳定维持 **83%** 验证准确率；FP4 部署下 **GSM8K 80.65 / SVAMP 87.26 / MATH-500 51.34 / GSM1K 75.53**，**超过 BF16 基线 12.7–16.4 个百分点**。
7. **系统开销极低**：相对未补偿的纯 FP4，8B 上仅慢 **2.3%**，32B 上**反而快 3.1%**；Nemotron3-Super-120B-A12B 上比纯 FP4 **快 1.56%**、比 QUADS **快 15.4%**。相对 BF16 基线提速 1.18–1.40×，相对 QUADS 提速 1.18–1.29×。
8. **关键机制消融**：在 Megatron 上 **PC 单独使用会导致最终策略崩塌**（AIME24 仅 10.0%），**SF 单独使用能稳定但停在次优**（20.8%），二者结合达 **26.3%**。在 FSDP 上 PC 单独即恢复大部分收益，但 SF 与 PC **各自都是必需的**。
9. **通道选择至关重要**：在冻结的退化 checkpoint 上，仅保护 **64 个方差选择通道**就把 AIME24 提到 **13.5%**（接近 BF16 的 14.0%），而**随机选通道完全失败**（与未补偿 FP4 持平）；扩到 256 通道仅多赚 1 pp，却使保护状态增加 4 倍。

## 问题背景
RL 后训练已成为 LLM 生命周期中不可或缺的一环。为降低其高昂算力成本并直接为低精度服务优化模型，**量化 RL** 已被广泛采用，旗舰模型越来越多地以激进的低比特格式（如 **NVFP4 W4A4**）做后训练或部署。

典型的 NVFP4 RL 流水线包含两个**解耦引擎**：
- **rollout 引擎**（vLLM/SGLang）在 Blackwell 等加速器上跑原生 NVFP4 GEMM 以快速生成；
- **训练引擎**（Megatron-LM/FSDP）做高精度的 **QAT** 以保证梯度稳定性，同时用原生或伪量化低比特前向以匹配量化 rollout。

**朴素 NVFP4 RL 是不稳定的**：即使启用了 **TIS（Truncated Importance Sampling）**，训练也会中途崩塌并只能部分恢复（Figure 1：Qwen3-8B 在 Step 280 崩塌，Step 330 不完全反弹）。

两个叠加的失败模式：
- **跨阶段 TIM**：rollout 与训练引擎的数值实现差异（kernel 实现、并行归约顺序、量化执行模式）导致相同权重产生不同分布。高精度下可管理，但在粗糙低比特表示下被**急剧放大**，把名义上的 on-policy rollout 变成实际 off-policy 的更新。
- **rollout 阶段内退化**：NVFP4 严重降低采样质量。跨连续的自回归解码 pass，每步的量化误差会馈入下一步并累积，产生漂移的 rollout，使策略更新得不到有效学习信号。

现有补救措施都迫使在**训练稳定性与系统效率**之间做昂贵取舍：
- **算法层**：TIS 等 token 级裁剪/掩码只能压制单个不匹配 token，**无法隔离被污染的轨迹**——扭曲的梯度会通过**共享的序列级 advantage** 泄漏；QaRL 等序列级过滤依赖**粗粒度聚合指标**，会漏掉序列内部的崩溃，且不补偿退化的 rollout。
- **算子层**：ARCQuant、HiFloat4、QUADS 通过重量化或混合精度计算恢复 rollout 质量，但**增加的开销基本抵消了低比特吞吐收益**。
- **系统层**：veXact 通过强制两个阶段共用引擎消除 TIM，但牺牲了各阶段专属优化，导致 RL step 变慢。

作者的核心论点：**这个取舍是可以避免的，因为 NVFP4 RL 的失败是集中的而非均匀的**——而这种偏斜被熵、跨引擎 KL 这类**聚合指标掩盖了**（它们只在崩塌之后才飙升）。

NVFP4 的技术细节：它通过组合张量级 FP32 全局 scale 与层次化 block scaling，partition 张量为 16 元素块、每块共享一个局部 FP8 (E4M3) scale，来克服裸 FP4 (E2M1) 的窄动态范围。但这种 block-wise 共享**对离群值脆弱**：只要块内有一个大离群值，其共享的局部 scale 就被抬高，同块内剩余 15 个元素的量化分辨率被严重粗化。

## 方法

### 1. 诊断一：TIM 集中在离群轨迹
**概率空间的证据**（Figure 2）：BF16 下 token 沿对角线 $p_{\text{roll}} = p_{\text{train}}$ 紧密聚成狭窄梭形包络；原生 FP4 下量化噪声即使在健康的早期阶段（Step 50）就明显拓宽包络；到 Step 350，分布严重弥散，且**底部边界上堆积起一条稠密横带**——这些 token 被 rollout 引擎以高置信度采样，却被训练引擎赋予接近零的概率。

**logit 空间的证据**（Figure 3，Figure 2 d 的"全局混乱"实为 Softmax 失真）：去掉 Softmax 后看 pre-softmax logits，即使在崩塌后（Step 420），**超过一半的 FP4 token 仍良好对齐在梭形包络内**；真正的严重失配是一个**局部的对角外异常簇**，其中 token 保持中等到高的 rollout logits，但训练 logits 崩塌到零或负值。标注训练分布极尾（$p_{\text{train}} < 10^{-3}$）的 token 能干净地隔离出这个簇。解码这些 tail token 显示它们是**语义退化的输出**——乱码 subword、重复符号循环、突发的跨语言漂移。

**轨迹级分布**（Figure 4，1024 条轨迹按 tail token 比例排序）：
- 崩塌前（Step 260）：tail token 稀疏、随机、孤立；
- 崩塌谷底（Step 320）：tail token 比例激增，且**不是均匀分布于 batch，而是重集中在少数轨迹内**；
- 部分反弹（Step 350）：集中度进一步极化——**近 89% 的轨迹恢复健康，其余几乎完全被 tail token 饱和**。

**为什么 token 级 TIS 失效**：GRPO/DAPO 给一条轨迹的每个 token 分配相同的 advantage，因此**即使裁剪了 tail token，轨迹的其余部分仍会带着被污染信息更新策略**。所以有效的防御必须**丢弃整条轨迹**。

### 2. 诊断二：rollout 退化源于量化敏感性
- 把崩塌后的 FP4 checkpoint 的 **rollout 精度从 W4A4 切到 BF16**（只改 rollout，不重训），GSM8K 测试准确率**立刻飙升 20 pp**，接近从头以 BF16 训练的模型的准确率轨迹。
- 训练全程**相对参数漂移至多 0.11%**，而 W4A4 量化引起的**相对策略输出误差增长近 8 倍**——即 **RL 基本不破坏权重，却逐步放大了 rollout 策略对量化噪声的敏感性**。
- 逐层逐通道分析显示：严重量化误差**一致地集中在极少量离群通道**（量级或方差异常大）。NVFP4 的 block scaling 会**放大**这一效应——离群通道抬高同块共享的 scale，粗化同块其余 15 个元素的量化网格。

### 3. TIM-aware 序列过滤（SF）
**双门机制**。标记 token 为 **tail token** 的条件是其训练概率 $p_{\text{train}}$ 低于小阈值 $\epsilon$：
- **G1（累计计数）**：轨迹中 tail token **总数**达到 $n_1$ 即丢弃——高数量的 tail token 表明全轨迹范围的数值漂移，丢弃可保持整体梯度卫生；
- **G2（连续计数）**：轨迹中出现**连续** $n_2$ 个 tail token 即丢弃——由于自回归解码以先前 token 为条件，一段连续 tail token 表明 rollout 已进入退化前缀、遭受局部模式崩塌。

过滤以**后验**方式施加，直接屏蔽序列 advantage：

$$
A_i^{\text{masked}} = \mathbb{1}[g(\tau_i) = \text{keep}] \cdot A_i
$$

修正后的 GRPO 目标：

$$
\mathcal{J}(\theta) = \mathbb{E}\Big[\frac{1}{\sum_j \mathbb{1}[g(\tau_j)=\text{keep}]}\sum_i \frac{1}{|\tau_i|}\sum_{t} \min\big(r_{i,t}A_i^{\text{masked}}\hat{A}_{i,t},\ \text{clip}(r_{i,t}, 1-\epsilon, 1+\epsilon)A_i^{\text{masked}}\hat{A}_{i,t}\big)\Big]
$$

**关键细节**：**保留原始分母**（不对存活序列数重新归一化）——减小分母会放大未过滤序列贡献的梯度信号，等价于隐式提高学习率。

### 4. 稀疏精度补偿（PC）
**混合精度 GEMM 分解**。对输入维度为 $d$、输出维度为 $d_o$ 的线性层，SpliceGEMM 把输入通道划分为稀疏集合 $S$（被保护）与补集 $\bar{S}$：

$$
Y = \underbrace{X_{\bar{S}}\, W_{\bar{S}}^{\text{NVFP4}}}_{\text{主路径}} + \underbrace{X_{S}\, W_{S}^{\text{BF16}}}_{\text{BF16 修正}}
$$

其中 $W_{S}^{\text{BF16}}$ 是**反量化后的 BF16 权重**，$W^{\text{NVFP4}}$ 与 $X^{\text{NVFP4}}$ 是量化后的权重与激活，$s_{\text{global}}$ 是全局 NVFP4 量化 scale，而 $X_{S}$ 保留其原始 BF16 值。

**方差基础的通道选择**。保护**激活方差最大的 top-$k$ 通道**（实验中 $k=64$）。论文给出误差上界证明：设 $S$ 是被保护的 $k$ 元通道子集，$Y_S$ 与 $Y$ 分别为补偿后与原始 BF16 输出，则期望重建误差被上界为

$$
\mathbb{E}\big[\|Y - Y_S\|^2\big] \le \sum_{i \notin S} \mathbb{E}\big[\big(\beta_i x_i w_i - \hat{\beta}_i x_i w_i\big)^2\big] + \text{(scale-rounding 项)}
$$

在 NVFP4（block size 16、scale-rounding 常数）下，该界表明输出量化误差**由未保护通道的二阶矩主导**。而当通道均值很小时，**二阶矩可由方差良好近似**——这就 justifies 了 top-variance 选择策略。完整证明在附录 9.3。

### 5. SpliceGEMM 算子
朴素实现（分别启动 NVFP4 与 BF16 GEMM 再在 global memory 合并）会有严重的 kernel launch 开销与显存带宽浪费。SpliceGEMM 把稀疏 BF16 修正**融合进 NVFP4 执行流水线**。

**数据准备**：给定 HBM 中的输入激活（$H$ 为输入 token 数），准备 kernel 用 **256-bit 向量化加载**单遍读入——每条 load 指令每线程读 16 个连续 BF16 元素，恰好匹配一个 NVFP4 micro-block。**不按通道分支**：每线程应用预计算的**寄存器 bitmask**把被保护 lane 在量化前清零（Mask），同时把未 mask 的 BF16 列写入紧凑的 side buffer（Extract）。权重张量在每次策略更新后**预切分**为 NVFP4 pack 与预缩放的 BF16 pack；一次 rollout step 内该切分固定。

**双通路执行**（按活跃 token 数分发）：
- **高吞吐 prefill 通路**（大 $H$，计算受限）：复用同一 SRAM buffer，在 NVFP4 MMA 之后加载 BF16 tile；BF16 MMA 结果**直接写入 TMEM 中同一个 FP32 累加器**；合并结果搬到 RF，按 $s_{\text{global}}$ 缩放后写回 HBM。
- **低延迟 decode 通路**（小 $H$，延迟敏感）：TMA setup 与窄 tile 的共享内存屏障带来不成比例的延迟。主 NVFP4 tile 走 NVFP4 MMA，而紧凑的 side operand **完全绕过 SRAM staging，直接从 HBM 载入 RF**；epilogue warp 每 CTA 预取受保护的权重列到寄存器，用 warp 级 `mma.sync` 计算修正，在写回前直接加到 RF 中的 TMEM 主累加器上。

### 6. 系统集成
实现于 **veRL** 之上，vLLM 做 rollout，Megatron-LM 或 FSDP 做训练。vLLM rollout 与 Megatron-LM 训练前向中的线性投影**全部替换为 SpliceGEMM**。为保留 vLLM 的完整 CUDA Graph 捕获，执行计划**仅按 shape 缓存**已编译 kernel 与 workspace descriptor，不绑定固定 tensor 地址。方差跟踪用一个轻量 forward hook 在掩码前**均匀下采样 token 行**，把运行中的通道矩累积到连续 GPU buffer。策略反向传播前，trainer 计算双门 G1/G2 并**原地掩码序列 advantage**；反向 pass 用 BF16 + **STE**。每次 optimizer step 后，FourSight 按**上一步累积的 top-$k$ 方差**重新选择受保护通道（每次更新的开销很小）。打包权重通过 **NCCL/CUDA IPC** 同步到 vLLM，无需重量化。

## 实验结果
- **Dataset/Task**: 主工作负载 **Qwen3-8B + DAPO 算法 + DAPO-Math-17k**（8K response limit）；另有 **Qwen3-1.7B + GRPO + GSM8K**（512 token 输出限制）。性能实验覆盖 Qwen3-8B / Qwen3-32B / Nemotron3-Super-120B-A12B，分别用 8 / 16 / 32 GPU。平台：4 节点 × 8 张 NVFP4-capable GPU；训练用 Megatron-LM 0.19.2 或 FSDP + PyTorch 2.9.1，rollout 用 vLLM 0.26.0。基线：BF16、原生 FP4+QAT、**QUADS**、**QuRL**、**QaRL**（均按各自默认配方启用 TIS）。最终 checkpoint 一律用 **FP4 推理**评测（以反映部署要求），且保留各自的补偿机制。指标：Qwen3-8B 报 Mean@16 于 AIME24 / AIME25 / AMC23 / MATH-500 / OCW；Qwen3-1.7B 报 Mean@16 于 GSM8K / SVAMP / MATH-500 / GSM1K。TIM 用两策略间的 K3 KL 采样估计度量。**AUC/AUC 类指标、置信区间、显著性检验未报告**（表中为 mean ± standard error）。

  - 每步耗时：**Qwen3-8B 43 s**、**Qwen3-32B 124 s**、**Nemotron3-Super-120B-A12B 252 s**。相对 BF16 基线提速 **1.18× / 1.40×**；相对 QUADS 提速 **1.28× / 1.29×**。相对**未补偿的纯 FP4**：8B 仅慢 **2.3%**，32B **反而快 3.1%**，Nemotron3 **快 1.56%**（比 QUADS 快 15.4%）。
  - SpliceGEMM kernel：Qwen3-8B / 32B 上相对 BF16 最高 **3.7× / 2.8×** 加速；Nemotron3 上 Up/Down 相对 vLLM BF16 最高 **2.4× / 3.7×**，优化后的 Down 阶段甚至比纯 FP4 快 **1.16×**。

## 关键洞察
1. **"失败是集中的"这一观察本身比任何补救措施都更有价值。** 聚合指标（熵、跨引擎 KL）在崩塌后才飙升，是**滞后的**；而 tail token 的**空间分布**（0.2% → 361/1024 → 89% 恢复）直接指出了机制。这是全文最有迁移价值的诊断方法论：面对系统性崩溃，应当问"失败集中在哪些样本上"而非"总体指标如何变化"。
2. **logit 空间视图揭示了被 Softmax 掩盖的真实结构。** 概率空间看起来是"全局混乱"，pre-softmax logits 却显示**超过一半 token 仍完美对齐**，真正的异常是一个局部的对角外簇。教训：分析分布偏离时，**先剥掉 softmax 这层非线性失真**，否则会把指数映射的伪影误读为灾难。
3. **token 级修正无法修复序列级污染。** GRPO/DAPO 中一条轨迹的所有 token 共享同一 advantage，因此裁剪 tail token 后**剩余部分仍带着被污染的轨迹级信号更新策略**。这在数学上决定了修复的粒度必须至少到序列级——FourSight 的双门设计由此而来。
4. **区分"权重损坏"与"量化敏感"是诊断 FP4 RL 崩塌的关键分岔。** 一个简单实验（只把 rollout 精度切回 BF16）就证明权重基本完好（漂移 ≤0.11%）而量化敏感性被 RL 放大了近 8 倍。这一区分直接导出了"补偿激活离群通道"而非"修复权重"的方案。
5. **NVFP4 的 block scaling 把离群通道问题放大 16 倍。** 一个离群通道抬高整个 16 元素块的共享 scale，粗化同块其余 15 个元素的分辨率——这解释了为什么"保护少量高方差通道"能恢复大部分精度：**只修那 1 个通道，整个块都被救了**。
6. **精度补偿必须与量化 kernel 融合才有意义。** 单独走 BF16 残差路径的开销会抵消低比特吞吐收益；SpliceGEMM 通过把修正折叠进 NVFP4 MMA 并为 prefill/decode 分别设计数据通路，实现了"8B 只慢 2.3%、32B 反而快 3.1%"。
7. **两个组件在不同引擎上的角色会互换，但都不能少。** Megatron（原生 FP4 前向）上 PC 单独会崩塌（因为它改变了 rollout 分布从而改变失配形态），FSDP（高精度模拟量化）上 PC 单独就够。**这说明"哪个组件主导"是执行框架的属性，而非方法的属性**——因此组合式设计是工程上的正确选择。
8. **通道选择方法比通道数量重要得多。** 64 个**方差选择**通道 → 13.5%；64 个**随机**通道 → 完全无效。附录 9.3 的误差界（未保护通道的二阶矩主导误差）把这个经验事实提升为可推导的原则。

## 局限性
- **依赖 NVFP4 与 Blackwell 级硬件**（四节点 × 8 张 NVFP4-capable GPU）；在更旧的 GPU（如仅支持 FP8 的 A100/H100）上，NVFP4 路径本身不可用。
- **top-64 通道预算与 4096 通道维度绑定**；不同模型/不同 hidden size 需要重新校准（论文未给自动选择规则）。
- **过滤阈值 $(\epsilon, n_1, n_2)$ 手工设定**，Figure 12 只给敏感性趋势，未给自动选择方法。
- **训练阶段仍需 BF16 反向 + STE**，因此显存与训练稳定性收益仅限于前向/rollout；论文未报告显存占用。
- **Qwen3-1.7B 上 FP4 部署超过 BF16 基线 12.7–16.4 pp 这个结果反常**——它源于 BF16 训练模型的 PTQ 损失，而非 FourSight 本身创造了新能力；这个对比基线（未经 FP4 适配的 BF16 模型）在部署语境下并不公平，解读时需注意。
- **单机/单节点的 rollout 与训练引擎不一致问题未彻底解决**：TIM 只是被序列过滤**缓解**而非消除；跨引擎 KL 在过滤后仍为 0.037–0.054，并非零。
- **性能实验只覆盖 8/16/32 GPU 的 3 个模型**，未覆盖 405B+ 级别的 MoE；Nemotron3-Super-120B-A12B 是 MoE，其激活离群特性可能与 dense 模型不同。
- **无显著性检验**：所有表格给出的是 mean ± standard error（且误差很大，AIME24 的 se 达 ±6.6），"26.3 vs 23.1"这类差异在统计上未必显著。
- **未评估多轮 RL 后训练**（如经过多轮 RLHF 的模型），离群通道分布可能已改变。
- 论文未公开代码（正文未给仓库链接）。
- 附录 9.3 的误差界基于"通道均值很小则二阶矩≈方差"的近似，该近似的适用范围未做定量讨论。

## 适用场景
- **适用**：在 Blackwell 等 NVFP4-capable 集群上做**低比特 RL 后训练**的团队（希望 RL 训练后模型直接以 W4A4 部署，避免 PTQ 二次损失）；多引擎（rollout 与训练引擎不同）环境下的 RL 稳定性问题；需要在保住 BF16 级精度的同时压低训练成本的场景；量化 rollout 质量退化导致 RL 无学习信号的诊断。
- **不适用**：非 NVFP4 量化格式（INT8/FP8/AWQ）——虽然诊断方法论（tail token 分布、通道方差稀疏性）可迁移，但具体实现依赖 NVFP4 的 block scaling 结构；单引擎（rollout 与训练同引擎）因而无 TIM 的场景；硬件不支持 NVFP4 的环境。
- **不适用**：训练后的模型仍计划以 BF16 部署的团队（该工作的收益几乎全部在 FP4 部署侧体现）。
