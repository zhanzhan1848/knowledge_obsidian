# Using Experience Twice: Dynamic Process Rubrics for Privileged Token-Level Credit Assignment

> **arXiv**: [2611.06543](https://arxiv.org/abs/2611.06543)
> **发表日期**: 2026-11-04 (v2: 2026-11-05)
> **分类**: cs.AI
> **会议/期刊**: arXiv preprint (18 pages, 3 figures)

## 📋 摘要

Agent 轨迹中往往同时包含成功决策与失败尝试，但在稀疏的轨迹级奖励下做优化，很难判断哪些关键决策应当被强化、哪些应当被抑制。作者观察到一个关键现象：on-policy 轨迹之间的有意义差异可以被**蒸馏为自然语言的 process rubrics（过程评分细则）**，并用作过程监督信号。基于这一洞察，作者提出 Online Rubric Self-Distillation (ORSD)，利用自生成的 process rubrics 产生稠密的 token 级监督，从而增强以结果为中心的强化学习。具体而言，当前策略在每一步根据同一组轨迹独立生成多个 rubric bundle，从**跨轨迹行为差异**中抽取候选 process rubrics；随后一个**冻结的 verifier**（frozen verifier）对组内每条轨迹评估所有 rubric 条目，并依据"rubric 满足度与任务成功之间的 bundle 级对齐程度"选出最优的一个候选 bundle。ORSD 把选中的 rubric bundle 视为训练期间的**特权信息（privileged information）**，然后比较"有 rubric"与"无 rubric"条件下原始 token 的对数似然；所得的似然差（likelihood gap）提供 token 级的过程信用（process credit），再通过**加性优势整形（additive advantage shaping）**叠加到原始的轨迹级 GRPO advantage 上。ORSD 由此架起了轨迹级结果监督与细粒度过程监督之间的桥梁，用过程信号实现 token 级信用分配。在 ALFWorld 与 WebShop 上的大量实验表明，在相同环境交互预算下，ORSD 能加速策略改进并提升最终任务表现，覆盖 Qwen3-1.7B 与 Qwen3-4B。代码已开源。

## 🎯 核心贡献

1. **关键洞察**：on-policy 轨迹之间的行为差异可以被**在线自蒸馏为自然语言 process rubrics**，从而把"轨迹级稀疏奖励"转成可用于 token 级信用分配的稠密过程监督。
2. **ORSD 框架**（Online Rubric Self-Distillation）：策略自生成候选 rubric bundle → 冻结 verifier 打分 → 按 bundle 级对齐度选优 → 作为特权信息计算 token 级似然差。
3. **似然差作为过程信用**：用"有/无 rubric 条件下原始 token 的 log-likelihood 之差"作为 token-specific process credit，数学上干净、无需额外标注。
4. **加性优势整形**：process credit 与原始 GRPO trajectory advantage 相加，避免替换原有结果信号，训练稳定。
5. **实证**：在 ALFWorld / WebShop 上、相同环境交互预算下，加速策略改进并提升最终任务性能（Qwen3-1.7B 与 Qwen3-4B 均有效）。

## 🔧 方法/架构

- **Step 1 — 候选 rubric 生成**：当前策略在每一步基于同一组 on-policy 轨迹 $G = \{\tau_1,\dots,\tau_k\}$，**独立**生成多个 rubric bundle $B^{(1)},\dots,B^{(m)}$；候选 rubric 从**跨轨迹行为差异**中抽取（成功轨迹与失败轨迹的分歧点）。
- **Step 2 — 冻结 verifier 评估**：一个 frozen verifier 对每个 rubric 条目在每条轨迹上评估（满足/不满足），得到 rubric 满足度矩阵。
- **Step 3 — bundle 选择**：依据"rubric 满足度与任务成功"之间的 **bundle 级对齐度**选出唯一 bundle $B^\star$：

```math
B^\star = \arg\max_{B \in \mathcal{B}} \ \mathrm{Align}\big(\mathbb{1}[\text{satisfied}(B, \tau)],\ \mathbb{1}[\text{success}(\tau)]\big)
```

- **Step 4 — 特权信息下的似然差（token 级过程信用）**：训练时把 $B^\star$ 作为 privileged information 注入，比较同一批原始 token 在"给出 rubric"与"不给 rubric"时的对数似然：

```math
\Delta_{\text{token}} = \log \pi_\theta(o_t \mid x_{<t}, B^\star) - \log \pi_\theta(o_t \mid x_{<t})
```

  $\Delta_{\text{token}}$ 即该 token 的过程信用。
- **Step 5 — 加性优势整形**：将过程信用与 GRPO 的轨迹级 advantage 合并：

```math
A_t^{\text{final}} = A_t^{\text{GRPO}} + \lambda \cdot \Delta_{\text{token}}
```

- **整体定位**：连接 trajectory-level outcome supervision 与 fine-grained process supervision，实现用过程信号做 token-level credit assignment。

## ⚠️ 局限性

- 额外开销：每一步都要由策略自生成多个 rubric bundle、再由 frozen verifier 全量评估，对环境交互与推理预算的额外消耗未在摘要中量化（"相同环境交互预算"仅指环境侧，推理 token 成本可能上升）。
- 依赖冻结 verifier 的判定质量；verifier 若有偏，bundle 选择与似然差信用都会继承该偏差。
- rubric 自蒸馏出的过程标准只反映"当前策略能表达的差异"，可能形成自我强化的窄化（bias amplification），而缺乏外部人类过程标准校准。
- 仅在 ALFWorld 与 WebShop 两个相对简单的具身/购物环境、Qwen3-1.7B/4B 两个小规模模型上验证，扩展到长程真实 Agent 或更大模型的可行性未知。
- 摘要未说明与现有 process-reward model（PRM）方法的对比结果。

## 💡 建议

- 是否推荐使用：**是**（对 GRPO 系 RL 的 token 级信用分配与"经验二次利用"思想有直接启发）
- 适用场景：训练长程具身/工具型 agent、需要稠密过程信号但缺乏人工过程标注的 RL 场景。
