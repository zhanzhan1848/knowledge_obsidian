# Transformer-FSQ: Discrete Latents for Extreme KV-Cache Compression

> **arXiv**: [2611.09598](https://arxiv.org/abs/2611.09598)
> **发表日期**: 2026-11-06
> **分类**: cs.LG
> **会议/期刊**: arXiv preprint

## 📋 摘要

私密化、个性化的语言模型必须运行在本地消费级设备上，那里放不下前沿大模型，而保留长上下文也并非常易之事。**序列记忆——KV cache**——随上下文长度线性增长，很快盖过模型本身：对 **Qwen3-1.7B-Base** 而言，保留 **200,000 个条目**需要 **21 GiB**，是模型权重的 **6.6 倍**。然而作者实测的 KV cache 压缩方法在超过中等压缩比后**纷纷失效**。作者提出 **Transformer-FSQ**，通过把标准的 key 与 value 投影替换为**有限标量量化（finite scalar quantisation）瓶颈**来解决极端 KV cache 压缩问题。其 cache 为**每个 token 存储一个打包的离散整数码向量**，且**不携带任何 per-token 量化元数据**。把预训练 transformer 转换为该形式时，**仅训练这些投影**，且每原始参数只需 **0.25 个 token**（数据效率极高）。作者在 **0.6B 到 8B** 参数的模型上，将 Transformer-FSQ 与**五类基线**对比。在长上下文检索（**RULER**）上，从 **12×** 到 **97.5×** 的压缩比范围内，Transformer-FSQ 是作者评测中**最准确的方法**，且在各规模上均成立。一个**融合 Triton kernel** 直接从整数码解码；在基线可获得作者原生 kernel 的公平设定下，它在未压缩 **Qwen3-8B-Base** 上以 **32×** 压缩时达到原生 SDPA attention 吞吐的 **1.01×**（95% 区间 **0.98–1.05**），在 **97.5×** 时达到 **1.54×**。结论是：**极端 KV cache 压缩是扩展固定设备可承载上下文的实用手段**。

## 🎯 核心贡献

1. **FSQ 瓶颈取代投影**：用**有限标量量化（FSQ）**替换标准 key/value 投影，把 K/V 空间强制投影到一个有限码本上，从根本上使 cache 极小且天然可打包。
2. **零 per-token 元数据**：每个 token 只存**一个打包的离散整数码向量**，无需 scales/zero-points 等量化元数据——这是实现极高压缩比且不损失精度的关键设计。
3. **极低成本转换**：把预训练 transformer 转成 FSQ 形式时**只训练投影层**，数据效率高达 **每原始参数 0.25 个 token**（即远小于 1:1 的极低 token 预算即可完成转换）。
4. **极端压缩比下的精度领先**：在 **12×–97.5×** 的压缩范围内，RULER 长上下文检索精度为所有评测方法中最佳，跨 **0.6B–8B** 模型规模稳定成立。
5. **高效 Triton kernel**：融合 kernel 直接从整数码解码，**32×** 时吞吐与原生 SDPA 持平（1.01×，95% CI 0.98–1.05），**97.5×** 时反而 **1.54×** 更快——压缩带来净收益而非净损失。

## 🔧 方法/架构

- **动机**：KV cache 是长上下文部署的内存瓶颈——Qwen3-1.7B-Base 在 200K 条目下 cache 占 **21 GiB**，为权重的 **6.6 倍**。
- **FSQ（Finite Scalar Quantization）瓶颈**：
  - key/value 投影层 $W_k, W_v$ 不再输出连续向量，而是输出**有限码本上的标量索引**；
  - 每个通道维度被量化为少量标量等级（level set），再**打包**进一个整数码向量；
  - 因为等级集合是固定且共享的，**量化参数（levels）全局共享**，因此**无需 per-token 元数据**。
- **Cache 布局**：每个 token 存一个**打包的离散整数码向量**（bit-packed），解码时反量化到连续 K/V。
- **转换流程（post-hoc conversion）**：冻结预训练模型全部权重，**只训练投影层**；数据预算 **0.25 tokens / 原始参数**（极低）。
- **系统实现**：**融合 Triton kernel**，直接从整数码路径完成反量化与 attention 计算，避免单独反量化中间张量；基线对比时给基线使用其作者官方 kernel（保证公平）。
- **对比范围**：**5 类基线**（摘要未逐一列出）与 **0.6B–8B** 模型规模。

```math
\text{FSQ:}\quad \mathbf{k}_t = \sum_{i=1}^{d} \ell_i \,\mathbb{1}\!\left[c_i = \text{code}_i\right],
\quad c_i \in \{0,\dots,L-1\},\quad L \ll 2^{\text{bf16 bits}}
\;\Rightarrow\;
\text{cache size} \approx d\log_2 L \ \text{bits/token} \ \ (\text{no per-token metadata})
```

## 📊 实验结果

- **模型规模**：**0.6B – 8B**（含 Qwen3-1.7B-Base、Qwen3-8B-Base）。
- **评测任务**：长上下文检索 **RULER**（needle-in-a-haystack 类）。
- **基线**：**5 类** KV cache 压缩方法（摘要未列出具体名称），其中可获得原生 kernel 的基线使用其**作者 kernel**。
- **精度结果**：
  - 在 **12× 至 97.5×** 压缩比区间内，Transformer-FSQ 是**评测方法中最准确**的，跨规模成立；
  - 对比之下，作者实测的既有 KV 压缩方法在超过中等压缩比后**失效**。
- **吞吐结果**（在未压缩 Qwen3-8B-Base 上，基线用其官方 kernel）：
  - **32×** 压缩：解码吞吐 = 原生 SDPA 的 **1.01×**（95% CI **0.98–1.05**）；
  - **97.5×** 压缩：解码吞吐 = 原生 SDPA 的 **1.54×**。
- **内存参照**：Qwen3-1.7B-Base 保留 200,000 条目时未压缩 cache 需 **21 GiB**（权重 6.6 倍）。
- **转换成本**：**0.25 tokens / 原始参数**（仅训练投影）。
- 摘要未给出绝对准确率数值、cache 字节数的精确缩减表、端到端（prefill+decode）延迟与 TPU/GPU 型号。

## ⚠️ 局限性

- **仅在 RULER 类检索任务上验证**：摘要的精度结论集中于"长上下文检索"，未说明在**生成质量、多轮对话、代码补全、指令遵循**等任务上的表现；这类任务对 KV 的语义丰富度更敏感，可能在 97.5× 下退化。
- **必须重训练投影**：虽然只需 **0.25 tokens/参数**，但仍是**后训练转换**，不是零成本部署；对极低算力/隐私要求场景，转换所需的一次性训练是额外门槛。
- **离散步的表达力上限**：FSQ 用有限标量等级替代连续向量，理论上存在信息瓶颈；97.5× 下的检索精度虽领先，但摘要未给出该压缩比上的绝对分数（领先幅度未知）。
- **硬件与 kernel 依赖**：Triton kernel 面向 GPU；摘要未给出具体 GPU 型号、不同 batch/seq 长度下的吞吐曲线，以及在 CPU/边缘设备（NPU/Mobile GPU）上的可迁移性——而"消费级设备"恰是其目标场景。
- **仅探索压缩比这一个维度**：未报告对模型总体质量、能耗或长时间运行的稳定性影响。
- 摘要**未给出**预填充（prefill）阶段的加速/质量数据——长上下文的 prefill 与 decode 是两个不同瓶颈。

## 💡 建议

- 是否推荐使用：**是**（尤其在本地设备/边缘部署、需保留超长上下文且预算极紧的场景）
- 适用场景：隐私敏感的个人设备上的长上下文助手（本地 LLM + 长文档/长历史）、以及显存受限于 KV cache 的自托管推理服务（0.6B–8B 规模 Qwen3 系模型效果最佳）。落地建议：先做 0.25 tokens/参数的投影转换验证，再按自身任务类型（RULER 之外的真实负载）实测质量衰减；并确认 Triton kernel 在目标 GPU 上的实际吞吐收益（32× 时基本持平，主要收益来自 97.5× 极端压缩）。
