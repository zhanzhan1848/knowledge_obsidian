## 核心贡献

> BPE tokenizer 的成员信号在候选数据集特有的稀有 token 上，而不在 merge 顺序上——后者被理论与实验双重证否。

1. 提出用 BPE tokenizer 判断某候选数据集是否曾进入其训练语料——关键洞察是**成员信号应体现在候选数据集特有的稀有 token 上，而非 merge 的先后顺序**。
2. 在 BPE 纳入的阈值模型下形式化了似然比检验，证明其权重最大的正是「在背景语料中稀有但在候选数据集中高频」的 token。
3. 该模型进一步预测：一旦已知 token 是否存在与数据集频率，**merge rank 与 merge 图位置不应提供一阶成员信号** —— 这一预测在实验中成立。

---

## 技术方案

### 核心思想

Tokenizer 常被当作固定的预处理工具，但它本身是在文本上训练出来的，词表里会**残留所训练文本的痕迹**。这篇论文问的是：能否用 token 推断一个候选数据集是否属于某 tokenizer 的训练语料？

作者的观察简单而有力：**稀有字符串只有在语料频率足够高、超过 merge 阈值时才会成为 token**。因此成员信号应当出现在候选数据集**特有使用的稀有 token** 上，而不是 merge 发生的顺序上。

在 BPE 纳入的阈值模型下，似然比检验给最大权重的正是那些「背景稀有 / 候选高频」的 token。反过来，该模型给出一个可检验的负面预测：merge rank 与 merge 图位置在已知 token 存在性与数据集频率之后，不应再提供一阶成员信号——作者通过实验确认了这一预测成立，这是一个难得的「理论证否」。

方法 RTAM-Fusion 用 **shadow tokenizer（影子分词器）** 校准稀有 token 质量，并在不同稀有度层级上组合信号。相比基线 Vocabulary Overlap，RTAM-Fusion 在成员推断基准上取得了更好的 AUC 与平衡准确率，同时**使用了更少的影子 tokenizer**（这是实打实的成本优势）。

论文还有一个关于防御的重要发现：**现有防御在生产词表规模下，面对自适应攻击者仍持续泄露成员信号**。

### 关键技术

| 技术 | 说明 |
|------|------|
| BPE 纳入阈值模型 | 形式化「稀有 token 需足够频率才成为 token」的纳入过程，导出似然比检验的权重结构 |
| 稀有 token 质量校准 | 用 shadow tokenizer 估计某 token 在背景语料中的稀有程度 |
| RTAM-Fusion | 跨稀有度层级组合信号，优于纯词表重叠法 |
| 负面预测检验 | 验证 merge rank 与 merge 图位置在控制 token 存在性/频率后无额外一阶信号 |
| 自适应攻击评估 | 在生产规模词表下评估现有防御（kNN、DP 等）的残留泄露 |

## 实验结论

- **数据集**: tokenizer 成员推断基准（含生产规模词表设定）
- **基线**: Vocabulary Overlap、merge rank / merge 图位置类信号、kNN / DP 等现有成员推断防御
- **结果**: RTAM-Fusion 在 AUC 与平衡准确率上超过 Vocabulary Overlap，且使用更少的影子 tokenizer；同时证明 merge 顺序类信号在控制后无额外价值；现有防御在生产词表规模下面对自适应攻击者仍泄露成员信号。

- 最有洞见的结论是**证否式**的：merge rank / merge 图位置在理论上不应提供一阶信号，实验也确实如此 —— 这排除了一个看似合理实则无效的攻击面。
- RTAM-Fusion 用更少的影子 tokenizer 达到更好的 AUC，实际防御成本更低。
- 「防御在生产词表规模下仍泄露」是一个重要的负面安全结果，对以 tokenizer 为边界的数据防线的假设提出挑战。

## 局限性

['依赖 tokenizer 训练语料与候选数据集之间存在可检出的频率差异，对高度常见或高度合成的数据不适用。', 'shadow tokenizer 的构造需要额外语料，引入额外假设与成本。', '论文主要评估成员推断，未涉及完整的数据投毒或重建攻击。']

---

## 实现建议

- **实现难度**: 中（需构造 shadow tokenizer 与频率统计）
- **适用场景**: 训练数据成员推断、隐私审计、版权与数据来源追踪、tokenizer 安全评估
- **建议**: 评估「某数据集是否被用于训练某 tokenizer」时，不要去比较 merge 顺序或词表位置（理论已证伪），而应统计候选数据集特有稀有 token 的频率与背景语料的对比。

## 原始摘要

```
Tokenizers are usually treated as fixed preprocessing tools, but they are trained on text and can retain traces of that text in their vocabularies. We ask whether a BPE tokenizer can reveal if a candidate dataset was part of its training corpus. The key observation is simple. Rare strings become tokens only when enough corpus frequency pushes them over the merge threshold. This suggests that membership signal should appear in rare tokens used by the candidate dataset, rather than in the order in which merges were made. We formalize this under a threshold model of BPE inclusion, showing that the likelihood-ratio test assigns its largest weights to tokens that are rare in the background but frequent in the candidate dataset. The same model suggests that merge rank and merge-graph position should not add a first-order membership signal once token existence and dataset frequency are known. We instantiate this view as RTAM-Fusion, which calibrates rare-token mass with shadow tokenizers and combines signals across rarity levels. On the tokenizer membership benchmark, RTAM-Fusion improves AUC and balanced accuracy over Vocabulary Overlap while using fewer shadow tokenizers. Existing defenses also continue to leak membership signal against adaptive attackers at production vocabulary sizes. Code: https://anonymous.4open.science/r/RTAM-Fusion-F7EE/
```
