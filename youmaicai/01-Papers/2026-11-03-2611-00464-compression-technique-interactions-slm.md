## 核心贡献
1. **系统性因子消融研究**：评估 **72 种压缩配置**，覆盖 **4 种 SLM 架构（2.7B–7B 参数）**，并扩展 **48 配置的顺序（ordering）分析**、**30 个压缩模型的基准准确率验证**，以及多随机种子与全语料困惑度的稳健性检验。
2. **量化与剪枝的交互失效被定量刻画**：INT8 量化近乎无损（**<0.5%** 准确率下降），而 **NF4 量化 + L1 幅值剪枝在全部 16 种测试组合中均导致模型崩溃**。
3. **LoRA 恢复效果的归因**：LoRA 微调在激进度剪枝后最多可降低 **97%** 的退化困惑度；对照实验（无教师模型的标准微调）表明恢复主要来自 **LoRA 适配本身而非蒸馏信号**。
4. **CPU 端到端部署验证**：通过 llama.cpp 在 CPU 上验证结论可迁移——4-bit 比 8-bit 快 **46–54%** 且困惑度差异 **<0.5** 分；**非结构化剪枝在 CPU 上没有延迟或内存收益**（因其稠密存储格式）。

## 问题背景
在资源受限硬件上部署小语言模型（SLM）必须做压缩，但实践者缺乏关于**量化、剪枝与压缩后恢复（post-compression recovery）三者组合时如何相互作用**的系统性指导。现有文献多为单技术研究或厂商基准，缺少以受控因子设计（factorial design）揭示**技术间交互效应**的工作，尤其缺少"哪些组合是安全的、哪些会崩溃"的明确边界。同时，多数压缩评估止步于 GPU 环境下的困惑度，缺少真实 CPU 部署路径上的延迟/内存验证。

## 方法

### 研究设计
- **因子设计**：量化 × 剪枝 × 压缩后恢复，共 **72 种压缩配置**。
- **模型**：4 种 SLM 架构，规模 **2.7B–7B** 参数。
- **顺序分析**：另设 **48 种配置**的 ordering 实验（量化与剪枝的先后顺序）。
- **基准验证**：对 **30 个**压缩模型做下游任务准确率验证。
- **稳健性检验**：多随机种子（multi-seed）验证 + 全语料困惑度评估。

### 涉及的压缩技术
| 技术 | 说明 |
|------|------|
| INT8 量化 | 近乎无损 |
| NF4 量化（4-bit） | 与 L1 幅值剪枝组合时崩溃 |
| L1 幅值剪枝 | 非结构化剪枝（unstructured），稠密存储 |
| LoRA 微调 | 压缩后恢复手段之一 |
| 标准微调（无教师模型） | 对照组，用于隔离蒸馏信号的作用 |

### 部署验证
- 通过 **llama.cpp** 做**设备端 CPU 部署**，测量延迟、内存与困惑度，检验 GPU 上得到的结论是否 off-GPU 可迁移。

## 实验结果

### 准确率 / 困惑度
| 配置 | 结果 |
|------|------|
| INT8 量化单独 | 准确率下降 **<0.5%**（effectively lossless），**40–45% 内存下降**，无质量损失 |
| NF4 + L1 幅值剪枝 | **16/16 全部组合模型崩溃** |
| LoRA 微调（激进度剪枝后） | 退化困惑度最多降低 **97%** |
| 标准微调（无教师）对照 | 恢复效果显著弱于 LoRA → 恢复由 LoRA 适配本身驱动，而非蒸馏信号 |
| 顺序效应（可行为配置之间） | 无显著效应，**ANOVA p = 0.96** |
| 顺序效应（对 NF4+剪枝） | 顺序**决定该组合是否可行（viability）** |

### CPU 部署（llama.cpp）
| 指标 | 结果 |
|------|------|
| 4-bit vs 8-bit 速度 | 4-bit 快 **46–54%** |
| 困惑度差异 | **<0.5** 分 |
| 非结构化剪枝 | **无 CPU 延迟收益、无内存收益**（稠密存储格式所致） |

摘要未给出具体下游任务名称、具体基线模型名与各配置的完整逐项数值表。

## 关键洞察
1. **量化的"位宽"与"与剪枝的交互"必须分开评估**：INT8 是安全的、几乎无损的；真正危险的不是低位宽本身（NF4 单独尚可），而是 NF4 + L1 剪枝这一组合——16/16 全崩说明存在明确的**交互相变**，而非两类技术的简单叠加劣化。
2. **压缩后恢复的收益来源被正确归因**：LoRA 恢复 97% 困惑度退化，但去掉教师模型的对照说明这不是知识蒸馏在起作用，而是**低秩适配本身在修复被剪枝/量化破坏的权重结构**。这纠正了此前把"恢复效果"归功于蒸馏的常见误读。
3. **顺序不重要，但顺序决定生死**：在可行的配置集合内 ordering 无统计效应（p = 0.96），但在 NF4+剪枝这一濒死配置上顺序却是可行与否的开关——说明工程上"先做什么后做什么"只在临界区间才有意义。
4. **非结构化剪枝在真实部署中可能是纯粹的负担**：GPU 侧或可接受，但 CPU 上既无延迟也无内存收益（因为权重仍是稠密存储），构成"论文有效、部署无效"的典型落差。

## 局限性
- 摘要未披露：4 种 SLM 架构的具体名称与家族、下游基准任务名称与数据集、困惑度与准确率的绝对数值（除给出的百分比区间外）。
- 4-bit vs 8-bit 的 CPU 加速区间 **46–54%** 依赖具体硬件（CPU 型号、线程数、批大小、上下文长度均未给出），迁移性需自行验证。
- 压缩方法覆盖的是量化（INT8/NF4）与 L1 非结构化剪枝；未涉及结构化剪枝、稀疏注意力、KV cache 量化等其他重要技术，外推需谨慎。
- 恢复方法限于 LoRA 与标准微调两种，剪枝感知训练、混合精度分解等未评估。
- 论文为 arXiv preprint（13 页、3 图 11 表），未见同行评审。

## 适用场景
- 在 CPU / 边缘设备上部署 2.7B–7B 级 SLM 的压缩方案选型（优先 INT8 或 NF4，避免 NF4+剪枝组合）。
- 需要在激进剪枝后恢复模型质量、但无教师模型可用时的方案设计（选 LoRA）。
- 制定"量化/剪枝/恢复"的流水线顺序与配置白名单的生产实践。
- 评估"非结构化稀疏"在无专用稀疏推理引擎时的真实收益。
