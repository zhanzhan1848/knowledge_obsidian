## 核心贡献

> RAG 通过查询外部知识增强 LLM，但暴露 datastore 的**隐私风险**。现有方法 (formal DP) 性能损失大。

1. 提出 **简单随机投影方法**保护 RAG datastore 隐私。
2. 对 datastore embeddings 与 query embeddings **应用相同 projection**：
   - **理论保证**：保留 semantic similarity（cosine / inner product）
   - **实际效果**：显著缓解 data extraction attacks
3. 跨多种 RAG 架构 + 数据集，**性能超 formal DP 方法**，utility 接近 non-private baseline。

---

## 技术方案

### Random Projection
```
For each vector v in datastore / queries:
  v' = A · v  (A 是固定随机投影矩阵)
```

### 关键性质
- **Johnson-Lindenstrauss** 风格：cosine / inner product **近似不变**（保留 semantic similarity）。
- 信息论角度：**A 是单向不可逆** → adversary 拿到 v' 难以还原 v。

### Pipeline
```
1. Offline: project datastore embeddings {v_i} → {v'_i}，存储到 vector DB
2. Online: project query q → q'，检索 top-k neighbors in {v'_i} by similarity
3. LLM 用 retrieved docs 生成答案
```

---

## 实验结论

- 多种 RAG 架构 (DPR / ColBERT / BGE 等) 上 retrieval + generation **质量超 formal DP**。
- Data extraction attack 成功率**显著下降**。
- Utility 几乎无损（vs 无隐私 RAG）。

---

## 关键洞察

- **Random projection ≠ DP，但提供**实用隐私**：
  - 优点：无 DP 训练 / 噪声计算，简单 / 快 / 几乎无 utility 损失
  - 缺点：非 formal DP guarantee → 适合**实用场景**，不适合强隐私合规
- **投影矩阵 A 是 secret**：泄露 A = 无隐私。

## 实现建议

- **实现难度**：低（核心是矩阵乘法 + 固定种子）
- **预期性能**：超 DP-RAG，utility 接近 non-private
- **适用场景**：企业 RAG、敏感数据 (医疗 / 法律 / 内部文档) 不愿走 formal DP 流程时

---

## 局限性

- 非 formal DP guarantee，无法应对**主动攻击者**精确重构。
- 投影矩阵的安全管理 = 新增 OPS 负担。
- 对高维 embedding 的投影维度选择需谨慎。
