# LooM: Loop-Invariant Memory for Causal Encoder-Decoder Language Models

> **arXiv**: [2611.06835](https://arxiv.org/abs/2611.06835)
> **发表日期**: 2026-11-04
> **分类**: cs.CL (Computation and Language)
> **会议/期刊**: arXiv preprint

## 📋 摘要

Looped Transformer 通过重复执行共享层来提升有效深度，但有三个限制阻碍其落地：内存随循环次数增长、计算量只能以整块（whole-block）为步长调整、循环次数在训练后难以更改。本文提出 **LooM（Loop-invariant Memory）**，逐一解决这三个问题。在因果编码器-解码器（causal encoder-decoder, CED）架构中，LooM 只循环第一层之后的 decoder 层；这些层读取一份**每 token 只写一次**的全局内存（global memory），且每层仅在其**首次访问**某个 token 时发布该 token 的 key-value (KV) 条目，因此 KV cache 不随循环次数增长。这些 decoder 层**独立循环**，从而可提供每 token 从 **3 到 21 次层执行**的全部预算；通过在训练中**随机采样预算**，单一模型即可覆盖全部预算而无需 router。实验表明，在循环次数足够时，LooM 在语言建模、zero-shot 准确率与长上下文 perplexity 上均优于在相同数据上训练的单次前向（single-pass）基线，同时**使用相同的 cache 尺寸**。进一步分析表明，**训练预算分布**决定了额外深度究竟带来什么收益。结论是：CED 是「循环」的自然载体——内存只写一次，而深度成为部署时可选择的预算。

## 🎯 核心贡献

1. **Loop-invariant Memory 机制**：把循环层的 KV 写入降为「每 token 只在首次访问时发布一次」，使 KV cache 大小与循环次数完全解耦，直接消除 Looped Transformer「内存随循环数增长」这一核心痛点。
2. **独立循环 + 随机预算训练**：decoder 层各自独立循环，实现每 token 3–21 次层执行的**连续可调预算**（而非只能整块调整）；通过在训练中随机采样预算，一个模型即可覆盖所有预算，**无需 router**（避免 router 带来的额外推理开销与训练不稳定性）。
3. **深度作为部署期资源**：把「模型深度」从训练期固定超参转化为部署期可调预算，同一权重可在不同算力/时延约束下灵活配置（推理时自适应算力分配的基础）。
4. **训练预算分布的系统性分析**：实证揭示「训练时预算分布」而非「预算数值本身」决定额外深度能买到什么，为 budget-aware 训练配方提供指导。

## 🔧 方法/架构

LooM 建立在**因果编码器-解码器（CED）**之上，而非因果解码器-only（decoder-only）架构，这是其设计成立的前提：

- **结构分工**：encoder 一次性编码输入；decoder 的**第一层**之后的各层构成循环组（looped group）。
- **全局内存（global memory）**：一份每 token 只写一次的共享状态，供所有被循环的 decoder 层读取。

  ```math
  M_t \;=\; \text{Write}\big(M_{t-1},\, z_t\big), \quad \text{written once per token}
  ```

- **KV 发布规则**：循环层 `L_i` 仅在 token `t` 的**首次访问**（first visit）时发布其 KV 条目，后续循环访问复用同一份 KV，因此：

  ```math
  \lvert \text{KV}(t)\rvert \;=\; \sum_{i} \lvert \text{KV}_i(t) \rvert
  \quad\text{(independent of number of loops } L\text{)}
  ```

  这是「cache 不随 loop count 增长」的形式化刻画。

- **独立循环（independent looping）**：各 decoder 层拥有各自的循环计数器，因此总层执行次数可在 3–21 之间任意配置；单次前向的层数下界为 3。
- **随机预算训练**：训练时对每个样本随机采样循环预算

  ```math
  b \sim p_{\text{train}}(b),\quad b \in [3, 21]
  ```

  使单一权重覆盖整个预算区间，无需训练/使用 router。

- **对比基线**：在相同数据上训练的单次前向（single-pass）基线，且比较时保持相同 cache 尺寸。

## 📊 实验结果

- **语言建模（language modeling）**：循环次数足够时，LooM 优于同数据训练的 single-pass 基线。
- **Zero-shot 准确率**：LooM 优于 single-pass 基线。
- **长上下文 perplexity**：LooM 优于 single-pass 基线。
- **Cache 效率**：与 single-pass 基线使用**相同 cache 尺寸**（cache 不随 loop count 增长）。
- **预算覆盖范围**：每 token **3–21** 次层执行，由**单一模型**通过随机预算训练覆盖，**无 router**。
- **消融/分析**：训练预算分布（training budget distribution）决定额外深度的收益性质——摘要未披露具体数值（详见原文实验章节）。

## ⚠️ 局限性

- 依赖**因果编码器-解码器（CED）**架构，无法直接套用于当前主流的 decoder-only LLM（GPT/Llama 家族），迁移路径未在摘要中说明。
- 需 encoder 一次性编码输入，对 encoder-decoder 之外的架构（如纯自回归、state-space 混合）不适用。
- 「循环次数足够时」才有优势，说明收益与预算强相关；低预算区间的表现相对基线优势未量化。
- 摘要未给出具体模型规模、训练数据量与绝对分数，规模可扩展性（scaling law）证据不足。
- 分析结论「训练预算分布决定收益」的具体配方与超参敏感度需查阅原文。

## 💡 建议

- 是否推荐使用：**是**（对推理算力弹性需求、编码器-解码器架构的团队价值高）
- 适用场景：需要在同一权重上动态调节推理深度的部署、编码器-解码器 TTS/翻译/摘要模型、边缘设备上的算力自适应、以及作为「深度即预算」这一思路的研究起点
