## 核心贡献
1. **提出 Continual AutoResearch：一个 agent-agnostic 的开放式环境**，研究 agent 能否在**保留并有效使用**先前 ML 研究经验的同时适应新的研究任务。核心设计是**配对比较**（paired comparison）：**持久实例（stateful）与重置实例（stateless）的同一固定模型**，在**完全相同的任务、数据、时间预算**下处理**同一有序任务流**。
2. **覆盖 4 个设定、9 个任务族、每族 3–5 个任务**：Synthetic AutoML（3 流：shared-latent / shared-sparse / shared-regime）、Symbolic regression（canonical-coordinates 5 任务 + 1 个**非对称对照任务**）、Time-series forecasting（3 流：ETT cross-resolution / PEMS / energy-system）、Tabular AutoML（SELA 评估子集 5 任务 + MLE-Bench Lite 3 任务）。任务流刻意设计为"**共享可复用结构但目标/数据集/采样过程不同**"，迫使 agent **识别什么可迁移、重新估计什么任务特定**。
3. **三个互补的迁移度量**，均以"归一化奖励点"报告：
   - **最终选定奖励增益** $\Delta^{out}_i = 100(M^{out}_{i,\text{stateful}}-M^{out}_{i,\text{stateless}})$（式 2）；
   - **首个解质量增益** $\Delta^{init}_i$（首个有效提交的隐藏测试奖励）；
   - **固定时域搜索效用增益** $\Delta^{search}_i$（主指标）：

$$U_{i,c} = \frac{1}{B_i}\int_0^{B_i}\max_{j:\,t_{ijc}\le t} r_{ijc}\,dt$$

   更高的效用意味着**更好的解被更早找到**（同时刻画质量与发现时刻）。该曲线**只在运行结束后构建，从不向 agent 展示**，以防 reward hacking。
4. **跨任务流的归一化**（式 1）使异质指标可比：Accuracy/F1 不变；RMSE 用 $(1+m)^{-1}$（零误差→1）；$R^2$ 用 $(2-\min\{m,1\})^{-1}$（1→1）。**明确不跨异质任务平均未归一化的原始指标。**
5. **主要发现（负面且精确）：持久状态提升全部五个 agent 的研究效率，但不 consistently 转化为更好的最终解**。
   - **时间收敛增益对所有五个 agent 均为正**：Kimi K3 **+21.3**、Sonnet 4.6 **+20.9**、Opus 5 **+7.5**、GPT-5.6-Sol **+6.1**、GPT-5.4 **+3.0**。
   - **最终结果增益则不一致**：只有 Sonnet 4.6 有实质增益 **+7.6**；Kimi K3 +0.4、GPT-5.4 +0.2；**GPT-5.6-Sol −0.8、Opus 5 −0.9**。结果胜率从 Opus 的 34.3% 到 Sonnet 的 66.7%。
   - **持久性优势随预算内时间推移而消失**：25% 预算时平均差距 **+24.0** 点，到截止时收缩到 **+1.2**，且只有两个 agent 仍为正。
6. **机制归因（Table 7 的三重控制）**：stateful 执行**对每个 agent 都更快到达首个有效解**（Kimi K3 减少 **9.2 分钟**、Sonnet 4.6 减少 **8.6 分钟**），但**四个 agent 产生的有效候选更少**。**匹配候选数量后每个 agent 的增益都下降**（Sonnet 保留 +6.5，Kimi K3 与 GPT-5.4 保留较小增益，Opus 5 与 GPT-5.6-Sol 降到接近零）；**再减去各自的首次有效奖励后，增益对每个 agent 都变为负**。**结论：持久状态通过"更早产出有效解"或"产出更强的首个解"提升效率；当前结果不显示初始化之后的通用优化改进。**
7. **时间预算改变持久性的价值（Figure 3，Shared Regime，GPT-5.6-Sol，15/30/60 分钟）**：随预算增大，**最终结果增益变小**而**初始化增益变大**，时间收敛增益也下降——与"reset run 通过任务内探索逐步追平"的预期一致。
8. **记忆消融实验（Energy-systems 流，三条件：matched / shuffled / no memory）**：每个任务都从**全新 agent session** 开始，信息只能通过 **agent 自己撰写的 insight cards**（记录 claims、支持证据、置信度、适用范围、建议动作、失败条件）传递。**matched vs shuffled 相比**：初始化改善（Opus 5 +2.6、GPT-5.4 +5.9、GPT-5.6-Sol +3.9）但**三者的时间收敛都变差**；Sonnet 模式相反（初始化 −2.9，时间收敛 **+25.6**）。**matched 与 shuffled 相对 no memory 的最终增益对 Sonnet 与 GPT-5.4 也相当**——**相关的信息影响初始化与搜索效率，但不 consistently 改善最终表现**。
9. **能力与持久性的关系**：**reset 表现越强的模型从持久性中获益越少**——Opus 5 与 GPT-5.6-Sol 的 reset 表现最强，但初始化与结果增益反而比 Sonnet 4.6 与 GPT-5.4 小。**但模型能力并不 consistently 预测时间收敛增益**（不同模式）。
10. **"选择遗憾"（selection regret）度量**：一次运行中产生的最佳隐藏奖励减去其选定解的隐藏奖励。stateful-minus-reset 差异在 agent 间为 **−0.7 到 +1.3** 点，五个 agent 中四个在 **±0.8 点**内——**选择失败不解释搜索效率与最终结果之间的聚合差异**。

## 问题背景
近年来把前沿语言模型扩展到不同 AI R&D 流程的兴趣大增。Karpathy 的 autoresearch 引入了一个最小循环：agent 编辑训练脚本、评估结果、保留或丢弃改动。PostTrainBench、InferenceBench、Claudini 把它扩展到 LLM 后训练、推理系统与对抗攻击发现；AutoLab 扩展到长时程闭环优化；AutoScientists 研究共享实验状态的自组织 agent 团队；AutoResearchBench 关注多步科学文献发现。

但这些工作**主要测量单个研究问题内部的进展**。已有评测把每个 R&D 问题孤立处理——**每个新任务前把 agent 重置**。虽然 autoresearch 式循环允许 agent 用反馈迭代优化解，但**任务结束后获得的经验就被丢弃了**。因此这些评测**无法评估**关于实验设计、建模选择或执行失败的教训能否被应用到相关任务并改进后续研究。

另一方面，重置虽能避免无关或误导性的经验携带过来，但也**可能迫使 agent 重新发现有价值的实践或重复可避免的错误**。且**保留经验未必有益**——经验只有在任务共享可迁移结构（共同的数据生成因子、建模原则、实验方法）时才有用。

本文研究**不更新模型权重**的设定，因此经验**只通过执行过程中累积的状态**来迁移。

## 方法

### 1. 形式化

把持续 AI R&D 表述为有序研究任务序列 $\mathcal{T}=(T^1,\dots,T^K)$。任务 $T^i$ 含任务描述与指令、训练与开发数据、固定墙钟预算 $B_i$。在 $B_i$ 内 agent 可无限制实验；可提交多个解，但须在预算耗尽前选定一个最终解。所有提交在运行后于隐藏测试集上评估。**中间提交的测试分数被隐藏**以防 reward hacking。

**环境不提供任何用于规划或记忆管理的特定 harness**——agent 通过其原生 CLI 接口操作，可修改文件、执行代码、自主检视可见反馈。

**Stateful**：跨任务恢复同一原生 agent session 与工作区。对话历史、文件、实验结果、执行轨迹都可以携带。**不提供额外的 harness 写入的记忆或摘要——一切通过原生 CLI harness 处理。**

**Stateless**：每个任务启动新 agent session 与干净工作区，无任何前序任务的 transcript、文件、代码或执行状态。任务、模型、环境、墙钟预算、评测流程与 stateful 匹配。由于 $T^1$ 没有前序 session，**迁移结果在 $T^2,\dots,T^K$ 上计算**。

### 2. 三个度量

**归一化**（式 1）：

$$r(m;\mu)=\begin{cases} m, & \mu\in\{\text{Accuracy},\text{F1}\}\\ (1+m)^{-1}, & \mu=\text{RMSE}\\ (2-\min\{m,1\})^{-1}, & \mu=R^2\end{cases}$$

RMSE 用该通道训练集的标准差标准化后再变换。这些变换**保持每个任务内解的排序**，同时把每个度量放到共同尺度上。

**配对增益**（式 2）：$\Delta^i_q = 100\left(M^{q}_{i,\text{stateful}}-M^{q}_{i,\text{stateless}}\right)$。

**搜索效用**（式 3）：$U_{i,c}=\frac{1}{B_i}\int_0^{B_i}\max_{j:t_{ijc}\le t}r_{ijc}\,dt$。首个有效提交之前曲线置零；若运行提前结束则末值延至预算末端。

**选择遗憾**：一次运行中最佳隐藏奖励减去其选定解的隐藏奖励。

### 3. 任务流设计

刻意让任务流"共享可复用结构但目标、数据集或采样过程不同"，**防止 agent 直接重提交前一问题的解**。四个设定从"有已知重复结构的受控合成任务"渐进到"方法论相近的现实任务"——**从重复的科学结构到更一般的研究实践**。

- **Synthetic AutoML**：三条流、五个分类任务。shared-latent（观测特征是重复潜因子的噪声混合，表示发现可迁移但预测因子变化）；shared-sparse（每个目标依赖相关特征池的不同子集，使特征选择与正则化策略可迁移）；shared-regime（重复的 regime 变量对每个目标影响不同，奖励重测 regime 依赖交互而非纯依赖前解）。
- **Symbolic regression**：canonical-coordinates 五任务流，方程在适当变量变换后变简单（中心化、重缩放、或把变量组合成径向坐标）。**另含一个非对称对照任务**，测试 agent 是否**验证**先前有用的对称性而非自动套用。给定含噪训练与开发样本，agent 提交显式表达式，在私有插值与外推样本上以 mean $R^2$ 评估。
- **Time-series forecasting**：三个相似性层级。ETT cross-resolution（同电力变压器系统内变化站点与采样频率，需重新校准周期与上下文长度）；PEMS（跨交通传感器网络与时段，保留域级季节性但改变通道关系）；energy-system（跨更广来源与采样率）。agent 可复用归一化、滞后构造、周期性检测、季节性基线、时序验证等**流程**，但必须避免过度依赖前解。提交可执行预测，在隐藏测试划分上用 RMSE 评估。
- **Tabular AutoML**：SELA 评估用的五任务子集（AMLB + Kaggle）与 MLE-Bench Lite 的三任务切片。**每个任务用不同的真实数据集**，测试 agent 能否跨数据集迁移研究实践。

**防数据集识别**：论文报告公开数据集名以便阅读，但**评测时 agent 只收到中性标识符**，防止识别数据集并走捷径。

### 4. 实验设置

五个前沿 agent，各经其原生 CLI harness：Sonnet 4.6 与 Opus 5（Claude Code）、GPT-5.4 与 GPT-5.6-Sol（Codex）、Kimi K3（OpenCode）。每 agent 每族 3–5 个任务，**每 agent 32 个迁移任务**。默认每任务预算 **30 分钟**。

**可重复性**：为评估 run-to-run 变异性，对 GPT-5.6-Sol **重复三次**配对的 stateful–reset 比较。结果与初始化增益变化**至多 0.75 点**，时间收敛增益**至多 7.14**，相对聚合效应都小。因重复完整基准成本高，**其余比较使用单次配对运行**。

## 实验结果

- **Dataset/Task**：4 设定 / 9 任务族 / 每 agent 32 个迁移任务；每任务 30 分钟预算（另做 15/30/60 分钟消融）；数据来自 ETT、PEMS、Monash（能源）、AMLB/Kaggle、MLE-Bench Lite。

- **Main results（Table 2，模型级结果，32 个迁移任务，mean [median] 归一化奖励点）**：

| 模型 | Reset 结果 | 结果增益 | 初始化增益 | 时间收敛增益 | 结果胜率 | 初始化胜率 |
|---|---|---|---|---|---|---|
| Opus 5 | 79.9 | **−0.9** [+0.0] | +1.3 [+0.5] | +7.5 [+10.3] | 34.3% | 46.3% |
| GPT-5.6-Sol | 80.5 | **−0.8** [+0.2] | **−1.0** [+1.2] | +6.1 [+7.4] | 59.3% | 69.4% |
| Kimi K3 | 73.1 | +0.4 [+2.0] | +1.8 [+2.0] | **+21.3** [+27.5] | 62.0% | 64.8% |
| Sonnet 4.6 | 70.3 | **+7.6** [+1.3] | **+7.0** [+7.0] | **+20.9** [+20.6] | 66.7% | 75.0% |
| GPT-5.4 | 72.9 | +0.2 [−0.2] | +3.0 [+3.1] | +3.0 [+2.0] | 51.9% | 75.0% |

（Reset 结果为族平衡的平均最终奖励。）

- **Main results（优势随时间的衰减，Appendix Table 8）**：在 25% 与 50% 预算处 stateful 对全部五个 agent 均领先；**平均差距从 25% 处的 +24.0 点收缩到截止处的 +1.2 点**，截止时只有两个 agent 仍为正。

- **Main results（机制归因，Table 7）**：
  - **到达首个有效解的时间**：全部 agent 都更快，最大降幅为 **Kimi K3 9.2 分钟**、**Sonnet 4.6 8.6 分钟**。
  - **有效候选数**：**五个 agent 中四个在 stateful 下产生更少的有效候选**——因此增益**不是**由产生更多候选解释的（无效、未变或更低奖励的提交不改善 best-so-far 曲线）。
  - **首个解质量**：四个 agent 更高，最明显的是 **Sonnet 4.6 +6.8 点**与 **GPT-5.4 +3.7**。
  - **匹配候选数量后**：Sonnet 保留 **+6.5 点**；Kimi K3 与 GPT-5.4 保留较小增益；**Opus 5 与 GPT-5.6-Sol 降到接近零**。
  - **以首个有效解为轨迹起点**（保留首个解质量差异）：同样的模式。
  - **更严格控制（再减去各 run 的首次有效奖励）**：**增益对每个 agent 都变为负**。

- **Main results（时间预算消融，Figure 3，Shared Regime，GPT-5.6-Sol）**：15/30/60 分钟三档，**最终结果增益随预算增大而变小**，**初始化增益随预算增大而变大**，**时间收敛增益也下降**（范围 −35 到 +35 点）。

- **Main results（记忆消融，Energy-systems 流，三条件）**：

| 对比 | Opus 5 | GPT-5.4 | GPT-5.6-Sol | Sonnet 4.6 |
|---|---|---|---|---|
| matched vs shuffled 初始化 | **+2.6** | **+5.9** | **+3.9** | **−2.9** |
| matched vs shuffled 时间收敛 | 变差（全部三者） | 变差 | 变差 | **+25.6** |
| matched vs shuffled 最终结果 | 小 | 小 | **负** | 小 |
| matched / shuffled vs no memory 的最终增益 | — | 相当 | — | 相当 |

- **Main results（能力与持久性，Appendix Figure 7）**：**reset 表现更强的模型从持久性获益更少**——Opus 5 与 GPT-5.6-Sol 的 reset 表现最强，但增益分别只有 +1.3/−0.9（Sonnet 为 +7.0/+7.6）与 −1.0/−0.8（GPT-5.4 为 +3.0/+0.2）。**但能力不 consistently 预测时间收敛增益。**

- **Ablations / 选择遗憾**：stateful-minus-reset 差异跨 agent 为 **−0.7 到 +1.3 点**，五个中四个在 **±0.8 点**内。**选择失败不解释聚合差异。**

- **任务位置效应（Figure 11）**：在受控合成流上，**除 Sonnet 4.6 外，所有模型在每个后续任务上的平均优势都大于 Task 1**——累积经验随流推进变得更有用。

- **任务族效应（Appendix Figure 8）**：**除 SELA AutoML 外，没有任何任务族在所有模型上一致改善。**

## 关键洞察
1. **"保留经验"与"有效使用经验"是两种不同的能力**——这是全文的核心结论，且被三个独立证据链支撑：(i) 时间收敛增益全为正而结果增益不一致；(ii) 更严格控制下（减去首次有效奖励）**增益对每个 agent 都变负**；(iii) 记忆消融显示 matched vs shuffled 与 vs no-memory 的差异模式不同。**持久化主要改善的是初始化，不是后续优化。**
2. **持久性优势是"早期优势"，会随时间蒸发**。25% 预算时 +24.0 点，截止时 +1.2 点。这给出一个实用的部署判据：**持久性在紧预算下最有价值**（15 分钟时结果增益最大，60 分钟时变小）。这与"重置 run 通过任务内探索逐步追平"的机制一致。
3. **更快的搜索不必带来更好的最终解**，且原因被拆成两类并分别度量：(i) reset run 稍后达到同等质量的解；(ii) **agent 生成强候选却选择了过拟合的弱解**（用 selection regret 度量，聚合上不显著但单题可严重）。**"发现了什么"与"选了什么"必须分开评估。**
4. **匹配候选数量这个控制是关键的方法论**：它排除了"stateful 只是产生了更多候选所以 best-so-far 曲线更高"这个平凡解释。**五个 agent 中四个在 stateful 下产生的有效候选反而更少**，所以效率增益不是候选数量的产物。
5. **状态携带有明确的失效模式**：agent 会**把早期教训套用得太宽**，围绕当前任务不成立的假设收窄搜索；或**早期找到强候选后来又被不可靠的开发证据替换掉**。失败案例包括"agent 用过拟合的候选替换稳健候选"与"把早期的操作性教训应用得过强"。
6. **作者明确区分"报告最终表现"与"过程级评估"**：最终表现无法区分晚发现候选、执行失败、弱候选生成与错误的最终选择这四种情况。**这是本文在方法论上最有价值的建议。**
7. **数据集识别是 self-evolving 评测的一个隐蔽捷径**，本文用中性标识符消除它——任何"benchmark 里有 X 数据集"的 agent 评测都应照做。
8. **归一化 + 配对的设计使异质任务的迁移可测**：式 1 的变换保持任务内排序而把不同度量放到共同尺度，从而允许"聚合增益"这种跨任务比较成立（且明确拒绝跨异质任务平均原始指标）。
9. **安全含义被明确点出而未被测试**：当状态包含外部提供的 artifact 时，**持久复用可能让一个任务中引入的误导性或恶意内容影响未来行为**。作者说"我们没有评测对抗性操纵，但观察到的失效促使我们测试诸如溯源追踪、显式适用条件、基于证据的记忆修订这类防护措施"。
10. **"不更新模型权重"的限定使结论更干净**：经验只通过执行状态迁移，因此观测到的效应不能被"模型被微调了"混淆。

## 局限性
- **agent 与 scaffold 不可分离**：每个模型通过其原生 CLI scaffold 评测（Claude Code / Codex / OpenCode），stateful 与 reset 的比较在每个 agent 内部是匹配的，但**跨 agent 差异可能同时反映模型与 scaffold**。
- **流长度很短**：每条流只有 3–5 个任务、30 分钟预算。**无法外推到数百任务的流**，也无法外推到需要 10 小时量级预算的任务（如 PostTrainBench 的后训练任务）。作者提到这类实验会测试本文未涉及的机制（如 compaction）。
- **消融范围有限**：作者明确指出未来工作应**分别测试 insights、代码、transcripts 与 execution state**，并测试显式的记忆选择或遗忘机制——**本文的消融只分离了 insight cards 这一路**。
- **除 GPT-5.6-Sol 外只有单次配对运行**：三次重复只在 GPT-5.6-Sol 上做（结果/初始化变化至多 0.75 点、时间收敛至多 7.14）。这意味着**其他四个 agent 的单次运行差异（如 Opus 5 的 −0.9、GPT-5.6-Sol 的 −0.8）可能落在 run-to-run 噪声内**——作者没有明确说这些差异不显著。
- **20 分钟的 per-task 响应截止的类比不适用**：本文用 30 分钟预算，与推理服务的 20 分钟超时不同。
- **未评测对抗性操纵与安全**：持久 workspace 中"一个错误假设、脆弱代码路径或过时指令"可影响多个后续任务；agent 生成的代码在无监控下执行（作者承认"未监控的代码执行、算力使用、凭据泄漏"等风险），只做事后日志。
- **五 个 agent × 九 个任务族 × 3–5 任务的规模，对"哪些可迁移"的一般性结论不够强**：论文自己指出"除 SELA AutoML 外没有任何任务族在所有模型上一致改善"，说明结论高度依赖任务族。
- **多 agent 系统的持续学习未被研究**：作者指出在多 agent 系统中"每个 agent 学到什么、知识如何传播取决于 agent 间的交互与连接拓扑，这使跨任务改进更难归因与评估"。
- **伦理与资源消耗未量化**：虽然提到日志记录与性能/失败报告，但未给出 token/算力成本的对比。

## 适用场景
- **为自进化/自动化研究 agent 设计评测**：必须把"跨任务的持久 vs 重置"作为一等对比维度，并同时报告初始化、搜索效率与最终结果三个量。
- **部署预算受限的持续研究 agent**：本文支持"预算越紧，持久执行越有价值"的结论。
- **设计 agent 的记忆机制**：matched vs shuffled vs no-memory 三条件是一个可直接复用的消融模板；且本文给出了两类具体失效（套用太宽、选择失败）作为设计目标。
- **评估 agent 的最终选择能力**：selection regret 是本文提供的、可直接使用的独立指标。
- **不适合**：需要外推到长时程（数小时/天）或多 agent 分布式研究；需要区分"模型能力"与"scaffold 能力"；需要安全/对抗性鲁棒性保证（未测）；需要跨任务的通用性结论（流太短）。
