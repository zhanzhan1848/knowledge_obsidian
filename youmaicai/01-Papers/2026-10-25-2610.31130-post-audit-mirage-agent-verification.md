## 核心贡献

> **离线测试可能无法揭示 agent 更新在部署后是否仍然安全** —— 这不是"测试集不够大"的问题，而是**可识别性（identifiability）问题**：某些情况下，观测证据在原理上无法区分"安全"与"有害"。

1. **提出 post-audit mirage（事后审计幻象）的可执行刻画**：构造**匹配的安全/有害生命周期（matched safe and harmful lifecycles）** —— 它们**暴露给验证器完全相同的可见证据**，但一个**隔离的 scorer 记录相反的部署真相**
2. **定理化该边界**：把标准的 **observational-equivalence（观测等价）** 与 **indistinguishability（不可区分）** 思想应用到这一**可执行的审计边界**上，并给出由此产生的 **error-abstention tradeoff（错误—弃权权衡）**
3. **提出 Post-Audit Mirage 基准**：把该边界在**授权（authorization）**、**调度（scheduling）**、**共享容量（shared-capacity）** 三类环境中**变成可执行的**
4. **提出 IdentifiangRangeMonitor**（原文：IdentifiedRangeMonitor）：使用**新采集的、按群体标注的伤害结果（fresh group-labelled harm outcomes）**，返回 **deploy / hold / cannot determine / unsupported** 四种决策
5. **核心论断**：verifier–agent 评测必须**同时检验两件事** —— ① 计算有效性（calculation validity）；② **可用证据是否支持该部署决策**（evidence sufficiency for the decision）

## 技术方案

### 核心思想：可识别性边界

```
        ┌─── 安全生命周期 (safe lifecycle) ───┐
        │   验证器可见证据: E                 │
        │   部署真相: SAFE                    │
        └────────────────────────────────────┘
                        ≡（观测等价）
        ┌─── 有害生命周期 (harmful lifecycle) ─┐
        │   验证器可见证据: E（完全相同）      │
        │   部署真相: HARMFUL（隔离 scorer 记录）│
        └────────────────────────────────────┘

结论：对任意只看 E 的验证器，safe 与 harmful 在证据上不可区分
      → 离线审计无法给出有保证的部署决策
```

### 四种决策输出

| 输出 | 含义 |
|------|------|
| **deploy** | 证据支持部署 |
| **hold** | 证据不支持部署，需暂缓 |
| **cannot determine** | 证据不足以判断（弃权） |
| **unsupported** | 该情形超出可支持范围 |

### 关键技术

| 技术 | 说明 |
|------|------|
| Matched safe/harmful lifecycles | 构造**证据完全一致**但**部署真相相反**的一对生命周期 |
| Isolated scorer | 一个与验证器隔离的组件，记录真实部署结果 |
| Executable audit boundary | 把"不可区分"从哲学陈述变成**可运行、可复现的边界** |
| Error–abstention tradeoff | 定理给出的权衡：越想少弃权，就越可能出错 |
| Fresh group-labelled harm outcomes | 监控器使用**新的、按群体标注的**伤害观测（不是离线日志） |
| IdentifiedRangeMonitor | 结合新观测范围给出四种决策 |

### 三类环境

| 环境 | 机制 |
|------|------|
| Authorization | 授权传递/继承导致的不可区分 |
| Scheduling | 调度决策中的可识别性缺口 |
| Shared capacity | 共享容量竞争导致的后果不可从单条日志判断 |

## 关键实验结果

| 维度 | 结果 |
|------|------|
| 基准覆盖 | **3 类环境**：authorization、scheduling、shared-capacity |
| 监控器行为 | 在**有利设定（favorable settings）**下能**恢复出缺失的区分** |
| 失败模式 | 对**罕见群体（rare groups）**、**小效应（small effects）**、**缺失观测（missing observations）** 可能**保持未决（remain undecided）** |
| 输出 | deploy / hold / cannot determine / unsupported |

> 摘要**未给出具体的数字指标**（无准确率、无错误—弃权曲线的具体数值、无样本量）。这是该文摘要的显著特点 —— 它以定理与基准为主。

## 关键结论

1. **"离线测试通过"不等于"部署后安全"**，而且这个 gap 有时是**原理性的**（不可识别），不是样本量问题。这一点对整个 agent 评测范式是警示。
2. **弃权是必要的输出**，不是失败模式。error–abstention tradeoff 表明：**强行给出二值部署决策必然付出错误代价**。
3. **监控需要"新证据"**：IdentifiedRangeMonitor 用 **fresh group-labelled harm outcomes** 才能恢复区分 —— 离线日志本身不够，因为离线日志正是不可区分的来源。
4. **评测要拆成两问**：
   - 计算有效性 —— verifier 的计算/逻辑是否正确？（大部分工作只测这个）
   - **证据充分性** —— 当前可得证据是否支持这个部署决策？（本文提出必须单独测）
5. **对罕见群体与小效应最脆弱** —— 恰好是最需要保护的群体最难得到确定结论。

## 局限性

- **无具体数值**：摘要无准确率、无 CI、无基线对比数字；无法评估方法强度
- **定理为理论性**，把观测等价思想"应用"到审计边界是概念迁移而非新证明 —— 需要检查其适用条件（匹配生命周期如何构造、是否覆盖真实 agent 行为）
- **三类环境是简化的**：授权/调度/共享容量都是可控构造，不能代表真实 agent 的全部不可识别来源
- **未解决"如何获取新观测"**：IdentifiedRangeMonitor 假设 fresh group-labelled harm outcomes 可得，但现实中收集需要时间与权限 —— **部署初期恰恰没有**
- **Workshop 论文**（NeurIPS 2026 workshop，17 页），未经完整同行评审
- **实践建议的落地成本**：四值决策需要下游流程支持 "cannot determine" 这一分支，这在多数 CI/CD 流程中需要专门设计

## 实现建议

- **实现难度**: 中高（需要构造 matched lifecycles + 部署监控数据采集管线）
- **适用场景**: agent 更新上线前的**放行决策**流程；以及高风险 agent 的**持续监控**设计
- **落地步骤**:
  1. 在 CI 中**显式加入"不可识别性检查"**：构造一对证据相同、真相相反的测试生命周期，看你的 verifier 是否给出不同结论 —— 若给出不同，必有泄露（leakage）
  2. 把部署决策从二值改成**四值**（deploy / hold / cannot determine / unsupported），并在流程上为 "cannot determine" 预留人工复核路径
  3. 监控侧**采集 group-labelled 的新鲜伤害观测**，而不是复用离线日志
  4. **特别关注罕见群体**的观测密度 —— 这是最容易被弃权覆盖、也最需要显式处理的群体
- **与相关工作互补**: 与 [[2026-10-25-2610.30738-agenttriage-replayable-security-diagnosis]] 构成一组："**证据足够时如何可重放地诊断**"（AgentTriage）+ "**证据不够时如何诚实地弃权**"（本文）。两者一起构成 agent 安全评测的完整闭环
- **价值点**: 把 agent 评测里长期被默认的一个问题 —— "测试通过就能上吗" —— 从工程经验问题升级为**有定理支撑的可识别性问题**
