## 核心贡献

> 提出 **Librarian Agents** —— 训练 **Builder agent** 把 raw documents **预先重组**为 hierarchical filesystem（synthetic files + reference links），下游 answering agent 在此 workspace 上工作。Workspace construction 形式化为 **MDP + RL**，直接优化**下游 answering accuracy**。**BrowseComp-Plus +33 pp / BRIGHT unseen domain +31 pp avg zero-shot**。

1. **新范式**：从 reactive retrieval / rigid KG → **anticipatory directed curation**（预先重组 corpora）。
2. **Builder agent + hierarchical filesystem**：raw docs → synthetic files + reference links。
3. **MDP + RL 训练**：直接 optimize 下游 answering accuracy（而非 intermediate retrieval metric）。
4. **强结果**：BrowseComp-Plus 超 baseline **+33 pp**；BRIGHT OOD **+31 pp avg**。
5. **成本摊销**：upfront construction cost 摊到多次 query。

## 技术方案

### Motivation

- 长 context 推理是 LLM 难题。
- 标准 retrieval 是 **reactive**（query-time 才查询）→ 复杂 cross-doc 推理的 bottleneck。
- KG (precomputation) 是 **rigid**（依赖手工启发式）→ 表达力不足。
- → 想要 **anticipatory directed curation**：预先把 corpora 重组为对未来查询有用的结构。

### 关键观察

- 现代 agentic harness (Claude Code 等)：agents 善于**导航已有 filesystem** 解决**当前**任务
- 但**很少被训练构建可复用的 workspace** 给未来用
- → 利用这一 asymmetry 训练 builder

### Librarian Agents 架构

```
Raw documents
      ↓
Builder agent ──── RL on downstream accuracy
      ↓
Hierarchical filesystem (synthetic files + reference links)
      ↓
Workspace tailored for downstream answering agent
```

- **Builder agent**：reorganize raw docs → hierarchical structure
- **Hierarchical filesystem**：synthetic files（summaries / chunks / derived data）+ reference links（cross-doc pointers）
- **Downstream answering agent**：在 workspace 上做 task

### 训练

- Workspace construction 形式化为 **MDP**：
  - State：current workspace
  - Action：add file / add link / reorganize
  - Reward：downstream answering accuracy（direct optimization）
- RL 训练 builder policy

### 与 baseline 对比

| 方法 | 类别 |
|------|------|
| Reactive retrieval | query-time |
| KG precomputation | rigid structure |
| **Librarian Agents** | anticipatory curated |

## 实验结果

### BrowseComp-Plus

| 方法 | Accuracy |
|------|----------|
| Strongest retrieval baseline | ~baseline |
| Strongest precomputation baseline | ~baseline |
| **Librarian Agents** | **+33 pp** over both |

### BRIGHT (Unseen Domains, Zero-Shot)

| 方法 | Avg Accuracy |
|------|-------------|
| Baselines | ~baseline |
| **Librarian Agents** | **+31 pp avg** |

→ Generalizes zero-shot to unseen domains → builder 学到的是**通用 workspace design**，不是 specific to training domains。

### Cost Amortization

- Upfront construction cost (一次性)
- 被多次 query 摊销
- 总 cost < 多次 reactive retrieval 总成本

---

## 局限与展望

- 训练需要大量下游任务标注（end-to-end RL 链路长）→ 训练 cost 未知。
- Hierarchical filesystem 设计的**通用性**取决于 builder policy → 不同 corpora 需 retrain?
- Synthetic files 与原始 docs 的**忠实度**未量化（hallucination 风险）。
- 大规模 corpora (Wikipedia 级别) 上 construction cost 可能极高。
- Builder 与 answering 的**协同**如何优化（joint vs separate training）。

## 实现建议

- **实现难度**: 高（需要 end-to-end RL infra + filesystem management + RL reward shaping）
- **预期性能**: BrowseComp / BRIGHT style benchmarks 上 **+30 pp** 量级
- **适用场景**:
  - 企业知识库**预先组织**（反复被查询）
  - Legal discovery / compliance（多次相关查询）
  - Research workspace（多文档 cross-reference 推理）
- **不适用**:
  - 一次性查询（upfront cost 不可摊销）
  - 高动态 corpora（每天变 → workspace stale）
  - 极小 corpora（overhead 相对过大）
- **工程提示**:
  - Builder 可**分阶段**：(a) 粗粒度 structure (b) 细粒度 fill-in
  - Workspace 版本化 → 支持 corpora 增量更新
  - Answering agent 与 builder **可解耦部署**（builder 离线跑）

## 一句话总结

Librarian Agents 把 "长 context 推理" 从 reactive retrieval 升级为 anticipatory workspace curation：用 RL 训练 builder 预先重组 corpora 为 hierarchical filesystem，直接优化下游 answering accuracy，BrowseComp-Plus / BRIGHT 上 **+30 pp** 量级提升。
