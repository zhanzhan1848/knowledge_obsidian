## 核心贡献

> 提出 **UPTURN** (User-Prompt TURN injection)：训练 130K-参数 MLP head 定位 failed rollout 的干预位置，以"新 user turn"形式注入指令重定向推理，无需 LLM fine-tuning。

1. **无 LLM 微调**: 仅训练 130K MLP head on frozen encoder
2. **注入机制**: 保留 prefix，以 new user turn 注入指令、重生成 suffix
3. **跨 reasoner 迁移**: 在 GPQA-Diamond 上无重训练直接迁移

---

## 技术方案

### 核心思想

self-correction 传统做法 fine-tune LLM 生成 revision 或 feedback，但很难可靠识别"何时何地纠错"。本文**只学"在哪介入"**，**用 new user turn** 而非 inline token injection 重定向推理。

### 关键技术

| 技术 | 说明 |
|------|------|
| Frozen encoder + MLP head | 仅训 130K 参数，定位干预位置 |
| Final-answer correctness signal | 只用最终答案对错训练 |
| User-turn injection | 注入为新 user turn 而非 inline token |
| Prefix retention + suffix regen | 保留 prefix、重生成 suffix |

### 关键发现

- **Inline injection** 在固定 budget 下**不可靠**重定向
- **New user turn** 形式在固定 budget 下**显著可靠**地重定向
- 同一指令，形式决定效果

---

## 实验结论

- **数据集**: 6 math benchmarks + GPQA-Diamond
- **模型**: 4 个 reasoner
- **结果**:
  - 32-rollout baseline 上 UPTURN 提升平均 accuracy
  - 优于 self-correction 和 reflection-token injection（匹配 budget）
  - 跨 reasoner 迁移
  - 迁移到 GPQA-Diamond 无重训练
  - 与 GRPO、self-correction 互补

---

## 局限性

- 130K MLP head 的可解释性有限
- 仅用最终答案对错作为信号 → 中间错误定位不够精细
- "New user turn" vs inline 形式为何差异如此显著，未给理论解释

---

## 实现建议

- **实现难度**: 低（仅训练小 MLP head）
- **预期性能**: math benchmarks 普遍 +X pp，跨模型迁移
- **适用场景**: math/code reasoning；无需重训的高效 self-correction 插件
