| **摘要** | Large language model agents interact with online services through tool calls that may access private data or perform sensitive actions. Specialized providers can supply and maintain pre-execution safety auditing capabilities for agent operators. However, sending task descriptions, call arguments, and interaction histories to an external auditor may expose sensitive user information. In this work, we propose a paradigm for privacy-preserving safety auditing that separates delegated audit computation from plaintext access and execution authority. Grounded in a three-domain auditing model, the paradigm connects trusted representation construction, encrypted audit computation, and trusted decision and execution through explicit interfaces. These interfaces accommodate alternative representations and scorers, while encrypted computation protects audit inputs from a semi-honest auditor. We instantiate this paradigm in SealCall, a framework combining learned audit representations, CKKS-based encrypted similarity computation, and execution control bound to audited tool calls. Evaluated on 1,252 public binary candidates, SealCall achieves a mean F1 score of 0.840 under grouped nested evaluation, while preserving plaintext audit decisions in all measured cases. A representative configuration completes each encrypted scoring operation in 0.176 s. |

## 核心贡献

1. **问题**：LLM agent 通过工具调用与在线服务交互，可能访问私密数据或执行敏感操作。专业供应商可为 agent 运营方提供**执行前安全审计**能力。但把**任务描述、调用参数、交互历史**发送给外部审计方，可能**暴露敏感用户信息**。
2. **提出范式**：**隐私保护的安全审计**，其核心是**把"委托的审计计算"与"明文访问及执行权限"分离**。
3. **三域审计模型**：
   - **可信表示构建**（trusted representation construction）
   - **加密审计计算**（encrypted audit computation）
   - **可信决策与执行**（trusted decision and execution）
   三者通过**显式接口**连接；接口**允许替换表示与评分器**，而**加密计算**保护审计输入**不被半诚实审计方看到**。
4. **实例化 SealCall**：结合**学习到的审计表示**、**基于 CKKS 的加密相似度计算**、以及**绑定到被审计工具调用的执行控制**。
5. **结果**：在 **1,252 个公开二进制候选**上，SealCall 在**分组嵌套评估（grouped nested evaluation）**下取得**平均 F1 = 0.840**，且**在所有测量情形下保留了明文审计决策**；代表性配置下**每次加密评分操作耗时 0.176 秒**。

## 技术方案

### 关键技术

| 技术 | 说明 |
|------|------|
| 技术 | 说明 |
|------|------|
| 三域审计模型 | 表示构建 / 加密计算 / 决策执行 |
| 显式接口 | 允许替换表示与评分器 |
| CKKS 加密相似度 | 同态计算保护审计输入 |
| 半诚实假设 | 审计方不查看明文 |
| 学习到的审计表示 | 替代原始文本 |
| 执行控制 | 绑定被审计的工具调用 |
| 分组嵌套评估 | 防泄漏的评测方式 |

### 关键发现

- **核心洞察**：安全审计本身会变成攻击面。这与 [[2026-11-02-2610.41803-what-standard-evaluations-hide-about-detectors-of-hijacked-llm-agents-ra]]（评测隐藏了什么）形成有趣对照 —— 那篇说**评测的标准没披露**，这篇说**审计的流程本身泄露数据**。两者合起来：**agent 安全的每一层都会引入新的风险**。
- **"委托计算与明文访问分离"** 是密码学式思路的正确迁移：让审计方**只能看到受保护的表示**，仍能给出判定。
- **"保留明文审计决策"** 这个设计要求很讲究：加密计算不能改变判定结果，否则就失去了审计意义。用 **F1 = 0.840** + 决策一致性双指标来验证是合理的。
- **0.176 秒/次** 说明 FHE 的性能代价在工具调用场景下可接受（相比 LLM 调用成本极低）。
- 与 [[2026-11-02-2610.40946-opening-the-box-changes-the-cat-llms-detect-chain-of-thought-monitoring]]（CoT 监控可被察觉）共同构成今日 agent 安全的两个方向：**监控有效性与监控本身的副作用**。

## 局限性

- 依赖 **CKKS 同态加密**的性能与密文膨胀，在更高吞吐场景下可能成为瓶颈
- "半诚实审计方"假设是理想化的 —— 现实审计方可能是恶意的
- 仅在二进制候选（工具调用风险）上评估，未覆盖更复杂的攻击形态
- 学习到的审计表示可能成为新的信息泄漏通道
