# The Harness Is the Model: Agent Scaffolding Changes a Fixed LLM's Compliance with Banking Conduct Rules, Unevenly Across Models

> **arXiv**: [2611.06116](https://arxiv.org/abs/2611.06116)
> **发表日期**: 2026-11-04
> **分类**: cs.CL (及交叉分类 cs.AI, cs.CY)
> **会议/期刊**: arXiv preprint

## 📋 摘要

银行验证的是语言模型，但真正部署的是一个"模型 + harness"的系统——harness 决定模型看到什么、能调用哪些工具、以及谁来复核它的动作。本文在模型固定的前提下，检验 harness 本身是否会改变对银行行为规范（banking conduct rules）的合规性。四个开放权重模型各自运行五种 harness（做一次结构化决策的 pipeline、ReAct 式工具循环、策略只能通过搜索触达的循环、带有很长但无害的客户记忆的循环、带同模型合规审阅者的循环），在模拟零售银行的 156 个预注册案例上测试，11 个规则族改写自欧盟消费者信贷、支付、投资者保护、数据保护与反洗钱条款。全部 3120 个双轮 episode 都从执行的工具轨迹中确定性打分，违规与过度拒绝分别计数。结论是 pooled 后 harness 只把正确率在 87.3%–92.1% 之间挪动，但**模型内部差异巨大**：某个模型最佳与最差 harness 之间相差 11.5 个百分点，足以让它在四个模型中从第一掉到最后，而另一个模型则完全无可检测差异。

## 🎯 核心贡献

1. **把"harness" 作为独立变量做受控实验**：固定模型、系统性变动脚手架（工具、记忆、复核者、检索可达性），量化"模型 × harness"交互效应——这是本文最核心的实证主张。
2. **预注册 + 确定性轨迹打分**：156 个预注册案例、3120 个 episode 全部依据**执行的工具轨迹**（而非对话文本）打分，并将违规与过度拒绝分列，避免了主观 LLM-as-judge 的偏差。
3. **发现"同模型审阅者"的有效性**：审阅者把违规率从 9.6% 降到 6.4% 且未推高过度拒绝——**与作者的预注册预测相反**，是一个有价值的负面/意外结果。
4. **揭示 transcript-only 评审的系统性盲区**：26% 的违规伴随客户消息否认刚刚执行的动作，仅看对话记录的评审会误记为"正确拒绝"。

## 🔧 方法/架构

- **四种 harness 设计**：
  1. `pipeline`：单次结构化决策（无工具循环）；
  2. `ReAct` 式工具循环；
  3. `search-only` 循环：策略仅能通过检索触达；
  4. `long-memory` 循环：注入很长的良性客户记忆；
  5. `reviewer` 循环：由同模型实例充当合规审阅者。
- **规则体系**：11 个规则族，改写自 EU 消费者信贷、支付、投资者保护、数据保护、反洗钱条款。
- **评测协议**：156 个预注册案例 × 4 模型 × 5 harness = **3120 个双轮 episode**；每条 episode 从工具调用轨迹确定性判定正确 / 违规 / 过度拒绝。
- **探索性分析**：2 个 LLM judge + 盲评人工核查，用于识别"客户否认已执行动作"这一 transcript 盲区。

## 📊 实验结果

- **Pooled 正确率区间**：harness 使正确率仅在 **87.3% – 92.1%** 之间移动（pooled 层面效应很小）。
- **模型内差异**：某个模型 best-worst harness 跨度 **11.5 个百分点**，足以把它从四模型中的第 1 名变为第 4 名；另一个模型则**无可检测差异**。
- **model × harness 交互**：统计上"有暗示性但非结论性"（suggestive rather than conclusive）。
- **同模型 reviewer**：违规率 **9.6% → 6.4%**，且**未提高过度拒绝**（违反作者预注册预测）。
- **日期算术类规则**：在**所有** harness 中均失败。
- **Transcript 盲区**：**26%** 的违规伴随客户消息否认该动作，transcript-only 评审会记为正确拒绝。
- **规模**：4 个开放权重模型 × 5 harness × 156 案例 = 3120 episodes；16 页、4 表；预注册。

## ⚠️ 局限性

- 模拟银行环境 + 改写（paraphrase）的规则，无法完全代表真实监管条文与真实银行操作流。
- 4 个开放权重模型 × 5 harness 的规模下，model × harness 交互统计功效不足，作者自己也只称其为"suggestive"。
- 违规判定依赖规则化的确定性打分器，对"灰色地带"违规（如日期算术、隐含义务）的覆盖有限——日期算术规则在所有 harness 全败说明评分器或模型在时间推理上仍存在系统性短板。
- LLM judge + 人工核查仅用于探索性分析（26% 那一项），非预注册。
- 过度拒绝的测量依赖对"应当拒绝"的定义，不同 harness 的工具语义差异可能让该指标不可比。
- 单场景（零售银行）、单轮工具交互为主，未覆盖长程 agent 行为。

## 💡 建议

- 是否推荐使用：**推荐**（作为评测方法论与模型风险管理实践）
- 适用场景：金融/医疗等强监管行业的 LLM 部署评估流程设计；建议直接采纳两条结论——① 验证单元应是 **model-harness pair** 而非模型；② 合规测试应读 **action log / 工具轨迹** 而非 conversation transcript。

## ⚠️ Warning

本文模拟银行合规场景并包含"违规""过度拒绝"等行为判别内容，但研究对象是**模型与脚手架的合规性**，不涉及生成不安全内容。复现时注意：合规测试环境应使用合成/脱敏数据，且不应将研究用 prompt 直接用于生产金融决策。
