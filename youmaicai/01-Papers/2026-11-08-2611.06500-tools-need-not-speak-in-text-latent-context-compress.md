# Tools Need Not Speak in Text: Latent Context Compression for Agents

> **arXiv**: [2611.06500](https://arxiv.org/abs/2611.06500)
> **发表日期**: 2026-11-04
> **分类**: cs.AI
> **会议/期刊**: arXiv preprint

## 📋 摘要

LLM agent 通常把原始 tool output 直接追加到上下文中。在多步交互过程中，冗长而嘈杂的观测会带来巨大的上下文开销，并稀释 agent 对任务相关信息的注意力。现有的 token pruning 与 summarization 方法受限于离散文本表示，压缩比的上限因此被压制。本文挑战了"agent 必须以显式文本 token 消费工具观测"这一主流假设，提出 Coca-Cola——一个面向 LLM agent 的连续潜在上下文压缩（continuous latent context compression）模型。Coca-Cola 把工具观测压缩为 latent token，并将其嵌入到 agent 的输入嵌入空间（input embedding space）中。作者进一步提出 **Action-Preserving Training**，在完整观测与压缩观测两种条件下对齐 agent 的 next-action 分布，从而训练压缩模型学到"动作充分"（action-sufficient）的 latent token，保留决策关键信息。在 web-search agent 上、四个 QA 基准与两个模型族上的实验显示，Coca-Cola 将 agent 的 token 消耗降低 **70.01%–89.24%**，端到端运行时降低 **24.45%–55.97%**，同时任务表现持续提升。

## 🎯 核心贡献

1. **提出 Coca-Cola 连续潜在上下文压缩模型**：直接把工具观测压缩成 latent token 并嵌入到 agent 的输入嵌入空间，绕开"必须用文本 token 表达工具输出"这一默认设定，从而突破离散文本方法（pruning / summarization）的压缩比上限。
2. **提出 Action-Preserving Training**：通过在"完整观测"与"压缩观测"两种条件下对齐 agent 的 next-action 分布，训练压缩器保留决策关键信息（action-sufficient latent tokens），而非追求语义相似度。
3. **在提升精度的同时大幅降本**：token 消耗降 70.01%–89.24%、端到端运行时降 24.45%–55.97%，而任务性能不降反升——压缩不只是省 token，还因去噪而提升了效果。
4. **开源实现**：代码见 https://github.com/THU-Agent/Coca-cola。

## 🔧 方法/架构

**整体流水线**

$$
\text{tool output} \xrightarrow{\ \text{Compressor (latent encoder)}\ } z \in \mathbb{R}^{k \times d} \xrightarrow{\ \text{embed into input space}\ } \text{agent input embedding sequence}
$$

1. **压缩器（Compressor）**：以连续隐编码器形式把原始工具输出（文本）映射为固定数量的 latent token $z$；这些 latent token 不经过 tokenizer，而是被直接投影（project）进 LLM 的输入嵌入空间，与文本 token 的 embedding 并排拼接。
2. **Action-Preserving Training**：设完整观测下的动作分布为 $p_{\text{full}}(a \mid o, h)$，压缩观测下为 $p_{\text{comp}}(a \mid \hat{o}, h)$，训练目标是对齐二者：

$$
\mathcal{L}_{\text{APT}} = \mathbb{E}_{(o,h,a)}\left[\mathrm{KL}\!\left(p_{\text{full}}(\cdot \mid o, h) \,\|\, p_{\text{comp}}(\cdot \mid \hat{o}, h)\right)\right]
$$

其中 $\hat{o} = \text{Compressor}(o)$。这一 KL 对齐让压缩器只需保留"会改变动作"的判别性信息，而不必保留全部可读语义。
3. **Agent 主干**：agent 本身（LLM policy）保持原样消费 embedding 序列，可与现有 tool-use agent 框架直接对接。

**与既有方法的区别**
- Token pruning / summarization：工作在离散文本层面，压缩比受文本冗余度上限约束，且删掉的信息常常是判别性的。
- Coca-Cola：工作在连续隐空间，压缩比可大幅提高，且训练目标直接对齐"决策行为"而非"文本内容"。

## 📊 实验结果

- **Token 消耗**：降低 **70.01%–89.24%**。
- **端到端运行时**：降低 **24.45%–55.97%**。
- **任务性能**：在四个 QA 基准上**持续提升**（consistently improving task performance）。
- 设置：web-search agent × 4 个 QA 基准 × 2 个模型族。
- 摘要未给出各基准的具体准确率数值（详见原文实验章节）。

## ⚠️ 局限性

- 仅在 **web-search agent** 与 4 个 QA 基准上验证；对代码执行、数据库查询等结构化输出（token 数少但精度要求高）的工具，压缩收益与风险未被充分评估。
- 需要**训练一个额外压缩器**，引入训练成本与额外的模型组件。
- 离散 → 连续的做法牺牲了可解释性与调试便利：被压缩掉的工具输出无法直接被人阅读，出错时溯源困难。
- Action-Preserving 的 KL 对齐以"模仿完整观测下的动作分布"为目标，可能继承原 agent 的系统性偏差。

## 💡 建议

- 是否推荐使用：是
- 适用场景：多步工具调用、长观测为主的 agent（web search、文档检索、代码执行日志）；上下文窗口紧张或 token 成本敏感的生产环境；希望在不牺牲（甚至提升）任务效果的前提下压缩上下文的工程团队。
