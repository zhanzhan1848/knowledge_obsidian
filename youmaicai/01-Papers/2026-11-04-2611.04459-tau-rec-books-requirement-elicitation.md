## 核心贡献
1. **把"信息披露时机"做成受控变量**：450 个任务分成 150 个 task family，每个 family 固定 request（谓词、答案集、persona、阅读历史、接受格式），只有**揭示时机**不同——全部主动说出（volunteer）、开头说一个其余被问时说（mixed）、部分永不说（hidden）。三者仅靠每个谓词上的 reveal tag 区分（stated / on ask / hidden）。
2. **量化了信息披露造成的巨大性能断崖**：4 个 agent × 2 种检索接口，全部条件下 pass^1 从 volunteer 的 **0.975** 降到 mixed 的 **0.756**（-23.3 点）再降到 hidden 的 **0.283**（-69.3 点）。Holm 校正后两项均 ≤0.0011。
3. **失败模式被定位到具体行为**：mixed 失败**主要因为 agent 不问**（GPT-6.1 Sol 在 40–49% 的 mixed trial 中一个 askable fact 都没引出；它 101 个"引出全部 askable fact"的 trial **全部成功**，而未引出的只有 52% 成功）。hidden 失败**主要因为 agent 推荐了从未向用户提议过的书**（78% 的失败如此，其中一半发生在任何提议之前；73% 紧随一次被拒绝的提问之后）。
4. **一句提示词即可修复 mixed 失败**：加入 Ask 提示后，每个 agent 的 mixed pass^1 都达到 **≥0.931**（GPT-6.1 Sol 提升 **59.0 点**）。
5. **协议知识（拒绝/回避的语义）比"先提议"更有价值**：Protocol 提示（告知"被回避的字段藏着一个要求""被拒的书至少违反一个要求"）使每个 agent 平均提升 **22.5 点**至 0.708–0.825，可检测地优于"提议热门书"的脚本 agent（0.600）。
6. **结构化检索接口优于关键词检索**：20k 目录下平均 **+7.1 点**（95% CI [+3.0, +11.4]，bootstrap p=0.0005），主要来自 Qwen（+18.7）和 mixed 任务（+13.2）。Holm 校正后仅 Qwen 与 DeepSeek 的增益成立。
7. **目录规模的影响远小于信息披露**：keyword 的 pass^1 从 5k 到 20k 仅下降 **4.2 点**，structured 仅下降 **0.8 点**（不显著）。固定 keyword query 在 5k 能为 135 个可满足 family 中 106 个找到答案，在 20k 只有 73 个。
8. **完全 LLM-free 的评分与可复现性**：评分针对 catalog 元数据（谓词谓词）而非 LLM judge；使用**规则化模拟用户**；发布 catalog pipeline、任务生成器、模拟用户、validators、参考 agent 与**全部 32,976 条 trial 的 trace**，可逐字节重建 catalog 并重放全部工具调用。

## 问题背景

对话式推荐系统提供了更自然的界面，但面临一个核心困难：**必须在能推荐出满足用户需求的物品之前，逐步发现用户的需求**。agentic recommender 把对话、目录检索与元数据工具结合起来，因此其评估必须检验的不只是排序质量，还有需求引出（elicitation）过程。

此前 $\tau$-Rec（Narasimhan & Narasimhan）在小规模电影目录上引入了**可验证奖励**（对着 catalog 谓词打分，不用 LLM judge），并发现需求从"陈述"变为"隐藏"时成功率陡降。但它留下几个未决问题：(1) 固定 request 下信息**披露时机**的影响；(2) **检索接口结构**的影响；(3) **目录规模**的影响。

第一个问题极为重要，因为真实用户很少一开始就说清所有需求。论文给出了 ReDial 的 11,348 段人类推荐对话的统计：用户对第一个 genre / era / origin 需求，只有 **36%** 是主动说出的，**52%** 是在被问到时说出的，**12%** 只在看到建议之后才说。天然语言推荐系统的用户也常在看到结果后追加条件。

现存的 agentic 推荐评估各有盲点：AgentRecBench 用 hit rate 评分但没有用户在环；WebShop 做属性匹配；EComAgentBench 发现需求放在 user profile 或只在澄清中揭示时满足率更低，但**没有做成 matched disclosure variants**。Ambig-SWE 是最接近的先例（给编码 agent 提供完整 / 欠定 / 可询问版本），但本文新增了一个**用户拒绝陈述但仍评判提议**的条件，并同时变动目录规模与接口。

## 方法

### 1. Books 资源

**Catalog**：从 Wikidata 抽取。保留被标注为文学或书面作品、且有作者、出版日期、语言、英文标题与映射流派的记录；过滤掉 edition、series、article、chapter、play、poem、short story。按归一化标题+作者去重，固定随机顺序，取 26.1k 条合格作品中的前 **20,000** 条构成 catalog；5k 与 10k catalog 是其前 5,000/10,000 条，因此**每个小 catalog 都内嵌于大 catalog 中**（这对规模实验至关重要——每个 5k 答案都保留）。修正了 25 条 Wikidata 标签，剔除两类错误记录。覆盖 **19 个流派、151 种语言、166 个国家标签、年份 1460–2026**。

**Task family**：450 个任务 = 150 个 family，每个 family 固定谓词、答案集、persona、阅读历史与接受格式，只变披露方式。谓词用四个字段：**genre、language、country of origin、publication year**。任务分三层——simple（2 个谓词）、medium（3–4）、complex（5 个，年份区间算 2 个），共 13 个模板（字段与年份界的固定组合）。

**NVR（无有效推荐）family**：15 个 family 满足"去掉任一谓词后仍至少有 3 个匹配"。每个谓词都是**实质性**的（去掉它会减少至少一个答案，且至少 5%）；每个可满足 family 在 5k catalog 中都保留至少一个可接受答案（未读、格式被接受）。

**Reveal tag 与三个条件**：
- **volunteer**：用户以完整形式开场，陈述每个谓词与接受格式。
- **mixed**：用户陈述一个谓词；被问到某字段时揭示该字段的 on-ask 谓词或其接受格式。**一个点名所有字段的宽问题即可披露全部 askable 事实**。
- **hidden**：用户在整个对话中至少隐瞒一个谓词；被问到该字段时回避——这**揭示了存在一个要求，但不揭示其取值**。被隐藏的谓词至少排除 50% 匹配已揭示谓词的书；任何已揭示事实都不会泄露隐藏事实（任务绝不会一边说"英式英语"一边把"英国"作为国家隐藏）。

**格式、历史与检查**：Wikidata 不记录版本形式，故每本书由其 Wikidata ID 的哈希确定性地赋予一组模拟格式（audiobook / ebook / hardcover / paperback）。36 个 family 的用户只接受一种格式，且 5k catalog 中至少有一个其他方面合格的书缺该格式。48 个 family 的用户有阅读历史，其中含一个有效答案，且对每个隐藏谓词含一本仅违反该谓词的书——因此历史中没有任何一本书泄露隐藏值。在 17 个有两个隐藏谓词的 family 中，历史整体会暗示它们，但 agent 在 panel 的 5 个这类任务上并不比随机 51/150 更好。

**协议检查（5 项）**：agent 至多推荐一本书、绝不推荐阅读历史中的书、用户点名格式后要检查格式、NVR 任务上必须弃权、其他任务必须调用 recommend。

### 2. 受控评估设计

四个研究问题：**RQ1（披露）** 固定 request 下，从主动说出到可问出到隐藏，成功率损失多少？**RQ2（接口）** schema 对齐的检索接口相对 top-20 关键词检索如何改变端到端成功？**RQ3（规模）** 每个 5k 答案都保留时，成功率如何随 catalog 大小变化？**RQ4（可靠性）** 哪些效应跨模型、trial、用户成立？

**Agents**：三个开源模型——DeepSeek V4.1 Flash、GLM 5.3 Flash、Qwen 3.8 27B（temperature 0，输出仍有波动），加前沿模型 **GPT-6.1 Sol**（用其要求的默认温度），全部高推理强度。所有 agent 收到相同 system prompt。

**Interfaces**：两者都提供元数据、格式可用性、阅读历史工具与终局 `recommend(item_id)`（评分 item id 而非从文本解析的标题）。**keyword 接口** 对每字段求 Okapi BM25 分之和，返回 top-20，不分页；年份字段未建索引，故**年份区间无法表达**。**structured 接口** 提供大小写不敏感、合取式的 genre / language / country（父标签覆盖子标签）/ 年份区间 / 可接受格式过滤器，按 Wikidata sitelink 数（流行度代理）或时间新近返回每页 20 条；未知值返回有效词表。structured 工具的 prompt 行会列出这些字段而 keyword 不会——因此这是一个**工具 + prompt 的捆绑对比**，而非纯 retriever 对比。

**Users**：默认**规则化用户**，持有任务事实并按固定规则回答（用关键词匹配判断 agent 在问哪些字段）。该匹配在 200 个留出的 agent turn 上与一个 LLM 的标注对照检查。LLM 用户块中 GLM 与 Qwen 扮演用户（temperature 1），拿到相同规则、事实与 reveal tag，但自己决定披露什么、怎么措辞，而**裁决仍由 identifier 检查给出**。基础 prompt 告诉 agent 用拒绝作为挑选更好候选的反馈，但**不告诉**它"拒绝意味着某个要求失败了"或"被回避的问题藏着一个要求"。

**Trials**：每次 trial 允许 20 个 agent turn（含无裁决的 turn）、600 秒 agent 时间；也会因 context 溢出或超过 150 次工具调用预算 10 次后结束——**这些上限不告知 agent**。

### 3. 度量与统计

$$\text{pass}^k = \frac{1}{|T|} \sum_{t \in T} \binom{c_t}{k} \big/ \binom{n_t}{k}$$

其中 $c_t$ 为任务 $t$ 的成功次数，$n_t$ 为 trial 数。区间与 p 值来自**配对 bootstrap**（重采样 task family）；差值以百分点计。共 12 个预注册检验：接口检验（20k 下 structured − keyword，平均 over agent 与条件）单独检验不做校正（$p<0.05$），其余 11 个用 Holm 校正。鲁棒性检查包括跨模板的精确 sign-flip 检验。

### 4. 参考 agent（脚本化）

两个脚本 agent 走完全相同的 user、tools、scoring 与上限，且只提议未读的书：

- **popularity agent**：问一个点名所有字段的问题，按用户所说过滤，提议最流行的匹配直到被接受；没有候选时弃权。**只使用 prompt 告诉它的信息。**
- **eliminating agent**：额外知道 protocol 的语义（被回避的字段持有要求；被拒的书至少违反一个要求）。它列出可能的隐藏要求（每个被回避字段的一个或两个取值），**排除每一个满足被拒 book's 要求**，提议最匹配剩余要求最多的书，没有候选适合任何剩余要求时弃权。

两者解决全部 300 个 volunteer 与 mixed 任务。在 135 个可满足 + 15 个 NVR 的 hidden 任务上，popularity agent 解出 84 + 2，eliminating agent 解出 **129 + 13**（每次成功中位数 3 次提议）。另有一个 **no-ask floor**：从不提问，直接推荐最流行的、匹配开场请求的未读书。

## 关键洞察

1. **agentic 系统的瓶颈不是排序，而是"知道该问什么"**。mixed 任务上，引出全部 askable fact 的 trial 成功率 98%，未引出的只有 52%——**差 46 点**。而所有 agent 都能轻松达到 volunteer 任务的 0.94–1.00。这说明推荐系统 agent 的能力上限主要被"澄清能力"而非"检索能力"限制。
2. **一句 prompt 就能把 mixed 失败几乎清零（+59.0 点）**，说明这是**接口/提示层的问题**，不是模型能力问题。工程含义：不要先换模型，先改 prompt 与工具契约。
3. **hidden 任务暴露了"未经检验的承诺"这一 agent 特有失败模式**（78% 的失败）：agent 会推荐一本自己从未提议、因而从未获得用户裁决的书。提议本身就是一个成本极低的风险控制动作——ask-and-verify 提示把这类失败压到 ≤30%。
4. **协议语义（拒绝/回避的含义）是最高杠杆的知识注入**：仅给一句"被回避的字段藏着一个要求、被拒的书至少违反一个要求"（不含任何策略），就使每个 agent 平均 +22.5 点；而"先提议"只让 agent 追平"提议热门书"的脚本（0.483–0.617 vs 0.600）。**推论式的策略（用拒绝做排除）比机械式的流程约束（先提议）有效得多。**
5. **人类真实行为本身就大量依赖澄清**：ReDial 数据显示 52% 的第一个需求是被问出的、12% 只在看到建议后才说。这为 hidden 条件不是人为刁难提供了经验依据。
6. **规模远不如时机重要**：5k→20k 只掉 4.2 点（keyword），而 volunteer→hidden 掉 69.3 点。做 agentic 推荐评测时，**把预算花在构造 disclosure variants 而不是扩大 catalog 上**。
7. **可验证评分 + 全量 trace 发布构成了评测方法论的可复用模板**：不用 LLM judge、规则化用户、20 次提议中位数可算、32,976 条 trace 可重放、catalog 可逐字节重建——这套东西让"agent 到底哪一步做错了"变成可归因的问题。
8. **GPT-6.1 Sol 的行为模式与开源模型截然不同**：它几乎不解 volunteer（0.994–1.000）却最差地处理 mixed（0.419–0.458），因为它在 40–49% 的 mixed trial 中一个事实都不引出。**"强模型不会问"是长上下文/长指令下的典型退化模式**，用单条件评测完全看不到。

## 局限性

- **目录与谓词空间有限**：四个字段（genre / language / country / year）、20,000 本书、19 个流派；结论对电影/电商等更丰富的字段（价格、评分、情节、主题情绪）外推性未知。
- **格式是模拟的**（由 Wikidata ID 哈希确定），不是真实的出版形式数据；阅读历史也是合成的。
- **persona 是合成的**，只由 LLM 用户扮演；真人用户的表达方式、模糊化需求、说谎等未被建模。
- **规则化用户的字段识别依赖关键词匹配**：与 LLM 标注对照后，匹配错误使 mixed 成功率最多变动 -3.9 / +2.0 点，误差不可忽略。
- **"用户拒绝陈述"这一最困难的 human 行为只用规则模拟**（固定回复模板），真人会给出理由、部分透露、或协商，行为复杂度远高。
- **critique（用户看到建议后提出新要求）被明确留给未来工作**，而这在 ReDial 中占 12%。
- **18 个 family 的 reliability block、33 个 family 的 panel** 规模不大，检验功效有限：论文自述在 80% 功效下，panel 只能探测约 6 点的效应（hidden 上需 14 点）。
- **接口对比是"工具 + prompt"的捆绑**，不是纯 retriever 对比；虽然做了字段列表拆分，但 prompt 差异仍可能贡献部分增益。
- **模型版本极新**（DeepSeek V4.1 Flash、GLM 5.3 Flash、Qwen 3.8 27B、GPT-6.1 Sol），结论随模型迭代可能变化。
- **隐藏条件的 NVR 任务通过率极低**（LLM 平均 0.047，最高 0.167），说明"知道自己不该推荐"这件事几乎没被解决。
- **未评估多轮追问的成本**——trial 上限 20 turn 与 600 秒可能不足以让 agent 完成 hidden 任务的系统排除（eliminating agent 中位数 3 次提议即达标，但 agent 常未达到）。

## 适用场景

**适用**：
- 构建 agentic 推荐、客服、需求澄清类系统的评测框架：matched disclosure variants 是一个可直接复用的设计范式。
- 诊断 agentic 系统失败：本文的失败归因（不问 / 未检验的承诺 / 未利用拒绝反馈）是一份具体的检查清单。
- 需要无 LLM judge 的可验证评分：catalog 谓词打分 + 规则化模拟用户的组合可直接搬到其他目录型任务（工具选型、配置推荐、资产检索）。
- 团队在做 agent 的 prompt 工程：本文提供了"加一句协议语义"的量化收益（+22.5 点）与"加一句ask"的收益（+59.0 点）。

**不适用**：
- 开放式内容推荐（摘要生成、相似内容发现）——那里没有可验证的目录谓词。
- 有真实人类用户的生产环境（simulator 的行为分布与真人差距大）。
- 单一接口、单一目录规模下的横向模型比较（本文的重点是条件对比而非模型排名）。
- 需要评估长期用户满意度/留存的研究——本文只测单次 trial 的成功。
