# BitDecoding-FP4: Native FP4 KV Cache Decoding via Algorithm-System Co-Design

> **arXiv**: [2611.09825](https://arxiv.org/abs/2611.09825)
> **发表日期**: 2026-11-06
> **分类**: cs.AI (及交叉分类 cs.AR, cs.CL, cs.PF)
> **会议/期刊**: arXiv preprint

## 📋 摘要

在长上下文 LLM 服务中，**KV cache** 主导了显存容量与带宽。尽管 **4-bit 微缩放格式（NVFP4、MXFP4）**能压缩 cache 并让 attention 跑在 **FP4 Tensor Core** 上，但算法量化与系统感知加速之间仍存在根本缺口：现有 FP4 KV 系统采用**朴素量化**，导致精度大幅下降；而追求精度的 4-bit 算法依赖**向量码本（vector codebooks）**，其查找开销又拖慢解码吞吐。本文提出 **BitDecoding-FP4**——一个面向精确且高效的**原生 FP4 KV 解码**的**算法—系统协同设计**。作者针对三类误差来源进行缓解：
- **Dual-Residual Query Quantization（双残差查询量化）**：把 query 拆成两个 FP4 张量，将 **query logit 误差从 60% 降到 1%**；
- **Underflow-Aware Probability Scaling（下溢感知概率缩放）**：防止 E4M3 scale 在长上下文下把概率**舍入为零**；
- **Outlier-Aware Key Quantization（离群感知键量化）**：结合**静态平滑、Hadamard 旋转与 scale 搜索**，在 token-wise scaling 下抑制 key 离群值。
在系统层面，作者用**转置 softmax + 融合概率量化 + 堆叠 query MMA** 消除 softmax 瓶颈，并支持 **paged KV cache**。在覆盖 dense 与 **MoE** 模型、**GQA** 与 **MLA** 架构的实验中，BitDecoding-FP4 在 **NVFP4** 下与 **BF16 KV** 精度差距在 **0.5 分**以内（**MXFP4** 为 **1 分**），并在 **RL 训练 rollout** 中与 BF16 KV 表现持平。在 **NVIDIA B300** 上以 **Qwen3-4B** 与 **Qwen3-30B-A3B** 做端到端服务，相比 BF16 KV 达到 **2.4–3.0 倍**的峰值服务吞吐。实现已开源：https://github.com/OpenBitSys/BitDecoding-FP4 。

## 🎯 核心贡献

1. **算法—系统协同设计**：同时在量化算法侧（精度）与系统侧（吞吐）动手，弥合"精度友好的 4-bit 算法跑不快、跑得快的 4-bit 系统不准"的缺口。
2. **Dual-Residual Query Quantization**：把 query 分解为两个 FP4 张量，将 **query logit 误差从 60% 大幅降至 1%**——这是精度提升的核心来源。
3. **Underflow-Aware Probability Scaling**：处理长上下文下 **E4M3 scale 下溢**导致概率被舍入为 0 的隐蔽失效模式（长上下文的关键问题）。
4. **Outlier-Aware Key Quantization**：**静态平滑 + Hadamard 旋转 + scale 搜索**三合一，抑制 token-wise scaling 下 key 的离群值。
5. **系统层优化**：**转置 softmax**、**融合概率量化**、**堆叠 query MMA**，配合 **paged KV cache**，消除 softmax 瓶颈。
6. **原生 FP4 落地**：在 **FP4 Tensor Core** 上直接执行 FP4 KV attention，无需退回到向量码本查找；端到端服务吞吐 **2.4–3.0×**（vs BF16 KV）。

## 🔧 方法/架构

- **误差来源与对策**：

| 误差来源 | 对策 | 效果 |
|---|---|---|
| Query 量化误差 | **Dual-Residual Query Quantization**：query $q$ 拆为两个 FP4 张量 $q = q^{(1)} + q^{(2)}$ | logit 误差 **60% → 1%** |
| 长上下文概率下溢 | **Underflow-Aware Probability Scaling**：调整 E4M3 scale 避免长尾概率被舍入为 0 | 防止长上下文 softmax 退化 |
| Key 离群值 | **Outlier-Aware Key Quantization**：静态平滑 + **Hadamard 旋转** + scale 搜索 | 抑制 token-wise scaling 下的离群 |

- **系统层**：
  - **转置 softmax（transposed softmax）** + **融合概率量化（fused probability quantization）**：避免物化中间概率张量；
  - **堆叠 query MMA（stacked query MMA）**：在 FP4 Tensor Core 上批量做矩阵乘累加；
  - **paged KV cache**：与非连续内存布局兼容，适配 vLLM 类服务框架。
- **格式支持**：**NVFP4** 与 **MXFP4** 两种 4-bit 微缩放格式；架构覆盖 **GQA** 与 **MLA**（DeepSeek 式），模型覆盖 **dense** 与 **MoE**。
- **设计哲学**：避免向量码本查找（精度好但慢）与朴素量化（快但不准）两条路线的二选一，改为在算法与 kernel 两端同时优化。

```math
q = q^{(1)} + q^{(2)}, \qquad q^{(1)}, q^{(2)} \in \mathrm{FP4}
\;\Rightarrow\;
\frac{\lVert \logit_{\text{quant}} - \logit_{\text{fp16}} \rVert}{\lVert \logit_{\text{fp16}} \rVert} : 60\% \rightarrow 1\%
```

## 📊 实验结果

- **模型**：**Qwen3-4B**（dense）、**Qwen3-30B-A3B**（MoE）；架构覆盖 GQA 与 MLA。
- **硬件**：**NVIDIA B300**，使用原生 **FP4 Tensor Core**。
- **精度基线**：**BF16 KV**。
- **精度结果**：
  - **NVFP4**：与 BF16 KV 差距 **≤ 0.5 分**；
  - **MXFP4**：差距 **≤ 1 分**；
  - **RL 训练 rollout**：与 BF16 KV **持平**（tracking）。
- **系统结果**：端到端服务**峰值吞吐提升 2.4–3.0×**（相对 BF16 KV）。
- **组件级结果**：Dual-Residual Query Quantization 使 **query logit 误差 60% → 1%**。
- **代码**：https://github.com/OpenBitSys/BitDecoding-FP4
- 摘要**未给出**绝对精度分数（具体 benchmark 名称与分数）、显存节省比例、具体延迟数值与测试 batch/并发配置。

## ⚠️ 局限性

- **硬件绑定**：效果依赖 **NVIDIA B300** 的 FP4 Tensor Core，迁移到其他加速器（如 AMD、Intel、TPU）需重写 kernel；摘要未给跨硬件结果。
- **依赖 Blackwell 级特性**：FP4 微缩放格式与 Tensor Core 支持是新硬件特性，老卡无法受益（这恰恰限制了实用性）。
- **精度差距虽小但非零**：NVFP4 仍有 ≤0.5 分差距，MXFP4 ≤1 分——摘要未给出该差距随上下文长度、模型规模的扩展趋势。
- **未覆盖更激进压缩**：仅 4-bit，未讨论 2-bit/3-bit 场景；与 [[2611.09598]] 的极端压缩（最高 97.5×）路线不同，两者难以直接比较。
- 摘要**未给出**绝对精度指标与端到端延迟/显存数字（只给吞吐倍数），难以评估在不同 SLA 下的实际收益。
- **RL rollout 场景验证有限**：仅说明与 BF16 持平，未给出长序列 rollout 的稳定性曲线。

## 💡 建议

- 是否推荐使用：**是**（若团队使用 B300/Blackwell 级 GPU 并有长上下文高并发服务需求）
- 适用场景：长上下文 LLM 服务（paged KV cache、vLLM/SGLang 类框架）、RL 训练 rollout 的显存压力优化、MoE/GQA/MLA 架构的推理加速。落地前建议实测自身 workload——摘要的吞吐倍数依赖 batch/并发配置，且需确认硬件是否支持原生 FP4。
