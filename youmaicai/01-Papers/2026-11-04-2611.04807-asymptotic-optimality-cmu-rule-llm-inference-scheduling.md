## 核心贡献
1. **建立显式刻画 KV-cache 显存约束与显存 I/O 成本的 LLM 推理排队模型**：请求带异质 prompt/output 长度到达，经历 **prefill → 自回归 decode** 两阶段，竞争有限的 KV-cache 容量 $M$ tokens。关键区别于经典排队模型：**处理时长同时依赖 prefill 计算与 KV-cache I/O**，且**服务能力由计算、显存访问、显存占用三者共同决定**。
2. **识别出恰当的渐近（fluid）区间**：处理速率与到达速率**同比例放大**，而**总显存容量保持固定**（$M=O(1)$）。这一区间直接刻画了 LLM 推理的关键瓶颈——把主要计算负担转移到显存约束与 I/O 成本上。
3. **证明流体极限下系统等价于带同质服务器的经典多类别单服务器排队模型**，但其**有效服务率 $\mu$ 必须同时计入 prefill 计算、KV-cache I/O 与显存容量约束对服务可用性的影响**。这是把经典 $c\mu$ 优先级规则迁移到 LLM 服务的关键桥梁。
4. **证明 $c\mu$ 规则在流体模型下的持有成本最优性**（Theorem 1）：对每个可行策略 $\pi$，$J(\pi^*;z_0)\le J(\pi;z_0)$。
5. **证明有限负载下的完成时间最小化与全程 output-token 吞吐最大化**（Theorem 2）：$\tau^c_{\pi^*}\le\tau^c_\pi$，且 $\text{TP}_\pi(\tau^c_{\pi})\le \text{TP}_{\pi^*}(\tau^c_{\pi^*})$。
6. **构造可实施的 $c\mu$-inspired 动态策略并证明其流体收敛**（Definition 5 + Theorem 3）：采用 Skorokhod 反射构造递归的累计完成过程，用移动平均把每个准入计划摊到 $w_r$ 步窗口内以满足显存约束；**该策略不需要知道到达率 $\lambda_j(\cdot)$**。命题 1 证明其在每个有限尺度 $r$ 上都是可行的（admissible）。
7. **在真实 LLM serving engine 上验证**：Meta-Llama-3-8B-Instruct + vLLM + 单张 NVIDIA H800。实现两个实用策略 **$c\mu$** 与 **$c\mu$-backfill**，与 vLLM 默认调度器、MC-SF、SVF、WAIT-frac 对比，在 Qwen-Bailian Anonymous Dataset 的四条生产 trace（To-B、To-C、Thinking、Coder）与八条半合成 trace 上评测。
8. **发现 WAIT 理论最优但实机表现恶化**：作者指出 WAIT (Ao et al.) 虽理论上最优，但在真实 GPU 实现中因**不必要的空闲（unnecessary idling）**而性能退化；WAIT-frac 是作者为适配小服务配额引入的分数信用变体（原始 WAIT 在其 GPU 配置下因 batch service-time 模型不同而无正的 $T_{\text{WAIT}}$，故设为 120ms）。

## 问题背景
2022 年底 ChatGPT 发布后，生成式 AI 快速普及，Deloitte 估计 **2026 年推理将占 AI 总算力的约三分之二**（2023 年约为三分之一）。推理工作负载持续扩张下，**GPU 显存成为关键瓶颈**：agentic 与 reasoning 工作负载中常见的长输入 prompt 与长生成序列导致大量 KV-cache 占用。

KV caching 是加速 LLM 推理的标准技术——它把已计算的 key/value 存于显存以避免重复计算——**但加速的代价是显著的显存消耗与密集的显存访问**，使显存容量与带宽愈发重要。

与经典随机装箱（stochastic bin packing）等问题的三点关键差异（作者明确列出）：(1) 经典模型假设请求到达时尺寸固定，而 LLM 请求的 KV 占用**随生成推进而增长**；(2) LLM 有 **prefill 与 decode 两个不同阶段**，显存动态不同；(3) 经典模型中服务时长通常独立于当前显存占用，而 **LLM 的处理时长依赖显存占用**（KV-cache I/O 成本）。

最相关的已有工作：Ao et al. 的 **WAIT**（已知输出长度时在显存约束下最大化吞吐）与 Ao et al. 的后续（速率限制准入与请求混合）；Jaillet et al. 的 MC-SF；Kong et al. 的 **SVF**（基于累计 KV-cache 用量的 Smallest Volume First）；Dai et al.（per-batch token 预算下的稳定吞吐）、Nie et al.（跟踪 KV 增长的细粒度模型，但假设恒定 batch 处理时长）、Lin et al.（多 GPU 下的 prefill–decode 争用）、Yao et al.（多轮对话中 LRU 淘汰下的 KV 复用均值场极限）。

## 方法

### 1. 排队模型

单 GPU 在线服务系统。请求被划分为 $J$ 类；class-$j$ 请求有已知 prompt 长度 $s_j$ 与 output 长度 $o_j$；GPU 有 KV-cache 容量 $M$ tokens。prompt 被切为大小 $c_{\text{chunk}}$ 的 chunk，故

$$L_j = \left\lceil \frac{s_j}{c_{\text{chunk}}} \right\rceil$$

class-$j$ 请求有 $L_j$ 个顺序 prefill 阶段，随后 $o_j-1$ 个顺序 decode 阶段（最终 prefill 阶段产生第一个 output token）。若 $o_j=1$，请求在最终 prefill 阶段后立即离开系统。

**显存约束**：令 $m(t)$ 为步骤 $t$ 期间的最大 KV-cache 占用（已占用的 KV states + 该步新写入的），则

$$m(t)\le M,\qquad t=0,1,\dots$$

**步骤时间的经验模型**：在 NVIDIA H800 上实测不同的混合 batch，观察到**步骤时间近似线性依赖 KV-cache I/O 体积 $n_{\text{kv}}(t)$ 与该步处理的 prompt token 数 $n_{\text{pf}}(t)$**：

$$b \approx a_{\text{pf}}\, n_{\text{pf}}(t) + a_{\text{kv}}\, n_{\text{kv}}(t) + c$$

（$a_{\text{pf}}, a_{\text{kv}}, c$ 对每张 GPU 单独校准。）

### 2. 有效服务率与 $c\mu$ 排序

对 class $j$ 记 $\tilde m_j$ 为其"满显存占用"下的显存度量，$\mu_j$ 为有效服务率。**$\mu_j$ 由计算速度、显存带宽与显存容量共同决定**。索引类使得

$$c_1\mu_1 \ge c_2\mu_2 \ge \cdots \ge c_J\mu_J$$

$c\mu$ 规则按此优先级顺序分配服务，每个类以其等待请求、新到达与显存约束所允许的**最大速率**服务，剩余容量传递给更低优先级的类。

### 3. 流体 $c\mu$ 策略的构造（Definition 4）

以累计完成过程表示策略，按优先级递归构造。记 $A_j(\tau)$ 为 class-$j$ 到时钟时刻 $\tau$ 的累计到达：

$$A_j(\tau) := p_{j,L_j(0)} + \int_0^\tau \lambda_j(s)\,ds$$

递归定义（Skorokhod 反射表示传递给低优先级类的剩余服务预算）：

$$R_j^*(\tau) := \sup_{0\le s\le\tau}\Big[R_{j-1}^*(s) - \mu_j^{-1}A_j(s)\Big]_+$$

再定义

$$F(\tau) := \frac{1}{M}\sum_{j=1}^J \tilde m_j\mu_j\big(R_{j-1}^*(\tau)-R_j^*(\tau)\big) + \frac{1}{b}R_J^*(\tau)$$

策略时钟为其广义逆 $f^*(\xi):=\inf\{\tau\ge 0: F(\tau)\ge\xi\}$，累计完成过程

$$X_j^*(\xi) := \mu_j\big(R_{j-1}^*(f^*(\xi)) - R_j^*(f^*(\xi))\big)$$

**无新到达时的闭式解**（Appendix E）：$X_j^*(\xi) = \left[\frac{M}{\tilde m_j}\left(\xi - \sum_{\ell=1}^{j-1}\frac{\tilde m_\ell p_{\ell,L_\ell(0)}}{M}\right)\right]^{p_{j,L_j(0)}}_0$，即各类按索引顺序（即递减的 $c_j\mu_j$）依次服务。

### 4. 三个定理

- **Theorem 1（流体持有成本最优）**：流体 $c\mu$ 策略 $\pi^*$ 可行且最小化累计持有成本，$J(\pi^*;z_0)\le J(\pi;z_0)$ 对每个可行 $\pi$ 成立。
- **Theorem 2（完成时间与吞吐最优）**：$\pi^*$ 最小化完成所有请求所需时间 $\tau^c_{\pi^*}\le\tau^c_\pi$；当 $\sum_j o_j A_j(H)>0$ 时，最大化全程 output-token 吞吐 $\text{TP}_\pi(\tau^c_\pi)\le\text{TP}_{\pi^*}(\tau^c_{\pi^*})$。证明要点：每个完成所有请求的策略产生的总 output token 数相同（$\sum_j o_j A_j(H)$），故完成时间最短即全程吞吐最高。
- **Theorem 3（流体极限收敛）**：在初始无请求处理、初始等待队列长度满足 $\frac{1}{r}p^r_{j,L_j(0)}\to p_{j,L_j(0)}$ 的条件下，prelimit 系统在 Definition 5 的平滑 $c\mu$-inspired 策略下，其累计控制过程与系统时钟在 fluid 缩放下**收敛到 Definition 4 的最优流体 $c\mu$ 策略**：

$$\sup_{0\le\xi\le T}\Big|\tfrac{1}{r}U^r_{j,k}(\lfloor r\xi\rfloor) - X_j^*(\xi)\Big| \xrightarrow{P} 0$$

### 5. 可实施的平滑策略（Definition 5）

预留显存用量（class $j$ 请求在准入后第 $h$ 步）：

$$k^{\text{kv}}_j(h) = \begin{cases} \min\{c_{\text{chunk}}(h+1), s_j\} & 0\le h\le L_j-1\\ s_j + h - L_j + 1 & L_j\le h\le L_j+o_j-2\\ 0 & \text{否则}\end{cases}$$

累计 KV 用量 $\tilde m_j$ 满足 $\sum_{h=0}^{H_{\text{kv}}} k^{\text{kv}}_j(h)=\tilde m_j$，其中 $H_{\text{kv}}:=\max_{1\le j\le J}(L_j+o_j-2)$。

按优先级顺序递归定义新的 class-$j$ 计划准入量：

$$y^r_j(t) = \min\Bigg[\Big(p^r_{j,L_j(0)} + \sum_{u<t}\eta^r_j(u) - \sum_{u<t}y^r_j(u)\Big)_+,\ \tilde m_j^{-1}\Big(w_r M w_r + H_{\text{kv}} - \sum_{\ell<j}\tilde m_\ell y^r_\ell(t)\Big)_+\Bigg]$$

准入增量由移动平均给出：

$$\Delta U^r_{j,L_j}(t) = \frac{1}{w_r}\sum_{v=0}^{w_r-1} y^r_j(t-v)$$

即把 $y^r_j(t)/w_r$ 的计划安排在步骤 $t,\dots,t+w_r-1$ 进入 GPU。取 $w_r=\max\{H_{\text{kv}}+1,\lceil\sqrt r\rceil\}$ 满足 $w_r\to\infty$、$w_r/r\to0$、$w_r>H_{\text{kv}}$。**允许分数请求**，故 $y^r_j$ 与 $\Delta U^r_{j,L_j}$ 可取非整数值。**该策略不需要到达率信息。**

### 6. 实验设置

Meta-Llama-3-8B-Instruct + vLLM，单张 NVIDIA H800，同一实验组内所有策略顺序跑在同一 GPU 上。生产 trace 来自 Qwen-Bailian Anonymous Dataset 的 To-B（业务 API 与任务自动化）、To-C（消费级交互聊天）、Thinking（推理密集聊天）、Coder（代码生成与交互编程），每条覆盖两小时；只保留 prompt+output 不超过 8K context 的请求；到达率调整至 **traffic intensity ≈ 0.95**。

| Trace | 请求数 | 平均 prompt 长度 | 平均 output 长度 |
|---|---|---|---|
| To-B | 172,015 | 863.0 | 88.4 |
| To-C | 39,937 | 1635.2 | 407.2 |
| Thinking | 7,057 | 2494.2 | 1993.9 |
| Coder | 27,099 | 2539.7 | 727.8 |

**对比策略**：vLLM 默认调度器、MC-SF（按递增 output 长度排序）、SVF（按递增累计 KV 体积 $s_io_i+\frac{o_i(o_i+1)}{2}$ 排序）、WAIT-frac（作者引入的分数信用变体；原始 WAIT 的正整数服务配额在最小配额为 1 时会消除"等待累积"机制，且其参数公式在其 GPU 配置下得不到正的 $T_{\text{WAIT}}$，故设为 120ms）。所有非默认策略均为非抢占实现，并**假设每个请求的输出长度已知**，且在准入前检查未来 KV-cache 可行性（考虑缓存增长与完成时的释放）。

**$c\mu$-backfill**：与 $c\mu$ 同排序同可行性检查，但当某请求不能立即准入时，用未来可行性检查找出其**最早可行的未来准入步**，并在后续检查中假设它在该步被准入；随后继续扫描更低优先级请求，若在包含这些计划准入的情况下可行则立即准入。

**指标**：平均请求延迟 $\text{Latency}_{\text{avg}}=\frac{1}{N}\int_0^\infty c_Q(\tau)d\tau$（其中 $c_Q(\tau)$ 为已到达未完成请求数）、mean TTFT、P99 latency、clearance time、output-token throughput。

- **Ablations / 关键观察**：
  - **吞吐几乎不变**（2,509–2,521 tokens/s 在半合成上；2,822–3,553 在生产 trace 上）——**这是设计使然**：Theorem 2 表明完成所有请求的策略产生的总 output token 数相同，调度只改变**何时**完成，不改变**总量**。因此延迟与 TTFT 的改善是纯粹的排序收益。
  - **$c\mu$ 与 $c\mu$-backfill 明显优于 vLLM 默认**：To-B 上平均延迟 9.47/10.40 vs 35.49 秒（约 3.5×）；TTFT 2.56/3.20 vs 28.77 秒（约 10×）。
  - **在 To-C 与 Coder 上 $c\mu$-backfill、$c\mu$、SVF 三者相近**——说明在某些长度分布下 $c\mu$ 排序相对 SVF（体积优先）没有优势。作者指出：当 $c_i=1$、$a_{\text{pf}}=0$ 且 prefill 不分块时，**$c\mu$ 规则退化为 SVF 那样的体积优先规则**。
  - **在 Thinking（长输出、长推理）上 $c\mu$ 最好**：平均延迟 128.83 vs $c\mu$-backfill 160.10、MC-SF 152.13、vLLM 61.49——注意**这里 vLLM 默认反而最低（61.49）**，作者未就此给出解释。
  - **P99 延迟排名与平均延迟不同**：WAIT-frac 在半合成上 P99 最低（67.163），但平均延迟远差于 $c\mu$ 系列。作者明确指出"排名在平均与尾部延迟之间可能不同"。
  - **WAIT 的实机退化被明确归因于"不必要的空闲"**。

## 关键洞察
1. **"显存容量固定而算力放大"的 fluid 区间是这类问题唯一有意义的渐近区间**。若显存也随负载放大，KV 约束就不再是瓶颈，模型退化回经典计算受限排队；固定 $M$ 才让内存约束成为一等约束。这是本文渐近分析中最关键的一步选择。
2. **$c\mu$ 规则之所以能迁移，核心是 $\mu$ 重新定义**。经典 $c\mu$ 中 $\mu$ 是服务率；这里 $\mu_j$ 被**计算速度、显存带宽、显存容量三者共同决定**——因此优先级不只反映"服务快慢"，而是反映"占用一单位显存能换来多少服务"。这个重构是全文的技术核心。
3. **Theorem 2 的一个漂亮推论：调度不改变总产出，只改变产出时序**。因为每个完成全部请求的策略产生相同的 $\sum_j o_j A_j(H)$ 个 token，最小化完成时间**等价于**最大化全程吞吐。这解释了为什么实验表中所有策略的 throughput 几乎相同而 latency 差异巨大——**调度的价值全在"何时"而非"多少"**。这一点对任何 LLM serving 优化的期望管理很重要。
4. **理论最优的 WAIT 在实机上因空闲而恶化**，这是理论与实现的经典落差：WAIT 的阈值需要到达率信息，且其批处理时间模型与本文 GPU 配置不符（原始公式甚至得不到正的 $T_{\text{WAIT}}$）。作者没有回避而是给出了 WAIT-frac 的分数信用变体并明确说明其参数是人为设定的（120ms）。
5. **$c\mu$ 与 SVF 在某些分布下会退化重合**。当 prefill 计算开销可忽略且不分块时，$c\mu$ 规则**就是**体积优先规则。这解释了 To-C/Coder 上三者相近的结果——也提示该方法的优势主要出现在**prefill 计算占比高**（长 prompt）或**输出长**（reasoning 负载）的场景。
6. **平滑策略不需要到达率信息**，这是从理论到落地的关键设计。用移动平均把准入计划摊到 $w_r$ 步窗口，同时满足显存约束与理论收敛要求。
7. **$c\mu$-backfill 的实用价值在于"预约"**：把暂时不可准入的请求预约到最早可行步，从而不浪费未来释放的显存。这是把一个纯排序规则变成实际可执行策略的工程桥梁。

## 局限性
- **所有策略假设输出长度已知**（除 vLLM 默认外），这在真实部署中是强假设——长 reasoning 负载的输出长度高度可变，论文未处理预测误差下的稳健性。
- **全部为单 GPU、单模型（Llama-3-8B-Instruct）、单 H800**；多 GPU、tensor parallel、pipeline parallel 下的行为未验证，而 Lin et al. 已研究多 GPU 的 prefill–decode 争用。
- **模型的 prefill 计算成本 $a_{\text{pf}}$ 在 decode 密集负载下变得极小**，导致 $c\mu$ 退化为 SVF——方法的主要理论优势场景（长 prompt）恰是训练数据中 Thinking/Coder 占比较高的情形，而那里 $c\mu$ 相对 SVF 的优势并未体现。
- **步骤时间的线性模型是经验近似**，忽略了 attention kernel 的非线性、batch 形状效应、KV 布局与 cache hit 模式。
- **fluid 极限结论是渐近的**：Theorem 3 的收敛需要 $r\to\infty$；实际系统处于有限尺度，$w_r=\lceil\sqrt r\rceil$ 的窗口与理论理想化行为之间的差距未量化。
- **Thinking trace 上 vLLM 默认的平均延迟（61.49 s）反而远低于所有 $c\mu$ 变体（128.83 / 160.10）**，论文未解释这一反常结果——这是主表中最难解释的一点。
- **P99 延迟未改善**（$c\mu$ 系列的 P99 与 vLLM 默认相当甚至更差），说明收益集中在均值而非尾部，对 SLO 以尾延迟衡量的场景价值有限。
- **traffic intensity 固定为 0.95**，未做负载扫描（overload 区的行为、准入策略的稳定性边界均未给）。
- **未考虑 preemption**：所有比较策略均为非抢占，长请求会阻塞短请求；抢占式策略（如 chunked prefill + 抢占）在 vLLM 生态中很重要，本文未纳入。
- **理论部分对"两阶段 + 显存增长 + 服务时长依赖占用"这三个 LLM 特有特征的建模是近似的**，例如假设同一类请求的输出长度相同（半合成实验中确实如此假设），这在真实 trace 中不成立。
- **Theorem 1 的持有成本是标准 $c\mu$ 框架下的线性/凸延迟成本**，未考虑本文目标中隐含的"错误答案""超时"等业务代价。

## 适用场景
- **为 LLM serving 设计调度策略**：需要可证明的最优排序规则 + 可实施的近似实现时，$c\mu$ 规则及其 backfill 变体是直接可用的起点。
- **长输出 reasoning 负载的调度**（Thinking 类 trace 上 $c\mu$ 给出最低平均延迟与 TTFT）。
- **显存受限的单卡部署**：$c\mu$ 的 $\mu$ 定义天然把显存带宽与容量纳入排序依据。
- **把经典排队论工具引入 LLM 系统的理论工作**：本文提供了可复用的建模路径（fluid 区间选择、有效服务率重构、prelimit-to-fluid 收敛证明）。
- **不适合**：需要严格尾延迟（SLO 以 P99 计）的场景；输出长度不可预知的生产环境；多 GPU 异构或 pipeline 并行；重载/过载区的准入控制与稳定性。
