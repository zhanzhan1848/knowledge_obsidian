## 🎯 今日主线

**今天最有意思的，是「层」这个概念在三篇论文里以三种完全不同的方式反复出现——而这可能不是巧合。**

一层是**服务栈的层**（SafeStart：每 token 路由到更少的 expert，服务更快了，但拒答能力被削掉）。
一层是**推理轨迹的层**（StepBack、Verifier-Guided Self-Consistency：CoT 的每一个 step，而不是整条 trajectory，才是正确的重采样与纠错单元）。
一层是**精度分配的层**（TileQuant：tile 而非 column 才是精度的分配单元，因为敏感性在 column 内部也是不均匀的）。

三条不同的论文，独立的团队，独立的领域（serving / test-time scaling / quantization），却都指向同一个修正：**我们此前选择的粒度层级错了——不是"整条轨迹 / 整列权重 / 全部 expert"，而是它的下一层。** 这看起来像是当前阶段的一个共同盲区。

### 一、安全性从"行为分数"转向"内部结构"（今天最重的一组）

- **Compositional Unalignment (CMaG)**：九种标准 direction-finding 方法能以 **AUC=0.99** 检出组合式伤害，但**消融这些方向要么让拒答纹丝不动，要么摧毁模型连贯性**——识别与拒绝是解耦的。80 个样本、单次反向传播即可得到 steering 方向，让 Qwen2.5-VL-7B / LLaVA-1.5-7B 的组合式安全分数**最多掉 65 分**，同时 **>98% 输出保持连贯**。同一方向还能迁移到显式文本伤害，并能逆向对齐经过防御性训练加固的模型。
- **Addition by Subtraction**：直接承认「安全对齐极其稀疏，剪掉少数安全关键 neuron 或消融单个 refusal direction 就能瓦解对齐」，并**在微调过程中逐步移除这些神经元**，用偏好优化重建安全行为。思路从「加固方向」反转成「删掉方向再重建」。
- **SafeStart**：vLLM 上只保留约 **2/3 的 selected expert**，离线解码加速 **15–28%**（batch size 8, RTX A6000）——但这**削弱了模型对有害请求的拒绝**。专家剪枝的安全性代价此前完全没有被测量过。
- **JailBound**：用一阶逻辑（FOL）自动合成越狱测试，不再优化 ASR，而是**探行为边界本身**。
- **The Harness Is the Model**：固定模型，只换 harness（5 种脚手架），在 156 个预注册案例、11 个规则族（改写自 EU 消费信贷/支付/投资者保护/数据保护条款）上，**合规性随脚手架不同而不同，且在不同模型间不均匀**。结论很硬：银行验证的是模型，部署的是系统。

> 这五条合起来是一记重击：**「benchmark 分数高」与「对齐是稳健的」之间没有任何逻辑关系。** CMaG 证明了最小 SFT 就能刷到与多阶段 RL 流水线相当的 LLM-judge 分数；The Harness Is the Model 证明了连外部脚手架都能左右合规性。我们一直在用「分数」测量一个「结构」属性。

### 二、Agent 的可靠性：从"平均准确率"到"系统级可靠性"

- **More Agents, More Reliable?**：直接质疑「agent 越多越可靠」的默认假设。基于 HIP-LLM 的分层不精确概率评估，agent 的**失效概率区间**沿贝叶斯网络传播（合并规则本身也会失效），得到一条**reliability envelope**——用来显示「是哪一环的证据在限制可靠性」。在受监管化学品危害抽取的流水线上验证。
- **Signed but Not Safe**（预注册研究，1,440 条轨迹，5 类威胁）：free-text / 结构化 JSON / **带签名的 requirement manifest**（HMAC-SHA256 签名 + 可校验 predicate + 逐字引用）三种 handoff 对比。签名 manifest 大幅降低 unsafe commit——但标题说的是「Signed but **Not** Safe」：签名能防篡改，防不了别的。
- **Beyond Instruction Override**：重新定义间接提示注入——不按「指令式措辞」定义，而按**权威性**定义：植入内容试图影响其来源无权决定的事项，就构成攻击。买方纠纷证据引用一条虚假的退款政策即可抬高退款额，而任务本身没变。
- **When File Ingestion Misleads Language Models**：LLM 读的其实是 extractor 从 OOXML 解析出的文本，而 extractor 之间行为不一致。**在幻灯片上微移文本框位置，就能改变模型阅读顺序，而人类看到的完全一样。**

### 三、上下文与记忆：压缩正在从"文本层"下沉到"表示层"

- **Tools Need Not Speak in Text (Coca-Cola)**：直接挑战「agent 必须以显式 text token 消费工具输出」这一前提，把工具输出压成 **latent tokens** 直接嵌入输入表示。token pruning 和摘要方法受限于离散文本表示，压缩比因此有上限。
- **SpecCompact**：观察到**结构化 summary slot 独立生成时仍能保留信息**，于是并行投机生成 slot、由 target model 逐行校验并修复被拒内容，后续 draft 使用更新后的 slot 前缀。
- **MEMOIR**：训练无关的记忆生命周期，把 **judge-gated consolidation**（压缩前先用 gate 检验答案相关证据是否会被毁）与 **retrospective attribution**（按实际使用情况回溯修正静态 importance 分数）统一起来。直指两个耦合失效：**consolidation 会静默销毁未来查询需要的证据，retrieval 却仍在偏爱陈旧记忆。**
- **LooM**：面向因果 encoder-decoder 语言模型的 loop-invariant memory。

### 四、测试时扩展：纠错单元从"轨迹"下沉到"步"

- **StepBack**：self-consistency 要采样大量完整轨迹。StepBack 用轻量信号定位**可能的第一个错误位置**，只重采样该步及其后缀，再做多数投票——**匹配全量 self-consistency 的准确率，但成本更低**。
- **Verifier-Guided Self-Consistency**：既有 verifier-weighted voting（无法引导生成）又有 beam 式 guided search（过度集中、放大 verifier 错误），VGSC 两者兼顾，并给出概率解释——近似从 **verifier-tilted 轨迹分布**采样：
  ```math
  \pi_{\text{VGSC}}(\tau) \propto \pi_{\text{LM}}(\tau)\,\prod_{t} w(v_t \mid s_{\le t})
  ```
- **Turn-Level Best-of-N**：generator 生成 N 个候选动作、selector 选一个执行。检验现成开源权重模型能否直接充当 action comparator。

### 五、推理能力本身：一个理论结果 + 一个数据选择结论

- **Understanding the OOD Generalization of CoT**：把 CoT 的 OOD 泛化刻画为**组合式泛化**——训练只提供 ID 原子步骤数据，CoT 通过**反复套用同一个单步预测器**来组合出可复用的 ID 转移。给出了关于步数 T、每子任务样本数 n、每步 token 数 k 的风险界。
- **Rethinking Data Selection**：难度导向（difficulty-based）的数据选择在 LLM 微调上**常常打不过随机选择**。原因不是"随机运气好"，而是随机选择**对输入空间的覆盖更好**。覆盖度，而非难度，才是 LLM 微调数据选择的主变量——这一条会推翻不少既有配方。

### 六、其他值得单独点名

- **TileQuant**：把精度分配单元从 column 下沉到 **tile**（column 内部的敏感性同样不均匀，整列保留会连带保护不敏感的权重；运行时离群检测则增加解码开销）。
- **Rotation Is Token-Blind**：几何 Transformer 里不同 token 类型共享同一套激活量化网格，少数特殊 token 就能左右全局输出——rotation 方法对它们是盲的。
- **Context–Answer Metamodels**：能否**在第一个答案 token 产生之前**就预测模型后续的 rollout 激活？把「同一 context 可引出多个答案」这件事从需要多次昂贵 rollout 才能刻画，变成一次前向即可预测。
- **What the Middleman Delivers**：实测 **20 个 API 中转服务**（GPT-6 Astra / Claude Opus 5），把答案与官方 batch-matched 响应比对——首轮样本中 **7/10 低价中转、2/10 同价或更高价中转**存在行为差异。中转生态的合规性缺口比预期大。
- **ServerBench**：让 coding agent 设计专用的 LLM serving system。
- **RAGAM-AI**：混合强化学习驱动的 agentic 方案（Genomic 领域）。
- **SecureGARD**：动态本体引导的治理，用于安全工具调用 agent。
- **FedReason**：LLM 作为权重空间 meta-aggregator，聚合异构（联邦）模型。
- **EvoCodeAgent**：架构-代码协同演化 + 经验引导修复，面向项目级代码生成。
- **Adapting LLM Judges to Observed Human Annotation Policy**：通过 soft prompt tuning 让 LLM judge 贴近人类标注者的实际策略。

1. **CMaG 的"识别 ≠ 拒绝"结论能否在纯文本 LLM 上复现**——今天它只在 LVLM（Qwen2.5-VL-7B / LLaVA-1.5-7B，7B 规模）上验证。考虑到"定位 ≠ 可干预"这条裂缝在 11-07 的《Localization Does Not Imply Steerability》中已独立出现（Llama-3.3-70B vs Phi-4 的极端分化），两篇论文指向同一个现象但模型谱系完全不同——**如果这不是"大模型专属 bug"而是通用现象，mechanistic interpretability 的整个干预层都要重新定价。**
2. **SafeStart 的安全代价与 11-07《When Bigger Becomes Brittle》的压缩代价能否串成同一条曲线**：都是"某项效率优化 → 某项能力被削掉 → 用 benchmark 分数几乎测不出来"。SafeStart 给出了更狠的结论：**加速 15–28% 换走了拒答能力，而验收 benchmark 里没有这一项。**
3. **TileQuant 的 tile 粒度能否推广到 KV cache 与激活量化**——tile 优于 column 的逻辑是"敏感性在更细粒度上仍不均匀"，这对 KV cache 应该同样成立，但没人验证过。
4. **Rethinking Data Selection 的覆盖度结论对多模态与 agentic 数据是否成立**——目前只在文本 LLM 微调上验证。
5. **Signed but Not Safe 的"签名能防什么、不能防什么"**值得单独读：1,440 条预注册轨迹、5 类威胁，是今天方法论最扎实的一篇，威胁模型值得借用。
6. **中转服务（relay）的行为差异检测方法**（What the Middleman Delivers，7/10 低价中转存在差异）可以做成一个持续监控任务——生态会变化。
