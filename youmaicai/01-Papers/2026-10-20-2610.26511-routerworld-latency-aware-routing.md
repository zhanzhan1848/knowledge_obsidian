## 核心贡献

> 提出 **RouterWorld** —— 首个将**延迟**作为一等公民、考虑**部分可观测性**的 LLM routing 综合 benchmark，涵盖 371k 单轮响应与 76k 多轮 agentic 轨迹。

1. **大规模数据**：371k 单轮 + 76k 多轮 agentic 轨迹，统一 LLM-as-a-judge 协议
2. **延迟作为一等指标**：硬件锚定的延迟标注，将效率与浮动价格解耦
3. **两种部分可观测设置**：
   - **Cold-Start**: 仅稀疏静态日志
   - **Voyager**: 持续数据流（routing 决策影响未来训练分布）
4. **系统评测 13 个 routing baseline**：发现大多数 router 过度强调 accuracy 而忽视延迟

---

## 技术方案

### 核心思想

现有 LLM routing benchmark 通常假设对所有候选模型输出完全可观测，并将延迟视为二等指标。RouterWorld 给出更贴近生产环境的评测协议：硬件锚定延迟 + 部分可观测的两种学习场景。

### 关键技术

| 技术 | 说明 |
|------|------|
| 371k Single-Turn + 76k Multi-Turn | 大规模真实路由数据 |
| Standardized LLM-as-Judge | 统一答案质量评估 |
| Hardware-Grounded Latency | 硬件锚定延迟，将效率与价格解耦 |
| Cold-Start Setup | 限制学习仅来自稀疏静态日志 |
| Voyager Setup | 持续数据流，routing 决策塑造未来训练分布 |
| 13 Routing Baselines | 全面评估现有方法 |

### 关键设置

| Setting | 描述 |
|---------|------|
| Cold-Start | 仅访问稀疏、静态日志学习 |
| Voyager | 在线数据流；routing 决策会进入下次训练数据 |

## 实验结论

### 主要发现

- **大多数 router 过度强调 accuracy**，在部分可观测下忽视延迟
- 在 Cold-Start 下表现良好的 router，在 Voyager 下可能失效
- 延迟感知 routing 与 accuracy 导向 routing 之间存在明显差距

### 评测规模

- **371k** 单轮响应
- **76k** 多轮 agentic 轨迹
- **13** routing baselines

---

## 局限性

- 主要是 benchmark 论文，未提出新 routing 算法
- 13 baselines 不一定涵盖最新 SOTA routing 方法
- Voyager 设置需要持续反馈循环，部署成本较高
