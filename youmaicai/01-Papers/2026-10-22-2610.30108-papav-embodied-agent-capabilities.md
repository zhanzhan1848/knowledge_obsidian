## 核心贡献
1. 定义 **multimodal embodied agents (MMEAs)**：把 multimodal task reasoning 与 physical action 耦合、并能从反馈中修正决策的目标导向系统。
2. 提出 **PAPAV** 统一 capability-centric 框架，包含五个反复出现的能力函数：**P**erce current state、**A**nticipate action effects、**P**lan a feasible course、**A**ct through an interface or body、**V**erify the outcome。
3. 以"功能而非架构"为定义依据，从而在同一坐标系下比较 MMEAs、MMA（computer-use 多模态 agent）与 RS（机器人系统），并指出三者共享的能力。
4. 对 **64 个 benchmark** 做横断面分析，揭示评测覆盖的严重偏斜：显式评测集中在 **Act**（64 个），而仅 **5 个**评测 **Anticipate**、**3 个**评测 **Verify**。
5. 归纳 **5 条物理约束**（从 partial observability 到 unverifiable outcomes），指出它们压缩了预先可固定的选择空间，并减少了纠错余地。

## 问题动机
多模态 agent（MMA）靠 reasoning、memory、tools 与 feedback 维持交互，最显眼的形式是 computer-use agent；机器人系统（RS）则把 sensing 与 actuation 耦合在物理动力学下。两者长期分属不同社区、缺少共同语言。论文提出的核心问题是：**当一个多模态 agent 从 computer-use 转向 robot-use 时，究竟什么发生了变化？** 缺少一个以功能（function）而非架构（architecture）为锚点的统一视角，就无法解释哪些能力是共有的、哪些是物理环境额外强加的，也无法解释现有评测体系究竟测了什么、漏了什么。

## 方法
这是一篇**视角/框架 + 评测横断面分析**型工作，而非提出新模型。

- **MMEA 定义**：goal-directed systems that couple multimodal task reasoning with physical action and revise decisions from the resulting feedback。
- **PAPAV 五能力函数**（按功能而非架构切分）：
  1. **Perceive** — 感知当前状态
  2. **Anticipate** — 预判动作效果
  3. **Plan** — 规划可行路径
  4. **Act** — 通过界面或身体执行
  5. **Verify** — 校验结果
- **三方对比**：用同一套能力坐标系比较 MMEA / MMA / RS，识别共有能力与差异。
- **5 条物理约束**：论文指明其范围"from partial observability to unverifiable outcomes"，其后果是**更少的选择可以被提前固定、更少余地去逆转错误**。
- **Benchmark 横断面**：横跨 64 个 benchmark 统计各能力被显式评测的次数。

## 实验设置与结果
- 数据/基准: **64 个 multimodal embodied agent 相关 benchmark**（清单见论文全文）。
- 对比方法: 不适用（这是对已有评测体系的覆盖度分析，而非模型性能比较）；横向对照对象为 MMA 与 RS 两类系统。
- 主要结果:
  - 显式评测**高度集中在 Act**；只有 **5 个** benchmark 评估 **Anticipate**，只有 **3 个**评估 **Verify**。
  - 因此 Anticipate 与 Verify 两项能力**很大程度上隐藏在 task success 之后**（largely hidden behind task success）未被独立度量。
  - 5 条物理约束同样被用来框定论文识别出的 open challenges。
  - 摘要未给出其他数值型结论。

## 关键技术细节
- 论文的核心贡献是可复用的**分析坐标系**：任何新系统都可按 PAPAV 五能力打标，从而使跨社区（VLM agent 社区 vs. 机器人社区）的比较成为可能。
- "以功能定义而非架构定义"是一个刻意的设计选择，目标是让同一框架能容纳完全不同的硬件与软件栈（屏幕+鼠标 vs. 机械臂+相机）。
- 64 个 benchmark 的统计揭示的是一个**评测生态问题**：社区把 task success 当作总指标，隐含假设了另外四项能力会自动成立——而物理约束恰恰说明这个假设不成立。

## 局限性
论文未在摘要中明确声明局限性。谨慎读者需注意：
- 这是**综述/立场型论文**，本身不提供新的可复现实验；其结论强度取决于 64 个 benchmark 的选取是否覆盖充分与无偏，选取口径可能带来系统性偏差。

- 统计出的 5 / 3 反映的是**评测设计的显式程度**，不等于相关能力的实际缺失程度——部分能力可能被内含在任务设定里而未被单独标注。
- 五能力划分是否正交、是否穷尽，框架层面仍可能存在争议（例如 Verify 与 Anticipate 的边界）。
