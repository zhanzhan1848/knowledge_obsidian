# ZeroRAG: Adaptive Semantic Peer Routing for Decentralized Retrieval-Augmented Generation

### 核心贡献
1. 提出 ZeroRAG：一个去中心化 RAG 路由层，在 peer overlay 上做语义查询路由，既不依赖全局数据结构，也不需要中心化编排。
2. 文档始终留在拥有它的 peer 上，每个 peer 只保留轻量本地状态：有界的邻居广告集合 + 最近路由查询的缓存。
3. 实证表明 ZeroRAG 在 recall 与所需网络消息数上优于两种去中心化基线，接近中心化文档存储的 recall 与 LLM 答案准确率，并能在 peer 灾难性故障后自愈、扩展到 100,000 个 peer。

### 技术方案
**核心思想**: 用「best-first walk」把每个查询沿覆盖网络逐步推进，边走边把 overlay 重连向语义更相关的邻居，使网络随查询自我组织、recall 随时间提升。

| 技术 | 说明 |
|------|------|
| 覆盖网络 | overlay of peers，无 global data structure、无 centralized orchestration |
| 文档归属 | 文档保留在 owning peer，不上交中心方（出于隐私 / 版权 / 合规） |
| 本地状态 | bounded set of neighbor advertisements + cache of recently routed queries |
| 路由算法 | best-first walk，逐步 rewires overlay 指向语义相关的邻居 |
| 自组织特性 | 网络在查询过程中自我组织，recall 随时间提升 |
| 鲁棒性 | peer 灾难性故障后自愈（self-heals） |
| 扩展性 | 可扩展至 100,000 peers |

### 实验结果
- **数据集**: 三个真实世界工作负载（three real-world workloads，摘要未列出具体名称）
- **基线**: 两种去中心化基线（摘要未具名，文中指出既有方法要么重新引入协调权威，要么依赖需全网持续协调的全局结构如 DHT）；并与中心化文档存储比较
- **结果**: ZeroRAG 在 recall 与所需网络消息数上优于两个去中心化基线，逼近中心化文档存储的 recall 与 LLM 答案准确率；支持 peer 故障后自愈；可扩展到 100,000 peers

### 局限性
- 摘要未给出具体 recall 百分比、消息数与答案准确率数字
- recall 依赖查询分布的持续覆盖；「随时间提升」意味着冷启动阶段表现较弱，摘要未说明冷启动指标
- best-first walk 的路由质量依赖邻居广告的语义覆盖度，有限的有界邻居集合可能限制可达性

### 关键洞见
> 关键在于把「检索索引」从全局状态改写为**拓扑状态**：既然不想建 DHT 这样的全局结构，那就让 peer 的邻居关系本身成为可路由的语义索引——每次 best-first 查询都在重塑 overlay，于是 recall 不再是固定属性，而是网络被使用次数的函数。
