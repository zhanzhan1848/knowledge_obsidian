# Robust LLM-Generated Text Detection through Matched Conditional-Response Probing

## 摘要
可靠的 LLM 生成文本检测必须在保义修订（重写、润色、扩写）下依然有效。实践中 LLM 输出常在发布前被重写、润色、扩写、翻译或轻度编辑，削弱了现有检测器依赖的词汇、句法与局部话语线索。本文提出 MCRP（Matched Conditional-Response Probing），一个冻结 LLM 的探针框架，测量候选文本在语义匹配条件被引入、移除或替换时的响应变化。对每个候选，冻结的 probe LLM 先生成一个简短语义条件，再在 matched、null、control 三种条件下比较 token 级 loss 与 prompt–target attention 度量；把双向条件对齐、反事实敏感性与内部注意力耦合聚合为探针表征，在其上训练轻量监督随机森林分类器，同时保持 probe LLM 冻结。在标准检测、保义修订鲁棒性、多语与多域评测上 MCRP 表现一致强劲：在重写、润色、扩写下取得 93.97% F1 与 96.24% ROC-AUC，分别超过最强基线 19.50 与 25.77 个百分点。组件消融显示三组响应特征互补；条件对照实验显示 matched 条件一致优于 random、mismatched 与 corrupted 备选，证明语义匹配带来可测量的增量收益。

## 核心贡献
1. **新经验发现**：虽然保义修订会削弱静态 artifact，但人类文本与 LLM 文本在"候选匹配的语义条件"下仍保留可区分的响应轮廓。
2. **MCRP 框架**：用同一个冻结 LLM 同时承担 sample-adaptive 的条件构造与 matched-vs-null 探针，整合双向对齐、反事实敏感性与 prompt–target 注意力耦合。
3. **全面实证验证**：覆盖 clean、revised、multilingual、multidomain，含 OOD 迁移、条件对照、组件消融、frozen-probe 对比与效率分析。

## 方法与架构
**问题定义**：候选文本 $x=(x_1,\dots,x_n)$，标签 $y\in\{0,1\}$（0 为人写、1 为 LLM 生成）；$f_\theta$ 为冻结的 decoder-only LM。

**条件构造（同一冻结模型）**：
```math
c = g_\theta(x; p_{title}) := \mathrm{Decode}_{f_\theta}\left[p_{title}, x\right]
```
$g_\theta$ 是 $f_\theta$ 在 prompt 下的解码过程，而非独立可训练的条件生成器；过程只用 $x$，**不接触标签、来源生成器或数据集元信息**。实际 prompt 为 "Write a title for this text: {sample} / Just output the title:"。

**两个上下文路径**：
```math
q_c = \mathrm{Prompt}(d(c), x),\qquad q_{\emptyset} = \mathrm{Prompt}(d(\emptyset), x)
```
matched prompt 为 "Given the title: {c} / Complete the following text:"，null prompt 只保留 "Complete the following text:"。两条路径用同一模型与同一候选文本，唯一差别是是否提供候选派生的条件 $c$。响应对比定义为：
```math
\Delta R_\theta(x,c) = R_\theta(x,c) - R_\theta(x,\emptyset)
```
**三种对照条件**：random（无关随机词序列）、mismatched（为另一个样本生成的有效条件）、corrupted（扰动 matched 条件以降低其与 $x$ 的语义一致性）。所有对照保持 prompt 模板固定。

**特征一：双向条件对齐**。前向 token loss：
```math
\ell^{\rightarrow}_i(x\mid r) = -\log p_\theta(x_i \mid d(r), x_{<i}),\quad i=1,\dots,n
```
保留 matched 前向对齐序列 $a^{\rightarrow}(x,c)=(-\ell^{\rightarrow}_i(x\mid c))_{i=1}^n$；null 路径的 loss 用于计算反事实敏感性。后向对齐用候选重建条件 $c=(c_1,\dots,c_m)$：
```math
\ell^{\leftarrow}_j(c\mid x) = -\log p_\theta(c_j \mid x, c_{<j}),\qquad a^{\leftarrow}(x,c) = (-\ell^{\leftarrow}_j(c\mid x))_{j=1}^m
```
因 $a^{\leftarrow}$ 按条件 token 索引，用全局统计概括：
```math
\rho(u) = [\mu(u), \max(u), \min(u), \sigma(u)]
```
高 alignment 值表示条件可预测性强，**并不意味 $c$ 就是原始生成 prompt**。

**特征二：反事实敏感性**。有些文本即使没有语义条件也可预测，故测量 matched 条件带来的 token 级 loss 削减：
```math
S_i(x,c) = \ell^{\rightarrow}_i(x\mid\emptyset) - \ell^{\rightarrow}_i(x\mid c),\qquad S(x,c) = (S_i)_{i=1}^n
```
正值越大表示 matched 条件对目标 token loss 的削减越强。作者强调这是**经验性的响应对比，而非因果生成机制的证据**。

**特征三：prompt–target intra-attention coupling**。设 $C$、$T$ 分别为条件 token 与目标 token 位置集合，$A^{(\ell,h)}\in\mathbb{R}^{N\times N}$ 为第 $\ell$ 层第 $h$ 头的自注意力矩阵：
```math
C_i^{(\ell,h)}(x,c) = \frac{1}{|C|}\sum_{j\in C} A^{(\ell,h)}_{ij},\qquad
C_i(x,c) = \frac{1}{LH}\sum_{\ell=1}^{L}\sum_{h=1}^{H} C_i^{(\ell,h)}(x,c)
```
该序列刻画冻结模型在预测候选不同部分时对条件的关注强度，**仅作为内部依赖性的代理**。

**统一探针表征与分类器**：把目标位置划分为 $K$ 个连续不重叠段 $T_1,\dots,T_K$，段级统计
```math
\phi_k(u) = [\mu_k(u), \max_k(u), \min_k(u), \sigma_k(u)]
```
```math
z_k = [\phi_k(a^{\rightarrow}), \phi_k(S), \phi_k(C)],\qquad z = [z_1;\dots;z_K; \rho(a^{\leftarrow})] \in \mathbb{R}^{12K+4}
```
用 100 棵树的随机森林 $h$ 预测 $\hat{y}=h(z)$；**probe 参数 $\theta$ 全程冻结**，只拟合 $h$。

## 实验设置
- **Benchmark**：Guo et al. (2025)（5 种文本类型 × 5 个生成器：GPT-3.5-Turbo、GPT-4-Turbo-Preview、Claude-3-Opus/Sonnet、Gemini-1.0-Pro）；Zhou et al. (2026)（对 GPT-4o、Gemini-2.5-Flash、Claude-3.5-Haiku 在 XSum、Writing、SQuAD 上做重写/润色/扩写）；multidomain（Hao et al. 2025，3 个生成器 × 21 个领域）；M4（Wang et al. 2024a，中文、俄语、阿拉伯语、乌尔都语、保加利亚语）。
- **指标**：F1 与 ROC-AUC。
- **基线**：Fast-DetectGPT、AdaDetectGPT、Binoculars、RADAR、ImBD、DNA-DetectLLM。
- **实现**：Intel Xeon Gold 6130 CPU、4× NVIDIA Tesla V100 32-GB、128 GB 内存。默认 probe 模型为 **Phi-3.5-mini-3.8B**，同时充当条件生成器与冻结 probe；只训练 100 棵树的随机森林；in-domain 实验用五折交叉验证。
- **消融**：组件移除（sensitivity / coupling）、null-condition 变体（仅双向 / 仅后向 / 仅前向对齐）、条件对照（random / mismatched / corrupted）、frozen probe 对比（Llama-2-7B、Gemma-3-9B、Qwen3-8B、Llama-3-8B、Falcon-7B、Phi-3.5-mini-3.8B）。

## 局限性
作者自述：MCRP 仍受限于**条件质量**与**多次 probe 带来的延迟**；其 conditional-response 轮廓**不能证明真实的生成过程**，也不能替代直接的 provenance（溯源）。未来工作包括更鲁棒的条件构造、计算复用与语言/领域漂移下的校准。多语结果虽强，但**未证明语言不变性**；跨域时法律文本仍困难；ROC-AUC 优势比 F1 优势更稳定，说明**阈值校准在生成器/领域漂移下仍然重要**。

我的补充批判：① 判别信号是否只是"LLM 文本更像某个紧凑指令的展开"这一先验的可测量代理，而非真正的条件依赖，论文的 condition control 实验支持后者但差距仅 3.2–3.8 F1，且作者自己也承认"generic predictability 与 alignment cues 也贡献不少"；② 每次检测需 2.92 秒、构造标题需一次生成、matched/null/control 需多次前向，在真实内容审核流水线中吞吐受限，作者只提出未实现优化；③ 训练了监督分类器（随机森林），因此并非零样本；论文把它与零样本基线并列比较，但监督信号来源与"无训练标签"的对比不完全公平（作者用 source-group-disjoint split 与五折交叉验证缓解，但未与 ImBD 的监督训练方式对齐讨论）；④ Code 类仍是最弱项（85.13 F1），说明代码的"紧凑 topic 规格"假设更不成立；⑤ 全部结果基于 V100 + Phi-3.5-mini，未验证更大 probe 或更新 generator。

## 评估与建议
- 是否推荐深入阅读：**是**。它提出了一个与传统静态 detector 正交、且在保义修订这一真实场景下增益巨大的思路（20 个百分点的 F1 提升）。
- 适用场景：学术出版/内容平台的 AI 生成内容审核、综述与投稿系统、翻译与润色流水线后的溯源、多语内容治理、模型评测中的"机器文本 vs 人写文本"判别。
- 与知识库的关联：与 DetectGPT / Fast-DetectGPT / Binoculars / DNA-GPT / DNA-DetectLLM（零样本与过程式检测）、RADAR / ImBD / AIDER（鲁棒与风格对齐检测）、MAGE / RAID / M4 / M4GT-bench（评测基准）、MGTBench 与 AI 文本检测综述形成完整谱系；也可与"文本 provenance 与水印"（Kirchenbauer 等）对照阅读。
