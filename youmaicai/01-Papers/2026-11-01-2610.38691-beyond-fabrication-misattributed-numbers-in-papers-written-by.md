## 核心贡献

> AI 研究 agent 论文的失败以「归因错误」而非捏造为主，确定性的 claim-to-evidence 检查器以 90%+ 精确率识别之。

1. 重新分析一个公开 AI 研究 agent 基准的全部 540 条判定，并人工标注 18 份投稿中的 256 条数值声明，发现失败模式以「论文与底层工作之间的错配」为主，而非显式造假。
2. 提出确定性的 claim-to-evidence 检查器：规则在标注前冻结，对盲标标注者达到 90%+ 精确率（78/85，Cohen's κ = 0.89），且能对每条声明用数值诱饵做校准。
3. 发现 LLM 验证器虽能找回更多可追溯声明，但会多接受约三倍的错配声明 —— 两者应配合使用，由此主张「provenance-first（溯源优先）」的 AI 研究审计范式。

---

## 技术方案

### 核心思想

AI 研究 agent 写的论文是否可信？这篇论文把「AI 写论文会不会造假」这个问题重新定义了。既有基准虽然能给出「通过/不通过」的判定，但这些判定通常来自单一 LLM judge，只能指出失败而无法说明失败的性质；已有检查要么测论文的内部一致性，要么测某个数值是否出现在 agent 的输出里——都不直接对应「论文中这个数字的出处对不对」。

作者手工标注后发现一个关键事实：**约五分之四的「无支撑声明」其实对应 agent 自己文件里真实存在的数值，只是来自错误的实验、错误的指标或错误的运行**。也就是说，这既不是凭空捏造，也不是恶意作弊，而是**归因错误（misattribution）**。这个区分很重要——归因错误可以用流程与工具来修，作弊则需要不同的治理手段。

为此作者设计了确定性的 claim-to-evidence 检查器：它判断的是「声明周围的上下文是否足以确定地标识出被声明的结果」，并对每条声明用**数值诱饵（numerical decoys）**做校准，以排除数值偶然命中的可能。规则在标注之前就冻结，保证不是事后拟合。

论文还给出了重要的操作结论：LLM 验证器能找回更多可追溯的声明，但接受错配声明的数量约为确定性检查器的三倍。因此**确定性检查器做高精度拦截、LLM 验证器做高召回补充**是更合理的分工。

### 关键技术

| 技术 | 说明 |
|------|------|
| Claim-to-evidence 确定性检查器 | 规则先验冻结；判定上下文是否标识出被声明结果；用数值诱饵做逐条校准 |
| 540 条判定全量重分析 | 覆盖 9 个 agent × 15 个开放研究问题，人工标注 256 条数值声明 |
| 错配语义分类 | 区分 fabrication（捏造）、misattribution（取自 agent 自有文件但实验/指标/运行错误）与可追溯声明 |
| 多厂商 judge 对照 | 第二个来自不同供应商的 judge 保持官方 agent 排名，但让两倍的论文通过 |
| 溯源优先审计范式 | 主张先建立数值—实验的 provenance 链，再谈内容质量 |

## 实验结论

- **数据集**: 公开 AI 研究 agent 基准（9 agents / 15 开放研究问题）的 540 条判定，18 份投稿 256 条数值声明，扩展到 99 份投稿
- **基线**: 单 LLM judge 判定、已有内部一致性检查、仅检测数值是否出现在 agent 输出中的检查、确定性 claim-to-evidence 检查器
- **结果**: 确定性检查器对盲标标注者达到 78/85 一致（Cohen's κ = 0.89，精确率 >90%）；LLM 验证器多接受约 3 倍的错配声明；应用到 99 份投稿时揭示了不同 agent 之间巨大的可追溯性差异；换用不同厂商的第二 judge 保持官方排名但通过率翻倍。

- **最具实践价值的数字**：LLM 验证器会多接受约 **3 倍** 的错配声明 —— 单靠 LLM judge 做完整性审计并不可靠。
- 约 **4/5** 的无支撑声明实际来自 agent 自己文件中的数值（错误实验/指标/运行），属于可工程化修复的归因错误。
- 确定性检查器在「无法验证」时输出的是「不可追溯」而非「为假」——作者强调**验证失败不等于造假**，这一点在审计中极易被误用。
- 99 份投稿的横向比较显示 agent 之间的可追溯性差异巨大，官方排名在不同 judge 组合下会变。

## 局限性

['结论基于特定公开基准的 agent 集合与任务类型，对闭源工业系统的适用性未知。', '确定性检查器只能验证可追溯的子集，无法覆盖全部声明。', '对「捏造 vs 归因错误」的边界判定依赖人工标注，存在主观性。', '论文提出的是审计方法论，未提出对 agent 训练过程的改进。']

## 实现建议

- **实现难度**: 中（需要 agent 运行日志、文件快照与论文三方对齐的审计基础设施）
- **适用场景**: AI 辅助科研的质量控制、agent 评测基准建设、论文自动化审查、合规与溯源
- **建议**: 审计 AI 产出的论文时，把「数值能否溯源到具体实验运行」作为第一道关，而不是先看内容质量。可直接借鉴其确定性检查器思路：规则先冻结、数值诱饵校准、并且明确区分「不可验证」与「为假」。

## 原始摘要

```
Verifying numerical claims in research written by AI agents is an important but challenging problem. Recent benchmarks show that many agent-written papers fail integrity checks, but such verdicts, often produced by a single LLM judge, identify failure without explaining its nature, and existing checks either test a paper for internal consistency or test whether a reported value appears somewhere in an agent's output. We re-analyze all 540 released judgments from a recent public benchmark of AI research agents (nine agents, fifteen open research problems) and manually label 256 numerical claims from 18 submissions. Failures concentrate on alignment between the paper and the underlying work rather than overt cheating, and about four in five unsupported claims correspond to values in the agent's own files that come from the wrong experiment, metric, or run. We introduce a deterministic claim-to-evidence checker that scores whether the surrounding context identifies the claimed result and calibrates each claim against numerical decoys. With its rules fixed before labeling, it certifies claims with over 90% precision against blinded annotators (78 of 85; Cohen's kappa = 0.89), while verifying only a subset of claims; most claims it cannot verify are nevertheless traceable, so failure to verify is not evidence of falsehood. An LLM verifier given the same evidence recovers more traceable claims but accepts about three times as many misattributed ones, so the two are best used together. Applied to 99 submissions, the checker reveals large differences in traceability across agents, and a second judge from a different vendor preserves the official agent ranking while passing twice as many papers. These findings motivate provenance-first auditing of AI-produced research.
```
