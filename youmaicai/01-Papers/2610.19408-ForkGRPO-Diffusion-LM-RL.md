## 核心贡献

1. **dLLM any-order 生成 entropy 退化** 的解决方案
2. **ForkGRPO**：在 high-entropy intermediate state 沿 reference trajectory fork 多条 continuation（textual boundary 优先 + 共享 prefix）
3. **两类 fine-grained credit signal**：
   - Within-state **group-relative advantage** → reinforce 哪条 continuation
   - **MC state-value differences** → 哪个 reasoning segment 改善 expected outcome

## 方法

### 核心 insight

dLLM any-order generation → entropy 退化 → 探索路径收窄；GRPO + L2R 仍 under-explore 中间态分支；trajectory-level advantage 对所有 token 一视同仁。

### ForkGRPO algorithm

```python
# 1. Sample reference trajectory
ref_traj = dLLM.generate(prompt)
# 2. Identify high-entropy intermediate states
high_entropy_states = detect_high_entropy(ref_traj)
# 3. For each state, fork multiple continuations
for state in high_entropy_states:
    continuations = sample_continuations(
        state, n_forks, prefer_textual_boundary
    )
    # 4. Two credit signals
    within_state_advantage = group_relative(continuations)
    mc_state_value = MC_difference(state, continuations)
# 5. Update policy
policy.update(within_state_advantage, mc_state_value)
```

### ForkGRPO-Fast

- 2.49× wall-clock speedup
- Negligible accuracy loss

## 实验结果

- 4 benchmarks 中 **3 个 SOTA**（vs architecture-preserving RL methods）
- vs 直接对照 JustGRPO：**+1.2pp**
- Token usage：**-27.8%**

| Variant | Speedup | Accuracy Loss |
|---------|---------|---------------|
| ForkGRPO | 1× | baseline |
| ForkGRPO-Fast | **2.49×** | negligible |

## 局限性

- 仅适用于 dLLM（不适用于自回归 LLM）
- 需要 textual boundary detection（增加 preprocessing）
- MC state-value estimation 增加 compute
- High-entropy state 检测可能引入 noise

## 建议

- **是否推荐使用**：是
- **适用场景**：dLLM reasoning / code RL 训练 / dLLM 架构的 LLM RL pipeline
- **运营价值**：token efficiency +27.8% + 速度 2.49× → 显著降低 dLLM RL 训练成本
- **配套**：与 dLLM architecture choice (LLaDA / SEDD / MDLM 等) 共同考虑
