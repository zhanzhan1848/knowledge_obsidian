## 核心要点
1. **ReTrace** 把 SOP 与少量已记录的 agent 运行变成**可复用的工作流**，其中**由代码而非 LLM 选择下一步**。
2. 关键洞察：**agent 的推理（它为每次工具调用写的解释）通常说明了为何采取该行动；而工具调用本身不说明**。
3. ReTrace 抽取每个步骤背后的条件，跨运行合并为紧凑的规则文档，并从中生成可执行工作流；**只有最后一步依赖平台**，因此规则文档可编译到不同编排平台。
4. **79 个生产流程**上：完成率 **93.8%**（对比 agent 的 96.8%），**每任务成本低 24%**。
5. **τ²-Bench** 上任务成功率 **75.8%**（agent 80.6%），但**耗时 1.3 秒 vs 170 秒**；三轮修复把 k=2 工作流从 66.7% 提到 81.2%。
6. SOP-Bench 八个流程上无修复时略逊于少样本生成（80.6% vs 83.6%），但从带标签的训练失败修复后达 **87.8%**，**每任务 0.40 秒**（对比 agent 的 85.5% / 46.6 秒）。

## 摘要（原文）
Business process automation runs the same Standard Operating Procedure (SOP) again and again on new
inputs. Large Language Model (LLM) agents can follow an SOP written in natural language, but they
call an LLM to choose every step of every run, which adds latency and cost at scale. We present
ReTrace, which turns an SOP and a few logged agent runs into a reusable workflow in which code, not
an LLM, selects the next step. The agent's reasoning, the explanation it writes with each tool call,
often states why it took an action; the tool calls alone do not. ReTrace extracts the condition
behind each step, merges these conditions across runs into a compact rule document, and generates an
executable workflow from it. Only this last stage depends on the platform, so rule documents can be
compiled for different orchestration platforms. On $79$ procedures from our production platform,
ReTrace workflows reach $93.8\%$ completion, against $96.8\%$ for the agent, at $24\%$ lower cost
per task. On $τ^2$-Bench, they reach $75.8\%$ task success (agent: $80.6\%$) and run in $1.3$s
instead of $170$s; three rounds of repair on training failures lift $k{=}2$ workflows from $66.7\%$
to $81.2\%$. On eight SOP-Bench procedures, ReTrace without repair trails few-shot generation
($80.6\%$ vs. $83.6\%$), but repair from labeled training failures lifts it to $87.8\%$ at $0.40$s
per task, compared to $85.5\%$ in $46.6$s for the agent.
