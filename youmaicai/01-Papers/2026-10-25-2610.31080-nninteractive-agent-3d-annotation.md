## 核心贡献

> 交互式 3D 分割模型（nnInteractive）能把少量空间提示变成准确的体积掩码，但**「找结构、放置提示、检查结果、纠正结果」这整段标注工作仍由人承担**。本文证明**通用 AI agent 无需额外训练即可接管这部分工作**：用户用自然语言提出请求，agent 自行判断要分割什么、定位目标、提示 nnInteractive、检查 3D 结果、纠正并响应反馈。

1. **提出「agent 作为 3D 标注员」的范式**：把 nnInteractive 通过 **Model Context Protocol（MCP）** 暴露为工具，并配套一个 **skill 编码「有经验的用户如何提示它」** —— agent 因此**无需训练**即可完成端到端标注。
2. **能力展示**：被要求「**咀嚼所用的肌肉**」时，agent 能识别并分割**咬肌（masseters）与翼肌（pterygoids）**；被要求**数肝脏病灶**时，agent **自己写代码**寻找候选并在被要求时**拆分一个融合的病灶**。
3. **定量 benchmark**：跨 **CT、MRI、PET 与 micro-CT**，涵盖**人、小鼠、蚂蚁**（**14 张图像 / 51 个目标**，从器官与肿瘤到肌肉、足骨、血管树与昆虫脑）。
4. **主结果**：**Claude Code 与 Codex 仅凭一句请求**即达到平均 **Dice 0.81 与 0.84**；当被告知每个目标的位置时，两者均达 **0.85**，其提示效率**接近 oracle**（用参考分割来放提示）。
5. **对照与失败分析**：文本提示的 3D 模型 **VoxTell** 在多数标准放射学目标上**更准确**，但**鲁棒性更差** —— 它对一个目标**返回空掩码**，并在**腿部肌肉、足骨、小鼠与蚂蚁**上失败，而 agent 在这些情况下**保持准确**。

## 技术方案

### 核心思想

**人机分工的错位**：交互式 3D 分割已经解决「**给定提示 → 准确掩码**」，但真实标注工作的成本分布恰恰相反 —— 成本集中在**决定分割什么、在哪里点、如何发现错误**。这些恰恰是**通用 agent 的强项**（理解意图、调用工具、写代码、检查输出）。

**因此本文不做新模型，而是做「连接」**：把一个已验证的分割模型（nnInteractive）**以工具形式**暴露给 agent，让 agent 承担**标注工作流**，分割模型承担**像素级精度**。

**Agent 工作流（从自然语言到掩码）**：
```
用户请求（自然语言）
  → agent 推理：需要分割什么？（解剖学知识）
  → agent 定位目标（在 3D 体积中找结构，写代码 / 用工具）
  → agent 调用 nnInteractive：给点/涂鸦/框提示 → 掩码
  → agent 检查 3D 结果（正确性判断 / 可视化）
  → agent 纠正（追加/移动提示）
  → agent 响应用户反馈（如「把这个融合病灶拆开」）
```

**两个关键组件**：
- **MCP tool exposure** —— nnInteractive 以工具形式提供（标准协议，便于复用与集成）；
- **Prompting skill** —— 一个 skill，编码**「有经验的标注者如何给 nnInteractive 提示」**。这是把**隐性的人类操作知识**注入 agent 的关键，也是**无需训练**却能接近 oracle 效率的原因。

**为什么比 VoxTell 更好**：VoxTell 是**单一文本提示的端到端 3D 模型**，把「理解解剖语义」和「分割」耦合在一个网络里；agent 方案把**语义理解交给 LLM、把分割交给专用模型**，因此在**训练分布外的目标（肌肉、足骨、小鼠、昆虫）**上更稳健 —— 这是**系统级解耦**对抗**单模型泛化边界**的经典案例。

### 关键技术

| 技术 | 说明 |
|------|------|
| **MCP (Model Context Protocol)** | nnInteractive 以工具形式暴露的标准协议 |
| **Prompting skill** | 编码有经验用户的提示策略，作为 agent 的操作知识 |
| **nnInteractive** | 交互式 3D 分割模型，接受点/涂鸦/框提示 |
| **VoxTell** | 文本提示的端到端 3D 分割模型，对照基线 |
| **Agent-generated code** | agent 自行编写代码以寻找候选结构（如病灶计数） |
| **Iterative correction** | agent 检查 3D 结果并追加/调整提示 |
| **Oracle prompting baseline** | 用参考分割放提示的 oracle，作为提示效率上界 |
| **Micro-CT** | 包含蚂蚁等微观成像，检验极端域外鲁棒性 |
| **Mean Dice** | 主要量化指标 |
| **Multi-species benchmark** | 人 / 小鼠 / 蚂蚁三物种 |

## 关键结论

1. **「通用 agent + 专用模型」可以接管专业标注工作流，且无需训练。** 仅凭一句自然语言请求，Claude Code / Codex 达 **Dice 0.81 / 0.84**；被告知目标位置后 **0.85**，**接近 oracle 提示效率** —— 意味着**最贵的环节（人找结构、摆提示）被廉价地自动化了**。
2. **告知位置只带来 ~0.01–0.04 的 Dice 增益。** 这说明 agent **自己定位目标的能力已经接近 oracle 水平** —— 这是本文最强的单条结论：瓶颈已从「定位」转移到「分割模型本身的精度」。
3. **系统解耦带来域外鲁棒性。** VoxTell 在标准放射学目标上更准，但**一个空掩码 + 肌肉/足骨/小鼠/蚂蚁的全失败**，暴露了单一端到端模型的泛化边界；agent 方案因为**把语义与像素解耦**而在这些场景保持准确。
4. **「自己写代码找候选」展示了 agent 超越工具调用的能力层级。** 数肝脏病灶这类需要**检测、计数、拆分融合实例**的任务，agent 通过**自行编码**完成，而不是靠现成 API。
5. **MCP + skill 是「把人类隐性操作知识交给 agent」的可复用范式。** 本文的可迁移物不是 3D 分割，而是**「用 skill 编码专家提示策略、通过 MCP 暴露专用模型」的架构模板**。

## 局限性

- **规模很小**：**14 张图像 / 51 个目标** —— 不足以做统计显著性判断；**未报告置信区间或多次运行的方差**。
- **单一 benchmark、无外部验证集**：结果绑定于该自建 benchmark，**与其他 3D 标注/分割工作无直接可比数字**。
- **两个 agent 框架（Claude Code、Codex）** —— 均来自少数厂商；**未评估开源 agent** 的表现，结论对闭源模型的依赖未讨论。
- **VoxTell 的失败可能部分源于配置**（提示词、分辨率、后处理），**未排除实现细节导致的失败**，因此「解耦优于端到端」的结论**证据强度弱于措辞暗示**。
- **成本未报告**：agent 多次调用工具 + 写代码 + 检查 3D 结果，**每张图的推理时间与 token 成本未知**；而「快」正是交互式 3D 分割相对于人工标注的主要卖点。
- **「oracle 提示效率」的比较口径不明**：0.85 vs oracle 具体数值未给，差距无法量化。
- **Dice 之外的指标缺失**（HD95、表面距离等），以及**标注一致性/边界质量**未评估。
- **agent 的失败模式未系统分类** —— 与 SecLog / SIM-UT 那两篇相比，本文**没有对失败做分解**（如「找不到结构」vs「提示位置不准」vs「不会纠正」）。
- **未做「被告知位置」的随机化对照**（如随机位置基线），因此 0.81 → 0.85 的增益归因不完全干净。

## 实现建议

- **实现难度**：中（MCP server 包装 nnInteractive + 一个 prompting skill；agent 框架现成）
- **预期性能**：仅凭自然语言请求约 **Dice 0.81–0.84**；告知位置后 **0.85**；提示效率接近 oracle
- **适用场景**：**3D 医学图像标注**（CT/MRI/PET）、**显微成像**（micro-CT，含昆虫脑）、**域外目标的交互式分割**；可作为「**低成本预标注 + 人工审核**」流水线的第一阶段
- **团队行动**：把本文的**架构模板**（专用模型包成 MCP 工具 + 用 skill 编码专家提示策略）迁移到自己的领域模型（如 2D 分割、病理、遥感），这比直接训练端到端模型更可能拿到域外鲁棒性
