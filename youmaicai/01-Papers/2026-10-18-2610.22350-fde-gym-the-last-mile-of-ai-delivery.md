## 核心贡献

> 提出 **FDE-Gym** —— 第一个评估 agent 在**真实客户交付**（forward-deployed engineer 风格）场景表现的 benchmark：**95 end-to-end delivery tasks / 20 客户场景 / 18 行业**，每 task 由行业专家改编自真实交付项目。结果显示**信息获取 ≠ 任务解决**，bench / real-world agent 能力差距巨大。

1. **任务设计哲学**：ambiguous 需求、live systems、unstated constraints。
2. **可交互仿真**：模拟客户环境 + scripted stakeholders + modifiable customer systems。
3. **新评分指标**：按**客户 success metric 改善**归一化（0 = unchanged system, 1 = reference solution），penalty 含 messages / trial runs / waiting。
4. **Online platform**：人类可在相同 grading 标准下练习 FDE 技能。
5. **关键发现**：best configuration **0.56 mean score**，仅解决 14/95 task；发现 unstated constraints 是首要瓶颈；即便获得所有 key fact，仅 10/23 task 达 0.8+ uplift。

## 技术方案

### Benchmark 结构

| 维度 | 规模 |
|------|------|
| Tasks | 95 end-to-end delivery |
| 客户场景 | 20 |
| 行业 | 18 |
| 每任务 | industry expert 改编自真实项目 |

### 仿真环境

- **Customer environments**：模拟脚本化的 stakeholders（脚本化的客户行为）
- **Modifiable customer systems**：可被 agent 操作
- **Production-like systems**：贴近真实部署环境

### 评分

```math
\text{score} = \frac{\text{achieved uplift} - \text{baseline uplift}}{\text{reference uplift} - \text{baseline uplift}} \in [0, 1]
```

- **0** = 系统未改变
- **1** = 达到 reference solution 水平
- **Penalties**：messages 数量、trial runs 数量、waiting time

### 任务成功定义

- **score ≥ 0.8** + **no incident** = "resolved"
- best configuration 仅 14/95 task 达此标准

## 实验结果

### 评估规模

- **13 model configurations** × **7 providers**

### 关键结果

| Metric | Best Configuration |
|--------|-------------------|
| Mean FDE-Gym score | **0.56** |
| Resolved tasks (≥ 0.8) | **14 / 95** |
| Tasks where all key facts obtained | 23 |
| Of those reaching 0.8+ uplift | 10 / 23 |

### 核心瓶颈分析

1. **Unstated constraints discovery = 首要瓶颈**
   - 必须由 agent 主动发现（非 explicit guidance）
   - performance 在该条件下**急剧下降**

2. **信息获取 ≠ 任务解决**
   - 即使获得所有 key fact，仍有 13/23 tasks 卡在 0.8 以下
   - → **integrate / execute / navigate** 能力是次瓶颈

### "Realistic" vs "Well-specified"

| Task 类型 | Best 模型表现 |
|----------|------------|
| Well-specified (issue report / ticket) | 显著更好 |
| Realistic FDE (ambiguous + live + unstated) | 显著更差 |

---

## 局限与展望

- 仅 95 task → 多样性有限。
- Scripted stakeholders 可能不完全反映真实客户的非线性 / 情绪化行为。
- 18 行业集中在 enterprise / B2B，consumer / 创意行业少。
- 评分"reference solution" 由 expert 提供 → reference 本身可能 sub-optimal。
- 实验仅 13 配置 → frontier reasoning model (o3 / Claude 4.5 / Gemini 3) 全覆盖未做。

## 实现建议

- **实现难度**: 极高（需要仿真 infra + scripted stakeholders + customer system API）
- **适用场景**:
  - **评测** enterprise agent / FDE 助手真实能力
  - 训练 **discovering unstated constraints** 这一 specific 能力
  - 评估 customer-facing LLM 的 discovery + integration 综合能力
- **不适用**: short-horizon / single-tool 任务（over-bench）
- **关键启示**: agent benchmark 应**包含 ambiguity + discovery**，否则"高分"幻觉

---

## 一句话总结

FDE-Gym 用 95 个真实改编的 delivery 任务揭示：current SOTA agent 在 well-specified task 上有进步，但在 "发现 unstated constraints" 这一真实部署关键能力上**几乎零进展**；且**信息获取 ≠ 任务解决**。
