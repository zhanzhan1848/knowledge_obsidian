## 核心贡献

> 通过真实科学工具 (PHREEQC, USGS 地球化学模拟器) 系统化揭示：Agent harness 将长工具输出"取出 context、按需检索"的常见做法会显著降低 GPT-5 系列准确率，根因是 **evidence substitution** 现象 —— 即 agent 跳过检索报告，改用自己的高精度输出文件并错误舍入到邻近选项。

1. **真实工具评测**：使用 846.8k 字符的 PHREEQC 报告与 158 道可执行验证的多选题
2. **量化检索代价**：GPT-5.1 损失 11.3 分，GPT-5.2 损失 7.9 分；Claude Opus/Sonnet 4.6 无明显代价
3. **失败命名：Evidence Substitution**：Agent 倾向于跳过权威报告，转用自己的高精输出并错误舍入
4. **缓解策略**：显式命名"权威输出"可将 accuracy 提升 6.3-7.9 分；GPT-5.1/5.2 上 inline 输出同样有效，但要求正确舍入无效
5. **方法论启示**：评估 agent harness 应关注**精度损失在哪发生**，而非仅看最终精度

## 技术方案

### 核心思想

当工具输出过长时，agent harness 倾向将输出写入文件并按需检索。这种"省 context"的策略可能看似无害，实则在某些模型（如 GPT-5 系列）上造成显著精度下降。作者通过"固定 simulation、变化 retrieval 方式"的控制变量实验定位精度损失源头。

### 关键技术

| 技术 | 说明 |
|------|------|
| PHREEQC Benchmark | 158 道 execution-verified 多选题 + 11,007 条 simulator 调用日志 |
| Section Index Retrieval | 让 agent 通过 section index 而非全文 context 检索报告 |
| Evidence Substitution Analysis | 追踪 agent 是否真的读取了权威输出 |
| Authoritative Output Naming | 在 prompt 中显式标注哪个文件是权威输出 |

### 关键公式

```math
\Delta_{\text{acc}} = \text{Acc}_{\text{full-context}} - \text{Acc}_{\text{retrieval}}
```

| Model | $\Delta_{\text{acc}}$ |
|------|---------------------|
| GPT-5.1 | **-11.3** |
| GPT-5.2 | **-7.9** |
| Claude Opus 4.6 | ≈ 0 (无明显) |
| Claude Sonnet 4.6 | ≈ 0 (无明显) |

GPT-5.4 上 simulation 更准但 evidence-use 损失 ~10 分，净变化不显著。

---

## 实验结论

### 主要发现

- **GPT-5.1/5.2 在 retrieval 下显著退化**：根因不是算错，而是**用错了 evidence**
- **Claude Opus/Sonnet 4.6 鲁棒**：检索与否几乎不影响 accuracy
- **GPT-5.4 simulation 准确掩盖了 evidence 问题**：净精度近似不变，但内部分项发生 ~10 分 evidence-use 损失

### 缓解方案

- **Naming authoritative output**: 提 6.3-7.9 分（三个 GPT 模型通用）
- **Inlining outputs (GPT-5.1/5.2)**: 等效有效
- **Asking for correct rounding**: 无效

---

## 局限性

- 仅在 PHREEQC（地球化学）单一工具上验证
- 仅测试 GPT-5 系列与 Claude Opus/Sonnet 4.6，其他模型行为未涵盖
- 158 题的 benchmark 规模相对小

## 实现建议

- **实现难度**: 低 (在 prompt 层显式命名权威输出即可见效)
- **预期性能**: 简单 prompt 改动即可挽救 6-8 分 accuracy
- **适用场景**: 任何使用 GPT-5 系列 + 长工具输出的 agent 部署
- **建议**: 评估 agent 时同时跟踪 evidence-use，避免"看起来变好"的伪改进
