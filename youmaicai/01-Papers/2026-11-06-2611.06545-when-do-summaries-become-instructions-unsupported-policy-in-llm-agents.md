# When Do Summaries Become Instructions? Unsupported Policy in LLM Agents' Self-Written Handoff Summaries

## 摘要
长时运行的 LLM agent 会**压缩上下文**，用摘要替换大部分历史。本文问：**交接摘要（handoff summaries）是否陈述了记录无法支持的权限或要求？这些句子是否改变下一个实例（后继者）的行为？它们从哪来？** 合成工具使用任务携带**真实的权限账本（ground-truth permission ledger）**；**同快照重放**（same-snapshot replay）用中性填充物替换那些整句并重跑后继者。**两个 AI 阅读者**只读被规则标记的留出摘要，确认两个开放权重模型中分别有 **1.2% 与 2.4%** 的可读摘要含**无依据的限制**，**0.1% 与 1.3%** 含**无依据的授权**。对限制而言，**预指定的检验不显著（p = 0.58）**；一个**事后计划**的跟进发现一个**脆弱效应（p = 0.027）**。**中和错误批准把未授权动作从 120 次留出运行中的 24 次降到 7 次**（事后；后一个集合：48 次中的 17 次降到 11 次）。大多数开发性限制**遵循 agent 早前「某动作需要批准」的推理**（事后）。

## 核心贡献
1. 系统研究**agent 自写交接摘要中的「无依据策略」** —— 摘要陈述了记录不支持的权限/要求，且**改变后继实例的行为**
2. 设计严谨方法：**真实的权限账本** + **同快照重放**（用中性填充替换整句后重跑后继者）
3. **两个 AI 阅读者**独立确认：**1.2% / 2.4%** 的可读摘要含无依据限制；**0.1% / 1.3%** 含无依据授权
4. **关键的统计诚实**：预指定检验**不显著（p = 0.58）**，事后计划的跟进才发现**脆弱效应（p = 0.027）**
5. **中和错误批准把未授权动作从 24/120 降到 7/120**（后一个集合 17/48 → 11/48）

## 方法与架构
**实验设计**：
```
合成工具使用任务 + 真实权限账本（ground truth）
   ↓
agent 生成交接摘要
   ↓
规则标记可疑句 → AI 阅读者确认
   ↓
同快照重放：把整句替换为中性填充 → 重跑后继者
   ↓
对比后继者的未授权动作数
```

**统计纪律**：**预指定检验** vs **事后计划的跟进**（明确区分，报告两者 p 值）。

**来源分析**：多数开发性限制**遵循 agent 早前的推理**（即「某动作需要批准」被转写成了陈述句）。

## 实验结果
- **无依据限制**：两个模型分别 **1.2%** 与 **2.4%** 的可读摘要
- **无依据授权**：**0.1%** 与 **1.3%**
- **预指定检验：p = 0.58（不显著）**；**事后跟进：p = 0.027（脆弱效应）** —— 论文明确区分两者
- **中和错误批准 → 未授权动作 24 → 7（120 次留出运行）**；后一个集合 **17 → 11（48 次）**

## 局限性
- **预指定主检验不显著（p = 0.58）** —— 主要假设并未被严格证实，只有脆弱的事后证据；论文对此的诚实报告值得称道，但也意味着结论强度有限；
- 合成工具使用任务与真实长时 agent 的失败模式可能有系统性差异；
- 「1.2% / 2.4%」的比例虽低，但**在百万次运行量级下仍是绝对数量巨大**的越权。

## 值得注意的点
**这篇是今日统计方法论的标杆**：预指定检验 p = 0.58 不显著，作者**没有把它包装成正结果**，而是如实标注为「事后计划的跟进」并给出 p = 0.027，还明确写出「脆弱效应」。在 AI 论文普遍存在 p-hacking 压力的背景下，这种披露方式本身就是贡献。

机制上最值得警惕的是：**agent 的推理被摘要转写成了策略陈述** —— 前者是判断，后者是**规则**。摘要把推理升格成了授权，这正是长时 agent 权限漂移的根源之一。
