## 核心贡献

> 解码阶段的 LLM 推理是 memory-bound；现有 Hessian-guided pruning 用**预收集的自然文本**做 calibration 与解码阶段的**自生成 token 分布**不一致，造成性能退化。SparseDecoding 用**自回归生成的激活**做 calibration，匹配 N:M SpMV kernel，A100 上 up to **1.48× wall-clock 解码加速**。

1. 识别关键问题：**prefill 阶段的 Hessian calibration 与 decoding 阶段的实际激活分布**之间存在显著偏移。
2. 算法侧：用**密集模型自回归生成过程中的激活**构建 calibration 矩阵（排除 prefill），让 pruning 目标与 decoding 对齐。
3. 系统侧：定制 **N:M sparse matrix-vector kernel**（bitmask indexing + fixed-step traversal），直接加速 memory-bound 的 SpMV。
5. 实验在 **Llama-3.1-8B / Llama-3.3-70B / Qwen3-14B/32B** 上 consistently 优于标准 fixed-text calibration；**A100 up to 1.48× end-to-end decoding speedup**。

---

## 技术方案

### 核心思想

现有 N:M 剪枝方法（Hessian-guided）在 calibration 阶段使用"自然文本"（如 WikiText）计算 Hessian，但 LLM decoding 时实际输入是**自生成的 token**（与自然文本分布不同）。这一分布偏移让 calibration 失真，激活分布偏差进一步损害 pruning 后模型性能。SparseDecoding 修复两点：(1) 用**自回归生成的激活**做 calibration；(2) 把 kernel 真正加速到 SpMV（而非仅 SpMM）。

### 关键技术

| 技术 | 说明 |
|------|------|
| Decoding-aware calibration | 用密集模型自回归生成（不含 prefill）逐层收集激活，构建 Hessian |
| Distribution shift fix | 让 calibration 分布 ≈ 实际 decoding 分布，消除 pruner 失真 |
| N:M sparse matrix-vector kernel | 定制 bitmask indexing + fixed-step traversal 的 SpMV kernel |
| SpMV vs SpMM 优化目标 | decoding 是 SpMV-dominant，传统方法只优化 SpMM |
| 端到端 wall-clock speedup | 在 A100 上实测 1.48× decoding 加速 |

### SpMV vs SpMM 的关键差异

| Op | 出现阶段 | Memory-bound? | 现有 N:M 工作覆盖？ |
|----|---------|---------------|------------------|
| SpMM (prefill) | 一次性处理 prompt | 计算密集 | 是（主要目标） |
| **SpMV (decoding)** | **每 token 一次** | **memory-bound** | **否（覆盖不足）** |

---

## 实验结果

- **Llama-3.1-8B / Llama-3.3-70B / Qwen3-14B / Qwen3-32B** 一致优于 fixed-text calibration
- **A100**：up to **1.48× end-to-end decoding speedup**
- 长文本生成 benchmark 上 perplexity 退化明显减小

---

## 关键 takeaway

- **Calibration 分布必须与部署分布匹配**：这是剪枝 / 量化类方法的隐形失败源。
- **SpMV 而非 SpMM** 才是 LLM decoding 的真正优化目标，但被现有 N:M 工作忽视。
- 算法侧（calibration 修正）+ 系统侧（kernel 优化）必须协同才能拿到端到端加速。

---

## 局限性

- N:M 模式主要是 2:4（GPU 友好），更高比例（如 4:8）需要新硬件支持
- 仅在 A100 测试，H100 / B100 等新一代 GPU 的 kernel 设计可能不同
- 校准数据用密集模型自回归生成，引入密集模型推理成本（一次性）
