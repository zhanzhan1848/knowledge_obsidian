# Two Birds with One Stone: Skill-Augmented Generation via Unified Retrieval and Utilization

## 摘要
Skills 作为可复用的外部知识，在提升 LLM 解决复杂任务的能力上展现出巨大潜力。然而现有的 skill-augmented generation 方法通常依赖**分离的模型**分别做 skill retrieval 与 skill utilization，导致这两个过程被割裂优化。本文提出 **Skill-Uni**——一个统一强化学习框架，联合优化 skill 检索与利用。具体而言，作者采用**生成式 skill 检索**范式，使单一模型既能学会如何检索相关 skill，又能利用它们解决任务。为有效训练这一统一框架，作者提出两阶段训练策略：**warm-up instruction tuning** + **GRPO**，使模型渐进地提升其 skill 检索与利用能力。在五个 skill 相关 benchmark 上的大量实验表明 Skill-Uni 的有效性：相对 base Qwen3-4B 与 LLaMA3.1-8B 分别取得平均 **66.59%** 与 **34.82%** 的性能提升。此外，Skill-Uni 与多种 skill 检索引擎兼容，展现出灵活性与泛化性。

## 核心贡献
1. **Skill-Uni 统一框架**：不同于把检索与下游推理视为独立阶段的 retrieve-then-utilize 流水线，Skill-Uni 把 skill 检索形式化为**生成过程**，把"是否检索 / 检索什么 / 如何利用"统一在单条任务轨迹中。
2. **有效训练配方**：warm-up instruction tuning + 强化学习，让模型先习得交互模式再联合提升检索与利用；并引入 **token masking** 把外部检索到的 skill 内容排除出优化目标，使学习聚焦于模型自身生成的检索与推理行为。
3. **能力感知的数据构造**：先测学生模型能否在无外部 skill 条件下解对；对解不对的题才让 teacher 生成 `<rec>` 检索请求，对已能解对的题则让 teacher 直接给 `<answer>`。
4. **全面实验**：五个 skill 相关 benchmark + 两个 OOD 数据集 + 三种检索引擎兼容性 + 分层性能分析 + 案例研究。

## 方法与架构
**问题形式化**：skill 库 $\mathcal{C}=\{S_1,\dots,S_N\}$，每个 skill 为 $S_i=(N_i, D_i, I_i, P_i)$（名称、简述描述、任务相关指令、附加 payload 如脚本/参考/资产）。传统 retrieve-then-utilize：
```math
\mathcal{C}_r = R\big(q, \{(N_i,D_i)\}_{i=1}^{N}\big),\qquad \mathcal{C}_r\subset\mathcal{C},\ |\mathcal{C}_r|=k\ll N
```
```math
A = M(q, \mathcal{C}_r)
```
即先用轻量元数据检索候选，再把 $k$ 个 skill 的完整内容载入上下文（progressive disclosure），以避免上下文爆炸。

**统一任务形式化**：受 Search-R1 启发，把检索引擎当作可通过结构化模型输出调用的**外部工具**。模型先在 `<rec>...</rec>` 字段中表达所需的 skill 描述，该描述被送入检索引擎，引擎返回 top-$K$ 相关 skill 的完整内容（置于 `<skill>...</skill>`），模型据此继续推理并在 `<answer>...</answer>` 中给出最终答案。**若不需要外部 skill，模型可完全绕过检索直接作答**。实际 prompt 模板：
```
To answer the given question, you can use a skill retrieval engine
by <rec> your desired skill's description </rec>, and it will return
the top-1 related skill information between <skill> and </skill>...
You can retrieve as many times as you want. If you find no further
external skill needed, you can directly answer the question inside
<answer> and </answer>.
```
两个优势：① 检索与利用在同一模型轨迹内，可联合优化（检索什么取决于检索到的 skill 将如何被使用）；② 生成式检索可借助 LLM 的推理能力弥合 user query 与 skill description 之间的语义鸿沟，且**与底层检索引擎 $R$ 无关**（可搭配 BM25、Qwen3-Embedding 等）。

**阶段一 — Warm-start instruction tuning**：与 cold-start RL 不同，作者发现在训练数据有限且任务需要较复杂推理时，直接 RL 效果不佳（学生模型无法产生足够有信息量的学习信号，optimization progress 弱或不稳定）。做法：
- 用 **DeepSeek-V4-Pro** 作为 teacher，按预定义模板生成响应，再按**答案正确性**与**格式有效性**过滤（后者要求所有结构化字段正确闭合且存在合法的 `<answer>...</answer>`）。
- **能力感知的数据构造**：先评估学生模型在每个 query 上能否在无外部 skill 条件下正确解答；对**解不对**的 query，让 DeepSeek-V4-Pro 生成 `<rec>...</rec>` 检索请求（为 skill 检索提供监督）；对**已能解对**的 query，让 teacher 直接产出 `<answer>...</answer>` 而不调用检索。这使监督信号与学生模型对外部 skill 的真实需求对齐，而非强行对所有样本检索。
- SFT 目标：
```math
\mathcal{L}_{\text{SFT}} = -\frac{1}{N}\sum_{i=1}^{N}\sum_{t=1}^{T}\mathbb{I}(o_{i,t})\log P(o_{i,t}\mid x_i, o_{i,<t}, \mathcal{R};\theta)
```
其中 $\mathbb{I}(o_{i,t})$ 指示该 token 是否由 LLM 生成；**SFT 阶段 mask 掉 `<skill>...</skill>` 中的检索 token**，让模型专注于学习使用检索引擎与应用 skill。

**阶段二 — GRPO 强化学习**：以 $\theta_{\text{SFT}}$ 为起点，采用 GRPO，**只用 outcome-based verifier 作为奖励**：
```math
r_i = \begin{cases} 1, & o_i \text{ 正确}\\ 0, & \text{否则}\end{cases}
```
作者明确**不引入任何"检索到 golden skill"的显式奖励**——这类监督难以大规模获取，且可能把模型过度约束到预定义检索目标，限制其探索其他同样有用的 skill 的能力。GRPO 目标（同样对 `<skill>` 内 token 做 mask）：
```math
J_{\text{GRPO}}(\theta) = \mathbb{E}_{q,\{o_i\}}\left[\frac{1}{G}\sum_{i=1}^{G}\frac{1}{\sum_t \mathbb{I}(o_{i,t})}\sum_t \mathbb{I}(o_{i,t})\min\Big(\phi_{i,t}A_{i,t},\ \mathrm{clip}(\phi_{i,t},1-\epsilon,1+\epsilon)A_{i,t}\Big) - \beta D_{\text{KL}}\right]
```
```math
\phi_{i,t} = \frac{\pi_\theta(o_{i,t}\mid x_i,o_{i,<t},\mathcal{R})}{\pi_{\theta_{\text{SFT}}}(o_{i,t}\mid x_i,o_{i,<t},\mathcal{R})}
```
优势 $A_i$ 由组内相对奖励标准化得到（标准 GRPO）：
```math
A_i = \frac{r_i - \mathrm{mean}(\{r_j\}_{j=1}^{G})}{\mathrm{std}(\{r_j\}_{j=1}^{G})}
```
采用 token masking 排除 `<skill>` field 的检索 token，以避免训练中的分布偏移。

## 实验设置
- **数据**：主要来自 **SRA-bench**，取 5 个子集——TheoremQA、LogicBench、CHAMP、MedCalc-Bench、BigCodeBench，每子集随机划分 **80% 训练 / 20% 测试**。OOD 泛化另在 **MBPP+** 与 **LiveCodeBench** 上评测。
- **基线（三类）**：① 词法匹配——BM25、TF-IDF；② 稠密 embedding——Qwen3-Embedding-4B、Octen-Embedding-8B、SkillRet-Embedding-0.6B、SkillRouter-Embedding-0.6B、SkillReason-Embedding-4B；③ LLM-based retrieval——从 BM25 检索的 top-50 候选池中用 LLM 选 skill，模型为 Qwen3-4B 与 DeepSeek-V4-Pro。另有 **Oracle Skill**（提供人工标注的 golden skill）。
- **实现**：2× Intel Xeon Platinum 8350C（2.60 GHz）、2× NVIDIA A100 80GB、CUDA 12.8；verl + vLLM；对 **Qwen3-4B** 与 **LLaMA3.1-8B** 用 LoRA 微调（rank 16、$\alpha=32$、作用于所有线性层）；AdamW、LR $1\times10^{-4}$、cosine decay、warmup ratio 0.03、weight decay 0.01；GRPO group size $G=8$；SFT 训 1 epoch、GRPO 训 2 epochs。默认检索器为 **SkillReason-Embedding-4B**，训练时检索 **top-1** skill。
- **指标**：task completion accuracy（%）；retrieval accuracy（%）；分层分析按"施加方法前后是否正确"划分四组。

**分层性能分析（Fig. 4，Qwen3-4B）**：Skill-Uni 把最多原本答错的 query 转为答对（**182** 个），同时产生最少的"原本对→变错"（**61** 个）——检索并非总是有益，不相关 skill 会干扰正确答案，Skill-Uni 更擅长在有益时引入 skill、在无益时避免其干扰。

**深度分析（Fig. 5）**：① **生成式检索的效果**——用 Qwen3-Embedding-4B 比较原始 query 与生成的 `<rec>` 到 golden skill 描述的 embedding 距离，生成的 `<rec>` 与 golden skill 描述在隐空间**明显更近**（distance 分布向 0 集中）。② **warm start 的效果**——有 warm-start 的 GRPO 训练曲线从**显著更高的 reward 起步**并收敛到更高性能（Fig. 5b：warm start vs cold start 的 train reward 曲线）。

**OOD 鲁棒性（Tab. 4）**：使用来自 SkillRet 的约 **11,085** 个 coding/software-engineering 技能构建全新检索库（训练期间完全未见）：MBPP+ 上 base 55.82 → **Skill-Uni 62.17**；LiveCodeBench 上 base 17.96 → **Skill-Uni 19.16**。

**检索引擎兼容性（Fig. 6）**：把 Skill-Uni 搭配 BM25 / Qwen3-Embedding-4B / SkillReason-Embedding-4B 三种检索器——retrieval accuracy 分别为 **39.8 / 55.2 / 72.7**（BM25 → Qwen3-Embedding → SkillReason），下游 task accuracy 分别为 **46.85 / 51.39 / 56.42**；对照同一检索器作为独立基线的 task accuracy **46.85 / 51.39 / 56.42**（Fig. 6b 中三条柱与 Tab. 1 对应值一致），说明 Skill-Uni 在不同检索后端下都能稳定提升检索与任务表现。

**案例（Fig. 7、8）**：① **检索案例**（TheoremQA，"10 人分成 3 个非空子集有多少种方式"）——Skill-Uni 生成的 `<rec>` 明确指向 Stirling numbers of the second kind，检索到含 $S(10,3)=9330$ 预计算表的 skill 并给出数值答案 9330；BM25 因 "partition"/"non-empty subsets" 的词面重叠错误检索到 Lah Numbers（有序划分的算法），只能给出符号表达式 $S(10,3)$。② **利用案例**（MedCalc-Bench，目标体重计算）——两者都检索到 golden skill，但 BM25 只表面模仿 skill 示例里的 `TOOL_CALL`/`TOOL_RESULT` 模板并幻觉出错误结果 59.1664；Skill-Uni 真正解析并执行公式 $W = \text{BMI}\times(\text{height}/100)^2$ 得到 73.07 kg。

## 局限性
论文没有独立的 Limitations 章节。从实验可读出：① **并非全数据集最优**——BigCodeBench 上 Skill-Uni 低于 base model（Qwen3-4B：28.07 vs 32.46），CHAMP 上也明显低于 SkillReason（62.22 vs 75.56），说明"生成式检索"并非在所有任务上都有效，可能在代码类任务上生成了偏离的检索意图；② 平均超过 Oracle baseline 这一点虽然亮眼，但 Oracle 只提供 golden skill 而不涉及利用能力，因此"超越 Oracle"更准确的解释是"利用能力的增益超过了检索精度的增益"，而非真正超越了信息上界；③ "至少 11,085 个技能"的 OOD 库以 coding 为主，覆盖面窄；④ 所有数值只有单次运行，无多 seed 与显著性检验；⑤ GRPO 使用标准组内标准化优势，作者自己在相关工作中也讨论过二值奖励下标准差归一化的放大问题（这与 CORD 的做法相反）——本文的 outcome reward 恰是二值的，可能存在梯度被放大的隐患。

我的补充批判：① token masking 的消融显示它是**最重要的单一组件**（去掉后掉 13.98 点），这暗示大部分增益来自"不让模型学习外部 skill 文本的分布"这一训练技巧，而非"统一建模检索与利用"的架构主张本身；② warm-start SFT 使用 DeepSeek-V4-Pro 生成教师轨迹，这引入了强教师蒸馏的成本，且 SFT 消融（51.89）与 GRPO 消融（51.64）相近，说明两个阶段几乎独立贡献，缺一不可的"互补"说法略强；③ 只在训练时检索 top-1 skill、评测时是否也是 top-1 未明确说明（prompt 模板写的是 top-1），这可能限制了多技能组合场景的评估；④ 主表未报告 retrieval accuracy 的绝对值（只在 Fig. 6a 中给出），因此"提升检索质量"的量化证据较弱。

## 评估与建议
- 是否推荐深入阅读：**是**。它提出了 agent skill 生态中一个被忽视的问题——检索质量与利用能力的解耦，并把两者统一到一条生成轨迹中，方法简洁且兼容性设计（与检索引擎无关）实用。
- 适用场景：Agent skill 库检索与调用的系统设计；"外部程序性知识"（如 Claude Agent Skills 风格的模块）的接入；RAG 中把"检索什么"与"如何使用"联合优化的思路；RLVR（可验证奖励强化学习）在工具调用场景的应用。
- 与知识库的关联：与 SkillRet、SkillRouter、SkillReason（检索侧）、Skill0、SelSkill、Skill1、SAGE、RASO（利用/演化侧）构成完整的 skill 文献谱系；方法上直接借鉴 Search-R1 的"检索作为工具 + RL"范式与 GRPO；与 RAG（LightRAG、LinearRAG）、tool learning（ToolACE、ToolRec）以及 progressive disclosure 概念相关。
