# HarnessFlow: MCTS-Guided Harness Optimization for LLM Agents

> **arXiv**: [2611.06254](https://arxiv.org/abs/2611.06254)
> **发表日期**: 2026-11-04
> **分类**: cs.AI
> **会议/期刊**: arXiv preprint (18 pages, 8 figures, 7 tables)

## 📋 摘要

LLM agent 的表现同时取决于底层模型与**harness**（支配 agent 与工具/环境交互的运行时脚手架）。然而 harness 设计在很大程度上仍是手工的；要自动化它，就必须在开放式的搜索空间中通过昂贵的端到端评估来导航。本文提出 **HarnessFlow**：在**固定的模型与任务环境**下、在**有限的候选评估预算**内优化**完整可执行 harness** 的框架。HarnessFlow 把候选方案及其评估历史组织成一棵**精化树（refinement tree）**，并使用基于 **Monte Carlo Tree Search (MCTS)** 的策略来平衡利用与探索（exploitation / exploration）。一个**编码 agent** 依据归档代码（archived code）、执行反馈与一个**可复用 harness 机制库**（library of reusable harness mechanisms）来精化被选中的 harness。实验在 **每个基准 15 次精化尝试**的预算下，在覆盖 agentic 任务、编码与网页交互的 **6 个基准**上进行，HarnessFlow 在所比较方法中取得**最高的平均测试分**。优化后的 harness 平均得分 **69.48%**，相较初始 harness 与 **Meta-Harness** 分别提升 **10.89** 与 **3.95 个百分点**，同时**平均每任务执行成本低于**手工设计的基线。

## 🎯 核心贡献

1. 提出 **HarnessFlow**：把"LLM agent 的 harness 设计"形式化为**在有限评估预算下的开放式搜索优化**问题，模型与任务环境保持固定，从而把优化目标隔离到 harness 本身。
2. 用 **MCTS 策略**组织候选与评估历史形成**精化树（refinement tree）**，显式平衡利用与探索，解决端到端评估昂贵导致的搜索不可行问题。
3. **编码 agent** 驱动的精化机制：以**归档代码 + 执行反馈 + 可复用 harness 机制库**为素材对选中 harness 做增量修改，形成可积累的"机制资产"。
4. 在 **6 个基准**（agentic 任务、编码、网页交互）上取得**最高平均测试分**。
5. 效率优势：平均 **69.48%** 得分，优于初始 harness（+10.89 pp）与 **Meta-Harness**（+3.95 pp），且**平均每任务执行成本低于**手工工程基线——搜索出来的 harness 不只是更准，还更省。

## 🔧 方法/架构

- **搜索对象**：完整可执行的 harness（工具调用协议、观察处理、重试/回退策略、提示编排、工具集合等）。
- **精化树（refinement tree）**：节点为 harness 候选，边为一次精化操作，节点附带其评估历史：

```math
\mathcal{T} = (V, E), \quad v \in V \;\widehat{=}\; \text{harness candidate}, \quad e \in E \;\widehat{=}\; \text{refinement step}
```

- **MCTS 选择策略**：以 UCT 类准则平衡利用与探索：

```math
\mathrm{UCT}(v) = \frac{Q(v)}{N(v)} + c\sqrt{\frac{\ln N(\mathrm{parent}(v))}{N(v)}}
```

- **精化执行器（coding agent）**：输入 = 归档代码 + 执行反馈 + 可复用机制库（reusable harness mechanisms）；输出 = 新的 harness 候选。
- **预算约束**：每个基准 **15 次精化尝试**（refinement attempts），即严格限制候选评估次数，用以检验搜索效率。

## 📊 实验结果

- **6 个基准**（agentic 任务 / 编码 / 网页交互），每个基准 **15 次精化尝试**预算下：**平均测试分 69.48%**，在所比较方法中最高。
- **对比初始 harness**：**+10.89 个百分点**。
- **对比 Meta-Harness**：**+3.95 个百分点**。
- **执行成本**：优化后 harness 的**平均每任务执行成本低于**手工工程基线。
- 摘要未披露各基准的逐项分数（详见原文 7 张表格）；涉及基准为 6 个（agentic、coding、web interaction）。

## ⚠️ 局限性

- 依赖**编码 agent** 自身能力来提出 harness 修改，agent 能力不足时搜索无从下手；模型与任务环境被固定，**跨模型/跨任务的 harness 迁移性未验证**。
- 仍依赖昂贵的端到端评估，只是把次数压到 15 次/基准；对更严苛预算（如 3–5 次）的表现未知。
- **69.48%** 的绝对平均分说明仍有大量失败案例，harness 优化的上限受基座模型能力约束。
- 单一 MCTS 变体，未与遗传算法、贝叶斯优化、RL 等搜索基线做对比。
- 摘要未披露各基准名称、harness 机制库内容、评估成本绝对数值与方差信息。
- 实验只覆盖 agentic / 编码 / 网页交互三类任务，未涉及长周期、真实生产环境任务。

## 💡 建议

- 是否推荐使用：是（对"agent 效果调优"从手写 prompt 转向自动化搜索的路线有实操参考价值）
- 适用场景：搭建/优化 tool-using agent 的运行时框架；把手工调 prompt 转为可复现的搜索流程；预算受限的 agent 性能提升；构建可复用 harness 机制库与回归测试基座。
