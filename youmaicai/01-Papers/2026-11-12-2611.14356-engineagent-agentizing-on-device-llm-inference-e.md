## 核心要点
1. 核心洞察：**可复用的引擎/硬件知识与模型特定的实现应当分离**。在使能新模型之前，EngineAgent 构建**层次感知的引擎索引（hierarchy-aware engine index）**，刻画引擎的抽象分层与**跨层依赖**，并用**已被支持的模型**预验证后端特定的构建、执行与调试流程。
2. 双角色架构：**builder** 依据该索引协调跨层改动（转换、图构建、算子、硬件后端），**auditor** 检查实现完备性，并通过**设备端验证**驱动迭代式调试——正是现有编码智能体缺失的跨层依赖发现与 host–device 执行路径故障定位能力。
3. 效果：在**3 个移动端 LLM × 4 个引擎–后端组合**（CPU/GPU/NPU）共 **12 个任务**上，端到端成功率 **75%**（底层可选两种 LLM 之一），最强编码智能体基线仅 **33.3%**；成功判据为**编译通过 + 设备端可执行 + 输出 logits 与参考实现一致**。此外单任务平均耗时与模型 API 成本均低于同底层 LLM 的基线。

## 摘要（原文）
Rapidly evolving LLM architectures and heterogeneous mobile hardware make supporting new models in
on-device inference engines a recurring and costly system challenge. Each model may require
coordinated changes across conversion, graph construction, operators, and hardware backends.
Existing coding agents often miss these cross-layer dependencies and struggle to diagnose failures
across host--device execution paths. We present EngineAgent, an agentic system for automating on-device
LLM model enablement. Its key insight is to separate reusable engine and hardware knowledge from
model-specific implementation. Before enablement, EngineAgent constructs a hierarchy-aware engine index
that captures engine abstraction layers and cross-layer dependencies, and pre-validates
backend-specific build, execution, and debugging workflows using already supported models. For each new
model, a builder uses this knowledge to coordinate cross-layer changes, while an auditor checks
implementation completeness and drives iterative debugging through device-side validation. Across 12
tasks spanning three mobile LLMs and four engine--backend pairs on CPUs, GPUs, and NPUs, EngineAgent
achieves 75% end-to-end success with either of two underlying LLMs, versus 33.3% for the strongest
coding-agent baseline. Success requires compilation, on-device execution, and output-logit agreement with
reference implementations. EngineAgent also reduces average per-task time and model-API cost relative to
baselines using the same underlying LLMs.
