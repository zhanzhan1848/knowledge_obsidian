# The Last Mile to the Real World: Agent-Native Primitives as Reusable Building Blocks for Solving Real-World Tasks
### 元信息

| 字段 | 内容 |
|------|------|
| **标题** | The Last Mile to the Real World: Agent-Native Primitives as Reusable Building Blocks for Solving Real-World Tasks |
| **作者** | Haibo Jin, Peng Kuang, Xiaopeng Yuan, Lucheng Fu, Jerry Wang et al |
| **发表** | arXiv preprint |

| **代码** | [项目页](https://www.heelo.dev/) |

### 核心贡献
1. 提出 agent-native primitives（智能体原生基元）：把资源与一个驻留的 LLM 打包在一起，使资源能在上下文中被就地应用，并可与其他基元通信。
2. 提出 harness engineering 框架 HEELO，从基元库出发按任务组装 harness：组合出任务专属图、对环境证据做校验、在失败牵连到某基元时修订它、验证通过后才接纳新基元或改进基元。
3. 在超过二十个基准上实例化八个基元族，实测把 Terminal-Bench 4.0 解决率从 37.3% 提到 55.5%、Terminal-Bench 2.0 Pass@1 从 60.0% 提到 72.2%、ToolBench 通过率从 55.8% 提到 75.1%、GAIA-Text-103 准确率从 45.6% 提到 58.3%。

### 技术方案
**核心思想**: 前沿模型失败往往不是「够不到资源」，而是「不会在真实环境里应用它」——因此把这份应用能力固化为可复用基元，再由 harness 工程按任务组装、验证与迭代。

| 技术 | 说明 |
|------|------|
| Agent-native primitives | 为资源配备驻留 LLM，在上下文中就地应用该资源，并与其他基元通信 |
| HEELO | Harness Engineering around Evolving Agent-Native Primitives for the Last Mile to Real-WOrld Tasks |
| 组装流程 | 把任务所需基元组合成 task-specific graph |
| 校验环节 | 用来自环境的证据（evidence from the environment）验证结果 |
| 修订机制 | 失败若牵连到某基元则修订该基元；新基元/改进基元须经 validation 才被接纳 |
| 基元族 | 实例化八个 primitive families（Dev / Harness / Tool / Navigation 等），覆盖二十多个基准 |
| 部署方式 | 通过自建 MCP server 把 HEELO 接入 agent |

### 实验结果
- **数据集**: Terminal-Bench 4.0、Terminal-Bench 2.0、ToolBench、GAIA-Text-103，以及自建真实世界任务平台上的 46 个真实任务；共二十多个基准
- **基线**: Codex / Claude Code 等自带 harness 的前沿模型（GPT-5.6 Sol with Codex 解决 Terminal-Bench 4.0 的 37.3%；Claude Opus 5 with Claude Code 为 51.8%）
- **结果**: Dev-Primitives 使 Terminal-Bench 4.0 从 37.3%（Codex）提升到 55.5%（同一 backbone）；Harness Primitives 使 Terminal-Bench 2.0 Pass@1 从 seed harness 的 60.0% 提升到 72.2%；Tool Primitives 使 ToolBench 通过率从 55.8% 提升到 75.1%；Navigation Primitives 使 GAIA-Text-103 准确率从 45.6% 提升到 58.3%。在 46 个真实任务上，Claude Opus 5.5 with Claude Code 与 GPT-6.1 Sol with Codex 各自独立仅完成 9 个，接入 HEELO（经 MCP server）后分别完成 39 与 35 个，单个完成任务耗时减少 1.9x 与 2.3x、成本降低 1.55x

### 局限性
- 论文极长（102 页、21 图、54 表），摘要未给出各基元族的完整消融与「基元数量 vs 收益」的曲线
- 「八个基元族」可能覆盖不足，未知领域任务仍需新造基元，泛化到基元库之外任务的效果未说明
- HEELO 自身引入循环（组网→校验→修订→接纳）的开销与额外 LLM 调用，摘要未给出 harness 构建期的成本
- 真实任务平台的 46 题样本量较小，且由作者自建，可能存在分布偏好

### 关键洞见
> 真实任务的瓶颈往往不是「能不能拿到资源」，而是「拿到之后会不会用」——把这份「应用能力」从每次 harness 里重新手写，固化成可复用、可被 harness 按任务组装并自我修订的 agent-native primitives，就让同一 backbone 的 Terminal-Bench 4.0 从 37.3% 跳到 55.5%，真实任务完成数从 9 跳到 39，同时更快更省。
