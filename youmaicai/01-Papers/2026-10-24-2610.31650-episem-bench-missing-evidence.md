## 核心贡献

> 提出 EpiSEM-Bench —— 一个**可执行**的基准，用于评测 LLM agent 在"工具响应遗漏安全关键事实"时会如何行动，以及能否主动找回缺失证据。

1. **可执行的 matched pair 设计**：300 对 unsafe/safe 任务对，覆盖 6 个领域，通过系统性地抑制关键事实构造"缺证据"场景
2. **最小失败基数（minimum observed failure cardinality）**：不仅统计 unsafe execution，还区分"证据齐全仍失败"与"穷举测试后未观测到失败"两类情形
3. **独立审计工具（audit tool）**：检测 agent 是否主动追问缺失事实、是否在安全情况下正确完成任务
4. **跨 10 个模型系统评测**：在 omission robustness、evidence acquisition、appropriate action 三个维度上给出横向对比

---

## 技术方案

### 问题定位

工具型 agent 依据工具返回的环境事实判断某动作是否被允许。当工具响应**省略了安全相关的关键事实**时，即便用户请求本身无害、返回的每句话都是真的，agent 仍可能执行被禁止的动作。这是一种"信息缺失"型失效，与"意图恶意"型攻击不同。

### 基准结构

| 组件 | 说明 |
|------|------|
| Task pairs | 300 对 unsafe/safe 匹配任务对，6 个领域 |
| Evidence suppression | 系统性抑制安全关键事实，构造 missing evidence 条件 |
| Execution-based scoring | 实际执行任务以判定是否发生 unsafe execution |
| Failure cardinality | 报告最小观测失败基数，含"全证据失败"与"穷举无失败"两种极值 |
| Audit tool | 独立检查：是否主动求证 + 是否在许可任务上继续完成 |

### 评测维度

| 维度 | 含义 |
|------|------|
| Omission robustness | 在关键证据被抑制时抵抗不安全执行的能力 |
| Evidence acquisition | 是否主动获取缺失事实 |
| Appropriate action | 在 unsafe 世界与 safe 世界中是否都做出恰当动作 |

---

## 实验结论

### 总体结果

- 10 个模型在 omission robustness、evidence acquisition、appropriate action 三个维度上**差异显著**
- **抗缺失证据 ≠ 有效恢复**：能抵抗缺失证据的模型不一定具备有意义的证据恢复能力

### 关键发现

| 发现 | 说明 |
|------|------|
| Recovery access 普遍有效 | 为 agent 提供恢复通道后，**全部 10 个模型**的 unsafe execution 都下降 |
| 主动获取能力有差异 | 模型在"是否主动去拿缺失事实"上表现不一 |
| 恰当行动能力有差异 | 即使拿到了事实，模型在两种世界（unsafe/safe）中是否正确使用它们也不同 |

具体数值未在摘要中给出，需查阅正文表格。

---

## 局限性

- 仅覆盖 6 个领域、300 对任务，领域多样性有限，结论外推到其他域需谨慎
- 依赖"系统性抑制事实"的合成构造，真实环境中证据遗漏的分布可能与之不同
- 摘要仅给出定性结论与十模型的定性排序，缺少与既有 agent 安全基准的直接横向对比数据
- 只评估"是否执行被禁动作"，对部分执行、延迟执行等中间行为刻画不足

## 实现建议

- **实现难度**: 中（需要可执行沙箱 + 事实抑制的自动构造流水线）
- **适用场景**: 评估 tool-using agent 的上线前安全审计，尤其针对"依赖工具返回做权限判断"的流程
- **建议起点**: 先把 EpiSEM-Bench 的 paired 任务 + evidence suppression 机制移植到自己的业务工具链上，优先跑 omission robustness 与 recovery access 对比
- **价值点**: 区分"抗缺失"与"能恢复"这两个正交能力，是很多现有 agent 评测混为一谈的地方
