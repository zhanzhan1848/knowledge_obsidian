## 核心贡献

> 把"长文本 → 预测特征"问题转化为**离线可执行程序搜索**，用 LLM 引导搜索但**部署时无需 LLM 调用**，兼顾表达力与延迟；5 个生产金融风控落地 +0.02–1.56 pp KS。

1. 提出 **LLM-BlockFE**：LLM 引导的离线特征构造框架，把长文本转化为**可执行特征程序**。
2. 程序以"不可变代码块"增量追加，并以下游模型反馈评估候选特征。
3. 引入**块级回滚**机制（depth-calibrated credit allocation）+ **交错搜索**减少重复探索。
4. 离线搜索完成后冻结程序，**在线推理时无需 LLM 调用**，满足工业部署的延迟需求。
5. 在 2 个公开 + 2 个私有数据集上全量对比最强 baseline AUC 提升 **+0.0069 ~ +0.0358**；5 个金融风控上线后 KS 提升 **0.02 ~ 1.56 pp**。

## 技术方案

### 核心思想

工业风控需要"快速、便宜、可解释"，又需要"理解长文本"。直接调用 LLM 在线推理成本/延迟不可接受。LLM-BlockFE 让 LLM 在**离线阶段**生成特征提取程序，**线上部署时只需运行 Python 程序**，把 LLM 的语言理解能力蒸馏成可解释、可审计的代码特征。

### 关键技术

| 技术 | 说明 |
|------|------|
| Blockwise program construction | 程序由不可变代码块顺序组成，每个块是原子操作（如 n-gram、regex、统计） |
| Depth-calibrated credit allocation | 为每个块按搜索深度分配信用，用于判断块是否应回滚 |
| Rollback 机制 | 块级回滚，避免传统 greedy search 陷入局部最优 |
| Interleaved 多轨迹搜索 | 多个独立搜索轨迹交错推进，共享 fixed-description 减少冗余探索 |
| Frozen program deployment | 搜索完成 → 程序冻结 → 在线无 LLM 调用 |

### 搜索流程

```
1. LLM 提议候选代码块
2. 用下游模型评估 → 得到当前最佳程序
3. 多轨迹交错推进：每轨迹保留方向描述（fixed description）
4. 块级回滚：若某块贡献为负，按信用分配回滚
5. 重复直到收敛
6. 冻结最终程序，部署
```

## 实验结果

- **4 数据集**：2 public + 2 private（金融风控）
- **AUC 提升**（vs 最强 baseline）：**+0.0069 ~ +0.0358** 全量对比
- **5 个生产应用 KS 提升**：**+0.02 ~ +1.56 pp** 相对现有人工策略
- 离线搜索时间可控；在线推理仅跑 Python，开销可忽略

---

## 关键 takeaway

- **"LLM 离线 + 程序在线"** 是 LLM 工业落地的重要模式：LLM 的表达力 + 程序的延迟/可解释性。
- 把 feature engineering 转化为**程序搜索**问题，让下游模型反馈成为搜索信号。
- 块级不可变结构 + rollback 是程序搜索的稳健设计模式。

---

## 局限性

- 代码块原语集（block library）需要领域定制，迁移到新领域需重新设计
- 仅在金融风控验证，跨领域（如医疗、电商）泛化待验证
- 离线搜索阶段的 LLM 调用成本未明确量化
