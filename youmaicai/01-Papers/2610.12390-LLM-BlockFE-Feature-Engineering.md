## 核心贡献

> **LLM-BlockFE**：用 LLM 在离线阶段把长文本转换为可执行特征程序，在线推理时无需调用 LLM；通过 block-level rollback 与并行多 trajectory 搜索跳出贪心局部最优；在金融风控上线监控中相对人工策略 KS 提升 0.02–1.56 pp。

1. **离线 LLM 引导的特征构造**：把长文本通过不可变代码块逐步拼装成可执行程序。
2. **Depth-calibrated credit allocation** 的 block-level rollback 机制 + 多 trajectory 共享 exploration direction。
3. 在 2 个公开 + 2 个私有数据集 + 5 个金融风控上线任务上验证 AUC / KS 显著优于最强 baseline。

---

## 技术方案

### 核心思想

工业风控需要从长文本中提取预测特征，调用 LLM 处理每条实时输入延迟与成本不可接受。LLM-BlockFE 让 LLM 离线生成"特征程序"，运行时直接执行。

### 关键技术

| 技术 | 说明 |
|------|------|
| Blockwise program construction | 以不可变代码块为单位逐步拼接，保证可追溯与可回滚 |
| Depth-calibrated credit assignment | 根据调用深度分配 credit，避免浅层 block 主导 |
| Multi-trajectory interleaved search | 多个独立搜索路径并行，共享固定 exploration direction description |
| Online frozen deployment | 搜索结束后程序冻结，部署为标准特征提取流程 |

### 公式

```math
\text{Program}^* = \arg\max_{\pi} \ \mathbb{E}_{x \sim \mathcal{D}} \big[ \text{AUC}(M_{\text{down}}( \pi(x) )) \big]
```

其中 $\pi$ 为可执行特征程序，$M_{\text{down}}$ 为下游风控模型。

    for traj in trajectories:
        new_block = llm_propose_next_block(traj.shared_direction)
        score = evaluate(traj.append(new_block))
        if depth_calibrated_update(traj, new_block, score) < rollback_threshold:

## 实验结论

- **数据集**: 2 公开 + 2 私有文本数据集；5 个金融风控生产应用
- **基线**: 传统手工特征工程、其它 LLM-guided FE 方法
- **结果**:
  - 全量比较 AUC 绝对提升 **+0.0069 ~ +0.0358**
  - 上线监控 5 应用 KS 提升 **+0.02 ~ +1.56 pp**

---

## 局限性

- 离线搜索成本高，迭代次数多。
- 程序生成依赖 LLM 质量，弱模型上搜索效率下降。
- 金融以外的领域（医疗、电商）适配性需进一步验证。
