# When to Ask, When to Answer: Strategic Clarification for Ambiguous Reference Resolution in Dialogue

## 摘要
对人类而言，**指称消歧是一个协作过程** —— 只在澄清提问会实质改变结果时才问。但已有研究表明 **LLM 偏向过早作答** —— 偏好确定的单轮回复而非更多的澄清交互。本文研究**策略性澄清（strategic clarification）** —— 在参考答案游戏中，当澄清问题的答案会**收窄候选指称集合**时提出澄清。研究者从 **SIMMC 2.1** 构造受控测试环境，记录**每个模糊指称需要多少个问题**才能被成功解析，并考察基线 LLM 行为与常见后训练方法在「提问 vs 尝试作答」上的取舍差异。本文提出 **BACE（Belief-Aware Critic with Epistemic tracking）** —— 一个构建在**冻结 LM 骨干**之上的**轻量动作选择器**，并显示 BACE 比 **GRPO** 与 **ArCHer** 等方法**更一致地选出最优的澄清问题数量**。

## 核心贡献
1. 识别 LLM 在对话中的**过早作答偏置** —— 偏好确定的单轮回复而非澄清交互
2. 从 **SIMMC 2.1** 构造受控测试环境，度量**每个模糊指称需要多少澄清问题**才能解析成功
3. 比较基线 LLM 行为与常见后训练方法（**GRPO、ArCHer**）在「提问 vs 作答」上的取舍
4. 提出 **BACE**（Belief-Aware Critic with Epistemic tracking）—— 冻结 LM 骨干上的**轻量动作选择器**，更一致地选出**最优澄清问题数量**

## 方法与架构
**问题形式化**：策略性澄清 —— 在参考游戏中，仅当澄清答案会**收窄候选指称集合**时才提问。

**测试环境**：由 **SIMMC 2.1** 构造，记录**每个模糊指称需要的澄清问题数**（→ 成功解析）。

**BACE 架构**：
```
冻结 LM 骨干（不微调）
   ↓
Belief-Aware Critic  —— 维护关于候选指称的信念状态
   ↓
Epistemic tracking   —— 跟踪不确定性
   ↓
动作选择器 → {提问 / 作答}
```

**对比方法**：GRPO、ArCHer、基线 LLM。

## 实验结果
- 基线 LLM **偏向过早作答**（偏好确定单轮回复）
- **BACE 比 GRPO 与 ArCHer 更一致地选出最优澄清问题数量**
- 冻结骨干 + 轻量 critic 的组合**成本远低于完整 RL 后训练**（结构优势）

## 局限性
- 基于 SIMMC 2.1 的受控环境，真实对话中指称消歧的模糊度与成本更高；
- 「最优澄清问题数量」在真实场景下难以定义（信息价值依赖用户意愿）；
- BACE 的信念表示假设（候选集合可枚举）在开放域对话中不成立。

## 值得注意的点
「**人类只在澄清会实质改变结果时才问**」被用作评估基准 —— 这是一个来自人类协作常识的**外部效度锚点**，比让 LLM 自己判断强得多。与今日多篇一样，**用一个外部的、人类行为定义的参照系**，而不是让模型自评。
