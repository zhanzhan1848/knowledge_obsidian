## 核心贡献

> 开源 **IQuest-Q1** —— 一个 **320B 总参 / 15B 激活**的 sparse Mixture-of-Experts **agentic 基础模型**，面向 CLI 系统的 agentic coding 能力。

1. **模型规格**：320B 总参数，激活 15B，sparse MoE 架构
2. **三阶段训练流程**：预训练 → 细粒度 mid-training → 多 scaffold / 多版本后训练
3. **稳定预训练配方**：**Stable SplitNorm + Muon + muP** 组合，两阶段课程中第二阶段提升 coding 数据占比，同时**保持安全学习率与最优学习率之间的宽裕间隔**
4. **Mid-training 设计**：跨领域、跨格式扩展数据混合，并**渐进扩展上下文长度**
5. **后训练组合**：SFT + 领域专门 RL + **MOPD**，在多种 scaffold 上整合互补训练信号
6. **模型合并**：合并不同专家与不同阶段的 checkpoint，同时**缓解其参数更新之间的冲突**

---

## 技术方案

### 三阶段流程

| 阶段 | 关键组件 | 目的 |
|------|----------|------|
| **1. 预训练** | Stable SplitNorm、Muon、muP；两阶段课程 | 稳定且高效；**第二阶段提高 coding 数据占比**；保持安全 LR 与最优 LR 的宽裕余量 |
| **2. Mid-training** | 跨领域/跨格式数据混合 + 渐进扩展上下文 | 细粒度能力扩展，避免预训练后期能力定型 |
| **3. 后训练** | SFT + 领域 RL + MOPD，多 scaffold 多版本 | 整合互补信号，强化 agentic coding |

### 模型合并

$$
\theta_{\text{merged}} = \text{Merge}\big(\theta_{\text{experts}}, \theta_{\text{stages}}\big) \quad \text{with conflict mitigation}
$$

合并不同专家与不同阶段 checkpoint 的参数更新，同时**缓解冲突**（这是模型合并最难的环节）。

## 实验结论

> 摘要要点（具体基准数值需查正文）：
> - IQuest-Q1 在**编码任务与通用任务**上均展现出能力
> - 稀疏 MoE 结构使 320B 模型仅激活 15B，推理成本可控
> - **模型以开源形式发布**，支持社区研究与开发

---

## 局限性

- 摘要未给出具体基准分数与对比模型
- 未披露训练算力、数据规模等关键复现要素
- "多 scaffold 多版本后训练"流程复杂，第三方复现难度高
- 15B 激活参数在长上下文 agentic 任务上的实际延迟未报告

## 实现建议

- **实现难度**: 高（需完整预训练基础设施与 MoE 训练栈）
- **适用场景**: CLI / 终端 agent 的底座模型选型 —— 320B/15B 的激活比是很有吸引力的性价比点
- **建议起点**: 先下载开源权重，在你自己的 CLI benchmark 上做对比评测，而非从零训练
- **价值点**: 论文真正可复用的是**训练配方**（Stable SplitNorm + Muon + muP 的组合 + 两阶段课程），而非模型本身
