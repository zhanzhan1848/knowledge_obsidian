## 核心贡献
1. **用"同义句对"设计了一个无需人工标注的一致性测试**：为支持性对话的 helper 行为写 12 条评分标准，每条标准写成 4 种从句结构（肯定 POS、否定 NEG、条件 COND、例外 EXC），其中 POS≡NEG、COND≡EXC 在语义上完全等价，因此若同一模型对两个同义项给出不同判决，至少有一个是错的。这使得研究不依赖参考标签。
2. **韩语 rubric 的跨供应商一致性显著低于英语 rubric**：Cohen's κ = 0.687（韩语，95% CI [0.667, 0.705]）vs. 0.745（英语，[0.726, 0.763]），差值 −0.058，95% CI [−0.072, −0.045]；10,000 次 bootstrap 重采样中无一例非负。Set A 差值 −0.046，Set B 差值 −0.132。
3. **不一致集中在否定/条件/例外句式**：混合效应逻辑回归显示非肯定句式的分歧几率是对肯定句式的 **5.6 倍**（log-odds contrast 1.72，SE 0.08，z = 21.8，Holm 校正 p < 10⁻¹⁰⁰）。
4. **同义项翻转率 11–15%**：六模型在韩语素材上，POS/NEG 对的判决翻转率在韩语 rubric 下 14.1%、英语 rubric 下 12.1%；COND/EXC 对分别为 14.9% 与 11.0%。逐模型看，Set B 下韩语 rubric 结构翻转率从 3.8%（Claude Sonnet 5.5）到 24.3%（GPT-5.4 nano）。
5. **两个假设被证伪并如实报告**：H3（同供应商模型之间一致性更高）不成立——供应商内 κ 与跨供应商 κ 差值仅 0.005（[−0.001, 0.012]，Holm p = 0.23）；H4（加入配对示例能缩小语言差距）不成立——log-odds contrast −0.08（SE 0.09，Holm p = 0.39）。
6. **分析计划在数据收集前 12 分钟 commit 到公开仓库**（假说、估计量、检验、排除规则、模型设置全部预注册；虽未在正式 registry 注册）。数据收集规模：7 个模型 × 51,744 次请求，88,704 条 item 级判决，其中 1,219 条（1.4%）缺失（1,199 条来自参考模型，因其 reasoning 无法关闭而触及输出 token 上限）。

## 问题背景
在非英语服务场景中，评估 rubric 通常由服务方自己用本地语言撰写并维护，然后交给 LLM judge。已有工作（Fu & Liu 2025 跨 25 语言一致性低；Zubiaga et al. 2026 翻译 rubric vs 英语 rubric；Mahmood et al. 2026 把 judge prompt 本地化为 5 种语言）都只改变**语言**这一个变量，从未控制 rubric 条目本身的**句法结构**。

但真实的 rubric 充满否定、条件与例外句式——这恰恰是"微小的理解差异会翻转判决"的高危构造。已有另一条线（Bagaria et al. 2026）做法是**改变语义**（反转标准含义）再看判决是否跟随；本文做法正交：**保持语义不变、只改结构**，看判决是否保持不变。两者互补。

另一个背景是 LLM judge 作为人工评估替代品的可行性：Zheng et al. (2023) 显示强模型 judge 与人类偏好的吻合度接近人类之间的吻合度。若 judge 对同一条韩语标准项理解不一致，rubric 分数反映的就不只是对话质量，还有 judge 的选择。

## 方法
### 1. Rubric 构造
- 12 条标准（如"在给出第一条建议之前先询问客户情况"），每条写成 4 个 item：POS（肯定要求）、NEG（否定句，满足条件与 POS 相同）、COND（带条件的同一要求，如"若客户尚未询问建议，则……"）、EXC（要求后接例外，如"……但若客户已询问建议则不适用"）。
- POS ≡ NEG，COND ≡ EXC。每条 item 提供韩语与英语两个版本，共 96 个 item；judge 指令也用 rubric 相同语言书写。
- 三种判决标签：met / violated / not applicable。
- 每个 item 附一个满足示例和一个违反示例；同一标准的 4 种结构共享同一示例文本。

### 2. 素材构建
- **Set A（自然对话）**：从 ESConv 采样 60 段对话（1,721 utterances，每段 21–40 轮，13 个话题），固定随机种子，用 Claude Sonnet 5.5 翻译为韩语。LLM 抽查 12 段（376 utterances）标出 5 条错误（1.3%）。无人工校验。
- **Set B（边界用例）**：每条标准构造 12 段短韩语对话 + 英文对应，共 144 例。最小对设计：同一标准内 helper 轮次固定，只改变 client 的 1 句话。四类：无例外情形 / client 明确否认例外情形 / client 明确陈述例外情形 / client 间接陈述例外情形。最后一类（36 例）中，字面读法与标准撰写者意图在 COND 与 EXC 上会给出不同判决。

### 3. 评测协议
- **确认性 judge**：6 个低成本模型，每家供应商 2 个——Claude Sonnet 5.5、Claude Haiku 4.5；GPT-5.6 Luna、GPT-5.4 nano；Gemini 3.5 Flash-Lite、Gemini 3.1 Flash-Lite。参考模型 Claude Opus 5.5 单独运行并从全部检验中排除。
- reasoning 关闭或设为最低档（参考模型无法关闭），默认 temperature，同样的 prompt 文本发给所有模型，不使用供应商特有的结构化输出特性。
- Set A 请求 = 1 段韩语对话 + 某一种结构的 12 个 item（一种 rubric 语言）；Set B 请求 = 1 个用例 + 1 个 item。Set B 还跑了"带/不带示例""韩语/英语用例""只给判决不给理由（verdict-only baseline）"以及 36 例上的 2 次额外重复。
- 每个模型 7,392 次请求，7 个模型共 51,744 次。格式错误重试一次后计为缺失（共 765 次重试）。

### 4. 测量与统计
- 两模型一致性用三分类 Cohen's κ，共 15 个模型对（3 个同供应商、12 个跨供应商）。
- **结构翻转（structure flip）**：同一模型对 POS/NEG 或 COND/EXC 在同条件同单元下给出不同判决；**语言翻转（language flip）**：同一 item 的韩语版与英语版给出不同判决。
- H1：韩语 vs 英语 rubric 的平均跨供应商 κ 之差，按 set 分层的 cluster bootstrap（10,000 次重采样）。
- H2/H4：混合效应逻辑回归（因变量为成对分歧），固定效应为 rubric 语言、结构、配对类型、是否带示例，随机截距为单元、标准、模型对；用 lme4 + emmeans 拟合；H2–H4 做 Holm 校正。

## 实验结果
- **Dataset/Task**: ESConv 翻译的 60 段韩语支持性对话（Set A）+ 144 个构造边界用例（Set B）；12 条标准 × 4 种句式 × 2 种语言 = 96 个 rubric item；6 个确认性 judge + 1 个参考模型。
- **Main results**:

| 指标 | 数值 |
|------|------|
| 平均跨供应商 κ（韩语 rubric） | 0.687 [0.667, 0.705] |
| 平均跨供应商 κ（英语 rubric） | 0.745 [0.726, 0.763] |
| 差值 | −0.058 [−0.072, −0.045] |
| 非肯定句式的分歧几率比 | 5.6（vs 肯定句式） |
| POS/NEG 结构翻转率 | 韩语 14.1% / 英语 12.1% |
| COND/EXC 结构翻转率 | 韩语 14.9% / 英语 11.0% |

按句式的平均跨供应商 κ（韩语素材、无示例）：

| Set | Rubric | POS | NEG | COND | EXC |
|-----|--------|-----|-----|------|-----|
| A | Korean | .752 | .621 | .675 | .696 |
| A | English | .766 | .676 | .736 | .747 |
| B | Korean | .827 | .505 | .636 | .597 |
| B | English | .892 | .784 | .729 | .729 |

- **Ablations**:
  - 供应商内 vs 跨供应商 κ：差值 0.005（[−0.001, 0.012]，Holm p = 0.23）；韩语下 0.697 vs 0.687，英语下 0.745 vs 0.745。H3 不支持。
  - 加入配对示例：log-odds contrast −0.08（SE 0.09，Holm p = 0.39），不缩小语言差距；示例确实提高了否定句的一致性（Set B 韩语 0.51→0.56，英语 0.78→0.85）但差距原样保留。H4 不支持。
  - 自一致性（Fleiss κ，3 次重复）：0.74（GPT-5.4 nano）到 0.97（Claude Sonnet 5.5），6 个模型中 5 个 ≥0.85——说明跨模型分歧部分来自运行间波动，但不足以解释大部分分歧。
  - verdict-only baseline（无理由）：平均跨供应商 κ 为 0.55（韩语）/ 0.71（英语）；要求"先写理由再判决"则为 0.64 / 0.78。要求理由在两种语言下都提高一致性，但**不消除差距**。
  - 用英语用例替代韩语用例时语言差异更大：−0.198 [−0.238, −0.159]。
  - 字面读法遵从率（36 例间接陈述用例）：跨模型 43%–92%；GPT-5.4 nano 约 90%（两种语言下皆是），两个 Gemini 模型接近 50%；Claude Sonnet 5.5 韩语 rubric 下 78% vs 英语 65%。
  - 探索性：否定句式的一致性下降集中在少数标准，如"结束总结"标准在韩语 rubric 下 κ = −0.05（英语 0.58），"推荐转介"标准 0.11（英语 0.92）；其余 7 条标准的差异较小（绝对差 0.08–0.25）且方向不一致。作者明确标注每格仅 12 例、只是示意来源而非估计量。
  - 单例诊断：结束总结标准下，25 个 model–case 组合在韩语 rubric 下翻转而英语下不翻转，其中 23 个的韩语 NEG 判决与其他三个相反。

## 关键洞察
1. **语义等价性是无标签一致性测试的强力杠杆**：POS≡NEG、COND≡EXC 的构造把"哪个判决是对的"这个开放问题变成"两个判决不一致即至少一个错"的判定，使得研究可以在完全无人工标注的条件下量化 judge 的可靠性——这对标注预算极紧的韩语等小语种场景尤其有用。
2. **rubric 语言与 item 句式是两个正交且可叠加的不一致来源**：语言切换改的是"读指令的方式"，句式切换改的是"读单条标准的方式"；两者叠加使 Set B 中韩语 NEG 的 κ 掉到 0.505（vs 英语 0.784）。
3. **否定/条件/例外是 LLM judge 的系统性薄弱区，而非随机噪声**：5.6 倍的 OR 且在 7 个模型上一致出现，且在字面读法遵从率上得到独立佐证（不同模型对"间接陈述的例外情形"给出从 43% 到 92% 不等的字面遵从率）。
4. **few-shot 示例不是解药**：这是最反直觉的发现之一。示例提高了绝对一致性，却完全无法缩小语言差距（contrast −0.08，p = 0.39），说明"给示例"这一常见补救手段对跨语言鲁棒性无效。
5. **供应商内聚假设不成立**：两个模型共享同一供应商（同一套 RLHF 后训练、同一 tokenizer 与对齐流程）并不带来额外的一致性收益。因此"同厂模型互为廉价验证器"这一常见工程直觉在 judge 一致性上缺乏证据支持。
6. **要求模型输出理由能提升一致性但会带来成本且不解决问题**：无理由时韩语 κ 仅 0.55，加理由后升到 0.64，但与英语的差距仍在——这提示多语言 judge 部署中，"让模型解释"并不能替代"用目标语言原生训练的 judge"。

## 局限性
- **无人工标注**：全部材料（96 个 item、示例、指令）由 Claude 起草且未经人工复核；ESConv 的韩语翻译仅由 LLM 抽查（1.3% 错误率），无人工校验。边界用例的"标签"来自 item 撰写者而非人类 gold label。
- **只测一致性，不测正确性**：全文只测量内部一致性（κ、翻转率），没有任何一个结论能说明"哪个判决更接近人类判断"；因此"韩语 rubric 更差"只意味着更不一致，不必然意味着更不准。
- **预注册不完整**：虽然分析计划在首个请求前 12 分钟 commit 到公开仓库，但未在正式 registry 注册；且在收集开始后追加了一条操作规则（瞬时供应商错误的请求重发一次）。
- **素材规模有限**：60 段对话 + 144 个构造用例；Set B 每条标准仅 12 例，故逐标准的 κ 极不稳定（作者自己标注为"仅示意来源"）。
- **单一语言对、单一领域**：仅韩语-英语、仅支持性对话；结论对中文、阿拉伯语等结构差异更大的语言是否成立未知。
- **参考模型不可用作对照**：Claude Opus 5.5 因 reasoning 无法关闭而触及输出上限，1,199 条判决缺失（占其全部缺失的 98%），实际上无法作为有效的高能力参考基线。
- **用例类型不均衡**：36 个"间接陈述"用例是字面读法与意图读法分叉的唯一来源，占 Set B 的 25%，这一子集主导了部分结论。
- **"同义"是构造意义上的而非严格语义学意义上的**：POS/NEG、COND/EXC 的等价性依赖 item 撰写者的设计，Claude 自己做的回译校验也无法排除残留歧义（附录列出 3 个仅被一个回译模型误译的 item）。

## 适用场景
- **多语言 LLM judge 部署**：在韩语等非英语场景部署 judge 前，先用本文的句式对照法自检 judge 的可靠性，再决定是换模型、换语言还是加人工抽检。
- **rubric 设计规范**：把否定/条件/例外句式的标准条目拆成肯定式平行条目，用"结构翻转率"作为 rubric 质量指标；对高风险标准（如合规、拒绝类）可考虑强制只用肯定式表述。
- **供应商选择**：由于供应商内聚不成立，同厂双模型互相验证不能替代跨厂交叉验证或人工抽检。
- **低成本消融实验设计**：本文的"同义项对"框架可迁移到任何"无 gold label 但要求判定一致"的评估任务（内容安全分类、事实核查的一致性测量）。

**不适用于**：需要判断 judge"准不准"的场景；需要人类偏好金标来校准的评估体系；单句、非结构化评测（本文的信号完全依赖标准条目的结构化构造）；以及声称对所有语言普适的结论。
