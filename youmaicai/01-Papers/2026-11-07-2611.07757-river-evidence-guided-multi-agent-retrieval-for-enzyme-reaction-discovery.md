# RIVER: Evidence-guided multi-agent retrieval for enzyme--reaction discovery

### 核心贡献
1. 提出 RIVER（Reaction--enzyme Inference via Evidence-guided Retrieval）：一个用于**双向** enzyme–reaction 检索的多智能体框架——既可为一个给定 enzyme 识别其可能催化的反应，也可为一个给定 reaction 对候选 enzyme 排序。
2. 指出既有方法依赖序列/结构相似度或已知 enzyme–reaction pair 训练，难以在大候选空间中整合生化证据，并且在成员高度相似的 enzyme family 检索任务上表现吃力；RIVER 通过多层级证据组装来补上这一缺口。
3. 引入专门的验证模块（dedicated validation modules）检查证据缺口与潜在冲突，并基于**可追溯的证据记录**（traceable evidence records）对候选重新排序。
4. 在基于近期文献构建的 Escherichia coli enzyme 检索任务上，RIVER 在闭源与开源两种模型配置下都取得最佳检索结果，显著优于 Claude Code、Codex、Phylo Max 等通用及生物专用多智能体系统。

### 技术方案
**核心思想**: 把「酶—反应」判定问题从相似度匹配改造成证据聚合推理：多个 agent 分别从反应化学、蛋白序列与结构域、催化机理、数据库注释等不同层级的来源收集证据，再由验证模块挑出冲突与缺口，最后用可追溯的证据记录重排候选。

| 技术 | 说明 |
|------|------|
| RIVER 框架 | Reaction–enzyme Inference via Evidence-guided Retrieval，多智能体、多层级证据、双向检索 |
| 多层级证据组装 | 反应化学（reaction chemistry）、蛋白序列与结构域（protein sequences and domains）、催化机理（catalytic mechanisms）、数据库注释（database annotations） |
| 专用验证模块 | 检查 evidence gaps（证据缺口）与 potential conflicts（潜在冲突） |
| 可追溯证据记录重排 | 依赖 traceable evidence records 对候选 rerank，保证每个判定都能回溯到证据 |
| 工具协同 | 协调 LLMs、专业生化计算工具与外部知识资源 |
| 双向任务 | (a) enzyme → reactions；(b) reaction → 候选 enzyme 排序；另覆盖 family-specific enzyme retrieval |

### 实验结果
- **数据集**: 公开基准上的 enzyme retrieval 与 enzyme annotation；family-specific enzyme retrieval 数据集；以及基于近期文献构建的 **Escherichia coli** enzyme 检索任务
- **基线**: 依赖序列/结构相似度的方法与基于已知 enzyme–reaction pair 训练的方法；多智能体系统对照含 **Claude Code、Codex、Phylo Max**（通用闭源与生物专用系统）
- **结果**: 在公开基准上，RIVER 在 enzyme retrieval 与 enzyme annotation 两项任务上均取得最高成功率；在 family-specific enzyme retrieval 中在所选数据集与指标上优于所评估基线；在 E. coli 任务上，无论闭源还是开源模型配置均取得最佳检索结果，并显著超过 Claude Code、Codex、Phylo Max 等系统。摘要未给出具体数值（成功率、MRR 等）

### 局限性
- 摘要未提供任何量化指标（成功率具体数值、排序指标、相对提升幅度），结论只能读出方向。
- 框架依赖多个专用生化计算工具与外部知识库，实际运行成本、可复现性以及工具失效时的降级行为未讨论。
- E. coli 任务基于「近期文献」构建，样本量与标注可靠性未说明；结论向真核生物、代谢网络更复杂物种的外推性未验证。
- 多智能体协调中如何避免证据重复检索与冲突放大，摘要未说明；验证模块的「证据缺口」判定标准也未公开描述。

### 关键洞见
> 这篇论文折射出生物信息学工具的一次范式转移：**「相似度」是死的统计量，「证据」才是可审计的科学过程**。在 enzyme family 这类成员高度相似的场景下，序列相似度注定失效，而 RIVER 的做法是让模型像生物化学家一样跨五个层级取证（化学、序列域、催化机理、注释、数据库），再把结论落在「可追溯的证据记录」上——这恰恰是 LLM 最擅长的任务形态：不是记住答案，而是组织证据链。也正因如此它能赢过 Claude Code / Codex 这类通用 coding agent：通用 agent 缺少把问题**分解到化学层级**的领域脚手架。
