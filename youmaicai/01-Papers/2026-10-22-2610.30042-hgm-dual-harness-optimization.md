## 核心贡献
1. **提出 HGM-Dual**：面向 planning agent 的**诊断引导式（diagnostic-guided）**、**预算高效**的 harness evolution 框架。
2. **机制一 — lineage-aware context**：将 agent 演化表示为**带血缘的上下文**，记录每个祖先**改了什么**、**哪些行为改善或退化**、**哪些修改无效**，从而给 editor 模型提供**显式的 edit–outcome 归因**，替代以往"无结构的历史 agent 归档"。
3. **机制二 — error-conditioned dual-path child generation**：对每个选中的 parent 生成**两类子代**——(a) 保持开放式探索的 **general child**；(b) 针对 parent 最高排序的 **constraint violations** 最可能归因的 harness 组件，专门生成的 **specialized children**。
4. **性能与效率双优**：相对最强基线 case accuracy **最高提升 14.45%（相对值）**，同时在**仅用 HGM 各变体 1/2 到 1/4 的评估预算**下达到与它们相同的最终性能。

## 问题动机
**Harness optimization**（优化 agent 的 prompts、tools、workflows）是增强基于冻结或闭源 LLM 的 agent 的日益有效手段。主流方法如 **Darwin–Godel Machine (DGM)** 与 **Huxley–Godel Machine (HGM)** 依赖递归自我改进（recursive self-improvement），但它们主要为 **coding** 任务开发——那里存在一个关键的对齐假设：**"改进 agent 所需的能力"恰好就是"被改进的能力"**（即 coding 能力自我循环）。**Planning 任务打破了这个对齐**：agent 必须产出一串工具调用来同时满足多个相互作用的约束，而评估这些结果所需的判断力与生成它们的规划能力并不重合。在这种情形下，开放式自我修改会反复探索无效改动，消耗大量评估预算。

## 方法
HGM-Dual 包含两个协同机制：

**1. Lineage-aware context（血缘感知上下文）**
agent 的演化历史不再是无结构的归档，而是带血缘结构的上下文，其中显式记录：
- 每个祖先**具体做了哪些改动**（edit）
- 改动导致的**行为改善或退化**（outcome）
- 哪些修改是**无效的**（ineffective）
目的是让 editor 获得 **edit–outcome 归因**，而非只知道"过去存在过若干个 agent"。

**2. Error-conditioned dual-path child generation（错误条件双路子代生成）**
对每个被选中的 parent，生成两条生成路径：
- **General path**：生成保持开放式探索的通用子代，避免过早收敛
- **Specialized path**：依据 parent **最高排序的 constraint violations**，定位最可能负责的 harness 组件，生成针对性的专门子代

二者结合，实现"在保持探索广度的同时，把预算精准投向已定位的失败原因"，从而提升单位评估预算的收益。
